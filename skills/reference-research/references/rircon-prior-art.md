# Research binding: Rircon prior art

Use this resource only for an explicit `rircon-prior-art/1` binding. Rircon keeps
its original Markdown layout and native report requirements. This resource does
not turn the collection into `reference/1` packages or add a validator.

The binding selects the repository snapshot/root, `docs/README.md`, the canonical
high-recall index `docs/prior-art.md`, `docs/prior-art/README.md`, the complete
`docs/prior-art/AGENTS.md`, the required example reports and the complete research
skill. Paths resolve from that explicit root. Read the bound policy in full;
its mission, source hierarchy, examples and acceptance checklist remain native
requirements. A live authoring task also needs its stated current-main, current
Zircon and external writing-resource prerequisites. A frozen navigation packet
does not establish those live prerequisites or permission to write.

One `docs/prior-art/<subject>/` directory represents a canonical research subject,
which may span repository renames, moves and implementation stages. Independent
implementations remain separate even when they share ancestry or compatibility
targets. The comprehensive report is `README.md`; substantial focused studies use
native companion Markdown paths. Update the canonical high-recall index for a
newly covered subject and do not create empty subject directories. Its entries
are discovery leads, not a complete report manifest or independently verified
technical claims; inspect the selected raw source inventory as well.

Keep established behavior, documented intent/rationale, strong inference and
hypothesis/stress analysis distinct. Record the actual upstream source snapshot,
research date and evidence gaps. A corpus capture commit is not the studied
project's upstream revision. Separate semantic ancestry, code/architectural
ancestry and inspiration; separate current Zircon compatibility requirements,
replaceable implementation choices, LK ancestry and Rust opportunities.

The native recommended headings are a checklist, not mandatory boilerplate.
Use relevant native lenses, reconstruct constraints/invariants/mechanisms and
architectural transitions, and retain uncertainty. Do not impose six fixed report
sections, JSON sidecars or reference/1 evidence-role labels. Before completion,
review every applicable item in the native manual acceptance checklist. No
machine validator was identified for this pilot; report manual checks and gaps
honestly rather than substituting a successful navigation build.

`docs/netstack3/` and `docs/zircon/` supply related studies and policy examples.
The prior-art policy does not by directory proximity authorize authoring in those
other namespaces. Their pilot use is read-only; any later authoring operation
requires its own applicable instructions and authority. During read-only work,
keep source qualifications, missing snapshot information and stale navigation
visible. An authorized report revision may investigate and explicitly correct
those gaps under native policy. No navigator or build environment is needed for
this research route.
