# Reference corpus research

Turn technical questions or preliminary findings into durable, self-contained
reports under an explicitly selected corpus contract.

Obtain the caller's binding and scope, then read the complete bound native policy
and report requirements. The binding selects the corpus root, governing resources,
research materialization, native inventory, validation route and allowed operation.
A native route may use a manual acceptance checklist; do not invent a machine
validator or require one merely because another corpus has one. Paths are absolute
or explicitly relative to the bound corpus root. Do not infer them from this
installation, siblings, a nearby `AGENTS.md` or the current directory.

Load the complete [research guidance](references/research.md) and the selected
interpretation's guidance, resolving both from this skill's directory:

- `reference/1`: [report packages](references/reference-1.md).
- `rircon-prior-art/1`: [native prior-art reports](references/rircon-prior-art.md).

The corpus owns its meanings, content, checks and publication rules. This skill
owns the research process. Missing required resources, an unsupported selected
interpretation, or ambiguous/conflicting bindings block the dependent operation;
report what is missing. Carry separate bindings and conclusions for separate
scopes. No navigator, index or Python build environment is required for research.

Establish questions and stopping conditions, inspect existing reports, acquire
primary evidence, cross-check rounds, and coalesce findings with their boundaries
and cheap revalidation probes. Return the result at the authorized stopping
boundary. Publish only when the current request and selected native policy
permit that exact action, using the native candidate, concurrency and readback
procedure. A complete resource copy supplies neither action authority nor a
semantic acceptance result.
