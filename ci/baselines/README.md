# Legacy CI baseline

These data files freeze the CI behavior at commit
`286dd29655e7ae2f5603a8af89c270cc3bd52f2e`. They are review fixtures for the
typed CI planner. They are not a recommendation to preserve every existing
choice, and they do not interpret GitHub Actions YAML at runtime.

The source workflow is `.github/workflows/ci.yml`. The standalone inventory
also reads `githooks/pre-push`, and command expansion uses values in
`zerocopy/Cargo.toml`. Their SHA-256 digests at the source commit are:

```text
.github/workflows/ci.yml
c96b8759c45d37eadfdac274fffd67242a3e40e08b13c7027505eb8c03476d89
githooks/pre-push
1347fc661d5d11bb8ca9445ab951a7d6a0fae7fedacfed0cdf809c0f0e4b0c0a
zerocopy/Cargo.toml
235a850df53602086a981a81ddac60d324c334df1fe2e08496f2b25ebee21a16
```

## Files

- `build-pr.tsv` contains the 60 ordinary build matrix cells for a pull
  request.
- `build-full.tsv` contains the 182 ordinary build matrix cells for a full
  event.
- `miri-pr.tsv` has no data rows because the whole Miri job is skipped for pull
  requests.
- `miri-full.tsv` contains the 64 Miri cells for a full event.
- `standalone-obligations.tsv` inventories operations outside the two test
  matrices. It expands the current pre-push hook so repeated checks are visible.
- `logical-obligations.tsv` normalizes matrix and standalone operations and
  records their physical occurrence counts on pull-request and full events.
- `command-goldens.tsv` records representative expanded argument vectors,
  action inputs, and relevant environment values.
- `manifest.tsv` records source identity, counts, and cross-check results.

Here, a *full event* means any non-pull-request event. `merge_group` was used to
derive the rows. `push` and `workflow_dispatch` produce the same matrix sets
because the only event-dependent matrix exclusions test for `pull_request`.

## Derivation and independent cross-check

The fixtures were generated by a disposable Python program in `/tmp`; no YAML
interpreter or generator is checked in. The program read the workflow directly
from the immutable Git object with this command:

```sh
git show \
  286dd29655e7ae2f5603a8af89c270cc3bd52f2e:.github/workflows/ci.yml
```

It calculated each set in two independent ways:

1. A generic matrix expansion formed each Cartesian product and applied every
   partial-map entry under `exclude`. It separately applied the Miri job-level
   event condition.
2. A hand-written model transcribed the documented policy: feature/toolchain
   compatibility, crate-specific profiles, toolchain-specific target coverage,
   the thumb and stable-wasm restrictions, and reduced pull-request targets.
   The Miri model independently transcribed its supported targets, profiles,
   crates, and borrow models.

The derivation command completed successfully and printed:

```text
source_commit=286dd29655e7ae2f5603a8af89c270cc3bd52f2e
workflow_sha256=c96b8759c45d37eadfdac274fffd67242a3e40e08b13c7027505eb8c03476d89
pre_push_sha256=1347fc661d5d11bb8ca9445ab951a7d6a0fae7fedacfed0cdf809c0f0e4b0c0a
cargo_sha256=235a850df53602086a981a81ddac60d324c334df1fe2e08496f2b25ebee21a16
generic_build_pr=60 manual_build_pr=60 equal=True
generic_build_full=182 manual_build_full=182 equal=True
generic_miri_pr=0 manual_miri_pr=0 equal=True
generic_miri_full=64 manual_miri_full=64 equal=True
standalone_occurrences=31
normalized_logical_obligations=475
```

The exact set comparisons are stronger than count comparisons: a missing cell
and an unrelated extra cell cannot cancel each other out. The row counts were
also checked directly from the finished TSV files.

## Logical normalization

The cell files preserve physical runner cells. The logical fixture instead
describes work performed within those cells. For example, one cross cell adds
both `cargo-check-tests` and `cargo-build` obligations.

The normalized target for `cargo-doc` is empty because the workflow does not
pass `--target` to that command. Consequently, the fixture exposes 22 doc
obligations that run between two and eleven times per event. It also exposes the
eight check scripts run both by their standalone jobs and by `run-git-hooks`.
There are 30 normalized rows with repeated physical executions. These counts
freeze existing behavior; they let a later planner distinguish an intentional
change from an accidental duplicate.

The semver rows describe eligible executions. They retain the condition
`unless SKIP_CARGO_SEMVER_CHECKS=1` because a commit-message marker can suppress
the third-party action at runtime.

## Command golden boundaries

An `argv` payload is an exact JSON argument vector after the matrix feature
profile is expanded. An `argv-template` is exact except for the named runtime
value. Miri computes `<2*nproc>` on the runner, so that value cannot be frozen
as a number. The two Miri rows preserve the exact effective `MIRIFLAGS`
strings, including the empty stacked-model contribution.

The semver check is a third-party action. The workflow does not expose the
action's eventual process argument vector, so the fixture freezes its pinned
action revision and visible inputs instead of inventing an argv. The nightly
docs environment records the effective Rustdoc flag tokens; insignificant
extra shell whitespace from the metadata pipeline is normalized.

The standalone inventory omits checkout, package installation, and other
setup-only steps. It includes the CI image producer, coverage upload, and the
required-check aggregate because failure of any of those operations fails CI.
The pre-push hook had one file at the source commit, `githooks/pre-push`; its
eight child checks and its script-inventory check are represented explicitly.

All rows are deterministically sorted. Their order does not model scheduling or
step order. The source workflow remains authoritative for shell setup,
third-party action internals, and GitHub runner behavior that these data-only
fixtures deliberately do not interpret.
