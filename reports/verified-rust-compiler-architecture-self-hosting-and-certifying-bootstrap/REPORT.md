# Verified Rust Compiler Architecture, Self-Hosting, Certifying Bootstrap, and Proof-Producing Executable Endpoints

## Summary

Verifying unsafe and safe Rust programs by extracting `Runtime(PostCleanup)` Mid-Level Intermediate Representation (MIR) and checking functional correctness and memory safety (`CrateTheorem`) inside the Lean 4 kernel (`v4.34.1`) leaves a critical gap if compilation from MIR to target machine code remains trusted (`TCBItem.rustcLowering`): any miscompilation in monomorphization, ABI lowering, SSA promotion, instruction selection, register allocation, stack frame layout, DWARF unwind tables, or linker scripts can silently invalidate a kernel-checked MIR proof. At the same time, discharging `TCBItem.rustcLowering` under a strict zero-trust kernel auditor (`trustLevel := 0`, restricting axioms to `{Classical.choice, Quot.sound, propext}` and forbidding both `Lean.ofReduceBool` / `native_decide` and `deriving` clauses) creates a tension between proof ergonomics, Trusted Computing Base (TCB) size, per-crate Lean kernel WHNF reduction latency, and standalone binary execution.

This report synthesizes six research packages covering the master architecture and 5-stage roadmap for a verified/certifying Rust compiler (`rustc_codegen_anneal`), self-hosting and Two-Step Equivalence in Lean 4 (`support/track2_self_hosted_compiler_probe.lean` and `support/round2_track2_probe.lean`), verified compiler bootstrap and executable endpoints across CompCert, CakeML, and CertiRocq, staged code generation and WebAssembly binary validator admission (`support/staged-code-generation-and-certirocq-endpoint-linkage/WasmValidator.lean`), Diverse Double-Compiling (`DDC`) and proof-produced checker executables (`support/ddc-and-proof-produced-checker-executables/ddc_witness.py`), and HOL proof-producing synthesis and binary lifting (`HOL4`, `CakeML`, `HolBA`):

1. **End-to-End Hybrid Verified/Certifying Rust Compiler Architecture (`rustc_codegen_anneal`)**:
   We specify a modular compilation pipeline from `rustc` `Runtime(PostCleanup)` MIR to AArch64, x86-64, and RV64GC machine code that adds fewer than 200 lines to the trusted semantic specification (`Trusted/`) while placing all compiler passes, symbolic checkers, and simulation proofs in an untrusted theory library. The architecture combines **once-verified structural passes** (`MonoMIR` ABI/layout lowering, escape-tracked `ANSSA` `mem2reg`, CompCert-style `Stacking`, `MemStateInj` memory injection, and `OpenModule` linking) with **linear-time certifying translation validators** (`BTL` superblock symbolic execution for ISLE and `aegraph` GVN, a repaired `regalloc2` symbolic checker, `MachBuffer` branch-relaxation validation, and DWARF `.eh_frame` CFI checking), supporting both **Path A (Direct Native Certifying Codegen)** and **Path B (`ANLLVM` + `seL4/graph-refine` Binary Translation Validation)**. We also catalog **seven concrete soundness bugs** discovered and repaired across upstream compilers and verification tools.
2. **Self-Hosting (`Architecture B`), Certifying Optimizer Checkers (`Architecture C`), and Stage 1 $\to$ Stage 2 Bootstrap Fixed Point**:
   Mechanized across 12,387 lines of zero-`sorryAx`, zero-`Lean.ofReduceBool` Lean 4.34.1 proofs (`support/track2_self_hosted_compiler_probe.lean` at 7,801 lines and `support/round2_track2_probe.lean` at 4,586 lines), we compare **Architecture A (Compiler-in-Lean-4)**, **Architecture B (Self-Hosted Compiler in Rust Subset $K$ via Two-Step Equivalence)**, and **Architecture C (Untrusted Native Rust Optimizer + Verified $O(|P|)$ Certificate Checker)**. We prove `f_spec_sound`, `CrateTheorem_transfers_to_IsaLang`, `compilerMirBody_two_step_sound`, `certifyingCompiler_verified`, `checkerMirBody_two_step_sound`, `self_hosted_bootstrap_sound`, and `self_hosted_stage2_reproducibility`, and extend `MirAst` and `FunctionalTranslation` with immutable slices (`&[usize]`, `evalSym_slice_sound`, `sliceCheckerMirBody_two_elem_sound`), struct/enum ADTs (`evalSym_enumCert`), post-PR `#154341` `Rvalue::Use(Operand, WithRetag)` lowering (`retag_lowering_compiles`, `retag_copy_prop_compiles`, and two negative refutations), fuel-indexed open `CallSpecTable` mutual recursion (`mutual_recursion_callSpec_sound`, `is_even_is_odd_mutual_sound`), and `deriving`-free 64-bit hardware projection $\pi_{\text{isa}}$ (`monotone_π_isa`, `lowerMirToHwIsa_compiles`).
3. **Verified Compilers, Staged Code Generation, CertiRocq Endpoint Linkage, and WebAssembly Binary Validator Admission**:
   Comparing CompCert 3.18 (`driver/Compiler.v`, `common/Smallstep.v`), Tristan/Leroy POPL 2008 verified scheduling validators, CakeML (`compilerProofScript.sml`, `x64BootstrapProofScript.sml`), CertiRocq (`theories/Compiler/correctness.v`, `anf_toplevel.v`, `metarocq_pipeline.v`, `pipeline.v`), and Cyclone/TAL/T staged runtime code generation (PEPM 1999, Cornell TR2000-1824), we resolve CertiRocq's `refines_toplevel` notation linkage to `refines_top` and `refines`, and execute an end-to-end WebAssembly binary validator experiment in Lean 4.34.1 and Node 24.21.0 (`support/staged-code-generation-and-certirocq-endpoint-linkage/WasmValidator.lean`, `support/staged-code-generation-and-certirocq-endpoint-linkage/WasmArtifact.lean`, `support/staged-code-generation-and-certirocq-endpoint-linkage/boolean4.wasm`).
4. **Diverse Double-Compiling (`DDC`), Proof-Produced Checker Executables (`CakeML` LPR / OpenTheory), and HOL Synthesis / Binary Lifting (`HolBA`)**:
   Inspecting Wheeler's 2009 DDC dissertation and `ddc.in`, CakeML's verified LPR SAT/unsat checker (`lpr_arrayProofScript.sml`, `lpr_arrayFullProgScript.sml`, `lpr_arrayCompileScript.sml`, `basis_ffi.c`), Abrahamsson's HOL proof-checker executable (JLAMP 2020), Myreen's compilation-via-decompilation (`HOL4` `codegenLib.sml`), CakeML's pure/monadic synthesis (`ml_translatorScript.sml`), and `kth-step/HolBA`'s BIR binary lifter (`bir_inst_liftingScript.sml`), we separate source-to-binary correspondence (`DDC`) from algorithmic checker soundness, I/O wrapper verification, and `BST_AssertionViolated` lifting guards.

### 1. End-to-End Verified Rust Compiler Architecture (`rustc_codegen_anneal`)

`Basis: synthesis of the 8 Verified Rust Compiler packages + 10 ISA specification reports + 29,917 lines of machine-checked Lean 4.34.1 proofs`

#### 1.1 Architectural Overview & Pipeline Topology

#### 1.2 Layer-by-Layer Specification and Verification Mechanism

1. **Layer 0: Exact `Runtime(PostCleanup)` MIR Capture**:
   - **Defect Resolved**: Invoking `rustc --emit=mir` without `-Zmir-opt-level=0` causes `rustc` to run 30+ `Runtime(Optimized)` MIR passes (including `DeadStoreElimination`, `InstSimplify`, and `GVN`) before emitting MIR, while `deduce_param_attrs` infers `ReadOnly` attributes on post-DSE MIR when `OptLevel != No`.
   - **Mechanism**: Pass `-Zmir-opt-level=0` and invoke a custom `rustc_driver` callback hooking `tcx.mir_drops_elaborated_and_const_checked(def_id)` plus post-monomorphization `tcx.layout_of` and `tcx.fn_abi_of_instance`.
2. **Layer 1: Monomorphization, Layout, `BackendRepr` ABI, and Intrinsics (`MonoMIR`)**:
   - **Scope**: Replaces polymorphic `TyKind::Param` with concrete layout descriptors (`Size`, `Align`, `FieldsShape::Arbitrary`, `Variants::Multiple`), computes byte-offset-guided niche tags (fixing `rustc_codegen_cranelift`'s `FieldIdx(0)` assumption on `ScalarPair`), lowers `PassMode::Direct`, `PassMode::Pair`, `PassMode::Cast`, and `PassMode::Indirect { on_stack }`, and desugars compiler intrinsics (`copy_nonoverlapping`, `arith_offset`, `wrapping_*`, `ctlz`/`cttz`).
   - **Verification**: General structural forward simulation (`mono_abi_pass_verified`) proved once in Lean 4 (`track1_abi_and_mono_probe.lean` and `round2_track1_probe.lean`).
3. **Layer 2: Block-Argument SSA (`ANSSA`), Escape-Tracked `mem2reg`, and MIR Semantic Hazards**:
   - **Scope**: Converts `MonoMIR` into Cranelift/MLIR-style **Block-Argument SSA (`ANSSA`)**, avoiding LLVM $\phi$-node parallel-copy swap anomalies by making block arguments explicit parallel assignments on CFG edges (`Terminator.jump target args`). Promotes non-escaping stack locals (`Place.local`) whose addresses are never taken (`Rvalue.addrOf`) into pure SSA registers while keeping address-taken locals in `MemState`, and enforces immediate dead-local poisoning on `Statement.storageDead`, explicit sub-word sign/zero extension, and eager niche-tag writeback on `PlaceElem.downcast` + field mutation (`track3_ssa_mem2reg_niche_probe.lean`).
4. **Layer 3A.1 (Path A): ISLE Instruction Selection, `aegraph` GVN, BTL Symbolic Execution, and DST/Vtable Lowering**:
   - **Scope**: Lowers `ANSSA` expressions via Cranelift's ISLE term-rewriting DSL and acyclic e-graphs (`aegraphs`), lowers fat pointers (`&dyn Trait`, `&[T]`) using aligned tail offset formulas (`alignTo(headSize, tailAlign)`) and immutable `.rodata` vtable descriptors (`vtable_memflags()` with `readonly + aligned + can_move`).
   - **Verification**: A **CompCert-BTL-style Superblock Symbolic Executor (`validateSuperblockWithMem`)** checks equivalence of each source `ANSSA` block and target `MachIR` block with `BitVec.eq_of_toNat_eq` and `bv_omega`/`omega` (avoiding `bv_decide` / `Lean.ofReduceBool`) discharging individual rewrite rules (`validateSuperblockWithMem_sound` in `track5_isle_egraph_dst_probe.lean` and `round2_track4_probe.lean`).
5. **Layer 3A.2 (Path A): Repaired `regalloc2` Symbolic Checker, `Stacking`, and Quantitative Stack Bounds**:
   - **Scope**: Runs `bytecodealliance/regalloc2`'s fast allocator followed by a **repaired, Lean-verified symbolic checker (`checkRegAlloc`)** and lowers virtual spill slots and callee-saved register saves into a concrete stack frame (`StackIR`) with an exact per-call-graph byte bound (`maxStackDepth : Nat`).
   - **Verification**: Proves that any allocation accepted by the repaired `checkRegAlloc` refines `ANSSA`/`MachIR` (`checkRegAlloc_sound`) and that when `initialSP ≥ maxStackDepth prog`, execution never faults on `FailureKind.stackOverflow` (`stack_bound_prevents_overflow` in `track4_regalloc2_stacking_probe.lean` and `round2_track3_probe.lean`).
6. **Layer 3A.3 (Path A): `MachBuffer` Binary Emission, Two-Pass Branch Relaxation, and Unwind/CFI Tables**:
   - **Scope**: Resolves symbolic labels into concrete PC-relative byte offsets via two-pass branch relaxation and constant-pool island insertion, emits DWARF `.eh_frame` Call Frame Information (including AArch64 `PACIASP`/`AUTIASP`), and emits `.gcc_except_table` LSDA tables with `EXCEPTION_HANDLER_TERMINATE_FILTER` (`ttype_index = -1`).
   - **Verification**: Validated by executable layout/relocation and CFI/LSDA checkers (`machBuffer_twoPass_sound`, `repaired_filter_phase1_and_phase2_sound`, `aarch64PrologueEpilogueCfi_sound`).
7. **Layer 3B (Path B): Verified `ANLLVM` Lowering, Tree Borrows `noalias`, and Binary Translation Validation**:
   - **Scope**: Lowers `ANSSA` to a pure Lean 4 LLVM IR model (`ANLLVM`) with true nondeterministic `freeze` semantics (fixing `lean-mlir`'s `freeze poison = 0` defect), directional peephole refinement (`DirectionalRewriteRefine`), and a machine-checked simulation from Tree Borrows `Frozen`/`ReservedIM` permissions to LLVM `noalias` and `readonly` attributes (`tree_borrows_frozen_implies_llvm_noalias_sound`). Validates the optimized ELF binary produced by `llc -O2` back against `ANLLVM` using an `seL4/graph-refine` symbolic execution graph validator (`checkGraphRefinement_sound`, `checkUnrolledLoopRefinement_sound` in `track6_llvm_lowering_and_binary_tv_probe.lean` and `round2_track5_probe.lean`).
8. **Layer 4: Target ISA Bridge, `MemStateInj`, Weak-Memory Atomics, Constant-Time, Bare-Metal ELF, and Compositional Linking**:
   - Connects compiled machine code to abstract `MemState` (`MemStateInj`), hardware weak-memory models (`LDAR`/`STLR`, LL/SC & LSE RMW, `SeqCst` fences), cryptographic constant-time leakage preservation (`CTSimulation`), bare-metal ELF `.data`/`.bss` startup initialization (`elfBootInit_establishes_fullMemInj`), inline assembly (`@[candidate inline_asm]`), and multi-crate / C FFI linking (`OpenModule.Refines`, `Module.link`).

### 2. Core Architectural Trade-Off Analyses and Upstream Soundness Bugs

`Basis: comparative evaluation, source audits, and mechanized prototypes across all 8 specialist packages`

#### 2.1 Direct Native Certifying Codegen (Path A) vs. LLVM + Binary Translation Validation (Path B)

| Engineering Dimension | Path A: Direct Native Certifying Codegen (`ISLE` + `regalloc2` + `Stacking` + `MachBuffer`) | Path B: Verified `ANLLVM` Lowering + `seL4/graph-refine` Binary Translation Validation |
| :--- | :--- | :--- |
| **Runtime Optimization Quality** | Equivalent to Cranelift `-O2` / CompCert (SSA GVN, algebraic ISLE rewrites, coalescing register allocation); no auto-vectorization or polyhedral loop nests | Full production LLVM `-O2`/`-O3` performance (inlining, SLP/loop vectorization, aggressive loop unrolling, target-specific scheduling) |
| **Verification & Check Predictability** | **100% deterministic linear/quadratic-time checkers** in Lean (`checkRegAlloc`, `validateSuperblockWithMem`, `checkCFITable`); never times out | SMT/symbolic graph equivalence can fail or time out on heavily vectorized or restructured multi-loop nests (requiring `-fno-vectorize` or loop annotations) |
| **Cryptographic Constant-Time (`CT`)** | **Provably preserved by construction** (`ctSimulation_preserves_constantTime`): ISLE rules and `regalloc2` spill slots forbid secret-dependent branches | LLVM `-O2` routinely introduces secret-dependent branches (`SimplifyCFG` turning `select` into branches); must be verified post-hoc on binary traces |
| **Quantitative Stack Bounds & DWARF Unwind** | Exact static frame sizes from `Stacking` (`stack_bound_prevents_overflow`) and constructive `.eh_frame`/LSDA generation | Must reconstruct stack bounds and CFI invariants by disassembling the LLVM-emitted ELF binary |
| **Compile-Time & Bootstrap Footprint** | Fast single-binary compilation; supports self-hosting (`Anc` written in verified Rust) without a 30M-LOC C++ LLVM dependency | Requires unverified C++ `llvm-project` at compile time (removed from TCB per-build via binary TV, but remains a build-availability dependency) |

Because both paths implement the same `Compiler ANSSA MachLang` interface in `theory/Anneal/Compiler/`, **Path A serves as the primary deterministic verified backend** while **Path B serves as an opt-in high-performance backend** for compute-intensive kernels, mixed per-function or per-module via `OpenModule` and `Module.link`. Similarly, **type, layout, memory, and ABI boundary transforms** (`MonoMIR`, `ANSSA` `mem2reg`, `Stacking`, `MemStateInj`, `OpenModule`) use universal forward/backward simulation proofs ($\forall p,\; \text{SoundOn}(C, p)$), whereas **combinatorial/heuristic intra-procedural passes** (ISLE + `aegraph` GVN, `regalloc2`, `MachBuffer` branch relaxation, DWARF `.eh_frame` CFI) pair an untrusted fast pass with a verified symbolic certificate checker ($\forall p, p',\; \text{check}(p, p') = \text{true} \implies \text{SoundOn}$).

#### 5.1 Diverse Double-Compiling (`DDC`) vs. Checker Soundness (`support/ddc-and-proof-produced-checker-executables/ddc_witness.py`)

Wheeler's Diverse Double-Compiling (`DDC`, 2009 dissertation §§4.2, 5.6, 5.7 and Prover9 input `ddc.in`) builds `stage1` by compiling parent compiler source $s_P$ with a trusted diverse compiler $c_T$, and builds `stage2` by compiling candidate compiler source $s_A$ with `stage1`. Proof #1 concludes:
$$\text{stage2} = c_A \implies \text{exactly\_correspond}(c_A, s_A, ls_A, e_{A,\text{run}})$$
under the explicit assumptions that $c_T$ accurately compiles $s_P$ and that an accurately compiled $s_P$ is a valid compiler for $s_A$.

Crucially, **source-to-binary correspondence is orthogonal to algorithmic checker soundness**, as demonstrated in our executable finite model `support/ddc-and-proof-produced-checker-executables/ddc_witness.py` (results recorded in `support/ddc-and-proof-produced-checker-executables/ddc-results.json`):
1. **Trojaned binary with clean source**: An infected binary $c_A$ compiling clean source $s_A$ reproduces the infection in a naive self-regeneration test (`stage1 = stage2`), whereas DDC using a diverse compiler $c_T$ produces the clean binary in `stage2` and detects the mismatch (`stage2 ≠ c_A`).
2. **Buggy source with faithful binary**: When the soundness defect is present in the source $s_A$ itself, DDC passes (`stage2 = c_A`, confirming $c_A$ faithfully implements $s_A$), while the independent checker soundness predicate fails. Thus, DDC can discharge binary-provenance trust, but never substitutes for a machine-checked soundness theorem of the checker or compiler algorithm.

## Boundaries

1. **`trusted/lean/` vs. `theory/Anneal/` Placement and `deriving`-Free Syntax**:
   Only primitive AST/machine definitions (`MirAst`, `MirSemantics`, `HwIsaState`, `HwIsaMachine`, `HwIsaLang`, `π_isa`, and `CrateTheorem`) belong in `trusted/lean/` (which must contain zero theorems). All lowering functions (`lowerMirBody`, `f_spec`), certificate checkers (`checkCert`, `beqHwIsaProg`), functional translation definitions (`evalSym`, `translatePure`), and soundness/bootstrap theorems belong in `theory/Anneal/`. Note that while `support/track2_self_hosted_compiler_probe.lean` uses `deriving DecidableEq` on `IsaProg` (elaborating to constructive decision procedures with zero extra axioms), `support/round2_track2_probe.lean` eliminates all `deriving` clauses completely using explicit `beq*` functions to match `TrustedBoundary.lean` Phase 1 syntax rules.
2. **Scope of Mechanized Slice, ADT, and Hardware Models in `support/round2_track2_probe.lean`**:
   `MirVal.refSliceLoc` models shared immutable slices (`&[usize]`); mutable slices (`&mut [T]`) and growable `Vec<T>` buffers require extending `LoanEntry` backward lenses or spatial heap predicates (`not yet modeled`). `hwToMirState` (`support/round2_track2_probe.lean:4373-4385`) lifts 2 register arguments (`rdi`, `rsi`); functions with $>6$ integer arguments or stack-spilled `PassMode::Indirect` frames require composing `π_isa` with the full `FnAbi` marshaling invariants.
3. **Frontend Typechecking, Floating-Point NaN Payloads, and Preemptive Context Switching**:
   The verification boundary begins at `Runtime(PostCleanup)` MIR. IEEE 754 floating-point NaN payload nondeterminism and full preemptive OS scheduler context switches require composing the integer/pointer compilation pipeline with Sail/Flocq NaN-canonicalization refinements and out-of-line assembly context-save invariants.
4. **External CompCert, CakeML, CertiRocq, and HolBA Replay Scope**:
   While `support/track2_self_hosted_compiler_probe.lean`, `support/round2_track2_probe.lean`, `support/staged-code-generation-and-certirocq-endpoint-linkage/WasmValidator.lean`, `support/staged-code-generation-and-certirocq-endpoint-linkage/WasmArtifact.lean`, and `support/ddc-and-proof-produced-checker-executables/ddc_witness.py` were executed and verified locally, no fresh Coq/Rocq or HOL4 builds of CompCert, CakeML, CertiRocq, or HolBA were executed (`not examined`). In the WebAssembly experiment, normative Wasm instruction interpretation and Node.js `24.21.0` / V8 JIT execution remain external premises outside the Lean 4 kernel proof.
