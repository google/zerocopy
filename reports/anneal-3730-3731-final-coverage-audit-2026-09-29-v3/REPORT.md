## Evidence changes that matter most

- **Subject identity:** the Charon `--test` result can be the wrong compilation unit despite exit 0, making requested target flags and output pathname insufficient evidence of the captured unit. The manifest and file-limit control also show why process exit and parseable last-good bytes need separate checks. These results strengthen I076/I078 and D05–D07, but the explicit unit-key selector and transactional Anneal publication are absent.
- **Lean worker freshness:** the two cached Lean versions now have a transitive dependency, option, macro and native-plugin transition with old/new worker divergence. A real rich RPC reference survived a transition and failed after release. This strengthens I041–I050 and C02/C09, without implementing a source/import/version-bound MCP response.
- **Lake cache integrity:** a partially written output map was detected and repaired, but a deliberately corrupted object under its existing cache name was still selected; direct Lean then crashed. These are different failure classes. I102/F11 now have an actual mapping-write interruption rather than only a kill during elaboration, yet concurrent object/map publication safety remains open.
- **End-to-end selected claims:** the hand-built Rust→Lean vertical shows that Lean exit 0 can coexist with a missing required claim, an admitted false claim, or a stale imported generation. Its acceptance gate rejected each on separate coverage, axiom, or source identity evidence. This sharpens I129–I132/I135/I159, but the obligation set and identity gate are experiment code, not Anneal behavior.
- **Human interpretation:** the I141 protocol is ready for a truthful rendered UI and consenting participants. It adds no measured comprehension rate or observed user mistake.
