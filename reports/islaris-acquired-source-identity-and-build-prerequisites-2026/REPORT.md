# Islaris acquired-source identity and build prerequisites

## Summary

The exact 74-package Islaris dependency selection, including all 35 requested roots, was acquired by opam 2.1.6 with `install --download-only`: exit 0 in 107.592145 seconds, with empty stderr and no installed packages or pins afterward. An offline audit bound all 43 deduplicated source artifacts to their declared identities and materialized consumers: 35 HTTP objects with all 63 declared checksum comparisons, and eight fixed Git commits with their current source trees. The original GitLab and INRIA source URLs worked during this acquisition; no replacement URI was used.

The verified scope is deliberately narrower than a build. Archive comparisons establish regular-file bytes and owner-execute bits, plus symlink targets; they do **not** establish archive directory identity, complete Unix modes, ownership preservation, or hardlink topology. Exact absence of extra source entries was established only for the 21 Git copies. Separately, all 154,231 observed cache/root filesystem entries and 115,763 regular-file hashes were unchanged before and after the audit. An independent artifact/code review passed within these limits. No package was built, no Z3 compatibility was tested, and no Islaris theorem was checked. The public evidence is an explicit projection: it retains 232 of the original 238 audit files, omitting all six raw external extra-source bodies under one publication rule. Every identity/check record and actual experiment claim remains unchanged.

## Findings

### Acquisition preserved the selected identities without installation

Basis: execution + metadata inspection. The [successful phase receipt](support/acquisition/download-phase.json), [stdout](support/acquisition/download.stdout), [empty stderr](support/acquisition/download.stderr), [raw native JSON](support/acquisition/native-acquire-result.json) and [selection gate](support/acquisition/source-selection-gate.json) bind the actual command and all 74 selected versions to all 35 ordered roots. The JSON contains a repeated `command-line` key with identical arrays. Duplicate-aware extraction checked this equality; the raw bytes were preserved rather than silently rewritten. [Installed](support/acquisition/post-installed.stdout) and [pin](support/acquisition/post-pins.stdout) observations were empty after the download-only operation.

Acquisition ran as UID/GID 1000 with one CPU, 1 GiB memory, no host mounts, one fetch job and one opam job. The source-download phase had network access, a 900-second timeout with five-second kill grace, a 4 GiB source-root stop threshold and a 16 GiB host-free-space floor. These are the actual phase limits; the earlier 512 MiB proposal in the preserved plan was not the eventual source-download allocation. Peak process memory was not measured. The source container was stopped and retained after success. Exact container configuration, controller argv, polling and status receipts are in the acquisition archive.

### All source-bearing records were reconciled to cache and source copies

Basis: source + execution + derived correspondence. Of 74 package records, 65 have source or extra-source sections and nine do not. Their 68 role/consumer associations deduplicate to 43 artifacts: 29 HTTP archives, six HTTP extra files and eight Git sources. There are 62 materialized main-source directories: 41 archive copies and 21 Git copies; three further packages have only extra-source files. These counts describe different relations and must not be interchanged. [Consumer coverage](support/audit-summary/consumer-coverage.json) and the artifact inventory retain the complete mapping.

For the 35 HTTP objects, the original audit checked every declared algorithm, including SHA256, SHA512 and MD5 where declared; every object had a strong declared hash. It also computed transport SHA256 while streaming the archive bytes into the host-side parser. The [transport ledger](support/audit-summary/http-object-map.json) binds actual bytes, rather than merely repeating declared checksums. The total observed HTTP transport size was 62,541,749 bytes. Across 41 archive consumers, 67,569 member/source-copy comparisons matched, including allowed extra files. Regular-file contents, regular owner-execute bits and symlink targets matched. Directory entries, complete permission bits, preserved ownership and hardlink inode relationships were outside this archive comparison. A hardlink was checked as byte-equivalent regular content. No exact archive directory/no-extra-entry claim follows.

For Git, all eight HEAD commits matched their fixed source revisions; none was shallow, and none of the current trees contained a gitlink. Strict full `fsck` receipts returned zero with empty streams. Current commit, recursive tree and blob bodies were streamed using `git cat-file --batch`, checked with Git SHA1 object framing and SHA256, and matched against the complete expected object sets. There were 4,998 per-repository distinct object comparisons, comprising 4,935 globally unique object IDs; shared objects explain the difference. This was not a complete remote-history authentication claim. No `git archive` transformation was used.

All 21 Git consumer copies matched their complete tracked file and directory sets, regular bytes, Git executable/nonexecutable distinction and symlink targets, with no extra entries after excluding exactly `.git` and its descendants. All 21 object alternates pointed to the exact expected local object store; their newline-free bytes were checked. Configurations matched their frozen file hashes and contained no external include/filter/credential sections. Git ran with optional locks disabled, global/system configuration disabled, fsmonitor and untracked cache disabled, and hooks redirected to `/dev/null`. No source or Git repository was written.

### Filesystem stability is a separate observation

Basis: execution. The audit container used one CPU, 1 GiB RAM and 128 PIDs, with network mode `none`, no host mounts and UID/GID 1000; writes were restricted to `/audit`. Its grant was bounded to 15 minutes; no additional allocation or installation was made. The [unchanged-state result](support/audit-summary/unchanged-state.json) binds complete NUL-framed before/after inventories: all 115,763 regular-file hashes and all 154,231 seven-field entries were byte-identical, including observed type, mode, owner, size and symlink target. This establishes stability of the observed filesystem, including directories. It does not establish that archive extraction originally preserved every upstream directory or ownership property. All 19,429 acquisition metadata/config input files and all 74 selected metadata bindings also matched. No opam install/build command ran during the audit; build/install/bin directories remained empty and no switch state file was present.

Observed apparent sizes were 1,524,081,218 bytes for the opam root, 212,005,364 for download cache and 1,286,338,476 for source directories. Allocated sizes were respectively 1,816,207,360, 212,185,088 and 1,578,213,376 bytes. These are overlapping scopes, not quantities to sum. They are measurements of the acquired subject, not estimates of build space or peak memory.

### The acquired sources expose concrete build and proof gates

Basis: exact source inspection. Old Sail's [INSTALL.md](support/source/old-sail/INSTALL.md), lines 21–27, requires an external `z3`, GMP development headers, `pkg-config` and zlib development headers. Lines 40–46 discuss problems with older Ubuntu Z3 packages but do not supply an exact historical minimum. In [constraint.ml](support/source/old-sail/src/lib/constraint.ml), lines 95–105 and 128–131, the default solver is external `z3` with `-t:1000 -T:10`. No exact compatible Z3 version was determined, selected or executed.

The old RISC-V [Makefile](support/source/old-riscv/Makefile), lines 383–388, passes `-dcoq_undef_axioms` during Coq generation. Lines 405–413 require generated outputs for **both RV64 and RV32** and install both architecture directories with common support. Thus an RV64-only build would not realize this package's declared install path. Any later proof result must inventory the actual generated undefined-operation axioms and theorem assumptions; source identity does not establish an axiom-free Sail-origin theorem.

Read-only package/PATH inventory found GCC/G++ 12.2, build-essential, make, binutils and libc development support. It found no Z3 executable in the inspected PATH/named-binary inventory and no installed Z3/libz3 package record; no Z3 program was executed. `pkg-config`/`pkgconf`, `libgmp-dev` and `zlib1g-dev` were absent from installed package records and are likely missing declared development prerequisites. `m4` was also absent; its necessity remains build-path dependent. [System observations](support/audit-summary/system-package-observations.json) preserve this bounded inventory. The already cached official AArch64 Z3 4.15.3 archive is a possible separately authorized compatibility candidate, not a selected or validated dependency here.

## Boundaries

No source installation, patch application, package build, Coq compilation, theorem replay or assumption inventory occurred in this phase. In particular, current selected Menhir `20260209`, Lem `2026-05-01` and Yojson `3.0.0` are acquired dependency choices, not compatibility evidence with old Sail 0.17. No source checksum, Git identity, opam dry solution or successful download proves compiler correctness, exported-CUDF translation correctness, dependency build compatibility or proof correctness. Source acquisition has crossed the former URL-availability gate for this exact run, not established permanent remote availability.

The archive and review limitations in Summary and Findings constrain every identity statement here. The raw original [RESULTS.md](support/raw-audit-results.md) is deliberately preserved unchanged, including its overbroad shorthand about archive modes. This report's narrower regular-owner-execute-bit interpretation is the intended account. Before/after stability and Git no-extra-entry results must not be used to strengthen archive-origin claims.

Actual failures were retained rather than treated as source failures. The first native observer requested unavailable Python and returned 127 before starting; existing native find/hash/Git tools plus isolated host Python replaced that observer without installation. A host predicate incorrectly excluded every `.git` prefix, losing `.github`; it was corrected to exclude only exact `.git` and its descendants. Positive `.github`, `.github/workflows` and `.gitignore` controls and genuine `.git` exclusion controls passed before accepting all 21 copies. A later config lookup expected tar members although raw config bytes were in stdout; corrected framing was checked against all 21 native file hashes. Rejected code, results and diagnostics remain in the frozen audit. These were observer/controller defects, not changes to source inputs. There were 13 native phase receipts: that initial 127 and twelve zero exits, with no panic or source-identity mismatch. Their summed controller phase times were 50.225973 seconds, not total research time or CPU time; peak audit memory was not measured.
