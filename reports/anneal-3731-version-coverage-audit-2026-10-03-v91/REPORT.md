# Version coverage audit and source-supplement index, v91

## Summary

This v91 index integrates three bounded version follow-ups with the published 651-row v90 matrix: R578's already-published CompCert development-source comparison, a Lean/Lake v4.35.0-rc3 source-only R414 supplement, and a Rust 1.99.0/Cargo source-only R349/R351 supplement. It records Rust 1.99.0 as a newer stable release in the **55** v90 rows whose exact target text named 1.98.1. The original 581 version-inventory classifications, pinned subjects, runtime coverage, feasibility fields, and issue statuses remain unchanged. No new tool behavior was executed here.

## Findings

Basis: pinned published Git objects, frozen source reports, and the Rust supplement's exact [matrix-delta.json](support/source-inputs/rust-matrix-delta.json). [Delta metadata](support/delta.json) gives every old and new cell for the **58** changed baseline rows. All other original v90 CSV lines remain byte-for-byte identical.

- **R578:** The frozen classification stays `no_newer_release` for official CompCert releases. The [published R507/R578 source review](../sel4-compcert-everest-current-source-review/REPORT.md) found development `master@66a9fd06` four commits ahead of the pinned 3.18 source `74cbdbf0`. Its three R578-mapped files retained identical Git blobs. The v90 row had omitted this published source evidence; v91 updates only `source_coverage` and `source_evidence_path`. No Coq proof or compiler runtime was retested.
- **R414:** The Lean/Lake [source-only supplement](../lean-lake-4350rc3-output-reference-routing-source-followup-2026-10-03/REPORT.md) compares stable 4.34.1 (`5045d005`) with tagged prerelease 4.35.0-rc3 (`470d5ce1`). The mapped `Build.Common` output-reference insertion condition changes from `pkg.isRoot` to `pkg.wsIdx = ctx.outputsIdx`; the direct `Cache.writeOutputs` call remains. v91 adds this narrow source evidence to R414's source cells, retaining its stable target text and unexecuted runtime. It does not upgrade the other Lean/Lake or Mathlib rows.
- **R349/R351:** The Rust [source-only supplement](../rust-199-cargo-source-followup-2026-10-03/REPORT.md) pins Rust 1.99.0 (`b940084d`) and its Cargo gitlink (`5f94df47`). It finds an Edition 2024 inherited `default-features` parser change mapped to R349 and a CI incremental-default profile change mapped to R351. Their source cells gain report evidence; R351 also gains the exact newer target. The source result does not negate the original contextual-feature or cache-mechanism distinctions. No 1.99 Cargo/rustc runtime was executed.
- **Rust availability:** Applying the supplement's exact-value selector changes `newer_target` in precisely 55 rows from 1.98.1/nightly availability to stable 1.99.0 availability, while explicitly keeping the old version checks pinned and marking 1.99 behavior unreviewed outside R349/R351. No other source cells change in those 55 rows. R349 is among the 55, so the total distinct baseline rows changed is 58: the 55 target rows plus R351, R414, and R578.

## Revalidation

From this package in a checkout containing the base commit, run `python3 -B support/check.py --reference-root /path/to/zerocopy --staged-reports-root /path/to/reports`. The checker uses no network or Lean/Lake build. It reconstructs the v91 CSV from the base Git matrix and frozen source inputs; checks the Rust 55-row selector and R349/R351 old values; verifies R578's official-release/development-revision distinction and mapped blobs; checks R414's source scope; compares every unchanged baseline CSV line byte-for-byte; and verifies the three staged `REPORT.json` files against the catalog additions and both source package file inventories. `python3 -B support/build_delta.py --reference-root /path/to/zerocopy` regenerates the three derived support files. Run `python3 tools/reference.py check` at the reference corpus root for whole-tree structural validation.
