# Rust Verifier IR Boundaries, Spatial Resource Contracts, and Symbolic Completeness

## Summary

Rust formal verification systems partition the semantic boundary between `rustc` intermediate representations (THIR, MIR, LLBC, VIR, Radium, Goto-C), spatial memory ownership disciplines, and logical proof assistants along five tightly coupled axes:

1. **MIR/IR Semantic Encoding Boundaries Across Borrows, Control Flow, Polymorphism, and Bytes:** Comparing Anneal (`joshlf/anneal@c065b55a3a143ec3f6a4f9c8166bd9e6a4c4633b` and `d79b0c070cf4115b523fe6ee62c1e72504de2254`), Charon (`1e08453924610c19d74c245a7308f17c1008e2db`) + Aeneas (`21345f80fa212c596f6437378d7d57984fa2ea77`), Creusot (`c4e9770ac1371ac4274bfe02145266d315c2fb86`) + Coma (`a52ad7b745fb8a1d0b54bf52b54f0cfaec18e59f587eda551a54702cf61a8d8e`), RefinedRust (`34573bac60de68c3597c23136cd5221a7129f89a24b69340f8e361750f331d53`), Verus (`0141ebc6f14410dfc87fef1da57408578002eb7c`), Kani (`9461e07af7ec929f050aa4192f29363c9be07779`), and MiniRust (`d821c6e3a3d358fa8a556774dc12b4aa5d0d65ed`), together with 15 kernel-checked Lean 4 theorems in `support/rust-verifier-mir-ir-boundaries-borrows-loops-traits-and-bytes-2026/VerifierEncodingComparison.lean`, establishes:
   - Frame-relative path lenses (`MirVal.refVal frameId localIdx proj mutability`, `resolvePlace`, `writePlace`) and functional backward functions/prophecies (`LoanEntry`, `Bor { cur: *p, final: ^p }`) produce bit-identical updated root values for acyclic single-owner mutable borrows (`lens_prophecy_equiv`) and multi-frame mutable reference chains (`cross_frame_ref_writeback_sound`), while escaping stack references fail closed (`escaping_ref_fails_closed`) and aliased raw-pointer-derived mutable references suffer silent last-writer-wins clobbering (`aliased_backward_lenses_clobber`) unless guarded by spatial disjointness (`(AllocId, Offset)` + Stacked/Tree Borrows).
   - Direct execution over uncanonicalized diamond control-flow graphs produces non-unifiable `MirState` terms at join blocks due to dead branch-local temporaries (`raw_diamond_join_states_ne`) and asymmetric `StorageDead` generation bumps (`asymmetric_storageDead_gen_mismatch`). Compiler-side canonicalization (`canonicalizeLocals`, proved in `canonicalize_join_unifies`, `execNormal_diamond_joined`, and `canonicalize_preserves_return`) restores syntactic equality at joins without changing return values.
   - A two-stage parameterized monomorphic envelope (`ConstsTotal` over layout predicates + `MonoAdmitted` over substituted `MirBody` definitions) is sound, whereas size-only layouts without alignment divisibility (`dst.align ∣ src.align`) admit unaligned reference transmutations (`size_only_insufficient_for_ref_transmute` vs. `pme_ref_transmute_sound`).
   - Algebraic ADT representations augmented with an explicit `paddingBytes` layout witness match `AbstractByte` (`Init(u8, Option<Provenance>) | Uninit`) semantics for padding-free types (`intoBytes_iff_paddingFree`) while rejecting padded `transmute` to integer targets (`padded_transmute_to_int_reads_uninit`).
2. **Unsafe-Rust Resource Primitives Across VeriFast, Verus, and Creusot:** VeriFast (`verifast/verifast@0a83dba42db7ce0b445034ece5298afe980e57dc`, `arXiv:2601.13727v1`), Verus (`verus-lang/verus@0141ebc6f14410dfc87fef1da57408578002eb7c`), and Creusot (`creusot-rs/creusot@c4e9770ac1371ac4274bfe02145266d315c2fb86`) all replace unmarked raw pointer dereferences with explicit ghost resource tokens (`<T>.own`/`<T>.share` in VeriFast, `PointsTo<T>`/`PointsToRaw`/`Dealloc`/`PCell` in Verus, and `Perm<*const T>`/`PermCell`/`AtomicI32` with ordering-parameterized invariants in Creusot). However, VeriFast's foundational Rocq export (`SymexSoundness.v`, `AxSem.v`) leaves `wp_Program` and `StorageLive`/`StorageDead` rules `Admitted`; Verus's `PointsToRaw` omits a byte-value map; and Creusot rejects MIR `BinOp::Offset` pointer arithmetic (`backend/program.rs:688`).
3. **Semantic Domains, Representation Relations, and Spatial Composition:** Across RustBelt (LambdaRust), RustHornBelt, RefinedRust (Caesium/Radium), MiniRust, Aeneas (PL/LLBC), and Corten (`arXiv:2609.04372v1`), pure functional translation suffices only when types satisfy a seven-component representation relation $\mathrm{Rep}_T(v, p, r)$ covering numerical geometry, byte initialization, representation validity, pointer provenance, spatial resource authority, lifetime/retag state, and pure value abstraction. Corten's THIR-to-Rocq weakest-precondition calculus (`hax2rocq` + defunctionalized continuations over a fractional forest of values) still depends on pending foundational axioms for variable, borrow, aggregate, control, call, and pattern rules (Appendix G Table 4).
4. **Symbolic Execution and Model Checking Completeness Boundaries:** Kani (`model-checking/kani@9461e07af7ec929f050aa4192f29363c9be07779`), Crux-MIR (`GaloisInc/crucible@7f49dac06c656f7b92c8b6cc054f47c63b60abe4`), and Soteria (`10.1145/3808306`, Zenodo `19080425`) enforce distinct completeness trade-offs: Kani's CBMC backend disables uninitialized-memory shadow checks (`check_uninit`) whenever function contracts or stubbing are enabled; Crux-MIR uses reference-cell tags rather than byte provenance and defaults to unbounded loop exploration unless `--iteration-bound` or `--recursion-bound` is set; and Soteria's Tree Borrows engine omits strong-protector deallocation checks (`tree_state.ml:675-689`) while mapping fuel-exhausted `OkPartial` runs to process exit code `0` (`outcome.ml:3-19`).
5. **Admission Diagnostics, Vacuity Checks, and Proof Certificate Transport:** Anneal's admission pipeline (`admission.py`, `prepare.py`, `workspace.py`, `inline.py`) and Lean verifier (`Check.lean`, `RustModel.lean`, `FunsExternal.lean`) enforce fail-closed source admission, dictionary-passing resolution, and non-vacuous required-contract checks, verified across 10 synthetic admission controls in `support/rust-admission-diagnostics-and-proof-transport-cce761ad/admission-control-results.json`. At the external solver boundary, SMTCoq (`smtcoq/smtcoq@7b870140f2ff7e4547a7db614a305d8b2945afa3`), Carcara (`ufmg-smite/carcara@20bf49c5ce31089ac83118574c888669355aaae1`), and LFSC (`cvc5/LFSC@5a127dbbcf9a0f822768e783dbf892ee90c435d5`) reveal concrete certificate-transport gaps: SMTCoq disables `c_bitblast` in its compiled checker (`MainChecker.v:1066`), Carcara returns `CheckResult::Holey` or suppresses rule failures under `Config.allowed_rules`, and LFSC trusts side-condition C++ code (`check.cpp:1292-1347`) outside the Lean kernel.

#### Axis 1: Borrows, Reborrows, Two-Phase Borrows, and Raw Pointers

`support/rust-verifier-mir-ir-boundaries-borrows-loops-traits-and-bytes-2026/VerifierEncodingComparison.lean` formalizes three reference encodings and proves four boundary theorems:
- **Lens-Prophecy Equivalence (`lens_prophecy_equiv`):** For any single-owner mutable borrow of a struct field (`&mut s.f`), evaluating a mutation via frame-relative path lenses (`Axis1Borrows.evalLensWrite s idx v'`) and via Aeneas/Creusot backward functions (`Axis1Borrows.evalProphecyWrite s idx v'`) yields identical updated structures (`evalLensWrite s idx v' = evalProphecyWrite s idx v'`).
- **Multi-Frame Callee Writeback (`cross_frame_ref_writeback_sound`):** When frame $0$ passes `&mut local_1[fieldIdx]` (`MirVal.refVal 0 1 [ProjElem.field fieldIdx] true`) to callee frame $1$, executing `writePlace` inside frame $1$ updates frame $0$'s root local in place while leaving callee locals untouched.
- **Escaping Stack Reference Rejection (`escaping_ref_fails_closed`):** Returning a reference pointing into the exiting callee frame (`frameId = calleeFrameId`) is rejected by `returnRefsOk`, preventing dangling stack references from escaping into caller state.
- **Aliased Backward-Lens Clobbering (`aliased_backward_lenses_clobber`):** When `unsafe` code constructs two co-live mutable references `(b1, b2)` to the same root from raw pointers, sequential backward writebacks overwrite `b1.final` with `b2.final` (`evalAliasedBackward s v1 v2 = v2` with `v2 ≠ v1`), silently discarding the first mutation. Unsafe raw-pointer aliasing therefore requires spatial disjointness (`(AllocId, Offset)` + Stacked/Tree Borrows tags in RefinedRust/MiniRust or explicit `PointsTo<T>`/`Perm<*const T>` tokens).

#### Axis 2: Loops, Unstructured CFG Joins, and State Canonicalization

When lowering `rustc` MIR into Lean 4 or Rocq, diamond control-flow graphs (`bb0 -> {bb1, bb2} -> bb3`) assign branch-local temporaries (`_2` in `bb1`, `_3` in `bb2`) or execute asymmetric `StorageDead` statements that increment per-local generation counters (`bumpGen`). In `support/rust-verifier-mir-ir-boundaries-borrows-loops-traits-and-bytes-2026/VerifierEncodingComparison.lean`:
- **`raw_diamond_join_states_ne`** proves `execDiamondTrue c ≠ execDiamondFalse c` when branch temporaries remain in `MirState.locals`.
- **`asymmetric_storageDead_gen_mismatch`** proves that bumping generation counters on only one branch (`bumpGen st 2 ≠ st`) prevents join-block unification even when local values match.
- **`canonicalize_join_unifies`**, **`execNormal_diamond_joined`**, and **`canonicalize_preserves_return`** prove that clearing dead branch-local temporaries and resetting non-live generation counters at join blocks (`canonicalizeLocals liveMask st`) unifies both branch states into a single symbolic `MirState` (`canonicalizeLocals [true, true, false, false] (execDiamondTrue c) = canonicalizeLocals [true, true, false, false] (execDiamondFalse c)`) without altering `_0`, collapsing $2^k$ sequential diamond paths to $O(k)$ symbolic states.

#### Axis 3: Generics, Trait Resolution, and Parameterized Monomorphic Envelopes (PMEs)

Rather than requiring either per-concrete-type harness duplication or full polymorphic dictionary translation for layout-generic code (such as `zerocopy::transmute_ref!`), Axis 3 formalizes a two-stage Parameterized Monomorphic Envelope (PME) in `VerifierEncodingComparison.lean`:
- **Stage 1 (`ConstsTotal`):** Proves once, universally over `TypeLayout` parameters (`size`, `align`, `paddingBytes`, `isZst`), that the `const` layout check (`checkSameSizeAndAlign src dst`) is total and implies the target alignment and size invariants.
- **Stage 2 (`MonoAdmitted`):** Instantiates the parametric `MirBody` via `MirBody.subst` for any concrete type env $\sigma$ satisfying `ConstsTotal`.
- **`size_only_insufficient_for_ref_transmute`** constructs the counterexample `srcLayout_u16x2 = { size := 4, align := 2, paddingBytes := 0 }` (`[u16; 2]`) and `dstLayout_u32 = { size := 4, align := 4, paddingBytes := 0 }` (`u32`) at address `addr = 2`, proving that equal size alone violates target alignment (`¬ isAligned 2 dstLayout_u32`). **`pme_ref_transmute_sound`** proves that enforcing `dst.align ∣ src.align` preserves alignment across all valid source addresses.

#### Axis 4: Bytes, Padding, `MaybeUninit`, Unions, and `transmute`

Comparing byte-exact memory (`AbstractByte.init b prov | AbstractByte.uninit`) against algebraic ADT values (`MirVal.adt`) in `VerifierEncodingComparison.lean` proves:
- **`intoBytes_iff_paddingFree`:** An initialized algebraic value with layout `L` encodes to a fully initialized byte sequence (`allInit (encodeWithPadding fieldBytes L.paddingBytes) = true`) if and only if `L.paddingBytes = 0`.
- **`padded_transmute_to_int_reads_uninit`:** Whenever `L.paddingBytes > 0`, `decodeFixedUInt (encodeWithPadding fieldBytes L.paddingBytes)` returns `none` (corresponding to undefined behavior when reading uninitialized padding bytes as an integer in MiniRust, Caesium, and `rustc`).

### 3. Semantic Domains, Representation Relations, and Spatial Composition

Synthesizing `support/rust-semantic-domains-spatial-composition-3886/coverage.json`, `support/rust-semantic-domains-spatial-composition-3886/evidence.json`, and `support/rust-semantic-domains-spatial-composition-3886/primary-evidence.json` across RustBelt, RustHornBelt, RefinedRust, MiniRust, Aeneas, and Corten (`arXiv:2609.04372v1`) yields a unified seven-component representation relation $\mathrm{Rep}_T(v, p, r)$ connecting a pure logical value $v$, a machine place/pointer $p$, and a spatial resource state $r$:

1. **Numerical Geometry ($\mathrm{Geom}_T(p)$):** Size, alignment (`p.addr % align_of::<T>() == 0`), field offsets, and address-space bounds (`size_of_val(p) <= isize::MAX`, non-wrapping `inbounds` offset arithmetic).
2. **Initialization State ($\mathrm{Init}_T(p, r)$):** Per-byte initialization masks distinguishing initialized value bytes from uninitialized padding or `MaybeUninit<T>` storage.
3. **Representation Validity ($\mathrm{Valid}_T(p, r)$):** Bit-pattern invariants required by `rustc` (`bool \in \{0, 1\}`, valid `char` scalar values, non-null `NonNull<T>`/`&T`, valid enum discriminants).
4. **Provenance & Aliasing Tag ($\mathrm{Prov}_T(p, r)$):** Allocation identity (`AllocId`) and Stacked/Tree Borrows tag permissions (`Unique`, `SharedReadOnly`, `SharedReadWrite`, `Reserved`, `Frozen`, `Disabled`).
5. **Spatial Resource Authority ($\mathrm{Own}_T(p, r)$):** Separation-logic ownership (`own`/`shr`/`PointsTo<T>`/`Perm<*const T>`) or fractional token authority governing reads, writes, and deallocation.
6. **Lifetime & Retag State ($\mathrm{Life}_T(\kappa, p, r)$):** Borrow lifetime token $\kappa$, two-phase reservation activation, and prophetic final-value continuation $v_{\text{final}}$ at lifetime expiration.
7. **Value Abstraction ($\mathrm{Abs}_T(p, r) = v$):** The pure mathematical decoding of the machine bytes at $(p, r)$ into the specification-level algebraic type $v$.

#### Corten THIR-to-Rocq Weakest-Precondition Calculus (`arXiv:2609.04372v1`)
Corten translates Rust THIR via `hax` and `hax2rocq` into Rocq and defines a weakest-precondition calculus over a fractional forest-of-values memory model with defunctionalized continuations (§3, Appendix C). However, Appendix G (Table 4) and Appendix H document that foundational soundness of the core calculus (`variable`, `borrow`, `aggregate`, `control`, `call`, and `pattern` rules) remains in `Pending` axiom status in the Rocq development, and both `rustc` and `hax2rocq` sit inside the unverified trusted computing base.

#### Concurrency (`Send`/`Sync`) and Self-Referential State (`Pin`/`Future`)
- **`Send` and `Sync` (`library/core/src/marker.rs`):** In RustBelt and RefinedRust, `T: Send` is a semantic predicate stating that the full ownership predicate $\llbracket T \rrbracket_{\text{own}}(\text{tid}, v)$ is thread-independent ($\forall \text{tid}_1, \text{tid}_2.\; \llbracket T \rrbracket_{\text{own}}(\text{tid}_1, v) \vdash \llbracket T \rrbracket_{\text{own}}(\text{tid}_2, v)$), while `T: Sync` states that shared borrow predicates $\llbracket T \rrbracket_{\text{shr}}(\kappa, \text{tid}, l)$ are thread-independent. Pure functional translators (Aeneas, Creusot) erase thread IDs and therefore cannot verify unsafe `Send`/`Sync` implementations (e.g., `Arc`, `MutexGuard`, `RwLock`) without an external concurrent separation-logic soundness proof.
- **`Pin<P>` and `Future::poll` (`library/core/src/pin.rs`, `future/future.rs` at `rust-lang/rust@b940084d7eb6a299eb4bfeb8e34901bc051e7ac4`):** The pinning invariant splits ownership at address $l$ into a movable handle and an address-pinned spatial invariant that persists until `Drop::drop(l)` completes before storage at $l$ is deallocated or overwritten. Because `async fn` state machines contain self-referential pointers across yield points, tree-shaped functional backward functions cannot represent pinned `Future` states directly without breaking the self-reference into an explicit state-machine invariant parameterized by the pinned base address $l$.

## Boundaries

1. **Pure Backward-Function Aliasing Ceiling:** Pure functional borrow encodings (Aeneas `SymbolicToPureCore.ml`, Creusot `Bor { cur, final }`, and Anneal's `MirVal.refVal` path lenses) are sound only while active mutable references form an acyclic forest of disjoint places. Once `unsafe` code converts raw pointers (`*mut T`) into co-live mutable references or interior-mutable aliases (`UnsafeCell<T>`), functional writeback clobbers updates (`aliased_backward_lenses_clobber`). Verification must switch to separation-logic tokens (`PointsTo<T>`, `Perm<*const T>`, or Caesium/MiniRust `(AllocId, Offset)` heaps) at that boundary.
2. **Padding-Free Boundary for Algebraic Value Models:** By `intoBytes_iff_paddingFree` and `padded_transmute_to_int_reads_uninit`, algebraic ADT models (`MirVal.adt`, Aeneas ADTs, Why3 records, VIR datatypes) can verify byte-reinterpreting operations (`transmute`, `FromBytes`, `IntoBytes`) only when accompanied by a static zero-padding witness (`L.paddingBytes = 0`). Types with inter-field or trailing padding (`L.paddingBytes > 0`), unions with heterogeneously padded variants, or partially initialized `MaybeUninit<T>` buffers require an `AbstractByte` (`Init(u8, Option<Provenance>) | Uninit`) representation.
3. **Foundational Mechanization Gaps in VeriFast and Corten:** Neither VeriFast's foundational Rocq export (`SymexSoundness.v:1573-1623`, where `wp_Program` and `StorageLive`/`StorageDead` are `Admitted`) nor Corten's THIR-to-Rocq calculus (`arXiv:2609.04372v1` Appendix G Table 4, where core step rules remain `Pending` axioms) currently provides a closed, axiom-free machine-checked soundness proof down to operational MIR.
4. **Symbolic Bug-Finder Silent Partiality and Flag Coupling:** Bounded symbolic tools cannot be treated as unbounded soundness certificates without auditing their configuration flags: Kani disables `check_uninit` when contracts or stubs are active; Soteria exits with status `0` on `OkPartial` fuel exhaustion and omits strong-protector deallocation checks in `tree_state.ml:675-689`; and Crux-MIR omits byte-level provenance and padding checks on `MirReference`.
5. **In-Kernel vs. External SMT Certificate Boundary:** External Alethe/LFSC/SMTCoq certificates do not yield Lean 4 kernel terms unless reflected into Lean (`bv_decide` LRAT reflection). Accepting unreflected external solver outputs or Carcara runs with non-empty `allowed_rules` enlarges the trusted computing base beyond the Lean kernel.
