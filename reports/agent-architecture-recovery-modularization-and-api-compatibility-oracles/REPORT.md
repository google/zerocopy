### 2. Multi-Level Louvain Disconnection Mechanics vs. Leiden Constrained Refinement

`Basis: source + derived + execution (Probe 1)`

- **Why Multi-Level Louvain Welds Disjoint Sub-Packages (`networkx/networkx@6c1a31d1613ad04cf2b2e3d63090b94979521981`, `networkx/algorithms/community/louvain.py:257–364`):**
  1. In `_one_level` (`louvain.py:285–343`), a shared utility or facade hub `0` initially pulls two otherwise independent modules $L$ and $R$ ($E(L, R) = 0$) into `{0} ∪ L ∪ R`, then migrates to a denser target subsystem $T$ without testing whether `partition[u_com]` remains connected after removing `0`.
  2. In `_aggregate_graph` (`louvain.py:346–364`), every block of `inner_partition` becomes a *single* coarse vertex (`L355`), permanently erasing the internal zero-edge cut $E(L, R) = 0$ from all subsequent levels.
- **Exact Analytical Multi-Level Witness Conditions (`Probe 1`):** For a disconnected remnant $C_{\text{rem}} = L \cup R$ (`cc = 2`) to survive all coarse Louvain passes rather than re-merging into $C_{\text{hub}} = \{0\} \cup T$ at Level 2, total graph weight $m$ must not be artificially inflated by external background cliques: inflating $m = 922$ via an external $K_6$ (`w_c = 3, w_b = 7, w_t = 10, w_{0T} = 13, w_{\text{bg}} = 50`) causes Level 2 to re-merge $C_{\text{rem}}$ into $C_{\text{hub}}$ ($42 \times 922 = 38{,}724 > 0.5 \times 78 \times 266 = 10{,}374$, leaving `0 / 500` permanently disconnected runs). Placing weight inside a $K_6$ attractor $T = \{7..12\}$ (`w_c = 3` on $L = \{1,2,3\}$ and $R = \{4,5,6\}$, `w_b = 5` from `0` to $L \cup R$, `w_t = 15` inside $T$, `w_{0T} = 18` from `0` to $T$, and `w_bg = 10` on decoupled $K_4 = \{13..16\}$) yields total edge weight:
  $$m = 18 + 30 + 225 + 108 + 60 = \mathbf{441}, \qquad K_{\{1..6\}} = \mathbf{66}, \qquad K_{\{0\}\cup T} = 138 + 558 = \mathbf{696}$$
  This simultaneously satisfies singleton bridge capture ($w_b = 5 > w_c = 3$), bridge migration into $T$ ($6 w_{0T} = 108 > 6 w_b = 30$), 1-move local Nash trapping inside $\{1..6\}$ ($2 w_c = 6 > w_b = 5$), and **strict Level-2 coarse non-merge**:
  $$6 w_b m = 30 \times 441 = \mathbf{13{,}230} < \frac{\gamma}{2} K_{\{1..6\}} K_{\{0\}\cup T} = 0.5 \times 66 \times 696 = \mathbf{22{,}968}$$
  Under `nx_louvain_communities` ($\gamma = 1.0$), **`25 / 60` (`41.7%`)** of random node-order seeds (including `seed = 0`) terminate permanently with `{1..6}` welded at **`max_cc = 2`** (`Q = 0.28515896`). Splitting $L$ and $R$ increases modularity by $\Delta Q = \frac{K_L K_R}{2m^2} = \frac{33^2}{2 \times 441^2} = \frac{1}{357} \approx \mathbf{+0.00279976}$ (`Q = 0.28795872`).
- **Paper Leiden vs. `libleidenalg` Implementation Nuances (`vtraag/leidenalg@9890a99a4bfe49b839905b8faba1bd4f9e5beec8`, `src/leidenalg/functions.py:21–94`; `vtraag/libleidenalg@fe2d4e79949048b7b79cce40892ce01490f7a24f`, `src/Optimiser.cpp:16–30, 241–288, 1346–1404`, `src/MutableVertexPartition.cpp:901–918`):**
  - Before `collapse_graph` (`Optimiser.cpp:277`), Leiden re-initializes singletons inside each rough community $S \in \mathcal{P}$ and merges only along edges inside $S$, guaranteeing `cc = 1`.
  - Whereas Traag et al. (2019) Algorithm A.2 filters $\gamma$-well-connected subcommunities and samples moves via $\exp(\Delta H / \theta)$ Gibbs weights, `libleidenalg` defaults to `refine_consider_comms = RAND_NEIGH_COMM` (`Optimiser.cpp:20, 1346–1371`), sampling neighbor communities proportional to **neighbor-incident multiedge multiplicity (ignoring scalar edge weights — aided by a no-op `comm_added[comm];` statement without `= true` at `MutableVertexPartition.cpp:913`)**, and `leidenalg.find_partition` defaults to **`n_iterations = 2`** outer hierarchy passes.
  - Even in a single outer pass (`n_iterations = 1` in `leiden_communities`), both Gibbs and `RAND_NEIGH_COMM` achieve **`max_cc = 1`** (`Q = 0.28795872`) on the 17-node witness and **`0 / 80` (`0.0%`)** disconnections (`mean_dQ = +0.000763`) across an `80`-seed parameter-jittered sweep of the 17/18-node hub-bridge witness topology (`w_c ∈ [2.8, 3.2]`, `w_b ∈ [4.9, 5.2]`, `w_t ∈ [14.5, 16.0]`, `w_{0T} ∈ [17.5, 18.8]`), where Louvain disconnects **`24 / 80` (`30.0%`)** instances (`24 / 290 = 8.28%` communities, demonstrating non-knife-edge witness parameter stability distinct from Traag et al.'s `16%–25%` empirical network rates).

### 3. `BasicMQ` / `TurboMQ` Cycle-Blindness vs. Reflexive `DSM` Propagation Cost

`Basis: documentation + derived + execution (Probe 2)`

- **Algebraic Cycle-Blindness and $k$-Inflation (`Probe 2`):**
  - On $N = 64$ files partitioned into $k = 8$ 8-file ring modules, a clean layered DAG (`2` forward edges $C_m \to C_{m+1}$, `maxSCC = 8`, reflexive `DSM` `PC = 56.25%` with $M^0 = I$ diagonal included) and a globally cyclic architecture (`1` forward $C_m \to C_{m+1}$ + `1` backward $C_{m+1} \to C_m$, `maxSCC = 64`, **`PC = 100.00%`**) receive **bit-identical** `BasicMQ = 0.121094` and `TurboMQ = 6.577778`.

### 6. Go `golang/exp` `apidiff` Type-Correspondence Automaton and Pointer-Receiver Soundness Hole

`Basis: normative + source + derived + execution (Probe 5)`

- **Bijective Unexported-Type Correspondence (`golang/exp@e1094eeca1b508317bb24413555d977dea6bb30c`, `apidiff/correspondence.go:207–308`, `compatibility.go:155–162`):**

Renaming `oldTok -> newTokA` consistently yields `0` incompatibilities, whereas splitting `Open() newTokA` and `Use(newTokB)` fails `prev == new` at `Use` (`1` incompatibility: `Use: changed`).
  - Adding an unexported non-comparable field (`cache map[string]int`) to an exported struct `Key` triggers `types.Comparable(old) && !types.Comparable(new)` (`compatibility.go:159–161`), catching external `map[pkg.Key]V` and `==` breakage (`Key: old is comparable, new is not`).
- **Stale `TODO` Comments vs. Live Pointer-Receiver (`*T`) Soundness Bug (`apidiff/apidiff.go:4–6, 114, 205–234` vs. `compatibility.go:110–126, 279–280`; `Probe 5`):**
  - When an exported interface `I` contains an unexported marker method `seal()`, `checkCompatibleInterface` (`compatibility.go:117–120`) treats method addition (`M2()`) as compatible because external packages cannot implement `seal()` directly.
  - Although `apidiff.go:4–6` and `compatibility.go:110–112` carry `TODO` comments stating whole-package satisfaction is unimplemented, `d.checkPackage` (`apidiff.go:205–234`, tested in `testdata/whole.go:36–42`) *does* iterate over `(otn1, nt1)` and `(otn2, nt2)` in `d.correspondMap` and runs:
    ```go
    if types.Implements(otn2.Type(), oIface) && !types.Implements(nt2, nIface) {
        d.incompatible(objectWithSide{otn2, false}, "", "no longer implements %s", objectString(otn1, oldRootPackagePath))
    }
    ```
    Consequently, value-receiver `type ValImpl struct{}` (`func (ValImpl) seal()`, `func (ValImpl) M1()`) is **caught** (`ValImpl: no longer implements I`).
  - **Live Soundness Bug:** Because `d.correspondMap` keys are strictly `*types.TypeName` value types (`apidiff.go:114`) and `apidiff.go:228` tests **only `otn2.Type()` (`T`)**—unlike `checkCompatibleDefined` (`compatibility.go:279–280`), which checks both `old` and `types.NewPointer(old)`—**pointer-receiver implementors (`func (*PtrImpl) seal()`, `func (*PtrImpl) M1()`) completely bypass `apidiff.go:228`**, even when `func NewPtr() *PtrImpl` is exported in the same package. Upstream `apidiff` reports `0` incompatibilities (`[I.M2: added]`) while external client code `var _ pkg.I = &pkg.PtrImpl{}` fails compilation (`*pkg.PtrImpl does not implement pkg.I (missing method M2)`). Testing `types.NewPointer(otn2.Type())` alongside `otn2.Type()` (`fix_pointer_implements=True` in `Probe 5`) closes the hole (`*PtrImpl: no longer implements I`).

### 7. Synthesized Engineering Invariants for Modularization and API-Compatibility Agents

`Basis: derived (synthesized from Sections 1–6)`

1. **Constrained Leiden + Directed SCC / `DSM` `PC` Objective:** Never partition dependency graphs with `louvain_communities` (`max_cc >= 2` supernode welding) or optimize undirected `BasicMQ`/`TurboMQ` alone (`|Δ| = 0` under DAG-to-cycle reversal and `2.15×` micro-cluster inflation); enforce Leiden (`cc = 1`) paired with Tarjan/Kosaraju SCC condensation and reflexive `DSM` Propagation Cost $\text{PC} = N^{-2}\sum_{i,j} V_{ij}$.
2. **Resolved Symbol Graphs + Chance/Folder-Adjusted SAR Benchmarks:** Extract compiler-resolved symbol references rather than `#include` (`3.98×–5.49×` bloat) or Java `import` (`46.6%–49.0%` intra-package omission) edges, report `ARI` and `a2a_adj` (on densely re-indexed `0..k-1` labels) rather than asymmetric `MoJoFM` or compressed `a2a`, and include immediate-parent-folder (`ARI(dir, gold)`) and directory-flattened ablations.
3. **Hybrid Bytecode + AST/Model + Downstream-Hierarchy JVM Gating:** Combine `japicmp` (`ACC_BRIDGE` bytecode descriptor inspection) with `revapi` (`ConstantValue` folding, `protected -> public` override checks, `METHOD_NOW_STATIC`) plus downstream client/inheritance closure (`Maracas` / `javac` compilation) to catch `ACC_BRIDGE` subclass breaks, overload ambiguities, and multi-interface `default` diamond conflicts.
4. **Pointer-Method-Set (`*T`) Augmentation for Go `apidiff`:** Augment `apidiff.go:228` to check `types.Implements(types.NewPointer(otn2.Type()), oIface)` alongside `otn2.Type()`, and pair `apidiff` with AST checks for unkeyed struct literals, embedded-field selector shadowing, and `const` overflow.
