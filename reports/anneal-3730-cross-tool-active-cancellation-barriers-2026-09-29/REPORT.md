# R20: active cross-tool cancellation barriers

Observed on 2026-09-29 with pinned local Charon, one-shot Aeneas, Lean and Lake CLIs. The bounded fixture used one active process group at a time, tiny Rust/Lean sources, private output directories, deterministic FIFO or tactic barriers, a retry, and a fresh Lean consumer. `support/results.json` retains commands, stdout/stderr, exit codes, process-group members before/after termination, artifact inventories and hashes, oracle output, and event markers. `support/probe.py` recreates the run; `python3 support/check.py` checks the retained result without invoking the toolchains.

| Gate | Observed component outcome | Retry/oracle |
| --- | --- | --- |
| Pre-exec wrapper | Killed while wrapper gate was entered; no CLI had started. | Establishes only a pre-launch cancellation control. |
| Charon `--format all` | A parseable JSON LLBC existed while Charon and `charon-driver` were alive and the Postcard destination was a blocked FIFO. SIGKILL of the group left no observed group members. | Removed the interrupted generation; the same command regenerated both formats, and Charon parsed the Postcard result. |
| Aeneas split-file output | `Types.lean` existed while Aeneas was alive and `Funs.lean` was a blocked FIFO. SIGKILL left no observed group members. | A fresh destination yielded complete `Base` modules; a fresh Lean compilation and `inc 0 = .ok 1` proof passed. |
| Lake build / Lean elaboration | `Cancel/A.olean` existed and `Cancel/B.olean` did not while Lake's Lean child was blocked in `run_tac`. SIGKILL removed both observed group members. | Releasing the gate and retrying completed B; a fresh Lake/Lean consumer proved `chosen = 8`. |
| Late stage completion | The old job's *real Aeneas CLI* completed, then a Python experiment wrapper waited. A new source completed real Charon→Aeneas→fresh Lean proof (`inc 0 = .ok 2`). After authority advanced to generation 2, the old wrapper resumed and its explicit generation check rejected publication of generation 1. | The rejected old output remained in its private directory as evidence; no shared destination was overwritten. |

The FIFO gates deliberately stop actual output writes. The Lake gate runs inside actual Lean elaboration. The late-publication gate and generation authority are **experiment-side code**, not behavior of Aeneas, Lean, or Anneal. The wrapper's delayed completion is after the Aeneas CLI exits, so this is a causal late *stage job* control, not a claim that Aeneas itself emitted bytes late. `ps` snapshots cover observed process-group membership immediately around the kill; they do not prove absence of orphaned work forever.
