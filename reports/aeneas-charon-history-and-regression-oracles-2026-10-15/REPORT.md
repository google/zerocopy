# Aeneas and Charon historical defects, regression coverage and oracle limits

*Authored by an AI agent acting on joshlf's behalf.*

## Summary

A bounded audit of 26 historical issue/PR records separates incorrect library models, a backend-specific inconsistent axiom, ill-typed generated code, unsupported inputs, internal translation failures, frontend representation defects, and proof tooling difficulties. These categories require different oracles. Successful extraction, target type checking, and proofs against the target model each detect useful failures, but none independently establishes correspondence with Rust.

The most discriminating historical examples are distinguishable order ties (#1286), insertion versus replacement (#1302), unsigned bytes for signed integers (#1355), preservation of the FnMut state/output tuple (#960), and partial output after an internal loop-join error (#1399). Projection, region, binder and identity handling recur across several independent fixes. A test strategy should retain those causal invariants and observe both intermediate representation and target behavior, rather than merely accepting new golden output.

### Semantic correctness is stricter than target consistency

[Ord #1286](https://github.com/AeneasVerif/aeneas/pull/1286) changes `max_body` and `min_body` from comparing `lt x y` to `lt y x`. For equal order keys, the returned operand matters when objects have distinguishable payloads. The Rust API specifies second-operand selection for max and first-operand selection for min. [Rust Ord documentation](https://doc.rust-lang.org/std/cmp/trait.Ord.html#method.max) Scalar numerical equations for min/max cannot discriminate equal operands. A later [#1360](https://github.com/AeneasVerif/aeneas/pull/1360) adds tests of ties together with default-method ABI, partial comparison returning None and reference comparisons. This distinguishes a semantic tie-selection error from the later ill-typed default-method interface.

[Vec #1302](https://github.com/AeneasVerif/aeneas/pull/1302) changes `List.set` to `List.insertIdx` and changes its specification accordingly. The old function could have proofs about replacement while incorrectly representing insertion. The Rust API allows insertion at the current length and shifts the suffix. [Rust Vec::insert documentation](https://doc.rust-lang.org/std/vec/struct.Vec.html#method.insert) The inspected patch still uses a strict `i.val < v.length` condition; this audit does not promote the PR to a complete Rust-equivalence result for insertion at the end or into an empty vector. That remaining boundary is a discriminating check, not a newly reproduced bug claim. A useful independent expected relation checks length increment, prefix preservation, inserted element and suffix shift, plus end/empty boundaries and failure behavior.

[#1116](https://github.com/AeneasVerif/aeneas/issues/1116) is categorically different: the Rocq `mk_array` axiom allows constructing an array of False of length one from an empty list, from which the issue derives False. The [maintainer response](https://github.com/AeneasVerif/aeneas/issues/1116#issuecomment-4676370504) agrees and describes the non-Lean backends as unmaintained at that time. The issue cites exact Rocq source revision `435b8340e50f132c4d91b628de53868c37dfadc5`, Primitives.v lines 750–751 and 765–766. This is backend-specific evidence of inconsistent assumptions, not evidence that Lean has the same axiom or inconsistency. Target theorem checking cannot repair a false foundational axiom; an assumptions audit and model-construction checks are separate obligations.

### Symbolic execution needs invariants beyond ordinary Rust type correctness

[#1055](https://github.com/AeneasVerif/aeneas/pull/1055) is especially informative because it separates three kinds of state: projected semantic regions, values needed for backward reconstruction, and metadata used only by translation. Using `ty_has_mut_borrow` instead of the region-restricted predicate inspected too much; independent region projections require appropriate overlap checks; ignored projected values may still be needed to rebuild an ADT consumed by a backward function. Conversely, comparing saved meta-values/environments caused a performance problem because those values should not affect symbolic execution equality.

[#1095](https://github.com/AeneasVerif/aeneas/pull/1095) allows intersecting shared projectors and repairs region abstraction kinds at breaks as well as ADT translation. The [#938 closure comment](https://github.com/AeneasVerif/aeneas/issues/938#issuecomment-4604038379) attributes its lost field update to that PR. This attribution is documentary, while the bundle's actual changed source/tests are separately recorded.

[#1348](https://github.com/AeneasVerif/aeneas/pull/1348) explains why two break paths may share loan/borrow IDs within one evaluation; joining against refreshed IDs can then miss abstractions. Its source reevaluates break contexts so a join sees the necessary relationships. The PR expressly excludes a final example moved to #1349. [#1379](https://github.com/AeneasVerif/aeneas/pull/1379) freshens even borrow-free copied symbolic values so expansion of a copy cannot expand its frozen original. The [subsequent commit](https://github.com/AeneasVerif/aeneas/commit/1dc1c98edc609a4cc982f283b9ca37f7f135ed82) explicitly addresses regressions following #1379. Identity-sensitive transformations therefore need both the intended freshening invariant and downstream simplification/assertion tests.

[#715](https://github.com/AeneasVerif/aeneas/pull/715) introduces sub-abstractions because a nested abstraction can contain both a loan and corresponding borrow; ending part without ending all is necessary. The PR calls support preliminary. The later [#1186](https://github.com/AeneasVerif/aeneas/issues/1186) supplies a failing aggregate-of-slice-references example and passing separate-locals alternative. “Nested borrows supported” is too coarse a compatibility promise.

[#1399](https://github.com/AeneasVerif/aeneas/issues/1399) reports a loop-context internal error at `InterpMatchCtxs.ml:230` with Aeneas `b86120db`, Charon `4bd5a29f6e97ce2201ed35251afe5716e53b0a3a`, and partial emitted Lean missing the function. Its reproducer intentionally leaves a borrow-carrying wrapper non-opaque. This source establishes a reported failure mode; it does not establish a newly reproduced crash here. Derived integration rule: a file's existence and syntactic validity are insufficient success criteria. Require successful process outcome, accepted diagnostics and coverage of the expected declarations, including their bodies.

### Frontend, binders and schemas need independent gates

[Charon #1189](https://github.com/AeneasVerif/charon/issues/1189) shows LLBC calling a filtered Drop function; [#1191](https://github.com/AeneasVerif/charon/pull/1191) removes exclusion of Drop impls in the Aeneas preset. This is reference closure in the IR, not merely missing support for Drop. The fix PR changes only options.rs; no new dedicated test was established from its patch.

[Charon #1451](https://github.com/AeneasVerif/charon/pull/1451) replaces a `no_bound_vars().expect(...)` path by erasure after skipping the binder. The patch explicitly calls this a loss of precision. Avoiding a panic is not evidence of preserving all lifetime information. [#1427](https://github.com/AeneasVerif/charon/pull/1427) instead translates a region binder before erasing it in predicate/vtable handling. These changes require binder-depth and region-identity checks rather than blanket “HRTBs work” conclusions. Aeneas [#1333](https://github.com/AeneasVerif/aeneas/pull/1333) repairs erased closure regions only for signatures binding exactly one region; its cardinality premise is material.

[Charon #1480](https://github.com/AeneasVerif/charon/pull/1480) adds drop-flag detection and conditional-drop resugaring for simple detectable cases. The PR claims inhabitedness checks; changed AST, generated decoders and pass source show a cross-layer representation change. A regression suite should validate both codec compatibility and transformed control-flow/drop behavior. [#1498](https://github.com/AeneasVerif/charon/pull/1498) extends vec reconstruction to repeat rvalues, and [#1518](https://github.com/AeneasVerif/charon/pull/1518) introduces a cast preserving statically sized array subslice types. Equivalent surface Rust forms can cross different MIR/LLBC cases.

### Target checks and hand-written target tests are necessary

[#1355](https://github.com/AeneasVerif/aeneas/pull/1355) reports successful Aeneas exit followed by Lean type errors: signed integer byte conversions incorrectly used `Array I8` while Rust interfaces use `[u8; N]`. A round-trip inside the same wrong model was self-consistent and passed; external unsigned buffers exposed it. Its changed Rust tests cover signed little/big endian conversions in both directions. This is direct historical support for interface-oriented tests and independent expectations, rather than testing only inverses of a model.

[#960](https://github.com/AeneasVerif/aeneas/issues/960) reports a `FnMut` result `Unit × P` bound as `P`; its [comment](https://github.com/AeneasVerif/aeneas/issues/960#issuecomment-4336963445) identifies unit-output simplification conflicting with trait method shape. Preserve trait ABI under monomorphic simplification and exercise associated outputs equal to Unit.

[#1390](https://github.com/AeneasVerif/aeneas/pull/1390) contains hand-written target-only test source inspected here in [ParserErrors.lean](https://github.com/AeneasVerif/aeneas/blob/73fc4e991e02eff4abb8deddd9a7c4f1d8105aeb/backends/lean/Aeneas/Tactic/Step/Tests/ParserErrors.lean). They check parser ambiguity, malformed syntax, type errors, explicit rejection with recovery enabled, and success of an alternative branch after a failed one. Its implementation disables recovery to synthetic sorry while elaborating specification/config arguments. Such target elaborator error-path tests are not generated by any Rust fixture.

[#1412](https://github.com/AeneasVerif/aeneas/pull/1412) and [its squash commit](https://github.com/AeneasVerif/aeneas/commit/6c2788d1366f09d69fd55b2b9be71cd17d28a9ab) describe a hand-written `tests/lean/FnPtrGenericUniverses.lean` test instantiating generated code at higher universes. However, that **exact path returned 404** at both the pinned tree and inspected PR head; PR file page 2 was empty, and inspected lakefile adds only FnPtrGeneric. The pinned [FnPtrGeneric.lean](https://github.com/AeneasVerif/aeneas/blob/21345f80fa212c596f6437378d7d57984fa2ea77/tests/lean/FnPtrGeneric.lean) is generated code. Therefore higher-universe testing is a valuable upstream-described methodology but that claimed specific artifact was not verified here. This limited absence does not establish that equivalent tests exist nowhere else. Generic trait methods and associated types inside trait fields remain restricted according to the PR.

### Existing harness and a regression/oracle matrix

Pinned [tests/README.md](https://github.com/AeneasVerif/aeneas/blob/21345f80fa212c596f6437378d7d57984fa2ea77/tests/README.md) describes separate generation and verification phases, golden outputs and hand-written proofs. [Input.ml](https://github.com/AeneasVerif/aeneas/blob/21345f80fa212c596f6437378d7d57984fa2ea77/tests/test_runner/Input.ml) distinguishes Normal, Skip and KnownFailure actions per backend, supports backend-specific options and stored diagnostics. The README explicitly says Charon failures belong in Charon tests and that no option covers successful translation whose backend verification fails. It also says HOL4 outputs are checked but not regenerated. These coverage distinctions must survive summary CI status.

The pinned [root Makefile](https://github.com/AeneasVerif/aeneas/blob/21345f80fa212c596f6437378d7d57984fa2ea77/Makefile) separates `test` (generation plus Rust unit tests) and `verify` (backend verification), and enables expensive `-checks` in CI. The source evidence supports this structure; no CI run was inspected here. [#1296](https://github.com/AeneasVerif/aeneas/pull/1296) is a test-only confirmation of a previously landed fix in #1158, showing why issue closure dates, code-change dates and regression-introduction dates need separate provenance.

The following is **derived regression design**, not a claim that upstream currently implements all gates.

| Gate | Discriminating historical probes | Oracle and limit |
|---|---|---|
| Extraction process contract | #1399; unsupported #1186 | Exit status, diagnostics, expected declaration/body inventory; catches partial artifacts, does not prove semantics. |
| LLBC structural validity | Drop dangling refs #1189; binders #1451/#1427; array subslice #1518 | Declaration closure, types, binder scopes, schema/codec roundtrip; a valid IR may encode wrong Rust behavior. |
| Symbolic invariants | #1055/#1095/#1348/#1379 | Region-restricted projections, loan/borrow relations, backward reconstruction, ID freshening and join stability; checks must not reuse the same faulty helper as the transformation. |
| Golden comparison | #779 representation modes; #1480 schema changes | Reveals output drift at pinned toolchain/options; a reviewed golden is an observation, not semantic specification. |
| Target type check | #938/#960/#1355/#1360 | Compile generated code against matching models; catches ABI/type mismatch, not wrong but typed models. |
| Target-only elaboration and assumptions | #1390, Rocq #1116; #1412 described higher-universe case | Negative elaboration tests; no silent admitted goals; inspect axioms; elaboration success remains relative to assumptions. |
| Independent behavioral/model checks | #1286/#1302/#1355 | Compare finite Rust inputs to separately derived expected relation or trusted specification; include ties/payload identity, empty/end insertion, signed extrema and external byte buffers. Bounded differential agreement is not a theorem. |
| Proof usability and performance | #1055 equality; regression commit39d61ed9 | Replay representative proofs, record elapsed time/heartbeats and assumptions with fixed machine/toolchain; timeouts do not imply semantic unsoundness. |

The commit [39d61ed942d56a7b0aa833d72b4863665a269712](https://github.com/AeneasVerif/aeneas/commit/39d61ed942d56a7b0aa833d72b4863665a269712) includes messages about WP inference blowup, a removed regression, and avoiding `step_array_spec` elaboration timeout. This is historical documentation of performance/test-maintenance pressure, not an independently measured performance result. #1055 separately ties a runtime equality slowdown to translation-only metadata.

Independent oracles should share as little implementation as practical: separately specified container relations rather than the model's own `set`; canonical byte encodings rather than only model round-trips; Rust observable payload identity rather than numerical order equations; explicit IR scope validation rather than trusting generated serializers. Differential testing against another translator or adjacent revision still shares frontend/model assumptions and detects disagreement, not which side is correct. Metamorphic equivalent Rust formulations help expose coverage gaps (#1186, #1498), but both translations may share an error. Hand-written target proofs establish their propositions about the translated model, conditional on axioms, and need a correspondence argument to speak about Rust.

## Boundaries

- **Not examined:** exhaustive historical search, all merged fixes, all issue discussion timelines, current CI jobs, source ancestry of every fix into either coordinating pin, current behavioral reproduction, security consequences, prevalence and severity distributions.
- **Unknown:** current behavior of open historical reports; which exact newer revision first fixes an issue when no explicit fix was found; whether tests outside the inspected paths cover #1412's higher-universe scenario.
- **Known not to apply:** the Rocq `mk_array` proof is not evidence of Lean inconsistency; a Lean type error is not itself evidence of a successfully checked false theorem; proof performance failures are not semantic counterexamples.
- **Unsupported/restricted as described upstream:** preliminary nested-borrow frontier; closure-region repair premise of one region; generic trait-field universes; simple detectable conditional drops. These historical statements are not blanket feature claims for the pins.
- A merged PR may be partial (#1348), later need follow-up (#1379), or contain source behavior not fully characterized by its summary (#1302). The ledger records evidence of the change, not an endorsement that all related behavior is fixed.
