# Unsaved Rust-comment proof over a retained Charon/Aeneas model

## Summary

A disposable driver joined a Rust-hosted, **unsaved** Lean comment to a **real prepared Charon/Aeneas generated model**. It projected the comment into Lean, opened and changed that document in Lean 4.30.0-rc2's actual language server, queried the initial goal and solved state, applied the proof change under a host/projection/version/model compare-and-swap guard, and checked the exact captured projected bytes in fresh batch Lean. A fixed proposition consumer accepted the theorem and `#print axioms` listed only `[propext, Classical.choice, Quot.sound]`. The saved Rust file and projected disk shadow remained unchanged during the live session.

This completes #3731 **I137's requested disposable prototype steps** for the recorded fixture. The comment marker, projector, edit guard, and orchestration are report-owned Python, not an Anneal V2 implementation or evidence that Anneal's actual annotation syntax or batch path behaves this way. A second disposable schedule also completes I138's requested prototype sequence: actual Charon/Aeneas source/model change, actual Charon failure for an invalid intermediate Rust state, before/during/after Lean goal queries, fresh batch comparisons, and a causally gated old Lean result rejected after the new generation is selected. The selection and fencing are fixture-local Python, not Anneal product behavior.

### Real model-change, failed intermediate state, and late old result

The source mutation changed `wrapping_add(1)` to `wrapping_add(2)` in the fixture Rust function. Installed Charon extracted new LLBC, installed Aeneas generated Lean, and fresh Lean processes compiled new `Current/Types`, `Current/Funs`, and `Current` artifacts. The Rust source changed from SHA-256 `4d39ee7a…` to `e1d8e815…`; generated `Funs.lean` changed from `e671fd23…` to `f45d572a…`. `Current/Funs.olean` changed from `2320c0125c0e0748942a5fde0e6d204b4f77b9cd3f6ac7abf7f43f9c97c4546c` to `57bcadabf1795a8540685e174966444097701f49da4c704446a2bb5ae5d94871`, while the small `Current.olean` entry artifact remained byte-identical. This is a concrete counterexample to using the entry artifact alone as an imported-model identity. The stand-alone mutation run's old proof failed under new imports (exit 1), while `.ok 2#u32` passed (exit 0). Basis: **execution**, `support/mutation-transcript.json`.

The integrated I138 driver began with host revision 1 and selected old generation `e88402506cd3206d87d2ba2e06b6fccb868559d555bcf5e9d0e4325249a11701`. The old server returned `no goals`; a fresh old-model batch check and fixed proposition/axiom consumer both exited 0. It then started a separate old-model Lean proof check whose `run_tac` wrote `gate.entered` and waited for `gate.release`. The driver observed the gate before advancing host authority, so the late result was causally in flight under old revision 1. Basis: **execution** for Lean and gate ordering; **prototype execution** for the selected pointer.

At host revision 2, the driver inserted an invalid Rust declaration after the changed function. The installed `charon cargo --preset aeneas` exited 101 without producing LLBC. The selected generation remained old revision 1, marked **last known good and stale for the current host**. An actual goal request to the old Lean server during this provisional failure still returned `no goals`; the transcript labels its old context and host revision 2, so it is guidance about the previous model, not verification of the invalid current source. The failed source SHA-256, Charon command, exit and stderr are retained. Basis: **execution** and fixture-local state classification.

Host authority then advanced to revision 3 with the valid changed source and `.ok 2#u32` proof annotation. The installed Charon pipeline extracted the new LLBC, then a deterministic gate paused the still-live child before Aeneas generation. While that new model was pending, an actual goal query to the old selected server again returned `no goals`; the record marks it **old selected, stale for revision 3**, not acceptance for B. Only after this query did the driver release the model gate and let Aeneas and Lean compile B. This establishes a literal query during new-model preparation as well as the earlier query during F failure. The installed Charon/Aeneas pipeline generated the new model. Fresh batch plus fixed proposition consumer exited 0 for old proof/old model and new proof/new model; old proof/new model and new proof/old model both failed (exit 1). The new selected generation ID was `6ce1f7d8554de56a5fc54111069c22df0baeaa8a58a7026217d4460980aa5870`, derived from the changed source, LLBC and complete six-file model manifest. The fixture's publication guard required the current host revision/hash, a complete model file set with exact hashes, and a monotonic revision. This guards against the observed cross-model mismatch, but is not an atomic production publisher. Basis: **execution** for tool results, **prototype execution** for the guard.

Only after selecting revision 3 did a new Lean server query the new proof, returning `no goals`; an old proof opened against that same new model returned the unsolved `⊢ golden_vertical.inc 0#u32 = …ok 1#u32` goal. A stale host edit based on revision 1 was rejected. The driver then released the old gate. The old Lean process exited 0 under its own old model, but an attempted publication of its revision-1 result was rejected while the selected pointer stayed at revision 3 and the new generation ID. The order `old gate entered → F failed/queried → B Charon complete, Aeneas gated and queried → B model completed/selected/queried → old gate released/completed → old publication rejected` is explicit in the event transcript and checked offline. Basis: **execution** plus **prototype** publication decision. This meets I138's disposable vertical-slice events on this fixture; it does not validate Anneal's scheduler, crash durability, or parallel publishers.

## Boundaries

- **Not examined:** current Anneal parsing/generation, actual source attachment, Rust compiler validation of the unsaved comment, editor/MCP transaction semantics, Lake server setup, and a single production batch/live engine. The projection is intentionally small and recognizes only this fixture marker.
- **Not established:** Rust-level soundness, obligation coverage, independent verification of Charon/Aeneas semantics, or general absence of axioms. The fixed consumer checks one Lean proposition and `#print axioms` reports this theorem's visible dependencies.
- **Not established:** production I138 behavior. The integrated schedule is a local single-driver prototype; no Anneal publisher, editor/MCP adapter, crash recovery, parallel writers, or cancellation propagation was exercised. The late result is an old Lean proof check, not a delayed Charon/Aeneas extraction.
- **Known not to apply:** `Current.olean` alone is insufficient as a model-change sentinel in this fixture; it stayed byte-identical while `Current/Funs.olean` and the proof result changed. The old server’s `no goals` during provisional F did not verify the current invalid Rust host.
