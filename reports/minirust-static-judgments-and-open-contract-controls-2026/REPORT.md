# Static judgments and open-library contract controls before MiniRust

## Summary

a-mir-formality's examined revision implements crate/trait/associated-type checks, expression borrow checking and MiniRust code generation. These are concrete judgments and code, beyond a plan in a README. Their accepted fragment still leaves surface resolution, generated-code coverage and semantic unsafe-trait contracts as explicit obligations. The Rust implementation's ProofTree is not itself a kernel-checked source-safety theorem.

New controls make two obligations consequential. A certificate for one implementation/const instance proves the wrong result when attached to another; an implementation-supplied unsafe-trait predicate can admit 254 invalid Boolean bytes if the caller domain is not independently required. Safe callback/returned-slice controls exercise restoration and a retained interior-mutable alias. They establish bounded examples and negative controls, not contextual soundness of arbitrary Rust clients.

## Findings

### F1. Implemented judgments expose both useful checks and explicit trusted leaves

Basis: pinned **source**; no fresh execution of these judgments.

`check_all_crates` adds its synthetic core crate when needed and checks every crate prefix. `check_crate` checks duplicates, binder restrictions, items and coherence. `check_fn` universally instantiates the function binder, combines where-clause assumptions and checks well-formed argument/result types. Expression bodies feed a flow-state/NLL borrow checker. A `TrustedFnBody` instead succeeds by a rule that assumes it valid; absence of a trait-declaration body also has its own rule. These acceptance paths must not be reported as body proofs. [Crate checks](https://github.com/rust-lang/a-mir-formality/blob/71dc31c1b186df1f0a64d8464b8103195902a5a5/crates/formality-rust/src/check/mod.rs#L32), [function/body rules](https://github.com/rust-lang/a-mir-formality/blob/71dc31c1b186df1f0a64d8464b8103195902a5a5/crates/formality-rust/src/check/fns.rs#L36).

Associated-type normalization is an actual relation: either use an assumption or select an alias-equality declaration, instantiate existential parameters, prove matching parameter equalities and where clauses, then apply its substitution. This is substantially more precise than replacing a GAT family with one chosen output type. Trait implementation checking also compares trait/impl Safety flags and required items; that syntactic safety comparison does not prove an arbitrary prose unsafe-trait invariant. [Normalization](https://github.com/rust-lang/a-mir-formality/blob/71dc31c1b186df1f0a64d8464b8103195902a5a5/crates/formality-rust/src/prove/prove_normalize.rs#L22), [implementation checks](https://github.com/rust-lang/a-mir-formality/blob/71dc31c1b186df1f0a64d8464b8103195902a5a5/crates/formality-rust/src/check/impls.rs#L76).

The borrow-checker call rule accepts a callee whose rigid type is FnDef, retrieves its declaration, instantiates parameters, requires Safety::Safe, checks argument count/types and proves where clauses. Its own FIXME leaves unsafe blocks/calls for later. Reference and move rules track loans, initialization and outlives constraints; block exit drops locals in reverse declaration order. The movable-place rule explicitly says owned deref types such as Box are not modeled there. These implemented judgments are a specific language fragment, not all rustc method resolution, overloaded auto-deref or temporary-lifetime extension. [Call rule](https://github.com/rust-lang/a-mir-formality/blob/71dc31c1b186df1f0a64d8464b8103195902a5a5/crates/formality-rust/src/check/borrow_check/nll.rs#L419), [move boundary](https://github.com/rust-lang/a-mir-formality/blob/71dc31c1b186df1f0a64d8464b8103195902a5a5/crates/formality-rust/src/check/borrow_check/nll.rs#L977).

`codegen_program` actually starts from main with empty generic arguments and follows a queue of monomorphic function keys. Call generation requires a resolved FnDef identity and parameters. The constructed program has empty globals, traits and vtables. `resolve_fn_body` accepts expression bodies and rejects trusted/missing bodies; thus the checking trusted-body leaf is not automatically executable codegen support. Upstream source tests include explicit generic identity calls and expected output, but they were not rerun. The CLI path examined checks parsed input and returns a ProofTree; it does not itself establish dynamic adequacy. [Code generation](https://github.com/rust-lang/a-mir-formality/blob/71dc31c1b186df1f0a64d8464b8103195902a5a5/crates/formality-rust/src/codegen/mod.rs#L32), [resolved calls](https://github.com/rust-lang/a-mir-formality/blob/71dc31c1b186df1f0a64d8464b8103195902a5a5/crates/formality-rust/src/codegen/mod.rs#L307), [body resolution](https://github.com/rust-lang/a-mir-formality/blob/71dc31c1b186df1f0a64d8464b8103195902a5a5/crates/formality-rust/src/codegen/helpers.rs#L104).

No machine-checked fundamental/safety-reflection theorem was located in the examined rules, codegen and test/entrypoint files. A complete, nontruncated tree inventory contains 254 blobs and no .lean/.v/.thy/.agda/.fst/.dfy files. This is a bounded repository search, **not proof that no related theorem exists elsewhere**. Rust rule-search ProofTree/ProvenSet objects and successful executable tests are evidence about the implementation's derivations, not a kernel theorem connecting all accepted programs to d821c6e safety.

### F3. New feature pairs make the resolved subject observable

Basis: **execution**, `support/open_contract.rs`, `runs/results.json`.

Both builds use the same source. Without feature_flip, Wrapper's `.len()` resolves through its Deref target and returns 2. With feature_flip, an inherent method of the same name exists and returns 99. The GAT Store<3>::View returns a three-byte view; `instance::<A,1>()` returns 11 and `instance::<B,1>()` returns 21. The macro-generated function returns native size_of::<usize>() = 8. These are safe, concrete distinctions; no extraction or formality judgment is inferred from rustc accepting them.

The owned selected-instance control separately evaluates A/const-1→11, B/const-1→21 and A/const-2→12. A result=11 certificate attached using only the generic function name is false for the latter two. Ten subject mutations—declaration, body, implementation, type, const, lifetime quantifier, target, configuration, generated owner and ABI—are rejected by the candidate binder. Equality checking these identities is only a **transport precondition**, not evidence that the body theorem or trait law is true. The differing executable results explain why a wrong-implementation/instance check matters.

The new macro is deliberately small. It does not test procedural macros, build scripts, every cfg combination, or completeness of a generated-item inventory. Existing capture/annotation reports supply distinct bounded counterexamples; a complete source census remains a stronger obligation.

Two additional safe pairs expose drop elaboration. A directly borrowed temporary survives until the enclosing block exits, logging [10,1]; a method result copied from a temporary logs the destructor before the following statement, [2,20]. Matching Some(Stamp) with a wildcard logs the arm before the destructor [30,3,40], while a bound value explicitly dropped in its arm logs [4,50,60]. These exact outputs are checked in both configurations. Emitted textual MIR is preserved for each build: it contains the generated macro function, two closure bodies, destructor implementations, promoted constants and normal/cleanup drop edges. This gives reviewable evidence beyond the surface source; it is not a complete census or a correctness proof of that compiler elaboration.

### F4. Unsafe-trait laws and the independently required client domain must survive linking

Basis: reviewed pinned **normative/source** findings + **owned execution** + **derived** linking contract.

At the reviewed Reference pin, an unsafe trait places obligations on implementations; a correct implementation can be used from safe code. Method safety remains separate. The reviewed rustc safety gate and the new formality safety-matching rule compare markers, rather than prove arbitrary semantic invariants. A trait dictionary with the right methods therefore does not by itself justify representation, Send/Sync, trusted-length or zerocopy validity premises. [Unsafe-trait contract report](../rust-unsafe-trait-invariants-nightly-2026-05-31/REPORT.md), [formality safety comparison](https://github.com/rust-lang/a-mir-formality/blob/71dc31c1b186df1f0a64d8464b8103195902a5a5/crates/formality-rust/src/check/impls.rs#L76).

The finite byte-law control requires Boolean validity on exactly {0,1}. Mutating an implementation-supplied predicate to True accepts all 256 bytes, including 254 invalid values. A checker that lets that predicate define its entire required domain can report a vacuous or weakened law. Our candidate interface independently requires the caller domain, rejecting both the all-byte claim and an empty-domain certificate. This is a deliberate negative control for a zerocopy-style safety premise, not a proof or executed mutation of any real zerocopy trait implementation. The earlier [admission/proof-transport report](../rust-admission-diagnostics-and-proof-transport-cce761ad/REPORT.md) owns the corresponding exact-source checker controls.

An owned Vec-like model has capacity 5 but only three initialized values. A safe indexed client returns None at index 3 under truthful len=3. A lying implementation premise len=5 exposes Uninit at index 4. This represents a **library abstraction/implementation-contract failure** visible to an otherwise safe client, not an unsafe caller knowingly violating a precondition. No invalid Rust value is constructed. The safe Rust Vec control separately calls try_reserve(usize::MAX), observes an error and retains [1,2,3]; this is capacity overflow, not allocation-failure injection or proof of a raw-storage implementation.

For a reusable theorem, quantify over every safe client in the selected source fragment whose trait/lifetime assumptions are satisfied, and every allowed library/environment execution. The exported relation must connect source abstract state, concrete allocation/provenance/bytes/alias state and the current lifetime/resource interpretation. Every callable and unsafe-trait law must bind the selected implementation/instance. This statement is a proposed theorem obligation; it is not established by the finite controls or rustc's type checker. The earlier [functional/spatial linking report](../minirust-rustbelt-spatial-linking-obligations-2026/REPORT.md) supplies its own conditional bridge models and adequacy limits.

### F5. Callbacks and returned resources require an exit-sensitive invariant

Basis: new safe Rust and owned **execution**, with **derived** contract obligations.

`callback_and_return` splits a six-byte mutable slice: the callback gets the first two bytes and the returned view gets the remainder. A retained `Cell` alias increments during the callback. After two further safe reborrows of the returned view, the final bytes are [9,1,2,3,8,5]. A Busy guard rejects reentrant acquisition while active and restores its flag on exit. A second callback deliberately panics inside catch_unwind; the guard restores the flag and the retained Cell reaches 2. Both process exits are 0, and stderr retains the expected panic hook. This does not execute an unexpected panic or suppress diagnostics.

The owned token protocol admits disjoint normal return and complete exceptional restoration. Negative controls reject recovering resources while the callback is active, retaining a forbidden mutable capability, overlap between caller/returned ranges, a lost token and a broken invariant. The forbidden retained capability is distinct from the **allowed** shared Cell alias in the safe fixture. This is an explicit candidate protocol, not a Tree Borrows protector transition model or a lambdaTB Iris proof.

A safely pinned, manually implemented two-poll Future is polled once to Pending and dropped; its owned drop count becomes 1. This checks one suspended-resource destruction path. It does not test compiler-generated async state, !Unpin projection, a scheduler, waking, or all repoll/drop states. The reviewed Pin/async report owns the stronger source contracts and earlier compiler-generated async/drop controls.

For an open library, callbacks can invoke other safe methods, mutate permitted interior state, retain aliases allowed by their types, diverge or unwind. Returned references transfer lifetime-indexed resources rather than give the library unconditional recovery of the original whole range. Foreign callbacks additionally require an explicit ABI/caller-state contract; the safe-client theorem cannot quantify over arbitrary foreign behavior as if rustc had type checked it. No foreign callback is executed here. MiniRust's foreign-item importer rejection and panic-runtime relation remain explicit boundaries, as documented in the [primitive report](../minirust-primitive-lowering-and-layout-frontier-d821c6e/REPORT.md).
