# ITU-T H.266 / VVC Partitioning, Transforms, In-Loop Filtering, SIMD Kernels, and 2D CTU Scoreboard Concurrency Anatomy

## Summary

ITU-T Rec. H.266 | ISO/IEC 23090-3 Versatile Video Coding (VVC) achieves roughly 40%–50% bitrate reduction over H.265/HEVC at equivalent subjective quality (`10.1109/TCSVT.2021.3101953`), at the cost of replacing HEVC's uniform power-of-two quadtree and single-stage wavefront pipeline with non-square ternary splits, dual-window table-free arithmetic coding, stateful trellis dequantization, coupled primary/secondary transforms, subblock optical-flow motion compensation, luma reshaping, and four Cascaded In-Loop Filters (LMCS, Deblocking, SAO, ALF/CCALF).

Primary-source inspection of FFmpeg's native VVC decoder (`FFmpeg/FFmpeg` at `7ddf7bc8a482cf28b4fab2e63b7093ba35cb6a80`, `libavcodec/vvc/`) and Fraunhofer HHI's production C++ decoder (`fraunhoferhhi/vvdec` at `8909ff880412629bdd31e87a9f68d652db89479c`) reveals three architectural realities that govern any clean-room, formally verified, or memory-safe reimplementation:

1. **Block geometry and transform invariants break HEVC power-of-two assumptions (`Basis: normative`, `Basis: source`):** Multi-Type Tree (MTT) ternary splits (`1:2:1` ratios) combine with `128x128` Coding Tree Units (CTUs) and `64x64` Virtual Pipeline Data Units (VPDUs) to produce blocks where one dimension is `4`, `8`, `16`, `32`, or `64` while the orthogonal dimension differs by up to `8:1` (`libavcodec/vvc/ctu.c:526-623`). Coupled with Intra Sub-Partitions (ISP) producing `1xN` or `2xN` transform blocks, SIMD dispatch tables cannot assume square or power-of-two pitches everywhere, while Dependent Quantization (`QState` 4-state trellis), MTS (`DCT-II`/`DST-VII`/`DCT-VIII`), and LFNST (`16x8`, `16x16`, `48x8`, `48x16`) all rely on an invariant `[-32768, 32767]` (`log2_transform_range = 15`) signed 16-bit intermediate envelope (`libavcodec/vvc/intra.c:70-169, 314-348`).
2. **2D CTU stage-scoreboard scheduling replaces simple 1D wavefronts (`Basis: source`):** Because VVC stacks inter-stage spatial hazards—intra prediction reads unreshaped top-right/left neighbors (`RECON`), LMCS inverse reshaping overwrites luma only after right/bottom/bottom-right neighbors finish `RECON`, 7-tap deblocking crosses `8x8` grids, SAO reads `3x3` neighborhoods, and 13-tap ALF reads `7x7` diamonds clipped at `ctu_end - 4` virtual boundaries—FFmpeg's `libavcodec/vvc/thread.c` models each CTU as a 10-stage finite automaton (`INIT` through `ALF`) synchronized via lock-free `atomic_uchar` predecessor counters (`target_score = {2, 0, 2, 3, 1, 2, 5, 8}`), boundary ghost-token pre-initialization, inline stage chaining, and 3-tier priority scheduling that throttles `INTER` wakeup storms (`libavcodec/vvc/thread.c:112-214, 670-737`). By contrast, VVdeC's `DecLibRecon::ctuTask` (`source/Lib/DecoderLib/DecLibRecon.cpp:734-1112`) batches `numColPerTask` CTUs horizontally, polls monotonic `std::atomic<CtuState>` neighbor states, and swaps a full-frame double buffer (`m_fltBuf`) for ALF rather than maintaining FFmpeg's CTU-local `alf_pixel_buffer_h/v` border strips.
3. **SIMD acceleration spans x86-64 AVX2, AArch64 NEON/I8MM, and Armv9 SME2 `ZA` matrix tiles (`Basis: source`):** Notably, FFmpeg's `libavcodec/aarch64/vvc/inter_sme2.S:1-651`—despite its filename—implements **13-tap luma ALF diamond kernels** (`ff_vvc_alf_filter_luma_{8,10,12}_sme2`, wired in `libavcodec/aarch64/vvc/dsp_init.c:327-440`), entering Streaming SVE mode (`sme_entry`) to accumulate 4 output rows simultaneously into 64-bit `ZA` tiles via multi-vector `sdot za.d` instructions, with a subtle bit-depth divergence between 8-bit wrapping `add` (`inter_sme2.S:332`) and 10/12-bit saturating `sqadd` (`inter_sme2.S:617`) prior to `sclamp`.

## Findings

### 1. QTBT and Multi-Type Tree (MTT) Partitioning, VPDUs, and Dual Chroma Trees

`Basis: normative` (ITU-T H.266 §§6.4.1–6.4.2, §7.3.11.4; Bross et al., `10.1109/TCSVT.2021.3101953`) and `Basis: source` (`FFmpeg/FFmpeg` `libavcodec/vvc/ctu.h:60-145`, `libavcodec/vvc/ctu.c:526-623, 2300-2550`; `fraunhoferhhi/vvdec` `source/Lib/CommonLib/CodingStructure.h`, `Partitioner.cpp`).

VVC generalizes HEVC's quadtree CTU (`16x16` to `64x64`) to CTUs up to `128x128` luma samples partitioned by a two-level hierarchy: first a **Quadtree (QT)** (`SPLIT_QT`), and from any QT leaf a nested **Multi-Type Tree (MTT)** supporting symmetric **Binary Tree** splits (`SPLIT_BT_H`, `SPLIT_BT_V`, `1:1`) and asymmetric **Ternary Tree** splits (`SPLIT_TT_H`, `SPLIT_TT_V`, `1:2:1`). Once a node executes any BT or TT split, further `SPLIT_QT` splits are normatively forbidden in its subtree; recursion depth is bounded instead by slice/SPS `max_mtt_hierarchy_depth_{intra_slice_luma, inter_slice, intra_slice_chroma}`.

In `libavcodec/vvc/ctu.c:526-623`, FFmpeg encodes exact normative split admissibility in `can_split()`, `allow_split_qt()`, `allow_split_bt()`, and `allow_split_tt()`:

| Split Mode | Spatial Geometry `(w, h)` -> Children | Core Admissibility Invariants (`libavcodec/vvc/ctu.c:526-623`) |
|---|---|---|
| `SPLIT_NONE` | `(w, h)` leaf Coding Unit (CU) | Forbidden if `x0 + w > pps_pic_width_in_luma_samples` or `y0 + h > pps_pic_height_in_luma_samples` (mandatory implicit boundary split). |
| `SPLIT_QT` | four `(w/2, h/2)` quadrants | Requires `mtt_depth == 0`, `w > min_qt_size` (`MinQtSizeY` or `MinQtSizeC`), and `w == h`. Forced implicitly when `w > max_tb_size` (`64` when `sps_max_luma_transform_size_64_flag == 0`, or `> 64` across VPDU rules). |
| `SPLIT_BT_H` / `SPLIT_BT_V` | two `(w, h/2)` or `(w/2, h)` halves | Requires `h > min_bt_size` (or `w > min_bt_size`), `w <= max_bt_size`, `h <= max_bt_size`, `mtt_depth < max_mtt_depth + implicit_offset`. Forbidden if resulting chroma CB would violate 2-sample width alignment or if a preceding parent TT split makes the identical midpoint redundant (`last_split == SPLIT_TT_H/V` at middle child). |
| `SPLIT_TT_H` / `SPLIT_TT_V` | `(w, h/4), (w, h/2), (w, h/4)` or vertical | Requires `h >= 2 * min_tt_size` (minimum `h >= 16` so quarter children have `>= 4` luma samples), `w <= min(64, max_tt_size)`, `h <= min(64, max_tt_size)`, `mtt_depth < max_mtt_depth`, and **complete containment inside the picture** (`x0 + w <= pic_w && y0 + h <= pic_h` — ternary splits are unconditionally forbidden across right/bottom picture boundaries). |

Three structural consequences directly shape memory-safe decoder design:

1. **64x64 Virtual Pipeline Data Unit (VPDU) hardware invariant (`ctu.c:550-595`):** Hardware decoders pipeline CTUs in `64x64` luma tiles. Consequently, H.266 forbids `128x128 -> 128x64` (`SPLIT_BT_H`) when `y0 + 64 > pic_h` is false? More specifically, `SPLIT_TT_H` and `SPLIT_TT_V` are forbidden whenever `w > 64` or `h > 64`, and `128x64` (`BT_H` from `128x128`) cannot subsequently split via `BT_H` into `128x32` (which would span two horizontally adjacent `64x64` VPDUs without honoring VPDU raster completion); instead a `128x64` node may only terminate as a `128x64` CU (split internally into two `64x64` TUs) or split vertically (`SPLIT_BT_V`) into two `64x64` VPDUs.
2. **Picture-boundary implicit split cascades (`ctu.c:2315-2365`):** When `x0 + cb_w > pic_w` and `y0 + cb_h > pic_h` simultaneously with `cb_w > min_qt_size`, `SPLIT_QT` is inferred without signaling bins; when only the right edge overflows, `SPLIT_BT_V` is inferred; when only the bottom edge overflows, `SPLIT_BT_H` is inferred. A verified parser must prove strict well-founded termination of `dual_tree_implicit_qt_split()` and `coding_tree()` over `(log2_cb_w + log2_cb_h)` even on adversarial `pps_pic_width_in_luma_samples` values (note H.266 requires picture dimensions to be multiples of `Max(8, MinCbSizeY)`).
3. **Separate Chroma Coding Tree (`DUAL_TREE_LUMA` / `DUAL_TREE_CHROMA`) and Local Dual Tree (`MODE_TYPE_INTRA` / `MODE_TYPE_INTER`, `ctu.c:2370-2485`):** In I-slices (`qtbtt_dual_tree_intra_flag == 1`), each `64x64` VPDU decodes a luma partition tree (`DUAL_TREE_LUMA`) down to `4x4` before decoding an independent chroma partition tree (`DUAL_TREE_CHROMA`), preventing `4x4` luma splits from inducing `2x2` 4:2:0 chroma blocks. Even in single-tree P/B slices (`SINGLE_TREE`), VVC forbids `2x2`, `2x4`, and `4x2` chroma intra blocks (`< 16` chroma samples or chroma width `< 4`): when a small MTT split (`cb_w * cb_h == 16` or `cb_w == 4` in 4:2:0) would violate this, VVC activates **Local Dual Tree (`mode_type`)**, restricting the small sub-tree either to `MODE_TYPE_INTER` (4:2:0 `2xN` inter chroma MC is permitted, or disallowed for `2x2` via `SCALING` / parent restriction) or `MODE_TYPE_INTRA` (luma splits into small intra CUs while chroma stays a single larger intra CU at the parent node).

### 2. Multi-Window Table-Free CABAC and Residual Bin-Throughput Caps

`Basis: normative` (ITU-T H.266 §9.3.2, §9.3.3.2) and `Basis: source` (`FFmpeg/FFmpeg` `libavcodec/vvc/cabac.h:28-140`, `libavcodec/vvc/cabac.c:35-95, 818-914, 2095-2145`; `fraunhoferhhi/vvdec` `source/Lib/CommonLib/Contexts.h:80-210`, `source/Lib/DecoderLib/BinDecoder.h:70-185`).

Whereas H.264 and HEVC store each CABAC context as a 6-bit probability index (`0..63`) + 1-bit MPS and step through a 256-byte `ff_h264_cabac_range_lps` lookup ROM, VVC replaces table-driven state transitions with **linear two-timescale exponential moving-average (EMA) estimators** updated via pure shifts (`cabac.c:818-914`):

- **Dual probability estimators:** Each context model maintains two unsigned fixed-point probability accumulators `(s0, s1)` representing `P(bin == 1)` (`FFmpeg` `CABACContext` / `VVdeC` `ProbModel`, where VVdeC packs both accumulators into a single `uint32_t` to execute parallel SIMD/SWAR shift-subtract updates):
  - $s_0 \in [0, 2^{10}-1]$ (`10`-bit fast-adapting estimator with context-specific shift rate $r_0 \in \{2, 3, 4, 5\}$ unpacked from `rate = ctx->rate`: `r0 = (rate >> 4) + 2`).
  - $s_1 \in [0, 2^{14}-1]$ (`14`-bit slow-adapting estimator with shift rate $r_1 = (rate \& 0xf) + 3 + r_0 \in \{5..12\}$).
- **Combined 15-bit LPS probability and `rLPS` multiplication:** Before decoding a regular bin (`ff_vvc_cabac_decode`, `cabac.c:860-905`), the combined 10-bit probability of `1` is `p = (s0 + (s1 >> 4) + 1) >> 1` (or equivalent 15-bit scaling in `VVdeC` `BinDecoder.h`), yielding the Least Probable Symbol (`LPS`) indicator `(p >= 512)` and quantized 5-bit probability index `q_p = min(p, 1023 - p) >> 4`. Rather than indexing a 2D ROM, the sub-range product reduces to a compact linear multiplication:
  $$\text{rLPS} = \left(\text{q\_p} \times (\text{ivlCurrRange} \gg 5) \gg 1\right) + 4$$
  This replaces cache-miss-prone ROM lookups on sequential bitstream critical paths with deterministic 32-bit integer ALU instructions (`imul`, `shr`, `cmov`).
- **Branchless dual-window update:** Given decoded bit `b ∈ {0, 1}`, if `b == 1`, `(s0, s1)` shift toward full scale (`s0 += (1023 - s0) >> r0`, `s1 += (16383 - s1) >> r1`); if `b == 0`, `s0 -= s0 >> r0` and `s1 -= s1 >> r1` (`cabac.c:832-855`). Because $0 \le s_0 \le 1023$ and $0 \le s_1 \le 16383$ are inductively preserved for all $r_0 \ge 1, r_1 \ge 1$, **state indices can never go out of bounds**, eliminating an entire class of fuzzer-reachable table-index faults.
- **Residual coefficient zero-out and `1.75` regular-bin budget (`cabac.c:2095-2145`):** For large `64x64`, `64x32`, or `32x64` transform blocks (`DCT-II`), VVC normatively zeros out high-frequency subblocks outside the top-left `32x32` region (`log2_zo_tb_width = min(log2_tb_width, 5)`, `log2_zo_tb_height = min(log2_tb_height, 5)` — further restricted to `16x16` when `MTS != DCT2` or `LFNST != 0`). Inside the active zero-out area, regular context-coded bins (`sig_coeff_flag`, `par_level_flag`, `abs_level_gtx_flag[0..1]`) are strictly capped at:
  $$\text{rem\_bins\_pass1} = \frac{7 \times 2^{\text{log2\_zo\_w} + \text{log2\_zo\_h}}}{4} = 1.75 \text{ regular bins / active sample}$$
  (`cabac.c:2109`). Once `rem_bins_pass1 < 4`, the decoder switches remaining coefficients in the TU entirely to bypass-coded Golomb-Rice `abs_remainder` (`dec_abs_level`, `cabac.c:2333-2401`), bounding worst-case CABAC sequential latency in hardware and software parsers.

### 3. Dependent Quantization (DepQuant) Trellis and Inverse Scaling Bounds

`Basis: normative` (ITU-T H.266 §8.7.3, §9.3.4.2) and `Basis: source` (`FFmpeg/FFmpeg` `libavcodec/vvc/cabac.c:2056-2058, 2333-2401`, `libavcodec/vvc/intra.c:308-358`; `fraunhoferhhi/vvdec` `source/Lib/CommonLib/Quant.cpp:85-190`).

When `sh_dep_quant_used_flag == 1` (mutually exclusive with Transform Skip and sign data hiding), VVC replaces memoryless scalar reconstruction with a **4-state trellis automaton** `qstate ∈ {0, 1, 2, 3}` initialized to `0` at the start of each Transform Block (`cabac.c:2112`) and stepped across every coefficient position in reverse-diagonal subblock scan order (including `0`-valued non-significant positions!).

- **State transition table (`cabac.c:2056-2058`):**
  ```c
  static const uint8_t qstate_translate_table[4][2] = {
      { 0, 2 }, { 2, 0 }, { 1, 3 }, { 3, 1 }
  };
  ```
  At each scan position, the *current* `qstate` selects the parity context offset for CABAC (`ctx_offset + (qstate >> 1)`) **and** selects which quantizer reconstructs the coefficient:
  - States `{0, 1}` (`(qstate & 2) == 0`, i.e., `qstate <= 1`) select **Quantizer $Q_0$**, whose reconstruction levels are integer multiples of the step size $\Delta$: $\hat{c} = \text{sign} \cdot (2 \cdot |\text{level}|) \cdot (\Delta / 2)$.
  - States `{2, 3}` (`(qstate & 2) != 0`, i.e., `qstate > 1`) select **Quantizer $Q_1$**, whose reconstruction levels are odd multiples of $\Delta / 2$ for nonzero levels: $\hat{c} = \text{sign} \cdot (2 \cdot |\text{level}| - 1 + \dots)$ — in H.266 bitstream syntax, `absLevel` already folds the parity bit, and FFmpeg's `cabac.c:2390-2398` stores reconstructed pre-scaled integers `(2 * abs_level - (qstate > 1 ? 1 : 0))` (equivalently in `intra.c:342-348`, scaling shifts QP by `+1` and right-shifts by an extra `+1` bit!).
  After reconstructing position $k$, `qstate = qstate_translate_table[qstate][abs_level & 1]`. Notice that even when `sig_coeff_flag == 0` (`abs_level == 0`), `qstate` transitions `0 -> 0`, `1 -> 2`, `2 -> 1`, `3 -> 3`! Skipping zero-coefficient positions in a sparse run-length decoder without advancing `qstate` through the $2\times$-periodic permutation `(1 <-> 2)` is a classic clean-room bug (`VVdeC` `Quant.cpp` fast-forwards zero runs of length $L$ by swapping states `1` and `2` iff $L \bmod 2 == 1$).
- **Exact inverse quantization dynamic range (`intra.c:314-348`):**
  - Effective quantization parameter: `qp = av_clip(qp_y + qp_bd_offset, 0, 63 + 6 * (bit_depth - 8)) + sh_dep_quant_used_flag` (`addin = ts ? 0 : s->ps.sh->r->sh_dep_quant_used_flag`, `intra.c:314`).
  - Scaling table: `level_scale[6] = { 40, 45, 51, 57, 64, 72 }` indexed by `qp % 6`, optionally multiplied by `scaling_list` (`16` default, adding `+4` shift).
  - Right-shift normalization: `bd_shift = bit_depth + rect_non_ts_shift + log2_tb_w + log2_tb_h - 5 + sh_dep_quant_used_flag + 4 (scaling_list)`, where `rect_non_ts_shift` compensates odd `log2_tb_w + log2_tb_h` (`× 181 / 256` $\approx 1/\sqrt{2}$ baked into `scale_m`).
  - Output saturation: Every dequantized coefficient is clipped via `av_clip_intp2(..., 15)` to **`[-32768, 32767]`** (`log2_transform_range = 15`, independent of whether `bit_depth` is 8, 10, or 12, except extended-precision profiles outside Main 10). Thus all `int16_t` inputs to LFNST and 1D inverse transforms are strictly bounded in `[-32768, 32767]`.

### 4. Multiple Transform Selection (MTS), LFNST, MIP, ISP, and CCLM

`Basis: normative` (ITU-T H.266 §§8.4.5.2, 8.7.4) and `Basis: source` (`FFmpeg/FFmpeg` `libavcodec/vvc/intra.c:70-169, 432-485`, `libavcodec/vvc/itx_1d.c:35-708`, `libavcodec/vvc/intra_utils.c:1-380`; `fraunhoferhhi/vvdec` `source/Lib/CommonLib/TrQuant.cpp`, `source/Lib/CommonLib/x86/TrafoX86.h`).

VVC places a **secondary non-separable transform (LFNST)** between dequantization and the **primary separable 2D transform (MTS)**:

$$\text{CABAC + DepQuant} \xrightarrow{[-2^{15}, 2^{15}-1]} \text{LFNST (4x4 or 8x8 low-freq)} \xrightarrow{[-2^{15}, 2^{15}-1]} \text{1D Vertical ITX} \xrightarrow{[-2^{15}, 2^{15}-1]} \text{1D Horizontal ITX} \xrightarrow{\text{res } i16} \text{Pred + Clip}$$

1. **LFNST (`intra.c:70-169`, `scale_coeff` & `lfnst_transform`):**
   - Active only for intra CUs (both luma and chroma when `tree_type` matches) with `lfnst_idx ∈ {1, 2}` when primary transform is `DCT2 × DCT2` (normatively disabled if explicit `MTS != DCT2`, `transform_skip_flag == 1`, or `ISP` produces sub-blocks `< 4x4`; for ISP with `w >= 4 && h >= 4`, LFNST applies without zero-out modification).
   - **Matrix shapes:** Intra mode maps to one of 4 transform sets (`lfnst_tr_set_index` in `0..3`), and `lfnst_idx - 1` selects kernel `0` or `1`.
     - If `min(w, h) == 4`: applies a **`16 × 8`** matrix (`w == 4 && h == 4`) or **`16 × 16`** matrix (`max(w, h) >= 8`) reconstructing the top-left `4x4` block (16 outputs) from the first 8 or 16 scan coefficients (`ff_vvc_lfnst_4x4[set][kernel]`).
     - If `min(w, h) >= 8`: applies a **`48 × 8`** matrix (`w == 8 && h == 8`, since coefficients `8..15` in the top-left `4x4` subblock are normatively zeroed) or **`48 × 16`** matrix (`max(w, h) >= 16`) reconstructing **three `4x4` subblocks** (`(0,0)`, `(4,0)`, `(0,4)`, 48 outputs total; subblock `(4,4)` and all higher subblocks are forced to zero in the bitstream) (`ff_vvc_lfnst_8x8[set][kernel]`).
   - **Fixed-point dynamic range proof:** LFNST basis weights are `int8_t` in `[-128, 127]` (scaled by `128`). For `N <= 16` inputs $x_i \in [-32768, 32767]$:
     $$\left|\sum_{i=0}^{15} w_{j,i} x_i + 64\right| \le 16 \times 128 \times 32768 + 64 = 67{,}108{,}928 < 2^{26} < 2^{31}-1$$
     Thus a 32-bit signed accumulator **never overflows**, and `av_clip_intp2((sum + 64) >> 7, 15)` (`intra.c:84`) restores the `[-32768, 32767]` invariant before primary 1D transforms run.

2. **Multiple Transform Selection (MTS, `itx_1d.c:459-708`):**
   - Supports independent horizontal and vertical 1D transforms selected from **8-bit integer approximations** of `DCT-II` (`2, 4, 8, 16, 32, 64`-point), `DST-VII` (`4, 8, 16, 32`-point), and `DCT-VIII` (`4, 8, 16, 32`-point), plus `ITX_1D_NONE` (Transform Skip).
   - Whereas `DCT-II` admits even/odd butterfly decomposition ($O(N \log N)$ via recursive `itx_dct2_{4,8,16,32,64}`), `DST-VII` and `DCT-VIII` lack full dyadic butterfly symmetry above small sizes and reduce to dense or partially factored matrix-vector products (`itx_dst7_{4,8,16,32}`, `itx_dct8_{4,8,16,32}`, `itx_1d.c:460-685`). To bound worst-case MAC count per sample, VVC restricts `DST-VII`/`DCT-VIII` to `w <= 32, h <= 32` and zeros out coefficients outside the top-left `16x16` quadrant whenever a `32`-point `DST-VII` or `DCT-VIII` is chosen!
   - **Two-pass 1D rounding:** Vertical 1D ITX rounds by `(sum + 64) >> 7` and clips to `[-32768, 32767]`; Horizontal 1D ITX rounds by `(sum + (1 << (shift - 1))) >> shift` with `shift = 20 - bit_depth` (`12` for 8-bit, `10` for 10-bit, `8` for 12-bit), yielding residual samples ready to add to prediction and clip to `[0, (1 << bit_depth) - 1]`.

3. **Intra Sub-Partitions (ISP), MIP, and CCLM (`intra.c:432-485`, `intra_utils.c`):**
   - **ISP:** Splits a luma intra CU horizontally or vertically into 2 (`4x8` or `8x4`) or 4 (all larger CUs) 1D sub-partitions—including **`1xN` (`1x16`, `1x32`, `1x64`) and `2xN` (`2x8`, `2x16`, `2x32`, `2x64`)** strips! Each sub-partition undergoes inverse transform and reconstruction **sequentially** so its reconstructed pixels immediately serve as reference samples for the next sub-partition inside the same CU (`intra.c:455-485`). Clean-room SIMD dispatchers must explicitly guard `w < 4` (`w ∈ {1, 2}`) in intra prediction and residual addition!
   - **MIP (Matrix-based Intra Prediction):** Downsamples top/left boundary lines to 4 or 8 samples, multiplies by small ROM matrices (`uint8_t` weights with offset), and bilinearly upsamples to the target block.
   - **CCLM (Cross-Component Linear Model):** Reconstructs chroma intra prediction from collocated **downsampled luma** (`LM_CHROMA`, `LM_L`, `LM_T`) via `pred_c = clip((alpha * luma_ds) >> shift + beta)`. In dual-tree or single-tree decoding, this creates an explicit intra-CTU data dependency: chroma `RECON` must wait for collocated luma `RECON` (before luma undergoes in-place LMCS inverse reshaping or deblocking!).

### 5. Subblock Inter Prediction: Affine + PROF, GPM, BDOF, and DMVR

`Basis: normative` (ITU-T H.266 §§8.5.3–8.5.6) and `Basis: source` (`FFmpeg/FFmpeg` `libavcodec/vvc/mvs.c:323-450`, `libavcodec/vvc/inter.c:595-967`, `libavcodec/vvc/inter_template.c:260-573`; `fraunhoferhhi/vvdec` `source/Lib/CommonLib/InterPrediction.cpp`).

VVC's inter pipeline decomposes complex motion into `4x4` or `16x16` subblock grids while preserving bounded memory bandwidth and division-free integer arithmetic:

| Tool | Granularity | Primary-Source Arithmetic & Hardware/Safety Invariants (`FFmpeg` `libavcodec/vvc/`) |
|---|---|---|
| **4/6-Param Affine + PROF** | `4x4` luma subblocks | Control-point MVs `(mv0, mv1[, mv2])` interpolate per-`4x4` center MVs (`ff_vvc_store_sb_mvs`, `mvs.c:323-450`). Look at `derive_affine_mvc` (`inter.c:908-915`): FFmpeg casts `(unsigned)mv->x + ...` to **unsigned** before clipping because malicious/out-of-range control-point deltas can overflow signed 32-bit `int`! Furthermore, `affine_cps_from_nb` / fallback bounding-box spread (`inter.c:885-945`) tests whether the `4x4` subblock MVs exceed `225` (`4`-param) or `165` (`6`-param) `1/16`-pel units across an `8x8` group; if exceeded, VVC **falls back to whole-CU center MV fetch** and disables PROF to bound worst-case DRAM cache-line gathers! When active, **PROF** (`apply_prof`, `inter_template.c:260-360`) computes spatial Sobel-like `gx, gy` gradients on `16`-bit unclipped MC intermediates and adds `clip(gx * dmv_x + gy * dmv_y, -dILimit, dILimit - 1)` with `dILimit = 1 << max(13, bit_depth + 1)`. |
| **GPM (Geometric Partitioning)** | `8x8` to `64x64` CUs (`w,h >= 8`) | 64 partition lines (24 angles × up to 4 radial offsets, excluding `1:8`/`8:1` aspect ratios). Evaluates two uni-predicted 16-bit MC arrays `pred0, pred1` and blends via precomputed ramp weight masks `w ∈ [0, 8]`: `(w * pred0 + (8 - w) * pred1 + offset) >> shift` (`inter.c:720-795`), storing split-zone motion vectors into the `4x4` MV field according to motion-mask thresholds. |
| **DMVR (Decoder-Side MV Refinement)** | `<= 16x16` sub-PUs (`w >= 8, h >= 8, w*h >= 128`) | True bi-prediction with equal opposite POC distances (`POC - POC0 == POC1 - POC`), zero CU weights, and luma-only refinement (`inter_template.c:470-573`). Fetches `[-2, +2]` integer-pel search window via fast **2-tap bilinear** interpolation, evaluates 25-point downsampled SAD (even rows only, halving SAD ops!), and applies **division-free parametric parabolic surface fitting** (`sad_subpel`) on `(E[-1], E[0], E[+1])` to derive `1/16`-pel `dmv` before final 8-tap luma / 4-tap chroma MC. **Concurrency consequence:** DMVR overwrites the sub-PU's stored `4x4` MVs used for spatial/deblocking/collocated-TMVP neighbors (`thread.c:491-516`)! |
| **BDOF (Bi-Directional Optical Flow)** | `4x4` subblocks inside `<= 16x16` bi-pred units | Refines 16-bit L0/L1 predictions (`pred0, pred1`) on an extended `6x6` gradient window (`apply_bdof`, `inter_template.c:365-465`). Computes cross-correlations $s_{G_x^2}, s_{G_y^2}, s_{G_x G_y}, s_{G_x dI}, s_{G_y dI}$ and solves for optical flow $(v_x, v_y) \in [-15, 15]$ **without integer division** via `av_log2(sGx2)` bit-length normalization! Adds `bdof_offset = (vx * (gx0 - gx1) + vy * (gy0 - gy1) + 1) >> 1` prior to bi-pred averaging. |

### 6. In-Loop Reshaping and Filtering: LMCS, 7-Tap Deblocking, SAO, ALF/CCALF, and Virtual Boundaries

`Basis: normative` (ITU-T H.266 §§8.7.5, 8.8.2–8.8.5) and `Basis: source` (`FFmpeg/FFmpeg` `libavcodec/vvc/ps.c:830-921`, `libavcodec/vvc/filter.c:1-995`, `libavcodec/vvc/filter_template.c:38-795`).

VVC executes four sequential post-reconstruction stages across each CTU:

1. **Luma Mapping with Chroma Scaling (LMCS, `ps.c:830-921`, `filter.c:160-210`):**
   - Partitions `[0, 1 << bit_depth)` into 16 equal bins (`OrgCW = (1 << bit_depth) >> 4`), mapping inter-frame reference luma via a 16-segment piecewise-linear **forward LUT (`lmcs_fwd_lut`)** before adding luma residuals, and mapping reconstructed luma back to the original perceptual domain via **`lmcs_inv_lut`** immediately before Deblocking. Meanwhile, **intra prediction operates purely in the reshaped domain**!
   - **Chroma Residual Scaling (`chroma_scale_coeff`):** Scales TU chroma residuals by the piecewise slope of the average top/left reshaped luma neighbors (`(res * scale + (1 << 10)) >> 11`). To avoid stalling chroma reconstruction on fine-grained CU luma reconstruction in hardware, VVC fixes one luma-dependent chroma scale per **`64x64` VPDU** (using the top-left `64x64` boundary luma neighbors)!
   - **Concurrency anti-dependency (`thread.c:188, 290-305`):** Because `ff_vvc_lmcs_filter` (`LMCS` stage) mutates `frame->data[0]` **in place** from reshaped luma to unreshaped luma, CTU $(x, y)$ **cannot** run `LMCS` until CTUs $(x+1, y)$, $(x, y+1)$, and $(x+1, y+1)$ have all completed **`RECON`** (since their intra/CCLM/LMCS predictors read CTU $(x, y)$'s right/bottom edges in the **reshaped** domain!).

2. **Deblocking Filter (`filter.c:230-780`, `filter_template.c:456-795`):**
   - Evaluates Boundary Strength (`BS ∈ {0, 1, 2}`) on an `8x8` grid (for CU/TU/SBT edges and `8x8` affine/ATMVP/DMVR subblock edges; `4x4` ISP sub-edges are skipped vertically/horizontally when orthogonal grid $< 8$).
   - **Long 7-tap luma & 3-tap chroma filters:** When either side of a `32`-aligned luma grid edge has perpendicular block length $\ge 32$, VVC extends HEVC's 4-sample modification window to modify up to **7 luma samples (`p0..p6` / `q0..q6`)** on each side using linear ramp interpolation toward middle reference levels (`vvc_deblock_luma_large`, `filter_template.c:520-645`), and up to **3 chroma samples (`p0..p2` / `q0..q2`)** when both chroma sides have length $\ge 8$.
   - **Order invariant:** All vertical edges across the frame logically filter before horizontal edges (`DEBLOCK_V` -> `DEBLOCK_H`), and because `p0..p6` reaches 7 pixels across a CTU boundary (reading `p7`), CTU $(x, y)$'s `DEBLOCK_H` on its top edge modifies bottom rows of CTU $(x, y-1)$ and cannot run until CTU $(x+1, y)$ has completed `DEBLOCK_V` (`target_score` = 2 in `thread.c:190`).

3. **Sample Adaptive Offset (SAO, `filter.c:790-895`):**
   - Identical in core structure to HEVC (Band Offset 4 consecutive bands of 32; Edge Offset 4 directional `3x3` convexity classifiers), operating on deblocked samples and requiring pre-SAO border backup strips (`sao_pixel_buffer_h/v`) because `EO` reads all 8 8-connected neighbors.

4. **Adaptive Loop Filter (ALF) & Cross-Component ALF (CCALF, `filter.c:901-989`, `filter_template.c:38-404`):**
   - **13-tap 7x7 luma diamond + non-linear clipping:** Classifies each `4x4` luma block into 1 of **25 classes** (5 directionality × 5 activity quantiles derived from `4x4` horizontal/vertical/diagonal Laplacian gradients over an `8x8` halo) and geometric transpose/rotation `transpose_idx ∈ {0..3}`, indexing APS or fixed ROM filter sets (`64` fixed × `16` mappings). Notice the **32-bit signed overflow hazard** in gradient direction ratio tests (`filter_template.c:265-295`): `hv1 * d0` can exceed $2^{31}-1$ at 12-bit (`hv1` up to $24 \times 4095 \times \dots$), requiring `int64_t` products (`(int64_t)d1 * hv0 <= (int64_t)hv1 * d0`).
   - Each symmetric neighbor pair $(n_k^+, n_k^-)$ is **clipped non-linearly relative to center pixel `curr`** before multiplying by filter tap $f_k \in [-127, 127]$ (`filter_template.c:55-85`):
     $$s = \text{curr} + \left(\left(\sum_{k=0}^{11} f_k \cdot \left(\text{clip}(n_k^+ - \text{curr}, -c_k, c_k) + \text{clip}(n_k^- - \text{curr}, -c_k, c_k)\right) + 64\right) \gg 7\right)$$
     Chroma applies a **5x5 7-tap** clipped diamond, and **CCALF** (`alf_filter_cc`, `filter_template.c:145-195`) adds a high-pass **3x4 7-tap luma diamond** correction (`(sum + 64) >> 7`, using 3-bit signed power-of-two shift weights `±{0, 1, 2, 4, 8, 16, 32, 64}`) directly onto U and V!
   - **Virtual Boundary (`ctu_end - 4`) Hardware Line-Buffer Invariant (`filter_template.c:95-140`):** An unrestricted 7x7 ALF diamond centered 1 pixel above the bottom of a CTU row (`y = ctu_end - 1`) would reach 3 rows into the *next* CTU row, which is simultaneously undergoing `DEBLOCK_H` (writing up to 7 rows above `ctu_end`)! To prevent hardware decoders from buffering 7+ full-frame deblocked luma lines, H.266 places a **Virtual Boundary 4 luma samples (`ctu_end - 4`) and 2 chroma samples (`ctu_end_c - 2`) above every horizontal CTU boundary** (except the bottom of the picture). Neither ALF nor CCALF ever reads across `y = ctu_end - 4`: for rows `ctu_end - 5` and `ctu_end - 4` (above VB) and `ctu_end - 3` and `ctu_end - 2` (below VB), out-of-side diamond taps are symmetrically mirrored (`p1 = p0`, `p2 = p0`, `p3 = p0`) **and** when 1-line mirroring occurs (`y == ctu_end - 4` or `y == ctu_end - 3`), the rounding right-shift increases from **`7` to `10` (`+ (1 << 9)) >> 10`, attenuating filter gain by `8x`)** (`filter_template.c:72-78`)!

#### Deep Dive: FFmpeg's Armv9 SME2 Kernel (`libavcodec/aarch64/vvc/inter_sme2.S`)

A critical primary-source discovery for anyone indexing or verifying FFmpeg's assembly corpus: **`libavcodec/aarch64/vvc/inter_sme2.S` (`651` lines) contains zero motion-compensation routines**. As verified in `libavcodec/aarch64/vvc/dsp_init.c:327-329, 382-384, 438-440` and `alf_template.c:246-274`, it exports three **ALF 13-tap luma diamond kernels**:

- `ff_vvc_alf_filter_luma_8_sme2` (`inter_sme2.S:196-360`)
- `ff_vvc_alf_filter_luma_10_sme2` (`inter_sme2.S:642-645`, instantiating macro `alf_filter_luma_16bit 10`)
- `ff_vvc_alf_filter_luma_12_sme2` (`inter_sme2.S:647-650`, instantiating macro `alf_filter_luma_16bit 12`)

Gated at runtime by `have_sme2(cpu_flags) && have_sme_i16i64(cpu_flags)` (`dsp_init.c:438`) and dispatched by `alf_filter_luma_sme2_{8,10,12}` only when `(width >= 16 && height >= 16)` with scalar tail fallback for trailing columns (`width % 16`) (`alf_template.c:250-272`), its microarchitecture demonstrates both the throughput power and formal-verification subtleties of Streaming SVE2 + `ZA` matrix storage:

1. **Streaming mode transition & `ZA` initialization (`inter_sme2.S:201-215`):** Invokes `sme_entry` (`smstart` entering Streaming SVE + enabling `ZA`, saving `d8–d15` per AAPCS64 SME ABI) and seeds four horizontal `ZA.D` tile slices (`za0.d`..`za3.d`, corresponding to 4 vertical block rows processed per outer `4x16` strip) with the rounding bias `64` (`dup z16.d, #64` followed by `mova za0h.d[w12, 0:3], {z16.d-z19.d}`).
2. **4-way multi-vector `sdot` accumulation (`inter_sme2.S:105-185`):** For each diamond tap pair `(n+, n-)`, loads neighboring pixels across 4 consecutive rows, computes signed differences `n - curr`, clamps via SME2 multi-vector `sclamp {z20.h-z23.h}, z24.h, z25.h`, sums symmetric pairs, and executes **`sdot za.d[w10, idx], {z20.h-z23.h}, {z28.h-z31.h}`** (`FEAT_SME_I16I64`, computing 4-way 16-bit × 16-bit signed dot products directly into 64-bit `ZA` accumulators!).
3. **Virtual-boundary shift selection & subtle `add` vs `sqadd` divergence (`inter_sme2.S:310-345` vs `:595-630`):** Extracts `ZA` slices back to Z-registers via `mova {z20.d-z23.d}, za0h.d[w12, 0:3]`, narrows and rounds 64-bit sums to 16-bit via multi-vector `sqrshr {z20.h-z21.h}, {z20.d-z23.d}, #7` (normal rows) or `#10` (`vb_pos` adjacent rows!). Then:
   - In **8-bit (`inter_sme2.S:332`)**, it adds `curr` with **wrapping 16-bit `add`** (`add z20.h, z20.h, z0.h`) followed by `sclamp` to `[0, 255]`. Because `curr ∈ [0, 255]` and `|sum >> 7| <= (12 * 2 * 255 * 127 + 64) >> 7 = 6071`, `curr + delta ∈ [-6071, 6326]`, which never overflows signed `int16_t` (`[-32768, 32767]`).
   - In **10/12-bit (`inter_sme2.S:617`)**, at 12-bit `curr ∈ [0, 4095]` and worst-case `delta` with unclipped `c_k = 4096` reaches `(12 * 2 * 4095 * 127 + 64) >> 7 = 97512 > 32767`! Wait: `sqrshr` **already saturates** the shifted `int64_t` result to signed 16-bit `[-32768, 32767]`, and `curr + 32767` up to `4095 + 32767 = 36862 > 32767` would wrap to negative under signed 16-bit `add`, so line `617` uses **signed saturating `sqadd`** (`sqadd z20.h, z20.h, z0.h`) before `sclamp` to `[0, (1 << bd) - 1]`! A bit-exact SMT proof (`verified-simd-vs-scalar-equivalence-for-media-dsp-kernels-and-asm`) must verify that `sqrshr` saturation at `±32767` cannot diverge from C's 32-bit `(sum + 64) >> 7` prior to `[0, (1 << bd) - 1]` output clipping: since `curr >= 0` and `max_pix = 4095`, any `delta >= 4095` clips to `4095` and any `delta <= -4095` clips to `0`, and `32767 >= 4095` holds strictly!
   - Finally, `zero {za}` (`inter_sme2.S:355`) clears `ZA` before `sme_exit` (`smstop`), avoiding streaming-mode state leaks across FFI seams (`rvv-lmul-vtype-hazards-arm-sme-streaming-za-tiles-and-ffload-speculation`).

### 8. 2D CTU Stage-Scoreboard Concurrency DAG (`vvc/thread.c`) vs VVdeC Row-Chunk State Polling

`Basis: source` (`FFmpeg/FFmpeg` `libavcodec/vvc/thread.c:42-847`, `libavcodec/vvc/dec.h:150-245`, `libavcodec/vvc/refs.c:638-712`; `fraunhoferhhi/vvdec` `source/Lib/DecoderLib/DecLibRecon.cpp:415-1112`; Wieckowski et al., `10.1109/ICIP40778.2020.9191199`).

#### FFmpeg's 10-Stage Atomic CTU Scoreboard (`libavcodec/vvc/thread.c`)

FFmpeg allocates one `VVCTask` per CTU $(r_x, r_y)$ per frame (`VVCFrameThread`), advancing strictly linearly through 10 `VVCTaskStage` states (`thread.c:42-55`), guarded by `atomic_uchar score[VVC_TASK_STAGE_LAST]` and `atomic_uchar target_inter_score` (`thread.c:77-78`). Stage $S$ of CTU $(r_x, r_y)$ becomes runnable iff `score[S] == target_score[S] + 1`, where the `+1` token comes from completing stage $S-1$ on the **same** CTU (`task_has_target_score`, `thread.c:184-216`):

| Stage (`VVCTaskStage`) | `target_score` (+1 self) | Spatial / Inter-Frame Predecessors Signaling `+1` into `(rx, ry)` (`thread.c:240-360`) | Why This Exact Predecessor Set Is Necessary and Minimal |
|---|---|---|---|
| `0: INIT` | `0` (`1` root / slice-prev) | Previous CTU in slice/entry-point (`PARSE` unlocks next entry/raster `INIT`) | Initializes CTU structures (`ctu.c`) in slice/WPP entry order. |
| `1: PARSE` | `0` + WPP top-right (`1` or `2`) | Previous CTU in tile/entry-point + WPP top-right CTU `(rx+1, ry-1)` (when `sps_entropy_coding_sync_enabled_flag`) + collocated ref `VVC_PROGRESS_MV` (`col_needed`) | Decodes CABAC syntax, QTBT/MTT tree, DepQuant levels, and non-DMVR MVs. Reports `VVC_PROGRESS_MV` immediately if `!ctu->has_dmvr` (`thread.c:491`). |
| `2: DEBLOCK_BS` | `2` (+1 self = `3`) | `(rx-1, ry)` (`L`) and `(rx, ry-1)` (`T`) completing `PARSE` (or `INTER` if DMVR) | Computes Boundary Strength using left and top CTUs' partition/MV/transform metadata. |
| `3: INTER` | `target_inter_score` (+1 self) | Dynamic count of `(ref_frame, VVC_PROGRESS_PIXEL, ref_y)` listener callbacks registered during `PARSE` (`check_inter_Ready`, `thread.c:365-430`) | Runs fractional MC, Affine+PROF, GPM, BDOF, and DMVR once reference lines (+ padding + ALF margin) exist in reference frames. Reports deferred `VVC_PROGRESS_MV` if `ctu->has_dmvr` (`thread.c:515`). |
| `4: RECON` | `2` (+1 self = `3`) | `(rx-1, ry)` (`L`) and `(rx+1, ry-1)` (`RT`) completing `RECON` | Intra prediction (including WAIP/MIP/PDPC/CCLM) reads reconstructed **reshaped** samples from `L`, `LT`, `T`, and `RT` (`(rx+1, ry-1)` transitively implies `T` `(rx, ry-1)` and `LT` `(rx-1, ry-1)`!). |
| `5: LMCS` | `3` (+1 self = `4`) | `(rx+1, ry)` (`R`), `(rx, ry+1)` (`B`), and `(rx+1, ry+1)` (`RB`) completing `RECON` | **Write-after-read (WAR) barrier:** `LMCS` overwrites `frame->data[0]` in place from reshaped to unreshaped luma; `R` (via intra/CCLM if sub-partition/wrapping? More specifically `B` reads `T`, `RB` reads `LT`, `LB` already waited on `RT`? Wait: `(rx+1, ry)`'s `L` is `(rx, ry)`, `(rx, y+1)`'s `T` is `(rx, ry)`, `(rx+1, y+1)`'s `LT` is `(rx, ry)`, and `(rx-1, ry+1)`'s `RT` is `(rx, ry)` — note `(rx, ry+1)` cannot finish `RECON` until `(rx-1, ry+1)` (`L`) finished `RECON`, so `B` finishing `RECON` **transitively proves `LB` `(rx-1, ry+1)` already finished `RECON`!**) |
| `6: DEBLOCK_V` | `1` (+1 self = `2`) | `(rx-1, ry)` (`L`) completing `DEBLOCK_V` (plus `(rx, ry)` own `LMCS`) | Vertical edge at `x = rx * ctu_size` reads/writes up to 7 samples into `(rx-1, ry)`, which must have finished `LMCS` and its own internal vertical edges. |
| `7: DEBLOCK_H` | `2` (+1 self = `3`) | `(rx+1, ry)` (`R`) completing `DEBLOCK_V` and `(rx, ry-1)` (`T`) completing `DEBLOCK_H` | Horizontal edges must follow vertical edges covering the same pixels (including `R`'s left vertical edge modifying `(rx, ry)`'s right 7 columns!) and `T`'s horizontal pass. |
| `8: SAO` | `5` (+1 self = `6`) | `L` `(rx-1, ry)`, `R` `(rx+1, ry)`, `LB` `(rx-1, ry+1)`, `B` `(rx, ry+1)`, `RB` `(rx+1, ry+1)` completing `DEBLOCK_H` | Note `B` `(rx, ry+1)`'s `DEBLOCK_H` modifies the bottom 7 rows of `(rx, ry)`! Thus `(rx, ry)` cannot read its own final deblocked pixels for `SAO` until `LB, B, RB` finish `DEBLOCK_H` (while `LT, T, RT` already finished `DEBLOCK_H` transitively via `(rx, ry)` and `R`!). |
| `9: ALF` | `8` (+1 self = `9`) | All 8 8-connected neighbors `(rx±1, ry±1)` completing `SAO` | Reads `7x7` SAO-filtered diamond (up to `ctu_end - 4` VB and 3 columns across vertical CTU edges using saved `alf_pixel_buffer_h/v` border strips) and reports `VVC_PROGRESS_PIXEL` (`thread.c:540-565`). |

Four systems-engineering mechanisms in `thread.c` make this scoreboard scale cleanly without deadlocks or queue thrashing:

1. **Pre-scored ghost boundary CTUs (`frame_thread_init_score`, `thread.c:713-737`):** Rather than branching on `rx == 0`, `ry == 0`, `rx == ctu_w - 1`, or `ry == ctu_h - 1` inside every `task_has_target_score` check, initialization runs `shepherd_score` from virtual out-of-frame coordinates `rx ∈ {-1, ctu_w}` and `ry ∈ {-1, ctu_h}`, pre-incrementing border CTUs' `score[]` arrays so runtime readiness tests remain uniform `score == target_score[stage] + 1`!
2. **Inline stage chaining (`run_one_task`, `thread.c:665-676`):** When a worker finishes stage $S$ on CTU $t$, it executes `t->stage++` and immediately tests `task_is_stage_ready(t, 1)` (atomically adding the self-token `+1` via `atomic_fetch_add`). Whenever neighbors have already deposited their tokens, the same OS thread runs stage $S+1$ immediately in hot L1/L2 cache without touching the central scheduler mutex!
3. **3-tier priority scheduling against 8K `INTER` wakeup storms (`task_priority_higher`, `thread.c:112-125`):** Priority `0` (highest) runs `INIT` and `PARSE` to keep entropy parsing and reference-dependency discovery ahead of pixel workers; Priority `1` runs `DEBLOCK_BS` and `RECON..ALF`; Priority `2` (`PRIORITY_LOWEST`) runs **`INTER`**. As documented directly in `thread.c:112-119`, when a reference frame finishes one CTU row of an 8K video (`64` CTUs wide), `ff_vvc_report_progress` wakes up 64+ dependent `INTER` tasks at once; demoting `INTER` below `PARSE` and `RECON..ALF` prevents `INTER` floods from starving pipeline drain and inflating memory residency.
4. **Lock-order discipline across inter-frame progress (`thread.c:452-476`, `refs.c:678-712`):** Frame thread mutex `ft->lock` is explicitly **released before** calling `ff_vvc_report_progress`, and `VVCProgress` mutex `p->lock` splices satisfied `VVCProgressListener` nodes onto a stack-local list and **unlocks `p->lock` before** invoking `l->progress_done(l)`, preventing `AB-BA` deadlocks when bidirectional or out-of-order GOP frames wait on one another.

#### Contrast with VVdeC (`fraunhoferhhi/vvdec`) and Published Throughput Reality

- **VVdeC (`DecLibRecon.cpp:424-428, 645-648, 734-1112`):** Groups `numColPerTask` horizontally adjacent CTUs into one `ctuTask` unit to amortize `NoMallocThreadPool` dispatch (`ThreadPool.h`), polling neighbor `std::atomic<CtuState>` monotonically (`MIDER -> LF_INIT -> INTER -> INTRA -> RSP -> LF_V -> LF_H -> PRESAO -> SAO -> ALF -> DONE`, returning `false` to suspend and re-schedule on unmet dependencies). Crucially, VVdeC allocates a **second full-frame picture buffer `m_fltBuf`** and writes ALF output **out-of-place** into `m_fltBuf` before swapping plane pointers (`m_pic->swapPicBufs(m_fltBuf)`, `DecLibRecon.cpp:646`), eliminating FFmpeg's vertical/horizontal pre-ALF border strip copies (`alf_pixel_buffer_h/v`, `filter.c:901-989`) at the cost of `+1` frame buffer per concurrent frame thread (~`12.4 MiB` for 4K 10-bit 4:2:0).
- **Published throughput & complexity breakdown (`Basis: documentation`, Wieckowski et al. `10.1109/ICIP40778.2020.9191199` & Bross et al. `10.1109/TCSVT.2021.3101953`):** Overall VVC software decoding requires ~`1.7x–2.0x` the CPU cycles of HEVC at matching resolution (despite ~`10x` encoding complexity). In SIMD-optimized VVC decoding (VVdeC on x86-64 AVX2, Random Access 10-bit 4K), runtime distributes roughly across **Inter prediction + subblock tools (MC/DMVR/BDOF/PROF, ~30%–38%)**, **ALF + CCALF (~18%–24%)**, **Deblocking + SAO (~14%–18%)**, **CABAC + DepQuant (~12%–16%)**, and **Inverse Transforms MTS + LFNST + Intra (~12%–16%)** — explaining why FFmpeg's current scalar C `itx_1d.c` (`MTS`/`LFNST`) and partial C deblocking represent concrete optimization headroom compared to VVdeC's full SIMDe `TrafoX86.h` + `LoopFilterX86.h` suite.

### 9. Clean-Room Verification Priority Stack and Safe Ownership Implications

`Basis: derived` from the verified `FFmpeg/FFmpeg` and `fraunhoferhhi/vvdec` implementations above:

1. **Level 1 — UB-Freedom:**
   - *Integer arithmetic:* Replace C signed-int motion-vector/gradient expressions with explicit wrapping/widening Rust types: `(i32::from(mv.x)).wrapping_add(dmvx)` (`inter.c:908`), `i64` cross-products in ALF direction ratio tests (`filter_template.c:275`), and `u32` shifts for CABAC EMA updates.
   - *Memory & Concurrency:* Eliminate C raw-pointer shared-plane aliasing across the 10-stage CTU DAG. Notice why per-pixel runtime borrow tracking (`DisjointMut`) would fail catastrophically on VVC: `DEBLOCK_V/H` (modifying `±7` pixels across `8x8` grids), `LMCS` (in-place CTU rewrite), `SAO`, and `ALF` generate millions of overlapping hull ranges per 4K frame. Instead, a safe Rust VVC engine should either:
     - **(a) Capability-indexed CTU tile + halo ownership:** Store reconstructed pixels in **64x64/128x128 CTU-owned blocks** during `INTER`/`RECON`/`LMCS` (passing immutable boundary edge strips `ipred_edge` explicitly between `RECON` stages, zero shared-plane locking!), then materialize horizontal CTU-row bands for `DEBLOCK_V -> DEBLOCK_H -> SAO`, and adopt **VVdeC's out-of-place `m_fltBuf` destination plane** for `ALF` (`&Plane` read-only SAO input -> `chunks_mut` disjoint CTU strips in `&mut Plane` ALF output)!
     - **(b) Verified ghost-token epoch scheduler:** Encapsulate the `target_score = {2, 0, 2, 3, 1, 2, 5, 8}` DAG inside a small (~300 LOC) audited/Loom-and-Lean-verified `CtuScoreboard<T>` abstraction whose transition graph proves pairwise spatial disjointness of every mutable sub-window (`RECON` writes strictly `[rx*C..(rx+1)*C, ry*C..(ry+1)*C]`; `DEBLOCK_V` writes `[rx*C-7..(rx+1)*C-7, ry*C..(ry+1)*C]`; `DEBLOCK_H` writes `[rx*C..(rx+1)*C, ry*C-7..(ry+1)*C-7]`)!
2. **Level 2 — Panic-Freedom:**
   - Statically discharge slice-index bounds for non-power-of-two MTT ternary dimensions (`4, 8, 12?` Note: because splits start from powers of two and `TT` splits `1:2:1`, **every CU width and height in VVC is still a power of two** `2^k ∈ {4, 8, 16, 32, 64, 128}` — ternary `1:2:1` splits a `2^k` span into `2^{k-2}, 2^{k-1}, 2^{k-2}`! Only **ISP** creates `w ∈ {1, 2}` and **GPM** creates arbitrary diagonal blend masks inside power-of-two CUs!). Encoding `Log2Size ∈ {0..7}` as a refined type eliminates arbitrary-modulo slice panics across all non-ISP transform and MC kernels.
3. **Level 3 — Differential & SIMD-vs-Scalar Equivalence:**
   - Pair every AVX2, NEON/I8MM, and SME2 (`inter_sme2.S`) kernel against the pure Rust scalar reference over the full legal domain (`[-32768, 32767]` for LFNST/MTS, `[0, (1 << bd) - 1]` with `vb_pos` active/inactive for ALF, and `[-dILimit, dILimit - 1]` for PROF/BDOF), verifying SME2 `sqrshr` + `sqadd` == scalar 32-bit `>> 7` / `>> 10` + `av_clip_uintp2`.
4. **Level 4 — Full Functional Spec Conformance:**
   - Validate bit-exact MD5 parity against the official ITU-T H.266.1 conformance suite (Main 10 `8`-bit and `10`-bit bitstreams covering `QTBT+MTT`, `DepQuant`, `LFNST`, `MTS`, `ISP`, `MIP`, `CCLM`, `Affine+PROF`, `GPM`, `BDOF`, `DMVR`, `LMCS`, `ALF+CCALF`, subpictures, and Virtual Boundaries) and FFmpeg's `fate-vvc` differential oracle (`ffmpeg-ffprobe-ffplay-cli-pipeline-scheduler-and-fate-differential-oracle`).

## Boundaries

1. **No cycle-counter execution benchmarks were run in this capsule (`Basis: source`, `Basis: documentation`):** All microarchitectural kernel structures (`inter_sme2.S`, `alf.asm`, `TrafoX86.h`) and stage-scoreboard counts (`thread.c`) were verified directly from pinned upstream source code, while decode runtime shares are cited from peer-reviewed literature (`10.1109/ICIP40778.2020.9191199`, `10.1109/TCSVT.2021.3101953`). Measured cycle/px ratios across Zen 4/5 AVX-512 vs Apple M4 SME2 for `ff_vvc_alf_filter_luma_*_sme2` remain an empirical benchmark task on target hardware.
2. **Range Extensions, Multi-Layer/V3C, and Screen Content Coding (IBC / Palette / ACT) scope:** While `libavcodec/vvc/intra.c` and `ctu.c` implement Intra Block Copy (`IBC` hash/BV search buffer), Palette mode, Transform Skip residual coding, and Adaptive Color Transform (`ACT`), this report focuses on Main 10 profile coding tools (`8`-bit and `10`-bit 4:2:0) and up to `12`-bit DSP paths; extended precision (`> 16`-bit intermediate `log2_transform_range` in High Bit-Depth Range Extensions) breaks the `int16_t` `[-32768, 32767]` transform buffer invariant and requires `int32_t` buffers.
3. **Subpictures, RPR (Reference Picture Resampling), and Wraparound Motion:** VVC also introduces independent rectangular subpictures (treated like picture boundaries on flag) and Reference Picture Resampling (`RPR`, scaling reference frames dynamically across resolution changes without an IDR). Their reference-line progress coordinate mapping (`ff_vvc_report_progress` scaled `y` coordinates in `thread.c:375-425`) requires dedicated bounds verification when `RPR` ratios approach `2x` downscaling or `8x` upscaling.
