## Purpose

Test the proposed shared batch/LSP/MCP architecture for Anneal v2: **interactive Lean annotations and tactic-state queries; coherent Charon/Aeneas/Lean state; correct Lake reuse; and parallel integration testing without per-worker dependency-tree copies**. Identify contracts to preserve now, assumptions to reject, and optimizations to defer.

This is a research agenda, not adopted architecture or a requirement to complete every item before v2 proceeds. Rust-authored specifications translated through Aeneas are outside scope except at the proof-only invalidation boundary. Syntax, theorem encoding, and backend placement remain open under the [principles][principles] and [design contract][design].

### Existing evidence and the additional work

Review baseline: `main@cc135f46155b72e4b51188525c2974a3b84acf92` and `reference@8c257ec3f4e067963e12441ce5b261714a005c74`: the catalog, selected relevant reports, #3725's coverage audit, and Anneal guidance. It did not rerun the experiments or audit every report.

This specializes unfinished interactive/build work in #3725 and complements #3720. Issue closure does not establish completion of every proposed experiment; the [coverage audit][audit] distinguishes completed, partial, missing, and conditional evidence. Check live coverage before starting an item: extend or link existing work rather than repeat surveys. Related: #3016, #3668, #3485, #3486.

The [old-version wait probe][wait] establishes an orderly version sequence, not a simultaneous edit race or a complete query/patch protocol. The [stale-import probe][imports] covers `lake env lean --server`, not every launch/reset mode. The [read-only probe][readonly] and [two-workspace experiment][concurrent] cover small configurations, not production-scale disk, memory, immutability, or crash recovery.

### How to use this agenda

Test the hypothesis that immutable logical snapshots, explicit input identities, live projections, replaceable backends, and prepared immutable dependencies provide sufficient correctness at acceptable cost. A pathname, version number, cache hit, or live worker alone is not evidence of the intended source/import context. Simpler alternatives and disconfirming results are welcome.

Each ID is a candidate investigation, not necessarily a separate report or mandatory implementation. **S** = source/specification research; **X** = execution/measurement; **M** = formal modeling, property testing, or mechanization, with its exact strength stated; **U** = human/agent evaluation. A source-only worker may design an experiment but cannot claim its result. Section references identify #3725 recommendations being specialized, not verified completion.

## A. Architectural alternatives and the contracts they actually provide

Prior work: #3725 R25/R33/R85/R118; [invalidation synthesis][invalidation].

**I001 — Minimal cross-mode contract [S/M].** Specify what batch and live modes must agree on: source subject, obligations, imported environment, assumptions, and accepted claims. Construct cases where diagnostics, proof terms, or timings differ legitimately. Determine which equivalence is necessary without requiring byte-identical incidental artifacts.

**I002 — Shared compiler core versus separate analysis engine [S].** Compare pinned Lean, TypeScript, Roslyn, clangd, and rust-analyzer boundaries, including where editor approximations diverge from compilation. Identify which APIs genuinely share semantics and which require a fresh compiler oracle; assess what each precedent supports for Anneal.

**I003 — Embedded-language precedents [S/X].** Examine representative Razor, Volar, or similar projection systems for virtual document identity, generated spans, completion edits, and multiple language servers. Reproduce a small ambiguous mapping or cross-language edit. Separate reusable mechanisms from assumptions that fail for proof contexts or compiled imports.

**I004 — One-shot, per-project, and shared-service topologies [S/X].** Compare a fresh process per operation, persistent project workers, and an optional shared broker on identical fixtures. Measure isolation, startup, reconstruction, and coordination costs. Determine when the simplest one-shot design is adequate and what a daemon would actually save.

**I005 — Snapshot engine versus a versioned job scheduler [M/X].** Implement minimal competing orchestration models with fake backends before choosing an incremental database. Replay identical edits, cancellations, and dependency changes. Identify the smallest model that prevents mixed or stale acceptance, and the workload that would justify a richer engine.

**I006 — Stage API and error boundaries [S/X].** Prototype structured requests/results for Charon, Aeneas, and Lean, separating semantic inputs from CLI output, process policy, and artifact storage. Inject failures, progress events, and stdout/stderr contamination. Test whether batch and live adapters can use the same contract without backend-specific state leaking upward.

**I007 — Cancellation, reuse, and ownership contracts [M].** Specify separately who owns work, who can cancel it, who can consume its result, and when cached work may be reused. Model two clients sharing a job. Look for cases where cancelling one request incorrectly kills another or permits an obsolete result to publish.

**I008 — Minimal upstream changes [S/X].** Identify missing observable identities, reset operations, overlay hooks, and source spans at exact upstream pins. Compare adapters with small upstream API proposals and coarse fallback behavior. Distinguish requirements for correctness from optional latency improvements; preserve a viable path without upstream changes where one exists.

## B. Workspace snapshots, document ownership, and coherent inputs

Prior work: #3725 R25/R31/R32/R77–R80.

**I009 — Input closure of one verification subject [S/X].** Enumerate actual source, manifest, lockfile, feature, target, environment, generated-file, model, and toolchain inputs. Perturb each while holding filenames fixed. Identify omitted dependencies that change extracted code, obligations, or proof interpretation and distinguish declared inputs from untracked external effects.

**I010 — Capturing a coherent live filesystem [M/X].** Compare immutable materialization with read-and-revalidate capture while files change. Include renames, symlinks, generated outputs, and large trees. Preserve a witness of which bytes were read; test whether validation can accept a mixed snapshot and what assumptions prevent that.

**I011 — Clocks, generations, and ABA changes [M/X].** Distinguish document versions, workspace revisions, model generations, and process epochs. Exercise content A→B→A, close/reopen with reset versions, workspace recreation, and reused request IDs. Determine which identities prevent an old result from masquerading as a current one without needlessly disabling content-based reuse.

**I012 — Disk versus open-buffer ownership [S/X].** Exercise open, change, save, external overwrite, close, rename, delete, and reopen. Determine when disk or client text is authoritative and how conflicts surface. Include a buffer that remains open after its file disappears; avoid silently replacing unsaved text with a disk reread.

**I013 — Coherent multi-document changes [M/X].** Change a proof and its helper, or two Rust modules, as one logical operation while queries run. Compare atomic workspace edits with ordered individual updates. Establish whether intermediate states are queryable, provisional, or rejected, and how a batch invocation selects the same intended snapshot.

**I014 — Multiple writers to one workspace [M/X].** Race an editor, MCP agent, generator, and external filesystem tool. Compare exclusive document ownership, compare-and-swap edits, and explicit forks. Test conflict detection and lost-update prevention without assuming that all clients share one transport or obey one editor's version counter.

**I015 — Subset freshness and conservative invalidation [M/X].** Change unrelated files while a proof query runs. Compare global-revision rejection with dependency-scoped acceptance, including dependencies discovered during processing. Determine whether narrower freshness checks are sound and useful; retain coarse invalidation as the baseline rather than assuming finer reuse is necessary.

**I016 — Reconstruction after Anneal restart [X].** Recreate a workspace from disk, a retained snapshot, or reconnected client buffers after losing all orchestration memory. Verify subject identity, unsaved edits, imports, and outstanding-result classification. Determine the minimum retained state and what must instead expire or require the client to resend text.

## C. Locating Lean annotations and attaching them to Rust subjects

Prior work: #3725 R23/R24/R31/R82.

**I017 — Tolerant annotation discovery during typing [S/X].** Compare candidate comment, attribute, or delimited encodings under incomplete Rust, unfinished Lean, missing delimiters, and temporarily malformed nesting. Determine which regions can still be located safely without compiling Rust, and when the editor must preserve text but suspend semantic attachment.

**I018 — A justified proof-only edit classifier [S/X/M].** Test edits to purported Lean-only regions with macros that inspect attributes/comments, source inclusion, and build-time readers. Determine the assumptions under which Rust semantics and extraction inputs really remain unchanged. Record unknown cases that require re-extraction rather than declaring every comment edit harmless.

**I019 — Compiler-backed annotation attachment [S/X].** Exercise conditional compilation, expanded and generated items, aliases, trait defaults, local items, and repeated names. Relate the authored annotation to the actual extracted declaration. Require explicit ambiguity or missing-subject outcomes when a source-level locator cannot establish that correspondence.

**I020 — One source file, several compilation subjects [X].** Open a file shared by library, tests, binaries, feature sets, or target triples whose generated models differ. Determine how a proof query selects its subject and how mismatches are exposed. Test whether stable annotation identity can remain separate from subject-specific proof context.

**I021 — Annotation identity across structural edits [M/X].** Move, duplicate, split, reorder, and delete annotated items while requests are outstanding. Compare range-, syntax-, compiler-, and explicit-ID-based identity schemes. Detect erroneous reassignment of a completed proof to a different obligation; preserve deliberate duplication without assuming names or offsets are globally unique.

**I022 — Multiple annotations and shared helpers [S/X].** Test declarations, specifications, proofs, imports, namespace commands, and helper lemmas distributed across annotations. Examine ordering, visibility, name collisions, and recursive dependencies. Determine which layouts preserve the authored meaning and which create unwanted dependencies between otherwise independent proofs.

**I023 — Editing against an unavailable or broken Rust model [X/U].** Introduce a Rust syntax error, unsupported extraction, or changed function signature while continuing a Lean proof. Compare stopping interaction with explicitly using the last prepared model. Test whether users and agents understand the model's age and avoid treating provisional feedback as current verification.

**I024 — Preserving authored source through regeneration [X].** Regenerate after Rust edits while Lean annotations contain unsaved changes, custom formatting, and unsupported-but-preserved text. Confirm that canonical user text is not reconstructed from LLBC or generated Lean. Test ownership rules for external proof/model files and explicit overrides without choosing a mandatory storage layout.

## D. Exact projections, provenance, and safe round-trip edits

Prior work: #3725 R31/R78/R82; [coordinates][coordinates] and [scaffolding provenance][provenance].

**I025 — Coordinate conversion property suite [M/X].** Generate source containing supplementary characters, combining marks, tabs, CRLF, empty lines, and boundary positions. Round-trip byte, scalar, and negotiated LSP coordinates where invertible. Treat lossy display-width coordinates and invalid boundaries explicitly; retain original bytes rather than silently normalizing Unicode.

**I026 — Piecewise projection invertibility [M/X].** Test stripping prefixes/indentation, escaping delimiters, and inserting scaffolding. Establish which Lean ranges map exactly to authored Rust ranges, including zero-width insertions. Reject edits crossing synthetic gaps or multiple source segments unless a deliberate transformation can preserve the surrounding source.

**I027 — One-to-many and many-to-one provenance [M/X].** Generate several obligations from one annotation and combine several annotations in one Lean declaration. Test query routing, related diagnostics, and edit ambiguity. Distinguish selecting a proof context from choosing an editable origin; an attribution anchor must not authorize replacement of unrelated Rust text.

**I028 — One generator for batch and live text [X].** Materialize and stream the same projection through separate sinks, including incomplete proofs and changed imports. Compare text, module context, source maps, and elaborated declarations. Detect accidental differences from newline handling, temporary filenames, omitted scaffolding, or a second editor-only code path.

**I029 — Revision-safe projected patches [M/X].** Obtain a Lean edit, then change the Rust document before applying it. Check both expected source bytes and projection identity, including edits elsewhere that shift ranges. Test atomic application and conflict reporting; a plausible re-mapped position must not silently overwrite a different proof.

**I030 — Completion and code-action edits beyond the cursor [S/X].** Exercise snippets, additional text edits, new imports, qualified-name fixes, and edits spanning generated/user regions. Determine which operations can be projected back safely and which need a specialized Anneal action. Preserve snippet placeholders and reject unsupported transformations rather than partially applying them.

**I031 — Diagnostics and provenance fidelity [X/U].** Produce errors in copied proof text, generated scaffolding, generated models, and external imports. Preserve the original Lean location plus the exact or approximate Rust explanation. Test range quality, related information, absent source, and responsibility selection without making a synthetic error look user-authored.

**I032 — Mapping stability and cost during edit streams [M/X].** Fuzz insertion/deletion around annotation boundaries and measure full versus incremental projection updates. Validate maps against regenerated ground truth after every edit. Determine whether incremental mapping complexity earns enough latency improvement to justify its additional invalidation and correctness burden.

## E. Projected Lean documents and module layout

Prior work: #3725 R24/R80/R82/R90.

**I034 — Stable document identity versus generation paths [X].** Compare stable logical documents with remapped generated imports, generation-specific physical paths, and close/reopen publication. **I035 — Per-annotation, per-file, and per-artifact layouts [X].** Use identical proofs with shared helpers and different model sizes under each layout. **I036 — Prefix reuse under generated-context changes [S/X].** Change early imports, namespaces, options, generated declarations, and late proof tactics separately. **I037 — Context fidelity of wrappers and scaffolding [S/X/M].** Compare direct Lean with projected annotations under namespaces, sections, variables, local instances, notation, macros, and options. Inspect elaborated proposition and dependencies, not only successful checking. Find wrapper transformations that accidentally capture names or change the statement being proved.

**I038 — Open documents that import other unsaved documents [S/X].** Keep both producer and proof open, change only the producer buffer, and compare server behavior with compiled-disk imports. **I039 — Dependency cycles and generated declaration order [S/X].** Construct cross-annotation helper dependencies, generated specifications referencing models, and mutually dependent proof modules. **I040 — Scratch proof forks preserve full context [X].** Clone a projected document for tactic experiments, varying module identity, options, imports, and surrounding commands. Compare results with applying the candidate to the real proof. Detect experiments that work only because the scratch context or pre-elaborated prefix differs from the intended document.

## F. Lean query causality, tactic state, and worker lifetimes

Prior work: #3725 R07/R77–R81/R85; [old-version probe][wait].

**I041 — Exact-version goal query protocol [S/M/X].** Compare serialized document access, client-side version fences, snapshot-specific documents, and any upstream version-aware operations. Introduce actual concurrent edits before, during, and after readiness waits and goal requests. Determine which protocol can justify the returned version rather than merely label an unversioned response.

**I042 — Readiness is not a single boolean [S/X].** Delay parsing, imports, elaboration, asynchronous tasks, diagnostics, and tactic information separately. Test available wait operations and progress notifications. Distinguish ready-at-position, whole-file completion, imports-out-of-date, and permanent failure, including files whose diagnostics are temporarily empty.

**I043 — Tactic-position selection semantics [S/X].** Query before/after tactics, within whitespace, at nested goals, tactic combinators, macros, errors, and EOF. Compare plain goals and interactive goals. Preserve exact coordinates and expected selection so an agent knows whether it is seeing input goals, output goals, or no applicable tactic state.

**I044 — Rich RPC object lifetimes [S/X].** Retain interactive goal/context handles across edits, cancellation, file close, worker restart, and server restart. Test reconnect and expiration handling. Determine which data can be copied into durable results and which must remain explicitly scoped to a live worker/RPC session.

**I045 — Worker incarnation and request-ID reuse [M/X].** Delay responses while replacing a worker and reusing file versions or transport request numbers. Verify that old responses, notifications, and RPC references cannot enter the new context. Test clean shutdown separately from forced termination and a crashed worker restarted by its supervisor.

**I046 — Partial and failed elaboration [X].** Place a valid proof before and after unfinished declarations, unknown tactics, timeouts, and recoverable syntax errors. Query reachable positions and inspect diagnostics. Determine what useful state is available without implying that the full module or its intended obligations have been checked.

**I047 — Historical queries versus latest-only queries [M/X/U].** Compare rejecting superseded requests, retaining old snapshots, and rebuilding a requested revision in isolation. Measure storage and latency, including rapid edits that continually supersede work. Establish explicit semantics for latest-at-start, latest-at-completion, and exact historical requests rather than silently switching among them.

**I048 — Imported-environment attestation [S/X].** Determine what a worker can report about loaded module artifacts, options, plugins, and build identities. Compare explicit instrumentation with a fresh-worker construction whose inputs are controlled. Show how Anneal could establish the actual environment used, not just store an intended generation tag beside the response.

**I091 — Environment setup versus current-document setup [S/X].** Change an unsaved projection's import header while keeping the project fixed. **I092 — No-build and no-cache as consumer contracts [S/X].** Exercise missing/stale imports, absent package configs, malformed manifests, and incomplete artifact families under the exact server no-build path. **I093 — Lean versus TOML package configuration [S/X].** Compare equivalent package declarations with configuration computation, environment dependencies, and dynamic library loading. **I094 — Pinned versus upgraded Lake ownership [S/X].** Re-run the same consumer-identity and read-only probes at the examined 4.30 pin and explicitly chosen later versions. **I095 — Observable reuse versus accidental rebuilding [S/X].** Record launched processes, writes, artifact reads, and setup outputs across repeated checks. **I096 — Configuration discovery and tool selection [S/X].** Compare CLI, editor, MCP, CI, and clean-process launches with different working directories, PATH, toolchain selectors, homes, and search paths. ## N. Scheduling, cancellation, crash recovery, and failure states

**I106 — Late messages after cancellation [M/X].** Deliver queued results, diagnostics, progress, and worker exits after cancellation or supersession. **I107 — Single-flight builds with several consumers [M/X].** Let multiple proofs request the same dependency generation, then cancel or fail individual consumers. **I108 — Lock ordering and publication deadlocks [M/X].** Combine environment preparation, generation publication, cache insertion, worker restart, and garbage collection. **I109 — Timeouts and resource exhaustion [X].** Use bounded fixtures that exhaust time, memory, disk, file descriptors, or process slots. **I110 — Restart reconstruction under forced failures [X].** Kill the worker, watchdog, Anneal process, and build subprocess separately at recorded states. **I111 — Interactive fairness and edit storms [X].** Combine expensive batch checks with rapid proof edits, many agents, and a slow document. Measure tail latency, useful completed work, and starvation; latest-only correctness must not make the interface permanently unresponsive.

**I112 — Lost filesystem and transport events [M/X].** Drop, duplicate, and reorder watcher notifications and disconnect transports while work proceeds. ## Coverage and completion

This is a scoped exhaustive brainstorm, not a claim to enumerate every future question. Cross-check selected experiments against the following independent dimensions; use pairwise coverage and failure-driven higher-order combinations rather than silently implying the full Cartesian product was tested.

| Dimension | Distinctions to preserve |
| --- | --- |
| Inputs | Saved/unsaved Rust; embedded/user-file Lean; generated models; manifests/config; transitive imports; native extensions; external build inputs |
| Identity | Workspace; Cargo subject; document/projection; model/artifact generation; toolchain; worker/request incarnation |
| Changes | Proof body; statement/helper; Rust semantics; model/assumptions; imports; configuration; toolchain; rename/deletion; unrelated edits |
| Consumers | CLI; editor; MCP; concurrent writers; scratch forks; historical readers; parallel tests |
| State | Cold/warm; fresh/stale/missing/corrupt artifacts; read-only/writable trees; complete/partial generations; reconstructed sessions |
| Events | Completion; interleaving; supersession; cancellation; timeout; crash; disconnect; lost notifications; exhaustion; collection |
| Outputs | Goals; diagnostics; edits; declarations; coverage; trust/taint; source-level acceptance; replay evidence |
| Resources | Logical/physical disk; peak temporary space; inodes; physical/shared memory; nested concurrency; throughput; tail latency; retained state |
| Applicability | Exact version tuple and binary provenance; launch mode; platform/filesystem; permissions; network/home environment; fixture size |

Each completed investigation should retain its hypothesis, exact subject, prior coverage and remaining delta, method, positive/negative controls, result, evidence limits, and cheapest revalidation. State which decision it informs and what observation would confirm, disconfirm, or restrict the proposed mechanism. Preserve small executable fixtures, causally ordered transcripts, counterexamples, and measurements where relevant. Unrun scripts are plans, and bounded model searches are not theorems about the implementation.

Follow the current [reference format][format]. Merge coupled questions; split different subjects; correct same-subject errors without erasing accurate old-version findings. Keep factual reports in `reference`, design decisions under their existing authority, and mutable work status in the chosen issue/coordination mechanism. This issue does not change scheduled workers or create another corpus lifecycle schema.

Completion means justified scaffolding contracts and affordable regression tests, with rejected alternatives and remaining uncertainty—not report counts or one successful demonstration.
