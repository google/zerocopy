# Monorepo Rust Toolchain Governance, Custom Driver ABIs, Sidecar Topologies, and Multi-Compiler Cargo Orchestration

## Summary

Integrating compiler-coupled Rust analyzers or formal verifiers across polyglot monorepos and multi-version Cargo workspaces requires respecting three hard representation and build-system invariants:

1. **Monorepo One-Version `.rmeta` Lock-In vs. Lazy Parallel `.verify.rmeta` Graphs:** Every compiled `.rmeta` blob (`METADATA_VERSION = 12`) embeds the exact compile-time `"rustc {CFG_VERSION}"` string at byte offset `40` alongside a 128-bit crate `Svh`; `MetadataBlob::check_compatibility` (`compiler/rustc_metadata/src/rmeta/decoder.rs:719-737`) rejects even a single-character `CFG_VERSION` difference with `E0514`. Consequently, Chromium, Fuchsia, and Android AOSP co-roll only production-codegen or in-tree tools (`clippy`, `bindgen`, `crubit`) inside the repository's single `rustc` archive while running heavy analyzers (`Kythe`, `CodeQL`) out-of-band. Mainline Linux (`torvalds/linux`, `rustc >= 1.85.0`) achieves a Cargo-free sliding multi-release window by pairing `RUSTC_BOOTSTRAP=1` + `-Astable_features` with `CONFIG_RUSTC_VERSION` (`100000*X + 100*Y + Z`) Kconfig feature gates (`@include/generated/rustc_cfg`), `--sysroot=/dev/null` source compilation of `core`, and an in-tree `kernel::alloc` replacing upstream `alloc`. In Bazel (`rules_rust`) and Buck2 (`MetadataKind("miri")`), any verifier using a decoupled compiler $v_{\text{verif}} \neq v_{\text{repo}}$ or custom MIR flags (`-Zalways-encode-mir`, `-Zmir-preserve-ub`) cannot reuse `rust_library` `.rmeta`s and must declare a lazy parallel `.verify.rmeta` (`-Zno-codegen`) + host `proc-macro` dependency action graph.
2. **Custom Monorepo `librustc_driver` Dual ABI Lock & Six-Shape Version Grammar:** Rebuilding the **exact same `rust-lang/rust` Git commit** with a custom `config.toml` `description` (Chromium), custom `CFG_VERSION` (Fuchsia), `omit-git-hash = true`, or `channel = "dev"` (`x.py stage1`) alters **both** Cargo's `compute_metadata` `DT_SONAME` (`librustc_driver-<16-hex>.so`) **and** `rustc`'s `StableCrateId::new(..., sess.cfg_version)` crate disambiguator embedded inside every `v0` (`_RNvCs...`) and `legacy` (`_ZN...17h...E`) exported symbol. Prebuilt upstream `rustc_private` binaries therefore cannot link custom monorepo `librustc_driver.so` libraries even via `patchelf --replace-needed`; custom builds require ~`0.38s` source compilation of a minimal capture shim against the monorepo's `(rustc, rustc-dev)`. Furthermore, `rustc_version_str()` and `rustc -vV` exhibit **six distinct concrete shapes**—including `0`-parenthetical `-dev` builds, `2`-parenthetical vendor builds where local cherry-picks diverge from `git-commit-info`, and runtime `RUSTC_OVERRIDE_VERSION_STRING` spoofing (which mutates `rustc -vV` while leaving `.rmeta` `CFG_VERSION` untouched)—making binary/sysroot SHA-256 digests mandatory for compiler-pin authentication.
3. **Decoupled Multi-Version Cargo Orchestration (`cargo 1.100.0` + Older `RUSTC`), Host ABI Survival, and Three-Cache Traps:** Unlike `cargo-hack --version-range` and `cargo-msrv` (which run `rustup run <old> cargo`, failing on `edition = "2024"` workspace siblings across `cargo <= 1.84.0` and mutating `Cargo.toml`/`Cargo.lock` in place), a single modern `cargo 1.100.0` binary driving `RUSTC=<older>/bin/rustc` parses `Cargo.lock` v4 (`1.78+` reader / `1.83+` writer) and `edition = "2024"` siblings cleanly, validates `package.rust-version` against `RUSTC -vV` over `unit_graph` only, works natively back to **`rustc 1.79.0`** (`0` shims), and reaches **`rustc 1.78.0`** after stripping `1.79.0`-stabilized `--check-cfg` and `--json=unused-externs-silent` (`--force-warn=unused_crate_dependencies`). Combining `RUSTC_WORKSPACE_WRAPPER` with explicit `--target <triple>` isolates host `proc-macro` and `build.rs` units from `CARGO_ENCODED_RUSTFLAGS`, while passing `CARGO_CACHE_RUSTC_INFO=0` + a `-vV` digest line (or `-C metadata=<nonce>`) closes Cargo's three silent `Fresh` cache-skip traps and runs 4 concurrent compilers against a `chmod -R a-w` read-only workspace in `0.54s`.

## Findings

### 1. Monorepo Toolchain Governance, Sidecar Compilers, and Build-Graph Topologies

#### 1.1 The One-Version Rule and Binary `.rmeta` / `Svh` Coupling

`Basis: documentation + source + execution`

In *Software Engineering at Google* (Winters, Manshreck, Wright 2020, ISBN `978-1-492-08279-8`, Ch. 21 *Dependency Management*, "The One-Version Rule"), a monorepo allows at most one selectable version per dependency across the build graph, trading local version flexibility for freedom from diamond-dependency skew. Whereas C/C++ occasionally isolates competing library versions behind symbol visibility or static archives, `rustc` enforces a **hard binary One-Version invariant on the compiler binary itself** across every linked Rust crate graph (`rust-lang/rust@342d74463af7dd3018ef6aa04dd5500c2deb5bd1`):

1. **Exact `METADATA_HEADER` and `"rustc {CFG_VERSION}"` byte equality (`compiler/rustc_metadata/src/rmeta/mod.rs:66-92`, `decoder.rs:719-737`):**
   Every standalone `.rmeta` or `.rlib`-embedded `lib.rmeta` begins with an 8-byte `METADATA_HEADER` (`b"rust\0\0\0\x0c"`, `METADATA_VERSION = 12`), followed by `ROOT_POS_OFFSET` (`8..16`, little-endian `u64`), `UNHASHED_POS_OFFSET` (`16..24`, `u64`), `CRATE_HASH_OFFSET` (`24..40`, 128-bit `Fingerprint`/`Svh`), and `VERSION_OFFSET` (`40`, `LazyValue<String>`). Before decoding `CrateRoot`, `MetadataBlob::check_compatibility` enforces exact string equality against compile-time `option_env!("CFG_VERSION")` (`compiler/rustc_interface/src/util.rs:749-756`):
   ```rust
   // compiler/rustc_metadata/src/rmeta/decoder.rs:719-737
   pub(crate) fn check_compatibility(
       &self,
       cfg_version: &'static str,
   ) -> Result<(), Option<String>> {
       if !self.starts_with(METADATA_HEADER) {
           if self.starts_with(b"rust") {
               return Err(Some("<unknown rustc version>".to_owned()));
           }
           return Err(None);
       }
       let found_version =
           LazyValue::<String>::from_position(NonZero::new(VERSION_OFFSET).unwrap()).decode(self);
       if rustc_version(cfg_version) != found_version {
           return Err(Some(found_version));
       }
       Ok(())
   }
   ```
   Live execution (`support/probe_rustc_version_sysroot_rmeta.py` and `.json` on `rustc 1.102.0-nightly` `3ef0c22cdb86ac42dc6b8f0f1ec36857daa6f2a1`) confirms `magic_bytes_hex = "727573740000000c"`, `metadata_version = 12`, and `"rustc 1.102.0-nightly (3ef0c22cd 2026-11-11)"` at byte offset `41` of a `2,172`-byte `.rmeta`; mutating 1 byte of that version string aborts downstream compilation (`exit_code = 1`) with `error[E0514]: found crate 'dep' compiled by an incompatible version of rustc`.
2. **Transitive `Svh` (`E0460`) and Cross-Language LLVM Bitcode Lockstep:**
   Downstream `.rmeta` dependency tables (`cnum_map`, `dep_extra_filenames`, `TargetModifiers`, `decoder.rs:770-774`) embed every upstream crate's 128-bit `Svh` and `StableCrateId`. Furthermore, polyglot monorepos such as Chromium (`tools/rust/README.md:12-34`, `tools/rust/build_rust.py:500-505` at `183a8b1a836ad889170030ba672f52b1cd1e1a53`) and Linux (`scripts/Kconfig.toolchain:89-98` at `4843f6873f7c4835e62f2c73ba0fd538e57a2f22`, `RUSTC_CLANG_LLVM_COMPATIBLE`) couple `rustc`'s LLVM version to Clang/LLD so cross-language ThinLTO (`-C linker-plugin-lto`), KCFI, `KASAN_SW_TAGS`, and C helper bitcode (`helpers.bc`) share identical LLVM IR bitcode formats.

Inspecting the three dedicated sidecar/codegen architectures in detail establishes what works and what fails for MIR-level formal verification:

1. **Co-Rolled Dual-Compiler Codegen — `google/crubit@5f9ae7da1aa70e5a1c0e536baf32e5ec56a7c003`:**
   Because ABI or layout disagreement between generated FFI bindings and production `rustc`/Clang causes silent miscompilation, Crubit co-rolls on the critical path while **splitting `librustc_driver` and Clang C++ `LibTooling` into two separate OS processes** to avoid in-process LLVM symbol collisions:
   - **`cc_bindings_from_rs`** (`cc_bindings_from_rs/BUILD:19-75`, `run_compiler.rs:7-16, 108-121`, `lib.rs:177-250`): Links `#![feature(rustc_private, cfg_accessible)]` (`rustc_driver`, `rustc_interface`, `rustc_middle`), consumes already-compiled target `.rmeta`s via `--enable-rmeta-interface` and `--extern=<crate>=<self_rmeta.path>` (`cc_bindings_from_rust_rule.bzl:287-291`) over a synthetic `#![feature(no_core)] extern crate r#<crate>;` buffer, sets `config.opts.cg.unsafe_allow_abi_mismatch = target_modifier_flag_names()` (`run_compiler.rs:33-42, 183`) to tolerate sanitizer/ABI target-modifier differences, and survives rolling `rustc` churn via a custom branch-date table (`RELEASES` in `rustversion_impl.rs:57-99` mapping nightly branch dates to `1.96`–`1.100`).
   - **`rs_bindings_from_cc`** (`rs_bindings_from_cc/BUILD:80-113, 178-196`, `src_code_gen_ffi.cc:14-31`, `clang_compat_macros.h:8-25`): Links `@llvm-project//clang:{ast,basic,sema,frontend,tooling}` (pinned at `b02dbdd4ef51d24d882cdd14112229144c05f9a1` in `MODULE.bazel:31-45`, checked against `rustc -vV`'s `LLVM version:` by `bazel/llvm_version_check.bzl:31-76`, with Ubuntu 24.04 RBE `libicu*.so.70` unpacked into `@llvm_toolchain_llvm//:lib` in `bazel/extensions.bzl:67-106`), guards Clang AST breaks with `#if LLVM_DEV_DATE_GE(YYYYMMDD)`, and emits Rust tokens via standard `quote` without `rustc_private`.
2. **Asynchronous Sidecar Extractors — `kythe/kythe@69141f022689a611e8a4a1d9b08a3783a2e8a9ed` vs. `github/codeql@aafa7deeff16c1e3c4e356eabec46cbca2dc09e3`:**
   - **Kythe `.kzip`** (`kythe/docs/kythe-kzip.txt:40-180`, normative spec; `kythe/proto/analysis.proto:90-191`): Content-addressed ZIP archive storing `CompilationUnit` messages (`units/<sha256>` or `pbunits/<sha256>`) and uncompressed input blobs (`files/<sha256>`). Build-interception `.kzip`s that capture compiled `.rmeta` dependencies and host proc-macro `.so`s in `required_input` **cannot** be replayed by a sidecar verifier on a different `rustc` version (`E0514` + host proc-macro ABI mismatch), whereas `rust_project_to_kzip.go` (`kythe/go/extractors/cmd/rust/rust_project_to_kzip.go:306-310, 477-549`) drops all non-`.rs` inputs (`include_bytes!`, `include_str!`) and codegen flags (`-C overflow-checks`, `-C panic`, `--target`), making it unsound for MIR verification.
   - **CodeQL Rust extractor** (`rust/extractor/src/toolchain.rs:27-89`, `config.rs:126-141, 188-196`): Hardcodes `FIXED_RUST_TOOLCHAIN = "1.99.0"` and `MINIMUM_NIGHTLY_DATE = 2026-07-15`, forcibly overriding `RUSTUP_TOOLCHAIN`, passing `--ignore-rust-version` to Cargo, and lowering through in-process `ra_ap_hir` rather than borrow-checked `rustc` MIR (`$v_{\text{verify}} \neq v_{\text{ship}}$).
   - **Derived Sidecar MIR Requirement (`Basis: derived`):** A decoupled sidecar verifier running compiler $v_k$ can soundly verify a monorepo target out-of-band if and only if the build exports a **topological source-graph compilation pack**: content-addressed `.rs` sources, all non-`.rs` compile-time inputs (`OUT_DIR`, `include_bytes!`/`include_str!`), proc-macro *source* crates (rebuilt for host $v_k$), and exact per-crate semantic flags (`--edition`, `--cfg`, `--target`, `-C overflow-checks`, `-C panic`), replaying `.rmeta` + MIR bottom-up against $v_k$'s sealed sysroot.

#### 1.3 Mainline Linux Kernel (`torvalds/linux@4843f6873f7c4835e62f2c73ba0fd538e57a2f22`): Cargo-Free Sliding Multi-`rustc` Window

`Basis: source + documentation`

Unlike single-pin corporate monorepos, `Rust-for-Linux` in mainline Linux supports building with any distribution or `rustup` toolchain across a **15+-release sliding window (`1.85.0` through `1.100.0+`, no upper cap)** using Kbuild (`Makefile` and `rust/Makefile`):

1. **Tool Overrides & 7-Digit Version Integer (`Makefile:464, 552-556, 640, 653-654`; `scripts/min-tool-version.sh:15-44`; `scripts/rustc-version.sh:13-18`):**
   Kbuild parameterizes `HOSTRUSTC = rustc`, `RUSTC = rustc`, `CLIPPY_DRIVER = clippy-driver`, and `BINDGEN = bindgen` (switching `RUSTC_OR_CLIPPY = $(CLIPPY_DRIVER)` under `CLIPPY=1`), enforces floors `rustc >= 1.85.0` (`1.95.0` on `powerpc`, `1.96.0` on `s390`), `llvm >= 17.0.1`, and `bindgen >= 0.71.1`, and encodes `X.Y.Z` as 7-digit **`CONFIG_RUSTC_VERSION = 100000 * X + 100 * Y + Z`** (`1.85.0 -> 108500`, `1.100.0 -> 110000`, widened specifically for `1.100.0`).
2. **Two-Sided `#![feature(...)]` Gating Without Cargo `--check-cfg`:**
   - *Features stabilized inside the window (`1.85 -> 1.100`):* `Makefile:647` sets `RUSTC_BOOTSTRAP := 1` and `Makefile:484-487` passes `-Astable_features -Aunused_features` so `#![feature(unsigned_is_multiple_of)]` (stabilized in `1.87.0`) and `#![feature(generic_arg_infer)]` (stabilized in `1.89.0`, `rust/kernel/lib.rs:20-23`) survive `-Dwarnings` (`CONFIG_WERROR`).
   - *Features introduced mid-window:* Because unknown feature names trigger unsuppressible parser error **`E0635`** on older compilers, `scripts/Kconfig.toolchain:275-286` defines version thresholds (`RUSTC_HAS_UNNECESSARY_TRANSMUTES` `>= 108800`, `RUSTC_HAS_FILE_WITH_NUL` `>= 108900`, `RUSTC_HAS_FILE_AS_C_STR` `>= 109100`, `RUSTC_HAS_SUSPICIOUS_RUNTIME_SYMBOL_DEFINITIONS` `>= 109800`), serialized by `scripts/kconfig/confdata.c:773-830` into `@include/generated/rustc_cfg` for `#![cfg_attr(CONFIG_RUSTC_HAS_FILE_WITH_NUL, feature(file_with_nul))]` (`rust/kernel/lib.rs:34`). Omitting Cargo's `--check-cfg` avoids `unexpected_cfgs` on disabled `CONFIG_*` symbols.
3. **Dynamic Flag/Edition Adaptation, `--sysroot=/dev/null` Source `core`, and Host `libmacros` Isolation (`rust/Makefile`):**
   - `rustc-min-version` (`scripts/Makefile.compiler:72`) switches `core-edition` between `2021` (`< 108700`) and `2024` (`>= 108700`, `rust/Makefile:78`), gates `proc_macro2` span cfgs (`>= 108800`, `line 103`), injects `-Zllvm_module_flag=frame-pointer:u32:2:max` (`< 109800`, `Makefile:978`), gates `KASAN_SW_TAGS` (`>= 109600`, `init/Kconfig:2072`), and passes `-Cunsafe-allow-abi-mismatch=fixed-x18` (`>= 108800`) and `,sanitizer` (`>= 109100`) to `rustdoc` (`rust/Makefile:167-170`).
   - Target crates (`core`, `compiler_builtins`, `zerocopy`, `pin_init`, `ffi`, `bindings`, `uapi`, `kernel`) compile with **`--sysroot=/dev/null -Zunstable-options`** (`rust/Makefile:651-664`), building `$(obj)/core.o` directly from `$(RUST_LIB_SRC)/core/src/lib.rs` (`lines 62-64, 742-752`, invalidated on `include/config/RUSTC_VERSION_TEXT`). Mainline Linux **eliminated upstream `alloc`** (`rust/Makefile:9`, `Documentation/rust/general-information.rst:13-15`), implementing fallible kernel allocations in `kernel::alloc` (`rust/kernel/lib.rs:47`) to insulate the kernel from unstable `alloc` churn.
   - Host proc-macros (`libmacros` via `libmacros_name := $(call procmacro-name,macros)`, `zerocopy_derive`, `pin_init_internal`) compile separately into `$(obj)/host/` against `$(HOSTRUSTC)`'s default host sysroot (`rust/Makefile:53-59, 597-650`), while `bindgen` (`scripts/rust_is_available.sh:161-245`, `rust/Makefile:443-531`) checks `libclang >= 17.0.1` (blocking the `bindgen < 0.72.1` + `libclang >= 22` regression) and pins `--rust-target 1.85`.

#### 1.4 Build-Graph Multi-Toolchain Resolution (`rules_rust` & `buck2`), RBE CAS Symlinks, and Parallel `.verify.rmeta` Graphs

`Basis: source + execution + derived`

1. **Bazel `rules_rust` (`5d99ff2e58d1a0c9387fc4945029df11144bc8a3`):**
   - `rust_repository_set` (`rust/private/repositories.bzl:284-287, 1401-1560`) registers per-`(exec_triple, target_triple, channel)` `@rules_rust//rust:toolchain_type` instances. `rust_library` keeps `deps` in the target configuration while transitioning `proc_macro_deps` via **`cfg = "exec"`** (`rust/private/rust.bzl:827-833`), and separates target `extra_rustc_flags` from host `extra_exec_rustc_flags` via `is_exec` (`rust/private/toolchain.bzl:436, 605, 744`, `rust/private/rustc.bzl:103, 1733, 1745-1749, 3531-3582`).

#### 3.2 Wrapper Invocation Matrix and Host `proc-macro` / `build.rs` ABI Survival

`Basis: source + execution`

In `crates/cargo-util/src/process_builder.rs:525-531`, `src/util/rustc.rs:121-134`, `src/compiler/compilation.rs:223-241`, `src/compiler/compile_kind.rs:53-62, 145-152`, and `src/compiler/build_context/target_info.rs:956-982` (verified in `exp2a` and `exp2b`):

- **Chaining order & scope:** Setting both wrappers spawns `argv = [$RUSTC_WRAPPER, $RUSTC_WORKSPACE_WRAPPER, $RUSTC, ...args]`. Both `-vV` (`Rustc::new`) and `--print=*` (`TargetInfo::new`) run through **both** wrappers. For crate compilations, `RUSTC_WORKSPACE_WRAPPER` wraps workspace members (`is_workspace = true`: primary target crate with `CARGO_PRIMARY_PACKAGE=1`, workspace library deps, and **workspace `proc-macro` and `build.rs` host units**) while skipping external dependencies (`ext_dep` lib and `ext_dep` `build.rs` run `$RUSTC_WRAPPER` -> `$RUSTC` only; `custom_build.rs:455-468` likewise strips `RUSTC_WORKSPACE_WRAPPER` from `ext_dep`'s `build.rs` runtime env).
- **Host `--target` & `RUSTFLAGS` isolation:** `CompileKind::for_target` maps every `proc-macro` and `build.rs` unit to `CompileKind::Host`, which **never** receives `--target <T>` on `rustc` argv (`add_target_arg`, `compile_kind.rs:145-152`). Without `--target` (`target-applies-to-host = true` default), ambient `RUSTFLAGS` / `CARGO_ENCODED_RUSTFLAGS` leak onto host `proc-macro` and `build.rs` units (`exp2a` `ambient_rustflags_no_target_default_applies_to_host`). Passing **explicit `--target <triple>`** (even matching the host triple!) or `-Z target-applies-to-host --config target-applies-to-host=false` sets `host_artifact_uses_only_host_config = true` (`target_info.rs:956-982`), completely stripping `CARGO_ENCODED_RUSTFLAGS` from all `proc-macro` and `build.rs` compilations.
- **Host ABI survival (`exp2b`) & jobserver FDs:** Replacing `--emit` with `--emit=dep-info,metadata` or returning `Compilation::Stop` (`exit 0`) on `build_script_build`, `my_proc_macro`, or `ws_lib_dep` aborts with `exit 101` (`os error 2` missing build-script binary, missing `libmy_proc_macro-<hash>.so`, or missing `libws_lib_dep-<hash>.rmeta`), while appending `--emit=metadata` without stripping `link` still links (`rustc` unions `--emit` flags). Stopping early only on leaf `crate_msrv` exits `0` once but leaves `.rmeta`/`.d` missing so Cargo marks `crate_msrv` perpetually `Dirty` on every incremental run (`second_incremental_run_compiled_crates: ["crate_msrv"]`). Passing host units (`--crate-type proc-macro`, `build_script_build`) straight through to `rustc_driver` with normal linking and returning `Compilation::Continue` after MIR capture on target units (`host_passthrough_target_continue`, preserving `CARGO_MAKEFLAGS` jobserver pipe FDs via `execv` or `close_fds=False`) succeeds cleanly (`returncode = 0`).

#### 3.3 Three-Cache Fingerprint Asymmetry, Cache-Skip Traps, and Concurrent `chmod -R a-w` Isolation

`Basis: source + execution`

Auditing `src/util/rustc.rs:318-393`, `src/compiler/build_runner/compilation_files.rs:743-946`, and `src/compiler/fingerprint/mod.rs:67-113, 1645-1727` (`exp3a` and `exp3b`) exposes a three-way cache asymmetry:

## Boundaries

- **`known not to apply` — Reusing `rust_library` `.rmeta` artifacts across mismatched `rustc` builds or custom `CFG_VERSION` strings:** `MetadataBlob::check_compatibility` (`decoder.rs:719-737`) rejects any `CFG_VERSION` discrepancy with `E0514`, and `patchelf --replace-needed` on a prebuilt `rustc_private` binary fails symbol resolution against custom monorepo `librustc_driver.so` builds because `StableCrateId` hashes `sess.cfg_version` into every `_RNvCs...` / `_ZN...17h...E` symbol.
- **`known not to apply` — Authenticating compiler identity via `rustc --version` or `rustc -vV` in an untrusted environment:** `RUSTC_OVERRIDE_VERSION_STRING` spoofs `rustc -vV` headline and `release:` strings at runtime (`override_env_affects_rmeta: false`), `omit-git-hash = true` emits `commit-hash: unknown`, and post-`git-commit-info` `.git` cherry-picks produce non-upstream `commit-hash` values.
- **`known not to apply` — Relying on `RUSTC_WRAPPER` or `RUSTC_WORKSPACE_WRAPPER` file `mtime` to invalidate Cargo build caches:** `RUSTC_WRAPPER` is absent from both `Metadata` and `Fingerprint`, and `RUSTC_WORKSPACE_WRAPPER` hashes only its `PathBuf` string (`compilation_files.rs:806`).
- **`unsupported` — Driving `rustc < 1.65.0` from `cargo 1.100.0` without `--print` query interception, or driving `rustc 1.78.0` without flag stripping:** `cargo 1.100.0` natively requires `rustc >= 1.79.0` (`--check-cfg` and `--json=unused-externs-silent`), requires a 2-flag wrapper shim for `1.78.0`, and fails in `TargetInfo::new` on `1.61.0` (`--print=split-debuginfo`). Likewise, native `cargo <= 1.84.0` cannot parse workspaces containing any `edition = "2024"` member.
- **`not examined` — Windows MSVC `.dll.lib` import-library hashing, macOS `dyld` `@rpath` custom monorepo driver builds, and intermediate `rustc` releases `1.62.0`–`1.77.2` and `1.85.0`–`1.93.0` in the live Cargo execution probe:** All execution probes ran on `x86_64-unknown-linux-gnu`; intermediate releases were bounded via `rust-lang/cargo` and `rust-lang/rust` Git source rather than direct execution.
- **`unknown` — Whether upstream Cargo will stabilize native wrapper-digest or custom-environment-variable fingerprinting:** Until Cargo hashes wrapper binary digests or declared verifier env vars into `Fingerprint`, wrappers must inject digests via `-C metadata` or `CARGO_CACHE_RUSTC_INFO=0` + `-vV` stdout.
