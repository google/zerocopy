# Translational verifier certification and cross-logic ghost-state interchange

## Summary

An SMT-based ("auto-active") verifier is a chain: front-end translation, intermediate verification
language (IVL), verification-condition generation, SMT solver. This report records which links of that
chain have machine-checked justification today, in what style, at what cost, and what form of ghost state
survives translation between a camera-based logic (Iris), a linear-token SMT logic (Verus, Creusot) and a
permission-based IVL (Viper).

- **Three certification styles coexist and cover different links.** (a) *Per-run certificates*: instrumented
  forks of Boogie and of the Viper-to-Boogie translation emit an Isabelle proof for each verified program;
  both cover a language subset and stop at "the generated verification condition is valid". (b) *Verified
  implementation or verified model*: a Rocq implementation of the Why3 logic API with proved
  transformations; an Isabelle semantics for a generic separation-logic IVL with soundness of models of
  Viper's two back ends; a Dafny-verified generator for the B3 IVL. (c) *Semantic model of trusted
  axioms*: VerusBelt interprets Verus's proof-oriented types in Iris and proves a type-specification
  soundness theorem; it justifies the ghost axioms, not the verification-condition pipeline.
- **No examined verifier asks its solver for a proof.** In the examined revisions of Boogie, Silicon, Carbon
  and Verus the solver option enabling proof production is never set; Boogie and Verus enable unsat cores
  only. Solver validity is the common unverified residue.
- **Replayable derivations are large and slow relative to SMT.** Published measurements: certificates of
  1,534 to 4,753 Isabelle lines for Boogie programs of 22 to 76 lines (ratio 41 to 89), checked in 18.7 to
  52.8 s; for Viper, a mean of 2,217 Isabelle lines per 54-line file, checked in a mean of 39.0 s
  (median 32.9 s). The authors position checking at release or continuous-integration time, not per run.
- **"Resource algebra" names four different interfaces.** Iris cameras have a total operation, step-indexed
  validity and a partial core; Verus's trusted `RA` has a total operation, a (prophecy-dependent) validity
  predicate, a unit and no core; Creusot's `RA` has a partial operation and a partial core constrained by
  a maximal-idempotent law; Viper's formalised state model is a partial commutative monoid with a core
  and a stabilisation operator. They agree on frame-preserving updates for discrete algebras; they
  disagree on everything involving cores, step indices and heap-dependent assertions.
- **The embedding of a Verus algebra into Iris is not the obvious one.** VerusBelt gives the carrier a
  *trivial* camera validity and keeps the real validity in an invariant that owns the authoritative
  element together with a prophecy observation; the user's resource is a fragment. One Verus axiom
  (`join_shared`) is not derivable in that model, storage protocols are proved for singleton maps only,
  and a soundness hole in local invariants was found and fixed upstream.
- **Tokenized state machines are trusted macro output.** At the examined Verus revision the token types
  and the per-transition exchange functions generated by the state-machine macro are
  `external_body` declarations; VerusBelt has no section for them. The intended reading (validity is
  "some completion satisfies the invariant", inductive transitions are frame-preserving updates) holds
  on an exhaustively checked finite instance and fails, with a concrete frame, for a non-inductive
  transition.
- **Fractions do not scale arbitrary assertions, and heap-dependent expressions are not stable.** Half of a
  disjunction of permissions recombines to a state outside the disjunction; a heap-dependent equality is
  self-framing only next to the permission that frames it, and conjunct order is observable through the
  well-definedness check. Both are the reason the common boundary fragment is small.

### 3. The solver link is uncertified in all examined production tools

Basis: source (text search of the pinned trees).

- Boogie: the SMT-LIB back end sends `(set-option :produce-unsat-cores true)` under a comment about
  option ordering; `SOLVER` accepts `z3`, `cvc5`, `yices2`, `noop` ("Invalid SOLVER value; must be 'Z3'
  or 'CVC5' or 'Yices2' or 'noop'"). `produce-proofs` does not occur under `Source/`; `get-proof` occurs
  only in a list of reserved SMT-LIB names.
- Silicon: has `Z3ProverStdIO`, `Z3ProverAPI` and `Cvc5ProverStdIO`; `produce-proofs` and `get-proof`
  occur in a reserved-name list, and `get-proof` once more, commented out, in `preamble.smt2`.
- Carbon: `get-proof` occurs only in the reserved-name list of its Boogie name generator.
- Verus: `-V cvc5` selects cvc5 and `-V cvc5-smtlib` selects cvc5-compatible output for Z3 (mutually
  exclusive); the AIR layer sets `produce-unsat-cores`; no occurrence of `produce-proofs` or `get-proof`
  was found under `source/air` or `source/rust_verify/src`.

So a second solver can be swapped in for three of the four tools, but none of them consumes a proof
object. Certificate formats and checkers for SMT proofs are outside this report.

### 4. The formal state model of a permission-based IVL

Basis: source (`viper-roots`) + documentation (POPL 2025 paper, section 3.1).

The paper contrasts two state models. Separation logic: `Σ_SL = L ⇀ (V × (0,1])`, every stored value
carries strictly positive permission. Implicit dynamic frames: `Σ_IDF = (L ⇀ V) × (L ⇀ [0,1])`, values
and permissions separated, "which allows states (h, π) where h(x.f) = 5 but π(x.f) = 0". A state is
*stable* iff it has values exactly where permission is non-zero; "Stable states are exactly those that can
be represented as states in Σ_SL".

The Isabelle classes (`vipersemcommon/SepAlgebraDef.thy`) make this an algebra:

```text
class pcm:            plus :: 'a ⇒ 'a ⇒ 'a option   (⊕)
  commutative:  a ⊕ b = b ⊕ a
  asso1:        a ⊕ b = Some ab ∧ b ⊕ c = Some bc ⟹ ab ⊕ c = a ⊕ bc
  asso2:        a ⊕ b = Some ab ∧ b ⊕ c = None    ⟹ ab ⊕ c = None
  positivity:   a ⊕ b = Some c ⟹ Some c = c ⊕ c ⟹ Some a = a ⊕ a

class pcm_with_core = pcm +   core :: 'a ⇒ 'a   (|_|)
  core_is_smaller: Some x = x ⊕ |x|        core_is_pure: Some |x| = |x| ⊕ |x|
  core_max:        Some x = x ⊕ c ⟹ (∃r. Some |x| = c ⊕ r)
  core_sum:        Some c = a ⊕ b ⟹ Some |c| = |a| ⊕ |b|
  cancellative:    Some a = b ⊕ x ⟹ Some a = b ⊕ y ⟹ |x| = |y| ⟹ x = y

class pcm_mult = pcm +        mult :: preal ⇒ 'a ⇒ 'a   (⊙)
  unit_mult: 1 ⊙ x = x       mult_mult: α ⊙ (β ⊙ x) = (α * β) ⊙ x
  distrib_state_mult: Some x = a ⊕ b ⟹ Some (α ⊙ x) = (α ⊙ a) ⊕ (α ⊙ b)
  distrib_scala_mult: Some ((α + β) ⊙ x) = (α ⊙ x) ⊕ (β ⊙ x)

class sep_algebra = pcm_with_core +   stable :: 'a ⇒ bool,  stabilize :: 'a ⇒ 'a
  already_stable:           stable x ⟹ stabilize x = x
  stabilize_is_stable:      stable (stabilize x)
  stabilize_sum:            Some x = a ⊕ b ⟹ Some (stabilize x) = stabilize a ⊕ stabilize b
  decompose_stabilize_pure: Some x = stabilize x ⊕ |x|
  stabilize_core_emp:       Some a = b ⊕ stabilize |c| ⟹ a = b
```

Read together with the paper's definition of stable states, `decompose_stabilize_pure` says a state is
its stable part plus its core, so the core is the duplicable *heap-knowledge* part (values without
permission) and `stabilize` forgets it (derived reading). The statements, with the names used in `main-results/PaperResults.thy`:

| Name | Statement shape |
|---|---|
| `operational_to_axiomatic_soundness_general` | `verifies_set Δ A C`, `wf_abs_stmt Δ C`, `self_framing A`, `semi_typed Δ A` ⟹ `∃B. Δ ⊢ [A] C [B]` |
| `completeness` | `Δ ⊢ [P] C [Q]`, `ω ∈ P`, `stable ω`, typing ⟹ `∃S. red_stmt Δ C ω S ∧ S ⊆ Q` |
| `sexec_verifies_set` (paper Theorem 6) | success of the formalised symbolic execution implies `verifies_set` |
| `abstract_refines_total_verifies_set` (Theorem 7) | absence of failing executions in the VCG semantics (`red_stmt_total`) implies `verifies_set` of the compiled CoreIVL statement |
| `soundness_CSL`, `adequacy_CSL` (Theorem 8) | derivations in the front-end concurrent separation logic are semantically valid and adequate for executions of the parallel language |
| `sound_front_end_translation` (Theorem 9) | if `Inhale P ;; translation(C) ;; Exhale Q` and the auxiliary statements verify, then `Δ ⊢CSL [P ⊗ true] C [Q ⊗ true]` |
| `sound_syntactic_translation_symexec`, `sound_syntactic_translation_VCG` | the two end-to-end chains |

The semantics uses dual non-determinism: `inhale A` is demonic over all states satisfying `A`; `exhale A`
"allows any choice of state ω_A satisfying A", an angelic choice that abstracts the back ends' differing
heuristics for *which* permission to give up. This is why one semantics can be sound for both a
symbolic-execution back end and a VC-generation back end.

Production surface versus formalised subset: the Silver AST has permission expressions `FullPerm`,
`NoPerm`, `FractionalPerm`, `WildcardPerm`, `EpsilonPerm`, `CurrentPerm`, resource assertions including
`MagicWand` with a `Package` statement carrying a proof script and an `Applying` expression, and
`Fold`/`Unfold` for predicates. The certified front-end subset of Finding 1 excludes predicates, wands
and iterated separating conjunctions.

### 5. Verus ghost axioms and their Iris model (VerusBelt)

Basis: source (both repositories) + documentation (VerusBelt README).

The trusted interface at the examined Verus commit is `vstd/resource/trusted/`, whose module comment
reads: "Primitive rules for monoid-based ghost state, including storage protocols. To ensures soundness
of these interfaces, the definitions and laws should match VerusBelt". `trusted/ra.rs` declares the
tracked type `Resource<P: RA>` as `external_body` and eleven `axiom fn`s: `alloc`, `join`, `split`,
`create_unit`, `validate`, `join_shared`, `weaken`, `validate_2`,
`update_nondeterministic_with_shared`, `into_copyable`, `into_resource`. `update`,
`update_nondeterministic` and `extract` are *proved* from those. `trusted/protocol.rs` declares eleven
more axioms for storage protocols. The `RA` trait:

```rust
pub trait RA: Sized {
    #[verifier::prophetic] spec fn valid(self) -> bool;
    spec fn op(a: Self, b: Self) -> Self;
    spec fn unit() -> Self;
    proof fn associative(a: Self, b: Self, c: Self) ensures Self::op(a, Self::op(b, c)) == Self::op(Self::op(a, b), c);
    proof fn commutative(a: Self, b: Self)          ensures Self::op(a, b) == Self::op(b, a);
    proof fn valid_op(a: Self, b: Self)             requires Self::op(a, b).valid(), ensures a.valid();
    proof fn op_unit(self)                          ensures Self::op(self, Self::unit()) == self;
    proof fn unit_valid()                           ensures Self::unit().valid();
}
pub open spec fn frame_preserving_update<P: RA>(a: P, b: P) -> bool {
    forall|c| #![trigger P::op(a, c), P::op(b, c)] P::op(a, c).valid() ==> P::op(b, c).valid()
}
```

Its documentation states the design choice: "we do not need a core for elements (the core is interesting
in Iris because of the persistent modality, which Verus does not have). Instead, we require a single unit
element", and "'partiality' is modeled with the validity predicate, since Verus does not support partial
functions". It cites a specific VerusBelt commit and line for the corresponding `VerusRA` record.

The Rocq side (`src/lambda_verus/typing/ra.v`):

```coq
Record VerusRA (A : Type) := {
  vra_valid : A → proph_asn → Prop;
  vra_op : A → A → A;
  vra_unit : A;
  vra_closed_under_incl a b π : vra_valid (vra_op a b) π → vra_valid a π;
  vra_commutative a b : vra_op a b = vra_op b a;
  vra_associative a b c : vra_op a (vra_op b c) = vra_op (vra_op a b) c;
  vra_op_unit a : vra_op a vra_unit = a;
  vra_unit_valid π : vra_valid vra_unit π;
}.
```

and the camera built from it has `Valid (vra_car P) := λ x, True` and `PCore := λ _, Some unit`. Its
comment: "Its validity is trivial; the (prophetic) validity of the [VerusRA] is tracked separately, by an
invariant holding the authoritative element". The type `ra_ty` owns `own γ (◯ VraCar VRA m) ∗ ra_inv γ`.
The embedding pattern is therefore **authoritative/fragment over a validity-free carrier, plus an
invariant asserting validity of the authoritative element under the actual prophecy assignment**, not
"use the user's validity as camera validity". Consequences recorded in the source and README:

- frame-preserving update is relative to a prophecy assignment:
  `vra_frame_preserving_update a b π := ∀ c, vra_valid (a·c) π → vra_valid (b·c) π`;
- for nondeterministic updates "the new value is chosen at the time of the update, so it can depend on
  the frame c but not on the prophecy assignment", hence the implication must hold for all assignments;
- `vra_conjunct_shared` "has no validity premise", unlike the Verus definition.

Correspondence table from the VerusBelt README (vendored Verus release), with its remarks:

| Verus item | VerusBelt type-spec | Remark |
|---|---|---|

Soundness theorem (`typing/soundness.v`): for a closed, semantically well-typed `main`,
`rtc erased_step ([main [exit_cont]], (∅, false)) (t, σ)` implies `nonracing_threadpool t σ` and every
thread is a value or reducible. Axioms used, per the README: dependent functional extensionality,
`eq_rect_eq`, and excluded middle (the last "only used by `atomic_inv.v`").

Two drift hazards are visible in the sources themselves. The Verus trait documentation pins one
VerusBelt commit while the VerusBelt artifact pins an older Verus release, and VerusBelt's README still
names `vstd/pcm.rs` and `vstd/storage_protocol.rs`, which the examined Verus commit has reorganised
under `vstd/resource/`. And the mask obligations of invariant opening "are not represented in Verus
source as requires/ensures clauses ... These operations are special-cased in Verus's VC gen", so that
part of the trusted base is in the verifier, not in a library axiom that can be diffed.

### 6. Tokenized state machines

Basis: source + execution (finite model) + derived.

The state-machine macro crate (`source/state_machines_macros`) accepts these field sharding
strategies (`enum ShardableType`): `Variable`, `Constant`, `NotTokenized`, `Option`, `Map`, `IMap`,
`Multiset`, `Set`, `ISet`, `Count`, `Bool`, the persistent variants `PersistentMap`, `PersistentIMap`,
`PersistentOption`, `PersistentSet`, `PersistentISet`, `PersistentCount`, `PersistentBool`, and the storage
variants `StorageOption`, `StorageMap`, `StorageIMap`. The transition kinds (`enum TransitionKind`)
are `Init`, `Transition`, `ReadonlyTransition` and `Property`; the last is documented as creating no
transition relation and serving "to define extra safety conditions, like guard properties".

For a tokenized machine, the module comment of `concurrency_tokens.rs` lists what is emitted: the
instance type, a token type per shardable field, and a proof method per transition. The per-transition exchange function is generated
as

```rust
#[cfg(verus_keep_ghost_body)]
#[verifier::external_body] /* vattr */
pub proof fn #exch_name#gen(#(#in_params),*) #out_params_ret
    #req_stream
    #ens_stream
{
    #extra_deps
    ::core::unimplemented!();
}
```

so each exchange is an axiom produced by the macro. The crate's `lemmas.rs` and
`safety_conditions.rs` generate the obligations left to the user (identified by file name and the
`check_lemmas` call in `lib.rs`; their contents were not read). The VerusBelt README contains no entry for
state machines or their tokens.

The semantic reading that makes those axioms sound is: the algebra's elements are partial assignments
of fields (shards); composition is disjoint union (for `variable` fields); an element is valid iff some
completion to a full state satisfies the inductive invariant; a transition's token exchange is then a
frame-preserving update. Probe section [4] checks this exhaustively on a three-field machine (`counter`
in 0..2, flags `inc_a`, `inc_b`, invariant `counter = inc_a + inc_b`): the transition
`{counter: c, inc_a: false} → {counter: c+1, inc_a: true}` is frame-preserving for every frame; the
variant that flips `inc_a` without holding the `counter` token is not, with violating frame
`{counter: 0}`; and holding `{inc_a: true, inc_b: true, counter: c}` implies `c = 2`. This is evidence for
the reading on one instance, not a proof for the macro.

### 7. Four interfaces called "resource algebra"

Basis: source for each column; the last row is execution (probe section [1]).

| Aspect | Iris camera (Lean port) | Verus trusted `RA` | Creusot `RA` | Viper IDF algebra (Isabelle) |
|---|---|---|---|---|
| Operation | total `•` | total `op` | partial `op(self, other) -> Option<Self>` | partial `plus :: 'a ⇒ 'a ⇒ 'a option` |
| Invalid compositions | step-indexed validity `✓{n}` | `valid: bool`, `#[verifier::prophetic]` | `op` returns `None` | `plus` returns `None` |
| Core | partial `pcore`, laws `pcore_op_left`, `pcore_op_mono` | none ("Verus does not have" the persistent modality) | partial `core(self) -> Option<Self>` with `core_idemp` and `core_is_maximal_idemp` | total `core` with `core_max`, `core_sum`, `cancellative` |
| Unit | separate unital class | required: `unit`, `op_unit`, `unit_valid` | separate `UnitRA` trait | none required (`positivity` instead) |
| Extra structure | OFE, `extend` (step-index extension) | none | `incl` deliberately irreflexive, `factor`, `cancelable` | `stable` / `stabilize`; scalar multiplication class |
| Update | `Update x y := ∀ n mz, ✓{n} (x •? mz) → ✓{n} (y •? mz)` | `forall c. op(a,c).valid() ==> op(b,c).valid()` | `forall y. self.op(y) != None ==> x.op(y) != None` | not an algebra-level notion; state change is `inhale`/`exhale` |
| Ghost object | `own γ a` | `Resource<P>` (`external_body`, axioms) | `Resource<R>` (`#[opaque]`, `#[trusted]` methods) | permission mask and heap of the state itself |
| Open-invariant bookkeeping | mask on the update modality | `opens_invariants` clauses and special-cased VC generation | explicit linear `Tokens<'a>` over `Namespace`s | not applicable |
| Finite check | — | frame-preserving updates of the fractional/agreement algebra coincide under the completion "add a unit and an invalid element" | same | PCM laws `commutative`, `asso1`, `asso2` hold for the same carrier |

Creusot's trait documentation explains its choice: it "does not require RAs to define a 'core' function.
Instead, we follow 'Idempotent Resources in Separation Logic — The Heart of core in Iris' by Gratzer,
Møller & Birkedal, and require RAs to satisfy a 'maximal idempotent' axiom"; and its `incl` is not
reflexive "Following Iris", with the product-algebra reason spelled out.

The probe's first section takes the carrier `{(q, v) | q ∈ {1/4, 1/2, 3/4, 1}, v ∈ {0, 1}}` with
"fractions add, values must agree", presents it partially (Creusot/Viper shape) and totally with a unit
and a bottom element (Verus shape), and checks: the Viper `pcm` laws on the partial presentation; the
Verus `RA` laws on the total one; and that the two definitions of frame-preserving update agree on all
64 pairs. It also confirms the three facts every boundary needs: `(1, 0) ~~> (1, 1)` holds,
`(1/2, 0) ~~> (1/2, 1)` does not, `(1/2, 0) ~~> (1, 0)` does not.

### 8. Fractional permissions do not distribute over arbitrary assertions

Basis: execution (probe section [2]) + documentation.

Let `A = acc(x.f) ∨ acc(y.f)` over permission masks for two locations. The set `(1/2)·A * (1/2)·A`
contains the mask `(1/2, 1/2)` (half of each disjunct), which does not satisfy `A`; for the single
disjunct `acc(x.f)` the halves do recombine. The probe finds exactly the witnesses
`(1/2,1/2), (1/2,3/4), (3/4,1/2), (3/4,3/4)` on a quarter-granular grid.

This is the *combinability* problem. The abstract of "Sound Automation of Magic Wands" (Dardinier,
Parthasarathy, Weeks, Summers, Müller, CAV 2022, arXiv:2205.11325) reports the same phenomenon for
wands: existing package algorithms "either have a high annotation overhead or, as we show in this
paper, are unsound", and "it is possible to soundly combine fractions of such [restricted] wands, which
is not the case for arbitrary wands". Viper's formal model carries the scaling laws as the class
`pcm_mult` (Finding 4), which states distributivity for *states*, not for assertions; Leaf's README
takes the opposite route and makes sharing a relation between propositions ("I take some G such that G
guards P") instead of a scaling operation.

Consequence for interchange: a boundary contract may scale *points-to-like, precise* resources by a
fraction; it may not promise `π·A * π'·A ⊢ (π+π')·A` for an opaque `A`.

### 9. Implicit dynamic frames against stable assertions

Basis: execution (probe section [3]) + documentation.

On states `(heap value of x.f, permission to x.f)`: the assertion `x.f == 5` alone is not self-framing (its
truth changes with the value of a location the state holds no permission to); `acc(x.f) && x.f == 5` is;
inhaling `acc(x.f) && x.f == 5` from the empty mask is well defined while inhaling
`x.f == 5 && acc(x.f)` reads `x.f` before any permission is held. Stable states are in bijection with
separation-logic states `x.f ↦ v`. The PLDI 2024 paper describes the same discipline in the translation
it certifies: Viper has expressions "whose evaluation is partial (only allowed with suitable
permissions)".

Iris assertions are all stable. The abstract of "Destabilizing Iris" (Spies, Mück, Zeng, Sammler,
Lattuada, Müller, Dreyer, PLDI 2025) says stability "excludes a core feature of the Viper verifier family,
heap-dependent expression assertions", and that supporting them required "extending [Iris] with a new
form of unstable resources (and adapting the frame rule accordingly)". Mapping an IDF assertion into
unmodified Iris therefore requires first rewriting it to its stable form (each heap read replaced by a
logical variable bound by the points-to that frames it); the unstable part has no counterpart.

### 10. What crosses a logic boundary, and what does not

Basis: derived from Findings 4 to 9; each row cites the finding that supports it.

| Ghost-state feature | Camera logic (Iris) | Linear-token SMT logic (Verus, Creusot) | Permission IVL (Viper) | First-order boundary form |
|---|---|---|---|---|
| Exclusive ownership of a location | points-to | linear `PointsTo` token | `acc(x.f)` | yes (Findings 5, 7) |
| Fractional, agreeing read shares of a location | fractional points-to | fraction-carrying token or shared borrow | `acc(x.f, p)` | yes, for precise resources only (Finding 8) |
| Discrete algebra with unit and frame-preserving update | camera with discrete validity | `Resource<P>` | ghost fields plus permissions, by encoding | yes; the three update definitions coincide (Finding 7) |
| Authoritative / fragment protocols, counters, tokenized machines | `auth` camera and invariant | tokens from the state-machine macro | ghost fields under an invariant, by encoding | yes as "validity = some completion satisfies the invariant" (Finding 6); trusted on the Verus side |
| Persistent (duplicable) knowledge via a core | `pcore`, persistence modality | absent in Verus `RA`; partial `core` in Creusot; "persistent" sharding strategies in the macro | the core of the IDF algebra is heap knowledge, a different notion | no common form (Finding 7) |
| Step-indexed validity, later modality, impredicative invariants | native | absent; invariants take a predicate type parameter and a namespace | absent | no (Findings 5, 7) |
| Prophecy-dependent validity | prophecy assignment parameter in VerusBelt's model | `#[verifier::prophetic]` on `valid` | absent | no; and it changes the update law (Finding 5) |
| Heap-dependent expression assertions | unstable resources only in the extended logic | ordinary program expressions over ghost views | native | only after rewriting to stable form (Finding 9) |
| Magic wands | native connective | absent | `package`/`apply` with a computed footprint | no; fractions of wands are unsound in general (Finding 8); outside every certified subset (Finding 1) |
| Predicates, iterated separating conjunction | definable | recursive specs / maps of tokens | native | outside the certified Viper subset (Finding 1) |
| Open-invariant masks | mask on the update modality | VC-level special case (Verus), linear tokens (Creusot) | not applicable | three incompatible encodings (Finding 7) |

The largest fragment that the examined evidence supports as embeddable on all three sides is therefore:
**discrete, unital, core-free resource algebras with a total operation and a validity predicate, their
frame-preserving updates, and fraction-scaled precise points-to resources.** Everything above that line
in expressiveness is either uncertified on at least one side or changes meaning across the boundary.

### 11. Boundary invariants for a cross-logic contract

Basis: derived. These restate the findings as obligations; none is established for a concrete tool pair.

1. **Export tokens, not assertions.** A contract `{P_phys ∗ R_in} f {Q_phys ∗ R_out}` across logics should
   restrict `R` to elements of an agreed discrete algebra; an opaque assertion cannot be scaled, split or
   framed uniformly (Findings 8, 9).
2. **State validity as a first-order predicate over a total operation.** This is the only presentation
   accepted by all four interfaces after completion; a partial operation must be completed with an
   invalid element before export, and a camera must be shown discrete (Finding 7).
3. **No core, no persistence, across the edge.** Duplicable knowledge must be re-established on the far
   side from an owned witness, because the three notions of core differ (Finding 7).
4. **No open invariant and no unresolved prophecy across the edge.** Mask bookkeeping has no common
   encoding, and prophetic validity makes the update law assignment-relative (Findings 5, 7).
5. **Self-framing, stable pre- and postconditions.** Heap-dependent expressions must be bound by the
   permission that frames them and translated to logical variables before entering a stable logic
   (Finding 9).
6. **Protocols cross as a state machine plus invariant.** The exporting side owes the inductiveness proof;
   the importing side may assume only the exchange rules that are frame-preserving for "some completion
   satisfies the invariant" (Finding 6).
7. **Record which link is certified.** A claim "verified by tool T" should name the links of Finding 1 that
   have machine-checked support for the features actually used; for every tool examined the solver link
   is unsupported (Finding 3), and for Verus the VC generator and the macro-generated token axioms are
   unsupported (Findings 5, 6).

### Probe: finite-model checks of the embeddings

Environment: Linux x86_64, Python 3.13.15, standard library only. Save the block as `ghost_probe.py`
and run `python3 ghost_probe.py`; exit status 0 and final line `ALL_CHECKS_PASS`.

```python
#!/usr/bin/env python3
"""Finite-model probes for cross-logic ghost-state embeddings.

Four independent brute-force checks (Python standard library only):

  [1] The fractional/agreement "points-to" resource algebra, presented in the
      three interface shapes used by different verifiers (partial op; total op +
      validity predicate; total op + unit), has the same frame-preserving updates
      under the standard partial->total completion.
  [2] Fractional scaling of an arbitrary (non-precise) assertion is not combinable:
      (1/2).A * (1/2).A does not entail A when A is a disjunction of full permissions.
  [3] Implicit-dynamic-frames states (total heap + permission mask): a
      heap-dependent expression assertion is not self-framing on its own, and the
      left-to-right well-definedness check makes conjunct order observable.
  [4] A tokenized state machine (shards of a global state constrained by an
      inductive invariant) induces a resource algebra in which every transition
      that preserves the invariant is a frame-preserving update of its tokens,
      and a transition that breaks inductiveness is not.
"""
from fractions import Fraction as F
from itertools import product
import sys

FAIL = []


def check(name, cond):
    print(f"  {'ok  ' if cond else 'FAIL'} {name}")
    if not cond:
        FAIL.append(name)


# --------------------------------------------------------------------------
# [1] fractional x agreement, in three interface shapes
# --------------------------------------------------------------------------
print("[1] fractional points-to resource algebra in three interface shapes")
QS = [F(1, 4), F(1, 2), F(3, 4), F(1)]
VS = [0, 1]
ELEMS = [(q, v) for q in QS for v in VS]          # carrier of the partial presentation


def pop(a, b):
    """Partial op (Creusot-style `op -> Option`, IDF-algebra `plus -> option`)."""
    (qa, va), (qb, vb) = a, b
    if va != vb or qa + qb > 1:
        return None
    return (qa + qb, va)


# total presentation: add a unit U and an invalid bottom B (Verus-style op + valid)
U, B = "unit", "bot"
TELEMS = ELEMS + [U, B]


def top(a, b):
    if a == B or b == B:
        return B
    if a == U:
        return b
    if b == U:
        return a
    r = pop(a, b)
    return B if r is None else r


def valid(a):
    return a != B


comm = all(pop(a, b) == pop(b, a) for a in ELEMS for b in ELEMS)
assoc_some = all(
    (pop(a, b) is None or pop(b, c) is None) or pop(pop(a, b), c) == pop(a, pop(b, c))
    for a in ELEMS for b in ELEMS for c in ELEMS)
assoc_none = all(
    not (pop(a, b) is not None and pop(b, c) is None) or pop(pop(a, b), c) is None
    for a in ELEMS for b in ELEMS for c in ELEMS)
positivity = all(
    not (pop(a, b) is not None and pop(pop(a, b), pop(a, b)) == pop(a, b)) or pop(a, a) == a
    for a in ELEMS for b in ELEMS)
check("partial op: commutative", comm)
check("partial op: associative when both sides defined (asso1)", assoc_some)
check("partial op: undefinedness propagates (asso2)", assoc_none)
check("partial op: positivity (vacuous here: no idempotent sums)", positivity)

t_assoc = all(top(a, top(b, c)) == top(top(a, b), c) for a in TELEMS for b in TELEMS for c in TELEMS)
t_comm = all(top(a, b) == top(b, a) for a in TELEMS for b in TELEMS)
t_closed = all(not valid(top(a, b)) or valid(a) for a in TELEMS for b in TELEMS)
t_unit = all(top(a, U) == a for a in TELEMS) and valid(U)
check("total op + valid: associative, commutative, valid closed under inclusion, unit laws",
      t_assoc and t_comm and t_closed and t_unit)


def fpu_partial(a, b):
    """Creusot-style: forall y. a.op(y) != None ==> b.op(y) != None (frames are proper elements)."""
    return all(pop(a, y) is None or pop(b, y) is not None for y in ELEMS)


def fpu_total(a, b):
    """Verus-style: forall c. valid(op(a,c)) ==> valid(op(b,c)) (frames include the unit)."""
    return all(not valid(top(a, c)) or valid(top(b, c)) for c in TELEMS)


agree = all(fpu_partial(a, b) == fpu_total(a, b) for a in ELEMS for b in ELEMS)
check("frame-preserving updates coincide across the two presentations (valid targets)", agree)
check("full permission may change the value: (1,0) ~~> (1,1)", fpu_total((F(1), 0), (F(1), 1)))
check("half permission may NOT change the value: (1/2,0) ~/~> (1/2,1)",
      not fpu_total((F(1, 2), 0), (F(1, 2), 1)))

# [2] combinability failure for fractional scaling of a disjunction

PERMS = [F(0), F(1, 2), F(1)]

def sadd(s, t):
    r = (s[0] + t[0], s[1] + t[1])
    return r if r[0] <= 1 and r[1] <= 1 else None


def scale(k, s):
    return (k * s[0], k * s[1])

    return s[0] == 1 or s[1] == 1


def in_p(s):                                             # acc(x.f) alone
    return s[0] == 1


half_a = {scale(F(1, 2), s) for s in STATES if in_a(s)}

# [3] implicit dynamic frames: self-framing and conjunct order
# --------------------------------------------------------------------------

    # truth must not depend on heap values at locations without permission

    """Left-to-right inhale from the empty mask; reading x.f needs permission gained so far."""

        if c == "acc":
            perm = F(1)

    return "well-defined"

# --------------------------------------------------------------------------

    return g["counter"] == int(g["inc_a"]) + int(g["inc_b"])

SHARDS = []
for mask in product([False, True], repeat=len(NAMES)):
    doms = [n for n, m in zip(NAMES, mask) if m]
    for vals in product(*[FIELDS[n] for n in doms]):
        SHARDS.append(tuple(sorted(zip(doms, vals))))


def sop(a, b):
    da, db = dict(a), dict(b)
    if set(da) & set(db):
        return None                       # each `variable` field has exactly one token
    da.update(db)
    return tuple(sorted(da.items()))


def svalid(a):
    da = dict(a)
    return any(inv(g) and all(g[k] == v for k, v in da.items()) for g in GLOBALS)

    for c in SHARDS:
        ac = sop(a, c)
        if ac is not None and svalid(ac):
            bc = sop(b, c)
            if bc is None or not svalid(bc):
                return False, c
    return True, None

    return tuple(sorted(kw.items()))

      not okbug)

           if svalid(s) and dict(s).get("inc_a") is True and dict(s).get("inc_b") is True
           and "counter" in dict(s))

      all(svalid(a) for a in SHARDS for b in SHARDS if sop(a, b) is not None and svalid(sop(a, b))))
print(f"  info |globals|={len(GLOBALS)} |inv|={sum(map(inv, GLOBALS))} |shards|={len(SHARDS)} "
      f"|valid shards|={sum(map(svalid, SHARDS))}")
```
