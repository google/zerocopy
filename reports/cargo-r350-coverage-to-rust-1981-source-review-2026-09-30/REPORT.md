# R350 Cargo compilation coverage: pinned nightly source to Rust 1.98.1

## Summary

The frozen [R350 report](../cargo-rust-charon-anneal-coverage-matrix-2026-09-28/REPORT.md) used `rust-lang/cargo@fbb61be30e5f9ac3a6ad58e56a5c0f5db2d2b3ef` and reported **12 units and 9 roots** for its workspace/all-targets unit graph, **14 recorded rustc invocations** for a separate build, and **7 units and one root** for its selected library graph. These numbers remain observations from the pinned nightly fixture. The official Rust 1.98.1 source tree, at `rust-lang/rust@48a229ceaefd4985c50990b14116b6d856af0985`, links to `rust-lang/cargo@797e8a9bca276c1c9f9f738d2a20f484fa4eea9d`. The release/gitlink evidence is preserved in [support](support/) and explained in the [published Cargo source review](../cargo-r348-r349-r352-to-rust-1981-source-review-2026-09-30/REPORT.md).

Ten claim-mapped Cargo files were compared as complete, commit-pinned blobs: **six identical and four changed**. The unchanged source preserves the inspected root-generation, recursive dependency-unit, feature-context, and unit-graph serialization code. The four changed files affect orchestration diagnostics/timing, rustc arguments/search paths, and build-script environment. Those changes can matter to an exact command or generated-output provenance claim, so this review does **not** transfer R350's counts, feature arrays, wrapper log, LLBC/model, or proof outcome to Rust 1.98.1. No Cargo, rustc, Charon, Aeneas, Anneal, Lean, build script, or fixture was executed here.

### Changed-file deltas that bear on R350

The [four retained diffs](support/diffs/) show: `ops/cargo_compile/mod.rs` changes parse-warning handling, `compile_ws` visibility, and logging timestamps; `core/compiler/mod.rs` removes a verbose rustc flag, adds optional `hint-msrv`, changes trim-paths remap construction, and skips custom-build output directories in dependency search-path arguments; `core/compiler/compilation.rs` changes dependency output paths to sets and alters host runner/linker fallback; `core/compiler/custom_build.rs` changes trim-paths environment names and remap data supplied to build scripts. The mapped root/graph operations are still present, but exact argv, environment, generated files, fingerprint decisions, and process counts remain unobserved for the newer source.

## Limits and source provenance

The old and new Cargo commits and Rust gitlinks are the same official source identities established by the published R348/R349/R352 review. The [local pin snapshots](support/rust-old-cargo-gitlink.json) and [new pin snapshot](support/rust-1981-cargo-gitlink.json), with [tag peel](support/rust-tag-refs.txt), let this report identify the official Rust 1.98.1 Cargo **source**. They do not establish the compiled Cargo binary supplied by any installation. The comparison is deliberately limited to ten R350-mapped files; it is not a repository-wide equivalence proof. The R350 Charon, Aeneas, Anneal, Lean, and rustc behavior claims are not revalidated here. In particular, Cargo's graph semantics cannot say whether a dependency body was local or opaque in LLBC, whether generated declarations had contracts, or whether a theorem was checked.

The [source manifest](support/source-observation.json) has commit-pinned URLs and full old/new files. To reconstruct source identity independently, inspect the Rust `1.98.1` annotated tag, its peeled commit `48a229ce…`, and that commit's `src/tools/cargo` gitlink; inspect the old Rust `14210df0…` tree's same gitlink. Fetch the ten listed files at `fbb61be30…` and `797e8a9b…`; compare raw bytes, calculate `git hash-object` and SHA-256, and diff the four changed pairs. The exact shell recipe, including a no-network offline check against retained snapshots, is in [reproduce.md](support/reproduce.md).
