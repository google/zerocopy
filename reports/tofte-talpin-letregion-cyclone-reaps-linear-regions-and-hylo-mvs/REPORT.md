# Region-based bulk reclamation versus mutable value semantics: Tofte–Talpin/MLKit `letregion`, non-LIFO and reference-counted regions, Cyclone regions and reaps, linear regions, and Hylo

## Summary

- **One invariant, many enforcement points.** Every region discipline examined enforces the same safety invariant — *no dereference of a pointer into a region after that region's storage is reclaimed* — but places the check differently: statically by an effect system with LIFO scopes (Tofte–Talpin, MLKit, Cyclone lexical regions), statically by flow-sensitive region state or linear capabilities (Henglein–Makholm–Niss, Walker–Watkins, Fluet–Morrisett–Ahmed), or dynamically by counting external references to a region (Gay–Aiken RC, Cyclone reference-counted keys). Mutable value semantics (Hylo, Racordon et al. 2022) enforces a *different* invariant — no two live names observe the same mutable storage (the Law of Exclusivity) — and gets deallocation from ownership/last use plus copy-on-write reference counts for dynamically sized containers.
- **Runtime metadata is per region, not per object, in MLKit without GC.** At `melsman/mlkit@30d46774b839fe8b6997e902526df65c95de88f4`, an infinite region is a 5-word stack descriptor plus a linked list of 8 KiB pages with a 2-word header each (0.195% of a page); finite regions (multiplicity ≤ 1, `K = 1`) live on the stack with no descriptor; objects carry no header unless profiling or GC is enabled (the GC help text states "all values are tagged"). Region deallocation splices the whole page list into the free list in O(1).
- **Measured (MLKit v4.7.26, x86_64 Linux): storage-mode analysis is what makes tail loops constant-space.** With `atbot` resetting, three tail-loop probes ran in 1.6–2.4 MB peak RSS at 16 million iterations; rebuilt from scratch with `--disable_atbot_analysis`, the same programs grew linearly at exactly the size of one dead object per iteration (8.06, 16.05, 24.11 B/iteration for a boxed real, a pair, and an 8-character string), and a list-iteration probe grew at 16 B per dead cons cell.
- **Measured: three region pathologies that a tracing collector does not have.** (1) Identical `iter` code ran in O(list) space when called from a function body (region passed `atbot`) but O(iterations × list) when its input was a top-level `val` (global region passed `attop`). (2) A `letregion` of two *finite* regions wrapped around a recursive call turned a tail loop into recursion: 96 B/iteration growth (stack frames plus accumulated cells) under pure regions and, with `-no_ri` GC, quadratic time (6.37 s at 1 M, 106 s at 4 M iterations). (3) Escaping closures and a FIFO whose elements die asynchronously grew linearly (201 B and 84 B/iteration) under pure regions; region inference plus GC rescued the closure case (1.6 MB) but not the FIFO (2.1 GB at 16 M), while GC alone kept the FIFO at 1.6 MB.
- **Measured (Heap-Layers `ZoneHeap`, `emeryberger/Heap-Layers@0df48633fe9e431ae867543aec5e935ba485802f`):** zero per-object header (cost is 16-byte size rounding only), 2.5–12.3 ns/allocation vs 15.3–36.1 ns for glibc `malloc`, bulk release of 10 M objects in 0.4–11.3 ms vs 127–298 ms of individual `free`s — but under a FIFO with 1,000 live 24-byte objects the zone held 13,340× the live payload.
- **Value semantics avoids the region pathologies by tying reclamation to ownership and last use, and pays in copies.** Its peak-space risks are transient duplication (copy-on-write splits, explicit copies at escape points) and per-container reference counts; region systems pay in retention (dead data kept until scope exit) and in programmer-inserted copies between regions. Both converge on the same idiom for loop-carried state: copy the surviving state into fresh storage and release the old storage in bulk (MLKit "copy" idiom, Cyclone dynamic-region swapping, Hylo `sink`/move).

## Applicability

**Subjects and their relationship.** The report is a comparison. MLKit (source at `melsman/mlkit@30d46774b839fe8b6997e902526df65c95de88f4`, executed as the v4.7.26 binary release built from tag commit `6adaef92147764eecd95a8bacb1bfc8c97a7002d`) is the reference implementation of Tofte–Talpin region inference. The Cyclone runtime and type checker were examined at the preservation mirror `mingodad/cyclone@d6aae7ffc3eb387ccc84d262a9dc983f11b4db66` (source inspection only; not built). Heap-Layers (`emeryberger/Heap-Layers@0df48633fe9e431ae867543aec5e935ba485802f`) supplies a zone (arena) allocator and the historical reap API; its `ZoneHeap` was compiled and executed. Hylo (`hylo-lang/hylo-new@fe703c7dae6c496ad21ae7024957c7e84020ef3c`) was examined at source level only (no Swift toolchain was available). Papers listed in `REPORT.json` were examined in fetched full text (the Tofte–Talpin PDF's text extraction was degraded, so its rules are paraphrased rather than quoted; Fluet–Morrisett–Ahmed was examined at the level of abstract and introduction); other cited papers were checked only for bibliographic identity (see **Evidence**).

**Execution environment.** All execution was on one x86_64 Linux host (Intel Xeon at 2.6 GHz, 96 hardware threads, kernel 7.1, glibc 2.43, g++ 15.2.0) on 2026-11-20. Peak memory is `/usr/bin/time -f %M` maximum resident set size; a baseline MLKit executable occupies about 1.6 MB, so values near that are "no growth". Times are single runs unless a range is given.

**MLKit configurations measured.** `ri` = `-no_gc -no_par` (pure region inference, storage-mode analysis on); `rinoatbot` = `-no_gc -no_par --disable_atbot_analysis` (all user-code allocation `attop`; the basis library was still compiled with storage-mode analysis); `rigc` = `-gc` (default: region inference plus reference-tracing GC); `gconly` = `-gc -no_ri` (values that would go to infinite regions go to global regions; finite regions remain). **Scope limits.** Claims about Tofte–Talpin and its relatives concern the published calculi and the named implementations; they do not transfer automatically to Rust lifetimes, OCaml/OxCaml regions, or arena crates. Heap-Layers findings concern `ZoneHeap` over `malloc`; they do not characterize the reap implementation from the 2002 paper, which is not present at the pinned revision except as an API header. Existing corpus material on MLKit's storage-mode region resetting in the context of actor heaps (`beam-procbin-heaps-pony-orca-capabilities-and-mlkit-region-resetting`) is complementary; this report focuses on the region discipline itself and its comparison with value semantics.

### 1. Discipline map

|---|---|---|---|---|

Basis: normative (papers) + source (MLKit, Cyclone, Hylo) + derived (classification).

### 2. Tofte–Talpin rules and the MLKit pipeline

**Core judgment (reconstructed).** TT translates a source term into a region-annotated term: `TE ⊢ e ⇒ e' : μ, φ`, where `μ = (τ, ρ)` is a type with place (the region holding the value), and the effect `φ` is a set of atomic effects `get(ρ)`, `put(ρ)` and effect variables `ε`. Function types carry arrow effects `μ₁ —ε.φ→ μ₂`. Allocation `e at ρ` adds `put(ρ)`; reading a boxed value adds `get(ρ)`. The key rule is

```text
TE ⊢ e ⇒ e' : μ, φ        φ' = Observe(TE, μ)(φ)        {ρ₁..ρₖ} = frv(φ) \ frv(TE, μ)
----------------------------------------------------------------------------------------
TE ⊢ e ⇒ letregion ρ₁..ρₖ in e' end : μ, φ'
```

`Observe` discards atomic effects on region/effect variables not free in the environment or the result type; those regions are bound locally and their storage is reclaimed at the end of `e'`. Region polymorphism (`letrec f [ρ₁..ρₖ] x = …`) with polymorphic recursion in regions lets each recursive call receive fresh regions. Soundness is stated as consistency between source values and target store contents, preserved under evaluation, with the twist that consistency may "decrease" as regions are popped: a value is only required to be consistent where it can still be observed. Basis: normative (Tofte & Talpin 1997, paraphrased; the extracted PDF text was too degraded to quote rule numbers).

**MLKit realization.** The pinned compiler implements the pipeline as separate passes, each a separate source of space behavior:

| Pass (file at pinned SHA) | Role | Space consequence |
|---|---|---|
| `src/Compiler/Regions/RegInf.sml` (header "Algorithm R / Mads Tofte") | region and effect inference (Tofte–Birkedal algorithm) | decides *which* region each allocation goes to |
| `src/Compiler/Regions/MulInf.sml`, `Mul.sml:36-37` (`datatype mul = INF \| NUM of int`, `val K = 1 (* the largest finite multiplicity *)`) | multiplicity inference: a region is finite iff at most one value is ever stored | finite regions go on the stack with no descriptor |
| `src/Compiler/Regions/AtInf.sml:1,43` ("Storage Mode Analysis"; `datatype 'a at = ATTOP of 'a \| ATBOT of 'a \| SAT of 'a`) | storage modes: `attop` (append), `atbot` (reset region, then store), `sat` (decided at run time from a bit passed with the region) | turns tail loops from O(n) into O(1) space (Finding 6) |
| `src/Compiler/Regions/PhysSizeInf.sml`, `DropRegions.sml` | physical sizes of finite regions; drop region parameters that are never written | fewer region arguments |
| `src/Compiler/Lambda/OptLambda.sml:221-229` | "aggressive optimisations … are not guaranteed to be region safe. Turning off garbage collection automatically turns off this option." | optimizer and region safety interact |

The `sat` mode is implemented by tagging the region pointer passed to a function: "The least significant bit is 1 iff the region is infinite. The second least significant bit is 1 iff stores into the region should be preceded by emptying the region" (`src/Runtime/Region.h:344-350`, macros at `:356-367`). In the compiled probe, the reset appears as a test of bit 1 followed by a call to `__reset_region` in the *base case* of `map` — after the input list has been fully traversed and before the first cons cell of the output is written (disassembly of the user object; Finding 6). Basis: source + execution.

### 3. Non-LIFO relaxations and what each one costs

- **Aiken–Fähndrich–Levien (PLDI 1995).** Keeps the TT type system but separates *when a region's storage is allocated or freed* from the `letregion` binding point, using a constraint-based analysis to allocate late and free early. Price: a whole-program-style analysis; no new runtime checks. Basis: documentation (paper identity verified; full text not examined, so no numbers are quoted).
- **Henglein–Makholm–Niss (PPDP 2001).** Replaces lexical binding with explicit region-state transitions that a flow-sensitive type system tracks, so regions can be created and destroyed at arbitrary program points. Price: a typestate-like system whose judgments depend on control flow. Basis: documentation (identity verified; not examined in full text).
- **Gay–Aiken reference-counted regions (PLDI 1998, PLDI 2001; Gay's 2001 dissertation).** C programs call `newregion`/`ralloc`/`deleteregion`; safety comes from counting references *into* a region from outside it, and deletion fails if the count is nonzero. Qualifiers `sameregion`, `traditional` and `parentptr` mark pointers whose writes need no count update; "between 35% and 99.99% of pointer assignments executed were to annotated types", static analysis eliminated "between 37% and 99.99% of checks", and the combination "reduces the largest reference counting overhead from 22.3% to 12.6% of runtime"; with a simpler local-variable scheme the overhead was "up to 25%". Basis: documentation (dissertation).
- **Walker–Watkins (ICFP 2001) and Fluet–Morrisett–Ahmed (ESOP 2006).** Region handles become linear capabilities, so a region can be freed whenever its unique capability is consumed. Fluet et al. state that λ^rgnUL "is powerful enough to encode Tofte-Talpin-like languages, and that eliminates the LIFO restriction", with "an extremely simple, substructural type system", and sketch encodings of TT regions and of Cyclone's dynamic regions and unique pointers. Price: linearity must be threaded through the program (or produced by a translation from a friendlier source language). Basis: documentation (ESOP abstract and introduction).

### 4. Cyclone: lexical, dynamic, unique, reference-counted regions and reaps

Cyclone pairs a static region type system (region-annotated pointer types, effects as capability sets, an outlives partial order) with a runtime that supports several region kinds behind one handle type.

- **Outlives order.** `src/rgnorder.h:40-46` exposes `add_outlives_constraint`, `add_youngest` (push a lexical region as the youngest), `add_unordered` (an opened dynamic region has no order with respect to its neighbors), `effect_outlives` and `rgn_outlives_rgn`. A lexical region thus extends a total order; a dynamic region enters only for the duration of an `open`.
- **Handle and page layout.** The handle (`bin/cyc-lib/cyc_include.h:42-57`) holds the runtime-stack link, current page, allocation offset and limit, an allocation-function table, an autorelease pool, an allocator key used by reaps, and `used_bytes`/`wasted_bytes` counters. A page is a `next` pointer followed by data (`:30-36`; profiling adds two counters). (The older header `lib/include/cyc_include.h:39-56` shows a smaller handle; the generated header is the one matching `runtime_memory.c`, which reads `used_bytes`, `wasted_bytes` and `key`.)
- **Page growth is geometric.** `grow_region` sets `next_size = prev_size * 2` (`lib/runtime_memory.c:225`) starting from `CYC_MIN_REGION_PAGE_SIZE 480` bytes (`:211`); pages come from the conservative collector's allocator (`_bounded_GC_calloc`). Consequently freeing a region walks its page list and calls `GC_free` per page (`free_region_impl`, `:470-490`) — O(number of pages), which is O(log₂(bytes/480)) under doubling (derived) — whereas MLKit splices the whole list in O(1) (Finding 5).
- **Reference counting is a per-object header word.** Reference-counted allocation reserves `s+sizeof(int)` and stores the count before the object (`:305`, again in the reap path at `:592`); `Cyc_Core_drop_refptr` frees at zero.
- **Unique pointers** are freed individually by `Cyc_Core_ufree` (`:774`), which "is not recursive; it assumes that programmer has freed nested pointers (otherwise will be grabbed by the GC)" (`:771-773`).
- **Dynamic regions** are created with a unique key (`Cyc_Core__new_ukey`, `:925`) or a reference-counted key (`Cyc_Core__new_rckey`, `:945`) and accessed only through `Cyc_Core_open_region` (`:1000`), which passes the handle to a callback — a lexical "open" over a non-lexical lifetime.
- **Reaps** — regions that also allow individual frees — are implemented by a second allocation-function table using the `bget` allocator: `reap_rufree_impl` releases one object with `brel(r->key, ptr)` (`:531-548`).

Published porting cost (Hicks et al. 2004, Table 3; non-comment lines changed): Boa web server 5,217 lines, 5% changed to port to Cyclone with GC and a further 1% to use manual mechanisms; BetaFTPD 1,146 lines, 16% and 21%; Epic 2,123 lines, 10% and 5%; Kiss-FFT 453 lines, 16% and 4%; MediaNet (written in Cyclone, 8,715 lines) needed 4% changes to move to unique pointers and dynamic regions, with "swap 74 times and alias 67 times, of which 67% were automatically inferred". Runtime effects reported: Boa throughput within 2–3% of C; MediaNet with free-on-forward achieved 23% higher throughput than GC-only at 4 KB packets; CycWeb's working set stayed below 6.5 KB. Swamy et al. (2006) report for the manually managed Cyclone versions "a thirty-fold reduction in memory usage" in the best case (BetaFTPD) and a worst case (Cfrac) "more than twice the size of the C version, though still roughly half that of the Cyclone GC version", which they attribute to "the need to copy between arenas with each loop iteration". Basis: documentation (papers) + source.

**Interpretation (each item states its evidence).**

1. *Storage modes make tail loops constant-space.* Without `atbot`, the slope between 4 M and 16 M iterations is 8.06 B (boxed real), 16.05 B (pair) and 24.11 B (string) per iteration — exactly one dead value per iteration, untagged — while `ri` stays at baseline. The fresh `rinoatbot` user objects contain 0 `__reset_region` call sites; the `ri` objects for `itermap2`, `tailpair` and `queue2` contain 3, 3 and 5. Basis: execution + derived.
2. *The caller's storage mode decides asymptotic space.* `itermap` and `itermap2` have source-identical `iter` functions, and both compiled `map` bodies contain the reset site. In `itermap` the region-annotated program shows `val r = iter[attop r4] (n, l0)` (global region, `attop`), so the run-time bit is never set and every iteration's list stays (15.99 B per cons cell, derived slope); in `itermap2` it shows `iter[atbot r81] (n, v230)` inside `main`, and the reset fires at `map`'s base case each iteration. The same holds for the copy idiom (`itercopy` vs `itercopy2`): the copy alone does not help when the outermost region is passed `attop`. Basis: execution + compiler output (`-Ppse`, preserved in `support/mlkit/*.regions.txt`).
3. *A `letregion` around a call defeats tail calls.* In `queue`, the region-annotated `run` reads `let … region r103:2, r105:2; val v137 = pop[…] … in run[sat r93,sat r91] (…) end`: two *finite* regions (2 words each) are bound around the recursive call, so the call must return to pop them. The stack therefore grows by one frame per iteration, and the pushed cons cells (`:: (v223, v263) attop r93`) also accumulate in the loop's region; together they give a 96.0 B/iteration slope under `ri`. With `-no_ri` the finite regions remain (`region r103:3, r105:3`), so GC scans an ever-growing stack: time rose 16.6× for 4× more iterations. Rewriting `pop` away (`queue2`) removes this frame growth under GC-only (1.6 MB) but not under region inference, where the refill branch is still wrapped in `region r31:inf … region r33:inf` and pushes accumulate `attop` in the loop's region (84.2 B/iteration). Raising the refill period from 100 to 1,000 cut the 16 M-iteration peak from 1,316,428 KB to 518,484 KB; the marginal cost per refill is ≈ 5.7 KB (derived: (84.15 − 33.10) B ÷ (1/100 − 1/1000)), the same order as one 8 KiB region page, but the exact decomposition was not established. Basis: execution + compiler output + derived.
4. *Asynchronous death needs a tracing collector or a different data layout.* `closure` keeps only 10 closures live, but all closures and their captured reals share the list's region: 201.3 B/iteration under `ri` and `rinoatbot`; the default `rigc` mode keeps it at baseline. For `queue2`, `rigc` (2.1 GB) was *worse* than `gconly` (1.6 MB). A plausible explanation — not verified, because the region-annotated program was dumped only for the `-no_gc` build — is that region inference creates the nested region frames seen in item 3, keeping data reachable, and a tracing collector cannot free reachable data. Basis: execution.

Published MLKit evidence agrees in kind: Elsman & Hallenberg (2021) sort 1,000,000 integers with a merge sort whose `merge` returns its arguments' tails (all intermediate lists "pile up in the same region") versus a "region-friendly" variant that copies the tails; under pure region inference the measured memory was 410 MB vs 103 MB (3.98×, derived) at 0.46 s vs 0.44 s, while region inference plus generational GC brought the unfriendly version to 139 MB at 1.14 s (0.44 s of it GC). Their measurements were on a 2.7 GHz Intel Core i7 laptop with MLKit 4.5.1, averaged over 30 runs. Basis: documentation.

| FIFO, 1,000 live × 24 B, 10 M total | 320,168,544 B held (13,340× live payload) | sampled peak 39,504 B (1.65× live payload) |
| mixed sizes 16–4,096 B, 200k objects | overhead vs requested: 20.27% (8 KiB chunks), 2.56% (64 KiB), 0.68% (1 MiB) | not measured |

The zone abandons the unused tail of the current arena whenever a request does not fit (`zoneheap.h:95`, "Get more space in our arena if there's not enough room in this one"), which is the source of the chunk-size-dependent overhead; `free` is a no-op (`:62`). The pinned revision carries a fix comment explaining that the 24-byte arena header previously left objects only 8-byte aligned and is now padded with `alignas` (`:125-131`); this is historical, not a current defect. Basis: source + execution.

Published allocator comparisons: van Kempen & Berger (2026) re-ran the 2002 custom-allocator study on current hardware and report that modern general-purpose allocators reduced "region allocator speedups from up to 44% in the original study to at most 15%", with mimalloc within 7.1%, 14% and 15% of custom region allocation on 197.parser, geometry_nodes and mudlle, and that region allocators retain a locality advantage on fragmented heaps. Gay (2001) measured space overheads "between 44% and 772% for the Boehm-Weiser conservative garbage collector", "between 2% and 174% for unsafe regions (with most benchmarks below 26%), and between 9% and 305% for RC", and, comparing against Doug Lea's malloc/free and the Boehm–Weiser collector, that "safe regions are from 6% slower to 55% faster" with memory usage "from 19% less to 4% more" except for applications needing only a few hundred kB ("up to 2.7x more memory needed for RC's regions"). Basis: documentation.

### 8. Regions versus mutable value semantics: four axes

**Hylo at the pinned revision.** Access effects are `let = 1` (immutable), `set = 2` (assigned, never read), `inout = 4` (mutable), `sink = 8` (consumed), `auto = 16` (`Sources/FrontEnd/Syntax/AccessEffect.swift:5-20`); `var` and `sinklet` bindings map to `sink` (`:28`). Projections have a `RemoteType` = projectee type + access effect (`Sources/FrontEnd/Types/RemoteType.swift:3-17`). The IR has region-entry/region-end instructions (`Sources/FrontEnd/IR/Instructions/IRRegion.swift:4-15`), and a pass "Adds missing closing instructions after the last uses of region opening definitions … Some instructions (e.g., `access`) define a value and open non-lexical region in which that value is considered alive … each opened region must be closed by an `end` instruction after the last use of the corresponding definition, on all execution paths" (`Sources/FrontEnd/IR/Transforms/IRFunction+RegionClosing.swift:5-12`). An exclusivity pass "Verifies that … `self` does not perform any overlapping access to mutable data" (`IRFunction+ExclusivityAnalysis.swift:5`). So Hylo's "regions" are liveness-bounded *access* windows over owned storage, not allocation arenas. Basis: source.

| Axis | Lexical regions (TT/MLKit/Cyclone LIFO) | Dynamic/linear regions (HMN, Cyclone keys, λ^rgnUL) | Mutable value semantics (Hylo; Racordon et al.) |
|---|---|---|---|
| Peak space | retention until scope exit; O(1) loops only with storage-mode reset or restructuring; asynchronous death leaks (Finding 6) | can free at any point the capability is consumed; loop state requires copy-to-new-region (Cfrac >2× C, Swamy et al.) | reclamation at last use; transient peaks from copies and CoW splits; not measured here |
| Duplication / copy elimination | sharing within a region is free; copies needed to move data to a shorter- or longer-lived region (`copy` idiom; Elsman & Hallenberg) | same, plus explicit `swap`/`alias` for unique pointers (Hicks et al.: 74 swaps, 67 aliases in ~9,000 lines) | copies are semantic defaults; compilers substitute aliases for copies when no mutation is observable and use CoW for arrays (Racordon et al. §6.2–6.3); `sink` moves |
| Runtime metadata | per-region descriptor and page headers; 0 per object without GC | per-region handle + key refcount; per-object refcount word when used | refcount per dynamically sized container (header ⟨r, n, k⟩); none for inline structs |
| Isolation from aliasing | none within a region: many pointers may name one object and observe each other's writes; safety is temporal only | unique pointers give exclusive access; RC keys do not | exclusivity: no two live names observe one mutable location; `inout` arguments must be independent |

Basis: source + documentation + execution (as cited per cell) + derived (comparison).

**Volatile/device writes.** Neither the TT/MLKit/Cyclone region rules nor Hylo's access effects, as examined, model volatile or memory-mapped I/O semantics; isolation from volatile writes is therefore *not provided* by either core discipline at the level examined (see **Boundaries**).

**Which workloads favor which model (derived from the evidence above).**

- Regions win on phase-structured allocation with a common death time (per-request arenas, compiler passes, per-frame scratch): zero per-object metadata, O(1) bulk free, contiguous placement (Findings 5, 7; van Kempen & Berger 2026).
- Value semantics wins when lifetimes are individual and determined by use (FIFOs, caches with eviction, event streams) — exactly the asynchronous-death cases where lexical regions grow linearly — and when local reasoning about mutation matters more than allocation throughput.
- Region inference plus a tracing collector (MLKit `-gc`) recovers most pathological cases at the cost of tags on all values and a collector; it does not fix space that is *reachable* only because of region structure (`queue2`).

**Where they converge.** (i) Loop-carried state: MLKit's region-friendly copy, Cyclone's copy-into-new-dynamic-region-then-free, and Hylo's `sink`/move all express "the next iteration owns a fresh copy; the old storage dies as a unit". (ii) Hylo's non-lexical access regions closed after last use are the borrow-side analogue of storage-mode `atbot` resets: both move a reclamation or invalidation point from the end of a lexical scope to the last use. (iii) Linear region capabilities (λ^rgnUL) and `sink` parameters are both linear resources; the difference is granularity — one capability per region versus one owner per value.

### 10. Comprehensibility (C1) and model refinement (C2)

**C1.** TT region inference has a low *annotation* burden and a high *diagnosis* burden: Finding 6 item 2 shows a change invisible in the source semantics (top-level `val` vs local `let`) changing peak space from O(len) to O(n·len), and the only diagnostic channel is a compiler dump of region-annotated code (`-Ppse`) plus knowledge of three storage modes, multiplicities, and region polymorphism — about six interacting concepts to hold in working memory. Cyclone's explicit regions are locally legible (`region r {…}`, handles in signatures) but dynamic keys, unique pointers, `swap`/`alias`, reference counts and reaps add five mechanisms with distinct rules. Hylo's four parameter conventions plus exclusivity are locally checkable at each call site; their failure mode is a compile-time exclusivity diagnostic rather than silent space growth. Human comprehension of any of these was not measured.

**C2.** The examined systems use several mechanisms to enforce the one temporal-safety invariant: static effects, run-time reset bits, reference counts on regions, reference counts on objects, linear keys. Fluet–Morrisett–Ahmed show one minimal universal core — linear region capabilities — under which TT regions, dynamic regions and unique pointers become encodings rather than special cases, without adding a run-time check. Mutable value semantics instead removes the aliasing that makes regions necessary for *safety*, leaving regions only as an allocation-*performance* device; Hylo's IR already treats regions as liveness windows. A design that wants both should keep the allocation question (arena vs per-object) orthogonal to the safety question (exclusive ownership vs region capability) rather than merging them; the evidence here does not establish that either subsumes the other (see **Boundaries**).

### 11. Validation of these mechanisms (V1–V4)

- **V1 (specification adequacy).** TT soundness is proved over an idealized store; MLKit adds a separate strengthening for GC safety (Elsman 2003). Nothing in the proofs bounds *space*, so space regressions such as Finding 6 escape them; the discriminating validation is differential execution of the same program under `ri`/`rinoatbot`/`rigc`/`gconly` with peak-RSS scaling checks, as done here. Mutation testing of region annotations: not examined.
- **V2 (lowering/checker soundness).** The presence of `__reset_region` sites in object code is a cheap translation-validation hook; this report used it to detect a stale-object build. Fuzzing of region inference or of Cyclone's checker: not examined.
- **V3 (concurrency/crash).** MLKit's parallel mode adds a per-region mutex field (`Region.h:242-246`); concurrent region behavior was not examined. Crash/fault injection: known not to apply to the examined questions.
- **V4 (human/plant).** Empirical studies of programmers' mental models of region lifetimes or value semantics: not examined.

## Boundaries

- **Not examined:** full texts of Aiken–Fähndrich–Levien 1995, Henglein–Makholm–Niss 2001, Walker–Watkins 2001, Grossman et al. 2002, Tofte–Birkedal 1998, Birkedal–Tofte–Vejlstrup 1996, Hallenberg–Elsman–Tofte 2002 and Berger–Zorn–McKinley 2002 (identities verified; no numbers from them are quoted except via the 2026 re-evaluation's summary of the 2002 paper). Cyclone was not built or run; Hylo was not built or run, so no Hylo peak-space, copy-count or compile-time number exists in this report. MLKit generational GC (`-gengc`), parallel mode, and region profiling were not run. The legacy Heap-Layers reap implementation was not run (only its API header exists at the pinned revision).
- **Unknown:** the exact decomposition of `queue2`'s 84 B/iteration and the per-refill ≈5.7 KB marginal cost; why `rigc` exceeds `ri` on `queue2`. Whether MLKit's region inference time is a significant share of compile time.
- **Observed tooling hazard, not diagnosed:** rebuilding a program with `--disable_atbot_analysis` in a directory where it had just been built with storage-mode analysis produced an executable whose user object still contained the `__reset_region` sites (object file timestamp earlier than the new link; 3 sites vs 0 in a fresh build). The responsible source lines in MLKit's dependency tracking were not located, so this is reported as an observation, not as an upstream bug. All `rinoatbot` numbers above come from fresh directories.
- **Known not to apply:** these results do not show that value semantics or regions is more expressive in a formal (macro-expressibility) sense; no theorem quantifying over translations between the two was examined or proved. The probe programs are small microbenchmarks chosen to exercise known pathologies; they do not estimate how often the pathologies occur in real programs.
- **Unsupported (by the examined rules):** isolation from volatile or memory-mapped writes; neither discipline's examined rules model it.
- **Attractive but unsupported conclusions:** "region inference with GC is always at least as good as GC alone" (contradicted by `queue2`); "the copy idiom always restores constant space" (contradicted by `itercopy` with a top-level input); "zones always save memory per object" (no saving at 24 or 40 B against glibc in the measured configuration).
