# Locally Complete Analyzers, State-Bounded Wp Oracles, and Trivial Compiler Equivalence Mutant Filtering

## Summary

Validation gates and interface contracts that attempt to exclude vacuous or deceptive implementations while admitting honest conservative static analyzers hit three sharp theoretical and empirical barriers—each with a precise, implementable engineering mitigation:

1. **Global completeness locks out sound static analyzers; local completeness certifies exactness per path.** By Rice's theorem and the theory of complete abstract interpretations (Giacobazzi, Ranzato & Scozzari, JACM 2000, DOI `10.1145/333979.333989`), no non-trivial sound syntactic analyzer can be globally complete across all inputs without collapsing into concrete execution. **Local Completeness Logic (`LCL`)** (Bruni, Giacobazzi, Gori & Ranzato, LICS 2021, DOI `10.1109/LICS52264.2021.9470608`) resolves this by certifying triples $\vdash_{\mathcal{A}} [p]\; c\; [q]$ where $q$ under-approximates $\mathrm{post}\llbracket c \rrbracket(p)$ while sharing its exact abstraction ($\mathcal{A}(q) = \mathcal{A}(\mathrm{post}\llbracket c \rrbracket(p))$), proving zero false alarms along accepted inputs without demanding global completeness elsewhere. Direct audit of `NASA-SW-VnV/ikos` (`ac7f7c1738976cabc58c6a53413df6e458995c38`) shows how production abstract interpreters implement 21 selectable numeric domains (`Interval`, `Congruence`, Granger's reduced product `IntervalCongruence`, `DBM`, `Gauge`, `VarPacking`, and APRON polyhedra/octagons) and report four-valued verdicts (`Ok`, `Warning`, `Error`, `Unreachable`), explicitly noting that the built-in `core` `Octagon` class carries unresolved unsoundness/segfault warnings (`octagon.hpp:76-78`) and recommending APRON instead.
2. **Finite black-box probes cannot rule out unbounded hidden-state evasion; active-learning completeness requires an explicit state upper bound $m$.** By Gold's identification-in-the-limit barrier (Gold 1967, DOI `10.1016/S0019-9958(67)91165-5`), no fixed finite observation set rules out a deceptive lookalike that diverges on an untested input. Angluin's $L^*$ algorithm (Angluin 1987, DOI `10.1016/0890-5401(87)90052-6`) learns a minimal $n$-state automaton in polynomial queries *only* given an Equivalence Oracle; implementing that oracle via Chow's $W$-method or Fujiwara's $W_p$-method requires an explicit upper bound $m \ge n$ on hidden implementation states and costs $\Theta(|\Sigma|^{m-n+1})$ queries. Direct execution of upstream `DES-Lab/AALpy` (`b3ed2fb48cb77840fb4cfa6bf7d8aab50c70d18a`) confirms: (a) `WpMethodEqOracle` reduces execution steps by **22.0%–28.8%** relative to `WMethodEqOracle` on minimal 4-state Mealy specifications ($|\Sigma| \in \{2, 3\}$, $m-n \in \{0..4\}$) while preserving the exact same exponential growth base $|\Sigma|^{m-n+1}$; (b) a deceptive 6-state combination-lock implementation completely evades both `WMethodEqOracle(m=5)` and `WpMethodEqOracle(m=5)` (and `L* + Wp(m=5)`), yet is caught immediately at $m=6$; and (c) an implementation edge case in `WMethodEqOracle.py:62` and `WpMethodEqOracle.py:109` computes `depth = self.m + 1 - len(hypothesis.states)`, silently running **0 queries** and returning `None` whenever a hypothesis exceeds `m`.
3. **Zero-survival mutation gates fail on real code because ~30%–52% of surviving mutants remain semantically equivalent even after compiler optimization.** Papadakis et al. (ICSE 2015, DOI `10.1109/ICSE.2015.103`) established on large C benchmarks that Trivial Compiler Equivalence (`TCE`) discards ~7% of generated mutants as equivalent and ~21% as duplicates (~28%–30% total) prior to test execution, yet catches only **~30% of true human-verified equivalent mutants**. Direct source inspection shows `mull-project/mull` (`4b53263e8880ae9f14a8abcf7effe4effcbb799d`, v0.39.1) filters LLVM IR *junk* mutations via `CXXJunkDetector` (Clang AST matching) and a Rust `FilterChain`, but contains **no TCE pass** because all mutants are injected behind runtime flags into a single binary; meanwhile `agroce/universalmutator` (`fec4223b30f9e26b9e0497d43375fbd5c1ecd5bf`, v1.14.1) ships no-op stubs for `c_handler.py`/`cpp_handler.py` and runs unoptimized `rustc` (`-C opt-level=0`) in `rust_handler.py`. Running `universalmutator` directly with `gcc 15.2.0` (C) and `rustc 1.98.0-nightly` (Rust) shows `-O2`/`-O3` TCE eliminates **35.8%** of compilable C mutants (**4.6%** equiv + **31.2%** dup) and **34.3%** of compilable Rust mutants (**5.1%** equiv + **29.3%** dup, **2.62×** higher than `rust_handler.py`'s `-C opt-level=0` baseline of **13.1%**)—yet **12 of 23 (52.2%)** non-TCE-equivalent surviving C mutants on a high-coverage test suite remain genuine TCE-escaping semantic equivalents (loop-invariant `lo != hi`, trisection search, memory-reload boundary, SWAR vs. loop popcount, commutativity, and CFG-layout `continue;`).

## Findings

### 1. Locally Complete Abstract Interpretation (`LCL`) vs. Global Completeness and Rice's Barrier

**Basis:** normative literature (JACM 2000 DOI `10.1145/333979.333989`, LICS 2021 DOI `10.1109/LICS52264.2021.9470608`) + source (`NASA-SW-VnV/ikos@ac7f7c1738976cabc58c6a53413df6e458995c38`, `core/include/ikos/core/` and `analyzer/include/ikos/analyzer/`) + execution (toy model of `LCL` and IKOS `IntervalCongruence` reduction, not the IKOS C++ binary).

Let $(C, \sqsubseteq)$ be the concrete collecting-semantics lattice ($\wp(\Sigma)$), $(\mathcal{A}, \sqsubseteq_{\mathcal{A}})$ an abstract domain linked by a Galois connection $(\alpha, \gamma)$ (or upper closure operator $\rho = \gamma \circ \alpha$), and $f : C \to C$ a concrete transfer function with best abstract transformer $f^\sharp = \alpha \circ f \circ \gamma$.

1. **Why global completeness locks out realistic sound analyzers (Giacobazzi, Ranzato & Scozzari, JACM 2000):**
   - **Soundness** requires $\forall x \in C.\; \alpha(f(x)) \sqsubseteq_{\mathcal{A}} f^\sharp(\alpha(x))$.
   - **Global (backward) completeness** demands equality everywhere: $\forall x \in C.\; \alpha(f(x)) = f^\sharp(\alpha(x))$ (equivalently $\rho \circ f = \rho \circ f \circ \rho$).
   - Giacobazzi et al. (JACM 2000) proved that global completeness is purely a property of the abstract domain $\mathcal{A}$ (not the implementation of $f^\sharp$) and constructively characterized the **complete shell** $S_f(\mathcal{A})$ (least refinement of $\mathcal{A}$ making it complete for $f$) and **complete core/kernel** $K_f(\mathcal{A})$ (coarsest restriction). However, for Turing-complete languages with non-trivial properties (such as buffer-overflow or division-by-zero freedom), the complete shell for all program constructs collapses to the concrete semantics—recovering Rice's undecidability barrier. Requiring an analyzer interface to satisfy a bidirectional "iff" on `Error` / `Unsupported` therefore **locks out every honest, scalable conservative analyzer**.

2. **How Local Completeness Logic (`LCL`) certifies zero false alarms without global completeness (Bruni, Giacobazzi, Gori & Ranzato, LICS 2021):**
   - Rather than requiring $\rho(f(x)) = \rho(f(\rho(x)))$ for *all* $x \in C$, **local completeness** $\mathbb{C}_{\mathcal{A}}(f, p)$ holds at a *specific* concrete precondition $p \in C$ iff:
     $$\alpha(f(p)) = \alpha(f(\gamma(\alpha(p)))) \quad\Longleftrightarrow\quad \rho(f(p)) = \rho(f(\rho(p))).$$
   - `LCL` defines a proof system parameterized by abstract domain $\mathcal{A}$ whose triples $\vdash_{\mathcal{A}} [p]\; c\; [q]$ simultaneously assert two invariants:
     1. **Under-approximation (reachability / true-witness grounding, akin to O'Hearn's Incorrectness Logic):** $q \subseteq \mathrm{post}\llbracket c \rrbracket(p)$ — every concrete state in $q$ is genuinely reachable from $p$;
     2. **Exact abstract fidelity (local completeness):** $\alpha(q) = \alpha(\mathrm{post}\llbracket c \rrbracket(p))$ — the abstract domain $\mathcal{A}$ loses **zero** precision between the concrete strongest postcondition and the under-approximated witness $q$.
   - **Operational consequence for verification gates:** When an analyzer accepts a program $c$ under precondition $p$ with an `LCL` derivation $\vdash_{\mathcal{A}} [p]\; c\; [q]$:
     - If $\alpha(q)$ is disjoint from the bad states $B$ (e.g., out-of-bounds indices), safety is proved **soundly** (`Ok`).
     - If $\alpha(q)$ intersects $B$ and $B$ is expressible in $\mathcal{A}$, then $q \cap B \neq \emptyset$ guarantees a **true reachable bug (`Error`, zero false alarms!)**, eliminating the "conservative `Warning` lockout" on certified paths while still permitting the underlying domain $\mathcal{A}$ to remain coarse and fast elsewhere.

### 2. Gold's Barrier, Angluin's $L^*$, and State-Bounded $W$/$W_p$ Conformance Oracles (`DES-Lab/AALpy`)

**Basis:** normative literature (Gold 1967 DOI `10.1016/S0019-9958(67)91165-5`; Angluin 1987 DOI `10.1016/0890-5401(87)90052-6`; Chow 1978; Fujiwara et al. 1991) + source (`DES-Lab/AALpy@b3ed2fb48cb77840fb4cfa6bf7d8aab50c70d18a`, `aalpy/oracles/WMethodEqOracle.py`, `WpMethodEqOracle.py`, `PacOracle.py`, `aalpy/base/Automaton.py:526-534`) + execution (real unmodified upstream `AALpy` via Python 3.13.15).

1. **The Inductive Inference Boundary (Gold 1967 vs. Angluin 1987):**
   - **Gold (1967)** proved that no **superfinite** class of languages (any class containing all finite languages plus at least one infinite language—including regular languages!) is identifiable in the limit from positive examples (*text*) alone: after any finite prefix of observations, an adversary can choose a distinct finite or infinite target agreeing on every observed string. Even with both positive and negative queries (an *informant*), **no finite test suite can decide equivalence of an unknown black-box program without an explicit structural hypothesis** bounding the implementation's state space—any fixed probe set $T$ is trivially evaded by a lookalike lookup table or hidden-counter automaton that hardcodes correct responses on $T$ and misbehaves outside $T$.
   - **Angluin (1987)** overcame Gold's negative result for regular languages by introducing the **Minimally Adequate Teacher (`MAT`)** model, granting the learner ($L^*$) both **Membership Queries (`MQ`)** and **Equivalence Queries (`EQ`)**. Under MAT, $L^*$ learns any minimal $n$-state DFA/Mealy machine using polynomially many queries in $n$, $|\Sigma|$, and the length of the longest counterexample.
   - **Realizing `EQ` on black-box systems requires an explicit state-count hypothesis $m$:** Because real software/hardware implementations lack a true white-box equivalence oracle, active learning libraries (`AALpy`) approximate `EQ` via conformance testing oracles:
     - **Chow's $W$-method (`WMethodEqOracle.py:11-81`):** Assumes the unknown System Under Learning (`SUL`) is deterministic, has a reliable reset, and has **at most $m$ states** (`max_number_of_states`). Given a minimal $n$-state hypothesis $H$ with transition cover $P = Q \cdot \Sigma$ (`Automaton.compute_transition_cover()`, `Automaton.py:526-534`, size $n \cdot |\Sigma|$) and global characterization set $W$ (`compute_characterization_set()`, size $|W| \le n - 1$), `WMethodEqOracle` executes:
       $$T_W(H, m) = P \cdot \Sigma^{\le m - n} \cdot W$$
       where `depth = self.m + 1 - len(hypothesis.states)` (`WMethodEqOracle.py:62`) iterates middle lengths $d \in \{0, \dots, m - n\}$. The test suite size scales as $\Theta(n \cdot |W| \cdot |\Sigma|^{m - n + 1})$.
     - **Fujiwara's partial $W$-method (`WpMethodEqOracle.py:11-134`):** Splits testing into two stages while keeping the **exact same completeness guarantee** for all implementations with $\le m$ states:
       - First stage (`first_phase_it`, lines 30–46): State identification $Q \cdot \Sigma^{\le m - n} \cdot W$ (uses state cover $Q$ of size $n$ instead of transition cover $P$ of size $n \cdot |\Sigma|$);
       - Second stage (`second_phase_it`, lines 49–70): Transition verification $(P \setminus Q) \cdot \Sigma^{\le m - n} \cdot W_{\delta(q_0, t \cdot \text{mid})}$, where each reached state $q$ is checked only against its *local* state characterization set $W_q$ (`state_characterization_set`, lines 11–27) rather than the full global set $W$.
     - **Probabilistic / PAC oracles (`PacOracle.py:9-67`, `RandomWpMethodEqOracle.py:137-209`):** Drop the worst-case state bound $m$ in exchange for a statistical generalization bound: `PacOracle` issues $\lceil \frac{1}{\varepsilon}(\ln(1/\delta) + r \ln 2) \rceil$ random walks of length in `[min_walk_len, max_walk_len]` in round $r$ (`PacOracle.py:45`), guaranteeing error probability $\le \varepsilon$ with confidence $1 - \delta$ **under the uniform walk distribution**, which provides **zero** guarantee against sparse adversarial triggers of probability $\ll \varepsilon$.

### 3. Equivalent/Redundant Mutants and Trivial Compiler Equivalence (`Mull`, `universalmutator`, `TCE`)

**Basis:** normative literature (Papadakis et al., ICSE 2015 DOI `10.1109/ICSE.2015.103`; Denisov & Pankevich, ICSTW 2018 DOI `10.1109/ICSTW.2018.00024`) + source (`mull-project/mull@4b53263e8880ae9f14a8abcf7effe4effcbb799d`, `lib/` and `rust/`; `agroce/universalmutator@fec4223b30f9e26b9e0497d43375fbd5c1ecd5bf`, `universalmutator/`) + execution (real upstream `universalmutator` + `gcc 15.2.0` + `rustc 1.98.0-nightly`).

1. **Published Large-Scale TCE Baseline (Papadakis et al., ICSE 2015, DOI `10.1109/ICSE.2015.103`):**
   - **Trivial Compiler Equivalence (`TCE`)** compiles the original program $P$ and each mutant $M_i$ with aggressive compiler optimizations (e.g., `gcc -O3` / `clang -O3`) and compares object/machine code (`.text` / `objdump` disassembly):
     - If $\mathrm{Compile}(M_i) = \mathrm{Compile}(P)$, then $M_i$ is **provably semantically equivalent** (modulo compiler soundness) and discarded before test execution;
     - If $\mathrm{Compile}(M_i) = \mathrm{Compile}(M_j)$ ($i < j$), then $M_j$ is a **provably redundant duplicate mutant** and collapsed.
   - Across large real-world C benchmarks in ICSE 2015, TCE automatically eliminated **~7% (avg. 7.4%)** of all generated mutants as equivalent and an additional **~21%** as duplicates (**~28%–30% combined**). Crucially, against human-verified ground truth, TCE detected **~30% of all true equivalent mutants**—leaving **~70% of true equivalent mutants undetected** by compiler comparison!

2. **Direct Source Audit of `mull-project/mull@4b53263e8880ae9f14a8abcf7effe4effcbb799d` (v0.39.1):**
   - Mull (`lib/`: 37 C++ files, 3,774 LoC; `rust/`: 45 Rust files, 7,898 LoC) operates on LLVM bitcode (`lib/Driver.cpp:95-180`, supporting LLVM 16–23 per `docs/HowMullWorks.rst:88`; LLVM JIT was removed in Jan 2021, lines 131–138).
   - **Single-binary runtime-flag injection prevents in-pipeline TCE:** Mull clones mutated functions and guards each mutation point behind a runtime toggle inside one compiled executable (`docs/HowMullWorks.rst:23-28`, `lib/MutationPoint.cpp:158-213`), running each mutant in a forked child subprocess. Because the toggle is dynamic at runtime, LLVM cannot fold an equivalent mutant into the original function during compilation.
   - **Junk detection $\neq$ equivalent-mutant detection:** Mull filters two completely different classes of noise:
     - `CXXJunkDetector` (`lib/JunkDetection/CXX/CXXJunkDetector.cpp:23-250`) parses source files with Clang's AST (`ASTStorage`) to discard **junk mutations**—LLVM IR artifacts (such as `llvm.lifetime.end` intrinsics, pointer-minus-pointer `sub` to `add` at lines 197–201, or compiler-synthesized temporaries) that do not correspond to any valid source-level operator.
     - The Rust `FilterChain` (`rust/mull-filters/src/filter_chain.rs:72-212`) chains `CoverageFilter`, `GitDiffFilter`, `MutationRangesFilter`, `FilePathFilter`, and `ManualFilter` (`mull-off`/`mull-on`/`mull-ignore` comments).
     - **Verified absence of TCE:** Neither `lib/` nor `rust/mull-filters/` implements TCE equivalence/duplicate elimination. Mull's own `docs/archive/EquivalentMutations.md` catalogs common surviving equivalents (`assert` removal, fast/slow performance branches, `std::vector::reserve`, `free`/`close` removal, and `if (a == b) ... else if (a > b)` mutated to `>=`) as open problems requiring manual filters or custom tests.

3. **Direct Source Audit of `agroce/universalmutator@fec4223b30f9e26b9e0497d43375fbd5c1ecd5bf` (v1.14.1):**
   - `universalmutator` (`2,548` Python LoC + `1,194` LoC across 22 `.rules` files) generates source mutants via regex (`mutator.py:148-299`) or Comby (`mutants_comby`, `mutator.py:88-146`), and delegates validity + redundancy checks to per-language `*_handler.py` modules (`genmutants.py:245-260`).
   - **Critical handler asymmetry discovered in source:**
     - `c_handler.py:1-4` and `cpp_handler.py:1-4` are **no-op stubs** (`dumb = True; def handler(...): return "VALID"`): out of the box, `universalmutator` performs **zero** compilation or TCE filtering for C/C++ unless the user supplies a custom `--cmd` or handler!
     - `rust_handler.py:6-28` DOES implement hash-based binary deduplication (`uniqueMutants[code]`, returning `"REDUNDANT"`), **but invokes unoptimized `rustc tmpMutantName` with zero optimization flags (`-C opt-level=0`)** and hashes the entire raw ELF binary bytes (including debug/panic metadata) rather than normalized `.text` machine code.

Four sharp empirical findings emerge directly from these executions:

1. **Optimization level drives a 2.6× TCE jump in Rust and 1.6× in C:** Enabling `-C opt-level=2`/`3` in Rust increases TCE elimination from **13.1% to 34.3%** (**2.62×** over `universalmutator/rust_handler.py`'s default `-C opt-level=0`), and in C from **22.7% to 35.8%**. `-O3` added zero detections over `-O2` on this suite.
2. **Rust TCE has a critical codegen-unit / symbol-visibility footgun:** When compiling a Rust library crate with `--crate-type=lib --emit=obj -C opt-level=2` *without* `-C codegen-units=1` and `#[unsafe(no_mangle)] pub extern "C"` (or inspecting all CGU object files), `rustc`'s default CGU splitting / empty-object emission caused `objdump -d` to report identical empty sections for **206/206 (100%)** mutants—a catastrophic false-equivalence trap if TCE scripts hash a single `--emit=obj` file naively! Forcing `-C codegen-units=1 -C panic=abort` and asserting non-empty disassembly (`96–98` instructions at `-O2/-O3`) eliminated the trap completely.
3. **Compiler-differential TCE catches complementary equivalents:** Both GCC `-O3` and Rustc/LLVM `-C opt-level=3` caught Mull's `else if (level > curr)` $\to$ `>=`, `while (x != 0)` $\to$ `x > 0` on unsigned `x`, and `if (cap == 0)` $\to$ `cap <= 0`. However, LLVM `-C opt-level=3` caught all 4 trailing `continue;` loop mutants that GCC 15.2.0 `-O3` missed due to jump-block ordering, whereas GCC 15.2.0 `-O3` proved that C `if (cap == 0) return 0;` $\to$ `if (0==1)` and `/*return 0;*/` are completely equivalent (`next = idx + 1; if (next >= 0) next = 0;` always returns `0` for `size_t`)—a proof Rustc/LLVM did not perform!
4. **Over HALF of surviving mutants after `-O3` TCE remain genuine semantic equivalents:** Running our 23-assertion C test suite against all 269 non-TCE(-O3)-equivalent compilable C mutants yielded **206 killed**, **36 timeouts** (infinite loops), and **23 survivors**. Exhaustive manual classification of all 23 survivors separates them cleanly into:
   - **12 genuine TCE-escaping semantically equivalent mutants (52.2% of survivors):**
     1. *Loop-invariant condition:* `while (lo < hi)` $\to$ `while (lo != hi)` (`m_38`, invariant `lo <= hi` preserved by `mid` updates; GCC emits `jne` instead of `jb`);
     2. *Algorithmic convergence-rate change:* `lo + (hi - lo) / 2` $\to$ `/ (2+1)` (`m_60`, trisection search) and `/ -1` (`m_59`, unsigned division by `SIZE_MAX` yields `0`, turning binary search into linear scan for $n < 2^{64}-1$);
     3. *Memory-reload boundary guard:* `} else if (arr[mid] < target)` $\to$ `<=` (`m_81`, preceded by `if (arr[mid] == target) return mid;`, missed by GCC due to array reload unlike register-resident `classify_level`);
     4. *Algorithmic fast/slow path equivalence:* `if (use_fast)` $\to$ `if (!use_fast)`, `if (0==1)`, `if (1==1)` (`m_205`, `m_206`, `m_207`: SWAR bit-twiddling popcount vs. `while (x != 0)` loop);
     5. *Post-`return` syntax collapse:* `} else {` $\to$ `/*} else {*/` (`m_355`, `if` branch unconditionally returns);
     6. *Commutativity across ABI registers:* `sat_add_u32(uint32_t a, uint32_t b)` $\to$ `(b, a)` (`m_517`, saturating add is commutative, but swaps `%edi`/`%esi` instructions);
     7. *CFG-layout noise:* 3 trailing `continue;` mutants (`m_100`, `m_107`, `m_416`, plus 1 `-O3` duplicate `m_110`).
   - **11 genuine test-suite gaps / UB artifacts (47.8% of survivors):** `lo = mid + 2` (`m_97`), 3 SWAR mask nibbles (`0x1F0F0F0FU`/`0x0F1F0F0FU`/`0x0F0F1F0FU` on `m_315`–`m_317`, only failing on inputs with odd high-nibbles in bytes 1–3), `/*return c;*/` (`m_422`, C UB leaving `c` in `%eax`), `cap == 1`/`-1` variants (`m_436`–`m_439`, note `cap == 1` is actually equivalent on non-overflowing `idx` while `cap == SIZE_MAX` is a test gap), and `if (s < a)` $\to$ `<=` (`m_533`, fails on `sat_add_u32(10, 0)`).

### 5. Human Comprehensibility (C1) and Conceptual Simplicity / Model Refinement (C2)

**Basis:** source + derived analysis applying Felleisen macro-expressibility and Ousterhout deep-module criteria.

- **(C1) Human Comprehensibility & Mental-Model Ergonomics:**
  - **Four-valued diagnostics vs. false-alarm fatigue (`IKOS` / `LCL`):** IKOS's explicit separation of `Ok`, `Warning`, `Error`, and `Unreachable` prevents conflating conservative incompleteness with proven bugs. However, without local completeness feedback showing *which* join, widening, or non-relational projection dropped precision (e.g., `Interval` losing $2\mathbb{Z}+0$ stride or `IntervalCongruence` losing $x = y$), engineers face opaque `Warning` walls and cannot tell whether to tighten code invariants, switch domains (`interval` $\to$ `gauge-interval-congruence` $\to$ `var-pack-apron-octagon`), or add a runtime check.
  - **Silent vacuity traps in black-box oracles (`AALpy`):** Humans routinely treat `WpMethodEqOracle(max_number_of_states=m)` as "complete testing," forgetting both that $m$ is an unverified axiom (evaded cleanly by our 6-state lock at $m=5$) and that `len(hypothesis.states) > m` silently runs **zero tests** (`WMethodEqOracle.py:62`, `WpMethodEqOracle.py:109`) rather than raising a `ValueError`.
  - **Mutation score illusions (`Mull` / `universalmutator`):** Raw mutation scores ($1 - \text{survived}/\text{total}$) severely mislead humans when equivalent and duplicate mutants are unpruned: on our C benchmark, raw survival rate on 282 compilable mutants is $(13 + 23)/282 = 12.8\%$, dropping to $23/269 = 8.6\%$ after GCC `-O3` TCE, while the **true non-equivalent test-gap rate** is only $11/257 = 4.3\%$—a **3× distortion**! Equally misleading is Mull's omission of TCE (forcing users to maintain `mull-ignore` comments by hand) and `universalmutator`'s silent no-op `c_handler.py`/`cpp_handler.py`.

- **(C2) Simplicity, Orthogonality & Universal Model Refinement:**
  - **One unified conceptual axis underlies all three domains:** Every verification/testing mechanism trades off **(i) Soundness over unseen behaviors** against **(ii) Completeness / zero false alarms** via an **explicit scope anchor**:
    1. In abstract interpretation (`IKOS` + `LCL`), the anchor is the **precondition + abstract domain** $(p, \mathcal{A})$ satisfying $\mathbb{C}_{\mathcal{A}}(f, p)$—replacing impossible global completeness with checkable local completeness.
    2. In black-box conformance testing (`AALpy`), the anchor is the **state-count hypothesis $m$** (or distribution $(\varepsilon, \delta)$ in `PacOracle`)—making the exact condition separating Gold's impossibility from Chow/Fujiwara completeness explicit rather than implicit.
    3. In mutation-based specification/test adequacy (`Mull` + `universalmutator` + `TCE`), the anchor is the **equivalence filter + survival triage budget** (IR/AST junk filter $\to$ multi-compiler `-O2`/`-O3` TCE deduplication $\to$ bounded manual/SMT equivalence audit)—replacing impossible "0% survivor" hard gates with honest, TCE-normalized mutation scores.
  - **Ousterhout deep-module test:** Trying to bolt TCE onto Mull's *single-binary runtime-flagged* architecture is awkward because runtime flags block compiler optimizations; conversely, compiling every mutant as a standalone object file (`universalmutator`) makes TCE trivial ($O(1)$ `.text` hash comparison) at the cost of higher compilation latency (L3). The cleanest orthogonal design decouples **LLVM IR mutant generation + Clang AST junk filtering** (Mull's strength) from **per-function LLVM `opt -O2` IR-level TCE deduplication** *before* injecting the surviving non-equivalent, non-duplicate mutants into the single test binary—capturing both Mull's fast single-binary execution and TCE's 30%–36% mutant reduction without shifting complexity onto users.

### 6. End-to-End Solution and Implementation Validation (V1–V4)

**Basis:** source (`ikos/core/test/`, `aalpy/tests/`, `mull/tests/`, `universalmutator/`) + execution + literature.

- **(V1) Specification Adequacy, Mutation & Non-Vacuity Validation:**
  - Mutation testing (`Mull`, `universalmutator`) IS a primary V1 tool for validating test and specification adequacy—provided it is gated with **TCE deduplication + calibrated survival thresholds + equivalence triage**, NEVER a naive 100% kill gate!
  - In `LCL`, non-vacuity is built directly into the under-approximation half ($q \subseteq \mathrm{post}\llbracket c \rrbracket(p)$): a triple with empty $q = \emptyset$ immediately exposes an unreachable/vacuous path rather than silently certifying `Ok` via `False => Q`.
  - In `AALpy`, validating an equivalence oracle requires paired positive/negative benchmark automata including deliberate $(m+1)$-state evasion locks and checking `oracle.num_queries > 0` (to catch the `n > m` zero-query silent pass).
- **(V2) Analyzer, Oracle & Compiler Soundness Fuzzing:**
  - `IKOS`'s own `core/include/ikos/core/domain/numeric/octagon.hpp:76-78` warning (*"segfaults, unsoundness, etc."*) illustrates why abstract domain implementations themselves require differential testing against concrete randomized execution (sampling concrete states $s \in \gamma(a)$ and asserting $f(s) \in \gamma(f^\sharp(a))$) and cross-domain differential fuzzing (`Interval` vs. `DBM` vs. `ApronOctagon` vs. `ApronPolkaPolyhedra`).
  - Compiler-based TCE relies on compiler soundness: if a compiler miscompiles a mutant via aggressive UB exploitation (like our C `m_422` `/*return c;*/` survivor), TCE can misclassify a UB mutant; cross-checking TCE with `-fsanitize=undefined` or multi-compiler differential TCE (GCC + Clang/LLVM) catches both UB artifacts and compiler-specific blind spots (`continue;` vs. `cap == 0`).
- **(V3) Concurrency, Nondeterminism & Stateful Real-System Validation:**
  - Classical `W`/`Wp`-method completeness assumes **determinism and a reliable reset** (`WMethodEqOracle.py:65`, `WpMethodEqOracle.py:120`). Real concurrent, stateful, or embedded systems violate both assumptions (nondeterministic schedulers, persistent flash/crash state, resetless protocols)—which is why `AALpy` includes separate `non_deterministic/` (`OnfsmLstar.py`), `resetless/` (`hW.py`), and `stochastic/` (`StochasticLStar.py`) learners with substantially weaker completeness guarantees.
- **(V4) Telemetry Replay, Hybrid Falsification & Human Mental-Model Validation:**
  - When $m$ is unknown or $|\Sigma|^{m-n+1}$ is intractable, combining `RandomWpMethodEqOracle` / `KWayTransitionCoverageEqOracle` (`aalpy/oracles/`) with **production telemetry replay** (`ProvidedSequencesOracleWrapper.py`, `CacheBasedEqOracle.py`) grounds equivalence checking in real field workloads rather than uniform random walks (`PacOracle`).
  - For static analyzers (`IKOS`) and mutation gates (`Mull`), empirical tracking of human triage time per `Warning` or surviving mutant directly measures whether domain refinement (`Interval` $\to$ `GaugeIntervalCongruence` $\to$ `LCL`) and TCE filtering genuinely reduce developer false-positive burden.

## Boundaries

- **`NASA-SW-VnV/ikos` C++ binary was not built or run on large C suites (`not examined`):** All `IKOS` findings are grounded in direct source inspection of `NASA-SW-VnV/ikos@ac7f7c1738976cabc58c6a53413df6e458995c38` (`core/` and `analyzer/`) plus our explicitly labeled Python toy model of `IntervalCongruence::reduce()` and `LCL`. Concrete `IKOS` runtime/RSS benchmarks on flight software or Juliet C/C++ suites were not re-executed here.
- **IKOS does NOT implement Local Completeness Logic (`LCL`) natively (`unsupported`):** `NASA-SW-VnV/ikos@ac7f7c1738976cabc58c6a53413df6e458995c38` is a classical over-approximating abstract interpreter (producing `Ok` / `Warning` / `Error` / `Unreachable` verdicts); it does not emit `LCL` under-approximating completeness witnesses or local-completeness proofs.
- **`AALpy` `W`/`Wp` completeness does NOT apply to nondeterministic, resetless, timed, or unbounded-register systems (`known not to apply`):** Both `WMethodEqOracle` and `WpMethodEqOracle` assume deterministic finite-state machines with reliable reset and a known state upper bound $m \ge n$. Moreover, as confirmed by direct execution, both silently execute 0 queries when `len(hypothesis.states) > m`.
- **`Mull` v0.39.1 (`4b53263e8880ae9f14a8abcf7effe4effcbb799d`) was audited at source level, not executed as a compiled LLVM plugin (`not examined`):** Because `clang` and LLVM 16–23 dev libraries are not installed on this host, live execution measurements used upstream `universalmutator@fec4223b30f9e26b9e0497d43375fbd5c1ecd5bf` + `gcc 15.2.0` + `rustc 1.98.0-nightly`. Mull's architectural lack of TCE and reliance on `CXXJunkDetector` + Rust `FilterChain` are established directly from source (`Driver.cpp`, `MutationPoint.cpp`, `CXXJunkDetector.cpp`, `filter_chain.rs`).
- **TCE cannot guarantee detection of arbitrary semantic equivalents (`known not to apply`):** Equivalence of Turing-complete programs is undecidable (Rice's theorem). Both Papadakis et al. (ICSE 2015: ~30% recall on true equivalents) and our real GCC 15.2.0 / Rustc 1.98.0-nightly execution (12/23 surviving C mutants still semantically equivalent after `-O3` TCE) establish that TCE is a fast, sound *filter* (subject to compiler soundness and proper CGU/section normalization), never a complete equivalence decider.
- **Rust test execution against surviving Rust mutants (`not examined`):** Our Rust TCE probe measured syntactic generation, compilability (198/575), and `-C opt-level=0/2/3` TCE-equiv/dup rates via normalized `objdump -d` `.text` hashes; full per-mutant Rust test-harness execution was omitted because the C harness already executed and audited all 269 non-TCE-equivalent mutants on the identical 5-function algorithm suite.
