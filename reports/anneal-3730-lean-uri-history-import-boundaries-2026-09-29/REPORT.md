# Lean URI, historical query, and imported-model boundaries

## Scope

This is a bounded direct Lean/Lake component experiment for **I033/H01–H02/H04**, **I047/A05–A06**, and **I056/C10**. It uses the cached Lean/Lake 4.30.0-rc2 pin, tiny private projects, fresh batch checks, and sequential LSP sessions. It does not exercise an Anneal generated workspace, Rust editor host, historical-query broker, or proof cache. The [probe](support/probe.py) loads only the class/function definitions from the previously published direct/Lake LSP framing harness in `anneal-3730-lean-launch-refresh-matrix-v4-30-0-rc2`, excluding that harness's unguarded experiment entry point; its SHA-256 is pinned in the [raw result](support/results.json). No published file is changed by this package.

## Observations

| Component cell | Actual result | Boundary |
| --- | --- | --- |
| URI and imports | Direct `lean --server` and `lake serve` each returned `⊢ selected = 7` for an on-disk `file:` URI, nonexistent-file `file:` URI, `anneal:` URI, and `untitled:` URI carrying the same unsaved `import Dep` document. All eight `waitForDiagnostics` calls completed. | The servers ran in a real tiny Lake project with prebuilt `Dep.olean`. This proves acceptance for these literal URIs in this launch/context, not generic scheme, editor, or build support. |
| `setup-file` | `lake setup-file Shell.lean` returned 0 with import artifacts; `lake setup-file Absent.lean` failed with a missing-file error, though the LSP had accepted the unsaved absent-file URI. | A virtual buffer working for LSP does not itself supply a physical file for this Lake operation. No custom-scheme setup command was supported or claimed. |
| Rapid edit/history | The live URI went through versions 1→2→3, and a latest query returned `⊢ 3 = 3`. An independently open revision-1 URI still returned `⊢ 1 = 1`; after `didClose` its query returned LSP `-32801` (closed file). Reopening the old text on the same URI, and opening it in a fresh server, both restored `⊢ 1 = 1`. This run measured 0.4 ms for the resident old goal, 600.8 ms for reopen plus wait/goal, and 624.1 ms for fresh server start plus wait/goal. | Separate open documents can retain distinct states, while old text can be recomputed. These one-run timings include different operations and are not a performance comparison. This is not an exact historical query on a single URI, retention policy, expiry implementation, or measured storage cost. RSS tree snapshots include process/runtime noise and cannot be attributed to one retained revision. |
| Proof-body and statement | Fresh `lean --json` checks for two proofs succeeded at baseline. Changing only one proof body from `rfl` to `decide` kept both checks successful and imported OLean hashes unchanged; changing its proposition from `helper = 7` to `helper = 8` made only that proof fail. | One tiny definitional equality, no Anneal dependency graph or output cache. |
| Helper and model | Rebuilding `Helper.olean` after its definition changed made both old obligations fail; `Model.olean` stayed byte-identical. Changing `model` from 7 to 8 and rebuilding changed both imported OLeans and made both old obligations fail. Updating both obligations to 8 restored successful fresh checks. | This establishes an invalidation control for this two-module graph. It does not identify the smallest safe incremental invalidation algorithm or test an already-running imported environment. |
| Eight-proof fanout | Eight distinct fresh `lean --json` proof files importing the same `Helper` all exited 0 under model 8. Rebuilding the imported graph after changing `model` to 7 made all eight stale obligations fail with `rfl` errors; changing each proposition to 7 made all eight pass again without another model build. | This is an eight-file lower bound, not a representative Anneal many-proof workload or concurrency measurement. |

The [raw record](support/results.json) retains request replies, diagnostics, source and OLean hashes, command arguments, exit codes, stdout/stderr, elapsed times, and two RSS tree snapshots. The retained [work tree](support/work) contains the exact tiny Lean and Lake source fixtures; generated C/OLean products were removed after their hashes were recorded. The [checker](support/check.py) validates the decisive positive and negative outcomes without launching tools. Run `python3 support/probe.py` to recreate the bounded fixture, then `python3 support/check.py` from this package. The probe deletes and recreates only its own `support/work` directory, requires at least 25% reported free memory, and uses one Lean process at a time. The recorded preflight was 50% free.

H03/H04 also need real hidden-document authority and lifecycle; C10 needs representative many-proof scaling. These rows and suggestions remain partial.
