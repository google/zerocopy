Key upstream invariants uncovered and mechanized:

1. **Why `205` cleanup bodies survive `-C panic=abort` (`abort_unwinding_calls.rs:33-37`):** `AbortUnwindingCalls::run_pass` exits immediately on `if !kind.is_fn_like() { return; }` to avoid a `tcx.type_of` query cycle on `const`/`static` MIR bodies. Across `zerocopy`, **`0 / 4,460` `fn`-like bodies** retain cleanup pads after `AbortUnwindingCalls` under `-C panic=abort`; all `205` surviving cleanup bodies are layout/size `const` items.
2. **Soundness of `AbortUnwindingCalls` under mutual recursion (`checkNoUnwindSummary`):** Because `dispatchUnwindStack` can only be entered from an active `.unwindResume` or a failing `.assert` with `.continue_`/`.cleanup`, an inductive boolean assignment `noUnwindFlags` where every flagged body contains zero `.unwindResume` terminators and every `.call`/`.assert` in a flagged body either cannot fail/calls a flagged body or carries `.terminate`/`.unreachable` is **coinductively/inductively closed across arbitrary call depth and mutual recursion** (`abortUnwindingCalls_sound_slice2`).
3. **`hasStorageAnnotation` hazard in `super::simplify::remove_dead_blocks(body)` (`abort_unwinding_calls.rs:140`, `CE5`):** In `Trusted.MirSemantics.initLocalsLoop`, locals without any `StorageLive`/`StorageDead` statement anywhere in `body.basicBlocks` start `.live` at function entry, whereas annotated locals start `.dead`. If an unreachable cleanup pad holds the *sole* `StorageDead(_k)` for local `_k`, deleting that dead cleanup block flips `hasStorageAnnotation body _k` from `true` to `false`, silently erasing `DeadLocal` UB in the surviving normal path (`CE5`). `checkPruneDeadCleanupBlocks` explicitly guards `allLocalsStorageAnnotEq` so dead-pad pruning is 100% UB-preserving.
4. **Unwind-aware `MIR Inline` across all 4 `callerUnwind` actions & mutual recursion (`Slice3c_InlineStep`):** Splicing a non-self-recursive callee `calleeDefId ≠ callerDefId` with internal cleanup pads and `.unwindResume` into `caller` requires routing every callee `.unwindResume` and `.continue_` action to a shared `unwindExitBlock` that executes `StorageDead` on all shifted callee locals (`locOff .. locOff + callee.locals.length - 1`) before dispatching `callerUnwind` (with `.terminate` encoded in unmodified `Trusted.MirAst` via a constant-failing `.assert false == true -> .terminate`, since `Trusted.MirAst.TerminatorKind` has no standalone `TerminatorKind.unwindTerminate` constructor). Furthermore, if the inlined callee calls back into `caller` (mutual recursion `caller -> callee -> caller`), the suspended fused pair `eCont :: cCont` on the source `callStack` corresponds to a *single* fused continuation frame on the target `callStack` (`InlStackRel.consFused`), proved via multi-step forward stuttering bisimulation (`fullSemanticEquivUnw_of_fwd_stutter_sim`) with zero `Classical.choice`.

## Boundaries

1. **Base-fragment `cleanup = false` guard (`isBaseMirBody`).** In unmodified `Trusted.MirSemantics.evalTerminator`, `.return_` does not inspect `bb.cleanup`, whereas `M_unwind` enforces `lean-miri` `ControlFlow.lean:74` (`if bb.cleanup then .fault .unsupported` on `.return_`, `CE1`). Accordingly, `isBaseMirBody` requires `cleanup = false` on `.return_` blocks in base programs (which holds on all well-formed `rustc` MIR) so `unwind_conservative_extension_exact` holds with zero behavioral discrepancy.
2. **Unmodeled `TerminatorKind::Drop` & `UnwindTerminate` AST encoding (`mirProfileVersion = 1`).** Inheriting unmodified `Trusted.MirAst`, `TerminatorKind::Drop` and standalone `TerminatorKind::UnwindTerminate` remain `.unsupported` in `MirAst`: `mkTerminateTerm` encodes standalone abort blocks (`abort_unwinding_calls.rs:83` and `unwindExitBlock` under `callerUnwind = .terminate`) as `.assert (.constant ⟨.bool, .scalar 0⟩) true .unsupported 0 .terminate` (stepping deterministically in 1 transition to `.done (.aborted callerMem)`), and cleanup pads execute over Anneal's scalar/boolean/unit/fieldless-enum value domain (`callerMem = ⟨[]⟩`) without heap deallocation.
3. **Direct static `FnDef` calls & unprojected call operands/destinations.** `TerminatorKind.call` models direct `DefId` calls within `p.bodies` (no indirect `FnPtr`, `dyn Trait`, `TailCall`, foreign `extern "C-unwind"` bodies outside `p.bodies`, or intrinsics), with unprojected `dst` (`dst.projection.isEmpty`) and supported scalar/unit/fieldless-enum arguments (`isSupportedScalarOrUnitTy`).
4. **Call-destination validation timing (`returnToCallerUnw` vs. call entry).** `M_unwind` validates call arguments and callee frame initialization at `.call` entry while checking `!cont.dst.projection.isEmpty`, `callerBody.locals[cont.dst.localId]`, and `writePlace` (`checkVal` + `dst` liveness) upon normal return in `returnToCallerUnw` (so an unwinding or diverging call does not fault at call entry on an invalid `dst`, whereas `checkInlineWithUnwind` enforces `callDstCompatible` statically).
5. **Open-library root unwinding (`.unwound`) vs. CTFE/Miri root UB (`ControlFlow.lean:76`).** Unwinding out of `callStack = []` yields `.done (.unwound callerMem)` (matching `Trusted.MirSemantics.TerminalOut.unwound` for open library entry functions) rather than CTFE/Miri whole-program root UB; panic-freedom or `-C panic=abort` entry behavior is enforced via `SatisfiesPostUnw` or `checkPanicAbortEntryTransform`.
6. **Direct `UnwindAction` dispatch on failing `TerminatorKind.assert`.** `evalTerminatorUnw` evaluates every `TerminatorKind.assert` in `Runtime(PostCleanup)` MIR (`ignoreOptionalOverflowChecks = false`) and dispatches `unwind : UnwindAction` directly without executing `core::panicking::panic_fmt` formatting frames or stateful `std::panic` hooks.
7. **`AbortUnwindingCalls` factoring (`checkAbortUnwindingCalls` vs. `checkPanicAbortEntryTransform`).** `VrustcFormal.F1_13` splits `abort_unwinding_calls.rs` into (a) self-certifying MIR-level `checkNoUnwindSummary` tightening (`checkAbortUnwindingCalls`, requiring an inductive MIR proof of non-unwinding rather than external ABI/attribute flags, preserving exact `↔` equivalence) and (b) non-recursive entry-body outer ABI enforcement (`checkPanicAbortEntryTransform`, requiring `!pSrc.bodies.any (bodyCallsDefId pSrc.entryDefId)` and refining top-level `.unwound` to `.aborted` after entry `.cleanup` pads rather than aborting inside interior Rust `Assert` panics before caller cleanup pads or rewriting interior non-entry `extern "C"` bodies).
8. **Dead-block pruning `hasStorageAnnotation` guard (`CE5`).** Unlike unguarded `remove_dead_blocks` (`abort_unwinding_calls.rs:140`), `checkPruneDeadCleanupBlocks` requires `allLocalsStorageAnnotEq` (and retention of `bb0`) so dropping an unreachable cleanup pad that holds the sole `StorageLive`/`StorageDead` marker for a local cannot flip `hasStorageAnnotation` and erase `DeadLocal` UB in backward VC transport (`←`).
9. **Single-site non-recursive inlining (`checkInlineWithUnwind`) & all-body `isBaseMirProgram pFlat` in Theorems 5–6.** Each `UnwindOptStep.inlineWithUnwind` inlines one non-self-recursive call site (`callerDefId ≠ calleeDefId`) in a `cleanup = false` block (while supporting arbitrary runtime recursion and mutual recursion `caller -> callee -> caller` via `InlStackRel.consFused`; recursive call cycles cannot be completely eliminated by a finite `UnwindOptTrace`). Because `UnwindOptStep` preserves `p.bodies.length` (no dead-body pruning pass), `isBaseMirProgram pFlat = true` in Theorems 5–6 requires every body in `pFlat.bodies` (including helper callees) to have zero remaining `.call`/`.assert`/`.unwindResume` terminators, and Theorem 5 requires `SpecsPropertyUnwInvariant specs`.
