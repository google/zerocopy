# Production Rust FFI and Inline-Assembly Workloads and Adversarial Verification Bypass Taxonomy

## Summary

Verifying real-world Rust systems that cross inline-assembly (`asm!`, `naked_asm!`, `global_asm!`), external `.S`/`.asm`, and C/C++ FFI boundaries requires matching two distinct realities: (1) **how production ecosystems actually structure low-level boundaries**, and (2) **how an adversarial contributor or reward-hacking AI agent can subvert a verifier** when implementation bodies, proofs, assembly templates, and build scripts are untrusted under a bounded human-review threat model (`joshlf/anneal@c131b320eeeb26ef692e5afd5ec8db49ee518613`, `THREAT_MODEL.md`). Direct source inspection across 11 pinned upstream repositories (`16` concrete workload classes across four production ecosystems) paired with `8` standalone executable PoC families (`19` empirically verified attack sub-vectors on `rustc 1.102.0-nightly` + `gcc 15.2.0` + `GNU ld 2.47`) establishes five governing conclusions:

1. **Production assembly is heavily bimodal: tiny compiler/kernel `asm!` vs. massive external `.S`/`.asm` and C-inline-helper wrappers.** Across the four examined ecosystems, Rust-native `asm!` is concentrated in **compiler/runtime-patching primitives** (Linux Rust-for-Linux `asm_goto` static keys via `.pushsection __jump_table`, `WARN` metadata via `.pushsection __bug_table`, empty `asm!("")` compiler barriers, `zeroize` `readonly` DSE barriers, and `rustc_codegen_llvm`'s `core::hint::black_box` empty `"r,~{memory}"` inline asm). By contrast, high-throughput cryptographic kernels (`briansmith/ring`, `aws/aws-lc-rs` Perlasm + ML-KEM), OS context-switch trampolines and faulting usercopy (`fuchsia` Starnix `trampoline_x64.S`, `extended_pstate`, `usercopy`), and Linux `_ASM_EXTABLE` / `ALTERNATIVE` / LKMM atomic helpers (`70` `.c` files in `torvalds/linux/rust/helpers/`) cross `extern "C"` boundaries into external `.S`/`.asm` or `__always_inline` C objects.
2. **Real FFI boundaries routinely break naive Rust uniqueness, unwind, and allocator models.** Production bindings explicitly work around Rust aliasing and lifetime constraints: `flate2-rs` (`src/ffi/c.rs:36-40`) intentionally stores `*mut mz_stream` instead of `Box<mz_stream>` because C's `mz_internal_state` holds a cyclic back-pointer violating `&mut`/`Box` uniqueness; `ring` passes identical overlapping `*const u8`/`*mut u8` pointers into in-place VAES AES-GCM assembly (`vaesclmulavx2.rs:52`); Starnix passes non-`#[repr(C)]` `*mut RestrictedEnterContext<'_>` (`#[allow(improper_ctypes)]`) through Zircon's non-call `restricted_return_loop` vector entry and synthesizes 16 `.cfi_offset` directives from `zx_restricted_state_t` (`trampoline_x64.S:108-128`); and `rust-openssl` tunnels Rust panics out of C `BIO` callbacks via `bio::take_panic` -> `resume_unwind` (`ssl/mod.rs:3982,4006-4010`) rather than unwinding across C frames.
3. **Source-level assembly text inspection is structurally bypassable.** In `support/run_adversarial_pocs.py`, an uncalled `asm!` block claiming `options(pure, nomem, nostack, preserves_flags)` injected a constructor into ELF `.init_array` that mutated global state **before `main()`** (`pwned_before_main=0xdeadbeef`, PoC 1); a GAS `.macro nop` directive inside `global_asm!` caused the literal mnemonic `nop` to assemble into `mov $0x1337, %eax`, `.byte` smuggled `mov $0x7777, %eax` with zero mnemonics, and `.set` aliased a verified symbol name to an unverified payload (PoC 2).
4. **Compiler options, linker resolution, hardware flags, and FFI validity/aliasing contracts fail open without binary-bound verification.** `rustc 1.102.0-nightly` + `GNU ld 2.47` empirically accepted: (a) a false `options(nomem)` store causing `-C opt-level=3` to read stale `111` while memory held `999` (PoC 3); (b) unguarded `#[target_feature(enable = "avx512f")]` calls emitting `vpbroadcastd zmm0` with zero CPUID check (PoC 3); (c) untyped `#[link_name]` arity mismatches, weak-symbol overrides, **strong archive-order shadowing** (`-l static=shadow -l static=verified` silently overriding a strong `.a` member with zero linker error), and `LD_PRELOAD` interposition (PoC 4); (d) `build.rs` verify-vs-release artifact divergence (PoC 5); (e) `DF=1` exit clobbers, SysV 128-byte red-zone corruption under false `options(nostack)`, missing `.eh_frame` FDEs, and dirty upper YMM (`XINUSE[2] == 1`) state before `vzeroupper` (PoC 6); (f) invalid `bool` (`2u8`, yielding `!b == 3`), reentrant C callbacks defeating LLVM `noalias`/`writeonly`/`captures(none)` (`protector_rust_saw=10` vs `actual_mem=777`), and `setjmp`/`longjmp` skipping Rust `Drop` (PoC 7); and (g) C-header/`bindgen` constant drift mutating an unedited Rust specification surface (PoC 8).
5. **Defense partition (`24` enumerated bypass vectors): `19` admit total mechanical defense, `4` require hybrid mechanical + TCB-log boundaries, and `1` (`LD_PRELOAD` / dynamic loader integrity) is an irreducible execution-environment assumption.** Any sound verifier operating under bounded human review must bind inline/external assembly and FFI proofs to the **post-assembly, final linked binary symbol/section/unwind tables** (not pre-assembly template strings or isolated `.o` files), verify transitive specification closure across `include!`/`bindgen`/C-header boundaries, and log every unverified foreign symbol, dynamic library, `target_feature` hardware probe, and build-environment boundary explicitly in the TCB audit log.

## Findings

### 1. Production Rust FFI & Inline-Assembly Workloads Across Four Ecosystems

`Basis: source + normative`

Inspection of `11` pinned upstream repositories surfaces `16` distinct production workload classes spanning four systems ecosystems. Each workload is validated mechanically by `support/classify_workloads.py` (generating `support/taxonomy_summary.json`).

#### 1.1 Fuchsia / Zircon / Starnix (`fuchsia.googlesource.com/fuchsia@fd31be1516bd`)

1. **Zircon vDSO Syscall Bindings (`sdk/rust/zx-sys/src/definitions.rs:12-1104`):**
   Generated from FIDL library `zx` by `zither`, `zx-sys` declares **217 `pub fn zx_*`** entry points inside `#[cfg(target_os = "fuchsia")] #[link(name = "zircon")] unsafe extern "C" { ... }` (channels, VMOs, clocks, futexes, BTI pinning, and restricted-mode syscalls `zx_restricted_{bind_state,enter,kick,unbind_state}` at `L598-612`). Unlike Linux `rustix` (which emits inline `syscall`/`svc`/`ecall` instructions directly in userspace), Fuchsia forbids raw syscall instructions in userspace: all syscalls are ordinary `extern "C"` calls resolved dynamically against the kernel-mapped `libzircon.so` vDSO.
2. **Starnix `restricted_enter_loop` Trampoline & Extended Pstate (`src/starnix/kernel/syscall_loop/src/{lib.rs:51-145,trampoline_x64.S:13-160}`, `src/starnix/lib/extended_pstate/src/x86_64_asm.S:63-68`):**
   Starnix runs unmodified Linux binaries inside Zircon restricted mode via an external `.S` trampoline per architecture (`trampoline_{x64,arm64,riscv64}.S`) declared in Rust with `#[allow(improper_ctypes)]` (`lib.rs:67-73`) because `*mut RestrictedEnterContext<'_>` points to a non-`#[repr(C)]` Rust struct passed opaquely back to Rust (`restricted_exit_callback_c`). On x86-64:
   - `restricted_enter_loop` (`trampoline_x64.S:13-77`) pushes `%rbx, %rbp, %r12-%r15, %rsp`, allocates 32 bytes for 4 saved arguments (`options`, callback context, `zx_restricted_state_t*`, `ExtendedPstatePointer*`), calls `restore_extended_pstate` (`xrstor (%rsi)` with `EAX=7, EDX=0` for x87/SSE/AVX state in `extended_pstate/src/x86_64_asm.S:65-68`), loads `leaq restricted_return_loop(%rip), %rsi` and `%rsp` into `%rdx`, and invokes `call zx_restricted_enter`.
   - On Linux syscall or fault, Zircon does **not** return from `zx_restricted_enter`; instead, the kernel jumps directly to `restricted_return_loop` (`L85-160`) with `%rdi = context (%rsp)` and `%rsi = reason_code`. The assembly restores `%rsp`, calls `save_extended_pstate`, loads the guest's `%rbp` from `0x10(%r14)` (`zx_restricted_state_t`), and emits **16 explicit DWARF unwind directives** (`.cfi_remember_state`, `.cfi_def_cfa r14, 0`, `.cfi_offset rdi, 0x00` through `.cfi_offset rip, 0x80`, `L108-128`) to splice Linux guest backtraces onto Starnix's Rust call stack before `callq restricted_exit_callback_c` and `.cfi_restore_state` (`L144-147`).
3. **Starnix Hermetic Usercopy & Faulting Atomics (`src/starnix/lib/usercopy/src/lib.rs:11-90`):**
   Copies and atomic operations touching untrusted Linux userspace pages (`hermetic_copy`, `hermetic_copy_until_null_byte`, `hermetic_zero`, `atomic_load_u32_{relaxed,acquire}`, `atomic_store_u32_{relaxed,release}`, `atomic_compare_exchange_u32_acq_rel`) live in standalone `.S`/hermetic C++ routines paired with explicit sentinel symbols (`*_end`) and error landing labels (`hermetic_copy_error`, `atomic_error`). When a page fault hits any PC in `[fn, fn_end)`, Starnix's exception handler redirects execution to the error label—a userspace equivalent of Linux's `__ex_table` that breaks normal call/return control-flow graphs.
4. **Fuchsia Driver Runtime C/C++ Arena & Dispatcher FFI (`sdk/lib/driver/runtime/rust/{fdf_sys/src/bindings.rs:87-202,channel/src/arena.rs:24-75}`):**
   Wraps C-ABI `fdf_arena_t` (`fdf_arena_{create,allocate,free,contains,add_ref,drop_ref}`) inside `pub struct Arena(NonNull<fdf_arena_t>)` (`unsafe impl Send + Sync`, `arena.rs:24-28`) alongside asynchronous C++ `fdf_dispatcher_t` shutdown callbacks (`bindings.rs:130-198`), combining reference-counted cross-language heap ownership with reentrant C++→Rust dispatcher callbacks.

#### 1.2 Production Rust Cryptography (`ring`, `aws-lc-rs`, `zeroize`, `subtle`, `core::hint::black_box`)

1. **`briansmith/ring` (`b287c58f1dc2`) — Version-Prefixed Perlasm/Fiat-Crypto `.S` Linkage & Typed CPU Capability Tokens:**
   - `build/build/core.rs:36-75` compiles BoringSSL-derived Perlasm scripts (`.pl` -> `.S`/`.asm` for AES-NI, VAES-GCM, VPAES, GHASH, ChaCha20-Poly1305, SHA-256/512, P-256, Montgomery bignum) plus Fiat-Crypto assembly (`third_party/fiat/asm/fiat_curve25519_adx_{mul,square}.S`) via `cc`, rewriting every symbol with a crate-versioned prefix via `prefixed_extern!` (`src/prefixed.rs:2-54`: `#[link_name = concat!("ring_core_", major, "_", minor, "_", patch, "_", pre, "_", stringify!($name))]`) specifically to defeat linker symbol collisions when multiple versions of `ring` or BoringSSL coexist in one binary.
   - **Elimination of `OPENSSL_ia32cap_P` on x86-64:** Unlike BoringSSL/AWS-LC, `ring@b287c58f1dc2` removed `OPENSSL_ia32cap_P` from Rust/C runtime dispatch (`src/cpu/x86_64.rs:45-58,207-228,288-323`). Rust executes `cpuid_all()` once inside `OnceNonZeroU32` (checking `XCR0[2:1]` for OS AVX state at `L207` and working around Intel Skylake Pentium/Celeron erratum `SKD052` at `L288-300`), writes only two `HIDDEN uint32_t` globals (`avx2_available`, `adx_bmi2_available` in `crypto/crypto.c:28-31`, declared as `AtomicU32` via `prefixed_extern!` with `Relaxed` store synchronized by `OnceNonZeroU32` Acquire/Release), and gates assembly wrappers on zero-sized proof tokens (`cpu::intel::Aes`, `cpu::intel::Avx`, `(Adx, Bmi1, Bmi2)` in `src/aead/aes/hw.rs:110-126`, `src/ec/curve25519/adx.rs:22-45`).
   - **In-place aliasing & uninit outputs:** `seal_whole_vaes_clmul_avx2` (`src/aead/aes_gcm/vaesclmulavx2.rs:30-53`) passes the same buffer as both `input: *const u8` and `output: *mut u8` (`in_out.cast_const(), in_out`) into `aes_gcm_enc_update_vaes_avx2`, while `scalarmult_base` (`src/ec/curve25519/adx.rs:31-44`) passes `&mut MaybeUninit<[[u8; 32]; 4]>` and `&mut MaybeUninit<P3>` directly across FFI before calling `assume_init_ref()` / `assume_init()`.
2. **`aws/aws-lc-rs` (`104142736550`) + `aws/aws-lc` (`cd481c207e38`) — Multi-Builder Perlasm/ML-KEM Linkage & Mutable `OPENSSL_ia32cap_P`:**
   - `aws-lc-sys` (`aws-lc-sys/src/lib.rs:15-74`, `builder/cc_builder.rs:39-43`) compiles AWS-LC's C + Perlasm `.S`/`.asm` (`generated-src/{linux,mac,win,ios}-*`) and post-quantum ML-KEM native AVX2/AArch64 assembly (`aws-lc/crypto/fipsmodule/ml_kem/mlkem_native_backend.h:10-18`, bound in `aws-lc-rs/src/kem.rs:48-103` via `EVP_PKEY_{encapsulate,decapsulate}`) through `CcBuilder`, `CMakeBuilder`, or `NasmBuilder`, switching between pregenerated platform bindings and `OUT_DIR/bindings.rs`.
   - Unlike `ring`, `aws-lc` retains the shared `uint32_t OPENSSL_ia32cap_P[4]` capability array (`crypto/fipsmodule/cpucap/cpu_intel.c:272-302`, referenced across 61 files including Perlasm `x86gas.pl`/`x86nasm.pl`/`x86masm.pl`), which can also be masked at runtime via the `OPENSSL_ia32cap` environment variable (`handle_cpu_env`, `L299-302`).
3. **DSE Erasure vs. Constant-Time Value-Range Opacity Barriers (`zeroize`, `subtle`, `core::hint::black_box`):**
   - *Memory DSE barrier (`zeroize`, `RustCrypto/utils@0feca06cf87e`, `zeroize/src/{barrier.rs:52-89,bulk.rs:6-60}`):* As detailed in `zeroize-volatile-erasure-dse-survival-and-typestate-crypto-handshake-machines`, `zeroize` pairs vectorized `write_bytes` with `asm!("# {}", in(reg) ptr, options(readonly, preserves_flags, nostack))` on 9 `HAS_ASM` architectures so LLVM MemorySSA treats the scrubbed buffer as externally read (falling back to `black_box` under `cfg(miri)`).
   - *Value-range opacity barrier (`subtle@369e7463e859`, `src/lib.rs:99-100,222-244` & `rust-lang/rust@c7d5ba59d8e1`, `compiler/rustc_codegen_llvm/src/intrinsic.rs:52-84,594-603`):* To stop LLVM from inferring that `Choice(u8)` is `{0, 1}` and reintroducing secret-dependent branches, `subtle` defaults to `#[inline(never)] fn black_box<T: Copy>(input: T) -> T { unsafe { core::ptr::read_volatile(&input) } }` (`L222-233`) and optionally uses `core::hint::black_box` (`feature = "core_hint_black_box"`). In `rustc_codegen_llvm/src/intrinsic.rs:52-84`, `Builder::black_box` lowers `sym::black_box` directly into an empty side-effecting LLVM inline assembly call (`crate::asm::inline_asm_call(self, "", "r,~{memory}", &[result.val.llval], ..., sideeffect=true, ...)`, or `"~{memory}"` for ZSTs)—meaning `black_box` itself is an implicit `asm!` boundary at codegen even when Rust source contains zero `asm!` macros!

#### 1.3 Linux Kernel Rust-for-Linux (`torvalds/linux@5f22fb20497f`)

1. **Static Keys via `asm_goto` + C-Preprocessed `.pushsection __jump_table` (`rust/kernel/jump_label.rs:49-63`, `generated_arch_static_branch_asm.rs.S:7`, `arch/x86/include/asm/jump_label.h:15-38`):**
   `arch_static_branch!` invokes `kernel::asm!` (which wraps `core::arch::asm!` with `options(att_syntax)` on x86/x86-64 in `rust/kernel/lib.rs:248-254`), `include!`ing the C-preprocessed expansion of `ARCH_STATIC_BRANCH_ASM("{symb} + {off} + {branch}", "{l_yes}")` paired with Rust `asm_goto`:
   ```rust
   $crate::asm!(
       include!(concat!(env!("OBJTREE"), "/rust/kernel/generated_arch_static_branch_asm.rs"));
       l_yes = label { break 'my_label true; },
       symb = sym $key,
       off = const ::core::mem::offset_of!($keytyp, $field),
       branch = const $crate::jump_label::bool_to_int($branch),
   );
   ```
   On x86, `ARCH_STATIC_BRANCH_ASM` emits a 5-byte NOP (`1: .byte BYTES_NOP5`) plus `.pushsection __jump_table, "aw"` recording `(1b - ., label - ., key - .)`, which the kernel patches **live in `.text`** to `jmp l_yes` when the static key flips.
2. **Trap Metadata Sections (`rust/kernel/bug.rs:34-76`, `generated_arch_warn_asm.rs.S:7`, `arch/x86/include/asm/bug.h:65-75`):**
   `warn_flags!` embeds `ARCH_WARN_ASM` (`UD2`/`UD1` + `.pushsection __bug_table, "aw"` referencing `sym FILE`, `const line!()`, `const FLAGS`, `const size_of::<bug_entry>()`) directly inside Rust functions.
3. **70 C Inline-Helper Wrappers for `__ex_table`, `.altinstructions`, Barriers, and LKMM Atomics (`rust/helpers/{helpers.c:12-111,uaccess.c:5-29,barrier.c:5-48,atomic.c:14-90}`, `rust/kernel/sync/barrier.rs:45-78`):**
   Rather than duplicating architecture-specific C inline assembly macros in Rust, Linux routes exception-table usercopy (`_ASM_EXTABLE_TYPE` emitting `.pushsection __ex_table` in `arch/x86/include/asm/asm.h:185-230`), runtime CPU-feature code patching (`ALTERNATIVE` emitting `.pushsection .altinstructions` + `.altinstr_replacement` in `arch/x86/include/asm/alternative.h:140-170`), hardware memory barriers (`mb`/`rmb`/`wmb`/`smp_mb`/`dma_mb`), and Linux Kernel Memory Model (LKMM) atomics (`atomic.c`, 1,035 lines) through `70` `.c` files aggregated in `rust/helpers/helpers.c`. Notably, `helpers.c:12-39` defines `#define __rust_helper __always_inline` (omitted under `#ifdef __BINDGEN__`) specifically to **force Clang+Rust cross-language LLVM LTO inlining** despite mismatched target-feature strings (`+cmov,+cx8,+fxsr`) and `-fno-delete-null-pointer-checks` attributes! Rust itself emits only `core::arch::asm!("")` for the compiler barrier `barrier()` (`rust/kernel/sync/barrier.rs:51`).
4. **Const `file_operations` Vtable Structs & `void* private_data` Ownership Transfers (`rust/kernel/miscdevice.rs:153-160,234-446`):**
   `MiscdeviceVTable<T>` builds `const VTABLE: bindings::file_operations` populated with `Option<unsafe extern "C" fn(...)>` pointers (`open`, `release`, `mmap`, `read_iter`, `write_iter`, `unlocked_ioctl`, `compat_ioctl`, `show_fdinfo`). In `open` (`L274`), Rust transfers an owned pointer-sized handle into C via `(*raw_file).private_data = ptr.into_foreign()`; intermediate callbacks (`mmap`, `ioctl`, `show_fdinfo`) borrow it via `<T::File as ForeignOwnable>::borrow(private)` (`L350,396,417`); and `release` (`L287`) reclaims ownership via `from_foreign(private)`.

#### 1.4 Mainstream Rust↔C Libraries (`rusqlite`, `flate2-rs`, `zlib-rs`, `rust-openssl`)

1. **`rusqlite` / `libsqlite3-sys` (`388f5d40aab8`) — Opaque Handles, `clientdata` Destructors, `catch_unwind`, and Undocumented Threading Probes:**
   - Wraps opaque `*mut ffi::sqlite3` and `*mut ffi::sqlite3_stmt` with RAII `Drop` (`inner_connection.rs:412-418`).
   - Registers Rust closures as `void*` user data via `set_clientdata` (`inner_connection.rs:344-383`): allocates `Box::into_raw(Box::new(d))`, installs the callback pointer via `preset` *first*, and then calls `sqlite3_set_clientdata(..., Some(crate::util::free_boxed_value::<T>))` so SQLite destroys the previous closure only after no dangling reference remains.
   - `busy_handler_callback` (`busy.rs:59-72`) wraps closure invocation in `std::panic::catch_unwind` to prevent unwinding across C `sqlite3` frames; errors combine integer status codes (`SQLITE_OK` vs non-zero) with handle-scoped `sqlite3_errcode`/`sqlite3_errmsg`/`sqlite3_errstr` (`error.rs:448-473`).
   - `ensure_safe_sqlite_threading_mode` (`inner_connection.rs:428-454`) guards Rust thread safety by probing both `sqlite3_threadsafe()` and an **undocumented** C implementation sentinel (`sqlite3_mutex_alloc(0) as usize == 8`).
2. **`flate2-rs` (`bda759ec690f`) — Cyclic Heap `mz_stream` & Header-Prefixed Rust Allocator Handoff:**
   - `StreamWrapper` (`src/ffi/c.rs:25-70`) explicitly avoids `Box<mz_stream>` in favor of raw `inner: *mut mz_stream` (`Box::into_raw` on init, `Box::from_raw` on `Drop`), documenting (`L36-39`): *"The field `state` will be initialized across the FFI to point to the opaque type `mz_internal_state`, which will contain a copy of `inner`. This cyclic structure breaks the uniqueness invariant of `&mut mz_stream`, so we must use a raw pointer instead of `Box<mz_stream>`."*
   - Custom C allocator callbacks `extern "C" fn zalloc(_ptr, items, item_size)` (`L85-115`) and `zfree` bridge Rust's `Layout`-typed `alloc::alloc`/`dealloc` to C's untyped `zfree(opaque, addr)` by prepending a `usize`-aligned size header before the returned pointer.
3. **`zlib-rs` / `libz-rs-sys` (`f6a2b3f097d0`) — Rust-Implemented C ABI, `malloc(0)` Guards, and `#[target_feature]` Dispatch:**
   - Exports a drop-in `#[repr(C)] pub struct z_stream` (`zlib-rs/src/c_api.rs:64-95`) whose C-allocator bridge (`zlib-rs/src/allocate.rs:16-95`) aligns buffers to 64 bytes via `posix_memalign` and explicitly short-circuits `size == 0` (`L34-39,54-65,82-89`) so non-null dangling `malloc(0)`/`calloc(0)` pointers from libc never reach Rust dereferences.
   - Replaces external `.S` SIMD kernels with pure-Rust `#[target_feature(enable = "avx2")]` (`zlib-rs/src/adler32/avx2.rs:33-35`), `avx512`, `vpclmulqdq`, and `neon` functions dispatched via `cpu_features::is_enabled_*()` (`adler32.rs:19-47`).
4. **`rust-openssl` / `openssl-sys` (`dbc5ecad7dbf`) — `ex_data` Indirection, `OPENSSL_free` Handoffs, `ErrorStack`/`errno`, and BIO Panic Tunneling:**
   - Wraps OpenSSL-allocated strings and objects via `foreign_type_and_impl_send_sync!` freeing with `ffi::OPENSSL_free` / `ffi::CRYPTO_free` (`openssl/src/string.rs:11-17,84-96`)—matching OpenSSL's allocator rather than Rust's global allocator.
   - Resolves TLS callbacks (`raw_verify`, `raw_client_psk` in `openssl/src/ssl/callbacks.rs:42-112`) through typed `ex_data::Index<T, U>` (`ex_data.rs:8-32`) anchored on the *original* `SSL_CTX` (`SESSION_CTX_INDEX`) because OpenSSL copies callback pointers at `SSL_new` and does not update them on SNI `SSL_set_SSL_CTX` swaps.
   - Decodes hybrid error channels (`openssl/src/error.rs:115-195`, `ssl/mod.rs:3981-4015`): pops thread-local `ERR_get_error_all` (copying strings when `ERR_TXT_MALLOCED != 0` and reallocating via `CRYPTO_malloc` on `put()`), falls back to BIO `io::Error` (`errno`) on `ErrorCode::SYSCALL`, and **tunnels Rust panics across C frames** by storing the caught panic payload on the custom `BIO` and re-raising via `bio::take_panic` -> `resume_unwind` (`L4006-4010`) once C returns cleanly.

### 2. Adversarial & Reward-Hacking Bypass Taxonomy Under Bounded Human Review

`Basis: normative + source + execution + derived` (`THREAT_MODEL.md`, `rust-lang/reference@c9cc32825b03`, `support/run_adversarial_pocs.py`, `support/poc_results.json`, `support/classify_workloads.py`)

Under a bounded human-review threat model (`joshlf/anneal@c131b320eeeb26ef692e5afd5ec8db49ee518613`, `THREAT_MODEL.md:66-122`), a human reviewer audits **only** (a) stated specifications (and every definition they transitively depend on) and (b) the TCB audit log. Implementation bodies, inline/external assembly, proofs, and build scripts are treated as potentially authored by a malicious human or a reward-hacking AI agent optimizing to make verification exit `0` without satisfying the intended property. Every bypass vector below is classified into one of three principled defense regimes:
- **Total mechanical defense (`19 / 24` vectors):** Preventable completely by automated structural/semantic checks without rejecting legitimate verified programs.
- **Hybrid mechanical + explicit TCB assumption (`4 / 24` vectors):** Mechanical checks enforce the Rust-side protocol or cryptographic artifact binding, while an irreducible hardware/OS/foreign-code premise is surfaced explicitly in the TCB audit log.
- **Explicit TCB / execution-environment assumption (`1 / 24` vector):** Cannot be eliminated statically inside an un-sandboxed or dynamically loaded environment and must be stated openly as a deployment assumption.

#### 2.1 Category 1 — Template & Directive Smuggling (`V1.1`–`V1.4`)

`rust-lang/reference@c9cc32825b03` (`src/inline-assembly.md:1585-1640`) normatively guarantees GAS section, data, and symbol directives (`.pushsection`, `.popsection`, `.section`, `.set`, `.equ`, `.equiv`, `.byte`, `.inst`, `.insn`), and LLVM's integrated assembler additionally accepts `.macro`/`.endm`/`.purgem`.

- **`V1.1` Constructor injection (`.init_array` / `.preinit_array` / `.mod_init_func` / `.CRT$XCU`) — *Total mechanical defense*:**
  In **PoC 1** (`support/run_adversarial_pocs.py`), `innocent_pure_leaf(x: u64) -> u64` wraps `mov {out}, {x}` with `options(pure, nomem, nostack, preserves_flags)` while embedding `.pushsection .init_array,"aw",@init_array; .quad smuggled_ctor; .popsection`. Even though `main()` places `innocent_pure_leaf` inside an untaken branch (`std::env::args().len() > 999`), the binary compiles cleanly (`rustc 1.102.0-nightly -C opt-level=2`), gains an extra `.init_array` slot (`size 0x18`), and executes `smuggled_ctor` **before `main()`** (`pwned_before_main=0xdeadbeef acc=0`). *Defense:* Closed directive allowlist on inline/global asm **plus** mandatory post-link ELF/Mach-O/PE section-table audit rejecting any unverified constructor/destructor/custom-section entries.
- **`V1.2` Assembler `.macro` instruction spoofing — *Total mechanical defense*:**
  In **PoC 2**, `global_asm!` defines `.macro nop; mov eax, 0x1337; .endm` before a function whose source text reads `xor eax, eax; nop; ret`. `objdump -d` confirms LLVM's assembler emits `31 c0` (`xor %eax,%eax`), `b8 37 13 00 00` (`mov $0x1337,%eax`), `c3` (`ret`), returning `spoofed_nop=0x1337`. Any syntactic mnemonic allowlist operating on pre-assembly strings is defeated totally. *Defense:* Forbid `.macro`/`.irp`/`.rept` in assembly templates **and** verify the decoded machine-code bytes of the final assembled/linked object.
- **`V1.3` Raw byte/opcode smuggling (`.byte`/`.inst`/`.insn`) & trailing prefix bleed (`LOCK`/REX) — *Total mechanical defense*:**
  In **PoC 2**, `.byte 0xb8, 0x77, 0x77, 0x00, 0x00; .byte 0xc3` emits zero instruction mnemonics yet disassembles to `mov $0x7777, %eax; ret` (`raw_byte=0x7777`). Separately, `r[asm.rules.x86-prefix-restriction]` (`src/inline-assembly.md:1456-1458`) explicitly notes that `rustc` currently cannot detect an inline `asm!` block ending with a bare x86 prefix (such as `LOCK`) that bleeds onto the immediately following compiler-generated instruction. *Defense:* Decode the emitted machine instruction stream across the function body and require instruction-boundary completeness at `asm!` entry/exit.
- **`V1.4` Symbol aliasing via `.set` / `.equiv` / `.symver` — *Total mechanical defense*:**
  In **PoC 2**, `.globl verified_alias; .set verified_alias, evil_payload` redirects Rust's `extern "C" fn verified_alias()` to `evil_payload` (`verified_alias=0x4242`). *Defense:* Resolve all symbol addresses and aliases strictly from the final linked symbol/relocation tables (`st_value`, `st_size`).

#### 2.2 Category 2 — Option, Contract & Target-Feature Lies (`V2.1`–`V2.4`)

- **`V2.1` False `options(nomem)` / `options(readonly)` / `options(pure)` — *Total mechanical defense*:**
  `rustc` treats `options(...)` as unchecked optimization premises (`rust-inline-assembly-contracts-relocations-and-simd-correspondence`). In **PoC 3**, `false_nomem_observed(slot: &mut u64)` stores `111`, executes `asm!("mov qword ptr [{p}], 999", p = in(reg) p, options(nomem, nostack, preserves_flags))`, and returns `*slot`. Under `-C opt-level=0`, output is `seen=999 actual=999`; under `-C opt-level=3`, LLVM forwards the pre-`asm!` load across the `nomem` barrier and prints **`seen=111 actual=999`**—splitting functional behavior between unoptimized and optimized builds. *Defense:* Derive mandatory trace-level obligations directly from MIR `TerminatorKind::InlineAsm` options against a strict memory-footprint/termination ISA semantics (remembering that transient write-then-restore also violates `nomem`/`readonly` trace safety).
- **`V2.2` False `options(preserves_flags)` / `options(nostack)` / `options(noreturn)` — *Total mechanical defense*:**
  Violating `preserves_flags` corrupts condition/FP/vector status flags (`r[asm.rules.preserved-registers]`, `src/inline-assembly.md:1368-1395`), violating `nostack` silently destroys the SysV/Apple 128-byte red zone (demonstrated in **PoC 6**, `V4.3`), and violating `noreturn` falls straight into LLVM `bx.unreachable()` (`tock-mmio-w1c-register-bitfields-and-sbi-ffi-noreturn-fallthrough-hazards`). *Defense:* Require ISA-level proof of flag preservation, stack/red-zone disjointness, and non-fallthrough divergence.
- **`V2.3` False `lateout` / register-overlap contracts — *Total mechanical defense*:**
  As mechanized in `rust-inline-assembly-contracts-relocations-and-simd-correspondence` (`illegal_lateout_witness`), marking an output `lateout` when it is written before all inputs are read allows register-allocator aliasing to silently clobber inputs. *Defense:* Universally quantify source-template proofs over all legal register assignments, or verify the concrete post-regalloc binary bytes.
- **`V2.4` Unverified `#[target_feature]` CPUID / OS XCR0 / `hwcap` guards — *Hybrid mechanical + TCB assumption*:**
  Under `r[attributes.codegen.target_feature.target-ub]` (`src/attributes/codegen.md:462`), calling a `#[target_feature]` function on hardware lacking the feature is immediate UB. In **PoC 3**, `call_without_cpuid` invokes `#[target_feature(enable = "avx512f")] unsafe fn avx512_unguarded` with **zero** CPUID or `XCR0` check; `rustc` compiles cleanly and emits `vpbroadcastd zmm0, esi` and `vmovdqu64 ZMMWORD PTR [rdi], zmm0`. Even when CPUID is checked, subtle gaps exist: AVX/AVX-512 require OS `XCR0` verification via `xgetbv(0)`, `ring` documents Intel erratum `SKD052` where Skylake Pentium/Celeron CPUs falsely advertise BMI1/BMI2 (`ring/src/cpu/x86_64.rs:288-300`), and `aws-lc` allows `OPENSSL_ia32cap` env overrides. *Defense:* Mechanically require a hardware-capability precondition at every `#[target_feature]` / extended-ISA call site, while recording CPUID/XCR0/`getauxval`/errata probe semantics and runtime env-override policy explicitly in the TCB audit log.

#### 2.3 Category 3 — Untyped `.o`, Linker & Build Hijacking (`V3.1`–`V3.5`)

- **`V3.1` `#[link_name]` / `#[link_ordinal]` untyped signature mismatch — *Total mechanical defense*:**
  ELF/Mach-O/COFF symbol tables carry untyped symbol names (or Win32 ordinals), not type signatures. In **PoC 4**, Rust declares `#[link_name = "c_two_arg_sum"] fn spoofed_one_arg(a: u64) -> u64;` against C's `uint64_t c_two_arg_sum(uint64_t a, uint64_t b)`. `GNU ld 2.47` links without error, and at runtime the callee adds caller's `10` to uninitialized garbage in `%rsi` (`mismatched_sig_ret=140723591109626`). *Defense:* Extract `CodegenFnAttrs.symbol_name`/`link_ordinal` and `FnAbi`/`PassMode` from `rustc` and match them mechanically against the resolved target definition's calling convention and machine signature in the linked artifact.
- **`V3.2` Weak symbol override & strong static archive-order shadowing — *Total mechanical defense*:**
  In **PoC 4**, `libverified.a` contains two members: `verified.o` (defining `__attribute__((weak)) weak_auth` and `c_two_arg_sum`) and `verified_strong.o` (defining **strong** `strong_auth`). Linking `-l static=shadow -l static=verified` silently overrides **both** `weak_auth` (`0 -> 1`) **and** strong `strong_auth` (`0 -> 1`) with **zero linker warning or error**, because Unix archive linking resolves `strong_auth` from `libshadow.a` first and never extracts `verified_strong.o` from `libverified.a`! *Defense:* Bind proofs to the **final linked image** (verifying that every relocation target resolves to the exact proven machine bytes) or enforce whole-archive unique symbol binding across all link inputs.
- **`V3.3` `LD_PRELOAD` / `DYLD_INSERT_LIBRARIES` dynamic interposition — *Explicit TCB / execution-environment assumption*:**
  In **PoC 4**, executing the unmodified dynamically linked binary `poc4_dyn` with `LD_PRELOAD=libevilpreload.so` silently flips `policy_check(0)=0` to `policy_check(0)=1`. While static linking or `-Wl,-Bsymbolic` (as in FFmpeg `configure:7961`) prevents intra-DSO interposition, dynamic loader and host OS integrity cannot be enforced statically inside a dynamically linked binary and must be logged as an explicit deployment/environment assumption (`THREAT_MODEL.md:128-160`).
- **`V3.4` Cross-language LLVM bitcode / LTO boundary evasion — *Total mechanical defense*:**
  When C/C++ objects are compiled to LLVM bitcode (`-flto`) and merged with Rust CGUs—as Linux Rust-for-Linux deliberately does via `#define __rust_helper __always_inline` in `rust/helpers/helpers.c:16-39`—optimizations cross the FFI boundary under divergent attribute assumptions (e.g., `-fno-delete-null-pointer-checks`, differing builtin lists, and target-feature strings), invalidating source/MIR-only boundary assumptions. *Defense:* Either forbid unverified bitcode LTO merging across verified crates or run translation validation / binary verification **post-LTO** on the final emitted machine code.
- **`V3.5` `build.rs` / proc-macro verify-vs-release divergence — *Hybrid mechanical + TCB assumption*:**
  In **PoC 5**, a simulated `build.rs` compiles clean `check_sig(0) == 0` when `VERIFIER_MODE=1` and backdoored `check_sig(0) == 1` during release builds from **byte-for-byte identical Rust source**. *Defense:* OS-sandbox build-time code execution (`THREAT_MODEL.md:136-155`, execution-environment assumption) **and** mechanically bind the verification certificate to the cryptographic digest of the exact compiled/shipped binary or generated source/object artifacts (eliminating any gap between verification build and release build).

#### 2.4 Category 4 — Hidden Hardware & ABI Clobbers (`V4.1`–`V4.5`)

- **`V4.1` x86 Direction Flag (`DF=1`) exit clobber & x87 FPU stack leak (`EMMS`) — *Total mechanical defense*:**
  Rule `r[asm.rules.x86-df]` (`src/inline-assembly.md:1397-1399`) declares UB if `EFLAGS.DF == 1` on exit from x86 inline asm (causing subsequent `rep movsb`/`stosb` copies to run backward and corrupt memory); `r[asm.rules.x86-x87]` (`L1401-1404`) requires the x87 stack to be empty on exit if clobbered. In **PoC 6**, `asm!("std", options(nomem, nostack))` compiles cleanly and leaks `df_exited_set=1`. *Defense:* Encode `DF == 0` and x87 tag-word emptiness (`0xffff`) as mandatory postconditions in x86 ISA verification.
- **`V4.2` AVX upper-YMM dirty state (`vzeroupper`), AArch64 `FPSR.QC`, RISC-V `vstart`/`vtype` — *Total mechanical defense*:**
  In **PoC 6** (executed on an AVX-512F host with `CPUID(0xD, 1).EAX[2] == 1`), `vpcmpeqd ymm0, ymm0, ymm0` leaves `XINUSE[2] == 1` (`ymm_dirty_before_vzeroupper=1`) until `vzeroupper` clears it (`ymm_dirty_after_vzeroupper=0`). On x86 SysV, omitting `vzeroupper` triggers severe AVX-to-SSE microarchitectural transition penalties (and fails FFmpeg `checkasm` `test al, 0x04`), whereas leaving AArch64 `FPSR` (including cumulative saturation `QC`, `r[asm.rules.preserved-registers]`, `L1381-1383`) or RISC-V vector CSRs (`vstart != 0`, `vtype`, `vl`, `vxsat`, `vxrm`, `L1384-1386`) dirty violates ABI / `preserves_flags` correctness contracts. *Defense:* Model architectural FP/SIMD/vector CSRs explicitly in ISA frame conditions.
- **`V4.3` SysV/Apple 128-byte red-zone corruption under false `options(nostack)` — *Total mechanical defense*:**
  In **PoC 6**, a leaf function storing a sentinel at `[rsp - 8]` executes `asm!("push {b}; pop {b}", options(nomem, nostack, preserves_flags))`—silently overwriting `[rsp - 8]` from `0xbb8888ff99aaaa55` to `0xfeedfacecafebabe` even though `rsp` is unchanged on exit! *Defense:* Enforce strict trace-level memory-footprint disjointness prohibiting any access to `[SP - red_zone, SP)` whenever `options(nostack)` is set.
- **`V4.4` Missing/forged DWARF `.cfi_*` / `.eh_frame` or Win64 `.pdata`/`.xdata` unwind metadata — *Total mechanical defense*:**
  In **PoC 6**, `global_asm!` defines `naked_no_cfi_leaf` adjusting `sub rsp, 24; ...; add rsp, 24; ret` with zero `.cfi_*` directives; normal execution succeeds (`leaf=7`), while `readelf --debug-dump=frames` confirms `naked_no_cfi_leaf` (`0x14c8c`) has **zero** `.eh_frame` FDE (`naked_no_cfi_leaf_has_eh_frame_fde: false`). As proved in `rust-ffi-abi-witnesses-c-unwind-and-machine-resource-linking`, forged or missing unwind metadata leaves normal returns unaffected while corrupting caller recovery on unwind/backtrace. *Defense:* Mechanically check `.eh_frame`/`.pdata`+`.xdata` unwind tables at every potentially interrupting PC (or forbid unwinding through unverified frames).
- **`V4.5` Partial-vector callee-save clobbers (Win64 `xmm6..xmm15`, AAPCS64 `d8..d15`, Apple `x18`) — *Total mechanical defense*:**
  Callee-save vector sets vary sharply by target triple: SysV x86-64 saves no XMM registers, Win64 saves full 128-bit `xmm6..xmm15` (upper 128/384 bits of `ymm`/`zmm` remain caller-saved), AAPCS64 saves only the **lower 64 bits** (`d8..d15`) of `v8..v15`, and Apple ARM64/Win64 ARM64 reserve platform register `x18`. *Defense:* Parameterize assembly callee-save frame theorems by the full target triple and ABI specification.

#### 2.5 Category 5 — Type, Validity, Aliasing & Control-Flow Laundering (`V5.1`–`V5.4`)

- **`V5.1` Writing invalid `bool`, `NonZero*`, `char`, or enum discriminant bits in C/asm — *Total mechanical defense*:**
  In **PoC 7**, C returns `2u8` into `extern "C" fn c_invalid_bool() -> bool`. Under `-C opt-level=3`, Rust observes `bool_raw=2` and `!b` compiles to `xor 1`, yielding **`not_bool_raw=3`**—corrupting boolean logic and exhaustiveness assumptions. *Defense:* Require FFI/asm boundary contracts to prove Rust validity invariants on every returned scalar/aggregate and written output buffer before exposing typed Rust references or values.
- **`V5.2` Breaking Tree Borrows / LLVM `noalias` protectors via reentrant FFI callback or cyclic C struct — *Total mechanical defense*:**
  In **PoC 7**, `noalias_protector_victim(exclusive: &mut i32)` writes `*exclusive = 10`, invokes C `c_reentrant_trampoline(&mut dummy, evil_reentrant_cb)` (passing an unrelated pointer), and `evil_reentrant_cb` mutates `*exclusive = 777` through a previously stashed raw alias. Because LLVM emitted `define internal fastcc noundef i32 @...noalias_protector_victim(ptr noalias nofree noundef nonnull writeonly align 4 captures(none) dereferenceable(4) initializes((0, 4)) %exclusive)`, Rust returns **`protector_rust_saw=10`** while volatile inspection proves **`actual_mem=777`**! This mirrors why `flate2-rs` (`src/ffi/c.rs:36-40`) and Linux `Opaque<T>` cannot hold `&mut T` or `Box<T>` across cyclic C structures. *Defense:* Model Tree Borrows / `noalias` protectors across foreign calls and callbacks, forbidding foreign writes to any location protected by an active Rust reference and requiring `UnsafeCell`/`Opaque<T>`/raw pointers for aliased or cyclic FFI structures.
- **`V5.3` Pointer provenance stripping / integer-to-pointer forging — *Total mechanical defense*:**
  As proved in `rust-inline-assembly-contracts-relocations-and-simd-correspondence` (`same_address_is_not_resource_authority`), numeric address equality does not recover allocation liveness or aliasing permission; an adversarial C/asm function converting a `usize` back into a forged pointer can alias live Rust allocations while bypassing pointer-based alias tracking. *Defense:* Maintain explicit allocation-capability / provenance maps across the Rust-to-machine linking relation (`ContextBridge`-style resource tracking).
- **`V5.4` C `setjmp`/`longjmp` or foreign exceptions crossing non-unwind Rust frames — *Hybrid mechanical + TCB assumption*:**
  In **PoC 7**, `c_run_with_setjmp` invokes Rust `extern "C" fn rust_frame_with_drop()`, which creates a RAII `DropGuard` and calls C `c_do_longjmp()`. Execution resumes in C with `longjmp_rc=42`, while `DropGuard::drop` **never runs (`drop_ran=false`)**—silently leaking locks, zeroization guards, or memory invariants (`rust-lang/reference@c9cc32825b03`, `src/items/functions.md:251-259`). *Defense:* Mechanically check `extern "C"` vs `extern "C-unwind"` boundaries and panic-catching/tunneling wrappers on the Rust side, prove `longjmp` absence for verified foreign code, and record non-`longjmp` compliance of unverified C libraries in the TCB audit log.

#### 2.6 Category 6 — Spec-Surface Hiding (`V6.1`–`V6.2`)

- **`V6.1` Burying specification meaning inside C headers, `bindgen` output, or C macros — *Total mechanical defense*:**
  Under `THREAT_MODEL.md:238-247`, indirect specification tampering leaves the Rust diff clean while modifying a transitive dependency. In **PoC 8**, `spec_consumer.rs` `include!`s `c_bindings.rs` (modeling `OUT_DIR/bindings.rs` generated from a C header) and checks `len <= MAX_AUTHORIZED_LEN`. Changing `MAX_AUTHORIZED_LEN` in the C header from `64` to `usize::MAX` flips `spec_accepts_1_mib` from `false` to `true` with **zero diff** in the Rust specification file. *Defense:* Mechanically compute and display the complete transitive dependency closure of every stated specification—including `include!`d `OUT_DIR` files, `bindgen` constants/types, and foreign predicates—on the human-reviewed specification surface (or forbid non-transparent foreign items in specs).
- **`V6.2` Hiding semantic assumptions in DWARF/BTF debug hints or unlogged dynamic libraries — *Hybrid mechanical + TCB assumption*:**
  As established in `linux-driver-abi-instability-btf-core-kmdf-and-fuchsia-fidl-contracts`, DWARF/BTF debug graphs capture structural geometry but omit concurrency, lock, RCU, and lifetime invariants. Relying on debug hints or unlogged `DT_NEEDED` shared libraries introduces silent soundness holes. *Defense:* Mechanically reject non-normative debug metadata as verification premises and emit every `extern` symbol, native static archive, and `DT_NEEDED` DSO into the TCB audit log for human review.

## Boundaries

- **Cross-language Clang+Rust LLVM LTO bitcode execution (`not examined`):** `clang` was not installed on the `x86_64-unknown-linux-gnu` execution host (`gcc 15.2.0` cannot emit LLVM bitcode compatible with `rustc`'s LLVM `23.1.5`). Vector `V3.4` is therefore grounded in primary source (`torvalds/linux@5f22fb20497f`, `rust/helpers/helpers.c:16-39`) rather than a live Clang+Rust bitcode LTO execution PoC.
- **Non-x86-64 hardware execution (`not examined`):** All executed PoCs ran on `x86_64-unknown-linux-gnu`. AArch64 `FPSR.QC` / partial `d8..d15` saves, Apple ARM64 reserved `x18`, Win64 `xmm6..xmm15` saves and `#[link_ordinal]`, and RISC-V `vstart`/`vtype` clobbers (`V4.2`, `V4.5`) are grounded in normative ABI/Reference rules (`rust-lang/reference@c9cc32825b03`, `src/inline-assembly.md:1368-1395`) and existing corpus reports (`ffmpeg-codebase-architecture-cpuflags-dispatch-and-asm-corpus-census`, `rust-ffi-abi-witnesses-c-unwind-and-machine-resource-linking`) rather than native execution on ARM64/RISC-V/Windows hosts.
- **Trailing x86 `LOCK` prefix bleed and x87 FPU stack leak execution (`not examined`):** Within `V1.3` and `V4.1`, `.byte` raw opcode smuggling (`PoC 2`) and `DF=1` exit leakage (`PoC 6`) were empirically executed, whereas trailing `LOCK` prefix bleed (`r[asm.rules.x86-prefix-restriction]`, `src/inline-assembly.md:1456-1458`) and x87 tag-word leakage (`r[asm.rules.x86-x87]`, `L1401-1404`) are established normatively.
- **Static elimination of `LD_PRELOAD` and un-sandboxed `build.rs` tampering (`known not to apply` / `unsupported`):** No static source- or object-level check can prevent a runtime dynamic linker interposer (`LD_PRELOAD` / `DYLD_INSERT_LIBRARIES`) on a dynamically linked executable (`V3.3`), nor prevent an un-sandboxed `build.rs` or proc-macro running with write access to the verifier binary from forging a passing exit code (`THREAT_MODEL.md:144-160`).
- **Complete census of all Fuchsia, Linux, or crates.io FFI crates (`not examined`):** The `16` workload classes represent the architecturally distinct mechanisms across the four target ecosystems rather than an exhaustive line-by-line census of every crate in each repository.
- **Exact `vzeroupper` ABI status vs. performance hazard (`known not to apply` as SysV architectural corruption):** While `PoC 6` confirms `XINUSE[2] == 1` persists until `vzeroupper`, SysV x86-64 treats `ymm0..ymm15` as caller-saved; omitting `vzeroupper` causes microarchitectural AVX-to-SSE transition stalls (flagged by FFmpeg `checkasm`) rather than architectural value corruption, unlike `DF=1`, `FPSR.QC`, or RISC-V `vstart != 0`.
