# Multimodal UI Synthesis, Visual-Regression Diffing, Visual Self-Refinement, and Automated Web Accessibility Oracles

## Summary

Primary-source inspection of 12 peer-reviewed papers and preprints (2024–2026), W3C WCAG 2.2, WebAIM Million (2024–2026), Deque automated coverage studies (2021–2022), eight pinned revisions across seven public repositories (`NoviScl/Design2Code`, `ChartMimic/ChartMimic`, `TencentARC/Plot2Code`, `WebPAI/DesignBench`, `mapbox/pixelmatch` `v7.1.1` and `post-v8.0.0`, `dequelabs/axe-core` `v4.14.1`, and `alphagov/accessibility-tool-audit`), and a deterministic pure-Python 3.10+ standard-library verification suite (`scripts/verify_multimodal_ui_a11y.py`) establishes four operational invariants for multimodal frontend synthesis, visual-regression verification, and automated web accessibility repair:

1. **Visual Self-Refinement Is Scale-Gated Below ~70B, High-Variance at the Frontier, and Frequently Harmful in Code-Repair / Layout-Triage Prompts:** Across `Design2Code` (`arXiv:2403.03163v3`), `ChartMimic` (`arXiv:2406.09961v2`), `DCGen` (`arXiv:2406.16386v3`), `DesignBench` (`arXiv:2506.06251v3`), and `WebCompat/XCompat` (`arXiv:2608.12518v1`), screenshot self-reflection below `~70B` parameters monotonically degrades both visual fidelity and execution rates (`ChartMimic` Table 5: `InternVL2-26B -0.5`, `8B -5.5`, `2B -6.6`; `Design2Code` Tables 1 & 9: `DeepSeek-VL-7B 37.4% -> 18.8%` vs. `Text-Augmented`, `Idefics2-8B 19.8% -> 3.3%` vs. `Direct`). At the frontier (`>= 70B`), visual self-revision is **high-variance and must be rollback-gated**: it helps `GPT-4o` on `ChartMimic` (`+3.6`), `Design2Code-HARD` (`Block +4.4`, `Pos +3.6`), and `Design2Code` human win+tie (`96.0% -> 97.0%`, despite slipping on 4/5 auto metrics vs. `Direct`), and helps `GPT-4V` on both auto and human scores (`74.0% -> 85.0%`), yet regresses `Claude 3.5 Sonnet` on 5/5 metrics on `Design2Code-HARD` (`Block 75.1 -> 71.9`). In repair and layout triage, frontier MLLMs fail to identify UI visual defects `> 60%` of the time (`DesignBench` Table 10 peak `39.51%`, 9-model mean `27.14%`), so attaching screenshots degrades `Design Repair` below `Code`-only on `6 / 9` MLLMs (`DesignBench` Table 7) and drops cross-device layout detection Test F1 on `GPT-5.5` (`0.851 -> 0.779`, Empirical Precision `-19.3` pp) and `Opus 4.8` (`0.856 -> 0.728`, `WebCompat` Table VI).
2. **Deterministic Multi-Viewport DOM + Computed-CSS Geometry Oracles Must Precede Pixel Diffing:** Single-viewport desktop visual scores hide catastrophic cross-environment breakage (`WebCompat`: `68%` [`139 / 203`] AI pages fail across 9 browser/OS environments vs. `40%` [`24 / 60`] human; `88.3%` Class A page-level failures, `46.0%` missing `<meta name="viewport">`; deterministic `XCompat` hits Test `F1 = 0.903` in `0.127 s / 0 tokens`), and compiler/navigation checks drive functional correctness invisible to CLIP (`DeclarUI`: ablating PTG + compiler refinement drops `PCR 96.8% -> 23.1%` while CLIP moves only `0.90 -> 0.87`). Even in `pixelmatch` `post-v8.0.0` (OKLab HyAB + sliding `windowSize`), Probe 3 shows a sharp window-size phase transition: on a `240x120` card, a benign `1px` horizontal shift (`600` diff px; `2.0833%` of crop, `0.0651%` of a static `720p` page; `0` DOM errors) dominates compact digit+sign corruption (`$100 -> $900, +1.2% -> -1.2%`: `84` px, `0.2917%` crop, `0.0091%` static `720p`) globally and at `windowSize >= 16` (`68 < 74..128`), while finer windows `windowSize in {4, 8, 12}` separate that dense glyph patch (`12/40/64 > 8/28/48`) yet still fail to separate a thin-stroke sign flip (`+1.2% -> -1.2%`: `16` px, tied `8 == 8` at `ws=4`, strictly dominated `12..16 < 28..128` for all `ws >= 8`).
3. **`axe-core` Is a Zero-False-Positive Mechanical Floor, Not a WCAG Conformance Oracle, and Accessibility Repair Must Gate Against Side-Effect Regressions:** Against W3C WCAG 2.2's `55` active Level A+AA Success Criteria (`86` active SCs total; `4.1.1 Parsing` obsolete), default `axe-core v4.14.1` (`105` rules) partially checks only **`20 / 55` (`36.4%`)** active A+AA SCs (`21 / 55 = 38.2%` with opt-in `target-size`, `23 / 55 = 41.8%` across all 105 rules), leaving `35 / 55` (`63.6%`) unaddressed (`5 / 6` new WCAG 2.2 A+AA SCs uncovered) and catching `41 / 142` (`28.9%`) barrier classes in the 2019 GOV.UK audit (`Keyboard Access 1 / 16 = 6.3%`). Reconciling `36.4%` touched SCs with Deque's `57.38%` automated issue-volume share requires `>= 1.58x` issue concentration on those 20 SCs and splits the `42.62%` non-automated volume across **both** within-20 partial-recall misses (`30.9%` at `r_auto = 0.65`, `19.1%` at `0.75`, `10.1%` at `0.85`) and the 35 unaddressed SCs (`11.7% / 23.5% / 32.5%`). Single-oracle RL (`A11yn` GRPO on `axe-core`) achieves real cross-oracle transfer (`IR_AChecker` drops `58.1%` from `0.62 -> 0.26`, beating frontier models `0.35–0.57`) **yet** widens the unguarded `IR_AChecker / IR_Axe` gap from `1.55x -> 5.20x`. In multi-file repair (`A11YRepair`), agents introduce `172–322` (`Lite`) to `679–2,387` (`Full`) new accessibility regressions (`N_side`), and dumping unfiltered WCAG docs (`A11YRepair_aw`) degrades repair (`74.94% -> 58.74%`) while inflating regressions (`194 -> 498`).
4. **Published Multimodal UI/Chart Benchmark Evaluators Contain Silent Metric-Distortion Bugs That Disqualify Them as Unaudited Acceptance Gates:** Direct source inspection confirms a live `IndentationError` (`Design2Code/visual_score.py:463`), center-only overlap/clipping blindness (`1.0000` score on `3.0x`/`4.0x` overlapping clipped boxes), `19`-tag semantic omission (`3,920` Table-5 instances), `3.75x` tall-page square CLIP squash, `ChartMimic` `ChartTypeEvaluator` singleton carryover inflating F1 up to `2.43x` at `58.7%` crash rate, `ChartMimic` `find("plt.savefig") == -1` silent tick contamination on `fig.savefig()`, and `Plot2Code` mixed-coordinate `exp(-d/100) > 0.8` making `[0, 1]^2` axes-fraction position checks `100%` vacuous (`min sim = 0.985957`) while falsely rejecting `2.5%` data-space shifts and `2x` `figsize` changes.

#### 1.2 Cross-Environment Responsive Layout Breakage (`WebCompat` / `XCompat`)

`Basis: documentation + derived`

- **Prevalence & Failure Modes (`Guo, Xiao, Sun, & Huo, Aug 2026`, `arXiv:2608.12518v1`, Tables I–VII):** Auditing `203` AI-generated webpages (across 8 tools) and `60` human webpages across `9` desktop/mobile browser environments (`N = 1,624` empirical + `408` test pairs) finds **`68%` (`139 / 203`)** of AI pages exhibit cross-environment incompatibility vs. **`40%` (`24 / 60`)** of human pages (`Direct-GPT-5 100% [43/43]`, `DCGen-GPT-5 93%`, `DCGen-GPT-4 84%`, `Cursor 79%`, `v0 26%`).
- **Symptom Taxonomy & Code Root Causes (Tables IV–V):** **Class A page-level failures occur in `88.3%`** of incompatible pairs (`(A1.1) Shrink-to-Fit 42.1%`, `(A1.2) Initial Scale Mismatch 23.1%`, `(A2.1) Overflow 23.1%`, `(A1.3) Whitespace Anomaly 13.8%`, `(A2.2) Overlap 5.5%`; sub-types sum to `107.6%` because single pairs manifest multiple symptoms). **Class B element-level failures occur in `13.4%`** (`Image Distortion 10.8%`, `Visibility Failure 2.1%`, `Appearance Deviation 0.5%`). Primary code root causes are **missing `<meta name="viewport">` (`46.0%`)**, missing flexible wrapping (`29.5%`), hard-coded dimensions (`19.4%`), and hard-coded image sizes (`10.1%`).
- **Screenshots Hurt Cross-Device Layout Detection vs. Deterministic DOM/Geometry Oracles (Tables VI–VII):**
  - `GPT-5.5 DOM-only` achieves Empirical `F1 = 0.874` / Test `F1 = 0.851`; adding screenshots (`DOM + screenshot`) drops Empirical Precision by **`-19.3` pp** (`0.926 -> 0.733`) and Test `F1` to **`0.779`** (`27.96 s / 20,721` tokens).
  - `Opus 4.8 DOM-only` achieves Empirical `F1 = 0.892` / Test `F1 = 0.856`; adding screenshots drops Test `F1` by **`-12.8` pp** to **`0.728`** (`8.45 s / 26,721` tokens).
  - Deterministic hybrid `XCompat` (page-level viewport/scale/overflow geometry + element-level invariants) achieves Empirical **`F1 = 0.939`** and Test **`F1 = 0.903`** in **`0.127 s / 0 API tokens`** (ablating its page-level module collapses Recall `0.889 -> 0.192`, and classic `RedeCheck` achieves only Test `F1 = 0.450`).

### 2. Benchmark Evaluator Forensics (Pinned Public Repositories)

#### 2.1 `Design2Code` Evaluator Distortions (`NoviScl/Design2Code@7a575e4c`)

`Basis: source + execution (Probe 1) + derived`

Direct inspection of `Design2Code/metrics/visual_score.py` and `ocr_free_utils.py` at commit `7a575e4c33f417c4be5c64072b8f5798de0d0f99` (`2024-11-02`), verified mathematically in `Probe 1` (exact port of core matching/scoring loop `visual_score.py:453–561` on pre-merged non-coalescing blocks, omitting `merge_blocks_by_bbox` / `find_possible_merge` and computing CIE Lab directly in D65 rather than `colormath`'s D65->D50 Bradford adaptation; identical to upstream on Probe 1's fixtures), identifies six structural defects:

1. **Live `IndentationError` at HEAD (`visual_score.py:458–463`):** Commit `acaf2c6d` (`2024-05-24`, *"Fix clip score bug in visual_score.py"*) indents line `458` (`if len(predict_blocks) == 0:`) at 9 spaces and line `463` (`elif len(original_blocks) == 0:`) at 12 spaces; `compile()` raises `IndentationError` unmodified. Separately, `calculate_current_cost` is defined twice (`L147–148` returning `.sum()`, immediately shadowed by `L170–171` returning `.tolist()`).
2. **Center-Only Position Metric & Overlap/Clipping Blindness (`visual_score.py:509–520`, `Probe 1 Case A`):** `position_similarity = 1 - max(|cx2 - cx1|, |cy2 - cy1|)` compares only normalized bounding-box centers, `final_size_score = sum(matched_areas) / sum(all_areas)` ignores matched box-size distortion, and `calculate_ratio` (`L520`) asserts only `> 0`. Inflating a heading block by **`3.0x` width (`0.40 -> 1.20`) and `4.0x` height (`0.10 -> 0.40`)** around the same center `(0.50, 0.25)` clips the viewport (`max_overflow = 0.10`) and overlaps the sibling paragraph (`max_IoU = 0.0400`), yet `Design2Code` awards **`Block = 1.0000, Text = 1.0000, Pos = 1.0000, Color = 1.0000`**.
3. **19-Tag Color-Injection Whitelist & Ancestry Inheritance Scope (`ocr_free_utils.py:49–53, 124–134`, `Probe 1 Case B`):** `text_tags` assigns fresh `ColorPool` colors strictly to 19 tags (`p, h1..h6, div, span, a, b, li, table, td, th, button, footer, header, figcaption`), omitting `<option>`, `<input>`, `<strong>`, `<nav>`, `<section>`, `<label>`, `<article>`, `<main>` (`3,920` occurrences across the first six in `Design2Code` Table 5). Because `extract_text_recursive` walks all descendants inheriting `parent_color`, non-whitelisted elements like `<nav>`, `<label>`, `<strong>`, and `<section>` are omitted specifically when **not** nested under a whitelisted `text_tags` ancestor (e.g., top-level semantic landmarks or standalone form controls directly under `<body>`/`<form>`) or when overriding inline `color`, whereas `<input value="...">` (attribute text, not text node) and unexpanded `<option>` are dropped regardless of ancestry. Deleting top-level `<nav>`, `<label>`, and `<input value=...>` in `Probe 1 Case B` still scores **`Block = 1.0000, Text = 1.0000, Pos = 1.0000`** (`3` missing elements flagged by the DOM oracle).
4. **Exact Scope of Latent `uint8 +/-4` Wraparound (`ocr_free_utils.py:14–25, 60–64, 94, 124, 212–213, 235–259`, `Probe 1A`):**
   - `get_blocks_ocr_free` creates `p_html` with `ColorPool(offset=0)` (`L237`) and `p_html_1` with `ColorPool(offset=50)` (`L238`).
   - `p_png_1` (`offset=50`) is used **only** inside `find_different_pixels(p_png, p_png_1)` (`L243`), which runs Python-int modular arithmetic `similar((r1 + 50) % 256, r2)` (`abs(n1 - n2) <= 8`, `L60–64, 94`) — **never** `cv2.inRange`.
   - `extract_text_with_color(p_html)` (`L250`) and `get_blocks_from_image_diff_pixels(p_png, ...)` (`L252`) read **only** `p_html`/`p_png` (`offset=0`), whose `ColorPool(0)` channels (`range(10, 251, 16) = [10, 26, ..., 250]`) satisfy `10 - 4 = 6 >= 0` and `250 + 4 = 254 <= 255` (`0 / 16` wrap).

### 5. Operational Synthesis for Agentic UI Synthesis and Verification Pipelines

`Basis: derived (synthesized from Sections 1–4)`

1. **Gate Visual Self-Refinement by Scale, Task Mode, and Rollback:** Disable screenshot self-revision below `~70B`; omit screenshots by default in code-repair and cross-device layout-triage prompts; restrict frontier visual reflection to spatially decomposed generation (`DCGen`) gated by deterministic non-regression rollback.
2. **Enforce Deterministic Structural Oracles Before Pixel Diffing:** Run framework compilation + navigation/PTG checks, multi-viewport (`1280x800` desktop + `390x844` mobile) DOM + computed-CSS geometry invariants (`<meta name="viewport">`, overflow against layout viewport, sibling overlap, image aspect ratio, effective font/target sizes, exact text/value assertions), and normative WCAG 2.2 contrast (`0.04045` luminance) before invoking fixed-viewport `pixelmatch` `post-v8.0.0`.
3. **Layer Accessibility Oracles & Zero-Regression Patch Gates:** Run `axe-core` with opt-in WCAG 2.2 `target-size` enabled as a high-precision floor; pair it with keyboard focus/tab-order tests and secondary/semantic checkers to close the `35 / 55` unaddressed SC gap and cross-oracle divergence; during repair, inject only targeted violation rules, prefer native semantic HTML over custom ARIA roles, and reject patches with `N_side > 0`.
4. **Audit Benchmark Evaluators Before Optimization:** Never treat unverified benchmark evaluators (`Design2Code`, `ChartMimic`, `Plot2Code`, `DesignBench`) as RL rewards or automated release gates without auditing their matching, extraction, and state-reset paths.

1. **Desktop / OS GUI Grounding (`known not to apply` / `not examined`):** 2D OS/desktop GUI coordinate-clicking, accessibility-tree grounding, and desktop navigation benchmarks (`OSWorld`, `ScreenSpot`, `OmniParser`) are excluded; findings apply strictly to frontend/chart code synthesis, visual-regression diffing, visual code self-refinement, and web accessibility oracles.
