# Rust Normative Authority Map, Inter-Specification Disagreements, and `rustc` Deviations

## Summary

A verified drop-in replacement for `rustc` targeting Rust `1.99.1` (`58cf8f9c35b355199727627d07ae34a4e2846d67`) must distinguish between behaviors that are **normatively guaranteed**, behaviors that are **unspecified in prose but de facto locked by standard-library or ecosystem assumptions**, behaviors that are **explicitly unspecified** (where an alternative compiler may choose any compliant representation or lowering), behaviors that are **undefined behavior (UB)**, and **open operational-semantics questions** governed by `t-opsem` Final Comment Period (FCP) decisions.

Across the eight authority corpora examined at pinned revisions (`rust-lang/reference`, `rust-lang/fls` `1.99`, `rust-lang/nomicon`, `rust-lang/rust` `1.99.1` standard-library documentation, `rust-lang/rfcs`, `rust-lang/opsem-team` FCP archive, `rust-lang/unsafe-code-guidelines`, and `minirust/minirust`), five structural findings govern compiler design:

1. **Hierarchy of Normative Standing (`opsem-team/fcps.md:3-6`, `reference/src/introduction.md`):**
   - Only **The Rust Reference** (`rust-lang/reference` at `bcd62f35e8bf480ec5b0fa569b6d12ea5924030c`) and **standard-library API documentation** (`library/{core,alloc,std}` in `rust-lang/rust` at `58cf8f9c35b355199727627d07ae34a4e2846d67`) establish stable normative guarantees for user code.
   - **FLS (`rust-lang/fls` `1.99` at `946eacae5a4a33a89af7832178504692439e7478`)** provides paragraph-indexed (`:dp:` `fls_*`) legality and dynamic-semantics rules used for safety-critical qualification, but lags the Reference and OpSem FCPs on abstract byte provenance fragments, CTFE provenance rules, IEEE 754 NaN payload propagation, and volatile semantics.
   - **`t-opsem` FCPs (`rust-lang/opsem-team` at `d462085814030cc5b21dfa0ce831dfc1619d69b1`) and `minirust/minirust` (`063d784186d3252bee242217f218223205c0b568`)** resolve operational ambiguities that the Reference still marks as open—most notably deciding that **unions are always valid** (`UCG#438`), **reference validity does not depend on pointee memory contents** except for uninhabited pointees (`UCG#414`, `UCG#413`), **`&UnsafeCell<T>` can be cast directly to `*mut T` without calling `.get()`** (`UCG#281`, favoring Tree Borrows over Stacked Borrows), **allocations may grow in-place but never shrink** (`rust-lang/rust#159729`), and **volatile accesses to non-Abstract-Machine MMIO memory may trap** (`rust-lang/rust#160564`).
2. **Where a Verified Compiler MUST Match `rustc` Beyond Formal Prose:**
   - **Implicit rvalue static promotion (`compiler/rustc_mir_transform/src/promote_consts.rs`):** While `r[destructors.scope.const-promotion]` describes promotion in general terms, user and `core`/`std` code relies on the exact syntactic promotability predicate (`validate_candidate`) for `'static` lifetime extension of `&expr`.
   - **Internal `core::intrinsics::*` contracts (`library/core/src/intrinsics/mod.rs`):** Permanently unstable in surface Rust (`r[undefined.intrinsic]`), but required verbatim to compile `core`, `alloc`, and `std` from upstream `1.99.1` source.
   - **Target C psABI and `-unwind` landing pads (`compiler/rustc_abi/src/extern_abi.rs`, `compiler/rustc_middle/src/ty/layout.rs:1282`):** `extern "C"` functions defined in Rust must catch unwinding panics and abort the process (`r[panic.unwind.ffi.undefined]`, RFC 2945), whereas `extern "C-unwind"` functions unwind across the FFI boundary.
3. **Where a Verified Compiler Does NOT Need to Match `rustc` (Unless Linking `rustc`-Compiled `.rlib` Artifacts):**
   - **`#[repr(Rust)]` field ordering, enum niche selection (outside guaranteed `Option`-like null-pointer optimizations), and wide-pointer (`*const [T]`, `*const dyn Trait`) field order** are explicitly unspecified (`r[layout.repr.rust.unspecified]`, `r[layout.pointer.unsized]`), provided layout is deterministic within a single compilation (`UCG#97`).
   - **`extern "Rust"`, `extern "rust-call"`, and `extern "rust-cold"` calling conventions** (`compiler/rustc_abi/src/extern_abi.rs:281-290`) and **closure capture drop order** (`r[destructors.operation]`, RFC 1857) are explicitly unspecified.
   - **NaN sign bits and non-deterministic choice among valid NaN payloads** (`library/core/src/primitive_docs.rs:1244-1320`, RFC 3514) are allowed to vary across optimization levels, targets, and compile-time (`const`) vs. runtime execution.
4. **Known `rustc` / LLVM Deviations and Unsoundnesses Against the Normative Authorities:**
   - **32-bit x86 (`i686` / `i586`) x87 float return-value corruption (`rust-lang/rust#115567`, `#114479`):** Passing `f32`/`f64` return values in x87 registers converts signaling NaNs to quiet NaNs via `fld`/`fstp`, violating RFC 3514's guarantee that passing a float around by value preserves its exact bit pattern.
   - **`!Unpin` mutable reference `noalias` omission (`rust-lang/rust#63818`):** `compiler/rustc_ty_utils/src/abi.rs:365-370` suppresses LLVM `noalias` on `&mut T` and `Box<T>` whenever `T: !Unpin`, departing from the Reference's unqualified uniqueness rule (`r[undefined.alias]`).
   - **LLVM pointer-provenance `icmp eq` substitution bug (`llvm/llvm-project#34548`, `#35229`):** GVN/NewGVN replacement of one pointer with another after an address-equality comparison remains unsound in upstream LLVM when integer-to-pointer casts or mixed-provenance pointers are present.
   - **x86-32 Windows MSVC 8-byte stack alignment mismatch (`rust-lang/rust#112480`, `opsem-team/fcps.md:8`):** `i686-pc-windows-msvc` foreign C frames may align 8-byte-aligned types (`u64`, `f64`) to 4 bytes on the stack, causing UB when borrowed in Rust.

## Findings

### 1. Authority Standing and Status Taxonomy

**Basis: normative + documentation + source (`rust-lang/opsem-team` `d46208581403` `fcps.md:1-38`, `rust-lang/reference` `bcd62f35e8bf` `src/behavior-considered-undefined.md:1-225`, `support/normative_authority_map.json`).**

Every semantic behavior in this report and in `support/normative_authority_map.json` is classified into one of five normative statuses:
- **`guaranteed`**: Normatively promised by the Rust Reference or standard-library documentation (`core`/`alloc`/`std`); any compliant Rust compiler **must** uphold the guarantee.
- **`unspecified_stable_in_practice`**: Not guaranteed to surface users by the Reference, or permanently unstable (`core::intrinsics`), or only partially specified (`promote_consts`), yet relied upon by upstream `core`/`alloc`/`std` or ecosystem crates so that a drop-in `rustc` replacement **must** match `rustc`.
- **`explicitly_unspecified`**: Explicitly left to the implementation (`#[repr(Rust)]` field layout, `extern "Rust"` calling convention, closure capture drop order, NaN sign bits); a verified compiler does **not** need to match `rustc`'s choices unless binary interoperability with `rustc`-compiled `.rlib` objects is required.
- **`undefined_behavior`**: Programs exhibiting this behavior have no semantics (`r[undefined.intro]`, `fls_f9mkI99mzPxY`); a verified compiler may assume the behavior never occurs and must prove its own passes never introduce it.
- **`open`**: Subject to active `t-opsem` / `UCG` debate or recently resolved by an OpSem FCP not yet backported into the Reference; recorded with its canonical tracking issue URL.

## Boundaries

1. **Unresolved Operational Questions (`unknown` / `open` in `t-opsem`):**
   - **Out-of-Thin-Air (`OOTA`) in Relaxed Atomics:** Neither C++20 (`N4868`), `library/core/src/sync/atomic.rs`, nor `minirust/spec/mem/concurrent.md` resolves the `OOTA` specification problem without either forbidding `Relaxed` load-to-store reordering (`RC11`) or adopting timestamped promise certification (`Promising 2.0/2.1`).
   - **Final Choice Between Tree Borrows and Stacked Borrows (`UCG#133`):** Although `t-opsem` FCP `UCG#281` (`&UnsafeCell<T> as *mut T`) and `minirust` (`spec/mem/tree_borrows/`) strongly favor Tree Borrows, neither model has yet been voted into the Rust Reference (`r[undefined.alias]`).
   - **Wide `dyn Trait` Raw Pointer Vtable Validity (`r[undefined.validity.wide]`):** Whether creating a raw pointer `*const dyn Trait` with a dummy/invalid vtable metadata pointer (without dereferencing or calling `size_of_val_raw`) is immediate UB remains open in `r[undefined.validity.wide]:156`.
2. **Unmodeled Areas in `MiniRust` and `FLS` (`unsupported` / `not examined` in those authorities):**
   - `minirust` (`063d784186d3252bee242217f218223205c0b568`) does not yet specify inline assembly (`asm!`), target features (`#[target_feature]`), linkage/symbol attributes (`#[no_mangle]`, `#[link_section]`), or volatile accesses (`read_volatile`/`write_volatile`).
   - `fls` (`946eacae5a4a33a89af7832178504692439e7478`) does not specify `core::intrinsics`, CTFE pointer-fragment provenance (`r[undefined.validity.const-provenance]`), or volatile accesses.
