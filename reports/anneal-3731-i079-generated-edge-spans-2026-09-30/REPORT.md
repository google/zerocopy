# Charon spans across CRLF, tabs and a generated multiline item

## Summary

One guarded offline Charon run used a `build.rs`-copied generated Rust file with six CRLF line endings, leading tabs, an emoji, a decomposed combining sequence and one multiline function. The actual 201-byte `OUT_DIR/generated.rs` was retained independently of LLBC. Six local file-ID-1 item records (four unique items) match independently predeclared line/column endpoints under a **fixture-specific fixed four-cell tab calculation**. The multiline function spans line 2 column 4 through line 5 column 5.

Charon's embedded file contents are **195 LF-normalized bytes**, rather than the 201 raw generated bytes: exactly six CRLF pairs become LF. The multiline item's `source_text` has the same LF normalization. This adds a concrete normalization boundary to #3731 I079's previously tested single-line generated-source fixture. I079 remains partial at its product gate.

## Applicability

The installed Charon, Cargo and rustc binary hashes are recorded in [REPORT.json](REPORT.json), with Rust nightly `2026-05-31` on macOS arm64. These hashes identify executed binaries; the package does not establish which source revision built the Charon binary. The dependency-free crate has a `build.rs` that copies checked-in [generated_template.rs](fixture/generated_template.rs) to `OUT_DIR/generated.rs`; `src/lib.rs` includes it with `include!`. The runner copied the actual output to [generated.rs](generated.rs) before deleting its private Cargo tree.

The [predeclared oracle](predeclared.json) was generated from the checked-in template by [oracle.py](oracle.py). Its local filesystem mtime was `2026-09-30T06:17:57.199670Z`, before the recorded Charon command start at `2026-09-30T06:18:40.370350Z`. The acquisition result does not contain a prelaunch hash or other independent attestation of the oracle's contents at launch; the checker verifies its retained contents now. It lists four unique item ranges, raw UTF-8 byte offsets, source text, endpoint lines and competing UTF-8-byte, Unicode-scalar, UTF-16-unit, fixed-tab and tab-stop column predictions. The one Charon invocation used `cargo --preset aeneas` with a private target, offline locked Cargo, one build job and incremental compilation disabled. Exact argv, selected environment, PIDs, timing and raw stdout/stderr are retained in [results.json](results.json) and [raw/](raw/).

## Findings

The retained template and actual generated file are byte-identical at SHA-256 `1a8f1e3ba34f78259326d24feeebf69c6b03356019ba08773e4f5992c833c620`. LLBC file ID 1 names the generated `OUT_DIR` path and embeds the exact CRLF→LF transform of that file, SHA-256 `59d0ebba3ee4303cb2284105e1915e7cdfd5bf95995e4f20ebc901b1de319e99`. Raw-byte equality with the embedded file is false. File ID 0 is the `include!` host source; two nonlocal core files have no embedded contents. **Basis: retained source/output bytes and LLBC.**

| Unique item | Observed begin | Observed end | Relevant discriminator |
| --- | ---: | ---: | --- |
| `PREFIX` | line 1, col 0 | line 1, col 31 | emoji width two; combining mark zero |
| `after_prefix` | line 1, col 35 | line 1, col 71 | tab after column 31 adds four, versus next-tab-stop four adding one |
| `tabbed_multiline` | line 2, col 4 | line 5, col 5 | leading tab adds four at both endpoint lines |
| `AFTER` | line 6, col 0 | line 6, col 28 | combining mark contributes zero |

Across all six serialized local records, mismatch counts are: UTF-8 byte 6, Unicode scalar 4, UTF-16 unit 6, one-cell tab/display 2, fixed four-cell tab/display **0**, fixed eight-cell tab/display 2, four-cell tab-stop 1 and eight-cell tab-stop 2. The `tabbed_multiline` `source_text` matches its independently selected source range **after** CRLF→LF conversion; the other three unique item texts have no newline and match raw slices. The comparator checks a changed-template byte, wrong file ID 0, shifted begin and inclusive-end controls; all are rejected offline. This is not a second compiler run. **Basis: [comparison.json](comparison.json) and offline checker execution.**

The runner's fresh preflight measured 34.9127% estimated reclaimable host memory and 18,764,558,336 bytes free disk. Across 23 live samples, the minimum reclaimable estimate was 34.7874%, minimum free disk 18,762,711,040 bytes, maximum process-group RSS 140,336 KiB and maximum private scratch 1,100,760 bytes. Charon exited 0 in 1.163 seconds. No 20%-memory, 10-GiB-disk, 512-MiB-RSS, 100-MiB-scratch or 15-second guard fired; the process group had zero postrun RSS and the work tree was removed. Sampling can miss shorter peaks. **Basis: execution.**

## Boundaries

This one generated file establishes an observed CRLF→LF transformation and fixed four-cell tab endpoints for its specific characters and positions. It does not prove a general Charon normalization or Unicode contract. Other whitespace, tabs after different columns, grapheme clusters, macro expansion, arbitrary build-script output, moved paths and cross-file spans remain untested. The 32 earlier generated-file records from an unrelated fixture still lack an independent original-source oracle. The nonlocal `core::str::len` record here is excluded.

Raw generated bytes, normalized LLBC contents and item `source_text` must be distinguished when using this fixture as provenance evidence. The result does not authenticate arbitrary rustc provenance, identify generated Lean declarations or demonstrate Anneal editor coordinate conversion, annotation attachment or cache policy. I079's status, gate and prerequisite are unchanged. I025 may use the coordinate evidence as context, but its Anneal source-map residual is unchanged.
