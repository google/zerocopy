# R423: Lake compiled-configuration ownership at 4.31.0 and 4.34.1

## Result

The published [4.31.0 source report](../lake-configuration-ownership-v4-31-0/REPORT.md) says that Lake moved compiled Lean package configurations from dependency-owned paths into workspace-owned numeric slots. This eight-command local execution probe confirms that placement for installed **4.31.0** and **4.34.1** on the same small fixture. Workspace A loads the shared Lean-configured dependency at `a/.lake/config/1/lakefile.olean` and `.trace`; workspace B loads that same physical dependency at `b/.lake/config/2/`, because B also has a local filler dependency. B's load left A's full tree **identical, including file hashes, sizes, mtimes, ctimes, and inodes**. On A's subsequent reload, its dependency-slot `.olean` and trace were **rewritten with identical bytes** (both mtimes changed; the `.olean` inode changed), and a zero-byte `a/.lake/config/1/lakefile.olean.lock` appeared. The root slot remained unchanged. The sequence does not isolate why A's own reload rewrote its dependency slot; B did not directly mutate A's tree or the shared package tree. No compiled config file was placed inside the shared dependency.

The shared dependency **did acquire an empty package-local `.lake` directory** on A's first load in both versions. The directory and its source files did not change during B's load, A's reload, or a TOML-root control. Thus the compiled-cache hoist is observed, while the older report's warning about a residual package-local directory-creation operation remains relevant. This run used a writable dependency and does not establish the error behavior on a read-only mount.

The TOML root loaded the same Lean-configured dependency into `t/.lake/config/1/`, with **no `t/.lake/config/0` root slot**, in both versions. No ownership or placement difference appeared between 4.31.0 and 4.34.1 in these eight cells. Their compiled `.olean` and `.trace` bytes differ across versions, as expected from different Lean toolchain identities; those bytes are not interchangeable merely because the path layout matches.

## Fixture and evidence

The [fixture](fixture/) contains a shared Lean-authored local package; A requires it directly; B requires it and a separate local filler so the shared package receives index 2; and T is a TOML-authored root requiring the same shared package. The [probe](support/probe.py) copies these files to separate version roots, writes each version's `lean-toolchain`, sets `LAKE_NO_NET=1`, and runs `lake --keep-toolchain update` serially in A, B, A again, and T. There are no remote requirements, builds, servers, or downloads. [results.json](results.json) retains exact commands, output, resource samples, and complete before/after tree snapshots with content hashes and file metadata. The generated trees remain under [runs](runs/) for independent inspection. The [offline checker](support/check.py) verifies the snapshot invariants and rehashes the final files without launching Lake.
