# Charon Closures, Traits, Generics, Constants and Statics, Item Provenance, and Enum Layout at 0.1.210

## Summary

At `AeneasVerif/charon@a535e914f74db4fd9e6be7048f4233270d8945c0` (`0.1.210`, embedded Rust toolchain `nightly`, pinned by `AeneasVerif/aeneas@ac9f1bc5262a5e4ff1e24ca78617121382202727` at release `nightly-2026.06.03`), Charon translates Rust's higher-level declaration and type-system constructs into explicit semantic structures inside `TranslatedCrate`:

1. **Closures (`translate_closures.rs`):** Charon desugars every ordinary Rust closure into (a) a struct state type whose anonymous fields have the compiler-inferred upvar capture types (`upvar_tys`), (b) trait implementations for `FnOnce` (always present), `FnMut` (for `FnMut` and `Fn` closures), and `Fn` (for `Fn` closures), and (c) call-method declarations (`call_once` taking `state` by value, `call_mut` taking `&mut state`, and `call` taking `&state`, with ordinary closure parameters packed into a single `Args` tuple). The user closure body is placed on the method matching `ClosureKind` (`Fn`, `FnMut`, or `FnOnce`) after rewriting locals to unpack the argument tuple, while supertrait methods (`call_mut` on an `Fn` closure, `call_once` on an `Fn` or `FnMut` closure) are synthesized as forwarding shims (with `call_once` visibly borrowing and then dropping the owned state). Closure binders track three distinct lifetime sources (captured upvars, higher-ranked closure signature lifetimes, and late-bound receiver borrows on `call`/`call_mut`) and inherit enclosing item generics and trait clauses. Non-capturing closures coerced to function pointers (`ClosureAsFnCast`) receive a synthetic top-level `as_fn` wrapper that constructs the empty state struct and dispatches through `FnOnce::call_once`.
2. **Traits, generics, and where-clauses (`translate_generics.rs`, `translate_predicates.rs`, `rustc_trait_elaboration`):** `GenericParams` separately stores region parameters, type parameters, const-generic parameters, positive `TraitParam` clauses (`TraitClauseId`), `RegionOutlives` and `TypeOutlives` predicates, and `TraitTypeConstraint` associated-type equalities, accumulating parent generics recursively via De Bruijn binding levels while hiding `rustc`'s early-vs.-late-bound lifetime distinction. A `TraitRef` records not only which trait predicate holds, but **how `rustc` proved it** (`TraitRefKind`: `TraitImpl`, `Clause`, `ParentClause`, `ItemClause`, `SelfId`, `BuiltinOrAuto`, `Dyn`, or `Unknown`). `TraitDecl` and `TraitImpl` index associated constants, associated types (under GAT binders), and required/provided methods (pruned when unused by `remove_unused_methods`, with non-overridden default methods normalized into `DefaultedMethod` entries) and carry optional `dyn Trait` vtable types/instances. Trait aliases normalize to empty-item traits carrying `implied_clauses`. However, `translate_predicate` intentionally drops `ConstArgHasType`, `HostEffect` (`const Trait`), `WellFormed`, `ConstEvaluatable`, and `UnstableFeature` predicates and asserts that trait predicates are positive.
3. **Constants, statics, and associated constants (`translate_items.rs`, `translate_constants.rs`):** Named constants and statics are split into a `GlobalDecl` (`GlobalDeclId`) plus a separate initializer `FunDecl` (`FunDeclId`, linked via `GlobalDecl.init` and `FunDecl.is_global_initializer`). `GlobalKind` distinguishes `Static`, `ThreadLocal`, `NamedConst`, and `AnonConst`, but does **not** distinguish shared `static` from `static mut` at the declaration level (both map to `GlobalKind::Static`). Use-site MIR nevertheless preserves the access distinction: shared statics form references directly to the global (`&SHARED_STATIC`), `static mut` accesses form `&raw mut MUT_STATIC` first, and references to `const` items copy the constant into a temporary before borrowing. Trait and inherent associated constants use the same `GlobalDeclRef` machinery (supporting generic parameters, trait-proof-dependent defaults, and impl overrides). Final LLBC is neither uniformly unevaluated nor uniformly CTFE-folded: named constants retain initializer call computations (`X3 = incr(32)`), whereas nested inline `const { ... }` blocks can be folded to scalar literals (`9`) with no residual `GlobalDecl`, and unsupported constant-expression casts or `Todo` forms emit error-marked `ConstantExprKind::Opaque`.
4. **Item identity, structured names, spans, and heuristic comments (`ast/names.rs`, `ast/meta.rs`, `translate_meta.rs`, `recover_body_comments.rs`):** In-crate identity is governed by typed integer IDs (`ItemId`), whereas `Name` is a vector of `PathElem` (`Ident(String, Disambiguator)`, `Impl(ImplElem)` with translated self type or `TraitImplId`, `Instantiated(Binder<GenericArgs>)`, `Target(TargetTriple)`) that collapses `rustc`'s type/value/macro namespaces and adds synthetic segments (`closure`, `{const}`, `{promoted_const}`, `{vtable}`). `#[charon::rename]` / `#[aeneas::rename]` attributes populate `AttrInfo.rename` without altering the underlying `Name`. `Span` stores a primary `SpanData` (`FileId`, 1-based line, 0-based display column, rewritten to the top-most `inlined_parent_scope` for macro/inlined statements) plus a single optional `generated_from_span`; file paths normalize sysroot and Cargo roots to `/rustc`, `/toolchain`, and `/cargo` while rejecting `FileName::NotReal` in `translate_span_data`. Doc comments become `Attribute::DocComment`, whereas ordinary `//` body comments are heuristically scanned from source lines and attached late by `recover_body_comments` (skipping `StorageLive`, ignoring `/* ... */` block comments, and susceptible to false positives on `//` inside multiline string literals).
5. **Enum logical discriminants, niche tag encodings, and target layouts (`translate_types.rs`, `reconstruct_matches.rs`, `tests/layout.rs`):** Charon strictly separates each enum variant's **logical discriminant** (`Variant::discriminant: Literal`, obtained from `rustc`'s `discriminant_for_variant` and observed by `Rvalue::Discriminant`, fieldless enum casts, and `reconstruct_matches` `Switch::Match` resugaring) from its **in-memory tag representation** (`Layout::discriminator` decision tree and per-variant `VariantLayout::tagger` byte-write sequence, obtained from `tcx.layout_of` per `TargetTriple`). The recursive `Discriminator` (`Known(VariantId)`, `Invalid`, `Branch { offset, int_ty, children, fallback }`) models direct tags, `NonZero`/char/pointer niches, non-zero tag offsets, layoutless/uninhabited variants (`Result<!, ()>`), and invalid values inside a niched tag range (`HasInvalidDiscr` UB detection), and is verified by `charon/tests/layout.rs`'s round-trip tagger-to-discriminator invariant check.

## Findings

### 1. Closure Representation, State Structs, `Fn*` Trait Shims, and Function-Pointer Coercions

**Basis:** `source`, `execution`, `derived`

#### 1.1 Explicit State ADT, Capture Types, and Closure Structural Identity
In `charon/src/bin/charon-driver/translate/translate_closures.rs` (blob `2081ec4748d1073dd5af306fcacf7829c5596d0c`) and `charon/src/ast/types.rs` (blob `548be29762fdc4f4d1cd652537db6f54065ff6ee`), Charon models every ordinary Rust closure as an ADT that implements `FnOnce`, `FnMut`, and/or `Fn`:
1. **State struct (`translate_closure_upvar_tys`, `translate_closure_adt`):** Reads the compiler-computed `upvar_tys` from Hax/`rustc` and creates a struct with one anonymous private field per captured upvar type. Charon does not guess capture modes from source syntax. In `charon/tests/ui/simple/closure-fn.{rs,out}`, the state struct carries two shared-reference fields; in `closure-fnmut.{rs,out}`, a mutable-reference field; in `closure-fnonce.{rs,out}`, an owned non-`Copy` value field. In `closure-capture-ref-by-move.{rs,out}`, a `move` closure that captures a variable whose type is already `&'_0 mut i32` produces `struct closure<'_0> { &'_0 mut i32 }` and constructs it by moving the reference into field `0`.
2. **Structural identity:** Closures receive normal Charon declaration IDs (`TypeDeclId`, `TraitImplId`, `FunDeclId`) tied to their `rustc` definition identity, rendered in pretty output as `foo::closure` or nested `foo::closure::closure` (`charon/tests/ui/simple/nested-closure.rs`). This struct layout is a semantic representation of captured state, not a normative cross-version guarantee of `rustc`'s physical memory layout or ABI.

#### 1.2 `ClosureKind`, `Fn*` Impl Hierarchy, Tuple ABI Rewriting, and Forwarding Shims
`ClosureInfo` (`types.rs`) records `ClosureKind` (`Fn`, `FnMut`, or `FnOnce`), the mandatory `FnOnce` implementation, optional `FnMut` and `Fn` implementations, and the higher-ranked closure signature:
- **Impl hierarchy (`translate_closure_info`):** An `FnOnce` closure generates `FnOnce`; an `FnMut` closure generates `FnOnce` and `FnMut`; an `Fn` closure generates `FnOnce`, `FnMut`, and `Fn` (requesting an invalid strengthening such as `FnMut` for an `FnOnce` closure triggers an internal translator panic). The generated `FnOnce` impl binds `type Output = <ReturnTy>`, and `FnMut`/`Fn` access `Output` through parent-trait implied clauses.
- **Receiver types and tuple argument packing:** `FnOnce::call_once` takes `closure_state` by value; `FnMut::call_mut` takes `&mut closure_state`; `Fn::call` takes `&closure_state`. All ordinary closure arguments are bundled into a single tuple parameter `(arg0, arg1, ...)` matching `Fn*<Args>`.
- **Where the user body lives vs. synthesized shims:** Charon places the translated user MIR body on the call method matching the inferred `ClosureKind`—rewriting the body by inserting the tupled `Args` local, shifting subsequent local IDs, and unpacking tuple fields into the original argument locals at entry. Less-specific supertrait methods are synthesized as forwarding shims:
  - For an `Fn` closure, `Fn::call` holds the translated body; `FnMut::call_mut` shared-reborrows `&mut state` and calls `Fn::call`; `FnOnce::call_once` uses `rustc`'s closure-once shim (borrowing the owned state, dispatching, and then dropping the state before return).
  - For an `FnMut` closure, `FnMut::call_mut` holds the translated body; `FnOnce::call_once` uses the closure-once shim to call through `&mut state` and drop the consumed state.
  - Because `call_once` consumes and drops the closure state (`Destruct`, whose body may be `<missing>` under default promoted MIR), `call`/`call_mut` and `call_once` are not resource-interchangeable.

#### 1.3 Three-Source Lifetime Binders, Parent Generics, Opacity, and `ClosureAsFnCast`
- **Three distinct lifetime binder sources:** `translate_closures.rs` separately tracks (1) lifetimes in captured upvars/state, (2) late-bound lifetimes in a higher-ranked closure signature, and (3) late-bound receiver-borrow lifetimes on `Fn::call` and `FnMut::call_mut` (`FnOnce::call_once` adds no receiver-borrow lifetime).
- **Parent generics and trait clauses:** Closures inside generic functions or impls inherit the surrounding type parameters, regions, and trait clauses (`nested-closure.rs`). Concrete closure calls resolve to the generated `Fn*` impl method with generic/proof arguments; generic `Fn*` calls use `TraitRefKind::Clause`.
- **Stateless closure-to-function-pointer coercion (`ClosureAsFnCast`):** In `translate_stateless_closure_as_fn` (`charon/tests/ui/closure-as-fn.{rs,out}`), when a closure with an empty upvar list is coerced to an `fn` pointer, Charon asserts that the upvar list is empty and emits a synthetic top-level function `closure::as_fn` with the closure's untupled parameter list that packs the arguments into a tuple, constructs `struct closure {}`, and calls `FnOnce::call_once`.
- **Opacity:** Both `translate_closure_method` and `translate_stateless_closure_as_fn` respect item opacity, emitting `Body::Opaque` when private contents are hidden.

### 2. Traits, Generics, Where-Clauses, and Structured Proof Provenance

**Basis:** `source`, `documentation`, `execution`, `derived`

#### 2.1 `GenericParams`, Recursive Parent Binders, and Predicate Normalization
In `charon/src/ast/types.rs` (blob `548be29762fdc4f4d1cd652537db6f54065ff6ee`), `charon/src/bin/charon-driver/translate/translate_generics.rs` (blob `7475da93f6e6b54cddce6df15a9af467d05afad1`), and `translate_predicates.rs` (blob `97ca285fb2573c0abb02d7ac0e8e6c2014e24379`):
- **Separated parameter and predicate tables:** `GenericParams` contains distinct vectors for `regions`, `types`, `const_generics`, `trait_clauses` (`TraitParam` indexed by `TraitClauseId`), `regions_outlive` (`RegionOutlives`), `types_outlive` (`TypeOutlives`), and `trait_type_constraints` (`TraitTypeConstraint`, representing `T: Foo<Item = U>` via a `TraitRef`, `TraitAssocTyId`, and target `Ty`). `GenericArgs` mirrors regions, types, const generics, and concrete `TraitRef` arguments.
- **Parameter-bound vs. `where`-clause normalization and `PredicateOrigin`:** `translate_generics.rs` reads `rustc`/Hax `ParamEnv` predicates rather than surface syntax placement, so `fn f<T: Foo>()` and `fn f<T>() where T: Foo` normalize to identical `TraitParam` clauses tagged with a semantic `PredicateOrigin` (`FunOrGlobal`, `Type`, `Impl`, `Trait`, `TraitSelf`, `TraitItem`, or `Dyn`).
- **Recursive parent generics and early/late region unification:** `push_generics_for_def` visits typing parents recursively and uses De Bruijn binding levels (`Binder`) to separate outer item generics from inner method, GAT, or higher-ranked `for<'a>` binders. Charon intentionally erases `rustc`'s early-bound vs. late-bound region taxonomy (`docs/what_charon_does_for_you.md`, `charon/tests/ui/predicates-on-late-bound-vars.{rs,out}`), mapping both into scoped region variables (with a known FIXME `#513` and `docs/limitations.md` note when trait method late-bound regions differ from the declaration).
- **Intentionally dropped and unsupported `rustc` predicates:** `translate_predicate` silently ignores `ConstArgHasType`, `HostEffect` (unstable `const Trait`), `WellFormed`, `ConstEvaluatable` (such as `[(); N + 1]:` const-evaluability obligations), and internal `UnstableFeature` clauses; unknown remaining predicate kinds register errors, and `translate_trait_predicate` asserts that trait predicates are positive (negative trait bounds `!Trait` are not represented as `TraitParam`).

#### 2.2 `TraitRefKind` Proof Trees, `TraitDecl`, `TraitImpl`, Default Methods, and Trait Aliases
In `charon/src/ast/gast.rs` (blob `23044319a8f763d241912c5d693ed94cf597682f`), `translate_items.rs` (blob `7964644be017856c6d165545a67bd6ef06e0c85c`), and `charon/rustc_trait_elaboration/src/lib.rs` (blob `e251b1b540e3abb17445694a3425be5b1d195d95`):
- **Structured trait-proof provenance (`TraitRef` / `TraitRefKind`):** Using `rustc_trait_elaboration`, every `TraitRef` records how `rustc` established a trait obligation:
  - `TraitImpl(TraitImplRef)`: concrete `impl` block with generic arguments;
  - `Clause(DeBruijnVar<TraitClauseId>)`: local generic `where`-clause parameter (`TraitClauseN`);
  - `ParentClause(Box<TraitRef>, TraitClauseId)`: supertrait/implied clause projected from another proof;
  - `ItemClause(Box<TraitRef>, TraitAssocTyId, TraitClauseId)`: bound declared on an associated type;
  - `SelfId`: implicit `Self: Trait` assumption inside a trait declaration (Charon rewrites method-local `Self: Trait` clauses from Hax to `SelfId` and removes the redundant parameter);
  - `BuiltinOrAuto(BuiltinImplData)`: compiler-generated `Auto` or builtin trait implementation (carrying parent proofs and associated types);
  - `Dyn`: automatic implementation provided by a `dyn Trait` trait object;
  - `Unknown(String)`: placeholder emitted after a trait-elaboration error.
- **`TraitDecl` and `TraitImpl` structure (`charon/tests/ui/traits.{rs,out}`, `filtering/opaque-trait.{rs,out}`):** `TraitDecl` stores `TraitDeclId`, `ItemMeta`, `GenericParams`, `implied_clauses` (supertraits), `consts` (`TraitAssocConst`), `types` (`Binder<TraitAssocTy>` for GATs and implied clauses, which `lift_associated_item_clauses` can later lift), `methods` (`Binder<TraitMethod>`, each pointing via `FunDeclRef` to a `FunDecl` whose body is `Body::TraitMethodWithoutDefault` for required methods or a translated body for provided methods), and optional `vtable` type. `TraitImpl` stores the implemented `TraitDeclRef`, `GenericParams`, `implied_trait_refs` satisfying the trait's supertrait clauses, associated const/type bindings, method `FunDeclRef`s (synthesizing a `DefaultedMethod` item when an impl inherits a provided method), and optional `vtable` instance. `MethodStatus` tracking and `remove_unused_methods` prune unmarked provided methods.
- **Trait aliases (`charon/tests/ui/simple/trait-alias.{rs,out}`):** `translate_trait_decl` lowers a `TraitAlias` into a `TraitDecl` with `GenericParams` and `implied_clauses` (and no associated items) plus a synthesized blanket `TraitImplRef`.

### 3. Constants, Statics, Associated Constants, and Constant Expressions

**Basis:** `source`, `execution`, `normative`, `derived`

#### 3.1 Dual `GlobalDecl` / Initializer `FunDecl` Identity and `GlobalKind`
In `charon/src/ast/gast.rs`, `translate_crate.rs` (blob `53536c6df6e241c9655840f6b1f8a4aca2113f90`), `translate_items.rs`, and `translate_constants.rs` (blob `e0b037b340b3ef1b5316f7af472cd7632ba5e89b`):
- **Global + initializer split:** Every translated global constant or static is registered twice in Charon's worklist: once as `TransItemSourceKind::Global` producing `GlobalDecl { def_id, item_meta, generics, ty, src, global_kind, init: FunDeclId }`, and once as `TransItemSourceKind::Fun` producing the initializer `FunDecl` (with `is_global_initializer: Some(GlobalDeclId)`).
- **`GlobalKind` categories and `static mut` collapse:** `GlobalKind` has four variants: `Static`, `ThreadLocal`, `NamedConst` (top-level, local function-scoped, and associated named constants), and `AnonConst` (inline `const { ... }`, type-level const expressions, and promoted constants). Both shared `static` and `static mut` map to `GlobalKind::Static`; `GlobalDecl` has no mutability field.
- **Preserved use-site distinctions (`charon/tests/ui/constants.{rs,out}`, `statics.{rs,out}`, `foreign-constant.{rs,out}`):**
  - *Named and local constants:* `constants.out` preserves initializer computations as explicit calls (e.g., `const X3: u32 = X3()` where `fn X3()` calls `const fn incr(32)`, and `Q3 = add(Q2, 3)`), and preserves function-local named constants (`get_z1::Z1`) as standalone `GlobalDecl` + initializer `FunDecl` pairs. `const fn` declarations (`incr`, `mk_pair0`, `mk_pair1`) translate as ordinary `FunDecl` items without a compile-time-only restriction.
  - *Borrowing `const` vs. `static` vs. `static mut`:* In `statics.out`, taking `&CONST` or `&mut CONST` copies the constant value into a local temporary and borrows the temporary. Accessing a shared `static` forms `&SHARED_STATIC` directly against the global storage (including for non-`Copy` statics). Accessing `static mut MUT_STATIC` first forms `&raw mut MUT_STATIC` and performs reads or reference creation through that raw pointer.
  - *Foreign constants:* In `foreign-constant.out`, an external crate constant emits a `GlobalDecl` whose initializer `FunDecl` has body `<opaque>` under default foreign opacity.

#### 3.2 Inherent and Trait Associated Constants and Constant-Expression Boundaries
- **Associated constants (`charon/tests/ui/assoc-const-with-generics.{rs,out}`, `simple/trait-default-const.{rs,out}`):** Inherent associated constants (such as `V<const N: usize, T>::LEN = N`) become parameterized `GlobalDecl` + initializer `FunDecl` items. In traits, `TraitAssocConst` records `name`, `item_meta`, `ty`, and `default: Option<GlobalDeclRef>` (which may depend on `SelfId` or supertrait proofs, as in `ALSO_LEN = Self::LEN + 1`). `TraitImpl.consts` maps each `AssocConstId` to the impl's override `GlobalDeclRef` or the instantiated trait default `GlobalDeclRef`.
- **Constant expressions vs. `Opaque` fallback (`translate_constants.rs`, `simple/nested-inline-const.{rs,out}`):** `ConstantExprKind` directly represents literals (byte strings, strings, chars, bools, integers, floats, `PtrNoProvenance`), ADTs, arrays, tuples, `Global`, `TraitConst`, shared/mutable borrows, raw borrows (including unsizing length metadata for arrays/strings), `Var` (const-generic variables), `FnDef`, `FnPtr`, and `RawMemory`. However, constant-expression casts, Hax `Todo` forms, and failed const-generic variable lookups register an error and emit `ConstantExprKind::Opaque`. Conversely, in `nested-inline-const.out`, `1 + const { 2 + const { 3 + 4 } }` is already folded by `rustc`/Charon to `9` with no standalone `GlobalDecl` emitted for the inner `const` blocks.

### 4. Item Identity, Structured Names, Source Spans, and Comment Recovery

**Basis:** `source`, `execution`, `derived`

#### 4.1 Typed `ItemId` Handles vs. Structured `Name` Paths and Rename Attributes
In `charon/src/ast/krate.rs`, `charon/src/ast/names.rs`, `charon/src/ast/meta.rs`, `charon/src/bin/charon-driver/translate/translate_meta.rs`, and `charon/src/transform/add_missing_info/compute_short_names.rs`:
- **`ItemId` vs. `Name`:** Within a `TranslatedCrate`, `ItemId` (`TypeDeclId`, `FunDeclId`, `GlobalDeclId`, `TraitDeclId`, `TraitImplId`) is the unique in-crate semantic reference. `TranslatedCrate.item_names` maps every registered `ItemId` (including items that failed translation) to a `Name(Vec<PathElem>)`, where `PathElem` is:
  - `Ident(String, Disambiguator)`: collapses `rustc`'s type/value/macro namespaces into one presentation namespace and suppresses zero disambiguators unless needed;
  - `Impl(ImplElem)`: resolves `rustc`'s abstract `Impl` path element into either `ImplElem::Ty(Binder<Ty>)` (for inherent impls, preserving disambiguators when multiple inherent impl blocks exist for the same type) or `ImplElem::Trait(TraitImplId)`;
  - `Instantiated(Binder<GenericArgs>)`: records monomorphized/instantiated arguments;
  - `Target(TargetTriple)`: qualifies target-specific items in multi-target mode.
  The first `PathElem` is always the crate name. Anonymous items receive synthetic segments: `closure` (+ disambiguator), `{const}`, `{promoted_const}`, `{use}`, `{vtable}`, `{vtable_method}`, and `{vtable_drop_shim}`.
- **`ItemMeta` and `#[charon::rename]` / `#[aeneas::rename]`:** `ItemMeta` carries `name`, definition `span`, optional `source_text`, `attr_info` (visibility, attributes, doc comments, and `rename`), `is_local: bool`, `opacity`, and `lang_item`. As verified in `charon/tests/ui/rename_attribute.{rs,out}`, `AttrInfo.rename` stores the consumer-facing override name without mutating the item's `Name` or `ItemId`. Local variable names in `Var` come from MIR `var_debug_info` (`Option<String>`, e.g., `sum_2` vs. anonymous `_7`) and are best-effort debug metadata rather than stable identities (`LocalId` is authoritative).

#### 4.2 Source Spans, `generated_from_span`, and File-Path Normalization
In `charon/src/ast/meta.rs` and `translate_meta.rs`:
- **Span structure and macro/inlining provenance:** `Span` contains `data: SpanData` (`file_id: FileId`, 1-based line and 0-based display-column `beg` and `end` `Loc`s) and `generated_from_span: Option<SpanData>`. For item declarations, `generated_from_span` is `None`. For MIR statements and terminators, `translate_span_from_source_info` walks `inlined_parent_scope` to the top-most inlined/macro call-site parent, setting `Span.data` to that top-most call site and `generated_from_span` to the immediate macro-body/inlined origin span (storing at most two levels rather than a full expansion stack).
- **Filename normalization and `FileName::NotReal` rejection:** `translate_filename` normalizes path separators and rewrites sysroot `lib/rustlib/src/rust/...` paths to `/rustc/<rel>`, other sysroot paths to `/toolchain/<rel>`, Cargo-home paths to `/cargo/<rel>`, and virtual `/rustc/<40-hex-hash>/...` paths to strip the compiler hash, while leaving project paths as `FileName::Local`. Although `FileName::NotReal` exists in the AST enum, `translate_span_data` hits `unimplemented!()` if a translated span resides in a `NotReal` file.

#### 4.3 Doc-Comment Attributes vs. Heuristic Line-Comment Recovery
In `translate_meta.rs`, `translate_bodies.rs`, and `charon/src/transform/add_missing_info/recover_body_comments.rs`:
- **Doc comments:** `AttributeKind::DocComment` translates directly from `rustc` HIR attributes into `Attribute::DocComment(String)` on items, fields, and variants.
- **Heuristic `//` body-comment scanner:** Because MIR drops ordinary comments, `translate_body_comments` scans the item's raw `source_text` line by line, grouping consecutive lines whose trimmed text starts with `//` and assigning 1-based source line numbers. Near the end of the transformation pipeline, `recover_body_comments` traverses final ULLBC/LLBC statements and attaches each unassigned comment group to `comments_before` on the first statement/terminator whose start line is $\ge$ the comment line, skipping `StorageLive` statements. Because the scanner is not token-aware, it ignores `/* ... */` block comments and mistakes a line starting with `//` inside a multiline string literal for a comment, as preserved in `charon/tests/ui/comments.{rs,out}` (`// Fooled ya`).

### 5. Enum Logical Discriminants, Niche Tag Encodings, and Target Layouts

**Basis:** `source`, `execution`, `derived`

#### 5.1 Logical Discriminants vs. Target-Specific Memory Discriminator Trees and Taggers
In `charon/src/ast/types.rs` (`L366-L589`), `charon/src/ast/expressions.rs` (`L720-L751`), `charon/src/bin/charon-driver/hax/types/ty.rs` (`L212-L228`, `L957-L975`), `hax/types/new/full_def.rs` (`L615-L647`), and `translate/translate_types.rs` (`L497-L718`, `L857-L943`):
- **Logical discriminant (`Variant::discriminant: Literal`):** Extracted via `def.discriminant_for_variant(tcx, variant_idx)` with its actual signed or unsigned integer type (`#[repr(i32)]` `12, 43, 123456`, `#[repr(i8)]` `-1, 0, 1`, `#[repr(u128)]` `18446744073709551615`). Represents the value returned by `std::mem::discriminant` and `Rvalue::Discriminant(place)`.
- **Target-keyed `Layout`, `Discriminator`, and `VariantLayout::tagger`:** Introduced in May 2026 commits `ca364ebd26c280f7b01e9dec38581f64ee80d462` ("Copy MiniRust's variant tag representation"), `8eeb1aad67b602fb7a2be9c1416df685241e54ee` ("Detect that reading the niched discriminant is UB"), `3c55c65462133f6847d9bed7380497395a1564a2` ("Move `ReprOptions` to be part of `Layout`"), and `80a5548302d54d45619f3da451877f1da922e32e` ("Correctly represent layoutless variants"). For each `TargetTriple`, `TypeDecl::layout` queries `tcx.layout_of(...)` and records:
  - `size` and ABI `align` (`None` for unsized types), `uninhabited: bool`, and reduced `ReprOptions` (`ReprAlgorithm::Rust` or `C`, optional `Align`/`Pack` modifier, `transparent: bool`, `explicit_discr_type: bool`; excluding `repr(simd)` and `repr(linear)`);
  - `variant_layouts: IndexVec<VariantId, Option<VariantLayout>>`, where each `VariantLayout` stores `field_offsets`, `uninhabited: bool`, and `tagger: Vec<(usize, ScalarValue)>` (byte-offset/scalar writes required to tag the variant);
  - `discriminator: Option<Discriminator>`, a recursive decision tree with nodes `Known(VariantId)`, `Invalid`, and `Branch { offset, int_ty, children: BTreeMap<RangeInclusive<ScalarValue>, Discriminator>, fallback: Box<Discriminator> }`.

#### 5.2 Direct Tags, Niche Encodings, Invalid Niche Subranges, and `tests/layout.rs` Verification
Across `charon/tests/layout.rs` (blob `521847f0d98fa5503f6fd4a13efe94d040d23c29`), `charon/tests/layout.json` (blob `3bc14852304b384e56e7bc3313643b2b9b9eff13`), `cross_compile_32_bit.{rs,out}`, and `cross_compile_big_endian.{rs,out}`:
- **Direct tags (`TagEncoding::Direct`):** `SimpleEnum` and `SimpleAdt` map exact tag values (`0`, `1`) at the tag offset to `Known(VariantId)` with `fallback = Invalid`, and populate each variant's `tagger` with that `(offset, tag_value)` write.
- **Niche tags (`TagEncoding::Niche`):** In `NicheAdt` (`None | Some(NonZero<u32>)`, 4 bytes), `0` at offset `0` selects `None` (`tagger = [(0, 0)]`), while `Some` is the `fallback` with an empty `tagger = []` because the `NonZero<u32>` payload carries the representation. `DiscriminantInNicheOfField` places the discriminator branch at byte offset `8`.
- **Invalid values inside a niched tag range (`HasInvalidDiscr`):** When the untagged niched variant's valid range surrounds explicit tag values that leave gaps, Charon constructs a nested `Discriminator::Branch`: in `HasInvalidDiscr`, the outer `u8` branch covers `2..=4`, mapping `2 -> Known(0)`, `4 -> Known(2)`, and inner `fallback -> Invalid` (so reading byte `3` is detected as UB), while outer `fallback` selects the untagged payload variant.
- **Uninhabited and layoutless variants:** In `SingleVariantButNonZero = Result<!, ()>`, variant `0` has `variant_layouts[0] = None`, variant `1` is inhabited, and `discriminator` is `Known(1)`. Uninhabited variants with a `VariantLayout` have `uninhabited: true` and an empty `tagger`.
- **Round-trip invariant test (`tests/layout.rs`):** For every type with a discriminator and every inhabited variant in `layout.json`, `tests/layout.rs` applies the variant's `tagger` writes, answers untagged discriminator reads with a non-tagged value, and asserts that walking `Layout::discriminator` returns the exact same `VariantId`.
- **Semantic enum IR and `reconstruct_matches` (`translate_bodies.rs:1078-1217`, `reconstruct_matches.rs:1-193`, `matches.{rs,out}`, `issue-91-enum-to-discriminant-cast.{rs,out}`):** Enum construction (`AggregateKind::Adt(..., Some(variant_id), None)`), `SetDiscriminant(place, variant_id)`, downcasts, and `Rvalue::Discriminant(place)` (as well as `core::intrinsics::discriminant_value` and enum-to-integer casts) remain semantic operations over `VariantId` and logical `Variant::discriminant`. In LLBC, `reconstruct_matches` maps each logical `Variant::discriminant` to `VariantId` and rewrites `Rvalue::Discriminant` + integer `Switch` into `Switch::Match` (emitting an error if the enum is opaque). Note that `Layout` explicitly states `"Does not include information about niches"` beyond the enum discriminator/tagger tree.

## Boundaries

- **`known not to apply`:**
  - The `move` keyword on a closure does **not** mean every field of the generated closure state struct is a non-reference value; moving a local of type `&mut T` produces an `&mut T` state field (`closure-capture-ref-by-move.out`).
  - Reusable closure methods (`Fn::call`, `FnMut::call_mut`) and consuming `FnOnce::call_once` shims are **not** interchangeable for drop/resource reasoning because `call_once` drops the closure state before returning.
  - `GlobalDecl.global_kind` does **not** distinguish shared `static` from `static mut` (both use `GlobalKind::Static`), and final LLBC neither preserves all `const` expressions unevaluated nor folds all named constants to scalar values.
  - `#[charon::rename]` / `#[aeneas::rename]` does **not** mutate the item's `Name` or `ItemId`, and `Name` display strings are **not** unique or namespace-preserving substitutes for `ItemId`.
  - Logical `Variant::discriminant` literals do **not** necessarily match in-memory enum tag bytes, and `Layout` does **not** expose a general inventory of scalar valid ranges or niches outside enum `Discriminator`/`tagger` trees.
- **`unsupported`:**
  - `translate_predicate` drops `ConstArgHasType`, `HostEffect` (`const Trait`), `WellFormed`, `ConstEvaluatable`, and `UnstableFeature` clauses, and `translate_trait_predicate` does not support negative trait bounds (`!Trait`).
  - Higher-ranked trait method signatures whose late-bound regions differ from the trait declaration (`#513`) have known binder limitations (`docs/limitations.md`).
  - Capturing closures cannot use `ClosureAsFnCast` function-pointer lowering; async closures, generators, and coroutines are unsupported.
  - Constant-expression casts and Hax `Todo` constant expressions fail translation and emit `ConstantExprKind::Opaque`.
  - `translate_span_data` rejects `FileName::NotReal` (`unimplemented!()`), and `recover_body_comments` does not parse `/* ... */` block comments or lex string literals (failing on `//` inside multiline strings).
  - `ReprOptions` excludes `repr(simd)` and `repr(linear)`, and generic types whose layout `rustc` cannot compute before monomorphization have no `Layout` entry.
- **`not examined`:**
  - No fresh `rustc` or Charon execution was performed in these six source-and-golden studies; checked-in `.out` and `tests/layout.json` files are preserved upstream test artifacts.
  - `dyn Fn*` trait objects, monomorphized closure specialization paths, and thread-local runtime execution semantics (`GlobalKind::ThreadLocal`) were not freshly probed.
- **`unknown`:**
  - Cross-version stability of synthetic closure/anonymous item path names, numeric `ItemId` indices across source edits, and `rustc`'s default physical layout of closures and non-`repr(C)` ADTs across compiler upgrades cannot be assumed without per-revision revalidation.
