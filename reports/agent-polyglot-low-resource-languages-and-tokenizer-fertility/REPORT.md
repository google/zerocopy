# Polyglot Code-Generation Harnesses, Subword Tokenizer Fertility, and Cross-Language Transfer

## Summary

Primary-source inspection and deterministic reproduction across six pinned public repositories and eight peer-reviewed studies establish four structural findings for polyglot and low-resource programming language (LRPL) code generation:

1. **Evaluation Harnesses Introduce Systematic Cross-Language Measurement Error (`Basis: source + execution`, `Probe 1`):**
   - **`nuprl/MultiPL-E@5d60ac014ea0e8567d7f24b8c733f129c6c5891c`:** Neither `dataset_builder/generic_translator.py` nor `dataset_builder/prepare_prompts_for_hfhub.py:88-132` validates target-language syntax or type soundness after AST translation. In OCaml, `dataset_builder/humaneval_to_ml.py:63-74` splits `"[]"` into `[""]` and emits syntactically illegal `"[.0]"` on `HumanEval_151_double_the_difference` (`ocamlc` exit code `2`), while `gen_literal` (`L113-125`) omits `None` (`TypeError` inside `gen_tuple`). In Julia, `dataset_builder/humaneval_to_jl.py:51` appends a stray `>` (`"Dict{K, V}>"`) across `2` HumanEval (`HumanEval_95` yields `0.0%` Codex `pass@100`) and `9` `mbpp-typed` problems. In R, `dataset_builder/humaneval_to_r.py:99-118` maps `[]` to `c()` (`NULL`) across **`42/161` (`26.1%`)** HumanEval and `4/400` `mbpp-typed` problems, and asymmetrically coerces `[0.5, 1e-5]` to `c(0.5, 1e-05)` on LHS calls (`L142`) while leaving `list(0.5, 1e-05)` uncoerced on RHS assertions. In Lua (`dataset_builder/humaneval_to_lua.py:48-76`), `[]`/`()`/`{}` collapse to `"{}"` and `None` emits unbound `"None"` (`nil`, creating sparse table holes that halt `ipairs` across `6` HumanEval and `10` MBPP tasks). In Racket (`dataset_builder/humaneval_to_rkt.py:45,56`), `None` maps to `#f` under global `(check-within ... 0.001)`.
   - **`MCEVAL/McEval@09dec129dd5756447227239b3e5b47e543c2e0fd`:** Hand-written tasks eliminate AST translation bugs but introduce subprocess execution defects: `eval/excute.py:46-48` (`Common Lisp`) and `eval/excute.py:144-146` (`Shell`) explicitly `return True` inside `except TimeoutException:` (`100%` pass rate for infinite loops) while outer `15.0 s` `SIGALRM` interrupts `eval/safe_subprocess/__init__.py:59-85` before `os.killpg` (`L83`, outside `try...finally`); `safe_subprocess.run` caps output at `2,048` bytes (`L34`) and breaks on `p.poll() is not None` (`L77`) without draining unread pipe bytes (`1,600 B` fast `AWK` output truncated to `1,024 B`); Haskell (`eval/excute.py:117,121`) corrupts stems via character-set `path.rstrip('.hs')` and rejects `exit_code == 0` outputs containing `'fail'` in `stdout`; and TypeScript (`eval/excute.py:886-889`) ignores `tsc` exit codes.
   - **`google-research/babelcode@e8314f6f438193893b705e9fa8f8c8069af26dec`:** R `templates/R/evaluation.txt:4` compares `toString(actual)==toString(expected)` (erasing map keys, nesting depth, and types), PHP `templates/PHP/evaluation.txt:4` compares insertion-ordered `serialize()` strings while `babelcode/languages/lang_implementations/php.py:56-59` overwrites duplicate literal key `'array'`, `babelcode/languages/lang_implementations/rust.py:86-89` rewrites `"dictionary"` to `"set"` in Rust docstrings despite `HashMap<K, V>` signatures, and `babelcode/languages/lang_implementations/elixir.py:85-92` calls misspelled `LanguageRegistry.register_lanuage(...)` (`AttributeError` when importing `babelcode.languages` via `babelcode/languages/lang_implementations/__init__.py:15-31`).
2. **Pre-Tokenization Regex Asymmetries and Byte-BPE Starvation Impose a Bounded Multiplicative Tax (`Basis: documentation + source + execution + derived`, `Probe 2`, `Probe 3`):**
   - Porting `openai/tiktoken@79dc2c0533685b893616c78160b5d9e40876e724` (`tiktoken_ext/openai_public.py:12-14,89,104-114` and `src/lib.rs:23-205`) over four semantically matched algorithms (`82` AST operations per language, evaluated under `380` deterministic byte-BPE merges fit on a strictly disjoint `95%` HRPL / `5%` LRPL code corpus with `0%` APL weight) yields **`1.40x–2.11x`** higher `cl100k_base` AST token fertility $\phi_L$ on non-Python languages (`Racket 1.40x`, `APL 1.41x` [`2.28x` tokens per non-space glyph], `Elixir 1.45x`, `OCaml 1.63x`, `Fortran 2.11x`).
   - Higher relative fertility $\phi_L$ reduces effective AST context capacity as $B / \phi_L$, scales prefill self-attention FLOPs quadratically as $\phi_L^2$, and compounds autoregressive sequence error (`Petrov et al., NeurIPS 2023`, §5.1–5.3 & §1; `Ahia et al., EMNLP 2023`). Conversely, `Dagan, Synnaeve, & Rozière (ICML 2024)` Tables 1, 2, and 5 establish that unconstrained cross-boundary phrase merging (`IdentityC`, `Code NSL = 0.69`) degrades `1.5B` HumanEval `pass@1` by **`-4.0` pp** (`22.8% -> 18.8%`) and MBPP by **`-6.7` pp** (`30.1% -> 23.4%`) relative to `LlamaC`. Effective code tokenizers preserve lexical token boundaries while fixing sub-identifier regex tears (`cl100k_base`'s `'state -> ["'s", "tate"]` contraction tear fixed in `o200k_base`) and merging multi-space indentation (`p50k_base`/`cl100k_base` vs. `r50k_base`).
3. **Cross-Language Post-Training Splits Between Low-Cost Format Alignment and High-Interference LRPL Specialization (`Basis: documentation + derived + execution`, `Probe 4`):**
   - Python-only SFT (`McEval` Appendix E Table 10: `CodeQwen-1.5` `33.2%` $\to$ `CodeQwen-1.5-Python` `45.5%` vs. 40-language `mCoder` `46.7%`; Table 1: `CodeQwen-1.5-Chat` `45.5%` $\to$ `mCoder` `46.7%`) recovers **`91.1%` (`+12.3` / `+13.5` pp)** of multilingual SFT gains by unlocking instruction compliance over pre-existing base syntax.
   - For genuine LRPL synthesis gaps, `MultiPL-T` (`PACMPL / OOPSLA 2024`, Tables 1–4) filters `22,311,478` Stack Python functions to `133,168` (`0.597%`) high-coverage seeds and pairs unit tests with target compilers ($K = 100$ for OCaml, $K = 50$ for others), lifting `StarCoderBase-1B` OCaml `1.5% -> 9.7%` (**`6.47x`**) and `15B` `6.9% -> 19.9%` (**`2.88x`**) while regressing idiomatic ADT/higher-order OCaml (`Table 4`: `50.6% -> 42.9%`). Meanwhile, `Agnostics` (`ICLR 2026`, Table 1) universal stdin/stdout GRPO lifts `Qwen3-8B` on `Fortran` (`0% -> 17%`) and `OCaml` (**`0% -> 7%`**; `Qwen3-4B`: `Fortran` `0% -> 15%`, `OCaml` `1% -> 7%`), **but** auditing all `80` cells of `Agnostics` Table 8 refutes its §4/§C.4 prose claim of zero cross-PL interference: single-language GRPO on `Qwen3-4B` preserves `Python` (`34.34% -> 32.96%` on `CF-Lua`) while collapsing sibling 1-indexed `R` by **`-70.0%`** (`10.00% -> 3.00%`, $z = -4.485, p = 7.29 \times 10^{-6}$) and `Julia` by **`-34.5%`** (`10.00% -> 6.55%`).
4. **Corpus Share Confounds Aggregate Static-vs.-Dynamic Averages, While `Julia`'s Label Flips `NICHE`-Tier Slopes (`Basis: source + execution`, `Probe 5`):**
   - `nuprl/MultiPL-E@5d60ac01:analysis/frequency-map.csv:7` labels dynamically typed `Julia` as `static` (`jl,Niche,static,NA`), contradicting `MultiPL-E` Table 1 (`Typed? = ×`) and `dataset_builder/humaneval_to_jl.py:6`. Re-analyzing `analysis/passk.csv` and `results/per_problem_all.csv` confirms the aggregate Codex HumanEval null (`static - dynamic = +1.92 pp -> +2.22 pp`, permutation $p = 0.679 \to 0.627$), **but** correcting `jl -> dynamic` flips the `NICHE`-tier Codex `static - dynamic` gap by **`-9.15` pp** (`+1.50 pp -> -7.65 pp`), nearly doubles `CodeGen` MBPP `static - dynamic` (`+2.98 pp -> +5.73 pp`, where `jl = 0.03%` [`0.00%` HE] and `rb = 0.00%`), and shows that holding $\log_{10}(\text{GitHub}\%_L)$ constant yields a slightly negative one-shot `static` partial slope ($\beta_{\text{static}} = -0.0283 \pm 0.0336$ in `N = 15` target-PL OLS; $-0.2836 \pm 0.5030$ in `N = 15` Table 2 GLMM contrast WLS).

### 2. Pre-Tokenization Regular Expressions and Byte-Level BPE Fertility (`tiktoken@79dc2c05`)

`Basis: source + execution`

Porting the full-Unicode (`U+0000..U+10FFFF`) regular expressions from `openai/tiktoken@79dc2c05:tiktoken_ext/openai_public.py:12-14,33-58,75-120` alongside `Dagan` `Punct` and verifying exact piece-for-piece equivalence between `_byte_pair_merge_large` (`src/lib.rs:47-138`) and `_byte_pair_merge` (`src/lib.rs:140-205`) establishes (`Probe 2`):

1. **Indentation Multi-Space Vocabulary vs. Pre-Tokenization (`r50k_base` vs. `p50k_base` vs. `cl100k_base`):**
   - `r50k_pat_str` (`openai_public.py:13`) already contains `\s+(?!\S)` and splits `"    return"` into `['   ', ' return']` (`2` pieces, identical to `cl100k_base`), and Codex's `p50k_base` (`openai_public.py:55`) reuses the exact same `r50k_pat_str`.
   - `GPT-2` (`r50k_base`, `explicit_n_vocab = 50257`, `openai_public.py:40`) inflates Python indentation (`Code NSL = 1.19` in `Dagan` Table 1) because its WebText BPE merge table lacks whitespace-to-whitespace merges, leaving each leading `0x20` space as a separate token; `p50k_base` (`explicit_n_vocab = 50281`, `openai_public.py:54`) resolves this by appending **`24` dedicated multi-space tokens (`50257..50280`)** without changing `r50k_pat_str`. Meanwhile, `r50k_pat_str` lacks `\s*[\r\n]` (merging across `\n` in `"  \n    return"` $\to$ `['  \n   ', ' return']`), splits `.get\n` into `['.', 'get', '\n']` (`cl100k_base`: `['.get', '\n']`), and leaves multi-digit runs unchunked (`"3.14159265358979d0"` yields `5` pre-tokens under `r50k_base` `\p{N}+` vs. `9` under `cl100k_base` `\p{N}{1,3}`).
2. **Contraction-Prefix Tears Fixed in `o200k_base` vs. `camelCase`/`PascalCase` Splitting:**

### 3. Multiplicative Fertility Compounding vs. Cross-Boundary Over-Compression

`Basis: documentation + execution + derived`

1. **Natural-Language Parity Disparity and Inference Cost Multipliers (`Petrov et al.`, `Ahia et al.`):**
   - `Petrov et al. (NeurIPS 2023)` Table 1 reports `FLORES-200` tokenizer parity ratios (comparing `GPT-2 / RoBERTa` vs. `ChatGPT / GPT-4 [cl100k_base]`) of `5.51` / `2.64` on Bulgarian, `16.89` / `11.70` on Burmese, and `18.76` / `15.05` on Shan, detailing in **§5.1–5.3 & §1** (`§3` defines *Measuring Tokenizer Parity*) how token inflation proportionally multiplies API cost, decoding latency, and context-window truncation.
   - `Ahia et al. (EMNLP 2023)` Table 1 establishes "doubled unfairness": billing token count correlates negatively with `XFACT` downstream accuracy (Spearman $\rho = -0.61$, Pearson $r = -0.55$) and Human Development Index ($r = -0.60$, Bonferroni $p < 0.0056$).
   - Under an analytical sequence-survival model (`Probe 3`, `Basis: derived + execution`) at context budget $B = 8{,}192$ tokens, target complexity $N_{\text{AST}} = 120$ nodes, $f_{\text{Py}} = 2.50$ tok/AST, and base per-token error $\epsilon_0 = 0.0020$, increasing $\phi_L$ from `1.00x` $\to$ `1.75x` $\to$ `2.50x` shrinks AST context capacity from `3,276` $\to$ `1,872` $\to$ `1,310` nodes, scales prefill attention FLOPs by **`1.00x -> 3.06x -> 6.25x`**, lowers pure length-tax survival $(1 - \epsilon_0)^{\phi_L f_{\text{Py}} N_{\text{AST}}}$ from **`54.85% -> 34.96% -> 22.28%`**, and under corpus-starved per-step error inflation ($\epsilon_L = 1.8\epsilon_0, 2.4\epsilon_0$) drops survival from **`54.85% -> 15.06% -> 2.71%`**.
2. **Scale-Qualified Pre-Tokenization Trade-Off and Over-Compression Refutation (`Dagan, Synnaeve, & Rozière, ICML 2024`):**
   - In `arXiv:2402.01035v2` Table 1, `Code NSL` (normalized sequence length relative to `Llama` = `1.00`) spans `GPT-2 = 1.19`, `Punct-32k = 0.86`, `GPT-4 (OpenAI, 100k) = 0.75`, `Ours: GPT-4 80k = 0.75`, `Ours: GPT-4 100k = 0.74`, and unconstrained `Identity-32k = 0.69`.
   - Unconstrained cross-whitespace merging (`IdentityC`, `NSL = 0.69`) severely degrades `1.5B / 32k` code generation (`Table 2`: `18.8%` HumanEval, `23.4%` MBPP vs. `LlamaC` `22.8%` / `30.1%` and `PunctC` `22.2%` / `29.8%`) by fracturing compositional identifiers across whitespace (Appendix G: `'tqdm '` $\to$ `['tq', 'd', 'm ']`).

### 6. Operational Design Rules for Polyglot Harnesses and Agents

`Basis: derived`

1. **Self-Validating Evaluation Harnesses:** Execute a canonical reference solution per target language; place `os.killpg` inside `try ... finally` independent of outer `SIGALRM` timers; drain subprocess pipes via `Popen.communicate()`; strip suffixes with `str.removesuffix(ext)` rather than `rstrip(ext)`; pass `--noEmitOnError` and check `tsc` exit codes; and compare composite outputs structurally (`identical()`, key-canonical ASTs, IEEE-754 tolerances) rather than via `toString()` or insertion-ordered `serialize()`.
2. **Fertility-Scaled Token Budgets ($\phi_L$-Aware Allocation):** Multiply `max_tokens` and repository context budgets by target-language AST fertility $\phi_L \in [1.40, 2.15]$ (`~1.45x–1.65x` for Elixir/OCaml/Racket/APL, `~2.1x` for Fortran) rather than applying uniform Python-calibrated token caps.
3. **Compiler-in-the-Loop Repair and Joint Multi-LRPL RLVR:** Pair static LRPL generation (`OCaml`, `Rust`, `Haskell`, `Fortran`) with `1–3` compiler type-error repair turns (converting one-shot type rejections into high-precision filtering), prepend concise target-PL pitfall checklists (`1`-based indexing, `Option` exhaustiveness, declaration intents), avoid relying solely on Python-transpiled examples for ADT-heavy ML code, and interleave sibling LRPLs jointly during GRPO rather than training single-language checkpoints that overwrite shared 1-indexed representations.

## Boundaries

- **known not to apply:**
  - Unconstrained BPE token-count minimization does **not** monotonically improve code generation: cross-whitespace phrase merges (`Dagan` `IdentityC`, `Code NSL = 0.69`) reduce `1.5B` HumanEval/MBPP `pass@1` by `-4.0` to `-6.7` pp despite `31%` shorter token sequences than `LlamaC`.
  - `MultiPL-E` Rust's dead `Dict` coercion pattern (`dataset_builder/humaneval_to_rs.py:113`) does **not** cause `rustc` compilation failures on monomorphic HumanEval `Dict` tasks (`HumanEval_95`, `HumanEval_111`), because Rust infers `HashMap::from([])` from `candidate`'s concrete signature (`83.0%` Codex `pass@1` on `HumanEval_111`).
  - Single-LRPL GRPO sibling negative transfer (`Agnostics` Table 8) does **not** apply uniformly to instruction-underfit base models (`DSC-6.7B-Ins`, `SmolLM3-3B`), where generic stdin/stdout compliance gains (`+19.4%` to `+22.6%`) outweigh sibling-language competition.
  - `Probe 4a`'s `92.90%` vs. `66.94%` accepted-pool precision figures are **known not to apply** as empirical measurements of `MultiPL-T`; they are derived outputs of an illustrative analytical Bayes model under assumed `(q_ill, alpha_ill, alpha_well)` priors.
- **not examined:**
  - Repository-scale C-to-Rust unsafe-to-safe transpilation suites, library/API version-migration benchmarks, and grammar-constrained CFG decoding masks were **not examined** in this package.
  - Proprietary network-hosted `cl100k_base.tiktoken` / `o200k_base.tiktoken` merge-rank files were **not examined** inside the offline stdlib probe, which fits `380` deterministic byte-BPE merges on the preserved disjoint `95%` HRPL / `5%` LRPL training corpus (`0%` APL weight).
- **unknown:**
  - Whether multi-language interleaved GRPO (`Lua + Julia + R + OCaml + Fortran` sampled jointly) eliminates the `-17.5%` to `-70.0%` sibling-LRPL negative transfer in `Agnostics` Table 8 while matching single-target peak `pass@1` remains **unknown** from published `Agnostics` experiments, which trained separate single-language checkpoints.
- **unsupported:**
  - `MultiPL-E`'s Python-AST test translator (`dataset_builder/generic_translator.py`) leaves higher-order function values (`lambda`), general algebraic sum types beyond `Optional`, and multi-helper Python prompts (`3/164` HumanEval tasks) explicitly **unsupported** for cross-language assertion translation.
