# Log Template Mining, Distributed Trace Tail Sampling, and High-Cardinality Metric Limits

## Summary

Autonomous diagnostic, incident-response, and service-reliability agents consume three ingestion-time telemetry primitives—**mined log templates**, **sampled distributed traces**, and **dimensional time-series metrics**—that fail silently when rare failure modes, memory-pressure evictions, or high-cardinality identifiers interact with bounded ingestion structures:

1. **Online Log Template Mining Defects & Evaluator Metric Divergence (`Drain3`, `LogPai`, `Khan et al.`, `Loghub-2.0`, `LILAC`):**
   - **Four Live Defects in `logpai/Drain3@0fb6d6e1` (`drain.py`, `masking.py`, `template_miner.py`):** (i) `DrainBase.get_content_as_tokens` (`drain.py:183–185`) applies literal `str.replace` *after* masking (`template_miner.py:138`), whereas `TemplateMiner.extract_parameters` (`template_miner.py:228–229`) runs unescaped `re.sub(delimiter, " ", log_message)` on the raw unmasked string—wiping messages to spaces under `extra_delimiters=["."]` (`dot_extract=None`), raising `re.error` on `["["]` (`bracket_re_error=True`), and breaking `exact_matching=True` even under default `extra_delimiters=["_"]` (`examples/drain3.ini:26`) whenever a mask spans an underscore (`USER_42` -> `underscore_masked_exact=None`) while splitting variable-token-count `snake_case` tokens (`err_conn_reset` vs. `err_timeout`) into `snake_case_clusters=2` disjoint depth-1 length subtrees; (ii) `_get_template_parameter_extraction_regex` (`template_miner.py:307–327`) iterates `set(self.masker.mask_names)`, making `p_0, p_1, ...` capture-group names and compiled regex strings `PYTHONHASHSEED`-dependent (`hash_order_changes_regex=True`, affecting serialized regex caches and nested-group numbering, whereas Python 3.7+ `re.Pattern.groupindex` and `Match.groupdict()` at `L243` preserve left-to-right pattern definition order on flat unnested masks: `unnested_groupdict_order_preserved=True`), while `get_parameter_list` (`exact_matching=False`, `L200, 295–296`) steals multi-word arguments left-to-right via `.+?` (`multiword_steal=['rm', '-rf /var/log']`); (iii) sequential `LogMasker.mask` (`masking.py:57–60`) clobbers IPv4 addresses into `'connect <:NUM:>.<:NUM:>.<:NUM:>.<:NUM:>'` if `NUM` precedes `IP` and corrupts RFC 4122 UUIDs with all-digit trailing blocks under default `drain3.ini` rules (`'req 550e8400-e29b-41d4-a716-<:NUM:>'`); and (iv) greedy non-backtracking `Drain.tree_search` (`drain.py:311–316, 465–470`) returns `match_never=None` when a literal branch shadows `'<*> req timeout'` (`match_fallback='<*> req timeout'`), while `max_children=0` raises `KeyError('<*>')` at `L382`.
   - **Volume-Weighted `GA` vs. Template-Level `FGA`/`FTA` Collapse (`Khan et al. ICSE '22`, `Loghub-2.0 ISSTA '24`):** `LogPai`'s `Parsing_Accuracy` (`logparser/utils/evaluator.py:45–49, 86–101`) measures only cluster-partition bijection (`GA`), scoring `GA = 1.0, FGA = 1.0` even when predicted templates are opaque hashes (`PA = 0.0, FTA = 0.0`; `IPLoM` on `HDFS` achieves `GA = 1.000 / 0.961` with `PA = 0.000 / 0.000`). When repetitive heartbeats comprise `95%` of lines, fragmenting `50` rare error lines into singletons keeps **`GA = 0.95` and `PA = 0.95`** while collapsing **`FGA = 0.0625` and `FTA = 0.0625`** (`Drain` on `OpenStack` drops `FGA: 0.117 -> 0.007` and `FTA: 0.018 -> 0.002` across `50,416,620` `Loghub-2.0` logs), whereas a single space around `=` (`PA_calculator.py:71`) collapses `PA = FTA = 0.0` despite `GA = FGA = 1.0`.
   - **Live Implementation Defects in `logpai/LILAC@163d199f` (`prompt_select.py`, `parsing_cache.py`):** An unconditional `return s` at `prompt_select.py:47` bypasses normalization (`L48–55`), misranking Jaccard k-NN candidates (`buggy_top1='abort uid=99 reason=oom'` vs. `intended_top1='conn:uid=1,host=node1'`) while `L70–71` mutates caller dictionaries (`mutates_caller_dicts=True`). In `ParsingCache`, `add_templates` (`L57–60`) and `modify` (`L100–101`) tokenize via whitespace `.split()` while `insert`/`delete` (`L76, 123`) use punctuation-aware `message_split()` (`split_vs_message_split_templates=2`), `delete` (`L137`) leaves orphaned intermediate dicts (`delete_retains_orphan_dict=True`), `find_template` (`L249`) mutates the caller's `parameter_list` via an unpopped `parameter_list.append("")` (`L249_unpopped_param_mutation=True`), and `L252` appends `("<*>", None, None)` (masked to `len(results) >= 2` across all public-API trees by `L244–246`, yet raising `TypeError` at `L227` whenever `len(results) == 1`).

## Findings

### 1. Online & LLM-Assisted Log Template Mining and Evaluator Pathology

`Basis: source + execution` (with the 1,000-line skewed log corpus explicitly tagged `[illustrative analytical model]`, `Basis: derived`)

#### 1.1 Fixed-Depth Prefix-Tree Parsing & Four Live Defects in `logpai/Drain3@0fb6d6e1`

`Drain` (`He et al., IEEE ICWS 2017`, §III, Eqs. 1–2, pp. 35–36) bounds per-message search cost by routing tokenized logs through a fixed-depth prefix tree (`depth >= 3`, internal prefix layers $= \text{depth} - 2$, `maxChild = 100`): regex preprocessing $\to$ token-count layer $n = |\text{seq}|$ $\to$ leading-token prefix layers (routing digit-containing tokens to `<*>`) $\to$ leaf scan choosing the cluster maximizing $\text{simSeq}(\text{seq}_1, \text{seq}_2) = \frac{1}{n}\sum_{i=1}^n \mathbb{I}[\text{seq}_1(i) = \text{seq}_2(i)] \ge st$. Across five benchmark logs, `He et al.` report `0.84–0.99` grouping accuracy (`Table III`) and `51.85%–81.47%` runtime reduction over `Spell` (`Table IV`). Direct inspection and execution of `logpai/Drain3@0fb6d6e1` (`Probe 1`) establish four structural defects:

1. **`extra_delimiters` Tokenization vs. Parameter-Extraction Desynchronization (`drain.py:183–185` vs. `template_miner.py:138, 228–229`):**
   - During ingestion, `TemplateMiner.add_log_message` (`template_miner.py:138`) masks the message *before* `DrainBase.get_content_as_tokens` (`drain.py:184`) executes literal `content.replace(delimiter, " ")`.
   - During extraction, `TemplateMiner.extract_parameters` (`template_miner.py:228–229`) executes unescaped `re.sub(delimiter, " ", log_message)` on the *raw, unmasked* `log_message` before matching compiled mask regexes:
     - `extra_delimiters=["."]` mines `"service.auth.user.alice.ok"` and `"service.auth.user.bob.ok"` into `'service auth user <*> ok'`, yet `re.sub(".", " ", ...)` replaces every character with `" "`, returning `dot_extract=None`.
     - `extra_delimiters=["["]` mines `" pod[0 "` cleanly yet raises `re.error` inside `extract_parameters` (`bracket_re_error=True`).
     - Even non-metacharacter `extra_delimiters=["_"]` (enabled by default in `examples/drain3.ini:26`) fails `extract_parameters(..., exact_matching=True)` whenever a mask matches an underscore-bearing token (`r"USER_\d+"` on `"login USER_42 ok"` mines `'login <:UID:> ok'`, yet `re.sub("_", " ", ...)` rewrites the raw input to `"login USER 42 ok"` before `<:UID:>`'s regex runs, returning `underscore_masked_exact=None`) and splits variable-length `snake_case` identifiers (`"status err_conn_reset retry"` vs. `"status err_timeout retry"`) across `snake_case_clusters=2` unmergeable depth-1 token-count subtrees (`5` vs. `4`).

2. **`PYTHONHASHSEED`-Dependent `p_k` Regex Group Naming vs. `groupdict()` Order, and `.+?` Multi-Word Stealing (`template_miner.py:200, 243, 252–331`):**
   - `_get_template_parameter_extraction_regex` (`L307–327`) constructs `mask_names = set(self.masker.mask_names); mask_names.add("*")` and replaces placeholders mask-name-by-mask-name, assigning capture-group identifiers `(?P<p_0>...)`, `(?P<p_1>...)` in `PYTHONHASHSEED`-dependent hash iteration order (`hash_order_changes_regex=True`). For flat, unnested mask instructions, Python 3.7+ `re.Pattern.groupindex` and `Match.groupdict()` (`L243`) preserve left-to-right pattern appearance order in the returned `ExtractedParameter` list (`unnested_groupdict_order_preserved=True`); the nondeterminism instead alters compiled regex strings stored in `parameter_extraction_cache`, serialized cache snapshots, and any consumer inspecting `p_k` group names or nested sub-group numbering (`L276–282`).
   - When `exact_matching=False` (forced unconditionally by `get_parameter_list` at `L200`) or for `<*>` wildcards (`L295–296`), each placeholder compiles to non-greedy `.+?` separated by `\s+`, mis-splitting multi-word arguments left-to-right (`"exec <*> <*>"` on `"exec rm -rf /var/log"` yields `multiword_steal=['rm', '-rf /var/log']`).

3. **Sequential `LogMasker` Rule Clobbering (`masking.py:57–60`, `examples/drain3.ini:6–14`):**
   - `LogMasker.mask` applies `MaskingInstruction` regexes sequentially over the mutating string. Placing `NUM` ahead of `IP` corrupts `"connect 10.0.0.1"` into `'connect <:NUM:>.<:NUM:>.<:NUM:>.<:NUM:>'`, and the default `examples/drain3.ini` order (`ID`, `IP`, `SEQ`, `HEX`, `NUM`) partially corrupts RFC 4122 UUIDs whose final 12-hex-digit node field contains only decimal digits into `'req 550e8400-e29b-41d4-a716-<:NUM:>'`.

4. **Greedy Non-Backtracking `tree_search` False Negatives, Symmetric `max_children - 1` Branch Caps, and `max_children = 0` Crash (`drain.py:282–322, 365–383, 465–470`):**
   - At default `depth=4`, after `"101 req timeout"` and `"202 req timeout"` form `"<*> req timeout"` under prefix child `"<*>"` and `"login req succeeded"` creates literal child `"login"`, `match("login req timeout", full_search_strategy="never")` greedily descends `"login"`, fails `required_sim_th = 1.0`, never backtracks to sibling `"<*>"`, and returns `match_never=None` (`full_search_strategy="fallback"` recovers `match_fallback='<*> req timeout'`).
   - In `add_seq_to_prefix_tree`, when `max_children = 3`, both numeric-first arrival (`L366`, where `<*>` is created first and `len < max_children` admits two literals) and literal-first arrival (`L373–380`, where `len + 1 < max_children` admits `'alpha'` and `'beta'` before `len + 1 == max_children` routes `'gamma'` to `'<*>'`) cap literal child branches symmetrically at `max_children - 1 = 2` (`max3_keys=(num_first=['<*>', 'alpha', 'beta'], lit_first=['<*>', 'alpha', 'beta'])`); arrival order instead determines *which* tokens claim the `max_children - 1` literal slots, while setting `max_children = 0` skips `L374–379` when `<*>` is absent and crashes at `L382` (`cur_node.key_to_child_node[self.param_str]`) with `KeyError('<*>')`.

#### 1.2 Evaluator Metric Gaming (`GA`, `PA`, `FGA`, `FTA`) & Scale Effects (`LogPai`, `Khan et al. ICSE '22`, `Loghub-2.0 ISSTA '24`)

Let $M$ denote the sequence of evaluated log messages ($|M|$ total log lines), $O$ denote the set of distinct ground-truth oracle templates ($|O|$ oracle templates), and $T_{\text{pred}}$ denote the set of distinct predicted clusters/templates ($|T_{\text{pred}}|$ predicted clusters):

- **Metric Definitions & Complexity (`logpai/logparser@d9d41807` `logparser/utils/evaluator.py:45–49, 86–101`; `Khan et al., ICSE '22 §§2.1, 3.1.1`; `logpai/LILAC@163d199f` `benchmark/logparser/utils/evaluator.py:61–98`, `PA_calculator.py:64–83`):**
  - **Grouping Accuracy (`GA`):** Fraction of messages in $M$ whose predicted cluster induces an exact partition bijection with an oracle cluster—computed without inspecting template text (`LogPai` labels `GA` misleadingly as `Parsing_Accuracy` at `evaluator.py:45–49` via an $O(|T_{\text{pred}}| \cdot |M|)$ full-series scan per predicted cluster at `L86–99`, whereas `LILAC`'s `evaluator.py:78` executes an $O(|O| \cdot |M|)$ full-series scan per ground-truth group—e.g., $|O| = 1,241$ times $|M| = 16,601,745$ lines on `Thunderbird`).
  - **F1 of Grouping Accuracy (`FGA`, `Jiang et al., ISSTA '24 §4.1`):** Harmonic mean of template-level grouping precision $\text{PGA} = N_c / |T_{\text{pred}}|$ and recall $\text{RGA} = N_c / |O|$, where $N_c$ is the count of strictly bijective clusters.
  - **Message-Level Parsing Accuracy (`PA`) & Template-Level `PTA` / `RTA` / `FTA` (`Khan et al., ICSE '22 §3.1.1`):** `PA` requires exact character-for-character string equality (`PA_calculator.py:71`) between predicted and oracle templates on each line; `PTA` $= |\{t \in T_{\text{pred}} : \text{corrOT}(t) = \{t\}\}| / |T_{\text{pred}}|$, `RTA` uses denominator $|O|$, and `FTA` is their harmonic mean.
- **Empirical Collapse on `Loghub-2k` (`Zhu et al., ICSE-SEIP '19`) and `Loghub-2.0` (`Jiang et al., ISSTA '24`):**
  - Across the 16 `Loghub-2k` datasets (`2,000` lines/system sampled from `440M` lines / `77 GB`), `Khan et al.` (`Tables 5–6`, pp. 1101–1103) show `Drain` achieves `GA = 0.87` (`0.86` with Oracle Template Correction) yet drops to **`PA = 0.29` (`0.34`), `PTA = 0.27` (`0.29`), and `RTA = 0.29` (`0.31`)**, with `19.4%` over-generalized (`OG`), `32.6%` under-generalized (`UG`), and `20.6%` mixed (`MX`) templates (`LFA`: `52.7% OG`; `LogCluster`: `72.9% UG`; `MoLFI`: `82.5% MX`).
  - Across all 14 `Loghub-2.0` datasets (`logpai/loghub-2.0@ac4aad2e`: **`50,416,620` logs** and **`3,488` oracle templates**, `mean = 249.143`, vs. **`1,147` templates**, `mean = 81.929` on matched `Loghub-2k`), `RQ2/effectiveness_results.csv` and `efficiency_results.csv` show: (i) `IPLoM` on `HDFS` (`11,167,740` logs) achieves **`GA = 1.000 / 0.961` and `FGA = 1.000 / 0.721`** while scoring **`PA = 0.000 / 0.000` and `FTA = 0.000 / 0.000`**; (ii) `Drain` on `OpenStack` (`207,632` logs) increases **`GA: 0.733 -> 0.752`** while collapsing **`FGA` `16.7x` (`0.117 -> 0.007`) and `FTA` (`0.018 -> 0.002`)** (14-dataset mean `FGA: 0.740 -> 0.550`, `FTA: 0.280 -> 0.280`); and (iii) `LogPPT` drops `GA: 0.760 -> 0.560`, `FGA: 0.860 -> 0.590`, `FTA: 0.640 -> 0.490` while requiring `12,133.69 s` on `HDFS` (vs. `Drain` `1,123.34 s`) and `27,008.59 s` on `Thunderbird`.
- **Controlled Reproduction (`Probe 2`, `[illustrative analytical model]`, `Basis: derived`):** Over a 1,000-line skewed log sequence (`|M| = 1,000`: `950` lines across `2` heartbeat templates + `50` lines across rare error templates):
  - *Opaque-template exact partition (`Case A`):* `GA = 1.0, FGA = 1.0` vs. **`PA = 0.0, FTA = 0.0`**.
  - *Rare-error singleton fragmentation (`Case B`, `|O| = 12`, `|T_pred| = 52`):* Splitting `10` five-line rare error templates into `50` singleton clusters yields **`GA = 0.95, PA = 0.95`** while collapsing **`FGA = 0.0625, FTA = 0.0625`**.

### 2. Distributed Trace Head, Tail, Consistent-Probability, Online Path & Retroactive Sampling

`Basis: normative + source + execution` (with unrouted $K=8$ multi-collector split-brain and the 1,200-trace `Sifter` stream tagged `[illustrative analytical model]`, `Basis: derived`)

#### 2.1 Head vs. Collector Tail vs. Retroactive Edge-Case Capture (`Canopy`, `Hindsight`, `tailsamplingprocessor@8f589e91`)

- **Architectural Trade-Offs (`Kaldor et al., SOSP '17 §§4.1–4.2`; `Zhang et al., NSDI '23 §§1, 2.3, 4, 5.1`):** Uniform head sampling (`0.001%`–`0.1%`, propagated via W3C `Trace Context` `traceparent` `sampled = 0x01`, `REC-trace-context-1-20211123 §3.2.2.5.1`) misses `>99.9%` of rare failures, whereas centralized collector tail sampling (`tailsamplingprocessor`) serializes and transmits 100% of spans over the network into bounded collector memory (`NumTraces`). `Hindsight` (`NSDI '23`) avoids normal-path network/serialization cost by writing spans into node-local lock-free shared-memory buffers (**`32 kB`** default buffer size, up to **`55 GB/s`** per-node throughput) and propagating lightweight RPC `breadcrumbs`, retroactively extracting **`>99%`** of symptomatic and lateral contending traces within **`100 ms`** of a trigger.
- **Exact `idbatcher.Batcher` Ring Mechanics & `NumTraces` Overflow Hazard (`processor.go:211–216, 574–575, 641–647, 731, 750–761, 867, 1200–1224, 1366–1429` & `id_batcher.go:75–101, 143–158`):**
  - `Start()` (`processor.go:211–212`) sets `numDecisionBatches := math.Max(1, tsp.cfg.DecisionWait.Seconds())` and calls `idbatcher.New(uint64(numDecisionBatches), ...)`. `idbatcher.New` (`id_batcher.go:85–90`) allocates **both** a pipe `batches := make([]Batch, numBatches)` (initialized to `nil` slots) **and** a separate `currentBatch := make(Batch, ...)` outside the pipe (`Batch` is `map[pcommon.TraceID]struct{}`, `L20`). `AddToCurrentBatch(id)` (`L95–101`) sets `b.currentBatch[id] = struct{}{}` and returns `b.takeID + uint64(len(b.batches))`. On each `CloseCurrentAndTakeFirstBatch()` tick (`L143–158`), `readBatch := b.batches[takeID % numBatches]` is popped and replaced by `b.currentBatch`, so a trace added at `takeID = 0` with `numBatches = 2` is popped when `takeID == 2`—on the **3rd** tick (`[DecisionWait, DecisionWait + tickerFrequency)` wall-clock wait).
  - When `block_on_overflow` is `false` (default) and `uint64(len(tsp.idToTrace)) >= tsp.cfg.NumTraces`, `waitForSpace` (`processor.go:630–652`) pops the oldest `TraceID` from `deleteTraceQueue` and calls `dropTrace` (`L1366–1387`), which deletes `idToTrace[id]` **without** removing `id` from `decisionBatcher` and **without** inserting `id` into `nonSampledIDCache`. By contrast, `Canopy` (`SOSP '17 §4.2`, p. 42, operating at `~1.16 GB/s` event rate with `5 traces/s` per-tenant token buckets in `§4.1` p. 41) maintains a **5-hour auxiliary `TraceID` cache** that suppresses trace re-entry after *both* normal trace completion/forwarding and 15-minute inactivity expiry or full-cache LRU eviction.
  - Exercising the 1-for-1 `IdBatcherPort` + `TailSamplingProcessorPort` (`Probe 3`: `NumTraces=100`, `num_batches=2`, `50` error root spans `1..50` evicted at `takeID = 0` by `100` benign root spans `101..200`) establishes three distinct arrival regimes for late `ERROR` child spans:
    1. **Subcase A — Same-Tick Re-Insertion (`takeID == 0`, before Tick 1 closes `currentBatch`; `tid = 1..10`):** `processTrace` (`L1214`) calls `AddToCurrentBatch(id)` while `takeID == 0`, deduplicating `b.currentBatch[id] = struct{}{}` into the **exact same `Batch` set** (`len(currentBatch) == 150`). Re-inserting `1..10` into full `idToTrace` causes `10` secondary cascade evictions (`101..110`), and Tick 3 evaluates `1..10` after the full `2` post-close ticks as rootless orphans (`same_tick_dedup_orphans=10/10`) with **`0` premature evaluations** and **`0` spurious `DroppedTooEarly` increments**.
    2. **Subcase B — Cross-Tick Re-Insertion (`0 < takeID < numBatches`, between Tick 1 and Tick 2; `tid = 11..35`):** Tick 1 has already moved `{1..50, 101..200}` into `batches[0]`, so `AddToCurrentBatch(id)` at `takeID = 1` inserts `11..35` into the new `currentBatch` (`batchID = 1 + 2 = 3`) while causing `25` more cascade evictions (`111..135`). At Tick 3 (`takeID == 2`), `batches[0]` fires the evicted roots' original deadline: `11..35` are present in `idToTrace` and get evaluated **early** relative to re-insertion (`numBatches - takeID = 1` post-close tick instead of `2`, risking missing sibling late spans; `cross_tick_early_orphans=25/25`), and `releaseSampledTrace` (`L1414`) deletes `11..35` from `idToTrace`. Then at Tick 4 (`takeID == 3`), `batches[1]` pops `{11..35}` again, sees `!ok` on `idToTrace` (`L751–753`), and increments `idNotFoundOnMapCount++` (`ProcessorTailSamplingSamplingTraceDroppedTooEarly`, `L867`) **`25` times (`spurious_sampled_drops=25`) even though those `25` orphan traces were already sampled and exported**!
    3. **Subcase C — Post-Deadline Re-Insertion (`takeID >= numBatches + 1`, after Tick 3; `tid = 36..50`):** Tick 3 records `15` `DroppedTooEarly` increments on `36..50` plus `35` on cascade-evicted benign traces `101..135` (`50` at Tick 3 + `25` spurious at Tick 4 = **`dropped_too_early=75`**). When `36..50`'s `ERROR` children arrive after Tick 3, uncached `dropTrace` lets all `15` re-enter `idToTrace` and export at Tick 6—yielding **`orphan_error_traces=50/50` and `complete_error_traces=0/50`** (vs. `canopy_5h_cache=50` drops, `0` cascade evictions, and `0` orphans).
  - **Post-Decision Late `ERROR` Drops & `NopCache` Hook Multiplication (`processor.go:618–623, 1313–1315, 1418–1429`):** Once a trace without early errors is decided `NotSampled` and cached in `nonSampledIDCache`, any slow downstream timeout `ERROR` span arriving after `decision_wait` is silently dropped by `processCachedTrace` (`late_post_decision_err_dropped=True`). Conversely, if `nonSampledIDCache` is disabled (`NopCache`), `releaseNotSampledTrace` (`L1425–1428`) never deletes `idToTrace[id]`, causing every subsequent late span in `processTrace` (`L1313–1315`, marked `// TODO: I don't think this is correct?`) to re-fire `nonSampledHooks` (`nop_cache_hooks=3`).

#### 2.2 56-Bit Consistent Probability Sampling, `sample_on_first_match` Bias & `sharded_processor` Skew

- **56-Bit `Rejection Threshold` `T` Precision Variants (`opentelemetry-specification@c216b822` `tracestate-probability-sampling.md:8, 79–126, 389–497` & `pkg/sampling/{probability.go:33–82, threshold.go:14, 18, 99–122}`):** Under `Status: Development`, spans carry 56-bit randomness $R \in [0, 2^{56})$ (`rv`) and rejection threshold $T \in [0, 2^{56}]$ (`th`, trailing hex zeros stripped), sampling iff $R \ge T$ and guaranteeing nested trace completeness whenever $p_2 \ge p_1 \implies T_2 \le T_1$ (`nested_violations=0` across `10,000` draws). At $p = 0.01$, `ProbabilityToThresholdWithPrecision` produces four distinct values: unrounded floor $\lfloor 0.99 \cdot 2^{56} \rfloor = \text{0xfd70a3d70a3d70}$, collector 14-digit rounding **`'th:fd70a3d70a3d71'`**, recommended SDK default `precision=4` (`L435, 450`) **`'th:fd70a'`** (`adjusted_count = 99.997711`), and `precision=5` (`L105, 450`) **`'th:fd70a4'`** (`adjusted_count = 100.000095`). When `useTracestate` is enabled on spans lacking both `rv` and `th`, `probabilistic.go:91–108` falls back to salted `FNV-1a` over `TraceID`.
- **`sample_on_first_match` + `useTracestate` Adjusted-Count Bias (`processor.go:182–187, 935–952`):** Unbiased multi-policy composition requires advertising $\min_i T_i$ (`L936`). Enabling `sample_on_first_match: true` when Policy 0 (`1%` probabilistic, `th:fd70a4`, weight `100.000095`) precedes Policy 1 (`status_code=ERROR`, `th:0`, weight `1.0`) terminates evaluation at Policy 0 for the `1%` of error traces satisfying $R \ge T_{0.01}$, inflating estimated error counts across `100` true error traces from `100.0` to **`199.0`**.
- **`Composite` First-Match Starvation, `sharded_processor` Division Skew & Unrouted Split-Brain (`composite.go:103–135`, `sharded_processor.go:51–58, 107–158, 233–247`):**

  - Under `Probe 3`'s `[illustrative analytical model]` (`Basis: derived`), round-robin export across $K = 8$ unrouted collector pods fractures $1 - (1/8)^{6-1} = \mathbf{0.999969}$ of 6-span traces and isolates a leaf `ERROR` span from its root span with probability **`0.875`**, requiring `TraceID`-keyed routing (`loadbalancingexporter` + `SplitMix64` `traceIDToShard` at `sharded_processor.go:239–246`).

#### 2.3 Unbiased Pre-Sampling Online Path-Embedding Learning (`Sifter`, `Las-Casas et al., SoCC '19`)

`Sifter` (`SoCC '19 §§5.1–5.5`, pp. 316–320) extracts length-$N = 5$ causal paths from each trace DAG, predicts the center node from the concatenated $(N-1) \times P$ ($P = 10$) context embeddings via a 2-layer softmax network, scores trace surprise against a sliding window of $k = 50$ recent trace losses via $\rho = \min\!\left(1, \frac{w_{k+1}}{\sum_{j=1}^{k+1} w_j}(k+1)\alpha\right)$ where $w_j = L_j - \min_m L_m$, and maintains an unbiased common-path baseline **without importance weights** by running unweighted SGD (`lr = 0.01`) on **every incoming trace *before* making the sampling decision** (`§5.4–5.5`, p. 318: *"This approach would fail if we only built the model using traces that are sampled"*). Across `70,966` non-isomorphic `HDFS` trace DAGs (`Avg. Nodes = 1,428`, `Avg. Labels = 38`, `Avg. Walks = 2,547`) and `15,148` `DeathStar` traces (`Avg. Nodes = 127`, `Avg. Labels = 82`, `Avg. Walks = 155`, `Table 1`), `Sifter` boosts `0.5%` rare `HDFS` writes at $\alpha = 0.01$ to **`0.3325`** vs. **`0.0084`** on common reads (`39.6x` over uniform head sampling, `Fig. 5`) and reduces cluster-balance MSE from `404.22` to `119.91` (`Table 2`). `Probe 4`'s `[illustrative analytical model]` (`1,200` traces, `0.5%` rare write DAGs, `alpha=0.01, lr=0.05`) reproduces this invariant: pre-sampling SGD yields **`mean_read_prob=0.0066`** and **`mean_anomaly_prob=0.4575` (`45.75x` enrichment)**, whereas updating weights only on post-sampled traces starves common-path learning and collapses enrichment **`11.52x` down to `3.97x`** (`mean_read_prob=0.0093, mean_anomaly_prob=0.0397`).
