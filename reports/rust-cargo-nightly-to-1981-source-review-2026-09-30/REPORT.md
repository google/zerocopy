# Rust/Cargo nightly cohort against stable 1.98.1: bounded source review

## Summary

The prior [581-report version inventory](support/version-inventory-ebcdcad-581.csv) selected 51 packages for the `Rust/Cargo/rustc nightly-2026-05-31` cohort. At frozen reference commit `d36bc9c6d21837e9881cde82a67ce72af50d415f`, all 51 remain present and five other report packages have been added. The [matrix](support/matrix.json) retains every selected report path, frozen report and metadata hashes, exact section/line claim excerpt, exact original subject identities, component-specific old commit links where provided, and the stable target. The [offline checker](support/check_matrix.py) verifies the inventory SHA-256, each row against the frozen Git objects, and the five additions against the 581-report [baseline path set](support/baseline-report-paths.txt) and 51-row [selector](support/frozen-cohort.csv).

This is **not a full 51-report revalidation**. One narrow R559 volatile-memory clause is supported by the official 1.98.1 standard-library documentation and commit-pinned source context. R240 was already pinned to Rust and Cargo 1.98.1 in its frozen report and is marked `already_current`, not a newer-version result. The other 49 rows are **unresolved** at the stable target. No Rust or Cargo compiler/build/runtime process was run for this review; every row is marked `unexecuted_in_this_review`. In particular, the selected R559 clause does not establish full volatile behavior equivalence, and no old Rust, Cargo, Charon, Aeneas, or Anneal runtime observation is generalized to a new toolchain.

## Applicability and component identities

As of 2026-09-30, the [official Rust release list](https://github.com/rust-lang/rust/releases) marks [Rust 1.98.1](https://github.com/rust-lang/rust/releases/tag/1.98.1) as latest stable. Its rustc/source commit is [`rust-lang/rust@48a229ceaefd4985c50990b14116b6d856af0985`](https://github.com/rust-lang/rust/commit/48a229ceaefd4985c50990b14116b6d856af0985). The official [Cargo documentation](https://doc.rust-lang.org/stable/nightly-rustc/cargo/version/index.html) separately identifies **Cargo 1.98.1**. Its header displays `48a229cea`, the Rust bootstrap/toolchain commit; the [Cargo version source](https://doc.rust-lang.org/stable/nightly-rustc/src/cargo/version.rs.html) distinguishes the Cargo Git commit field from the version injected by bootstrap. This review did **not** establish the separate `rust-lang/cargo` source checkout commit used by the 1.98.1 distribution. `stable_cargo.source_revision` is therefore `null` in every matrix row, and no Cargo source delta is claimed.

The old side is not one interchangeable nightly commit. The frozen report metadata directly names `rust-lang/rust@14210df0e27ccd7d9e6a05b8085cbd438e4bbc65` in 44 subject entries, `rust-lang/rust@f8a08b688cbe60acc386ed1fbd1b7cbaaf5576b1` in five, and the already-stable 1.98.1 commit in one. Two subject entries directly name `rust-lang/cargo@fbb61be30e5f9ac3a6ad58e56a5c0f5db2d2b3ef`. Other reports encode binary hashes or composite subjects instead of separate repository revisions. The matrix preserves their exact metadata, rather than replacing a missing component commit with a neighboring report's pin. The old [Rust 14210df0](https://github.com/rust-lang/rust/commit/14210df0e27ccd7d9e6a05b8085cbd438e4bbc65), [Rust f8a08b68](https://github.com/rust-lang/rust/commit/f8a08b688cbe60acc386ed1fbd1b7cbaaf5576b1), and [Cargo fbb61be3](https://github.com/rust-lang/cargo/commit/fbb61be30e5f9ac3a6ad58e56a5c0f5db2d2b3ef) links identify those old sources; their presence is not evidence of stable-version behavior.

The baseline selector came from `version-inventory-ebcdcad-581.csv` (SHA-256 recorded in the matrix) at reference commit `ebcdcadb63fefd1e6c0f46cb2030270ae3232837`, which categorized 51 rows under this exact cohort. ## Findings

### R559: one selected volatile clause remains documented

The selected exact R559 excerpt says: “Volatile does **not** make an access atomic and does not provide inter-thread synchronization.” Its original report ties the claim to [`rust-lang/rust@f8a08b688cbe60acc386ed1fbd1b7cbaaf5576b1` `library/core/src/ptr/mod.rs`](https://github.com/rust-lang/rust/blob/f8a08b688cbe60acc386ed1fbd1b7cbaaf5576b1/library/core/src/ptr/mod.rs) and records old Git blob SHA-1 `ff2c18d685b65832c296731f23f1664779b874f2`. The [official 1.98.1 `read_volatile` documentation](https://doc.rust-lang.org/stable/std/ptr/fn.read_volatile.html) still states that volatile access is non-atomic and supplies no inter-thread synchronization; its page identifies std 1.98.1 and Rust commit `48a229cea`. The [commit-pinned stable source page](https://github.com/rust-lang/rust/blob/48a229ceaefd4985c50990b14116b6d856af0985/library/core/src/ptr/mod.rs) is the corresponding source context. This is continuity of **that selected documented clause only**. The report's other claims about provenance, target load splitting, alignment, ownership, MMIO, and hardware behavior were not fully compared or executed at 1.98.1.

### R240: already at the stable version

R240's frozen subject metadata names the [same Rust 1.98.1 commit](https://github.com/rust-lang/rust/commit/48a229ceaefd4985c50990b14116b6d856af0985) and records a Cargo executable at version 1.98.1 with its own binary SHA-256. It is retained in the 51-row reconciliation because the baseline inventory classified it there, but a nightly-to-stable migration claim would be false for this row. Its prior local observation stays scoped to its report fixture; it was not rerun here.

### Remaining 49 rows and source hashes

The remaining 49 selected passages are `unresolved`. The passages index what must be revisited, not claims of source persistence or change. Some frozen reports are normative/source analyses; others contain direct Rust/Cargo/Charon/Aeneas or product-adjacent experiments. A stable release date, documentation heading, and an unrelated source change cannot decide those claims. The matrix records `unexecuted_in_this_review` for every row.

Forty-two frozen reports mention one or more 40-hex Git blob SHA-1 values; the checker re-extracts those mentions from each frozen report. These are **old-source identifiers reported by the original authors**, not freshly recomputed bytes or stable-source hashes. The new source pages were inspected remotely without acquiring raw source files, so no new source snapshot SHA-256 is supplied. The matrix uses `null` for both old/new raw-byte snapshot SHA-256 fields, rather than inventing hashes. Further source review should use commit-pinned files for the exact report claim, independently resolve Cargo's 1.98.1 source checkout, and record actual raw-file hashes if a later resource admission permits source acquisition.

The old reports and all Anneal issue/product gates remain unchanged. A subsequent behavioral recheck needs a separately admitted stable toolchain and a claim-specific fixture; its observations must be distinguished from source documentation and from Anneal integration guarantees.
