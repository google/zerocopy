# Agent Test-Driven Development, Property-Based Testing, Mutation-Guided Test Generation, and Specification-First Coding Workflows

## Summary

Primary-source inspection of 27 peer-reviewed papers and technical reports (2022–2026), 10 pinned public repositories, and a deterministic four-probe verification suite establishes five operational invariants for steering coding agents with tests, properties, mutants, and executable specifications:

1. **Test-First Steering Helps Only When Oracles Are Independent or Programmatic, Whereas Same-Context or Unverified Self-Tests Degrade Correctness:** Supplying immutable human/reference tests upfront lifts private-suite `pass@1` by `+7.27 pp` to `+38.60 pp` (`LLM4TDD`, subject to cascade censoring on already-solved public tasks), and interactive discriminative test selection (`TiCoder` $s_{\text{discr}}$) yields `+33.50 pp` (`TiCoder-Output`) and `+26.33 pp` (`TiCoder-PassFail`) unweighted mean gains across 7 models / 14 rows (`81.56% > 80.88%` all-tests-in-prompt at $k = 1$, reversing at $k = 5$ where all-tests hits `91.58%`). Conversely, authoring tests *after* or alongside faulty code inflicts severe contextual drag on subtle `<50%`-failing bugs (`Konstantinou et al.`: `Prompt + Code` `13.0%` collapses to `Code only` `11.1%` vs. `Prompt only` `26.2%`, `-13.2 pp`; stateful same-session history `25% → 14%`; `AgentCoder` single-session test accuracy `89.9% → 51.8%`), while pre-fix repository issue tests still fail on the golden fix `73.0%` of the time (`TDD-Bench Verified` `GPT-4o Auto-TDD`: `286/392`).
2. **Self-Debugging Obeys a Difficulty-Dependent Poisoning Boundary $p_0^*(D)$, While Low Attack Rates Trigger Premature Halts:** Compounding per-case output errors across 10 zero-shot self-generated tests reduces empirical whole-suite oracle validity to **`44.44%–59.15%`** (`Chen et al. ACL 2025` Table 3: `Claude-3.5-Sonnet HumanEval` `89.14%` output acc $\implies$ `31.68%` i.i.d. vs. `56.71%` empirical; `LLaMA-3-70B MBPP` `82.08%` $\implies$ `13.88%` i.i.d. vs. `51.85%`; `Probe 2A`). Whenever initial accuracy exceeds $p_0^*(D) = \frac{d_{\text{TN}}(D) r_{\text{TN}}(D)}{d_{\text{TN}}(D) r_{\text{TN}}(D) + (1 - q_{\text{eff}}(D)) c_{\text{cap}}(D)}$, wrong-assertion capitulation outweighs bug repair: on `HumanEval+` ($p_0^* = 61.15\%$), `Claude-3.5-Sonnet` drops **`89.0% → 81.1% → 79.3%`**, and on `LiveCodeBench-Hard` (`Table 4`), simultaneous collapse of $q_{\text{eff}}(\text{Hard})$ and $r_{\text{TN}}(\text{Hard})$ pushes $p_0^*(\text{Hard})$ into `(6.0%, 16.4%)`—so `Claude-3.5-Sonnet` (`16.4%`) **still degrades under `Self-debug w/ detail` (`16.4% → 13.8% → 8.6%`)** while only very-low-$p_0$ models (`GPT-4o` `6.0% → 8.6%`, `LLaMA-3-70B` `2.6% → 4.3%`) gain slightly (`Probe 2B`). Defenses require removing expected-output text via CFG state tracing (`In-Execution`), $k = 8$ majority-vote abstention + suite-monotonicity backtracking (`UTDebug`, where sampling $n = 3$ `Random` tests/round at `25.29%` attack rate yields a `58.30%` raw / `25.73%` vote-kept Round-1 trigger ceiling, causing `Alg. 2` `x_d = \emptyset` early return at `22.94% < 32.94%` `No-UT` self-critique until `UTGen` raises attack rate to `56.08%` and `Pass@1` to `45.29%`; `Probe 2C`), or anchor-grounded Bayesian log-odds co-evolution (`BACE`, `Probe 1C–1D`).
3. **Bipartite Consensus Collapses Under Shared Misconceptions Unless Anchored in Log-Odds Space with Prior-Dampened Generations:** `microsoft/CodeT@35f54d60` (`agreement.py:153–156`) ranks clusters by $\sqrt{|S_x|}|S_y|$ with raw multiplicity expansion (`App. A/C/D`, vs. main-text $|S_x||S_y|$) and merges tied top clusters by multiplicity (`evaluation.py:34–42`), narrowing `sort_array`'s misconception lead from `+16.46%` (`552 vs. 474`) to `+0.85%` (`276.00 vs. 273.66`) yet still losing on `53/164` `HumanEval` tasks and trailing single-example filtering on `CodeContests` (`9.6% vs. 9.9%`; `Probe 1A–1B`). `BACE` (`wso2-incubator/BACE@d859540e`) stabilizes noisy-sensor Weight of Evidence in log-odds space (`_EPS = 1e-9`, uniform $\eta = 0.10$), deduplicates redundant test columns (`§4.5.1`, $N \le 15, M \le 20$), and evaluates candidate code against **start-of-generation test priors** (`orchestrator.py:570–575`) so colluding tests cross the exact inversion boundary $b^*_{\text{test}} = 3/19 \approx 0.1579$ ($b^*_{\text{code}} = 1/19 \approx 0.0526$) across subsequent generations—outperforming hard anchor pruning when an anchor is noisy ($b_{\text{anc}} = 0.92$) while failing predictably when anchors are trivial or corrupted (`Probe 1C–1D`).
4. **Property-Based (`PBT`) and Example-Based (`EBT`) Testing Exhibit Dual Failure Modes Linked by Shortlex Shrinking:** `EBT` fails primarily through wrong expected-value arithmetic (`59%` of `PBT-Bench` Baseline misses; `10.3%` in `Tanaka et al.`) and premature single-bug satisficing, whereas `PBT` eliminates concrete output calculation (`PGS` anchor-filtered property verification reaches `93.0%` vs. `63.0%` code synthesis on `LiveCodeBench`) but fails through generator over-restriction (`31%` `hypothesis.assume()` starvation + `31%` narrow `@given` domains in `PBT-Bench`, hitting `Hypothesis` Conjecture's exact `50`-draw `filter_too_much` and `(invalid + overrun) > 458 + 100 * valid` cutoffs, while weaker models `DeepSeek V3.2` `-3.2 pp` and `Grok 4.1 Fast` `-8.0 pp` regress; `Probe 3A`). Conjecture's `ChoiceNode` shortlex shrinker (`shrinker.py:73–94`) directly minimizes prompt counterexample tokens (`PGS`), while `Optimiser.hill_climb` skips `"string"` nodes (`optimiser.py:107–108`; `Probe 3B`). Pairing constructive `@composite` `PBT` with spec-filtered `EBT` literals captures both structural permutation/boundary bugs and exact literal regressions (`95.1%` union recall on `PBT-Bench`; `Probe 3C`).
5. **LLM Mutation Pipelines Require Two-Stage Comment-Stripping Equivalence Gates and Violate Soundness Whenever Assertions Rewrite to `PUT(input)`:** LLM fault generators produce `25%` verbatim copies and `24.4%` (`67.9%` of non-identical equivalents) misleading-comment pseudo-mutants (`Meta ACH` Table 5); stripping comments and canonicalizing ASTs before LLM equivalence judging slashes leaked equivalents `9×` (`Recall: 0.47 → 0.96`, `Precision: 0.95` [`0.962 / 0.966` after correcting Table 7's `46`-mutant `TN`/`TP` mis-accounting]; `Probe 4A`). However, pipelines that discard failing tests or rewrite assertions to `PUT(input)` (`TestGen-LLM`, `ACH`, `MuTAP Alg. 3`, `MutGen Fix_assert`) are strictly **regression oracles**: on buggy agent code, unshielded `MuTAP Alg. 3` reports `100%` illusory mutation score while cementing pre-existing bugs into the test suite; partial specification-invariant guards catch boundary, identity, and symmetry violations (`3/3`), while symmetric interior value bugs still require an independent reference or differential oracle (`Probe 4B`).

## Findings

### 1. Test-First Synthesis, Consensus Ranking, and Interactive Disambiguation

`Basis: source + derived + execution`

#### 1.1 Ground-Truth Reference Tests Upfront (`LLM4TDD`) vs. Pre-Fix Issue Test Authoring (`TDD-Bench Verified`)

1. **Human/Reference Tests Upfront (`LLM4TDD` / `TGen`, `2402.13521v2` Tables 1, 3, §3.2, §4.2–5.2):**
   - Across `MBPP` (`399` sanitized tasks), `HumanEval` (`164`), and `CodeChef` (`1,100` file-level problems stratified across 11 rating buckets, `T = 0, seed = 1106`) with `"IMPORTANT: Tests cannot be modified"` (`Fig. 3`) and a 5-attempt / 3-identical-failure remediation cap, supplying human public tests upfront plus bounded repair raises private held-out `EvalPlus` / `CodeChef` accuracy on `GPT-4 Turbo (v1106)` from `69.67% → 82.45% → 87.71%` (`MBPP+`, `+18.04 pp`), `78.66% → 87.81% → 93.30%` (`HumanEval+`, `+14.64 pp`), and `23.00% → 26.09% → 30.27%` (`CodeChef`, `+7.27 pp`; `Llama 3 70B`: `MBPP+` `46.37% → 75.94% → 84.96%`, `+38.60 pp`; `HumanEval+` `62.20% → 75.61% → 84.15%`, `+21.95 pp`).
   - **Three critical confounders:** (i) Remediation saturates by attempt 4 (`MBPP`: `11, 7, 2, 1, 0` fixes across attempts 1–5; `HumanEval`: `7, 1, 1, 0, 0`); (ii) **selective cascade censoring (`§3.2`, pp. 5–6):** `TGen` runs `Prompt+Tests` *only* on tasks that failed `Prompt-only` on public tests, masking test-induced context-dilution regressions that appear when `EXP2` (`§5.2`, `92.4%` `MBPP` and `75%` `HumanEval` canonical solutions already reach `100%` line coverage on test #1) feeds extra tests unconditionally; and (iii) `§4.2–4.3` prose mixes public-suite percentage deltas (`12.0%` / `8.5%`) with private-suite problem counts (`51/399 = 12.78%`, `15/164 = 9.15%`).
2. **Synthesizing Repository Fail-to-Pass (`F2P`) Tests Before Code (`TDD-Bench Verified`, `2412.02883v1` Tables II–VII & `IBM/TDD-Bench-Verified@3df8be06`):**
   - Filtering `SWE-bench Verified` (`500` issues) to `449` container-valid human-`F2P` tasks (`tddScore` weighting `F2P` by pooled deleted+added line coverage `(total_change - total_miss) / total_change` in `tddbench/harness/run_evaluation.py:681–689`), zero-shot full-file generation achieves only `11.4%` (`Llama-3.1-70B`, `69` syntax errors), `12.7%` (`Mistral-Large-123B`), and `18.7%` (`GPT-4o`) `F2P`.
   - `Auto-TDD` (LLM file localization at `56.3%–61.9%` Top-1 vs. `15.4%` BM25 $\to$ issue-function extraction $\to$ 3-shot AST test insertion) lifts `GPT-4o` to **`23.6%` (`106/449`, `tddScore = 22.6`)** and `Mistral-Large` to **`18.9%` (`85/449`, `tddScore = 18.3`, where `395` fail $c_{\text{old}}$ and `318` fail $\hat{c}_{\text{new}}$: `310` persistent fail-to-fail + `8` pass-to-fail regressions)**, while `Llama-3.1-70B` drops to `8.2%` (`37/449`). Crucially, on `GPT-4o Auto-TDD`, **`392/449` generated tests fail on $c_{\text{old}}$, yet `286/392 (73.0%)` still fail on the human golden fix $\hat{c}_{\text{new}}$** due to hallucinated assertions, wrong API signatures, or overspecified expectations—and revealing $\hat{c}_{\text{new}}$ (`Table VI`, "write first, test later") barely moves `GPT-4o` (`23.6% → 24.3%`).
   - **Execution-scope & statistical nuances (`Table IV`, `§V.D`, `Table VII`):** On `SWE-Bench Lite` (`N = 276`, `Table IV`), `Auto-TDD` (`21.7%`) executes *only* newly contributed test functions, whereas `SWE-Agent+` (`19.2%`) and `SWE-Agent` (`16.7%`) execute the *entire* test file (penalized by pre-existing unrelated file failures, `p. 7`). At the authors' **99% confidence threshold ($\alpha = 0.01$)** (excluding `67/449` `SymPy` tasks due to `coverage.py` defects), human vs. generated `F2P` diff coverage shows **no statistically significant difference** (`Auto-TDD GPT-4o` `0.96 vs. 0.98`, $p = 0.02$; `Mistral-Large` `0.97 vs. 0.99`, $p = 0.04$; `Zero-shot GPT-4o` `0.92 vs. 0.95`, $p = 0.01$), whereas **non-`F2P` tests** collapse sharply (`0.49–0.59 vs. 0.93–0.94`, $p < 0.001$, though `35%` still hit `1.00`).

#### 1.2 Bipartite Consensus (`CodeT`), Programmatic Oracles (`ALGO`, `TestChain`, `R2E`), and Interactive `TiCoder`

1. **`CodeT` Paper-vs.-Repo Formula, Tie Merging, and Hard-Task Reversal (`2207.10397v2` §2.2, §4.4, App. A/C/D/G & `microsoft/CodeT@35f54d60`; `Probe 1A–1B`):**
   - While main text `§2.2` writes cluster score $f(S) = |S_x||S_y|$, `CodeT/src/agreement.py:99–112,153–156` (documented in `App. A/C/D`) expands duplicate code and assertion samples (`No/No` deduplication) and scores clusters by **$\sqrt{|S_x|}|S_y|$**, while `CodeT/src/evaluation.py:34–42` (`_turn_solution_scores_into_choose_count`) merges equal-score clusters and samples uniformly by multiplicity (`Probe 1A`).
   - Square-root damping widens the misconception tolerance threshold from $p_{\text{misc}}/p_{\text{true}} > |T_{\text{true}}|/|T_{\text{misc}}|$ to $(|T_{\text{true}}|/|T_{\text{misc}}|)^2$ (`Probe 1B`), shrinking `Fig. 5b` `sort_array`'s buggy lead from `552 vs. 474` (`+16.46%`) to `276.00 vs. 273.66` (`+0.85%`) and lifting `code-davinci-002` zero-shot `HumanEval` `47.0% → 65.8%`. However, `CodeT` still misranks `53/164 (32.3%)` `code-cushman-001` tasks where a correct program was sampled, and on **1-shot `CodeContests` (`App. G Table 9`)**, filtering on the single prompt example alone (`Baseline Filter`: **`9.9%`**) **beats `CodeT Filter` (`9.6%`, `-0.3 pp`)** because noisy generated assertions outvote valid solutions.
2. **Programmatic Oracles (`ALGO` `2305.14591v3`; `TestChain` `2404.13340v1`; `R2E` `r2e-project/r2e@bcbed156`):**
   - Synthesizing an exhaustive brute-force reference verifier $f_{\text{brute}}$ (`ALGO`: `88%` oracle correctness, `8×` over `Codex` and `2.6×` over `CodeT` on `CodeContests`) or decoupling input design from a ReAct Python interpreter `Calculator` (`TestChain`: lifting `GPT-4` `LeetCode-hard` test accuracy `57.95% → 71.79%`, `+13.84 pp` over `AgentCoder`) eliminates token-level mental arithmetic errors. Offline benchmark builders (`R2E`) similarly execute generated input setups against existing repository ground truth.
3. **Interactive Discriminative Querying (`TiCoder` `2208.05950v2`, `2404.10100v2` Tables IV–V, §V–VIII & `microsoft/TiCoder@3362f001`):**
   - `src/test_ranking.py:125–149` (`rank_tests_by_distinguishing_power`) isolates semantic `AssertionError` (`L139`) from runtime crashes so invalid precondition-violating inputs do not pollute $s_{\text{discr}}(t) = \min(|G^+_t|, |G^-_t|) / \max(|G^+_t|, |G^-_t|)$. *(Source-audit note: `rank_tests_by_weighted_distinguishing` at `L42, L52` has a latent `defaultdict((int, int))` + key-type crash, and `src/dynamic_pruning.py:31` writes `passes = passes or result[0] or result[1] == AssertionError`, retaining `AssertionError`-failing codes and pruning only universal runtime crashes.)*
   - Across all **7 evaluated models / 14 benchmark rows** in `2404.10100v2` `Table IV` (`text-davinci-003`, `code-davinci-002`, `CodeGen-6B`, `CodeGen2.5-7B`, `GPT-3.5-turbo`, `GPT-4-turbo`, `GPT-4-32k`; zero `StarCoder` runs—`v2` prose strings `"four LLMs"` and `+45.97%` / `+45.73%` / `38.55%` are stale `v1` revision artifacts), unweighted mean 5-query gain is **`+33.50 pp`** (`TiCoder-Output`) and **`+26.33 pp`** (`TiCoder-PassFail`). On `MBPP` (`GPT-4-32k`, `Table V`), 1 user query (`TiCoder-PassFail` `81.56%`) beats `Prompting w/ Tests` (`80.88%`) at **`pass@1` ($k = 1$) only**; at **`pass@5` ($k = 5$)**, `Prompting w/ Tests` reaches **`91.58%`** vs. `TiCoder-PassFail` `86.42%` (`TiCoder-Output` `91.81%`). In the $N = 15$ user study (`§V.B, §VI.A`, fixed 5-candidate pools of 4 buggy + 1 correct code, halting pruning at 3–4 survivors), only binary `TiCoder-PassFail` (`0.84 vs. 0.40`, $p = 0.001$) achieved statistical significance; `TiCoder-Output` (`0.64`) did not because half of participants supplied wrong edge-case outputs on `FirstMissing`.

### 2. Self-Debugging Oracle Poisoning, Contextual Drag, and Prior-Dampened Bayesian Co-Evolution

`Basis: source + derived + execution`

#### 2.1 Difficulty-Dependent Poisoning Boundary $p_0^*(D)$ (`Chen et al. ACL 2025`)

1. **Correlated 10-Test Suite Invalidity (`2501.12793v1` Tables 1–3; `Probe 2A`):**
   - While 2 rounds of **oracle** self-debugging lift `HumanEval+` across all 4 models (`Claude-3.5-Sonnet` `89.0% → 94.5%`, `GPT-4o` `87.8% → 92.1%`, `LLaMA-3-70B` `73.8% → 81.7%`, `Qwen2.5-Coder-7B` `81.7% → 84.1%`), `Self-debug w/ detail` over 10 zero-shot self-generated tests **degrades `HumanEval+` on every model**: `Claude-3.5-Sonnet` **`89.0% → 81.1%` (Iter 1) `→ 79.3%` (Iter 2, `-9.7 pp`)**, `LLaMA-3-70B` `73.8% → 66.5% → 67.1%` (`LCB-Easy`: **`72.3% → 56.6%`, `-15.7 pp`**), `Qwen2.5-Coder-7B` `81.7% → 75.6%`, and `GPT-4o` `87.8% → 84.1% → 85.4%`.
   - Verbatim `Table 3` (`L389–395`) shows why (`Probe 2A`): although input validity is `94.53%–97.68%` and intra-task correlation keeps empirical 10-test suite validity `+25.03 pp` to `+37.97 pp` above i.i.d. $q_{\text{out}}^{10}$, **41%–56% of whole 10-test suites still contain wrong expected outputs**:
     - `GPT-4o-2024-05-13 HumanEval`: `89.77%` per-case output $\implies$ `33.99%` i.i.d. vs. **`59.15%`** empirical suite validity.
     - `Claude-3.5-Sonnet HumanEval`: **`89.14%`** per-case output $\implies$ **`31.68%`** i.i.d. vs. **`56.71%`** empirical suite validity.
     - `LLaMA-3-70B-Instruct MBPP`: **`82.08%`** per-case output $\implies$ **`13.88%`** i.i.d. vs. **`51.85%`** empirical suite validity.
     - `Qwen2.5-Coder-7B-Instruct MBPP`: **`77.33%`** per-case output $\implies$ **`7.65%`** i.i.d. vs. **`44.44%`** empirical suite validity.
2. **Exact Phase Boundary $p_0^*(D)$ and `LiveCodeBench-Hard` Degradation (`2501.12793v1` Table 4, Fig. 2; `Probe 2B`):**
   - Let $p_0$ be initial `pass@1`, $1 - q_{\text{eff}}(D)$ the false-negative trigger rate on initially correct programs, $c_{\text{cap}}(D)$ capitulation probability given a false negative, $d_{\text{TN}}(D)$ bug-detection rate on initially wrong programs, and $r_{\text{TN}}(D)$ 1-step repair probability. Post-debug accuracy is $P_1 = p_0[1 - (1 - q_{\text{eff}})c_{\text{cap}}] + (1 - p_0)d_{\text{TN}}r_{\text{TN}}$, so self-debugging hurts ($P_1 < p_0$) iff:
     $$p_0 \;>\; p_0^*(D) \;=\; \frac{d_{\text{TN}}(D)\,r_{\text{TN}}(D)}{d_{\text{TN}}(D)\,r_{\text{TN}}(D) + (1 - q_{\text{eff}}(D))\,c_{\text{cap}}(D)}$$
   - On `HumanEval+` (`Claude-3.5-Sonnet`: $p_0 = 146/164 = 89.02\%$, `Fig. 2` $\text{FN} = 33.54\% \implies q_{\text{eff}} = 62.33\%$, $\text{TN} = 4.27\% \implies d_{\text{TN}} = 38.90\%$, `Table 1` oracle $r_{\text{TN}} = 44.5\%$, and 1-DOF calibrated $c_{\text{cap}} = 0.292$), $p_0^*(\text{HE+}) = \mathbf{61.15\%} < 89.02\%$, reproducing Iter-1 `81.13%` (`-7.89 pp`).
   - **Crucial `LCB-Hard` sign check (`Table 4`, `L435–444`):** On `LCB-Hard`, `Claude-3.5-Sonnet` One-pass is **`16.4%`**, yet under `Self-debug w/ detail` it **still degrades monotonically to `13.8%` (`-2.6 pp` Iter 1) and `8.6%` (`-7.8 pp` Iter 2)** (whereas withholding wrong expected-output values in `Self-debug w/ label` gives `16.4% → 17.2% → 16.4%`), while ultra-low-$p_0$ models gain slightly (`GPT-4o`: **`6.0% → 8.6%`**, `LLaMA-3-70B`: **`2.6% → 4.3%`**). ## Boundaries

- **`unknown` — Unconfounded Contribution of Random `Hypothesis` Search vs. Anti-Satisficing Instructions in `PBT-Bench`:** Because `PBT-Bench` `Table 2` (`2605.15229v4` §6.1 `L528–531`) bundles `@given` with `"cover the specification rather than hunt for one bug"`, the exact fraction of `Opus 4.8`'s `+41.5 pp` jump attributable to input randomization alone vs. stopping-rule prompting remains unresolved.
- **`unknown` — Multi-Rater Precision of `Agentic-PBT` vs. Execution-Enabled `Proptest-AI` at Matched Sample Size:** `Naziri et al.` (`2610.34487v2` Table 5) denied build/execution feedback to `Proptest-AI` in `RQ1` and audited $n = 30$ failures per arm with overlapping Wilson 95% CIs (`[16.7%, 47.9%]` vs. `[5.3%, 29.7%]`); `Maaz et al.` (`2510.09907v1`) similarly carries a `[30.2%, 57.8%]` subsample FDR 95% CI, and `Kiele et al.` (`2609.35841`) used a single rater on its `65` `EvalPlus`-surviving mutants.
- **`known not to apply` — Fixed-Parameter Transfer of `HumanEval+` $p_0^* \approx 61\%$ to Competitive `Hard` Tasks:** On `LiveCodeBench-Hard` (`2501.12793v1` Table 4), simultaneous degradation of output-oracle validity $q_{\text{eff}}(D)$ and repair rate $r_{\text{TN}}(D)$ lowers $p_0^*(\text{Hard})$ into `(6.0%, 16.4%)`, causing `Claude-3.5-Sonnet` (`16.4%`) to degrade (`16.4% → 13.8% → 8.6%`) under `Self-debug w/ detail` (`Probe 2B`).
- **`known not to apply` — Regression Mutation Pipelines (`TestGen-LLM`, `ACH`, `MuTAP Alg. 3`, `MutGen Fix_assert`) as Pre-Existing Bug Detectors, and Partial Invariant Guards as Complete Oracles:** Enforcing pass-on-`CUT` or `expected := PUT(input)` yields `0%` detection of pre-existing `CUT` bugs and cements defects into assertions; partial specification invariants catch boundary/symmetry/identity violations but pass symmetric interior value bugs (`Probe 4B`). Likewise, `PBT` is not universally beneficial on weaker models (`DeepSeek V3.2` `-3.2 pp`, `Grok 4.1 Fast` `-8.0 pp` on `PBT-Bench`), and `Agentic-PBT` does not replace domain fuzzers (`MetaMut` `23` vs. `4` compiler crashes, `0` overlap).
- **`unsupported` — Single-Test `UTDebug` Halt Ceilings, Instantaneous Single-Pass `BACE` Inversion, `PGS` `EvalPlus` Equivalence on `HE`/`MBPP`, and `Clover` Uncompiled Code Equivalence:** Treating `UTGen`'s 1-test attack rate (`25.29%`) as a 3-test Round-1 ceiling contradicts `UTDebug Alg. 1` ($n = 3$, raw ceiling `58.30%`; `Probe 2C`); feeding Step-2 `BACE` test posteriors into the *same* generation's code update violates `orchestrator.py:570–575` (`Probe 1D`); `PGS` uses base `HumanEval`/`MBPP` and leaks `MBPP` test #1 (`App. B`); and `Clover` `equiv_test_code()` returns `True` on `"Uncompiled" == "Uncompiled"` (`equiv_tests.py:15–34`).
- **`not examined` — GUI/Browser End-to-End Agent Testing, Concurrency/Heisenbug Flakiness Repair, and Hardware-in-the-Loop Fuzzing:** Visual DOM/Playwright oracle synthesis, non-deterministic thread-schedule exploration, and embedded/RTL mutation workflows were outside scope.
