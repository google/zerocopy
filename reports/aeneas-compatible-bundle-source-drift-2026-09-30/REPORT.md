# Aeneas compatible-bundle source drift across 169 reference reports

## Summary

The Aeneas `nightly-2026.06.03` to `nightly-2026.09.30-0855ce1` comparison has concrete **source-contract drift**: current source adds optional `-emit-json` / `translation.json`, defaults to Lean module-system output, changes translation and proof-support regions, and selects a newer compatible Charon and Lean. The paired Charon source adds `ItemMeta.started_from`. These are source and release findings. **No newer Aeneas, Charon, Lean, Rust, generated artifact, or proof fixture was executed.** The 169-row [claim matrix](support/claim-matrix-ebcdcad-169.csv) identifies the original report section, a normalized plain-text excerpt of its opening claim, relevant source delta, bounded next probe, and tool requirement for each affected package. The [verbatim source paragraphs](support/frozen-claim-excerpts-ebcdcad-169.json) are preserved separately.

The old Aeneas tag pins Charon `a535e914…`, whose `charon/rust-toolchain` selects **nightly-2026-05-31**. A separately cached Charon `nightly-2026.06.03` checkout at `0c91ca1…` selects **nightly-2026-06-01**. The former is the Aeneas dependency; the latter is a distinct control. The new Aeneas tag pins Charon `e435e5f…`, Rust nightly-2026-09-17, and Lean 4.31.0. The standalone Charon September 30 release at `2804f2d` is another distinct revision.

## Applicability

The matrix is anchored to the 581 tracked report packages at `google/zerocopy` `reference@ebcdcadb63fefd1e6c0f46cb2030270ae3232837` (`ebcdcad`). It selects **150** reports whose inventory cohort or `REPORT.json` subjects name Aeneas and **19** additional reports whose title or opening claim names Aeneas: **169 unique paths**. Of the 169, 60 concern Aeneas or a full compatible bundle, 35 primarily concern paired Charon, 16 paired Lean, and 58 cite Aeneas contextually. The contextual rows do not acquire an Aeneas runtime claim merely by appearing in this matrix.

The source comparison uses the exact old and new Git commits in `REPORT.json`, not moving branches. The companion [source-delta note](support/source-deltas.md) maps delta codes to the upstream commit, file, or release page. The [path diff](support/source-path-diff.csv) compares full Git-blob trees, finding 536 changed Aeneas paths and 992 changed Charon paths. A changed path is a recheck signal, not evidence of a changed executable result.

The bounded source probe used only locally cached Git objects and Python standard-library code. The September Aeneas archive, Lean 4.31.0, and paired Rust nightly-2026-09-17 were absent from the enumerated local tool cache. No download or installation was attempted.

## Findings

### Source contracts changed

At the old Aeneas commit, `src/Main.ml` has neither `-emit-json` nor `-use-lean-modules`. At the new commit, `src/Main.ml` exposes both, `src/Config.ml` sets `emit_json` false and `use_lean_modules` true by default, and `src/EmitJson.ml` plus `documentation/emit-json.md` define a `translation.json` representation with declaration IDs, Rust/Lean names, Lean files, source locations, and version fields. Current `src/Main.ml` still specifies one required `.llbc` file and says it processes one file at a time. This establishes a source-level CLI and representation delta; it does not establish what bytes a release executable emits for a particular fixture. **Basis: source + documentation.**

The two Aeneas `charon-pin` files select `a535e914…` and `e435e5f…`; the two Aeneas `backends/lean/lean-toolchain` files select Lean 4.30.0-rc2 and 4.31.0. The respective *paired* Charon `charon/rust-toolchain` files select nightly-2026-05-31 and nightly-2026-09-17. The new Charon `charon/src/ast/meta.rs` contains `ItemMeta.started_from` where the old paired revision does not. This establishes source-level dependency and AST-field drift, not LLBC serialization or compatibility outcomes. **Basis: source.**

The inspected Aeneas history also contains targeted changes to trait-method/signature handling, Lean identifier escaping, shared/nested borrow joins, loops, closure regions, Lean models, and proof tactics. The exact commits and changed source paths are linked in [source-deltas.md](support/source-deltas.md). Their relevance to each old result is recorded per matrix row. A source fix title does not demonstrate that any old reproducer now passes or that a generated proof has the same proposition or trust dependencies. **Basis: source + derived relevance.**

It also checked all 169 unique matrix paths, the 150/19 selection split, explicit `runtime_status` labels, and 536/992 changed-path counts. This directly prevents the May 31 versus June 1 confusion caught by the source checker. **Basis: derived process refinement from the pinned files and failed first assertion.**
