# I061: local Rust position projection into Lean goal/RPC queries

Observed 2026-09-29 with pinned nightly rustc and direct Lean 4.30.0-rc2 `--server`. A tiny **local Python harness** reads three `// ` Lean lines between explicit markers in a valid Rust file, emits `Projected.lean` with two scaffold lines, and records a line/column map. The Rust file compiled to metadata. This is a minimal locator and protocol adapter, **not** Anneal parsing, an editor extension, or an InfoView UI.

The harness started from the Rust **byte** range for `helper` in the theorem. The same line contains `café 🦀` before that use: 55 UTF-8 bytes versus 52 UTF-16 code units precede it in the projected Lean line. A direct `$/lean/plainGoal` query at the mapped position returned `n : Nat`, `h : n = 7`, and `⊢ helper n = 8`. `$/lean/rpc/connect` followed by `Lean.Widget.getInteractiveGoals` returned a structured goal with tagged expressions and separate `n`/`h` hypotheses. Ordinary Rust and marker positions did not map; the generated-only `import Lean` line had no reverse Rust mapping. Byte positions inside the emoji and UTF-16 positions between surrogate halves were rejected.

At the mapped `helper` use, direct `textDocument/definition` returned one generated-Lean target and `textDocument/references` returned the declaration and use. The harness **opened the Rust source file** and reverse-mapped all three returned Lean locations to authored `helper` snippets on the corresponding Rust comment lines. A `textDocument/hover` response also identified `helper (n : Nat) : Nat`. These are protocol results and local source-file reads; no actual clickable Rust UI was rendered.

After `didClose`, a call using the old RPC session received `Cannot process request to closed file` (−32801). Reopening the same document in that server and connecting a fresh session restored both plain and structured goals. After clean server shutdown and a new server process, the old session was rejected as `Outdated RPC session` (−32900) before any new connect; a new connection again returned the structured goal. The harness's routing fence treats both prior sessions as expired regardless of accidental numeric reuse. `support/results.json` preserves all client/server JSON-RPC messages, process IDs, session IDs, returned locations and opened source snippets; `support/check.py` validates them without rerunning the server.

**I061 residuals.** This is a direct Lean protocol and local projection experiment. It does not launch the actual VS Code InfoView, render custom widgets or hyperlinks in an editor, test an Anneal LSP/MCP adapter, establish annotation ownership or production byte mappings, or measure client reconnection across a real transport. The observed process restart is a server-incarnation replacement; it does not expose an internal Lean worker identity. A real Rust-hosted InfoView and user interaction test remains necessary. The rich RPC response demonstrates data that simple text-goal forwarding omits; it does not prove that an existing InfoView can consume a Rust document URI without extension glue.

**Replay.** From this directory run `python3 support/probe.py`, then `python3 support/check.py`. The standard-library probe uses cached pinned binaries, one Lean server at a time, no installs, and replaces only this package's `support/work` and `support/results.json`. Copy the package first if the original transcript must be kept.
