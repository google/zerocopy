# Prepared Anneal archive availability and bounded missing-manifest Lake control

## Summary

The actual prepared Anneal omnibus archive needed for #3730 F04 / #3731 I089 was not present in the enumerated local checkout, `.anneal-local-tools`, or top-level Nix store. Three Nix derivation files were present, but no built archive output. The available Aeneas release tar and its mutable extracted/build tree are a different artifact. Thus this run **does not execute F04 on the real archive**.

A separate, tiny Lean/Lake 4.30.0-rc2 control reproduced the local manifest failure mechanism with empty home/cache and an OS sandbox denying writes to the prepared producer and network access. A complete manifest allowed `setup-file` and batch checking; removing the manifest made both fail at a denied Lake configuration-lock write in the producer. Removing the producer made `setup-file` fail with an explicit missing-directory error. This is component evidence only.

## Applicability

The execution subject is a one-module `probe_dep` package and a one-module `probe_consumer` on macOS arm64. The producer defines `depValue : Nat := 7`; the consumer imports it and proves `depValue + 1 = 8` by `decide`. Local binaries are the installed `leanprover/lean4@3dc1a088b6d2d8eafe25a7cd7ec7b58d731bd7cc` (`v4.30.0-rc2`) tools. The script pins `ELAN_TOOLCHAIN`, sets `LEAN_NUM_THREADS=1`, uses empty `HOME` and `XDG_CACHE_HOME`, disables the configured Lake artifact cache, runs one Lake command at a time, and limits each command to 35 seconds. Only scratch under this package was mutated. There was no network download or dependency installation.

The availability observation has a bounded search scope. `support/availability.json` records the exact checkout, local-tools, and top-level Nix-store inventories. It does not prove that no archive exists anywhere on the machine or remotely. The downloaded 61 MB `aeneas-macos-aarch64.tar.gz` has `aeneas` and `backends/` top-level members; its separately extracted tree is 8.7 GiB and has later `.lake` modifications. It is neither a built Anneal omnibus archive nor an immutable installation with the target consumer contract. Nix `.drv` files alone are build recipes, not archive payloads; `nix-store` was not on `PATH`. No Nix build was attempted.

## Findings

The local control required a complete *prepared producer*, including configuration products generated by a primer consumer. A bare `lake build Dep` was insufficient under strict producer-write denial: the first attempted complete-manifest consumer still needed to create the producer configuration directory. The retained successful run first prepared that configuration state with a writable primer, then froze producer writes through macOS `sandbox-exec`. This preparation distinction matters when translating the small control to a real archive. **Basis: execution**; initial setup failure was observed during probe development, while the retained `results.json` records the corrected run.

| Retained operation | Exit | Observation |
| --- | ---: | --- |
| Prepare producer and primer consumer | 0, 0 | One `Dep.olean` and producer configuration state existed before read-only consumption. |
| Fresh consumer, complete relative path manifest, sandboxed `setup-file` | 0 | `importArts.Dep` resolved to the prepared producer OLean. |
| Same consumer, sandboxed `lake env lean --json` | 0 | `firstGoal` reported no axioms. This is a batch proof result, not an interactive first-goal query. |
| Fresh consumer, **no** manifest, sandboxed `setup-file` and batch | 1, 1 | Both tried the producer's `.lake/config/probe_dep/lakefile.olean.lock` and received `operation not permitted`. |
| Rename producer out of the required path; complete-manifest `setup-file` | 1 | `probe_dep: package directory not found`. |

The producer inventory contained 16 regular files and matched byte-for-byte, by relative path, size and SHA-256, before and after the four sandboxed consumer calls. The prepared `Dep.olean` SHA-256 was `cebebbbc892381bd3920a0b12ab5e4d65f1804574357994ccb20f95f87f98f9b`. The sandbox profile explicitly denied `file-write*` below the producer and `network*`; the observed `operation not permitted` at the lock is evidence of a blocked write attempt. No general system-call trace of all reads/writes was obtained. **Basis: execution**.

The existing [small Lake relocation report](../lake-generated-workspace-readonly-probe-v4-30-0-rc2/REPORT.md) already showed a missing-manifest config-lock attempt. This run adds empty home/cache, an enforced macOS producer-write and network denial, and explicit producer removal. It does not change that report's real-archive limitation. Related [prepared-contract probes](../anneal-3730-lake-prepared-contract-2026-09-29/REPORT.md) cover other artifact families and wrong-generation cache content.

## Boundaries

**F04 / I089 remains not run at its requested scope.** The missing prerequisite is an actual prepared Anneal archive and matching consumer workspace/toolchain, already installed or supplied locally. Once available, create an empty home/cache, install the complete intended manifest before any Lake invocation, protect dependency trees, and trace configuration, batch check, server startup and the first tactic-state query. Repeat with manifest omitted and producer removed. Classify attempted shared-location writes and distinguish an unsuccessful query from a trustworthy verified theorem. This local control covered neither the real Aeneas/Mathlib graph nor server/RPC startup or a first-goal query.

**M06 is not advanced.** Its I100/I142/I158 residual asks for realistic generated graphs, matched adoption economics, and compatible-revision Rust/Charon/Aeneas/Lean golden replays to justify removing workarounds. This one-module same-version control cannot answer those questions. It did not modify or propose deleting a workaround.

The availability search and synthetic execution were on this host and date only. The sandbox's profile prohibited network access, but no network-attempt trace or independent network-denial positive control was run here; the local package had no remote dependency. The owner of the dependency could deliberately alter its permissions outside this sandbox. Read-only behavior is not an integrity proof. No claim about Anneal V1/V2 runtime behavior, actual archive contents, all Lake operations, first-goal write tracing, or cross-platform enforcement follows.
