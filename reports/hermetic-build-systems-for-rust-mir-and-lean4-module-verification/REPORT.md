# Hermetic External Build Systems for Rust MIR Capture and Lean 4 Module Verification

## Summary

Integrating unmodified Rust MIR capture and Lean 4 formal verification across heterogeneous build systems—**Bazel**, **GN/Ninja**, **Buck2**, **Cargo**, **Nix**, **CMake (Corrosion)**, and **Meson**—exposes eight concrete technical constraints verified by primary source inspection and live compiler/build execution:

1. **Cross-crate `.rmeta` SVH diamonds and MIR phase drift:** Every verification metadata flag (`--emit=metadata` vs. `--emit=link`, `-Zmir-preserve-ub`, `-Zalways-encode-mir`, `-Zmir-opt-level=0`, `-Copt-level=*`) is tracked in `rustc`'s Strict Version Hash (`Svh`). Mixing a rebuilt `.verify.rmeta` dependency with an opaque production `.rlib` that depends on the same crate causes `E0460` or `colliding StableCrateId`. Furthermore, `-Zalways-encode-mir` encodes `tcx.optimized_mir` (`MirPhase::Runtime(Optimized)`), where `RemoveUnneededDrops` still erases Miri `eval_place` UB and `CheckAlignment`/`CheckNull`/`CheckEnums` mutate dev-build ASTs unless explicitly disabled via `-Zmir-enable-passes=-CheckAlignment,-CheckNull,-CheckEnums,-RemoveUnneededDrops`. Overriding `optimized_mir` to skip `MentionedItems`/`ForceInline` ICEs `rustc_monomorphize::collector`. Clean resolution: use **out-of-band compositional `PostCleanup` capture** for non-generic boundaries (zero SVH collisions) and **sparse upward-closure metadata rebuilds** only when transparent cross-crate generic instantiation is required, keyed by `(StableCrateId, Svh, fd_sha256)`.
2. **Capture flag fidelity and zero-LLVM `required_consts` checking:** Stripping `-Copt-level=2` flips `rustc`'s `debug_assertions` and `overflow_checks` defaults from `false` to `true`, silently altering captured `PostCleanup` MIR. `-Cinstrument-coverage` injects `StatementKind::Coverage` at `1-1-011.InstrumentCoverage` before `PostCleanup`. Plain `--emit=metadata` (and even `--emit=metadata,obj` on `-O2` `cross_crate_inlinable`, `#[inline]`, and private functions) misses failing post-monomorphization `const { panic!() }` blocks (`E0080`); a 20-line BFS over `tcx.items_of_instance((inst, CollectionMode::UsedItems | MentionedItems))` inside `after_analysis` catches 5/5 cases in `1–3 ms` under pure `--emit=metadata` with `0 ms` LLVM codegen.
3. **CAS symlink forests and `$ORIGIN` materialization:** `/proc/self/maps` resolves symlinks to flat CAS paths (no `libLLVM`, `.so`, or sysroot prefix), breaking pathname-based DSO checks; closed-world `(st_dev, st_ino)` allowlisting over all `r-xp` VMAs (identifying self via function-pointer VMA lookup and performing a post-`after_analysis` pass for declared `proc_macro` `.so`s) is required. Symlinking a dynamic ELF executable with `DT_RUNPATH=$ORIGIN/../lib` directly into a flat CAS blob directory fails with `exit 127` because glibc expands `$ORIGIN` via `readlink("/proc/self/exe")`.
4. **Build-system containment limits and `.olean` deserialization RCE:** In Bazel, `no-local` is ignored by `LocalSpawnRunner`, `RemoteSpawnRunner`, and `SpawnStrategyRegistry`; `--modify_execution_info` overrides tags; default `linux-sandbox` enables network and read-only host `/`; and `darwin-sandbox` uses `(allow default)` with host reads and writable `/tmp`/`~/Library/*`. Unsigned CLI executor attestation flags are therefore spoofable. Separately, Lean 4's C++ `compact.cpp` relocates raw pointers without release bounds checks, allowing a hostile `Proof.lean` (even inside a hermetic container) to overwrite its own `.olean` and subvert C++ `.olean` loaders (`TrustedBoundary` or `lean4export`). Closing this requires a 3-action Comparator-grade split: trusted-only `ExportExpected`, sandboxed `ExportProof`, and pure memory-safe Rust `VerifyNdjson` checking canonical DAG identity against `expected_cone.ndjson` plus a pinned 34-primitive `init_primitives_cone.ndjson` (closing `nanoda_lib` unused-primitive substitution under `nat_extension`).
5. **Dual-View zero-mutation Lean 4 `module` loading supersedes binary `.olean` stubbing:** Native Lean 4 `module` writes `public theorem`s and unexposed `public def`s as `.axiomInfo` in `.olean` (`-76.2%` size on Anneal's 44-file `theory/`), whereas binary `.olean` rewriting segfaults (`rc=245`) multipart `module` loading and breaks strict 3-axiom external kernels (`nanoda_lib`). A single `importModules` loading Stage-1 `.olean`-only (`level := .exported`) plus `readModuleDataParts` on Stage-2 (`VIEW_A_SINGLE`) cuts peak RSS by `-70.6%` (`811.91 → 238.52 MiB`) and wall time by `7.7×` (`1,318.0 → 170.9 ms`), provided `subsumesInfo` (`Replay.lean:90`) is handled via fresh-name checking. Under `-DElab.async=false`, all 7 Lean outputs (`.olean`, `.olean.server`, `.olean.private`, `.ir.sig`, `.ir`, `.ilean`, `.c`) are 14/14 bit-for-bit identical across directories, path styles, `mtime`, and `LEAN_PATH`; `Elab.async=true` causes `.olean.private` divergence (`Lean.extraModUses`).
6. **Zero-axiom parameterized `D = 1` sharding and multi-output early cutoff:** Static-DAG build systems (Bazel `< 9`, GN—whose binary has zero `dyndep` support—non-IFD Nix, CMake, Meson) cannot mint dynamic execution-time SCC outputs. Expressing per-shard obligations as zero-axiom parameterized implications (`ShardObligation_i := DepSpecs_i → ShardSpec_i`) linked by function application in `Proof.Link` yields embarrassingly parallel `D = 1` compilation with `VIEW_B_AXIOMS = []` (100% compatible with `nanoda_lib`), supporting both checked-in nominal plans and fixed-$K$ bucket slots alongside Buck2 `dynamic_output_new` and Cargo. On Ninja, `restat = 1` misses early cutoff (`2/2` downstream runs) when unchanged `.olean` bytes are rewritten with a newer `mtime`, requiring a `move-if-changed` wrapper (`1/2` runs).
7. **Nix unpatched `bin/lean` loader execution and Meson introspection:** Invoking an unpatched Linux `bin/lean` via `/lib64/ld-linux-x86-64.so.2 --library-path <sysroot>/lib/lean <sysroot>/bin/lean --setup <setup.json>` produces 5/5 bit-identical module outputs while keeping `bin/lean` byte-identical to its SHA-256 lockfile. Meson's `generate_rust_target` exports complete resolved `rustc` arguments and staged `structured_sources` into `meson-info/intro-targets.json`, enabling unmodified Rust target binding without `meson.build` wrappers.
8. **Zero-`.lake` IDE-to-CI parity:** Upstream `lean --server` honors `LAKE=<shim> setup-file <file> -` and `vscode-lean4` falls back cleanly to `workspaceDir` when no `lakefile.{lean,toml}` exists, enabling one universal `anneal-project.json` + `setup-file` shim across all external build systems without `.lake` symlinks.

## Findings

### 1. Cross-Crate `.verify.rmeta` SVH Collisions, MIR Optimization Leakage, and `required_consts` Soundness

Basis: source + execution

#### 1.1 SVH Mutation and Diamond Failures

Live `rustc 1.102.0-nightly` compilation probes tested each verification flag individually against a baseline `foo` crate compiled with `-Copt-level=2 --emit=link`:

- **Flags that mutate `Svh` (`CrateHeader.hash`, `[TRACKED]`):** `--emit=metadata` vs. `--emit=link` vs. `--emit=metadata,link`, `-Zmir-preserve-ub`, `-Zalways-encode-mir`, `-Zmir-opt-level=0`, `-Copt-level=0` vs. `2`, `-Zshare-generics={yes,no}`.
- **Flags that preserve `Svh`:** `-Zno-codegen`, `-Cstrip=debuginfo`, `-Ccodegen-units=1`.

In a diamond dependency graph `bar -> foo (verify_rmeta)` + `bar -> dep_c (production .rlib compiled against production foo.rlib)`:
- Passing `-Ldependency=verify_rmeta` alone fails with `error[E0460]: found possibly newer version of crate 'foo' which 'dep_c' depends on`.
- Passing both `-Ldependency=verify_rmeta` and `-Ldependency=prod` (in either order) fails with `error: found crates ('foo' and 'foo') with colliding StableCrateId values`, even when `bar` and `dep_c` share no public types from `foo`.
- Mutating `-Cmetadata` to separate crate IDs causes `error[E0308]: mismatched types` on any shared type.
- Filename resolution probe: `lib<crate>-<hash>.verify.rmeta` succeeds in both `--extern` and `-Ldependency` (`rc = 0`), whereas `.rmeta.verify` fails with `unknown type`; segregated `verify_rmeta/` directories remain required to avoid colliding with production `.rlib`/`.rmeta`.

Two sound cross-crate resolutions follow:
1. **Tier 1 (Default — Out-of-Band Compositional Capture):** Capture each verified dependency `foo` independently at true `MirPhase::Runtime(PostCleanup)` into a sidecar MIR artifact while compiling `bar` against 100% unmodified production `.rlib`/`.rmeta` files (zero SVH collisions, zero upward-closure rebuilds).
2. **Tier 2 (Opt-In — Sparse Upward-Closure Metadata Rebuild $U(B, V)$):** Needed strictly when transparent cross-crate *generic* monomorphization requires `rustc`'s `tcx.instance_mir`. Rebuild only $V$ (`verify_deps`) and their ancestors in $B$'s dependency DAG as lightweight `--emit=metadata -Zno-codegen` into segregated `verify_rmeta/` directories, leaving all non-ancestors as untouched production `.rlib`s (verified live `rc = 0`). Stop propagation strictly at `proc_macro_deps` (host plugins run at AST expansion time; even non-re-exported `#[derive]` puts the proc-macro crate in the intermediate crate's `CrateDep` table, requiring `-Ldependency=<pm_dir>` downstream). Match metadata sidecars by `(tcx.stable_crate_id(cnum), tcx.crate_hash(cnum), fd_sha256)` via unkeyed repeatable `--anneal-verify-meta <path>` rather than `<crate_name>=<path>` (which collides on multi-version diamonds and breaks on `--extern alias=...`).

#### 1.2 Unconditional Passes in `run_optimization_passes` at `-Zmir-opt-level=0 -Zmir-preserve-ub`

Auditing all 46 steps in `rustc_mir_transform/src/lib.rs` (`inner_optimized_mir` + `run_optimization_passes`) and verifying via live `-Zdump-mir=all`:
- `-Zalways-encode-mir` encodes `tcx.optimized_mir(def_id)` (`rustc_metadata/src/rmeta/encoder.rs:1839`), whose `body.phase` is **`MirPhase::Runtime(Optimized)`**, not `Runtime(PostCleanup)`.
- **`RemoveUnneededDrops` (`PassPolicy::optional(true)`):** Runs unconditionally at `-Zmir-opt-level=0 -Zmir-preserve-ub`, replacing `Drop { place, target }` with `Goto(target)` when `!ty.needs_drop(...)`—erasing Miri's `eval_place(place, false)?` UB (`rustc_const_eval/src/interpret/step.rs:658-671`).
- **`CheckAlignment`, `CheckNull`, `CheckEnums` (`PassPolicy::optional(ctx.ub_checks())`):** Run in `-Copt-level=0` (debug) builds even at `-Zmir-opt-level=0 -Zmir-preserve-ub`, injecting `Transmute(*const () -> usize)`, `UnevaluatedConst`, and `Assert`s absent from `PostCleanup`.
- **Verified mitigation:** Adding `-Zmir-enable-passes=-CheckAlignment,-CheckNull,-CheckEnums,-RemoveUnneededDrops` disables all four optional passes, leaving only four mandatory steps (`remap_mir_for_const_eval_select`, `MentionedItems`, `ForceInline`, `AddCallGuards::CriticalCallEdges`) with zero UB-erasing passes. Overriding `providers.queries.optimized_mir` to skip `MentionedItems` or `ForceInline` was empirically falsified—downstream monomorphization ICEs at `rustc_monomorphize/src/collector.rs:1384` (missing `mentioned_items`) and `collector.rs:1092` (attempt to codegen `#[rustc_force_inline]` item).

#### 1.3 Preserving `-Copt-level=*`, Stripping `-Cinstrument-coverage`, and Universal Zero-LLVM `required_consts` Checking

Live MIR dumps at `2-2-010.StateTransform.after.mir` (`Runtime(PostCleanup)`) establish:
- Stripping `-Copt-level=2` from a release command line silently flips `debug_assertions` and `overflow_checks` from `false` to `true`, changing `#[cfg(debug_assertions)]` branches and turning wrapping `Add` into `AddWithOverflow` + panic `Assert`. Keeping `-Copt-level=2 -Zmir-opt-level=0 -Zmir-preserve-ub` yields bit-identical `PostCleanup` MIR to `-Copt-level=0 -Cdebug-assertions=no -Coverflow-checks=no`.
- `-Cinstrument-coverage` runs at `1-1-011.InstrumentCoverage` (before `PostCleanup`) and injects `StatementKind::Coverage` into every basic block; capture drivers should strip `-Cinstrument-coverage`.
- **Post-monomorphization `required_consts` 5-case matrix (`fn f<T>() { const { assert!(size_of::<T>() == 8); } }` called as `f::<u8>()`):**
  - Plain `--emit=metadata`: misses `error[E0080]` (`rc = 0`).
  - Calling `tcx.collect_and_partition_mono_items(())` under `--emit=metadata` on an `rlib`: still misses `E0080` (`mono_items = 0`, because `reachable_non_generics_provider` returns empty when `!should_codegen()`, `symbol_export.rs:56`).
  - Full `--emit=metadata,obj` (with LLVM): STILL misses `E0080` on small `pub fn`s at `-Copt-level=2` (`cross_crate_inlinable`, `symbol_export.rs:114`), `#[inline] pub fn`s at `-O0`, and private functions!
  - **Universal fix (`1–3 ms`, `0 ms` LLVM, `0 B` `.o`):** Running a 20-line BFS over `tcx.items_of_instance((inst, CollectionMode::UsedItems | MentionedItems))` inside `after_analysis` seeded from all captured/selected `def_id`s catches **5/5 cases** (`opt0 pub`, `opt2 pub`, `opt0 #[inline]`, `opt0 private`, `bin main`) under pure `--emit=metadata`.
- **Sysroot `core`/`alloc`/`std`:** Stock `libcore` is compiled at `-O3` without `-Zmir-preserve-ub` (stripping `PlaceMention`, while preserving deferred `switchInt(UbChecks)` on generic `#[inline]` helpers). Rebuilding `libcore` as `.verify.rmeta` forces a 100% upward-closure rebuild of every dependency graph; model `core`/`alloc`/`std` axiomatically/spec-side (gating on `tcx.intrinsic(def_id)` to avoid bodyless `must_be_overridden` `Unreachable` stubs).
- **Crate types & Cargo `--target <host_triple>`:** Admitting `CrateType::Executable` alongside `Rlib`/`Lib` unlocks `rust_binary`, integration tests, and `--select`-scoped `--test` targets (note `--cfg test --crate-type=rlib` strips `#[test]` functions). In Cargo, passing explicit `--target <host_triple>` even on native builds guarantees 100% of target units carry `--target` and 100% of host units (`build.rs`, `proc-macro`, shared `HostDep`s) omit `--target`, with `0` extra `shared` compilations under `cargo check` and bit-identical `CARGO_CFG_*` env vars.

### 2. CAS Symlink Forests, `$ORIGIN` Materialization, and Two-Pass Closed-World DSO Identity

Basis: source + execution

- **Why pathname filtering fails in CAS symlink forests:** Live execution of a dynamically linked binary inside a simulated flat CAS symlink forest proved `/proc/self/maps` reports kernel-resolved blob paths (`/cas/ab/e504d519...`) containing zero `libLLVM`, `.so`, or sysroot substrings. Meanwhile, Fuchsia's prebuilt `librustc_driver-*.so` (`200.19 MiB`) links LLVM statically (`0` `libLLVM*.so` exists). Furthermore, `rustc-capture/src/main.rs:148-163` canonicalizing `crate_root`/`sysroot` and `capture.rs:137` (`path.canonicalize()? != path`) reject multi-file crates in CAS forests.
- **Two-Pass Closed-World `(st_dev, st_ino)` Allowlist ($M_{\text{exec}} \subseteq A$):** Identify self via function-pointer VMA lookup (handling `ld.so --library-path` launchers where `/proc/self/exe == ld.so`), open and `fstat` every logical allowed file (`{self_vma, optional <sysroot>/lib/*.so*, PT_INTERP + core libc/libm/libpthread/libdl/librt/libgcc_s}`), assert $M_{\text{exec}} \subseteq A_1$ pre-compile, and run Pass 2 in `after_analysis` permitting $A_2 = A_1 \cup A_{\text{pm}} \cup A_{\text{pm\_needed}}$ matched against `tcx.used_crate_source(cnum).dylib` (verified live: `PRE_VMAS=12 -> POST_VMAS=13` on a proc-macro crate). Hash every loaded proc-macro `.so` in `CaptureManifest.json` and record in-process proc-macro trust explicitly.
- **Flat-CAS `$ORIGIN` failure:** Symlinking a dynamic ELF executable with `DT_RUNPATH=$ORIGIN/../lib` directly into a flat CAS directory fails with `exit 127` because glibc resolves `$ORIGIN` via `readlink("/proc/self/exe")`, whereas 2-hop symlinked DSOs succeed (`exit 0`) when the executable itself is a regular file or hardlink. On Buck2 local builds (`assembled_dir.symlink`), `$ORIGIN` executables require `assembled_dir.copy`; Bazel hermetic `HardlinkedSandboxedSpawn` and REAPI workers hardlink/copy regular files.
- **Path & env normalization for cross-worker RBE caching:** Normalize manifest paths into `crate/<rel>`, `out_dir/<rel>`, and `workspace/<rel>` (or `workspace/gen/<rel>` stripping `bazel-out/<cfg>/(bin|genfiles)/`), and allow `OUT_DIR`/`CARGO_MANIFEST_DIR` as macro path prefixes while rejecting unnormalized host-path escapes into runtime MIR `&str` constants.
- **Mid-cycle nightly drift:** Two `rustc` nightlies sharing the same `major.minor` (`1.102`) can differ in `rustc_private` APIs (e.g., `run_compiler` → `compiler_entrypoint`, `rustc_structures`); pure `major.minor` cfg gating is insufficient—use declarative capability flags (`--cfg anneal_cap_*`) driven by a data table keyed on `(release, commit_date)`.

### 3. Build-System Containment Limits, Provenance Separation, and `.olean` Deserialization RCE

Basis: source + execution

#### 3.1 Why Unsigned CLI Executor Attestations Are Spoofable

- **Bazel (`bazelbuild/bazel`):** `ExecutionRequirements.NO_LOCAL` (`"no-local"`) is checked ONLY in `DynamicExecutionModule.java:214`—`LocalSpawnRunner.canExec()` (`LocalSpawnRunner.java:177-179`), `RemoteSpawnRunner.execLocallyAndUploadOrFail()` (`RemoteSpawnRunner.java:595-597`), and `SpawnStrategyRegistry.getRemoteLocalFallbackStrategy()` (`SpawnStrategyRegistry.java:208-216`) never check `no-local`. Any caller can pass `--modify_execution_info=LeanCompile=-no-local,-block-network,+local,+no-sandbox` (`CoreOptions.java:863-888`). Default Bazel `linux-sandbox` has `--sandbox_default_allow_network=true` (`SandboxOptions.java:292`) and `--experimental_use_hermetic_linux_sandbox=false` (`SandboxOptions.java:341`, mounting `/` read-only in `linux-sandbox-pid1.cc:358-406`). Default Bazel `darwin-sandbox` (`DarwinSandboxedSpawnRunner.java:145-173, 274-325`) uses `(allow default)`, granting full host `file-read*`, writable `/tmp` and `~/Library/{Caches,Logs,Developer}`, non-loopback `network-inbound`, and all Unix sockets. (Bazel provides CI-side `--allowed_local_actions_regex` in `AllowedLocalActions.java:35` plus execution log `SpawnExec.runner`.)
- **GN/Ninja, Buck2, Nix:** Plain local Ninja has zero OS isolation; Reclient/Siso allow `remote_local_fallback`/`racing`; Buck2 allows `--local-only`/`--prefer-local`; Nix allows `--option sandbox false`/`relaxed` and `__noChroot`.
- **Receipt separation law:** A verification receipt emitted by a build action must separate **self-verified `kernel_verdict`** from **`elaboration_containment`**, using four distinct enforcer variants: `self_execseal_in_process` (`self_verified: true`, including a local orchestrator binding child `compile-lean` invocations via an ephemeral 256-bit CSPRNG HMAC key passed over an inherited pipe FD), `split_action_execseal_unauthenticated` (`self_verified: false`), `external_unverified_by_binary` (`self_verified: false`, marking any CLI executor hint `UNTRUSTED` and requiring out-of-band CI provenance such as SLSA v1.0 / `--allowed_local_actions_regex` + `SpawnExec.runner`), and `none` (tainted).
- **RBE cache isolation:** Untrusted PR builds must never hold write permissions to main/CI action caches (`--remote_upload_local_results=false`, separate REAPI `instance_name` namespaces, write-once CAS/AC immutability, zero `?trusted=1` Nix substituters).

#### 3.2 `.olean` C++ `compact.cpp` Deserialization RCE and 3-Action Comparator-Grade Audit

- Lean 4's C++ `.olean` loader (`compact.cpp:518-570`: `fix_object_ptr`, `fix_array`, `fix_constructor`) relocates raw pointers and iterates over untrusted sizes with debug-only `lean_assert` checks. Even inside a 100% hermetic `LeanCompile` container, hostile `Proof.lean` can overwrite its own declared `Proof.olean` via `run_elab` `IO.FS.writeBinFile` + `IO.Process.exit 0`, achieving memory corruption inside any downstream C++ `.olean` consumer (`TrustedBoundary` or `lean4export`)—which could emit a forged NDJSON stream defining `Expected.claim := True; Proof.verify := True.intro` that passes naive `nanoda_bin` checking.
- Moreover, inspecting `nanoda_lib v0.4.32` (`util.rs:757-791`, `tc.rs:342-455`, `expr.rs:606-640`, `quot.rs:67-316`) reveals 34 `Init` primitives trusted by name under `nat_extension`/`string_extension`/`Quot`, and live export of a minimal `Expected.claim` (`560.9 KiB`, `381` decls) proved **11/34** (`Nat.{gcd,xor,land,lor,shiftLeft,shiftRight}`, `Quot.*`, `eagerReduce`) are absent from `expected_cone.ndjson`—allowing a compromised exporter to inject `def Nat.gcd _ _ := 0` and derive `False`.
- **Closing both attacks (zero `compact.cpp` TCB):**
  1. **Action 5a (`ExportExpected`):** Mount ONLY trusted `combined_scope` (`{Init.*, Trusted.*, Captured, Spec.*, Expected}` — zero `Anneal.*`, zero `Proof.*`), run `LEAN_ABORT_ON_PANIC=1 lean4export Expected -- Expected.claim` → `expected_cone.ndjson`.
  2. **Action 5b (`ExportProof`, sandboxed):** Run `LEAN_ABORT_ON_PANIC=1 lean4export Proof -- Proof.verify` inside an isolated sandbox with read-only inputs and sole writable output `proof_full.ndjson`.
  3. **Action 5c (`VerifyNdjson`, pure memory-safe Rust):** Run `nanoda_bin` (or `con-ron` on Lean `v4.35+`) with `unpermitted_axiom_hard_error: true` and `permitted_axioms = ["propext", "Classical.choice", "Quot.sound"]`, plus a ~80-LOC canonical hash-consed DAG identity check proving every constant in `expected_cone.ndjson ∪ init_primitives_cone.ndjson` (`+360.4 KiB` once per toolchain, pinning all `34/34` primitives) appears identically in `proof_full.ndjson` and `Proof.verify : Expected.claim`.

### 4. Dual-View Zero-Mutation Lean 4 `module` System and Determinism

Basis: source + execution

- **Native `module` supersedes binary `.thmInfo -> .axiomInfo` stubbing:** Live `readModuleDataParts` on Lean `v4.34.1` proved Lean 4's `module` system natively writes every `public theorem` (tactic, term `:= rfl`, and compiler-generated `.inj`/`.injEq`/`.sizeOf_spec`) and every unexposed `public def` as `.axiomInfo` (`hasVal = false`) inside `.olean` while storing full `.thmInfo`/`.defnInfo` bodies in `.olean.private`. Converting all 63 runtime Anneal files (`19` `Trusted.*` + `44` `Anneal.*`) to `module` (`63/63 PASS` on both `v4.33.1` in `49.84s` and `v4.34.1` in `44.15s`) shrunk `theory/` public `.olean`s by **`76.2%`** (`53.76 → 12.81 MiB`). Rewriting `.olean` via `saveModuleData` broke cross-region raw `object_compactor` pointers (`+0x10000`, `+0x20000`), causing **`SIGSEGV` (`rc = 245`)** on multipart load and hard-failing `nanoda_lib` on stubbed axioms.
- **Dual-View zero-mutation consumption (`VIEW_A_SINGLE` vs. `VIEW_B`):**
  - *View A (`VIEW_A_SINGLE` — fast Stage-2 `TrustedBoundary`):* Single `importModules` of Stage-1 `.olean`-only (`level := .exported`, `0 B` of Stage-1 `.olean.private`) + `readModuleDataParts` on Stage-2 full parts. Measured on `N = 24` Stage-1 `module`s (`15.17 MiB` `.olean.private` vs. `1.94 MiB` `.olean`): **`170.9 ms` (`7.7×` faster than double-import `VIEW_B` `1,318.0 ms`)** and **`238.52 MiB` peak RSS (`-70.6%` vs. `811.91 MiB`)**, growing only `+0.70 MiB` when tripling Stage-1 `.olean.private` (`5.06 → 15.17 MiB`).
  - *Required `Replay.lean:90` `subsumesInfo` fix:* When Stage-1 exports a realized equation lemma (`ModA.sharedRec.eq_1`) as `.axiomInfo` and Stage-2 realizes it as `.thmInfo`, `finalizeImport` (`Environment.lean:2274`) succeeds but raw `Kernel.Environment.replay` crashes with `alreadyDeclared`. Verifying `subsumesInfo`, omitting from `replayMap`, and checking the body under a fresh name `_anneal_subsumed_check.<idx>` via `addDeclCore` resolves this cleanly. Exact View-B axioms are recovered in $O(1)$ by unioning precomputed 3-bit Stage-1 axiom summaries (`propext | Classical.choice | Quot.sound`).
  - *View B (external multi-kernel replay):* Unmodified `combined_scope` (`.olean` + `.olean.server` + `.olean.private`) loaded at `level := .private` recovers full `.thmInfo` bodies with `0` extra axioms.
- **Bit-for-bit determinism & `Elab.async`:** Across working directories, directory depths, relative vs. absolute input/setup paths, `LEAN_PATH`, `+200,000s` `mtime` shifts, and `-j1` vs. `-j4`, all 7 outputs (`.olean`, `.olean.server`, `.olean.private`, `.ir.sig`, `.ir`, `.ilean`, `.c`) are **14/14 bit-for-bit identical** under `-DElab.async=false` with zero embedded filesystem paths (even `.ilean` embeds zero paths). - **Binary `.olean` ABI portability:** `olean_header.flags` bit 0 encodes `LEAN_USE_GMP`, and `module.cpp:493` unconditionally rejects flag mismatches. Portable source/DAG manifests (`theory-dag.json`) must therefore stay strictly decoupled from per-toolchain-ABI compiled artifact locks keyed by `(lean_version, githash, use_gmp, elab_async, target_arch)`.

### 5. Static vs. Dynamic Action Graphs, Zero-Axiom `D = 1` Sharding, and Multi-Output Early Cutoff

Basis: source + execution

- **Static-DAG capability wall:** Live inspection of the `gn` binary confirmed **zero `dyndep` support** (`depfile` only affects incremental rebuilds after the first run). Bazel `< 9` `declare_directory` (`TreeArtifact`) collapses per-shard RBE reuse to `0%`; Bazel `9+` `ctx.actions.map_directory` (`StarlarkActionFactory.java:1152-1270`, `ExpandedDirectoryApi.java:28-40`) exposes `.children` paths only and cannot read JSON contents. CMake and Meson restrict Ninja `dyndep` to C++20/Fortran. Nix IFD serializes evaluation and is banned in `nixpkgs`. Only Buck2 (`ctx.actions.dynamic_output_new`) and Cargo natively read execution-time manifests to register dynamic per-shard actions.
- **Zero-axiom parameterized `D = 1` sharding (proved live on Lean `v4.34.1`):** Defining per-shard obligations in `Expected/Shard_<i>.lean` (over $\mathcal{E}_0$) as parameterized implications `ShardObligation_<i> : Prop := DepSpec_1 → ... → DepSpec_m → ShardSpec_<i>` lets every `Proof/Shard_<i>.lean` import **zero** other `Proof.Shard_*` modules (`D = 1`, structurally precluding cross-shard computational `DefinitionVal`/`Acc.rec` leakage), while `Proof/Link.lean` discharges `Proof.verify : Expected.claim` by function application with **`VIEW_B_AXIOMS = []`** (100% natively checkable by `nanoda_lib` without custom Merkle axioms; for mega-crates exceeding single-export RSS, per-shard `5a_i`/`5b_i`/`5c_i` + pure-Rust `5d` linking preserves $O(\text{shard})$ memory). This unifies four shard modes across static and dynamic build systems: `none`, `nominal` (checked-in `anneal-shards.json`), `fixed-buckets=K` (statically declared `Expected/Bucket_0..K-1.lean` with zero `BUILD` churn), and `dynamic` (Buck2/Cargo).
- **Multi-output early cutoff:** Editing a Lean `module` proof body without changing its used axiom set leaves `.olean` and `.ir.sig` bit-for-bit unchanged (changing only `.olean.server` and `.olean.private`; switching tactics to add a new axiom updates `exportedAxiomsExt` in `.olean`). Bazel Skyframe tracks per-artifact digests, and Buck2 `EnsureProjectedArtifactKey`/`ArtifactGroupValues` (`artifact_groups/calculation.rs:470-622`) projects only the upstream `.olean` digest into downstream `ActionDigest`s—yielding automatic early cutoff. By contrast, live Ninja probing proved plain `restat = 1` with raw rewrite **misses early cutoff (`2/2` downstream runs)** because `mtime` advances; adding a `move-if-changed` (`cmp -s` before `mv`) wrapper achieves **`1/2` runs (100% early cutoff)**.

### 6. Nix `--lean-loader`, Meson Native Rust Introspection, and Zero-`.lake` IDE Parity

Basis: source + execution

- **Nix unpatched `bin/lean` inside `nix-sandbox`:** Unpatched upstream `bin/lean` (`PT_INTERP=/lib64/ld-linux-x86-64.so.2`) cannot be `exec`ed directly inside Linux `nix-sandbox`, while `patchelf` mutates its SHA-256 lock digest. Live probing proved invoking `<ld.so> --library-path <sysroot>/lib/lean <sysroot>/bin/lean --setup <setup.json>` succeeds with `rc = 0` and produces **5/5 bit-identical module outputs** across all 4 invocation modes while keeping `bin/lean` 100% unpatched (passing explicit `LEAN_PATH=<sysroot>/lib/lean` also makes `--run` work despite `IO.appPath` returning `ld.so`).
- **Meson native Rust binding:** `mesonbuild/backend/ninjabackend.py:880-958, 2029-2050, 2275-2312` and `mintro.py:121-187` show `generate_rust_target` calls `create_target_source_introspection`, exporting 100% of resolved `rustc` `parameters` (`--extern`, `-Ldependency`, `--cfg`, `--edition`, `--crate-type`), compiler path, and staged `structured/` crate roots into `meson-info/intro-targets.json` (plus `rust-project.json`), enabling unmodified `static_library()` verification without `meson.build` wrappers.
- **Zero-`.lake` IDE-to-CI parity:** Upstream Lean 4 natively honors `LAKE=<shim> setup-file <filePath> -` (`Lean/Util/LakePath.lean:14-21`, `SetupFile.lean:26-97`), and `vscode-lean4` (`projectInfo.ts:105-168`, `leanclient.ts:800-868`) falls back to `workspaceDir` when no `lakefile.{lean,toml}` exists. Emitting a build-system-agnostic `anneal-project.json` (analogous to `rust-project.json`) consumed by one `cargo-anneal-lake-shim` (`serve` + `setup-file`) eliminates `.lake` symlinks and prevents IDE-vs-CI split brain via atomic-rename `/tmp` generation swaps and staleness checks on generated Rust/`verify_deps`/proc-macro inputs.

- **unsupported:** Overriding `rustc` `providers.queries.optimized_mir` to skip `MentionedItems`/`ForceInline` during `.rmeta` encoding is unsupported and ICEs `rustc_monomorphize::collector`.
