# Internationalization, UTS #35 CLDR Plural Operands and MessageFormat 2.0, ICU4J and FormatJS Parser Semantics, UAX #9 BiDi Isolation, and PEP 495 `zoneinfo`

## Summary

Primary-source verification across six normative Unicode, IETF, W3C, and Python standards, thirteen peer-reviewed and preprint localization studies (2009–2026), ten pinned public GitHub repositories, and a deterministic five-pillar Python 3.10+ verification suite establishes five governing conclusions for software internationalization (`i18n`) and localization (`l10n`):

1. **Formatted-String Plural Operands (`n, i, v, w, f, t, c`) Defeat Numeric-Only and Binary Plural Heuristics (`Basis: normative + source + execution`):**
   - `UTS #35` Part 3 (`LDML` Revision 79, `CLDR 49.0.0`; `unicode-org/cldr@267bae66b10db620caca6d5df88c1719fc0fd457:common/supplemental/plurals.xml:30-33, 118-122, 163-168, 181-186, 236-243`) defines cardinal plural categories over the *formatted decimal string* rather than IEEE-754 numeric values. Across a `95`-case verification matrix (`19` canonical operands $\times$ `5` locales: `en`, `fr`, `pl`, `ru`, `ar`), naive binary `n == 1` branching misclassifies **`37/95` (`38.9%`)** cases (including `"1.0"` in English, where `v = 1` requires `"1.0 days"` [`other`] rather than `"1.0 day"` [`one`]), IEEE-754 numeric coercion (`Number(x)`, erasing visible fraction digit count `v` and compact decimal exponent `c`) misclassifies **`12/95` (`12.6%`)** cases (corrupting `"1.0"` in `en`/`pl`/`ru`, `"0.0"`/`"2.0"`/`"3.0"`/`"21.0"` in `pl`/`ru`, and `"1.2c6"` [`"1,2 million de vues"`, `many`] in `fr`), and legacy pre-CLDR-38 two-branch French (`n in {0, 1}`) misclassifies **`4/19` (`21.1%`)** French cases (`"1.30"`, `"1.5"` $\to$ `one`; `"1000000"`, `"1.2c6"` $\to$ `many`). Even sibling Slavic locales diverge (`"21"` is `one` in Russian [`21 файл`] vs. `many` in Polish [`21 plików`], while `"21.0"` [`v = 1`] routes to `other` in both).
2. **Legacy `MessageFormat` v1 Syntax Traps and Four Compounding BiDi Implementation Defects in `ICU4J 78` `MessageFormat 2.0` (`Basis: normative + source + execution`):**

## Findings

### 1. `UTS #35` Part 3 Plural Operands and Cross-Locale `plurals.xml` Semantics

`Basis: normative + source + execution`

`UTS #35` Part 3 (`docs/ldml/tr35-numbers.md` `#Language_Plural_Rules`, `#Operands`, `#Relations`, `#Plural_Operand_Examples`; `common/supplemental/plurals.xml`) mandates that cardinal plural selection operate on the **formatted string representation**, preserving seven operands—absolute value `n`, integer digits `i`, visible fraction digit count with trailing zeros `v`, visible fraction digit count without trailing zeros `w`, visible fraction digits as integer `f`, stripped-zero fraction digits as integer `t`, and compact decimal exponent `c` (synonym `e`)—and evaluating `{zero, one, two, few, many}` in order before `other`. On `"1.20050c3"`, shifting the decimal point right by `c = 3` yields `(n=1200.50, i=1200, v=2, w=1, f=50, t=5, c=3)`. Crucially, range relations `x = a..b` match **strictly integers** in $[a, b]$, whereas `%` computes floating-point remainder (`3.5 % 100 = 3.5`, failing `3..10`).

| Locale (`plurals.xml` Lines) | Active Cardinal Categories & Key Predicate Structure | Canonical Divergences Verified in Pillar 1 |
| :--- | :--- | :--- |
| **English (`en`, `L30–33`)** | `one`: `i = 1 and v = 0`; `other` | `"1"` $\to$ `one`, whereas **`"1.0"` (`v = 1`) $\to$ `other`** (*"1.0 days"*); binary `n == 1` and `Number("1.0")` both emit ungrammatical `one` |
| **French (`fr`, `L118–122`)** | `one`: `i = 0..1`; `many`: `e = 0 and i != 0 and i % 1000000 = 0 and v = 0 or e != 0..5`; `other` | `"0"`, `"0.0"`, `"1.30"`, **`"1.5"` (`i = 1`) $\to$ `one`** (*"1,5 jour"*); **`"1000000"` & `"1.2c6"` $\to$ `many`** (*"1,2 million de vues"*), while `"1000000.0"` (`v = 1`) $\to$ `other`; numeric coercion of `"1.2c6"` to `1200000` (`e = 0`) loses `many` |
| **Polish (`pl`, `L163–168`)** | `one`: `i = 1 and v = 0`; `few`: `v = 0 and i % 10 = 2..4 and i % 100 != 12..14`; `many`: `v = 0 and (i != 1 and i % 10 = 0..1 or i % 10 = 5..9 or i % 100 = 12..14)`; `other` | **`"21"` $\to$ `many`** (*"21 plików"*); **every visible fraction** (`"0.0"`, `"1.0"`, `"2.0"`, `"2.5"`, `"21.0"`) has `v > 0` and routes to **`other`** (genitive singular *"2,5 pliku"*) |
| **Russian (`ru`, `L181–186`)** | `one`: `v = 0 and i % 10 = 1 and i % 100 != 11`; `few`: same as `pl`; `many`: `v = 0 and (i % 10 = 0 or i % 10 = 5..9 or i % 100 = 11..14)`; `other` | **`"21"` $\to$ `one`** (*"21 файл"*), diverging from Polish; `"11"` $\to$ `many`; all visible decimals (`"1.0"`, `"21.0"`) route to **`other`** (*"21,0 файла"*) |
| **Arabic (`ar`, `L236–243`)** | All `6`: `zero` (`n=0`), `one` (`n=1`), `two` (`n=2`), `few` (`n%100=3..10`), `many` (`n%100=11..99`), `other` | Keyed solely on `n` (ignoring `v`): `"1.0"` $\to$ `one`, `"3.0"` $\to$ `few`, `"3.5"` $\to$ `other`, `"11"` $\to$ `many`, **`"100"` $\to$ `other`**, **`"103"` $\to$ `few`** |

Across the `95`-case (`19` samples $\times$ `5` locales) verification grid in Pillar 1, naive `n == 1` branching fails **`37/95` (`38.9%`)**, IEEE-754 float coercion fails **`12/95` (`12.6%`)**, and pre-`CLDR 38` two-branch French fails **`4/19` (`21.1%`)**.

### 2. `ICU MessageFormat` v1/v2 Parsing, `.match` Validation, and Cross-Implementation BiDi Audit

`Basis: normative + documentation + source + execution + derived`

1. **`ICU4J` `MessagePattern` Apostrophe Automaton (`MessagePattern.java:115-136, 973-1060`) and `FormatJS` Tag Trap (`parser.ts:50, 212, 282-305, 494-525`):**
   - Under `ApostropheMode.DOUBLE_REQUIRED` (`java.text.MessageFormat` compatibility), `"L'élément {0} est introuvable"` treats `'` as opening an unclosed quoted literal span to `msg.length()`, silently emitting `"Lélément {0} est introuvable"` without substituting `{0}`.
   - Under ICU's default `ApostropheMode.DOUBLE_OPTIONAL`, `'` opens a quoted literal span whenever followed by `{`, `}`, `|` (inside `choice`), or `#` (inside `plural`/`selectordinal`), with `''` inside a quoted span encoding a single literal `'` (`MessagePattern.java:1004-1007`): (a) `"Impossible d'ouvrir '{filename}'"` strips quotes and outputs literal `"{filename}"`; (b) top-level `"L'{item} a été supprimé"` (`nestingLevel == 0`) deletes `'` and outputs literal `"L{item} a été supprimé"` silently; and (c) nested `"{count, plural, one {L'{item} est prêt} other {# éléments}}"` (`nestingLevel == 1`) consumes all closing `}` braces through `EOF` and throws `IllegalArgumentException: Unmatched '{' braces in message` despite balanced braces (repaired only by escaping `L''{item}`).
   - In `FormatJS` (`formatjs/formatjs@0dd5f944`), `ignoreTag` defaults to `false`: unescaped `<` followed by `/` or ASCII `[A-Za-z]` triggers XML tag parsing, causing `"Save to </tmp/out>"` to fail with `UNMATCHED_CLOSING_TAG` and `"Constraint a <b failed"` to fail with `UNCLOSED_TAG`, whereas `"Score <3 points"` (`'3'` non-ASCII-alpha), `"Constraint a '<'b failed"`, and `ignoreTag=True` succeed.
2. **`MessageFormat 2.0` `.match` Validation Split (`UTS #35` Part 9 `#Data_Model_Errors` vs. `ICU4J` Source) and Offline-vs.-Runtime Synthesis Trade-Off:**
   - Normatively, `UTS #35` Part 9 `#Data_Model_Errors` rejects `.match` blocks with unannotated selectors (`MissingSelectorAnnotation`), mismatched variant-key arity (`VariantKeyMismatch`), variant keys colliding under Unicode `NFC` (`("caf\u00e9",)` vs. `("cafe\u0301",)` $\to$ `DuplicateVariant`), or missing an all-`*` catch-all row (`("1", "*")` + `("*", "1")` without `("*", "*")` $\to$ `MissingFallbackVariant`). In `unicode-org/icu@9407c634`, `ICU4J` splits these checks across three stages: `MFParser.java:708` (`getLiteral(true)`) normalizes literal variant keys to `NFC` during parsing; `MFDataModelValidator.java:50-89` (`validateVariants`) enforces key arity, `StringJoiner("<<::>>")` duplicate detection, and all-`*` catch-all presence while `validateSelectors` (`L91-96`) checks only `selectors == null || selectors.isEmpty()`; and `MFDataModelFormatter.java:186-198` defers unannotated or unknown selector failure to runtime formatting (`fatalFormattingError("Unknown selector type: " + functionName)`).
   - *Offline vs. runtime inflection trade-off (`Basis: derived` from `UTS #35` + `BabelArena`, `Kaye 2026`, `IFMTBench`):* Multi-axis agreement ($6 \text{ plurals} \times 3 \text{ genders} \times 7 \text{ cases} = 126$ upper-bound Cartesian cells, sparse in practice where plural forms syncretize gender or case) makes hand-authoring `.match` tables verbose. However, replacing deterministic `MF2` templates with runtime LLM string generation introduces `O(100 ms)` tail latency, non-determinism, **`20.0%` broken placeholder/entity references** (`BabelArena` Table 3), **`49.7%–50.2%` direct numerical/date localization error rates** (`Kaye, 2026` Table 2), and multi-constraint structural degradation (`IFMTBench` §6.4: even `Gemini 3.1 Pro` drops from `>0.94` single-turn structural compliance to `0.55–0.72` under composed constraints). Consequently, LLM synthesis belongs strictly **offline** behind deterministic AST/validator gates (`MFParser` + `MFDataModelValidator` + placeholder schema checks), compiling down to static `MF2` resources evaluated deterministically at runtime.
3. **Four Live BiDi Implementation Defects in `ICU4J 78` `message2` vs. `UTS #35` Part 9 and `ICU4C` (`locale = "ar"`):**
   - Under `UTS #35` Part 9 (`tr35-messageFormat.md:2356-2399, 4242-4244`), `BidiIsolation` MUST default to the Default Bidi Strategy (`2356-2357`), and `u:dir=inherit` is the normative default equivalent to omitting `u:dir` (`4242-4244`, verified in `ICU4C` `messageformat2_function_registry.cpp:266-271, 1938-1946` and Pillar 2's `format_mf2_placeholder_uts35_spec`).
   - Auditing `unicode-org/icu@9407c634` uncovers four concrete `ICU4J` defects:
     1. **`MessageFormatter.java:369, 421` (`BidiIsolation.NONE` Default):** `MessageFormatter.Builder` defaults `bidiIsolation` to `BidiIsolation.NONE`, emitting zero isolates unless the caller explicitly configures `BidiIsolation.DEFAULT` (violating `tr35-messageFormat.md:2356-2357`).
     2. **`MFDataModelFormatter.java:95, 125` (Hardcoded `msgdir = LTR`):** Whereas `ICU4C` (`icu4c/source/i18n/messageformat2_formatter.cpp:243-255, 267`) resolves `msgdir` via `locale.isRightToLeft()` (`U_MF_DIRECTIONALITY_RTL` for `ar`/`he`), `MFDataModelFormatter.java:95` hardcodes `Directionality msgdir = Directionality.LTR;` without calling `Directionality.of(this.locale)` (`Directionality.java:58-63`). For `{$pct :number u:locale=en-US}` (`"-12.5%"`) in `ar`, `NumberFunctionFactory` sets `dir = LTR, isolate = false`, hitting `if (msgdir == Directionality.LTR && !isolate)` at `L125` and emitting bare `"-12.5%"` instead of `"\u2066-12.5%\u2069"`. (By contrast, `:string` in `TextFunctionFactory.java:21, 28, 40-44` sets `isolate = true` and passes `OptUtils.getDirectionality(fixedOptions)`—which at `OptUtils.java:136-139` returns `Directionality.UNKNOWN`, never `null`, making `L28`'s `? Directionality.INHERIT` dead code via `create()`—so `{$name :string u:dir=ltr}` still emits `"\u2066Alice\u2069"`.)
     3. **`NumberFunctionFactory.java:118-127, 156-157` (`u:dir` Option Ignored):** Constructs `mergedOptions` from `fixedOptions` + `variableOptions` at `L118-122`, then at `L156` calls `OptUtils.getBestDirectionality(variableOptions, locale)`. Because `MFDataModelFormatter.java:551-552` passes expression options (`u:dir=ltr`) in `fixedOptions` and runtime message arguments in `variableOptions`, `{$n :number u:dir=ltr}` (`"42"`) in `ar` ignores `u:dir=ltr`, falls back to `Directionality.of(ar) = RTL`, and emits `"\u206742\u2069"` (`RLI`..`PDI`) instead of `"\u206642\u2069"` (`LRI`..`PDI`).
     4. **`DateTimeFunctionFactory.java:49, 246` (Implementation Defect Dropping `dir`):** Computes `Directionality dir = OptUtils.getBestDirectionality(fixedOptions, locale);` at `L49`, never stores `dir`, and at `L246` calls the deprecated 2-argument `new FormattedPlaceholder(toFormat, ...)` (`FormattedPlaceholder.java:56-58`), hardcoding `(Directionality.LTR, isolate = false)` so `:datetime`, `:date`, and `:time` (`{$dt :datetime u:dir=rtl}` = `"2026-11-22"`) emit bare `"2026-11-22"` instead of `"\u20672026-11-22\u2069"`.

### 3. `UAX #9` Runtime UI BiDi Corruption and Sink-Partitioned Isolation

`Basis: normative + documentation + source + execution`

### 4. `PEP 495` / `PEP 615` `ZoneInfo` Algebraic Paradoxes vs. `pytz` `LMT` and `localize(is_dst)` Semantics

`Basis: normative + source + execution`

Executing `Python 3.13.15`'s standard-library `datetime` and `zoneinfo.ZoneInfo` (`Lib/_pydatetime.py:2227-2263`, `Lib/zoneinfo/_zoneinfo.py:162-188, 366-398`; `peps/pep-0495.rst:240-260, 560-584`) over a standards-compliant RFC 8536 `TZif` v2 `America/New_York` binary (`ttinfo[0] = -17,762s` `LMT`) establishes four algebraic invariants alongside `pytz`'s transition mechanics:

1. **Intra-Zone Fold Erasure vs. `3,600s` Physical Elapsed Time:** At fall-back `2024-11-03 01:30` (`dt_f0` with `fold=0` = `01:30 EDT` / `05:30Z`; `dt_f1` with `fold=1` = `01:30 EST` / `06:30Z`), `dt_f0 == dt_f1` is **`True`**, `hash(dt_f0) == hash(dt_f1)` is **`True`** (colliding in `dict`/`set` keys), and `dt_f1 - dt_f0 == timedelta(0)`, even though `dt_f1.timestamp() - dt_f0.timestamp() == 3600.0` (`u1 - u0 == 1:00:00`).
2. **Inter-Zone UTC Disequality, Broken Antisymmetry, and Broken `<=` Transitivity:** When `mytz is not ottz`, `_pydatetime.py:2240-2243` returns `2` (`!=`) in `__eq__` whenever either operand's `utcoffset()` changes under `replace(fold=not self.fold)`, yet `__le__`/`__ge__` invoke `_cmp(..., allow_mixed=False)` which falls through to offset-aware subtraction (`L2259: diff = self - other`):
   - `dt_f0 == u0` (`dt_f0.astimezone(UTC)`) is **`False`** and `dt_f1 == u1` is **`False`**;
   - **Antisymmetry fails:** `dt_f0 <= u0` is **`True`** and `dt_f0 >= u0` is **`True`**, yet `dt_f0 == u0` is **`False`**;
   - **Transitivity of `<=` fails:** `dt_f1 <= dt_f0` is **`True`** (`mytz is ottz` wall-clock tie) and `dt_f0 <= u0` is **`True`** (`05:30Z <= 05:30Z`), yet `dt_f1 <= u0` is **`False`** (`06:30Z > 05:30Z`).
3. **Uncached `ZoneInfo` Object-Identity Leak (`mytz is ottz`):** Loading the identical `TZif` stream twice via `ZoneInfo.from_file` yields distinct objects (`nyc is not nyc_dup`), so `dt_f0 == dt_f0_dup` (identical wall time and `fold=0` in `America/New_York`) evaluates to **`False`**.
4. **Spring-Forward Gap (`2024-03-10 02:30`) and `pytz` `-04:56` `LMT` vs. `localize(is_dst)`:** In `ZoneInfo`, non-existent `02:30` constructs without error; UTC round-trip yields `03:30 EDT` (`07:30Z`) for `fold=0` and `01:30 EST` (`06:30Z`) for `fold=1` (**`3,600s` (`1h`) physical UTC delta**, spanning **`2h` on the local wall clock**). In `stub42/pytz@e3c6fe22` (`src/pytz/tzfile.py:74-124`, `src/pytz/tzinfo.py:182-195, 206-260, 320-434`), `DstTzInfo` binds `self._transition_info[0]` (`1883` `LMT`, `-17,762s` rounded to `-04:56`) on the base zone object: `DstTzInfo.utcoffset(dt, is_dst=None)` (`tzinfo.py:427-434`) returns static `self._utcoffset` (`-04:56`) whenever `dt.tzinfo is self` (`datetime(2024, 7, 1, 12, 0, tzinfo=pytz_nyc)` $\to$ **`+3,360s` (`56m`) drift** vs. `EDT`), while delegating `dt.tzinfo is not self` to `self.localize(dt, is_dst)` (`tzinfo.py:320-403`). `localize` probes `dt ± timedelta(days=1)` via `normalize()`, raises `NonExistentTimeError` on `2024-03-10 02:30` and `AmbiguousTimeError` on `2024-11-03 01:30` when `is_dst=None`, resolves `localize(datetime(2024, 11, 3, 1, 30), is_dst=True)` to **`EDT` (`-04:00`)** vs. `is_dst=False` to **`EST` (`-05:00`)**, and requires explicit `normalize(...)` after `timedelta` addition across DST transitions (`01:30 EST + 2h` stays `03:30 EST` until `normalize()` advances it to `04:30 EDT`).

- **known not to apply:**
  - Numeric-coercion plural operand erasure (`_float_coerced_cldr_plural`, `12/95` errors across `en`/`fr`/`pl`/`ru`) does **not** misclassify Arabic (`0/19` errors in `ar`), because `common/supplemental/plurals.xml:236-243` defines all six Arabic cardinal rules purely over `n` rather than `v` or `c`.
