# OpenAPI 3.0 vs. 3.1 Schema Drift, Stateful API Fuzzing, Consumer-Driven Contracts, Tool-Use Benchmarks, and Retry-After Backoff

## Summary

Autonomous agents and automated test generators integrating with HTTP/REST services traverse four coupled verification boundaries—**specification dialects**, **stateful server fuzzing**, **cross-service consumer-provider contracts**, and **evaluation/runtime transport harnesses**—each of which exhibits silent soundness inversions established across normative specifications (`OpenAPI 3.0.3`/`3.0.4`/`3.1.0`/`3.1.1`, `JSON Schema Draft 2020-12`, `RFC 9110`, `RFC 6585`, `RFC 8288`), primary research corpora, nine pinned upstream repositories, and a deterministic five-suite verification probe (`scripts/verify_api_openapi_pact_backoff.py`):

1. **OpenAPI `3.0.3`/`3.0.4` $\leftrightarrow$ `3.1.0`/`3.1.1` (`JSON Schema Draft 2020-12`) Dialect Inversions & `Schemathesis` Canonicalization (`OAI/OpenAPI-Specification@4f86429f`, `schemathesis/schemathesis@f5ed7dd3`):**
   - OpenAPI `3.0.3` (`2020-02-20`, `versions/3.0.3.md:148, 2287–2342`) and `3.0.4` (`2024-10-24`, `versions/3.0.4.md:2697–2708`) define the Schema Object over an extended subset of `draft-wright-json-schema-00` where `null` is not a primitive `type`, `type` must be a single string, Reference Objects (`$ref`) ignore all sibling keywords (`3.0.3:2326`), and `nullable: true` applies **only** when `type` is explicitly declared within the same Schema Object (`3.0.3:2335`, `3.0.4:2701`; `H2_ref_nullable(3.0=False)` in Probe 1). OpenAPI `3.1.0` (`2021-02-15`, `versions/3.1.0.md:147, 2306–2370`) and `3.1.1` (`2024-10-24`, `versions/3.1.1.md:2740–2762`) adopt `JSON Schema Draft 2020-12` as a superset and silently omit `nullable` from the Schema Object **Fixed Fields** table (`3.1.0:2331–2338`, `3.1.1:2749–2757`; `nullable` occurs `0` times in `versions/3.1.1.md`). Because `Draft 2020-12` treats unrecognized keywords as **no-op annotations**, evaluating an un-migrated OAS `3.0` schema `{"type": "string", "nullable": true}` or legacy boolean `{"type": "integer", "minimum": 0, "exclusiveMinimum": true}` under strict OAS `3.1` silently rejects `null` (`H1_nullable_null(3.0=True, strict_3.1=False, sch_3.1=True)`) and accepts boundary `0` without raising a schema-parse error.
   - Composing closed object schemas via `allOf` with `additionalProperties: false` evaluates locally per subschema without cross-branch visibility, collapsing the intersection to zero valid instances (`H4_allOf_closed_valid(additionalProps_false=0, unevaluatedProps_false=1)`; Hatfield-Dodds & Dygalo, 2022, §2.2). Combining top-level `required: ["name", "created_at"]` with an `allOf` `$ref` containing `readOnly: true` renders request generation unsatisfiable (`unrepaired=0`) until `_forbidden_in_allof_branches` (`converter.py:267–294`) prunes forbidden `readOnly` keys from `required` (`repaired=1`). On polymorphic `oneOf`/`anyOf` schemas, `_pin_discriminator_property` (`converter.py:297–382`) injects per-branch `{"properties": {prop_name: {"enum": [val]}}}` without adding `required` so `defaultMapping` still accepts absent tags (`H6_discriminator(unpinned_mistag=True, pinned_mistag=False, default_absent_tag=True)`).
   - On non-JSON HTTP wire locations (`query`, `path`, `header`), naive negative type mutation (`string -> 42` or `true`) serializes onto the URI as `?tag=42` / `?tag=True`, which compliant servers parse as valid strings (`query_string_neg_FP(naive=2/2, guarded=0/2)`), requiring `mutations.py:638–652` plus eight post-serialization suppression predicates in `checks.py:898–905`. For stateful link inference without explicit OpenAPI `links`, `_normalize_location` (`stateful/inference.py:171–200`) drops every absolute `http://` / `https://` `Location` header (`abs_Location_no_base=None`) whenever `_base_url` is unset (e.g., ASGI/WSGI in-process test clients) and rejects paths outside `_base_path` via `_strip_base_path_from_location` (`L188, 193–200`).

## Findings

### 1. OpenAPI `3.0.3`/`3.0.4` vs. `3.1.0`/`3.1.1` (`Draft 2020-12`) Dialect Inversions & `Schemathesis` Rewrites

`Basis: normative + documentation + source + execution`

 Consuming or migrating OpenAPI descriptions across `3.0.3`/`3.0.4` and `3.1.0`/`3.1.1` replaces a custom OpenAPI schema dialect (`draft-wright-json-schema-00` extended subset) with standard `JSON Schema Draft 2020-12` (`draft-bhutton-json-schema-00`), inverting validation behavior across seven constructs verified in `OAI/OpenAPI-Specification@4f86429f`, `schemathesis/schemathesis@f5ed7dd3`, and Probe 1:

1. **Bidirectional `nullable` Omission & `$ref`-Sibling Inversions (`3.0.3.md:148, 2314, 2326, 2335`, `3.0.4.md:2701` vs. `3.1.0.md:147, 2331–2338`, `3.1.1.md:2749–2757`):**
   - **Trap H1 (`3.0 -> 3.1` silent `null` rejection):** In OAS `3.0.3` (`2020-02-20`) and `3.0.4` (`2024-10-24`), `{"type": "string", "nullable": true}` permits `null` (`3.0=True`). In OAS `3.1.0` (`2021-02-15`, `versions/3.1.0.md:2331–2338`) and `3.1.1` (`2024-10-24`, `versions/3.1.1.md:2749–2757`), OpenAPI drops `nullable` silently by omitting it from the Schema Object **Fixed Fields** table (which retains only `discriminator`, `xml`, `externalDocs`, and deprecated `example`; `versions/3.1.1.md` contains `0` occurrences of `nullable`). Because `JSON Schema Draft 2020-12` treats unrecognized keywords as inert annotations (`3.1.1.md:2746, 2762`), feeding an un-migrated `{"type": "string", "nullable": true}` schema into a strict OAS `3.1` validator **silently rejects `null`** (`strict_3.1=False`) without emitting any schema error. Conversely, `schemathesis` `adapter/v3_1.py:36` deliberately sets `nullable_keyword = "nullable"` (`sch_3.1=True`) to tolerate hybrid production `"3.1"` specs that retain OAS `3.0` `nullable: true`.
   - **Trap H2 (`$ref` + `nullable: true`):** Under strict OAS `3.0.3`/`3.0.4`, `{"$ref": "#/components/schemas/User", "nullable": true}` rejects `null` (`3.0=False`) for **two independent normative reasons**: Reference Objects require all sibling properties to be ignored (`3.0.3:2326`), and `nullable: true` takes effect *only* if `type` is explicitly defined within the same Schema Object (`3.0.3:2335`, `3.0.4:2701`). Strict OAS `3.1` evaluates `$ref` alongside siblings by intersection (`adapter/v3_1.py:41` `ref_siblings = True`), yet *also* rejects `null` (`strict_3.1=False`) because `nullable` is ignored. `schemathesis` `converter.py:107–114` explicitly preserves `nullable` while stripping other `$ref` siblings in `3.0` mode (`sch_3.0=True`).
   - **Trap H3 (Request-vs-Response `nullable` + `enum` Asymmetry, `converter.py:119–133`):** When `nullable: true` or `type: ["string", "null"]` co-occurs with `enum: ["active", "paused"]` (without `null` in `enum`), strict JSON Schema rejects `null` because `enum` intersects `type`. `to_json_schema` resolves this asymmetrically: for **requests** (`is_response_schema=False`), it leaves `null` disallowed so generated client calls do not violate server `enum` checks (`req=False`), whereas for **responses** (`is_response_schema=True`), it wraps in `anyOf` / appends `None` (`resp=True`) so servers returning `null` on nullable enum columns do not trigger false alarms.
2. **Legacy Boolean `exclusiveMinimum` & Tuple `items` (`converter.py:593–620`):**
   - An un-migrated OAS `3.0` constraint `{"type": "integer", "minimum": 0, "exclusiveMinimum": true}` rejects `0` under `3.0.3`, whereas strict `Draft 2020-12` expects a numeric `exclusiveMinimum` and ignores boolean `true`, silently accepting boundary `0` unless rewritten by `_upgrade_legacy_exclusive_bounds` (`L593–609`). Likewise, tuple-typed `items: [...]` + `additionalItems: false` must be upgraded to `prefixItems: [...]` + `items: false` (`L611–620`).
3. **Non-Local Composition Hazards (`allOf` + `additionalProperties: false`, `readOnly` + `required`, & `discriminator`):**
   - **Trap H4:** Under both `3.0` and `3.1`, composing two closed object branches via `allOf` with `additionalProperties: false` causes each branch to reject the other's required properties, leaving **`0` valid instances** (`additionalProps_false=0`; simplified by `hypothesis-jsonschema` to `{"type": "object", "maxProperties": 0}`, Hatfield-Dodds & Dygalo, 2022, §2.2). Only OAS `3.1` / `Draft 2020-12` `unevaluatedProperties: false` tracks evaluated property annotations across `allOf`/`oneOf`/`$ref` boundaries (`unevaluatedProps_false=1`).
   - **Trap H5 (`converter.py:175–187, 267–294`):** Rewriting `readOnly: true` properties to `{"not": {}}` for request generation makes any schema that lists an inherited `allOf` `$ref` `readOnly` property (`created_at`) in top-level `required` unsatisfiable (`unrepaired=0`). `_forbidden_in_allof_branches` traverses nested `allOf` and `$ref` graphs with cycle detection (`seen: set[int]`) to remove forbidden properties from `required` (`repaired=1`).
   - **Trap H6 (`converter.py:297–382`):** Without explicit tag constraints inside `Cat`/`Dog`, `oneOf` accepts a mis-tagged payload `{"petType": "Dog", "meows": true}` (`unpinned_mistag=True`). `_pin_discriminator_property` injects `{"allOf": [item, {"properties": {property_name: {"enum": [disc_value]}}}]} ` (`L371`, using `enum` rather than `const` because Draft 4 ignores `const`, `L370`) *without* injecting `required`, and pins `defaultMapping` (`L379–381`) via `{"properties": {property_name: {"not": {"enum": sorted(routed)}}}}` so that mis-tagged payloads are rejected (`pinned_mistag=False`) while omitted-tag payloads route cleanly to `defaultMapping` (`default_absent_tag=True`).
4. **HTTP Wire-Serialization False-Positive Guards, Stateful `Location` Normalization, & Corpus Arithmetic (`Hatfield-Dodds & Dygalo, 2022`):**
   - Across `66,925` OpenAPI Directory endpoints (`arXiv:2112.10328v1`, Table 2), `65,195` (`97.42%`) generate tests out-of-the-box and `1,730` fail (`1,254` recursive `$ref` cycles [`72.5%`], `170` ECMA-262 regex incompatibilities, `168` YAML syntax errors, `45` invalid `enum`s, `33` `/` in path parameters, `26` complexity caps, `26` logically unsatisfiable schemas, `8` un-inlined remote `$ref`s). Across `16` live targets, primary-source auditing surfaces three internal paper accounting nuances verified in Probe 1: (i) `§3.2` prose reports `755` bugs (`111` HTTP 500s + `436` unexpected status codes + `52` response-schema violations + `152` content-type errors = **`751`**, leaving `4` response-header violations unitemized in that sentence); (ii) summing the `16` target cells of `schemathesis:AllChecks` yields **`664`** in `Table 6` and **`136`** in `Table 7` (`HTTP 500`) due to cross-endpoint Sentry deduplication vs. per-endpoint counting; and (iii) `§3.1` says *"seven other fuzzing tools"*, `Table 4` lists `9` non-Schemathesis tools, and `Tables 6–9` report `7` non-Schemathesis rows after `Swagger-conform` and `Fuzzy Swagger` failed on targets.
   - Mutating `type: "string"` on `query`, `path`, or `header` parameters to `42` or `True` serializes onto the URI as `tag=42` / `tag=True` (`2 / 2` false positives if unguarded), requiring `negative/mutations.py:638–652` to block `change_type` when `"string" in old_types` on non-JSON locations and `checks.py:898–905` to chain **8 post-status suppression predicates** (`has_only_additional_properties_in_non_body_parameters`, `_body_negation_becomes_valid_after_serialization`, `_body_negation_is_only_forbidden_property`, `_single_element_array_becomes_valid_after_serialization`, `_type_mutations_become_valid_after_serialization`, `_path_array_becomes_valid_after_serialization`, `_non_body_negative_values_match_schema`, and `_negative_body_replaced_by_caller`).
   - In `stateful/inference.py:171–200`, `_normalize_location` returns `None` on every absolute `http://` / `https://` `Location` header when `self._base_url` is unset (`L177–180`, `abs_Location_no_base=None`) and strips `self._base_path` via `_strip_base_path_from_location` (`L188, 193–200`), returning `None` when an absolute URL's path falls outside `_base_path`.

### 2. Stateful Producer-Consumer Inference, `BFS-Fast`, and Cloud Security Checkers (`RESTler` & `ISSTA 2022`)

`Basis: documentation + source + execution + derived`

1. **Four-Way Producer-Consumer Inference Split in `RESTler` (`Dependencies.fs` & `ApiResourceTypes.fs:286–288`):**

### 3. Consumer-Driven Contract Loose-Matcher Escapes & Deployment Asymmetry (`Pact` vs. `Schemathesis`)

`Basis: source + execution`

1. **Five Provider-to-Consumer Verification Escapes in `pact_matching` (`rust/pact_matching/src/json.rs:9, 94–285, 444–476`):**
   - Idiomatic consumer pacts using `like(...)` (`MatchingRule::Type`), `regex(...)`, and `boolean(...)` pass provider verification (`loose_Pact_Ok=5/5`) on five malformed payloads in Probe 3 that deterministically break a strict typed consumer (`strict_typed_consumer_Ok=0/5`):
     1. *Float-for-Integer (`json.rs:125`):* `MatchingRule::Type` matches `(&Value::Number(_), &Value::Number(_)) => Ok(())`, accepting `42.75` for `like(42)` unless `MatchingRule::Integer` (`L197`: `actual_value.is_i64() || actual_value.is_u64()`) is used.
     2. *Empty-Array Vacuity (`json.rs:123`):* `MatchingRule::Type` matches `(&Value::Array(_), &Value::Array(_)) => Ok(())`, passing `[]` without checking any element's `{"sku": ...}` object contract unless `MatchingRule::MinType(1)` (`L133`) is specified.
     3. *Unanchored Multiline Oniguruma `Regex` + Non-String `.to_string()` Coercion (`json.rs:9, 97–101`):* `re.is_match(&actual_str)` searches unanchored substrings under `onig::Regex` (where `^`/`$` match `\n` line boundaries rather than string ends, requiring `\A...\z`) AND `L99` converts non-string JSON values via `actual_value.to_string()`, so `Regex(r"\d{8}")` passes integer `20260115` (`nonstring_int_regex_coerced=True`).
     4. *Stringified `Boolean` Coercion (`json.rs:270–277`):* `MatchingRule::Boolean` accepts `Value::String("true" | "false")`, whereas `MatchingRule::Type` on `true` (`L124`) enforces strict JSON `Value::Bool`.
     5. *Response `AllowUnexpectedKeys` (`json.rs:445–476`):* Pact enforces `NoUnexpectedKeys` on requests but `AllowUnexpectedKeys` on responses, passing extra provider fields (`"debug_trace"`) that reject deserialization under `#[serde(deny_unknown_fields)]` or `additionalProperties: false`. Hardening all five rules cuts false passes to **`0 / 5`** (`hardened_Pact_Ok=0/5`).
2. **Missing `--state-change-url` Silent No-Op & `can-i-deploy` Directional Asymmetry:**
   - In `pact_verifier` (`rust/pact_verifier/src/callback_executors.rs:188–193`), omitting `--state-change-url` on a stateful interaction logs a warning (`"State Change ignored as there is no state change URL provided"`) and returns **`Ok(hashmap!{})`**, leaving provider state unseeded. Static **Bi-Directional Contract Testing** (comparing consumer pacts against a provider OpenAPI document without running provider state callbacks) likewise cannot observe state-conditional `404`/`409` transitions or runtime serializer drift from hand-maintained specs.
   - In `pact_broker` (`lib/pact_broker/matrix/deployment_status_summary.rb:114–155`), `can-i-deploy` is directionally asymmetric: deploying an unverified consumer version to production fails (`(False, 'PactNotEverVerified')`), whereas deploying a new provider with zero registered consumers succeeds (`(True, 'NoDependenciesMissing')`). Consumer-driven contracts (`Pact`) and schema fuzzing (`Schemathesis`) are therefore non-subsuming: `Schemathesis` catches `500` crashes and code-vs-spec drift missed by loose Pact matchers, while `Pact` `can-i-deploy` blocks breaking provider field removals that remain valid OpenAPI changes.

### 5. Pagination Consistency Under Writes & Two-Regime `HTTP 429` `Retry-After` Backoff

`Basis: normative + source + execution + derived`

1. **Offset vs. Single-Column vs. Composite Keyset Pagination (`Winand, 2012`, `RFC 8288`, Probe 5 `[illustrative analytical model]`):**
   - Scanning an $N = 1,000$-row table at $P = 25$ (`40` pages, `8` rows sharing each `created_at` second):
     - **`LIMIT 25 OFFSET 25k`:** Touches $\sum_{k=0}^{39} 25(k+1) = \mathbf{20,500}$ index entries (`20.5x` keyset's `1,000`), emits **`78` duplicates** under `+2`/page prefix inserts, and **permanently skips `74` rows** under `-2`/page prefix deletes.
     - **Single-Column Cursor (`WHERE created_at < :last_ts`):** Because $25 \bmod 8 = 1$ splits timestamp cohorts across page boundaries, strict `<` drops the remaining `7` tied rows at every split boundary—losing **`217` of `1,000` rows (`21.7%`)** even without concurrent writes.
     - **Composite Keyset Seek (`WHERE (created_at, id) < (:last_ts, :last_id)`, carried in `RFC 8288` `Link: <...>; rel="next"`):** Scans **`1,000`** rows (`1.0x`) with **`(0, 0)` duplicates/skips** under concurrent inserts and deletes on immutable keys, but misses **`1` row** (`mutable_sort_skips=1`) when an unvisited row's mutable `updated_at` advances past `:last_ts` mid-scan—requiring an immutable monotonic sequence (`seq_id`) or MVCC snapshot transaction.
2. **Coarse `1*DIGIT` `Retry-After` Thundering Herds, `RESTler` Fixed-`5s` Drops, & Additive Jitter (`RFC 9110 §10.2.3`, `RFC 6585 §4`, `Brooker 2015`, `RESTler` `request_utilities.py:425–479`):**
   - Porting Brooker's discrete-event OCC simulator (`aws-samples/aws-arch-backoff-simulator@66cb1692` `src/backoff_simulator.py`, $C = 100$ clients, `25` trials, `Net(10, 2)`, `base=5, cap=2000`, `1`-indexed retry counter) reproduces `FullJitter` cutting mean server write calls by **`56.5%`** vs. `Exponential` (`797.7` vs. `1,834.2` calls; completion `5,069.2 ms` vs. `62,495.1 ms`) and beating `EqualJitter` (`811.7` calls, `6,468.9 ms`), with `Decorr` fastest to finish (`4,598.9 ms`, `998.7` calls).
   - Under `HTTP 429` (`RFC 6585 §4`, p. 3), **`RFC 9110 §10.2.3` (`STD 97`, `194` pp., pp. 89–90)** restricts `delay-seconds = 1*DIGIT` to non-negative integers. When $C = 100$ clients hit a contended token bucket ($B = 10, r = 50\text{ tok/s}$ = `1` token per `20 ms`), the server must round sub-second waits up to **`Retry-After: 1` (`1,000 ms`)**:
     - **Regime A (Contended Token Bucket):** Obeying `Retry-After: 1` literally (`Literal_RA`) re-fires all `90` throttled clients in phase-locked `1,000 ms` waves (`443` `429`s, `90` reqs/50ms retry spike, `p99 = 9,214.8 ms`). In `microsoft/restler-fuzzer@6d984dee`, `RetryStrategy.EXPONENTIAL` (`restler/engine/core/retry_handler.py:49–50`) is **dead code** outside `restler/unit_tests/test_retry_handler.py:35` (and `RetryHandler()` at `request_utilities.py:77` runs only for token refresh in `L65–95`); actual `HTTP 429` handling in `request_utilities.py:425–479` (`send_request_data`) sleeps a **fixed `5` seconds** (`RETRY_SLEEP_SEC = 5`, ignoring `Retry-After`) up to `MAX_RETRIES = 5`. Simulating `RESTler_Fixed5s` fires `5` synchronized `5,000 ms` waves—each draining only `B = 10` tokens while overflowing `240` tokens of idle refill—incurring `350` `429`s, a `90`-req/50ms retry spike, and **permanently dropping `50 / 100` requests** at `MAX_RETRIES = 5`, while synthetic unbounded `Unjittered_Expo` (`min(16s, 1s * 2^k)`) incurs `437` `429`s and inflates `p99` to **`95,214.5 ms`**. Treating `Retry-After` as an additive floor (`sleep = Retry_After + jitter`) breaks synchronization with zero dropped requests: `RA+FullJitter` cuts `429`s to **`188` (`-57.6%`)**, peak burst to **`23`** (`-74.4%`), and `p99` to **`4,446.8 ms` (`-51.7%`)**; `RA+Decorr` cuts `429`s to **`146` (`-67.0%`)** and peak burst to **`12`** (`p99 = 4,666.0 ms`).
     - **Regime B (Fixed Quota-Window Reset):** When a single-tenant quota window resets deterministically at $t = 2,000\text{ ms}$ with capacity $\ge C$ (`Retry-After: 2`, initial `429` received at $t_0 = 20\text{ ms}$), sampling blind jitter *under* `Retry-After` (`sleep = U(0, 2000.0)`, `Blind_U_0_RA`) causes **`99 / 100` (`99%`) premature `429` rejections** before $t = 2,000\text{ ms}$—matching the exact analytical probability $(2000 - 20) / 2000 = 0.99$—whereas `RA_Plus_FullJitter` (`2000.0 + U(0, 250.0)`) incurs **`0 / 100`** premature rejections.

## Boundaries

- **Proprietary cloud target schemas and live external API endpoints (`not examined`):** Closed-source Microsoft Azure and Office 365 service specifications and internal bug reports referenced in Atlidakis et al. - **White-box JVM evolutionary coverage vs. non-JVM runtimes and stylized DES parameters (`known not to apply`):** `EvoMasterWB`'s white-box coverage advantage (`52.76%` vs. `32.19%`–`45.41%` black-box in Kim et al., `ISSTA 2022`, Table 3) relies on JVM bytecode instrumentation and JaCoCo over `20` Java/Kotlin services and is **known not to apply** directly to Python, Go, or Rust services lacking equivalent evolutionary bytecode runners. - **Explicit dialect, compiler, and executor feature gaps (`unsupported`):** Array-valued `type` keywords (e.g., `type: ["string", "null"]`) and `$ref` sibling keywords are **unsupported** in strict OpenAPI `3.0.3`/`3.0.4` (`versions/3.0.3.md:2314, 2326–2328`); `nullable` as a normative type-widening keyword is **unsupported** in strict OpenAPI `3.1.0`/`3.1.1` (`versions/3.1.0.md:2331–2338`, `3.1.1.md:2749–2757`); `PATCH` exact-endpoint producer lookup (`getIndexedByEndpointProducers`, `Dependencies.fs:353–355`) and unannotated `Query` parameter producer inference (`Dependencies.fs:311–314`) are **unsupported** in `microsoft/restler-fuzzer@6d984dee`; and `HTTP PATCH` execution in `RestGPT` `RequestsCaller` (`model/caller.py:189`, raising `NotImplementedError`) is **unsupported** despite `utils/oas_utils.py:113` exposing `patch` endpoints to the planner.
