# R534 Rust local-identity HIR recheck, with R565 identity context

## Scope and result

The published [R534 local/nested-item report](../rust-local-nested-items-nightly-2026-05-31/REPORT.md) (REPORT.md SHA-256 `6fc4f5702da4dd9a616090d014b551202d7094fcd789e46e3237372265816b9c`) described block-local items, closures, anonymous constants, and compiler definition paths at Rust commit `f8a08b688cbe60acc386ed1fbd1b7cbaaf5576b1`. The related [R565 name-resolution report](../rustc-name-resolution-stable-item-identity-nightly-2026-05-31/REPORT.md) (SHA-256 `c3d3788c3b1bd83a59a3265fa8694914138c00e9e6edf2af408e3db41f63c7bb`) used a different source commit, `14210df0e27ccd7d9e6a05b8085cbd438e4bbc65`, for broader identity claims. Neither executed a compiler identity fixture. This report runs R534's retained [`probes/local.rs`](../rust-local-nested-items-nightly-2026-05-31/probes/local.rs) against two already installed rustc nightlies. It supplies a narrow runtime recheck for R534 and an illustration of R565's warning about numeric session IDs; it does not directly revalidate R565's source pin or its name-resolution and hash-stability claims.

The **exact retained fixture fails to parse in both toolchains**. Its first two bytes are a literal backslash and newline (`5c 0a`); both rustc processes report `unknown start of token: \` at line 1. The [original fixture](fixture/original-local.rs) is preserved byte for byte, SHA-256 `bb1204b54f7fd536e5b1c4875cf2440dc3005f14dd5c64f3fdf30fa549a36691`. The [repaired specimen](fixture/repaired-local.rs) removes exactly those two bytes. The [inserted-control specimen](fixture/shifted-local.rs) additionally inserts one closure and one inline const before the original closures. These are labeled experimental inputs, not the original fixture's bytes.

For each repaired or inserted specimen, `rustc -Zunpretty=hir-tree` exited 0 under both versions, as did a separate `--emit=metadata` compile. Across the two toolchains, the HIR output displays the same **23 distinct `DefId` paths** for the repaired specimen and **25** for the inserted control, including the crate root and injected prelude paths, with the same numeric `DefId` indices for corresponding paths. The printed crate tag differs: `local_identity[18ae]` in May and `local_identity[fcc1]` in September. The complete HIR text is not byte-identical across versions; this report compares the extracted displayed fields, not a serialized compiler identity guarantee.

## Exact observations

| Input | May 31 nightly | Sep 30 nightly | Meaning |
| --- | --- | --- | --- |
| Original 577-byte fixture | parse exit 1 | parse exit 1 | Leading backslash prevents valid semantic execution. |
| Repaired 575-byte fixture | HIR exit 0, compile exit 0; 23 displayed paths | HIR exit 0, compile exit 0; 23 displayed paths | Both expose distinct `outer_a::inner` and `outer_b::inner`, block-local `Local` and its impl, `outer_a::generated_local`, two closures, and three anonymous constants. |
| Inserted 700-byte control | HIR exit 0, compile exit 0; 25 displayed paths | HIR exit 0, compile exit 0; 25 displayed paths | The added closure and inline const receive anonymous paths in both versions. |

In the repaired input, the two closure paths under `outer_a` display `{closure#0}` and `{closure#1}`, and the three anonymous constant paths display `{constant#0}` through `{constant#2}`. Inserting an earlier closure and constant yields three closure paths and four constant paths. The original closure and constant expressions now occur after the inserted expressions, so their displayed sibling numbers shift. Numeric `DefId` indices for later unchanged named items shift too: `outer_b` moves from 18 to 20, and `main` from 20 to 22, in both toolchains. This directly illustrates why a numeric session `DefId` or anonymous sibling label should not be treated as an edit-invariant source ID.

The HIR dump does **not** print `DefPathHash`, and the short `[18ae]` / `[fcc1]` crate tags are printed diagnostics, not a measured 128-bit hash. We do not claim a `DefPathHash` equality or difference. The observed path/index agreement on one unchanged specimen cannot establish cross-version identity stability in general. The exact source-review target, stable rustc 1.98.1, is installed but was **not** used for HIR comparison; this experiment instead compares the two named nightlies. It does not run Charon, Aeneas, Anneal, or a compiler driver callback.

## Toolchains, resources, and replay

May 31 uses `rustc 1.98.0-nightly`, commit `f8a08b688cbe60acc386ed1fbd1b7cbaaf5576b1`, executable SHA-256 `2ab7af1ea2ec5c69195fd8dfb0e1f91afdb7cc1e53127bba416616ce43a18dbc`. September 30 uses `rustc 1.101.0-nightly`, commit `5c543b0b8c73c7b72bc8284ced4fb22ead15734d`, executable SHA-256 `29f8ccc9aa7b0d8798eda854fa7f0e4ba3867c8c336b87d52dbb3b24b3f0878d`. Both are arm64 macOS binaries; their full `rustc -Vv` output and absolute command arrays are in [results.json](results.json).

The probe ran 10 corrected cells serially, checking before each that estimated reclaimable RAM exceeded 20%, free disk exceeded 1 GiB, and owned raw output was below 100 MB. Minimum recorded admission was **24.1697%** RAM and **4,246,933,504** free disk bytes; maximum owned raw output at admission was **955,572** bytes. No download, install, server process, or shared-checkout edit was needed. The metadata compile emitted a zero-byte `.rmeta` for this binary crate; compilation success is established by exit status, not metadata content.

An initial four metadata attempts used `/dev/null` as output. rustc then tried to create a temporary file under `/dev` and failed with `Operation not permitted`; these were setup-path failures, not compiler-version results. Their original records are retained in [initial-devnull-results.json](support/initial-devnull-results.json) and corresponding `raw/*metadata-devnull*` files. The corrected local-output cells are the ones interpreted above.

[Raw outputs](raw/), [analysis.json](analysis.json), and [fixture variants](fixture/) preserve the evidence. From this package, `python3 -B support/check.py` checks exact input derivations, all output and executable hashes, version strings, commands, resource arithmetic, the displayed HIR map, and the excluded setup attempts without invoking any compiler. `python3 -B support/probe.py` actively repeats the small comparison using the two installed toolchains. Different rustc releases may change HIR formatting, and a future identity study should use a compiler driver to print `DefPathHash`, parent, kind, and span for each definition.
