# Thirty-two Lean rich RPC references: release and keep-alive in one session

## Result and scope

One pinned Lean 4.30.0-rc2 direct server returned **32 distinct** `InfoWithCtx` references for 32 named hypotheses in one goal. All 32 resolved successfully before release. The client released the 16 odd-indexed references in one `$/lean/rpc/release` notification, sent five `$/lean/rpc/keepAlive` notifications over **43.2004 seconds**, and then queried all 32 exact references through the original session. All 16 released references returned `-32602` with their own `RPC reference '…' is not valid` error; all 16 retained references returned successful interactive popups. The retained popup documentation and rendered expression text matched their pre-release responses.

This is a many-reference **functional** control for #3731 **I044**, with #3730 **C08** context. It extends the previous single-reference keep-alive report, which resolved one reference after 43.1137 seconds, and the earlier one-reference release control. It does not measure attributable reference-retention memory, a scale curve, or any Anneal product policy.

## Limits

The observed 32-reference split shows that explicit release invalidated selected references while their unreleased peers remained usable under this keep-alive schedule. It does not isolate keep-alive's causal effect against a same-fixture no-message run; the separately published one-reference no-message control expired after 42.01 seconds. It does not establish the precise expiry threshold, unbounded survival, memory reclaimed by release, behavior with hundreds of references, imported definitions, document edits, cancellations, file/worker/server replacement, or reference collision across sessions. No batch proof passed; the fixture deliberately contains `exact ?_`. No Anneal V2, MCP broker, editor, generated workspace, or durable historical-query service was exercised. I044 and C08 therefore remain partial at their product gates.
