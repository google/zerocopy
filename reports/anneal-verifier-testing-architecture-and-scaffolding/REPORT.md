# Testing Architectures, Fenced Testkits, and Soundness Oracles for Rust-to-Lean Verification Toolchains

## Summary

- **Fenced two-zone Cargo workspaces cut human-audited TCB volume by one-third while preserving full feature-gated CLI testing:** In `google/zerocopy@74d509c8529b05e0e4839cc739d6da2fe0841e41`, `anneal/trusted/` contains `113` files (`88,328` lines), of which `50` files (`29,965` lines, `33.92%`) are non-shipping integration tests and fixtures under `trusted/{audit,cargo-anneal,rustc-capture}/tests/`. Moving integration suites into `publish = false`, build-script-free workspace crates under `tests/` requires two coupled invariants in `check_cargo_boundary`: (1) generalizing strict target-zone checks (`to.starts_with("trusted/")`) to a **two-zone monotonic lattice** (`Zone::Trusted = 0 < Zone::Tests = 1`, requiring `zone(to) <= zone(from)`) so `tests/{audit,cargo-anneal,rustc-capture}` can share `tests/testkit` while `trusted/*` remains strictly forbidden from depending on `tests/*`; and (2) exposing `#[doc(hidden)]` library CLI entrypoints paired with non-colliding `*-test-bin` binary targets in `tests/*` so `--no-default-features` integration tests invoke binaries compiled with the exact active Cargo feature set via `CARGO_BIN_EXE_*`.
- **Decomposing multi-thousand-line integration monoliths requires domain-submoduled single-binary crates plus typestate fixture builders:** Across `anneal`'s `14` Cargo integration test binaries (`27,771` Rust lines, `257` `#[test]` functions, `7` `#[ignore]`), four files account for `65.0%` (`18,037` lines) of all test code (`boundary_audit.rs` `9,824`L, `integration.rs` `4,315`L, `target_audit.rs` `2,332`L, `mvp_e2e.rs` `1,566`L) and duplicate tool-discovery, temp-staging, and process-supervision boilerplate four times. Splitting monoliths into `N` separate top-level `tests/*.rs` files forces Cargo to link `N` multi-hundred-megabyte test executables (especially costly when linking `rustc_private`); grouping domain submodules under **one integration test binary per test crate** (`tests/suite/main.rs`) paired with `cargo-nextest` (`nextest-rs/nextest@26ebeda79b9ae1d008cf64ddb01984bcaa6e1239`, `v0.9.152`) provides process-per-test crash isolation, `slow-timeout` hang termination, and single-link compilation.
- **Soundness verification requires both stage-typed `must-reject` UI directives and public-entrypoint guard-ablation mutation:** Stage-typed `//@ fail(capture | spec | proof, <scope>): "<substr>"` directives (`integration.rs`, inspired by `rustc` `compiletest` and `oli-obk/ui_test@7917d5025f381a7348d7a78dbe557c4bd64e8cbd` `v0.30.7`) prevent polarity-flipping `ANNEAL_BLESS=1` updates and cross-stage false kills, while single-guard mutation (`ci/check_guard_mutation.py`, `46` cataloged Lean TCB guards) proves each UB or import guard is non-redundant. However, Rust TCB guards inside `rustc-capture` (sysroot DSO residency, `env_depinfo`, `required_consts` CTFE) and NDJSON structural comparators currently lack mutation coverage, requiring a unified guard-ablation schema keyed to negative corpus cases through public entrypoints.
- **Dual differential oracles close both semantic modeling drift and single-kernel `.olean` deserialization trust:** At the MIR layer, four-way differential execution (`rustc -C opt-level=0 -C overflow-checks=no`, `Miri`, Lean `MirSemantics`, and `cargo-anneal verify`) separates exact semantic agreement from intentional conservative over-approximations (such as faulting on post-`Operand.move` reads of `Copy` locals). At the proof-auditing layer, Lean `v4.35.0` (`leanprover/lean4@eb6cafb7290e8bd5f2937522d8d804f58f02bafc`) enables replacing `.olean` memory-mapping (`CompactedRegion.read`) in the verdict process with disjoint `leanexport` (`3.1.0`) NDJSON streams (`5-init`, `5a` expected-only, `5b` proof), a safe-Rust alpha-equivalence DAG comparator (`5c`), and `ExecSeal`-confined independent kernels (`nanoda_bin 0.4.19` + `con-ron --verified` by default; `+ con-leche + lean4lean --import` under paranoid quorum), bypassing upstream `Lean/Replay.lean`'s `String.ofList` `Name.quickCmp` replay bug in `leanchecker --from-export`.
- **Hermetic simulation of split Nix/CAS stores in Rust tests is governed by three OS and sandbox invariants:** Verified by standalone execution (`support/verify_testing_invariants.py`), deterministic split-output store tests must (1) wrap `0o555`/`0o444` directories in a top-down `chmod u+rwx` drop guard (`shutil.rmtree` / `TempDir::drop` otherwise fails with `EACCES`), (2) place `cwd` and simulated `PT_INTERP`/`DT_RUNPATH` store trees in **disjoint sibling subdirectories** (`<root>/work/` vs. `<root>/store/`) so `canon_cwd.starts_with(runpath_dir)` (`identity.rs:440-446`) does not reject the loader directory, and (3) bind cross-package symlink forests (`0002-lean-joined -> 0001-lean-unwrapped`) to `/nix/store` inside unprivileged `bubblewrap` (`bwrap --ro-bind <store> /nix/store`) because `symlink_stays_within_dedicated_root` (`sandbox.rs:588-600`) rejects cross-directory symlinks outside `/nix/store`.
- **First-customer `zerocopy` corpora and cold `lean -j1` umbrella gates catch crate-wide and scaling cliffs invisible to unit fixtures:** Running verbatim `zerocopy` (`33,939` LOC, `4,545` MIR bodies, `547` `unsafe` blocks, `63` Kani contracts) immediately exposed crate-wide `enum_id` collisions in anonymous `const _` blocks and `env!("CARGO_PKG_VERSION")` `env_depinfo` rejections inside `#[doc]` attributes. Simultaneously, `installed_smoke.rs:lean_case` compiles the full `Anneal` umbrella (`73` reachable Lean modules, `66,307` lines, `28`-module `19,704`-line critical path) under `lean -j1 -DElab.async=false -Ddebug.skipKernelTC=false` (`120 s` per-child timeout)—including `36` `theory/` modules (`43,393` lines) outside the `18`-module `theory/bundle-manifest.json` (`16,799` lines)—creating an unbudgeted cold-elaboration and peak-RSS cliff unless per-module time, RSS, `.olean` size, and constructive axiom-footprint budgets are enforced as first-class CI gates.

### 1. Fenced Non-Publishing Test Workspaces and Two-Zone Cargo Boundary Lattices

Basis: source (`google/zerocopy@74d509c8529b05e0e4839cc739d6da2fe0841e41`: `anneal/Cargo.toml`, `anneal/trusted/audit/src/cargo_boundary.rs`, `anneal/trusted/{audit,cargo-anneal,rustc-capture}/Cargo.toml`; `verus-lang/verus@d749566d31400c9d1ab437f0853ee16d769d1b04`; `creusot-rs/creusot@faeb61f5b5a8ffda94fde1f100ef96a1d798088b`) + execution (`support/verify_testing_invariants.py`) + derived

#### 1.1 Measured TCB Inflation When Integration Suites Live Inside `trusted/`

At `google/zerocopy@74d509c8529b05e0e4839cc739d6da2fe0841e41`, `anneal/Cargo.toml` admits only three workspace members (`trusted/audit`, `trusted/cargo-anneal`, `trusted/rustc-capture`), and `check_cargo_boundary` (`trusted/audit/src/cargo_boundary.rs:555-561`) rejects any workspace member or local `path` dependency outside `trusted/`. Consequently, all integration harnesses, synthetic `.olean`-forging scripts, and multi-file test fixtures reside inside `anneal/trusted/*/tests/`:

| Subtree in `anneal/trusted/` (`74d509c852`) | Files | Lines (LOC) | Share of `trusted/` LOC | TCB Role |
| :--- | ---: | ---: | ---: | :--- |
| Non-test production sources, locks, and manifests | `63` | `58,363` | `66.08%` | Human-audited verification TCB (`rustc-capture`, `cargo-anneal`, `anneal-audit`, `Trusted.*`, `Trusted.Correspondence.*`, `TrustedBoundary.lean`) |
| Embedded integration suites (`trusted/*/tests/**`) | `50` | `29,965` | **`33.92%`** | Non-shipping test harnesses (`27` `.rs` files = `27,771`L; `23` `.lean`/`.json` fixtures = `2,194`L) |
| **Total `anneal/trusted/`** | **`113`** | **`88,328`** | **`100.00%`** | Inflates human TCB review surface and forces `Cargo.toml` `exclude` filters + dev-dependency leakage into `Cargo.lock` |

Peer Rust formal verifiers avoid co-locating integration harnesses inside compiler/verifier crates: `verus-lang/verus@d749566d31400c9d1ab437f0853ee16d769d1b04` isolates end-to-end verification suites in a dedicated non-published `source/rust_verify_test` crate, and `creusot-rs/creusot@faeb61f5b5a8ffda94fde1f100ef96a1d798088b` separates UI/Why3 runner crates from `creusot` driver internals.

#### 1.2 Why Strict Target-Zone Filtering Blocks Shared Testkits—and the Two-Zone Monotonic Lattice

A naive relaxation of `check_cargo_boundary` that admits workspace members in `trusted/*` or `tests/*` while requiring every `path` dependency across all members to satisfy `rel_str.starts_with("trusted/")` enforces one-way `tests/ -> trusted/` edges for isolated leaf test crates (`tests/audit`, `tests/cargo-anneal`, `tests/rustc-capture`), **but makes a shared test-support crate (`tests/testkit`) impossible**: `tests/audit -> tests/testkit` fails `rel_str.starts_with("trusted/")`, while placing `testkit` inside `trusted/` re-contaminates the TCB.

Generalizing `validate_dep_table` (`cargo_boundary.rs:367-441`) to a **two-zone monotonic lattice** resolves this cleanly without weakening any TCB invariant:
- Assign every workspace member a total trust zone: $\mathrm{zone}(\text{member}) = 0$ for `trusted/*` (`Zone::Trusted`) and $\mathrm{zone}(\text{member}) = 1$ for `tests/*` (`Zone::Tests`); reject any path outside `{trusted/*, tests/*}`.
- Across all five Cargo dependency tables (`dependencies`, `dev-dependencies`, `dev_dependencies`, `build-dependencies`, `build_dependencies`) and `[target.<cfg>.*]` sections:
  1. Reject `git` and custom `registry` dependencies, `package.build`, `build.rs`, `package.workspace`, and target-path `..` escapes across **both** zones (`Cargo.lock` provenance remains 100% `crates.io-index` SHA-256 + workspace members).
  2. Require `package.publish == Some(Boolean(false))` on every `Zone::Tests` crate.
  3. Require every local `path` dependency edge `src -> dst` to target a registered workspace member and satisfy **zone monotonicity**:
     $$\mathrm{zone}(\text{dst}) \le \mathrm{zone}(\text{src})$$
     Thus `Zone::Trusted` (`0`) can depend only on `Zone::Trusted` (`0`)—blocking `trusted/* -> tests/*` in both `[dependencies]` and `[dev-dependencies]`—while `Zone::Tests` (`1`) can depend on both `Zone::Trusted` (`0`) and `Zone::Tests` (`1`, such as `tests/testkit`), with cycle freedom guaranteed by Cargo's crate DAG. As verified across all `12` boundary cases in `support/verify_testing_invariants.py`, the monotonic lattice differs from `to.starts_with("trusted/")` strictly on `Zone::Tests -> Zone::Tests` shared-harness edges while rejecting every TCB-escape, non-member, `publish != false`, and `build.rs` vector.

#### 1.3 Feature-Preserving Binary Shims (`*-test-bin`) and Runtime Asset Separation

Moving `trusted/<crate>/tests/` into `tests/<crate>/tests/` breaks `env!("CARGO_BIN_EXE_<bin>")` because Cargo sets `CARGO_BIN_EXE_*` only for binaries defined in the *same* Cargo package as the integration test. Invoking prebuilt `target/debug/<bin>` paths instead creates two subtle hazards: (a) running `cargo test -p cargo-anneal-tests --no-default-features --test cli` can silently execute a stale default-feature `cargo-anneal` binary left in `target/debug/`, and (b) declaring `[[bin]] name = "cargo-anneal"` in both crates collides in `target/<profile>/`.

Exposing a minimal `#[doc(hidden)] pub fn cli_main() -> ExitCode` from each `trusted/` library and adding a 4-line `src/bin/<crate>-test-bin.rs` shim inside each `tests/<crate>` package (forwarding Cargo features such as `setup = ["cargo-anneal/setup", "dep:exocrate"]`, and `#![feature(rustc_private)] extern crate rustc_driver;` for `anneal-rustc-capture-test-bin`) ensures `CARGO_BIN_EXE_<crate>-test-bin` is compiled on demand with the exact active feature flags and zero filename collisions. Simultaneously, runtime assets required by `cargo-anneal skill --example` (`scalar/{lib.rs,request.json,Spec.lean,Proof.lean}`, `97` lines) belong in `trusted/cargo-anneal/assets/scalar/` rather than `tests/fixtures/`, decoupling `cargo publish` packaging from the test suite.

Four structural anti-patterns drive monolith growth and maintenance friction:
1. **4x duplicated tool discovery and subprocess wrappers:** `integration.rs:73-170` (`Tools::discover`, explicitly carrying comment `// Keep in sync with Tools::discover in tests/mvp_e2e.rs`), `mvp_e2e.rs:33-121`, `installed_smoke.rs:154-217`, and `rustc-capture/tests/common/mod.rs` independently resolve `ANNEAL_CLI`, `ANNEAL_CAPTURE`, `ANNEAL_LEAN`, `ANNEAL_SYSROOT`, and `ANNEAL_TEST_INSTALL_ROOT` with subtly divergent env-var precedence (`ANNEAL_MVP_*` accepted in `integration.rs` but not `mvp_e2e.rs`).
2. **Orphaned grandchild leaks under direct-child `wait_timeout`:** `support/mod.rs:263-276` kills only the direct child PID (`child.kill()` + `child.wait()`), explicitly noting in comments that orphaned grandchildren (`lean`, `rustc`, `ld`) survive until CI's outer 90-minute job timeout. As proved in [`reports/anneal-subprocess-supervision-elf-runpath-and-archive-packaging/`](../anneal-subprocess-supervision-elf-runpath-and-archive-packaging/REPORT.md), combining `CommandExt::process_group(0)` with `PR_SET_CHILD_SUBREAPER` and `waitpid(-pgid)` until `ECHILD` reaps the entire subprocess tree synchronously in `~157 µs` without leaking file locks.
3. **Cargo multi-binary link amplification vs. single-binary domain trees:** In Cargo, every `tests/<name>.rs` file compiles and links a separate executable. Splitting `boundary_audit.rs` (`9,824`L) and `typed_capture.rs` (`2,643`L) into 20 top-level `tests/*.rs` files would link `anneal-audit` and `rustc_private`-linked harnesses 20 times, inflating debug `target/` disk usage by gigabytes (cf. [`reports/ci-core-sandboxed-github-actions-and-nix-container-economics/`](../ci-core-sandboxed-github-actions-and-nix-container-economics/REPORT.md)). Organizing each fenced test crate around **one primary integration binary** (`tests/suite/main.rs` with domain submodules `cargo_boundary.rs`, `preflight.rs`, `pass1_audit.rs`, `pass2_correspondence.rs`, `miri_cache.rs`) plus any feature-isolated binary (`cli_offline.rs` for `--no-default-features`) links once while decomposing files to `<800` lines each.
4. **Thread-shared `libtest` state vs. `cargo-nextest` (`0.9.152`):** Under `cargo test`, concurrent tests share process-wide environment variables, `cwd`, and signal masks, forcing `integration.rs:2575-2660` to implement a custom `Condvar` job semaphore (`ANNEAL_TEST_JOBS`). Running single-binary suites under `cargo-nextest` (`nextest-rs/nextest@26ebeda79b9ae1d008cf64ddb01984bcaa6e1239`) executes each `#[test]` in its own OS process, tracks per-test wall time and peak RSS, enforces profile-driven `slow-timeout = { period = "30s", terminate-after = 4 }` budgets, and schedules heavy Lean tests via `threads-required = N` slots without custom `Condvar` plumbing.

#### 2.2 Typestate `anneal-testkit` Builder Invariants

Consolidating `support/mod.rs`, `Tools::discover`, `TempFixture`, `Fixture`, and `Capture` into a shared `tests/testkit` (`anneal-testkit`) crate allows invalid test setups to be excluded at compile time via typestate transitions:
- **`ToolchainEnv` (immutable validated tool coordinates):** Single canonical resolver enforcing explicit test-mode selection (`WorkspaceBuild` using `CARGO_BIN_EXE_*-test-bin` vs. `InstalledBundle` using `ANNEAL_TEST_INSTALL_ROOT` / `ANNEAL_TEST_ARCHIVE`), eliminating accidental cross-contamination between workspace tests and `installed_smoke` environment variables.
- **`WorkspaceBuilder<Z>` -> `StagedWorkspace<Z>` -> `ExecutedRun<R>`:**
  - In state `Building`, callers declaratively stage regular files, symlink topologies, or `ReadOnlyTreeGuard` (`0o555`) directories under a `0o700` canonicalized temporary root (`owned_path` + `reject_symlink_components` from `support/mod.rs:433-473`), with `work/` and `store/` automatically segregated into sibling directories.
  - Transitioning `.stage()?` freezes inputs, writes `run.json`, and yields `StagedWorkspace`, which exposes typed runners (`run_capture`, `run_verify`, `run_repo_audit`, `run_target_audit`) backed by process-group + subreaper supervision and automatic `commands/<NNNN>/{invocation.json,outcome.json,stdout,stderr,reproduce.py}` evidence recording.
  - Transitioning `.expect_policy_reject(phase, code, detail_substr)` or `.expect_verified()` consumes or borrows the typed `ReceiptV3` / `AuditVerdict`, automatically retaining and exporting the `0o700` evidence bundle to `ANNEAL_TEST_DIAGNOSTICS` if and only if an assertion fails (or `ANNEAL_KEEP_SANDBOX=1` is set), and otherwise running top-down `ReadOnlyTreeGuard` cleanup before `TempDir::drop`.

#### 3.2 Unifying `must-reject` Corpora with Guard-Ablation Mutation (`K_entry == 100%`)

As established in [`reports/guard-ablation-mutation-testing-and-postcleanup-mir-validation-contracts-for-verified-interpreters/`](../guard-ablation-mutation-testing-and-postcleanup-mir-validation-contracts-for-verified-interpreters/REPORT.md) and [`reports/boolean-derivative-guard-sensitivity-conjunct-independence-and-test-probe-evasion/`](../boolean-derivative-guard-sensitivity-conjunct-independence-and-test-probe-evasion/REPORT.md), a `must-reject` corpus and a guard-mutation harness are dual views of one soundness relation $G \times C$:
- Every `must-reject` fixture $c \in C$ asserts that the unmodified verifier rejects an invalid program, forged artifact, or vacuous spec at an exact `(phase, guard_family)`.

### 4. Multi-Oracle Differential Verification: Native/Miri Execution and Multi-Kernel NDJSON Quorums

Basis: source (`leanprover/lean4@eb6cafb7290e8bd5f2937522d8d804f58f02bafc`: `src/lean/Lean/Replay.lean`, `src/lake/Lake/CLI/Check.lean`; `leanprover/lean4export@5a9a355dc6c5fd82b69058d433e2ae2e8dfbf8fe`; `ammkrn/nanoda_lib@0da9f98feadd3a0a2ef4b3dbcf52a298a6fef929`) + derived (synthesizing [`reports/anneal-scalar-mir-differential-execution-and-capture-alignment/`](../anneal-scalar-mir-differential-execution-and-capture-alignment/REPORT.md), [`reports/reference-model-bisimulation-executable-semantics-and-differential-oracles/`](../reference-model-bisimulation-executable-semantics-and-differential-oracles/REPORT.md), and [`reports/lean4-external-checkers-nanoda-leanexport-and-compiled-checker-tcb/`](../lean4-external-checkers-nanoda-leanexport-and-compiled-checker-tcb/REPORT.md))

#### 4.1 Semantic Differential Oracles (`rustc` / `Miri` ↔ `Trusted.MirSemantics`)

Pass-2 deductive correspondence (`correspondence/Anneal/MirCorrespondenceProof.lean`, `25,037` lines across `16` files) mechanically proves simulation between `Trusted.MirSemantics` and vendored `lean-miri`. However, Pass 2 cannot by itself catch bugs in **capture lowering** (`rustc` internal MIR $\to$ `Captured.lean` AST) or **drift between `vendor/lean-miri` and real `rustc`/`Miri`**. A declarative `differential/` suite closes that empirical loop by running identical Rust inputs (including `#![feature(custom_mir)]` boundary programs) across four oracles:
1. **Native `rustc` execution** under the exact capture compilation profile (`-C opt-level=0 -C debug-assertions=off -C overflow-checks=no`) for defined-behavior boundary vectors;
2. **`cargo miri` execution** (with Tree Borrows / Stacked Borrows configured explicitly) as the executable UB oracle on concrete inputs;
3. **Executable Lean evaluation** (`MirTotal` / `MirSemantics` step evaluator) over the `rustc-capture`-emitted `Captured.lean` program; and
4. **End-to-end `cargo-anneal verify`** checking that defined-behavior vectors admit a valid proof and UB-exhibiting vectors fail closed (`proof_failed` or `unsupported`).

Crucially, the differential oracle assertion relation must encode **directional refinement** rather than naive equality on fault states:
$$\text{Lean Evaluates to }\mathsf{Ok}(v) \implies \text{Miri Evaluates to }\mathsf{Ok}(v) \land \text{Native Evaluates to }v$$
$$\text{Miri Raises UB} \implies \text{Capture Refuses }\lor\text{ Lean Evaluates to }\mathsf{Fault}$$
When `Miri` permits an execution (such as copying a `Copy` local after `Operand::Move` in `Runtime(PostCleanup)` MIR) while `Trusted.MirSemantics` faults (`.uninit` after `.move`), the case is classified explicitly as **`ConservativeFault`**—sound for verification (`Verified => UB-free`), tracked deliberately so neither silent unsoundness (`Miri UB` + `Lean Ok`) nor unintended completeness regressions pass unnoticed.

#### 4.2 Eliminating `.olean` Deserialization and Single-Kernel Trust via Disjoint NDJSON Quorums

2. **Safe-Rust hash-consed DAG comparison (`5c`):** A `#[forbid(unsafe_code)]` Rust parser interns `init`, `expected_cone`, and `proof_full` into one shared `CanonicalArena` (handling disjoint numeric NDJSON node indices across separate `leanexport` runs), checking alpha-equivalent DAG identity of every expected declaration and every pinned `Init` primitive, `Quot.{mk,lift,ind}` uniqueness, absence of `.opaqueInfo` / `partial` / `unsafe` declarations, `optParam`-stripped statement-origin isolation, and closed axiom allowlisting (`{Classical.choice, Quot.sound, propext}`, or `sorryAx` strictly on proof-only edges under `--allow-sorry-in-proof`).

Note that when `--allow-sorry-in-proof` is active and `sorryAx` is present, `con-ron` rejects `sorryAx` by design and must be recorded in `kernelsSkipped` with structured reason rather than silently dropped.
   - **Paranoid 4-kernel quorum (`--paranoid-quorum`):** Adds `con-leche` and `lean4lean --import` directly over `proof_full.ndjson` inside `ExecSeal` (note from [`reports/lean4-external-checkers-nanoda-leanexport-and-compiled-checker-tcb/`](../lean4-external-checkers-nanoda-leanexport-and-compiled-checker-tcb/REPORT.md) that `lean4lean` fails on raw `v4.35.0` `.olean` binary headers with `incompatible header`, whereas `lean4lean --import` over NDJSON `3.1.0` succeeds cleanly).

### 5. Hermetic Simulation of Split-Output Read-Only Stores, Symlink Forests, and ELF `DT_RUNPATH`

Basis: source (`google/zerocopy@74d509c852`: `anneal/trusted/rustc-capture/src/identity.rs:336-742, 951-1355`, `anneal/trusted/cargo-anneal/src/sandbox.rs:281-760`, `anneal/flake.nix:52-99, 265-320`) + execution (`support/verify_testing_invariants.py` -> `support/probe_results.json`)

1. **`ReadOnlyTreeGuard` for `0o555` directory teardown (`probe_results.json`):** Both `exocrate` archive extraction and Nix store derivations strip write bits (`0o555` on directories, `0o444`/`0o555` on files). 2. **Sibling segregation of `cwd` and simulated `PT_INTERP` / `DT_RUNPATH` directories (`identity.rs:440-446`):** When `anneal-rustc-capture` validates ELF `PT_INTERP` and `DT_RUNPATH` / `DT_RPATH` directories, `is_allowed_pt_interp_dir(dir)` (`identity.rs:409-448`) enforces:

   ```rust
   if let Ok(cwd) = std::env::current_dir() {
       let canon_cwd = fs::canonicalize(&cwd).unwrap_or(cwd);
       if canon_cwd.starts_with(dir) {
           return false;
       }
   }
   ```
   and `validate_toolchain_mount_dir` (`sandbox.rs:488-533`) enforces the identical check against `cwd`, `$HOME`, and `stage_root`. If a naive test creates a temporary directory `T`, places `libfoo.so` at `T/libfoo.so` (making `dir = T`), and runs the child process with `current_dir(T)` or `current_dir(T/work)` (`canon_cwd.starts_with(T) == true`), `is_allowed_pt_interp_dir` silently drops `dir` and fails closed! 3. **Cross-package symlink confinement in `sandbox.rs` vs. unprivileged `bwrap --ro-bind <store> /nix/store`:**
   - In `rustc-capture` (`identity.rs:1057-1234`), `RuntimeClosure::resolve` scans validated `PT_INTERP`/`DT_RUNPATH` directories (up to `MAX_DIRS = 256`, `MAX_SYMLINK_TARGETS = 1024`), follows non-toolchain symlinks (`libgcc_s.so.1 -> ../../0002-gcc-libgcc/lib/libgcc_s.so.1`), and admits their canonical `(st_dev, st_ino)` targets on **any** host path passing `is_allowed_pt_interp_dir`—so split-package C runtime DSOs (`gcc-lib` $\to$ `gcc-libgcc`) and explicit `ld-linux` launches (`identity.rs:713-740`) can be tested directly in `<temp_root>/store/` using tiny C/ASM stub `.so` fixtures patched with `patchelf` (or synthesized ELF64 headers) across the 5-cell `DT_RUNPATH` vs. `DT_RPATH` matrix ([`reports/anneal-subprocess-supervision-elf-runpath-and-archive-packaging/`](../anneal-subprocess-supervision-elf-runpath-and-archive-packaging/REPORT.md)).
   - By contrast, in `cargo-anneal` (`sandbox.rs:588-600`), `walk_dedicated_lean_stdlib_tree` checks symlinks inside `<prefix>/lib/lean` via:
     ```rust
     Ok(canon_target.starts_with(canon_root)
         || (canon_root.starts_with("/nix/store") && canon_target.starts_with("/nix/store")))
     ```
     Consequently, a Nix `symlinkJoin` Lean wrapper (`store/0002-lean-joined/lib/lean/Init.olean -> ../../../0001-lean-unwrapped/lib/lean/Init.olean`) is **rejected** if tested at `/tmp/.../store/0002-lean-joined` (`host_cross_pkg_symlink_stays_within_joined_root = false`), because cross-directory symlinks are permitted **strictly when both `canon_root` and `canon_target` reside under `/nix/store`**. (When testing `NestedBwrap` inside outer CI containers, apply the `ci-core` outer/inner capability contract from [`reports/ci-core-sandboxed-github-actions-and-nix-container-economics/`](../ci-core-sandboxed-github-actions-and-nix-container-economics/REPORT.md).)

#### 7.2 Four Orthogonal Performance, Memory, and Axiom Hygiene Gates

Preventing late CI timeouts, OOM kills on 16 GiB runners, and silent constructive-axiom regressions requires a dedicated `perf-and-hygiene` gate recording JSON metrics across four dimensions:
1. **Per-module cold `lean -j1 -DElab.async=false -Ddebug.skipKernelTC=false` wall-clock & instruction/heartbeat budgets:** Enforce a hard per-module cold wall-clock ceiling well below `installed_smoke`'s `120 s` timeout (e.g., `60 s` warning / `90 s` hard fail on standard CI hardware, paired with deterministic `maxHeartbeats` caps inside `theory/` modules) and split `4,000+`-line modules before they approach the cliff.

3. **End-to-end `cargo-anneal verify` & `installed_smoke` stage-latency budgets:** Record structured phase timings (`capture_ms`, `spec_preflight_ms`, `compile_ms`, `export_expected_ms`, `export_proof_ms`, `rust_compare_ms`, `nanoda_ms`, `con_ron_ms`) on canonical benchmark targets (`scalar`, `spin`, `scale_50_fns`, `starnix`, and verbatim `zerocopy` items).
