# Stateful Enterprise Workflows, Evaluator Side-Effect Blind Spots, HTTP Idempotency Keys, and Saga Compensation Laws

## Summary

Primary-source analysis of 13 peer-reviewed papers and preprints (1987–2026), the IETF HTTPAPI `Idempotency-Key` specification (`draft-ietf-httpapi-idempotency-key-header-09`), line-level source code forensics across nine pinned public GitHub repositories (`StonyBrookNLP/appworld`, `apple/ToolSandbox`, `ServiceNow/WorkArena`, `TheAgentCompany/TheAgentCompany`, `ietf-wg-httpapi/idempotency`, `temporalio/temporal`, `temporalio/sdk-python`, `temporalio/ai-integrations`, `mustafarslan/janus`), and a deterministic five-pillar Python 3.10+ standard-library verification suite (`scripts/verify_enterprise_stateful_sagas.py`) establishes five operational laws for long-horizon stateful enterprise agents and benchmark evaluators:

1. **Stateful Benchmark Evaluators Exhibit Reproducible Collateral-Mutation & Partial-Credit Blind Spots (`AppWorld`, `ToolSandbox`, `WorkArena`, `TheAgentCompany`, `Probe 1`):** Pinned evaluators across all four major stateful agent benchmarks allow corrupted or incomplete multi-app trajectories to score `100%`:

   - `apple/ToolSandbox@c8571d78` multiplies `0/1` `guardrail_similarity` vetoes (excluded from the geometric-mean denominator, `evaluation.py:852–915`) only between milestone nodes and their DAG predecessors (`evaluation.py:996–1041`), leaving **all post-final-milestone mutations ($t > t^*$) invisible** unless anticipated by an explicit `Minefield`, while `-log(0)` Hungarian assignment (`evaluation.py:325, 338–341`) collapses a `19/20`-cell (`95%`) exact-match snapshot to `0.0` whenever every row assignment encounters at least one `0.0`-similarity cell (`evaluation.py:649–699`) and ignores extra unexpected columns (`L312`).

2. **Default Infinite Activity Retries Require Step-Scoped Deterministic `Idempotency-Key` + Canonical Payload Fingerprints (`Temporal`, `IETF draft-09`, `Probe 2`):** Temporal Server's default `MaximumAttempts = 0` (`retry_policy.go:76–81`) retries `StartToClose` and `Heartbeat` timeouts indefinitely (`retry_policy.go:36–44`), yet neither `temporalio/sdk-python` (`_workflow_instance.py:3595`) nor `temporalio/ai-integrations` automatically injects `(workflow_id, activity_id)` into HTTP `Idempotency-Key` headers (and `DeepAgentsPlugin` misses positional `tools`, sub-agent tools, and pre-imported `from deepagents import create_deep_agent`, `_tools.py:17–20`, `_model.py:370–372, 455, 459`). Under IETF `draft-ietf-httpapi-idempotency-key-header-09` (§2.3–§2.7), omitting keys or minting per-attempt `uuid4()` inside an Activity produces `100%` duplicate side effects (`250` extra commits across `150` faulted workflows); reusing a step key *without* server payload fingerprinting causes `100%` (`50/50`) silent stale-receipt replay on LLM parameter drift (§2.4 L233–237); only pairing a deterministic step-scoped key with SHA-256 canonical payload fingerprinting (`HTTP 422` on payload drift, `HTTP 409` with backoff on in-flight overlap, `TTL > ScheduleToCloseTimeout`) eliminates both duplicate execution and silent parameter loss.
3. **Saga Pivot-Ordering, Outbox Commit Gating, & Idempotent Compensation Retry Govern Irreversible Leakage and Dirty Aborts (`Sagas`, `Atomix`, `Janus`, `Probe 3`):** Semantic compensation $C_j, \dots, C_1$ (Garcia-Molina & Salem, SIGMOD 1987) cannot retract externalized I/O (`Atomix` Table 2 p. 7 & Appendix C.3 Table 15 p. 21: `400/500 = 80%` invalid-send leak rate for `Saga-Compensation` and `300/500 = 60%` for `Atomix-MisclassifiedIrreversible` vs. `0/500 = 0%` for commit-gated `Tx-Full`, `TCC-Confirm`, and `Mutex+WAL+Rollback`). - **Causal-Observation vs. Deferred-Commit Impossibility Boundary (`derived`):** Outbox commit gating (`Atomix` `ToGated`, `Cordon`, `Janus` `IRREVERSIBLE_GATED`) achieves `0%` invalid-send leakage **if and only if** downstream workflow steps do not causally depend on an external actor's live reply to the irreversible action. When step $T_2$ requires observing a human colleague's response to external message $T_1$ (such as RocketChat budget inquiries in `TheAgentCompany`), $T_1$ cannot be held until workflow commit; it must execute eagerly under Helland's CIDR 2007 **Tentative / Cancel / Confirm + Domain Apology** protocol.
- **Exact External-Step Position Leak Law (`Probe 3B`):** In a sequential workflow of **`m = 5` steps** comprising $m - 1 = 4$ fallible compensable/validation steps (independent failure probability **`p_f = 0.15`**) and 1 un-gated external send $E$ (failure probability **`p_e = 0.02`**) placed at 1-indexed position $k \in \{1, \dots, m\}$, exact $2^m$ truth-table enumeration and closed-form derivation give identical aborted-workflow leak probability:
  $$P_{\text{leak}}(k) = (1 - p_f)^{k - 1}(1 - p_e)\bigl(1 - (1 - p_f)^{m - k}\bigr)$$
  Evaluated across $k = 1 \dots 5$: **`k = 1: 46.84%` $\to$ `k = 2: 32.14%` $\to$ `k = 3: 19.65%` $\to$ `k = 4: 9.03%` $\to$ `k = 5: 0.00%`** (identically zero only when gated behind all fallible steps).
- **Imperfect Backward Compensation & Transient Retry Scaling (`Probe 3B`):** Consider **`K = 6` compensable steps** (each failing with **`p_f = 0.10`**) followed by a **7th pre-commit validation gate** failing with **`p_g = 0.10`**, yielding total workflow abort probability $1 - (1 - 0.10)^6(1 - 0.10) = 1 - 0.9^7 = \mathbf{52.17\%}$ (vs. $1 - 0.9^6 = 46.86\%$ without the 7th gate). If each invoked compensation handler $C_i$ fails with **independent transient** probability **`p_c = 0.08`**, exact forward-backward Markov propagation yields:
  $$P_{\text{dirty}}(p_c) = \sum_{j=1}^{K-1}(1 - p_f)^j p_f\bigl(1 - (1 - p_c)^j\bigr) + (1 - p_f)^K p_g\bigl(1 - (1 - p_c)^K\bigr)$$
  Unretried single-attempt compensation leaves **`9.54%` of all workflows (`18.29%` of aborts)** in dirty partially-compensated state, whereas wrapping each $C_i$ as an idempotent Activity with $r = 4$ independent transient attempts ($p_{c,\text{eff}} = p_c^4 = 4.096 \times 10^{-5}$) reduces transient dirty aborts by **`1,729×`** to **`0.00552%` overall (`0.01058%` of aborts)**. *(Crucial scope qualification: the $p_c^r$ exponentiation holds only for independent transient network/timeout faults; deterministic compensation bugs, non-idempotent undo handlers, or schema mismatches have correlated failure probability $\approx 1$ across retries and require dead-letter residue tagging as in `Atomix` Table 16.)*

### 6. Operational Design Rules for Stateful Enterprise Agents & Evaluators

`Basis: derived (synthesized from Sections 1–5)`

1. **Effect-Class Taxonomy, Digest-Pinned Approvals, & Pivot-Outbox Ordering:**
   - Partition every tool into five explicit effect classes: `PURE` (read-only), `REVERSIBLE_LOCAL` (copy-on-write workspace/FS snapshot, `Cordon`/`AgentRewind`), `COMPENSABLE` (paired with registered idempotent undo handler $C_i$), `IRREVERSIBLE_GATED` (external effect with no mid-workflow causal return dependency, buffered in a durable transactional outbox), or `IRREVERSIBLE_INTERACTIVE` (external message whose live reply is required mid-workflow, governed by `Tentative/Cancel/Confirm` + domain apology).
   - Enforce topological ordering `[PURE / REVERSIBLE_LOCAL / COMPENSABLE]* -> PRE_COMMIT_VALIDATION -> PIVOT (SEAL_COMMIT_AND_OUTBOX) -> [RETRIABLE_IDEMPOTENT (incl. OUTBOX_DELIVERY)]*`: when external effects are commit-gated via a durable transactional outbox (`Atomix`, `Janus` `I4`), **atomically sealing the durable commit and outbox record itself constitutes the `PIVOT`**, and subsequent outbox delivery under a stable idempotency key executes as one of the post-pivot `[RETRIABLE_IDEMPOTENT]*` steps rather than being deferred behind potentially non-terminating retriable work.
   - Bind human/policy approvals to a cryptographic digest of the **canonical proposal payload** (`sha256(tool, canonical_args)`—preventing `Janus` `PROPOSAL_CHANGED` `100 -> 1,000,000` substitution) AND verify structured fields against untrusted source documents via an independent reader/extractor before admission (`Janus` §V-D `4,000 EUR` under-declaration boundary). Never issue parallel tool calls across state-dependent resources (`ToolSandbox` `SD`).
2. **End-to-End Idempotency-Key & Payload-Fingerprint Discipline:**
   - Execute all mutating tools as Activities (verifying positional, keyword, and sub-agent tool lists at runtime rather than import-time `setattr` monkey-patching) with explicit `ScheduleToCloseTimeout` and `NonRetryableErrorTypes` covering `HTTP 400` and `HTTP 422`.
   - Derive `Idempotency-Key` deterministically outside the retry loop from `(tenant_id, workflow_id, activity_id)`—never `activity.info().attempt` or in-Activity `uuid4()`. Require resource adapters to persist `(idempotency_key, sha256(canonical_payload))` with `TTL > ScheduleToCloseTimeout`, backing off without payload mutation on `HTTP 409 Conflict` and allocating a fresh workflow-sequenced `activity_id` whenever an LLM planner revises tool arguments.
