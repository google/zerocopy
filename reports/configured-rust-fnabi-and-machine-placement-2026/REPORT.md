# Configured Rust FnAbi witnesses and observed machine placement

*Authored by an AI agent acting on joshlf's behalf.*

## Summary

A complete compiler `FnAbi` observation is a configured witness, not a portable calling convention or a physical register map. The pinned May1 compiler supplies four fixed Darwin profiles and one Windows profile whose correct candidates match independently generated fresh references. Whole-field comparisons also reject selected counterclaims about instances, attributes, hidden operands and opaque renderings. Matched IR, assembly and original objects separately show target-specific placement: Darwin's indirect result uses x8, while these Windows aggregate bodies use RCX and return that pointer in RAX; selected stack and variadic calls differ substantially.

These observations depend on the exact compiler, observer, source, target, options, runtime and consumer authority. They do not prove classification soundness, Rust validity, permission/resource transfer, ISA semantics or source-to-machine correspondence. Preserved warning stops and operational failures remain failures of their original stages; later authorized continuations do not rewrite them.

### FnAbi classifications and emitted interfaces

Basis: source + execution. C/system narrow u8/i16/bool use Zext/Sext/Zext; Rust omits the first two extensions. C/system canonicalize to C for the selected targets, while Rust remains a distinct query convention. Big is24 bytes/alignment8 and indirect. Slice is Pair; unit is Ignore. Direct tracked function has fixed_count1 and two ABI arguments; TrackFn has one. The generic u8/u64 queries have sizes1/8. VarC with promoted extras has four ABI arguments/fixed_count1/c_variadic=true; its no-extra query has one. FnAbi is not a complete register/stack allocation record.

The host C Pair uses an integer-unit cast while the Rust tuple uses Pair. Host Hfa is a consecutive four-F32 cast; Windows C Pair and Hfa instead use indirect input/result, with size/alignment16/8 and16/4 respectively. Host C/system SIMD is Direct while Rust SIMD is Indirect; no Windows SIMD result exists.

Optimization affects attributes. Shared u64 references acquire capture/NoAlias/ReadOnly/pointee-size information in host opt2 that is absent at opt0; UnsafeCell remains distinct. LLVM lowering emits alignment/extensions/InReg but conditions other attributes on optimization; `dereferenceable(8)` may replace explicit nonnull, and the optimizer adds body-derived properties. FnAbi, final IR and physical behavior are separate observations. Equal identity bodies do not equate pointer/ownership contracts. [Primary-source receipt](PRIMARY-SOURCES.json) identifies the exact upstream paths, hashes and inspected ranges; retained implementation files include `rustc_ty_utils/src/abi.rs`, `rustc_target/src/callconv/{mod,aarch64,x86_win64}.rs` and `rustc_codegen_llvm/src/abi.rs` at the compiler revision.

### Darwin bytes, stack forwarding and variadic placement

Basis: execution + derived stack arithmetic. Four actual host compiles emitted IR/assembly/MachO for ordinary/vector fixtures at opt0/opt2. [Host summary](evidence/abi-witness/stage5/host-summary.json) binds outputs; [artifact comparison](evidence/abi-witness/stage5/artifact-comparison.json) binds every instruction, raw word, range, alias and relocation. All904 text bytes/226 instructions are covered across616/252/20/16-byte text sections. Each disassembler word equals its raw object word, and emitted assembly agrees modulo spelling/whitespace, with unresolved calls matched through actual branch relocations. Ordinary opt2 contains16 bodies/four aliases for20 exported symbols; query-only roots need not emit code.

Big's C opt0 range[0x1c,0x34) saves x8 in x9, reads through x0 and stores24 bytes through the result pointer; opt2[0,0x14) stores through x8 directly. Rust/system alias it at opt2. Track opt2[0xa8,0xb4) reads the line at x1+16 and xors x0. The hidden location is concretely used through x1 here.

For the twelve-scalar driver at both optimization levels, entry SP=S; allocation48 and saved FP/LR at newSP+32 give FP=S−16. Incoming args9–12 at S+[0,8,16,24] move to outgoing newSP+[0,8,16,24]; x0–x7 remain unchanged. Actual BL words at0x15c/0x94 have external `ARM64_RELOC_BRANCH26` binding to `_abi_opaque_twelve`. After call the body adds1, restores and returns; IR `tail call` does not mean a machine tail branch. Host variadic driver opt0[0x230,0x268)/opt2[0xcc,0xfc) stores three extras at outgoingSP+[0,8,16], sets w0=1 and calls `_abi_opaque_vararg` through actual relocations. Only the declared32-bit integer value is asserted, not meaningful padding/upper bits.

Hfa opt0 explicitly handles s0–s3; opt2 is ret. Pair uses two i64 units while tuple IR splits i64/i32. Slice returns length with `mov x0,x1; ret`; unit disappears in IR. Narrow opt2 C relies on boundary extensions while Rust still masks/sign-extends its narrower operands. Experimental SIMD C/system identity is ret and cannot alone discriminate incoming vector-register assignment; Rust emits `ldr q0,[x0]; str q0,[x8]; ret`. Full per-function ranges and exact raw words remain in the bound comparison and [host oracles](evidence/abi-witness/stage5/HOST-ORACLES.md). The historical host handoffs/oracles report896 as the aggregate byte count. Independent recomputation of their listed section sizes gives904, also226 four-byte instructions; the original artifacts remain unchanged, and [ERRATA.md](ERRATA.md) records this correction.

### Windows bytes, shadow space and mixed varargs

Basis: execution + derived stack arithmetic. The single actual Windows opt2 compile emitted IR SHA256 `10c750313470ad04c2073c7c8ada22effd90763b7395f24fe30f889832c30b5c`,2883-byte COFF SHA256 `e60f2c51f131496d62fca49ce5c56ee0b28d1f36a9e490f5e9d4e4b2616b4e77` and assembly SHA256 `d2dfd499b9988433eddaafa5eb9e7b2efc06a6a54ab7e6d80061338aeb3040bb`. [Actual outputs](evidence/abi-witness/stage5/windows-codegen/subjects-opt2-01) and [COFF comparison](evidence/abi-witness/stage6/analysis/artifact-comparison.json) preserve all232 text bytes/72 instructions in16 nonempty COMDAT sections, with20 symbols via four aliases. No unexplained text or padding remains. Offsets are section-relative; identical zero addresses in different sections are distinct.

Big in one-based COFF section4[0,0x12) copies RCX to RAX, then24 bytes from RDX to that result address. C/system/Rust alias this body. Hfa section6[0,0xa) copies16 bytes through XMM0 from RDX to RCX and returns RCX in RAX. Pair section8[0,0x10) copies bytes0..12, leaving padding12..16 unwritten; IR's `initializes((0,12))` agrees with this selected body. Rust tuple section12[0,4) moves RCX to RAX and leaves EDX unchanged, consistent with its two-scalar identity IR; this identity alone does not independently discriminate every return component. Track section16[0,7) reads a32-bit line at RDX+16 and xors RCX, locating the selected hidden use in RDX.

For stack driver section15[0,0x45), entry RSP=S and return address S+[0,8); allocation104 gives F=S−104. Incoming args5–12 at S+[40,48,56,64,72,80,88,96] are loaded as four16-byte chunks and forwarded to F+[32,40,48,56,64,72,80,88]. RCX/RDX/R8/R9 pass through. Incoming shadow area is S+[8,40); outgoing shadow area F+[0,32). The frame includes8 alignment/unused bytes beyond the32 shadow+64 stack-argument bytes. Actual call at0x38 is `e800000000`, REL32 at0x39 bound to `abi_opaque_twelve`; the body increments RAX and restores104. At callee entry T=F−8, the new return address is T+[0,8), shadow area T+[8,40), arg5 T+40.

Vararg driver section19[0,0x24) receives x in ECX and y in XMM1, allocates40, moves x to EDX, sets ECX=1, duplicates y into XMM2 and R8, and zeros R9 for the null pointer. The outgoing four positions are tag ECX, i32 EDX, double XMM2/R8, pointer R9. No extra spills to a stack-argument slot in this example;32 shadow bytes plus8 alignment/unused bytes are reserved. The call at0x17 has REL32 at0x18 bound to `abi_opaque_vararg`, followed by increment/restore/return. No fifth-or-later variadic position is observed. C/Rust narrow bodies both explicitly extend CL/DX/R8B despite their different IR attributes. Ordinary FP uses XMM0/XMM1. [Windows detailed candidate](evidence/abi-witness/stage6/analysis/WINDOWS-ORACLES-CANDIDATE.md) supplies all named ranges and interpretation limits; its references to future checks describe the earlier analysis checkpoint.

Independent review rechecked the raw/public bindings and every retained object instruction/range/relocation, then repeated correct-candidate checks for ordinary Darwin opt0 and Windows opt2. Both fresh references matched their original raw packet hashes with empty ordinary diagnostics. This corroborates the same fixed subjects under the existing trust boundary; it adds no ABI soundness theorem or new target domain. The [independent review record](independent-review/README.md) preserves the initial environment stop, successful fresh runs and correction verdict.

## Boundaries

The observed foreign calls remain unresolved object relocations; no foreign implementation, final linking, SDK, fixture execution, native SIMD call or Windows runtime behavior was tested. Valid typed source does not prove every downstream caller/callee, stack, memory, alias or resource contract. No theorem connects all compiler source to the driver binary or validates the reader's ISA decoding. Exact tool hashes and source dispatch support a trusted implementation boundary, not its removal.

The selected reader is Apple LLVM21.0.0 SHA256 `83b32f39e5475ee168927eb1509c82978e08e0100ec8c6fafeca588d9960773c`, distinct from compiler LLVM22.1.4. It actually parses these MachO and COFF artifacts; help listings alone were never used to prove format support/absence. Bounded Python parsers/comparators remain untrusted. Direct runtime libraries are OS/shared-cache dependencies without a complete transitive hashed closure.

All successful observer/compile runs retain status, streams and lifecycle records. The controller's periodic scoped RSS samples and60-second observation/600-second compile stop budgets, sampled1GiB RSS and128MiB output stops are operational policies, not hard address-space isolation or unsampled peak bounds. Several short Windows mutant observations have zero RSS samples; zero is not their actual peak. No benchmark claim follows.

Historical diagnostics are not silently converted into success: initial observer compilation had E0283/E0284, and a separate postlaunch monitor denial left its wait status unknown. Authorized type disambiguation produced a distinct observer. The first v2 capture stopped on qualified-name resolution; v3 changes retained exact-name guards rather than suffix matching. Case-insensitive L/l metadata filenames overwrote one capture; diagnosis and authorized create-only recapture remain distinct. See build-01/diagnosis.json, build-02/loader-reader-diagnosis.json, capture-host-subjects-opt0-01/diagnosis.json and V3-CAPTURE-HANDOFF.md in evidence.

Vector observer O0 first produced its valid packet but the outside wrapper stopped on an unclassified five-warning bundle: repr_simd internal_features plus four improper_ctypes_definitions warnings. Parent reviewed the exact bundle SHA256 `79b0bff29ae803e776d901c83d6f577c970498f5566aab0445bec062e126c3ec` and authorized continuation, using that existing packet for the fresh check without recapture. The later vector compile O0 exited0 but its wrapper stopped on a sixth unused-simd_ffi warning, exact six-warning SHA256 `078bbcb76e817bd6800545b4015f68ca5b5d6935c00f2cc9e73a4de4b6915ba8`; only the remaining original vector O2 compile was then authorized. The pinned driver's post-codegen unused-feature reporting explains the extra warning absent from after_analysis-stop observations. Original STOP records, full streams and continuation helpers are retained. Experimental repr_simd/simd_ffi and FFI-unsafety warnings are not portable C support.

## Revalidation

First verify MANIFEST.json's per-file bytes/hashes and PROJECTION.json's distinction between public and raw identities. Inspect the fixed source/selector/authority bindings and exact relevant primary-source ranges before interpreting a new compiler or profile. Rechecking byte bindings and assembly/relocation consistency is cheaper than recompilation, but establishes only those stored artifacts' consistency. Preserved object-reader invocations and bounded reader/comparison sources identify how the original bytes were inspected.

A fresh semantic check requires a reviewed compatible host runtime and observer loader geometry, exact toolchain/target-library identities and newly owned output directories. Recover the original private observation layout or independently bind a rebuilt observer and new authority; do not weaken source-path or whole-field equality to accept the public projections. Review unchanged e33_consumer_v3.py/e33_consumer_windows.py, then use their `capture` and `check --candidate` interfaces with the fixed profile and a fresh run directory. The recorded invocations are authoritative examples; public path labels are placeholders, not runnable literal paths. The original binary hash can identify a privately retained binary, but a rebuilt binary needs its own provenance/binding review.

For machine changes, rerun only the original fixed fixture/configuration compile with `--emit=llvm-ir,asm,obj`, without linking or executing fixtures. Bind the new output hashes, exact sections/symbols/raw bytes and call relocations; account for every text instruction and padding byte, then derive offsets from entry SP, allocation, saved registers and return address. Inspect hidden result/location and mixed-variadic positions separately from FnAbi attributes. Changed compiler/target/options/source do not inherit these results merely through adjacent versions. Any new diagnostic, identity failure, reader/format failure or monitoring failure requires diagnosis as an operational stop before extending the claim.
