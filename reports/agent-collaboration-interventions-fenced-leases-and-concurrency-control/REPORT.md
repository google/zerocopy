# Multi-Agent Collaboration Interventions, Fenced Leases, Concurrency Control, and Pre-Work Intent Norms

## Summary

Primary-source synthesis of 25 peer-reviewed distributed-systems, database, and empirical software-engineering works (1968–2026), 14 pinned public GitHub repositories, and a deterministic five-probe verification suite (`support/verify_collaboration_leases_fencing_probes.py`, including ephemeral real-`git` hook and `update-ref` execution) establishes five operational invariants for coordinating concurrent coding agents and human contributors:

1. **Spatial Conflict Avoidance Without Shared Contracts Does Not Improve Semantic Integration:** Across `652` multi-agent coding tasks in `12` repositories (`CooperBench`, `arXiv:2601.13295v2`), free-form peer chat cuts raw textual `git merge` conflicts (`29.4%` vs. `51.5%` when an explicit first-turn `Plan` names files and line ranges; `+6.54 pp` `Naive` clean merge rate on `GPT-5` and `+4.45 pp` on `Claude 4.5 Sonnet`) yet produces **zero or slightly negative net gain** in end-to-end task pass rate (`GPT-5`: `27.91% → 27.90%`; `Claude 4.5 Sonnet`: `27.30% → 25.92%`, trailing a single `Solo` agent at `48%` and `47%`). Across the `1,694` historical merges with executable build and test suites in `Git`, `Perl5`, and `Voldemort` (`Brun et al.`, ESEC/FSE 2011 Fig. 4, correcting §4.2's `"5,355"` prose typo), **`33.33%` (`133/399`, Wilson 95% CI `[28.89%, 38.10%]`) of real integration failures pass `git merge` cleanly** (`9.31%` = `133/1,428` of all Git-clean merges fail build or tests). Under agent-speed execution (`NP-Bench`, `arXiv:2610.07261v1`), reactive conflict warnings (`C1-DETECT`) raise clean integration (`CTSR`) only from `1/9` (`C0`, `13` conflicts, `54` wasted LOC) to `4/9` (`12` conflicts, `49` wasted LOC) and still score `0.0` on live breaking-contract migrations, whereas upfront **scope partitioning + producer-to-consumer merge ordering** (`C1-PLAN`; `Co-Coder`, `arXiv:2606.00953v1`) reaches `9/9` `CTSR`, `0` conflicts, and `1.00` frontier migration success.
2. **Lease Duration Obeys Distinct Demand-Driven vs. Proactive-Keepalive Optima, and Write Safety Requires Lock-Held Sink Fencing:** Under `Gray & Cheriton` (SOSP 1989, Eq. 1–2), a server grant $t_S$ yields client validity $t_C = \max(0, t_S - \Delta)$ ($\Delta = m_{\text{prop}} + 2 m_{\text{proc}} + \epsilon$); choosing $0 < t_S \le \Delta$ creates a **sub-skew penalty cliff** ($t_C = 0$, `+22.57%` server load at $S = 10$). Balancing renewal messages against crash-stall cost separates two renewal physics (`[derived]`): **(a) demand-driven non-heartbeated cache leases** incur conditional stall $\frac{1}{2} t_S$ weighted by active duty factor $\pi_{\text{on}}(t_S) = \min(1, \frac{R t_S}{1 + R t_C})$, giving high-duty closed form $t_S^{\text{hd}*} = \Delta - \frac{1}{R} + \frac{2}{\sqrt{\lambda_{\text{fail}} c_{\text{stall}}}} = 12.3605\text{ s}$ (`12.4015 s` exact-duty at $\pi_{\text{on}} = 0.9213$ on V) and collapsing to `0.0 s` on un-heartbeated high-abandonment issue claims; **(b) proactively heartbeated task/lock leases** renewed every $\tau_{\text{hb}} = \eta(t_S - \Delta)$ reset expiry on each touch, leaving larger expected crash stall $(1 - \frac{\eta}{2}) t_S + \frac{\eta}{2}\Delta$ (`32.0 s` = $\frac{5}{6} t_S + \frac{1}{6}\Delta$ under ZooKeeper $\eta = 1/3$, **not** $\frac{1}{2} t_S$) with exact optimum $t_S^{\text{hb}*} = \Delta + \sqrt{\frac{2}{\eta(1 - \eta/2)\lambda_{\text{fail}} c_{\text{stall}}}} = 38.0\text{ s}$ ($\tau_{\text{hb}}^* = 12.0\text{ s}$). Because pauses and **orphan child subagents** bypass TTLs (`3/10` parent-only and `23/30` full-matrix split-brain corruptions under client clock recheck; `10/30` when only the parent checks tokens), every mutating sink must enforce monotonic fencing tokens (`Chubby` sequencer, `ZooKeeper` `zxid`, `etcd` `CreateRevision`, `Consul` `LockIndex`). In real Git (`[real git execution]`), bare `--force-with-lease` fails after background `git fetch`, explicit `--force-with-lease=<ref>:<C0>` fails after ABA rollbacks to `<C0>`, and **`hooks/pre-receive` suffers a live TOCTOU split-brain race** against concurrent `git update-ref --stdin` lease advancement because `pre-receive` runs *before* `receive-pack` locks `refs/heads/<branch>.lock`; closing the race requires checking `refs/leases/<task>` inside **`hooks/reference-transaction` at `prepared`** while `refs/heads/<branch>.lock` is held.
3. **Finite Compute Capacity Inverts `OCC` vs. Pessimistic Locking, Until Un-Heartbeated "Cookie-Licking" Inverts It Back:** Under infinite compute slots ($K = \infty$), optimistic concurrency control (`OCC`, `Kung & Robinson` 1981; `Franaszek & Robinson` 1985 fixed point $\Lambda_{\infty} = N(1 - p_c)^{\Lambda_{\infty}}$) scales as $\Theta(\ln N)$ and beats two-phase locking (`12.872` vs. `5.736` commits/unit-time at $N = 36, G = 40$ in `Probe P3`). Under **finite compute/token slots** ($K = 8$, `Agrawal, Carey & Livny` TODS 1987), **the ranking inverts**: `OCC` slices $K$ across all $N$ workers and burns full executions before commit-time abort (`2.816` throughput, `35.20%` useful compute fraction), whereas `Blocking 2PL` reaches **`4.976` (`1.77×`, `93.12%` useful compute fraction)** because waiting consumes zero compute. However, under open-stream silent abandonment ($p_{\text{abandon}} = 0.25$) with long un-heartbeated claim TTLs ($\text{TTL} = 60.0$ at fixed $N = 16, G = 24, K = 8$), orphan locks starve `Blocking 2PL` down to **`0.288` vs. `OCC = 2.624` (`9.11×` collapse)**, while shortening fenced leases to $\text{TTL} = 1.0$ at the identical parameters restores **`Blocking 2PL = 4.176 > OCC = 2.624`**. Furthermore, pure liveness heartbeats fail against looping agents ("active cookie-licking"), requiring renewals beyond $k_{\max}$ intervals to carry monotone **progress witnesses** (`Probe P1`).
4. **Sequential Unawareness Dominates Open-Source Duplicate Work, While Heavy Upfront Gatekeeping Drives Hard Forks:** Across the `1,751` multi-PR duplicate groups (`3,619` unique duplicate PRs / `2,032` $\binom{k}{2}$ pairs in `whystar/MSR2018-DupPR@62782219`, derived by filtering `330` intentional cross-branch/submodule duplicates from `Yu et al.` MSR 2018's `2,323` pairs; `Li et al.` IEEE TSE 2022), **`95.15%` (`1,924/2,022`) are sequentially `Exclusive`**—the second contributor started local commits a median of `212.59 h` (`8.86 d`) *after* the first PR was already submitted—and maintainers discard one PR in **`94.33%` (`1,082/1,147`)** of resolved pairs (`Accept Both` = `3.14%`, `Reject Both` = `2.53%`). Across `1,131` GitHub projects (`Zhou, Vasilescu & Kästner`, ESEC/FSE 2019), voluntary issue pre-communication explains only `3%` of duplicate-PR deviance ($R^2 = 4\%$) and centralized upfront management increases community hard forks (`12%` deviance, $p < 0.01$), whereas **architectural modularity** raises external PR merge rates (`6%` deviance, $R^2 = 27\%, p < 0.001$) without inducing hard forks.
5. **Six Post-Detection Interventions Partition Sunk-Progress and Ambiguity Space (`[toy model / parametric decision model]`):** Separating goal redundancy $\omega \in [0, 1]$ from structural file coupling $\kappa \in [0, 1]$, directional dependency $\delta \in [0, 1]$, pre-code ambiguity, and `Knight & Leveson` (1986) correlated fault escape $p_{\text{diff}} = p^2 + \rho p(1 - p)$ maps distinct regimes to **M1 Yield/Abort** (early duplicate $\omega \approx 1$), **M2 State Merge** (low coupling $\kappa \ll 1$, exact `2.00` work baseline at zero overlap), **M3 Scope Split** (early coupled decomposable $\omega = 0, \kappa \gg 0$), **M4 Producer/Consumer Handoff** (directional contract migration $\delta \gg 0$), **M5 Cross-Review / Differential Testing** (late high-stakes duplicate $s_1, s_2 \ge 0.85, V_{\text{bug}} \gg 1, \rho < 1$), and **M6 Shared Living Spec** (pre-code high semantic ambiguity $s_1 = s_2 = 0$).

## Findings

### 1. Six-Mode Collaboration Intervention Taxonomy and Agentic Merge Conflict Evidence

`Basis: source + documentation + derived + execution`

When a coordinator or peer protocol detects that two workers $W_1, W_2$ at sunk progress $(s_1, s_2) \in [0, 1]^2$ overlap in goal redundancy $\omega \in [0, 1]$ or structural file coupling $\kappa \in [0, 1]$, six interventions span the operational design space:

| Mode | Operational Mechanism | Primary Theoretical & Empirical Anchors | Dominant Regime | Primary Failure Mode if Misapplied |
| :--- | :--- | :--- | :--- | :--- |
| **M1. Yield / Abort** | Lower-progress or younger-timestamp worker halts immediately; surviving worker finishes alone. | `Rosenkrantz, Stearns & Lewis` (TODS 1978) `Wait-Die` / `Wound-Wait`; `Li et al.` (TSE 2022): `94.33%` (`1,082/1,147`) OSS duplicate PRs end in `Accept One`. | True goal duplication ($\omega \approx 1$), asymmetric or early sunk progress ($\min(s_1, s_2) \ll 1$), high coupling $\kappa$. | Drops required distinct scope when $\omega < 1$; forfeits $\min(s_1, s_2)$ if triggered post-hoc. |
| **M2. State Merge / Patch Integration** | Both workers complete on isolated branches/worktrees and integrate via 3-way merge + build/test gate. | `Brun et al.` (ESEC/FSE 2011); `AgenticFlict` (AIware 2026, `27.67%` conflict); `Xu et al.` (2026, `41.74%` cross-agent vs. `19.80%` intra-agent). | Distinct compatible features ($\omega = 0$), low coupling ($\kappa \ll 1$), zero directional breakage ($\delta \approx 0$). | **`33.33%` of true conflicts pass `git merge` cleanly** (`Brun` 2011); **`29.7%` divergent architecture** (`CooperBench`). |
| **M3. Scope Split / Interface Partitioning** | Isolate high-degree hub files and partition peripheral cohesive clusters across disjoint module seams. | `Parnas` (CACM 1972); `Conway` (1968); `Zhou et al.` (ESEC/FSE 2019); `Co-Coder` (`arXiv:2606.00953v1`); `CAID` (`arXiv:2603.21489v2`). | Early detection ($s_1, s_2 \approx 0$), distinct decomposable goals ($\omega = 0, \kappa \gg 0, \delta \ll 1$). | Breaks when edits crosscut an indivisible hub without an interface seam or when directional API migration ($\delta \to 1$) is unsequenced. |
| **M4. Producer / Consumer Handoff** | Factor shared contract/substrate to Producer $W_1$; Consumer $W_2$ codes against stub or rebases atop $W_1$'s commit. | `Parnas` (1972); `NP-Bench` (`arXiv:2610.07261v1`, `0.0 → 1.00` live migration); `Li et al.` (TSE 2022) `3.14%` (`36/1,147`) `Accept Both`. | High directional contract asymmetry ($\delta \to 1$), e.g., breaking signature or schema migration. | Serializes critical path if Producer stalls before publishing a minimal stub; broken commitment (`3.7%` in `CooperBench`) breaks Consumer. |
| **M5. Cross-Review / Differential Oracle** | Complete both independent versions; run zero-oracle differential tests $P_1(x) == P_2(x)$ and cross-inspection. | `Knight & Leveson` (IEEE TSE 1986); `McKeeman` (DTJ 1998); `Fagan` (IBM SJ 1976). | Late accidental duplication ($s_1, s_2 \ge 0.85, \omega \approx 1$), high bug-escape loss $V_{\text{bug}}$, $\rho < 1$. | Burns `~2×` compute on low-stakes tasks; **cannot assume $p^2$ independence** due to shared spec blind spots ($\rho > 0$). |
| **M6. Shared Scratch / Living Spec Co-Editing** | Converge on a versioned specification (types, signatures, invariants) committed before isolated coding starts. | `CooperBench` (`arXiv:2601.13295v2` §5–§6); `CAID` (`arXiv:2603.21489v2` §2.3); `PEP 1` / `Rust RFC` / `Blink Intent`. | Pre-implementation ($s_1 = s_2 = 0$), high architectural ambiguity (`42%` Expectation + `32%` Commitment gaps). | Heavy synchronous overhead if imposed on routine low-ambiguity bug fixes (`Zhou et al.` 2019 hard-fork effect). |

#### 1.1 Timestamp Preemption (`M1`) vs. Post-Hoc State Merge (`M2`)

1. **Deadlock-Free Timestamp Priority (`Rosenkrantz, Stearns & Lewis`, ACM TODS 3(2):178–198, 1978, `doi:10.1145/320251.320260`):** Ordering workers by start timestamp $\mathrm{TS}(W_i)$ prevents wait cycles via non-preemptive `Wait-Die` (older waits, younger aborts) or preemptive `Wound-Wait` (older preempts younger, younger waits). `Wound-Wait` induces fewer restarts because a wounded younger worker that restarts waits rather than repeatedly colliding with the same older holder. In human OSS pull requests (`Li et al.`, IEEE TSE 48(4):1309–1335, 2022, Tables 12 & 15), **`94.33%` (`1,082/1,147`, Wilson 95% CI `[92.84%, 95.53%]`)** of resolved duplicate pairs end in post-hoc `Accept One`, led by `"First-come, First-served"` (`30` coded rationales vs. `20` `"Higher quality"` and `11` `"Correctness"`), forfeiting `100%` of the discarded patch (`mean 502.68 LOC` across `13.79 files`).
2. **Higher-Order Build/Test Failures Behind Clean Textual Merges (`Brun, Holmes, Ernst & Notkin`, ESEC/FSE 2011, pp. 168–178, `doi:10.1145/2025113.2025139`; IEEE TSE 39(10):1358–1375, 2013; `Probe P5`):**
   - Summing every row of `Brun et al.` Figure 4 (p. 171) across all `9` open-source systems yields **`3,562` historical merges** with **`564` textual conflicts (`15.83%`, unweighted project mean `17.0%`)**.
   - Summing the `3` systems with executable build and test suites (`Git = 1,362`, `Perl5 = 185`, `Voldemort = 147`) proves the exact denominator is **`1,694` merges** (correcting an editorial typo `"5,355"` in §4.2 prose, where `266 / 5,355` would be `4.97%` rather than `16%`): **`266` `TEXTUAL⚡` (`15.70%`)**, **`24` `BUILD⚡` (`1.42%`)**, **`109` `TEST⚡` (`6.43%`)**, and **`1,295` `TEST✓` (`76.45%`)**.
   - Out of `399` total conflicts (`266 + 24 + 109`), **`133/399 = 33.33%` (Wilson 95% CI `[28.89%, 38.10%]`) pass `git merge` cleanly** and fail only during compilation or test execution—a **`9.31%` (`133/1,428`, Wilson 95% CI `[7.91%, 10.93%]`) conditional failure rate** among merges reported clean by Git. Moreover, `93%` of conflict pairs evolved from an earlier clean `TEST✓` state as parallel branches drifted (`RQ3`).
3. **Empirical Merge Conflict Rates in Autonomous Coding Agents (`AgenticFlict` & `Xu et al.` 2026; `Probe P5`):**
   - **`Ogenrwot & Businge` (*AgenticFlict*, ACM AIware 2026, pp. 323–331, `doi:10.1145/3805760.3814923`, `arXiv:2604.03551v2`):** Across `142,652` AI-authored PRs from `59,412` repositories (`107,026` merge-simulated), **`29,609` (`27.67%`) produce textual merge conflicts** (`336,380` conflict regions; mean `4.36` / median `2.00` files, `11.36` regions, and `540.42` conflicting lines per conflicting PR), rising from `~9.9%` at `2`-line churn to `32%–33%` at `46–185` lines. Reconciling `Table 1` (`29,609` conflicting + `75,924` clean = `105,533`) against `Table 2` (`N = 107,026`) isolates `1,493` (`1.40%`) non-clean/non-conflict exit statuses and confirms `Table 2` uses Wald normal intervals: **GitHub Copilot `15.24%` (`2,583/16,954`, Wilson `[14.71%, 15.79%]`)**, **Cursor `19.75%` (`1,421/7,196`, `[18.84%, 20.68%]`)**, **Devin `22.85%` (`1,883/8,241`, `[21.96%, 23.77%]`)**, **Claude Code `25.93%` (`202/779`, Wald `[22.85%, 29.01%]`, exact Wilson `[22.98%, 29.12%]`; §4 prose `26.86%`)**, and **OpenAI Codex `31.85%` (`23,520/73,856`, `[31.51%, 32.18%]`)**.
   - **`Xu, Subramanian & Karthik` (`arXiv:2607.04697v2`, July 2026):** Across `33,596` agent PRs in `2,807` `AIDev-pop` repositories, **`79.4%` (`26,691` PRs in `40.2%` of repos)** overlap on the exact same day (`k = 0`), reaching **`95.0%` (`31,916` PRs in `53.4%` of repos)** within `±7` days. Across `716` evaluable co-active pairs (`git merge-tree --write-tree`), **cross-agent pairs (two distinct agent tools) conflict at `41.74%` (`48/115`, Wilson 95% CI `[33.14%, 50.88%]`) vs. `19.80%` (`119/601`, `[16.81%, 23.17%]`) for intra-agent pairs**—strictly disjoint by **`+9.97 pp`**. Of `1,646` conflicted files, **`84.4%` are source code** (only `3.9%` manifests/lockfiles), and **`41.9%` are structural** (`26.8%` `modify/delete` + `15.1%` `add/add` vs. `57.6%` `content`).

#### 1.2 Hub-Isolated Scope Split (`M3`), Topological Handoff (`M4`), Differential Oracles (`M5`), and Living Specs (`M6`)

1. **Cohesion Partitioning & Hub Isolation (`Parnas` 1972; `Conway` 1968; `Co-Coder` `arXiv:2606.00953v1`, `Flitternie/CoCoder@64fddee2`; `CAID` `arXiv:2603.21489v2`):** Encapsulating design secrets behind narrow interfaces (`Parnas`, CACM 15(12):1053–1058, 1972) satisfies `Conway`'s homomorphism constraint without continuous peer chat. `Co-Coder` (`code_team/cohesionbase/partition/{clustering.py,w_rib_cosine.py,post_processing.py}`) statically extracts the repository dependency graph, isolates high-degree hub files (analogous to `Geng & Neubig`'s `CAID` §2.3 committing preparatory changes to `main` and marking package `__init__.py` hubs restricted before branching), clusters peripheral modules, and improves pass rate by up to **`+14.0%`** with **`2.10×` speedup** and **`35%` lower API cost** across `28` `DevEval` and `CodeProjectEval` tasks.
2. **Why Upfront Producer→Consumer Planning Beats Reactive Warnings (`Muku`, *NP-Bench*, `arXiv:2610.07261v1` Table 2; `Probe P5`):** Under agent-speed generation, reactive overlap alerts arrive after conflicting tokens are already emitted: `C1-DETECT` lifts deterministic clean integration (`CTSR`) from `1/9` (`C0`, `13` conflicts, `54` wasted LOC) to **`4/9`** (`12` conflicts, `49` wasted LOC) and achieves **`0.0`** on live breaking-contract migrations, whereas `C1-PLAN` (disjoint file scope + Producer→Consumer merge sequencing) achieves **`9/9` `CTSR`, `0` conflicts, `0` wasted LOC, `0/5` scope violations, and `1.00` live migration success on frontier models (`0.60` on small models)**.
3. **Differential Testing & Correlated Blind Spots (`McKeeman` 1998; `Fagan` 1976; `Knight & Leveson` IEEE TSE SE-12(1):96–109, 1986):** When high-stakes duplication is discovered late ($s_1, s_2 \ge 0.85$), running generated inputs through $P_1(x) == P_2(x)$ (`McKeeman`, DTJ 10(1):100–107) and adversarial cross-inspection (`Fagan`, IBM SJ 15(3):182–211) avoids manual oracle authoring. However, `Knight & Leveson`'s `27`-version × `1,000,000`-input experiment rejected independent failure ($p < 0.01$): joint escape follows $p_{\text{diff}} = p^2 + \rho p(1 - p)$ ($\rho \in (0, 1]$), reducing to single-version $p$ as $\rho \to 1$.
4. **Why Unstructured Chat Fails (`CooperBench` `arXiv:2601.13295v2` Tables 1, 2, 6; `cooperbench/CooperBench@63b9d44d`):** Across failed cooperative traces, `Work overlap` (`33.2%`) and `Divergent architecture` (`29.7%`, incompatible designs passing clean `git merge`) represent `62.9%` of symptoms, driven by `Expectation` failures (`42%`, ignoring a partner's stated plan), `Commitment` failures (`32%`, promising an edit that is absent from the final diff), and `Communication` breakdowns (`26%`). **Mode 6** replaces chat promises with a checkable base-branch specification committed before branching.
5. **Unit-Consistent Parametric Selector (`Probe P4`, `[toy model / parametric decision model]`):** Measuring all six modes on a single **total expected remaining agent-work + defect-loss** scale (charging positive unsequenced contract-breakage rework $1.65 \delta (1 - \omega)(1 - \min(s_1, s_2))$ to modes that do not sequence Producer→Consumer rather than subtracting negative work) confirms: (i) on two disjoint zero-ambiguity features from scratch ($s_1 = s_2 = \omega = \kappa = \delta = \text{sem\_ambig} = V_{\text{bug}} = 0$), `M2_State_Merge` wins at the exact `2.00` two-feature work floor (all other modes $\ge 2.35$); (ii) all six canonical archetypes map to distinct winners (`M1 = 0.65`, `M2 = 1.1583`, `M3 = 2.9613`, `M4 = 2.8375`, `M5 = 2.62`, `M6 = 4.319`); and (iii) setting $\rho \to 1.0$ flips `M5 → M1` (`4.70 > 4.10`), setting $\delta \to 0.0$ flips `M4 → M3` (`3.4788 > 2.7406`), and flipping $\omega: 1.0 \to 0.0$ at fixed $\kappa = 0.80$ separates `M1` from `M3`.

### 2. Lease-Term Physics, Monotonic Fencing Tokens, and Git `reference-transaction` Safety

#### 2.1 Exact `Gray & Cheriton (1989)` Cache Leases vs. Demand and Proactive-Keepalive Crash-Stall Optima

1. **Exact V-System Equations & Sub-Skew Cliff (`Gray & Cheriton`, SOSP 1989, pp. 204–205, `doi:10.1145/74850.74870`; `Probe P1` Part 1A):** With read rate $R$, write rate $W$, sharing degree $S$, transit $m_{\text{prop}} + 2 m_{\text{proc}}$, and clock skew $\epsilon$, effective client lease validity is $t_C = \max(0, t_S - \Delta)$ where $\Delta = m_{\text{prop}} + 2 m_{\text{proc}} + \epsilon$. Consistency message load and average per-operation delay are:
   $$L(t_C) = \frac{2 N R}{1 + R t_C} + N S W, \qquad \bar{d}(t_C) = \frac{1}{R + W}\!\left(\frac{2 R (m_{\text{prop}} + 2 m_{\text{proc}})}{1 + R t_C} + W t_a\right)$$
   with multicast write-approval latency $t_a = 2 m_{\text{prop}} + (S + 2) m_{\text{proc}}$ and benefit factor $\alpha_{\text{mcast}} = \frac{2R}{SW}$ (unicast $\alpha_{\text{unicast}} = \frac{R}{(S - 1)W}$, fn. 7). Leasing beats $t_S = 0$ iff $\alpha > 1$ and $t_S > \Delta + \frac{1}{R(\alpha - 1)}$. At V-system Table 2 parameters ($R = 0.864\text{ s}^{-1}, W = 0.039\text{ s}^{-1}, m_{\text{prop}} = 1.0\text{ ms}, m_{\text{proc}} = 0.25\text{ ms}, \epsilon = 100\text{ ms} \implies \Delta = 0.1015\text{ s}$, consistency = `30%` of zero-lease traffic):
   - **Sub-skew cliff:** $t_S = 0.050\text{ s} \le \Delta \implies t_C = 0$, inflating consistency load at $S = 10$ to **`1.2257×` (`+22.57%`)** above $t_S = 0$.
   - **$S = 1, t_S = 10\text{ s}$:** relative consistency load drops to **`10.47%`**, cutting total server traffic by **`26.86%`** (`4.49%` above $t_S = \infty$), with Eq. (2) mean consistency delay **`0.3005 ms`**.
   - **$S = 10, t_S = 10\text{ s}$:** $\alpha_{\text{mcast}} = 4.4308$ ($t_S^{\text{be}} = 0.4389\text{ s}$), unicast $\alpha_{\text{unicast}} = 2.4615$ (**$t_S^{\text{be}} = 0.8934\text{ s}$**), cutting total traffic by **`20.09%`** (`4.09%` above $t_S = \infty$; delay `0.5164 ms`).
   - **$S = 40$:** $\alpha_{\text{mcast}} = 1.1077$ pushes multicast break-even to **`10.8489 s`** (`rel_load = 1.0075 > 1` at `10 s`), while unicast $\alpha_{\text{unicast}} = 0.5680 < 1$ never breaks even at any finite or infinite lease duration.
2. **Demand-Driven vs. Proactive-Keepalive Crash-Stall Physics (`[derived]`, `Probe P1` Part 1B):** `Gray & Cheriton` treat crash recovery qualitatively as bounded $\le t_S$ wait under rare failures. Quantitative optimization under failure rate $\lambda_{\text{fail}}$ ($\text{s}^{-1}$, $\lambda_{\text{fail}} t_S \ll 1$) and stall penalty $c_{\text{stall}}$ ($\text{message-equivalents}\cdot\text{s}^{-1}$) depends critically on whether renewals are **demand-driven** or **proactively heartbeated**:
   - **Demand-driven non-heartbeated cache leases:** Renewed only on the next $\mathrm{Poisson}(R)$ read *after* local expiry $t_C$, so the server grant is active for duty fraction $\pi_{\text{on}}(t_S) = \min\!\bigl(1, \frac{R t_S}{1 + R\max(0, t_S - \Delta)}\bigr)$ with conditional residual stall $\frac{1}{2} t_S$:
     $$J_{\text{demand}}(t_S) = \frac{2R}{1 + R\max(0, t_S - \Delta)} + \frac{1}{2}\lambda_{\text{fail}} c_{\text{stall}} \pi_{\text{on}}(t_S)\, t_S \xrightarrow{R t_S \gg 1} t_S^{\text{hd}*} = \Delta - \frac{1}{R} + \frac{2}{\sqrt{\lambda_{\text{fail}} c_{\text{stall}}}}.$$
     On V file caching ($\lambda_{\text{fail}} = 1/3600\text{ s}^{-1}, c_{\text{stall}} = 80$), $t_S^{\text{hd}*} = \mathbf{12.3605\text{ s}}$ (`12.4015 s` exact-duty grid optimum at $\pi_{\text{on}} = \mathbf{0.9213}$). On an un-heartbeated high-abandonment issue claim ($R = 1/600\text{ s}^{-1}, \lambda_{\text{fail}} = 1/900\text{ s}^{-1}, c_{\text{stall}} = 25$), the stationary point is negative (`-588.0 s`), collapsing the optimal blocking grant to **`0.0 s`**.
   - **Proactively heartbeated task/lock leases (`ZooKeeper` / `Chubby` / `etcd`):** Renewing every $\tau_{\text{hb}} = \eta(t_S - \Delta)$ ($\eta \in (0, 1)$, e.g., ZooKeeper $\eta = 1/3$ in `Hunt et al.` 2010 §4.4) resets server expiry to $t_S$ on every touch. A crash uniform over $[0, \tau_{\text{hb}})$ occurs $\frac{1}{2}\tau_{\text{hb}}$ after the last renewal, leaving **expected residual server stall $(1 - \frac{\eta}{2}) t_S + \frac{\eta}{2}\Delta$** ($\frac{5}{6} t_S + \frac{1}{6}\Delta$ at $\eta = 1/3$—`1.67×` larger than $\frac{1}{2} t_S$!) and objective:
     $$J_{\text{hb}}(t_S) = \frac{2}{\eta(t_S - \Delta)} + \lambda_{\text{fail}} c_{\text{stall}}\!\left(\Bigl(1 - \frac{\eta}{2}\Bigr)t_S + \frac{\eta}{2}\Delta\right) \implies t_S^{\text{hb}*} = \Delta + \sqrt{\frac{2}{\eta\bigl(1 - \frac{\eta}{2}\bigr)\lambda_{\text{fail}} c_{\text{stall}}}}.$$
     At active agent lease parameters ($\eta = 1/3, \Delta = 2.0\text{ s}, \lambda_{\text{fail}} = 1/1800\text{ s}^{-1}, c_{\text{stall}} = 10$), **$t_S^{\text{hb}*} = 38.000\text{ s}$**, $\tau_{\text{hb}}^* = \mathbf{12.000\text{ s}}$, and $\mathbb{E}[\text{stall}] = \mathbf{32.000\text{ s}}$. Conversely, if $\tau_{\text{hb}}$ is *fixed* (e.g., `5.0 s` independent of $t_S$), renewal load $2/\tau_{\text{hb}} = 0.40\text{ msg/s}$ is constant, so total cost increases strictly with $t_S$ and selects the smallest jitter-safe multiple $\Delta + k_{\text{miss}}\tau_{\text{hb}}$ (`17.0 s` at $k_{\text{miss}} = 3$).
3. **Progress-Witness Renewals Against Active Cookie-Licking (`Probe P1` Part 1C, `[toy discrete simulation]`):** Pure OS/RPC heartbeats allow an agent stuck in a zero-progress or 2-cycle `A <-> B` edit oscillation loop to hold a lease indefinitely (`completed = False`, `280 s` wasted). Requiring renewals after $k_{\max} = 3$ intervals (`30 s`) to attach a monotone progress witness `(passing_tests, -compiler_errors)` or a previously unseen Git tree hash evicts zero-progress loops at `50 s` (`W2` completes at **`90 s`**, stale token-1 write blocked at `70 s`) and `A <-> B` oscillations at `70 s` (`W2` completes at **`110 s`**, stale token-1 write blocked at `90 s`, `zombie_writes_blocked = 1` in both), with **`0` false evictions** on legitimate `20–25 s` compile/proof turns (`completed_at_s = 80 s`).

#### 2.2 Monotonic Fencing Tokens, Orphan Subagents, and Live Git `pre-receive` vs. `reference-transaction` Races

1. **Why Timeouts and Client Clock Rechecks Fail (`Kleppmann` 2016 / *DDIA* 2017 pp. 301–306; `Probe P2` Part 2A):** Sweeping `30` schedules ($\tau \in \{2, 6, 11, 18, 75\}\text{ s} \times \{\text{before\_check}, \text{after\_check}\} \times \{\text{no\_child}, \text{ambient\_cred\_child}, \text{token\_scoped\_child}\}$ at $T_{\text{lease}} = 10\text{ s}, D_{\text{lock\_delay}} = 60\text{ s}$):

   - **HashiCorp Consul (`hashicorp/consul@9225feae6d51cb92b812926f811b6064653c1e3f`) vs. Redis (`redis/redis@fd7710ca2bf6ff025aedb3cf1d5da146854a6db2`):** Consul `agent/consul/state/kvs.go:405-407, 459, 514-515, 528-546` increments `entry.LockIndex = e.LockIndex + 1` on acquisition, **preserves `LockIndex` across unlock** (`L514–515`), and enforces `kvsCheckSessionTxn`, whereas Redis `src/t_string.c:61-115` (`OBJ_SET_NX`, `OBJ_PX`, `setGenericCommand`) provides single-node TTL efficiency locking without monotonic fencing tokens.
3. **Git Ref-Level CAS Footguns and the `pre-receive` TOCTOU Race (`[real git execution]`, `Probe P2` Part 2B):**
   Running real `git` against an ephemeral bare repository (deterministic OIDs `C0 = 6867feff4ea6`, `C1_w1 = 5aba5d8f6c0c`, `C1_orphan = 448c00ccbfa3`, `C2 = d5dae011d592`, `C3 = 1f99bbc43ccc`) proves five concrete VCS properties:
   - **`G1` & `G2a`:** Unfenced `git push --force` by an orphan child silently overwrites `C2` (`rc = 0`), while explicit `git push --force-with-lease=refs/heads/task:<C0>` rejects stale writes after a linear `C0 → C2` advance (`rc != 0`).
   - **`G2b` (Two `--force-with-lease` failure windows without monotonic tokens):** **(i)** Running `git fetch origin` inside a shared or inherited checkout refreshes `refs/remotes/origin/task` to `C2`, causing bare `git push --force-with-lease` to **succeed (`rc = 0`) and clobber `C2`**; **(ii)** if holder `3` intentionally rolls `refs/heads/task` back to `C0` (**ABA hazard**), stale holder `1`'s explicit `--force-with-lease=refs/heads/task:<C0>` matches `C0` (`rc = 0`) and resurrects dead branch `C1_w1`.
   - **Atomic `git update-ref --stdin` single-ref rule:** `update <ref> <new> <old>` performs CAS on mutated refs while `verify <ref> <old>` checks unmutated refs (combining `verify` and `update` on the *same* ref in one transaction aborts with `multiple updates for ref ... not allowed`); a failed `verify refs/leases/task` aborts the entire transaction cleanly without mutating `refs/heads/task`.
   - **`G3a` (Live `hooks/pre-receive` TOCTOU split-brain race):** In `git-receive-pack`, **`hooks/pre-receive` runs *before* `receive-pack` creates `refs/heads/task.lock`**. When `W1` (`Fencing-Token: 1`) pushes `--force-with-lease=refs/heads/task:<C0>`, `pre-receive` reads `refs/leases/task == 1` (`1 >= 1`); before `pre-receive` exits, a concurrent Coordinator `git update-ref --stdin` (`update refs/leases/task <t3> <t1>` + `verify refs/heads/task <C0>`) **commits (`coord_rc = 0`)** because `task.lock` is not yet held; `receive-pack` then locks `task.lock`, sees `HEAD == C0`, and **overwrites `refs/heads/task` with stale `C1_w1` (`w1_rc = 0`) under active lease token `3`**.
   - **`G3b` (Lock-safe `hooks/reference-transaction` at `prepared` + trust boundary):** Enforcing monotonic `refs/leases/task` comparison inside `hooks/reference-transaction` when `sys.argv[1] == "prepared"` runs **while `receive-pack` already holds `refs/heads/task.lock`**. Under Interleaving 1 (push enters `prepared` first), a concurrent Coordinator `git update-ref --stdin` (`verify refs/heads/task <C0>`) fails closed (`coord_rc = 128`, `cannot lock ref 'refs/heads/task': ... File exists`); under Interleaving 2 (Coordinator atomically advances `refs/leases/task: 1 → 3` and rolls `HEAD` back to `C0`), `reference-transaction` (`prepared`) rejects both `W1`'s ABA push and `W1_orphan`'s post-`fetch` push (`FENCE_REJECT`) while accepting `W3` (`Fencing-Token: 3`, `HEAD == C3`). **Trust boundary:** reading `Fencing-Token:` from plain commit trailers assumes cooperative/non-Byzantine worker processes; adversarial writers require server-authenticated per-token push credentials or signed capability certificates.

### 3. Resource-Bounded Concurrency Inversion and Open-Stream Cookie-Licking

`Basis: source + derived + execution`

1. **Optimistic Validation & Processor-Shared Scaling (`Kung & Robinson`, ACM TODS 6(2):213–226, 1981; `Franaszek & Robinson`, ACM TODS 10(1):1–28, 1985; `Tay, Goodman & Suri`, ACM TODS 10(4):415–462, 1985; `Probe P3` Part 3A):** `Kung & Robinson` buffer writes locally during `Read`, assign transaction number `tnc` after `Read` (§3.2), validate serial equivalence (§3.1 conditions 1–3), and cure repeated restarts via exclusive lock fallback (§5). Under `Franaszek & Robinson`'s small independent pairwise commit-conflict probability $p_c$ and zero rollback delay, infinite-slot throughput satisfies $\Lambda_{\infty}(N) = N(1 - p_c)^{\Lambda_{\infty}(N)} \sim \Theta(\ln N)$. Under processor sharing across $K$ finite compute slots ($s = \min(1, K/N), t_{\text{exec}} = 1/s$), $x = \Lambda_K t_{\text{exec}}$ satisfies the identical fixed point $x = \Lambda_{\infty}(N)$, so useful compute utilization $u(N) = (1 - p_c)^{\Lambda_{\infty}(N)}$ is invariant to $K$ (`0.6528` at $N = 16$, `0.3752` at $N = 64$) while finite-slot throughput drops as $\Lambda_K(N) = \min(1, K/N)\Lambda_{\infty}(N) \sim \Theta(K \frac{\ln N}{N})$ (`6.2089` at $N = 8 \to 3.0017$ at $N = 64$ for $K = 8, p_c = 0.04$).
2. **The `Agrawal–Carey–Livny` Resource Inversion (`ACM TODS` 12(4):609–654, 1987, Figs. 5–9; `Probe P3` Part 3B):**
   - **Infinite slots ($K = \infty, N = 36, G = 40, p_{\text{abandon}} = 0$):** In the 2-granule discrete-step simulator (`3,000` ticks, $\Delta t = 0.05$, aborting youngest true wait-for cycle member `max(cyc)` with `0` lasso-prefix bystander aborts), **`OCC` (`12.872` commits/unit-time) beats `Blocking 2PL` (`5.736`, `2.24×`)** because blocked 2PL holders retain `g1` while waiting on `g2`.
   - **Finite slots ($K = 8, N = 36, G = 40, p_{\text{abandon}} = 0$):** Matching `Agrawal et al.` Experiment 2 (`1` CPU + `2` disks, where `Blocking` peaks at `mpl = 25` with `92%` useful disk utilization while `Optimistic` peaks at `mpl = 10` and collapses), **`Blocking 2PL` (`4.976` throughput, `93.12%` useful compute fraction, burning `6.88%` on deadlock-cycle aborts) beats `OCC` (`2.816` throughput, `35.20%` useful compute fraction) by `1.77×`** because waiting workers consume zero compute slots.
3. **De-Confounded Open-Arrival Cookie-Licking (`Probe P3` Part 3B):** Decoupling orphan-lock retention (`orphan_locks[g] = TTL`) from immediate contributor replacement (`reset_worker(w)`) isolates pure lock starvation:
   - **Zero-contention negative control ($G = 10,000, N = 16, K = 8, p_{\text{abandon}} = 0.25, \text{TTL} = 60.0$):** `OCC = 7.312` vs. `Blocking 2PL = 6.480` (`1.13×`), confirming zero spurious closed-pool worker depletion.
   - **Controlled contention ($N = 16, G = 24, K = 8, p_{\text{abandon}} = 0.25$ held strictly fixed):** Un-heartbeated long leases ($\text{TTL} = 60.0$) collapse `Blocking 2PL` to **`0.288` vs. `OCC = 2.624` (`9.11×` starvation)**, whereas shortening fenced leases to **$\text{TTL} = 1.0$** at the **exact same** $(N = 16, G = 24, K = 8, p_{\text{abandon}} = 0.25)$ restores **`Blocking 2PL = 4.176 > OCC = 2.624` (`1.59×`)**.

## Boundaries

1. **Cryptographic / Byzantine Lease Forgery (`known not to apply` for plain commit trailers; `not examined` for cryptographic implementation):** `Probe P2` `G3b` enforces monotonic `Fencing-Token:` commit trailers inside `hooks/reference-transaction` (`prepared`), which prevents split-brain overwrites by delayed, crashed, or ambient-credential orphan processes under a **cooperative / fail-slow crash model**. It **does not apply** to adversarial/Byzantine writers capable of forging arbitrary `Fencing-Token:` trailers; defending against untrusted writers requires server-authenticated per-token credentials (e.g., short-lived HMAC/macaroon tokens bound to `(ref, lease_token)` validated by the Git receive service), whose key-distribution overhead was **not examined**.
2. **Parametric Intervention Weights (`known not to apply` as universal constants):** `Probe P4` (`[toy model / parametric decision model]`) proves topological regime separation and unit-consistent comparative statics ($\rho \to 1$, $\delta \to 0$, $\omega \perp \kappa$), **not** calibrated empirical cost constants across arbitrary programming languages or model families. Concrete threshold crossovers must be re-estimated from repository merge-conflict rates (`AgenticFlict` `15.2%–31.9%`), test-suite runtime, and bug-escape severity $V_{\text{bug}}$.
3. **Queueing Arrival Distributions Beyond Fixed-Population / Open-Replacement Surrogates (`not examined`):** `Probe P3` Part 3A uses `Franaszek & Robinson` (1985) deterministic processor sharing ($t_{\text{exec}} = 1/\min(1, K/N)$) and Part 3B simulates uniform 2-granule transactions with immediate slot replacement on abandonment. Heavy-tailed zipfian hotspot granules (such as a single root `Cargo.toml` or router modified by `>50%` of tasks) shift the finite-slot optimum even further away from unpartitioned `OCC` toward **Mode 3 hub isolation** (`Co-Coder`) or **Mode 4 sequential producer→consumer staging** (`CAID`, `NP-Bench`).
4. **Live Multi-Agent LLM Benchmark Re-Execution (`not examined`):** Metrics from `CooperBench`, `Co-Coder`, `CAID`, `AgenticFlict`, `Xu et al.`, and `NP-Bench` are audited directly from primary papers, Crossref/arXiv records, and pinned repository artifacts rather than re-running multi-thousand-dollar proprietary API benchmarks.
