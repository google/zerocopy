# GoogleSQL `ResolvedAST` Boundaries, `NaN < -Inf` Float Semantics, Disconnected Ghost-Real Unsoundness, Columnar Dead-Row Validity, and 3VL Join-Filter Mirroring

## Summary

Deductively verifying a Rust columnar SQL engine that conforms to GoogleSQL's `PreparedQueryBase` / `EvaluatorTableIterator` / `ResolvedStatement` contract hinges on five subtle semantic and soundness invariants:

1. **GoogleSQL `NaN < -Inf` float total preorder vs. Arrow/DataFusion `NaN`-greatest:** Unlike Rust `f64::total_cmp` and Apache Arrow / DataFusion (`-0.0 < +0.0` or `NaN` greatest), `googlesql::SimpleType::ValueContentLess` (`googlesql/public/types/simple_type.cc:986-1015`) orders `NaN` *strictly below* `-Inf` (`NaN < -Inf < -0.0 == +0.0 < +Inf`). `SimpleType::HashValueContent` (`simple_type.cc:779-812`) hashes all `float`/`double` `NaN` bit patterns to fixed constants (`0x739EF9A0B2C15522ull` / `0xA00397BC84F93AA7ull`) and delegates non-`NaN` floats to `absl::HashState::combine` (`value == 0 ? 0 : value`), preserving hash congruence across `-0.0 == +0.0` and payload-distinct `NaN`s. By contrast, `kDefaultFloatMargin` (`googlesql/common/float_margin.h:59, 171-174, 202-203`, `kDefaultUlpBits = 4`, i.e., $2^4 = 16\text{ ULPs}$) is non-transitive and applies only to approximate test harnesses, whereas query grouping/joins use `kExactFloatMargin` (`ulp_bits = 0`).
2. **Disconnected Ghost-Real Float Soundness Trap:** In SMT-backed Rust verifiers (such as Verus), pairing a runtime `f64` with an unconstrained ghost exact real `(val: f64, ghost_real: Real)` (`wf_pair := true`) and axiomatizing comparison observers (`eq`, `lt`, `is_nan`, `hash`) to return predicates on `ghost_real` is **runtime-unsound** even though the axioms alone are logically consistent (`False` is unprovable in empty context): on `big = 2^54` and `one = 1`, `(big + one) - big == one` reduces in exact arithmetic to `1 == 1` (`true`), allowing safe code to prove bounds check `idx = 0 < 1` statically while IEEE-754 binary64 round-to-nearest-even evaluates `(2^54 + 1.0) - 2^54 = 0.0 != 1.0` (`idx = 999`, out-of-bounds UB at runtime; `ghostRealFloat_proves_inBounds_while_runtime_oob`).
3. **Rust MIR dead-row bit-validity (`FromBytes` vs. `bool`) and empty-safe dictionary gather:** Under `lean-miri`'s `ValidityMemory.readImmediate` (`Miri/Interpreter/ValidityMemory.lean`), reading `.uninit` bytes on masked-out rows is immediate UB, and reading initialized slack byte `>= 2` as `bool` faults with `invalidScalarBits` (`rustMirReadBool_stale_byte2_is_ub`). Branchless Rust columnar engines must store `FromBytes` scalars (`i64`, `u64`, `f64`, and `u8` byte masks instead of `[bool]`), zero-fill unused bytes of inline SSO string headers, and guard `dictVals.isEmpty()` before applying branchless index blending `blendedIdx := if outerNull then 0 else rawIdx` on two-level nullable dictionary columns (`safeBlendedGather_eq_logicalMappedRead`).
4. **Necessary and sufficient conditions for inner-join filter mirroring and 4-branch `LIMIT`/`OFFSET` folding:** Pushing/mirroring a filter `P(L.k)` across an inner equijoin `L.k = R.k` onto `R.k` is exact if and only if `P` is **both** (i) 3VL `isKeep`-congruent across `eqK`-equivalent representations (`∀ x y, eqK x y = true → (P x).isKeep = (P y).isKeep`, violated by `1.0 / k < 0.0` on `-0.0 == +0.0` and by collation-insensitive functions on collated strings) **and** (ii) infallible on unmatched right-hand rows (`∀ r, P r ≠ .runtimeErr`, violated by `10 / k > 0` on `L = [], R = [0]`; `fallibleJoinMirror_introduces_spurious_error_on_unmatched_rhs` and `joinFilterMirror_exact_of_infallible_and_congruent`). Merging adjacent unfiltered `LIMIT`/`OFFSET` nodes is exact across all four `(Option Nat × Option Nat)` limit combinations (`foldProjectLimitAndOffset_all4_exact`) provided `cOff + pOff` is checked against `i64` overflow.
5. **`AnyResolvedStatementProto` ingestion seam & `EvaluatorTableIterator` typestate:** Deserializing `AnyResolvedStatementProto` (`googlesql/resolved_ast/resolved_ast.proto.template:51-59`, `serialization.proto:31-151`) from an external C++ `AnalyzeNextStatement` front-end into a verified Rust `ResolvedAstValidator` (`googlesql/resolved_ast/validator.h:106-118`) isolates C++ SQL parsing/catalog binding outside the Rust memory-safety TCB, while encoding `EvaluatorTableIterator` (`googlesql/public/evaluator_table_iterator.h:49-186`) as a 4-phase, 10-operation typestate machine (`stepIterProtocol`) statically rules out post-`NextRow()` configuration mutations and post-EOF `GetValue` UB.

## Findings

### 1. GoogleSQL Floating-Point Ordering (`NaN < -Inf`), Hash Congruence, and `FloatMargin` Non-Transitivity

`Basis: source + formal`

SQL engines diverge sharply on how `GROUP BY`, `ORDER BY`, and hash/sort joins order IEEE-754 `NaN` and signed zeros (`-0.0` vs. `+0.0`). Direct inspection of `google/googlesql@762ca7a16f2b555c85b6f9250c713a82bd1052d6` establishes GoogleSQL's exact invariants:

- **`NaN` is strictly smallest (`NaN < -Inf`):** In `SimpleType::ValueContentLess` (`googlesql/public/types/simple_type.cc:1000-1015`):
  ```cpp
  case TYPE_DOUBLE:
    if (std::isnan(x.GetAs<double>()) && !std::isnan(y.GetAs<double>())) {
      return true;
    }
    if (std::isnan(y.GetAs<double>())) {
      return false;
    }
    return ContentLess<double>(x, y);
  ```
  Because `ContentLess<double>` uses C++ `<` (`-0.0 < +0.0` is `false` and `+0.0 < -0.0` is `false`), `ValueContentLess` defines a strict weak ordering whose induced equivalence classes (`!(x < y) && !(y < x)`) collapse all `NaN` bit patterns into a single least class below `-Inf` and collapse `-0.0` and `+0.0` into a single zero class (`googleSqlFloat_nan_smallest_and_signedZero_congruent` in `support/ColumnarMemoryAndFloat.lean`). `TupleComparator::operator()` (`googlesql/reference_impl/tuple_comparator.cc:81-86`) invokes `Compare(..., /*compare_floating_point_approximately=*/false, ...)`. This is the exact opposite of DuckDB / Apache DataFusion (`NaN` sorts greatest, above `+Inf`) and differs from raw `f64::total_cmp` (which separates `-0.0 < +0.0` and sign/payload-distinct `NaN`s).
- **Hash congruence:** `SimpleType::HashValueContent` (`simple_type.cc:779-812`) intercepts `std::isnan` and combines fixed constants `kFloatNanHashCode = 0x739EF9A0B2C15522ull` (`TYPE_FLOAT`) and `kDoubleNanHashCode = 0xA00397BC84F93AA7ull` (`TYPE_DOUBLE`), while delegating non-`NaN` floats to `absl::HashState::combine`, which normalizes `value == 0 ? 0 : value` before hashing bytes—ensuring `hash(-0.0) == hash(+0.0)` and `hash(qNaN_1) == hash(sNaN_2)`.
- **`kExactFloatMargin` vs. `kDefaultFloatMargin`:** `SimpleType::ValueContentEquals` (`simple_type.cc:933-936`) delegates to `options.float_margin.Equal(x, y)` (`googlesql/common/float_margin.h:91-102`). `kExactFloatMargin` (`float_margin.h:197-198`, `ulp_bits_ = 0`) checks `x == y || (isnan(x) && isnan(y))`, which is an equivalence relation compatible with `ValueContentLess`. By contrast, `kDefaultFloatMargin` (`float_margin.h:59, 171-174, 202-203`) sets `kDefaultUlpBits = 4`, allowing `|x - y| <= 2^4 * Ulp(max(|x|, |y|)) = 16 * Ulp(...)` (plus `16 * Ulp(1.0)` near zero), which is *not* transitive and must never be used as a hash-table or sort-join equivalence relation.

### 2. The Disconnected Ghost-Real Float Soundness Trap

`Basis: formal + derived`

When verifying floating-point query operators (sorting, quantile/window functions, hash/merge joins) in SMT-based deductive verifiers (`Verus` and similar Floyd-Hoare tools) where SMT `FPA` bit-blasting over nonlinear arithmetic times out, a tempting specification pattern wraps runtime `f64` with a ghost mathematical real `struct IdealFloat { bits: f64, ghost model: Real }` whose type invariant `wf_pair` is trivially `true`, axiomatizing `+`, `-`, `*`, `/` to update `model` by exact real arithmetic and axiomatizing `eq(&self, other) -> (r: bool) ensures r == (self.model == other.model)` (plus `lt`, `is_nan`, `hash`).

Even though those specification axioms contain no internal contradiction in pure logic (`False` cannot be derived without calling runtime code), **the axiomatized observer bridge is unsound at runtime**:

- Let `big = flFromNat (2^54)` (`18014398509481984.0_f64`, where `Ulp(2^54) = 4.0`) and `one = flFromNat 1` (`1.0_f64`).
- In IEEE-754 binary64 round-to-nearest-even (`ieee64AddAt2Pow54` in `support/ColumnarMemoryAndFloat.lean`), `2^54 + 1.0` has exact midpoint remainder `1 < 2` (`rem4 = 1`), so it rounds down to `2^54`; subtracting `2^54` yields runtime `0.0_f64`. Meanwhile, the ghost real field computes `(2^54 + 1) - 2^54 = 1`.
- Evaluating `let idx = if diff.eq(&one) { 0 } else { 999 }; slice.get_unchecked(idx)` on a 1-element slice `[T; 1]` allows the verifier to prove `axiomatizedSpecEq diff one == true` (`specIdx = 0 < 1`) and discharge the `unsafe` bounds obligation with zero `unsafe` blocks in caller code, while at runtime `0.0 == 1.0` evaluates to `false` (`runtimeIdx = 999`), executing an out-of-bounds memory read (`ghostRealFloat_proves_inBounds_while_runtime_oob` in `support/ColumnarMemoryAndFloat.lean`, proved by `⟨rfl, rfl, rfl⟩` with zero axioms).

Sound floating-point verification in operational frameworks like Anneal must bind runtime `f32`/`f64` directly to IEEE-754 bit-level semantics (`FloatBits` in `proofs-rs/lean-miri@c92d1d9754c9dd585b6b9d6949ae67e5e4665d6a`, where `NaN < -Inf` ordering and `-0.0`/`+0.0` canonicalization are simple bitwise/sign-magnitude theorems requiring zero FPA SMT bit-blasting) and attach error bounds for transcendental/summation kernels via verified interval/dyadic enclosures rather than uncoupled ghost reals.

### 3. Operational Rust MIR Columnar Memory Validity (`FromBytes` vs. `bool`) and Empty-Safe Dictionary Gather

`Basis: source + formal`

In `proofs-rs/lean-miri@c92d1d9754c9dd585b6b9d6949ae67e5e4665d6a` (`Miri/Interpreter/ValidityMemory.lean`, vendored in `joshlf/anneal@c131b320eeeb26ef692e5afd5ec8db49ee518613` under `vendor/lean-miri/`), `readImmediate` checks byte initialization and scalar validity on *every* typed scalar load before downstream expressions execute:

1. **Uninitialized vs. stale initialized dead rows:** Loading an `.uninit` slot in a branchless scan `let raw: i64 = col[row]; if valid { Some(raw) } else { None }` faults immediately with `ValidityFailure.uninitialized` (`branchlessScan_uninit_dead_row_is_ub`). If column buffers are zero-initialized or recycled from prior initialized writes of `FromBytes` types (`i64`, `u64`, `f64`, `u8`), `branchlessScan_stale_init_i64_safe_and_invariant` proves that dead rows (`valid = false`) never fault and produce results invariant to arbitrary stale payload values `s1, s2`.
2. **Restricted-validity `bool` trap (`invalidScalarBits`):** Unlike `i64` or `u8`, reading a `[bool]` buffer over recycled arena memory whose dead row holds byte `2` faults immediately with `ValidityFailure.invalidScalarBits` (`rustMirReadBool_stale_byte2_is_ub`). Rust columnar engines must represent byte-per-row validity/selection vectors as `[u8]` (or bit-packed `[u64]`) and decode `b & 1 != 0`, and must zero-initialize all 16 bytes of inline SSO `Bytes`/`StringView` headers (`[0u64, (len as u64) << 56]`) rather than leaving trailing inline bytes uninitialized.
3. **Two-level nullable dictionary (`Mapped` / `DictionaryArray`) gather:** Dictionary-encoded columns carry an optional outer per-row null bitmap `outerNulls`, an index array `indices[r]`, an inner dictionary array `dictVals`, and an optional inner dictionary null bitmap `dictNulls` (`none` when non-nullable). Branchlessly rewriting `blendedIdx := if outerN then 0 else indices[r]` avoids out-of-bounds reads on dead outer rows *except* when `dictVals` is empty (`[]`) and every row has `outerN = true` (`emptyDictAllOuterNull` in `support/ColumnarMemoryAndFloat.lean`), where indexing `dictVals[0]` panics or faults out of bounds! Checking `col.dictVals` for emptiness once per batch before the branchless gather loop handles both empty dictionaries and omitted (`none`) inner/outer bitmaps identically to logical two-stage lookup (`safeBlendedGather_eq_logicalMappedRead`).

### 4. Exact 3VL + Error-Aware Inner-Join Filter Mirroring and 4-Branch `LIMIT`/`OFFSET` Folding

`Basis: source + formal`

Query optimizers routinely mirror single-side predicates across inner equijoins (`Filter(P(L.k), Join(L.k = R.k)) -> Join(Filter(P, L), Filter(P, R))`) and fold stacked pagination nodes (`Paginate(pLim, pOff, Paginate(cLim, cOff, xs))`). Mechanization in `support/SqlRewriteAndIteratorTypestate.lean` establishes two exactness boundaries:

1. **Dual failure modes of naive inner-join filter mirroring:**
   - *Quotient non-congruence (`naiveJoinMirror_drops_signedZero_match`):* Under GoogleSQL float join equality `floatJoinEq` (`-0.0 == +0.0`), `P(k) := (1.0 / k < 0.0)` evaluates to `valTrue` on `L = [-0.0]` and `valFalse` on `R = [+0.0]`. Mirroring `P` onto `R` drops `(+0.0)` before the join, turning `some [(-0.0, +0.0)]` into `some []`. The same defect arises for byte-length or raw regex predicates over collation-equal strings.
   - *Fallible predicates on unmatched RHS rows (`fallibleJoinMirror_introduces_spurious_error_on_unmatched_rhs`):* Even over exact `Nat.beq` integer equality—where `∀ x y, Nat.beq x y = true → P x = P y` holds trivially!—mirroring a fallible predicate `P(k) := (10 / k > 0)` onto `R = [0]` when `L = []` evaluates `10 / 0` on an unmatched right row, turning `joinFilterLeftOnly = some []` into `joinFilterMirrored = none` (`divByZero`).
   - *Necessary and sufficient soundness theorem (`joinFilterMirror_exact_of_infallible_and_congruent`):* When `P` is **both** infallible on `R` (`∀ r, P r ≠ .runtimeErr`) **and** 3VL `isKeep`-congruent across `eqK` (`∀ x y, eqK x y = true → (P x).isKeep = (P y).isKeep`, allowing `valFalse` and `valNull` to interconvert since both have `isKeep = false`), `joinFilterMirrored eqK P left right = joinFilterLeftOnly eqK P left right` holds identically for all `left, right` (including when `left` itself errors).
2. **Complete 4-branch `LIMIT`/`OFFSET` folding (`foldProjectLimitAndOffset_all4_exact`):** Defining `foldOptLimits cLimOpt pLimOpt pOff` over `Option Nat` (`none, none => none`; `none, some pLim => some pLim`; `some cLim, none => some (cLim - pOff)`; `some cLim, some pLim => some (min pLim (cLim - pOff))`) satisfies `paginateOpt pLimOpt pOff (paginateOpt cLimOpt cOff xs) = paginateOpt (foldOptLimits cLimOpt pLimOpt pOff) (cOff + pOff) xs` across all four cases when the parent node carries no filter (filtering between two `LIMIT`/`OFFSET` nodes does not commute with `OFFSET`) and `cOff + pOff` does not overflow signed 64-bit integer bounds (`checked_add`).

### 5. `AnyResolvedStatementProto` Ingestion Seam, `EvaluatorTableIterator` Typestate, and SMT-Free Proof Scaling

`Basis: source + formal + derived`

- **Protobuf AST boundary (`googlesql/resolved_ast/`):** GoogleSQL exposes a canonical protobuf wire serialization of resolved statements via `googlesql/resolved_ast/serialization.proto:31-151` and `googlesql/resolved_ast/resolved_ast.proto.template:51-59` (`AnyResolvedStatementProto`), accompanied by invariants checked in `googlesql::Validator::ValidateResolvedStatement` (`googlesql/resolved_ast/validator.h:106-118`) and `gen_resolved_ast_column_visibility.py`. Accepting `AnyResolvedStatementProto` bytes produced by an out-of-TCB SQL parser/catalog binder and validating column/parameter scope, unique column IDs, and expression types inside an Anneal-verified Rust `ResolvedAstValidator` guarantees memory-safety and evaluation soundness for *arbitrary* untrusted proto bytes while preserving end-to-end SQL semantics whenever the external analyzer is faithful.
- **`EvaluatorTableIterator` 10-operation lifecycle typestate (`googlesql/public/evaluator_table_iterator.h:49-186`):** Upstream C++ specifies strict phase preconditions in prose: `SetColumnFilterMap` (`:133-136`), `SetReadTime` (`:138-147`), and `SetDeadline` (`:172-176`) must be called *prior* to the first `NextRow()`; `GetValue(i)` (`:154-158`) is valid only after `NextRow()` returns `true`; once `NextRow()` returns `false` (`:149-152`), only schema/memory inspectors (`NumColumns`, `GetColumnName`, `GetColumnType`, `Get*MemoryUsage`), `Status()` (`:160-162`, valid in all phases), and thread-safe `Cancel()` (`:170`) remain legal. Encoding this protocol as the 4-phase machine `stepIterProtocol` (`support/SqlRewriteAndIteratorTypestate.lean`, `iterProtocol_full_conformance`)—or directly as Rust typestates `UnstartedScanIter -> ActiveRowCursor<'a> -> ExhaustedScanIter` paired with an `Arc<CompiledPlan>` + `Mutex<Vec<Box<OperatorTreeState>>>` execution-state pool for `PreparedQueryBase` (`googlesql/public/evaluator_base.h:482-530`)—eliminates iterator protocol violations at compile time.
- **SMT trigger elimination:** Whereas universal sequence quantifiers (`forall |r: int| 0 <= r < n ==> ...`) in Z3-backed Rust verifiers require thousands of manual `#[trigger]` annotations and `assert(...)` hints across relational operator proofs, structural induction over `List` / chunked columnar batches in Lean 4 (`dropRows_takeRows`, `joinFilterMirror_exact_of_infallible_and_congruent`, `safeBlendedGather_eq_logicalMappedRead`) discharges the same relational laws purely by definitional reduction and constructor case splits with zero quantifier triggers.

## Boundaries

- **Known not to apply (outer joins and `LIMIT`-over-`Filter`):** `joinFilterMirror_exact_of_infallible_and_congruent` applies strictly to *inner* equijoins (`L ⋈_{L.k = R.k} R`); mirroring a left-side filter onto the preserved side of a `LEFT` or `FULL OUTER JOIN` changes unmatched outer-padded rows and is unsound. Similarly, `foldProjectLimitAndOffset_all4_exact` requires the outer node to have *no* `WHERE` filter between the two pagination steps.
- **Not examined (GoogleSQL C++ SQL lexer/parser and catalog resolution internals):** Treating `AnyResolvedStatementProto` as the verified engine's entry boundary isolates C++ parsing/name-binding bugs from Rust memory safety and execution soundness, but a bug inside the external C++ analyzer that emits a type-valid yet semantically unintended `AnyResolvedStatementProto` is outside the Rust engine's specification unless the SQL parser/binder itself is separately verified.
- **Unsupported in `joshlf/anneal@c131b320eeeb26ef692e5afd5ec8db49ee518613` without MIR coverage extensions:** At `c131b320eeeb26ef692e5afd5ec8db49ee518613`, `trusted/lean/Trusted/MirSemantics.lean` executes scalar/unit/fieldless-enum locals (`isSupportedScalarOrUnitTy`); verifying a full Rust columnar SQL engine in Anneal requires wiring `lean-miri`'s `FloatBits` (`f32`/`f64`), struct/enum ADTs (`Downcast`/`SetDiscriminant`), slice indexing/casts, `Drop` cleanup frames, and `CoreBuiltin` contracts for arena/slice/atomic-refcount primitives (`Arc`, `Vec`).
- **Attractive stronger conclusion not established:** Consistency of a ghost specification library in isolation (`⊢ False` unprovable from its `axiom` declarations) does *not* imply soundness of `#[external_body]` / `#[trusted]` observer wrappers over runtime IEEE-754 types; soundness requires proving refinement against actual IEEE-754 bit operations (`FloatBits`).
