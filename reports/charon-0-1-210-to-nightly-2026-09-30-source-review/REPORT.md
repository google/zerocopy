# Charon 0.1.210 cohorts against standalone nightly-2026.09.30: bounded source review

## Summary

The [matrix](support/matrix.json) reconciles all **45** frozen Charon 0.1.210 report packages: 17 classified as `Charon 0.1.210 + Rust nightly-2026-05-31` and 28 classified as `Charon 0.1.210 + Rust/Cargo nightly-2026-05-31`. It preserves the exact first-section claim paragraph and locator, source report and metadata SHA-256, every original subject identity, and direct Charon, rustc, and Cargo pins separately. The standalone [Charon September 30 release](https://github.com/AeneasVerif/charon/releases/tag/nightly-2026.09.30) resolves to [`2804f2dbc349a4c80201f7c528adf70f8d1ee5fa`](https://github.com/AeneasVerif/charon/commit/2804f2dbc349a4c80201f7c528adf70f8d1ee5fa), whose source identifies package version **0.1.274** and selects Rust **nightly-2026-09-17**. Those are source identity and configuration findings. **All 45 report claims remain unresolved at the newer version.** No newer-version runtime was executed; compatibility is unresolved and Anneal product behavior was not assessed.

## Applicability

The baseline is the 581-row `version-inventory-ebcdcad-581.csv` at reference commit `ebcdcadb63fefd1e6c0f46cb2030270ae3232837`. The present frozen corpus is reference commit `2e9db344b6c0e6391ff78655a18b81ecb7e293e1`, with 587 report packages. Six packages were added after the inventory; the matrix lists their frozen paths and hashes separately. None belongs directly to the two inventory cohorts. A newer audit or synthesis mentioning Charon does not silently become a member of this original 45-row selection.

The two old Charon **source commits must remain distinct despite both declaring `0.1.210`**. Direct subject metadata in 17 reports names [`a535e914f74db4fd9e6be7048f4233270d8945c0`](https://github.com/AeneasVerif/charon/commit/a535e914f74db4fd9e6be7048f4233270d8945c0); three direct subject entries name [`0c91ca1a8e002d6bfa8d8f1f452804fce2f92cf1`](https://github.com/AeneasVerif/charon/commit/0c91ca1a8e002d6bfa8d8f1f452804fce2f92cf1), with one report naming both. Thus 19 reports have a direct Charon repository subject. The remaining reports use other or composite identities; the matrix retains those verbatim and never assigns them a neighboring row's source commit. Two reports directly name old `rust-lang/rust@f8a08b688cbe60acc386ed1fbd1b7cbaaf5576b1`, and one directly names `rust-lang/cargo@fbb61be30e5f9ac3a6ad58e56a5c0f5db2d2b3ef`; a Charon revision, rustc revision, Cargo revision, channel name, and binary SHA-256 are different coordinates, not interchangeable pins.

The target is the **standalone** Charon `nightly-2026.09.30` release. The official release links to full commit `2804f2dbc349a4c80201f7c528adf70f8d1ee5fa`. Read-only `git ls-remote` of the official repository returned that commit directly for `refs/tags/nightly-2026.09.30` and no separate peeled `^{}` line, so the tag is lightweight in that observation. The Aeneas-paired Charon commit `e435e5f` appears as a parent of the standalone release commit; it is **not** substituted for the release target. The release date does not mean a September 30 Rust toolchain: the release source selects September 17.

## Findings

### Source configuration delta, not claim revalidation

Both old commit-pinned [`a535e914` Cargo.toml](https://github.com/AeneasVerif/charon/blob/a535e914f74db4fd9e6be7048f4233270d8945c0/charon/Cargo.toml) and [`0c91ca1` Cargo.toml](https://github.com/AeneasVerif/charon/blob/0c91ca1a8e002d6bfa8d8f1f452804fce2f92cf1/charon/Cargo.toml) declare `charon` version `0.1.210`; the [target Cargo.toml](https://github.com/AeneasVerif/charon/blob/2804f2dbc349a4c80201f7c528adf70f8d1ee5fa/charon/Cargo.toml) declares `0.1.274`. The [old a535 toolchain file](https://github.com/AeneasVerif/charon/blob/a535e914f74db4fd9e6be7048f4233270d8945c0/charon/rust-toolchain) selects `nightly-2026-05-31`, while the [old 0c91 toolchain file](https://github.com/AeneasVerif/charon/blob/0c91ca1a8e002d6bfa8d8f1f452804fce2f92cf1/charon/rust-toolchain) selects `nightly-2026-06-01`. This is why the inventory's May 31 cohort label must not override a report's exact source pin. The [target toolchain file](https://github.com/AeneasVerif/charon/blob/2804f2dbc349a4c80201f7c528adf70f8d1ee5fa/charon/rust-toolchain) selects `nightly-2026-09-17`; its components are `rustc-dev`, `llvm-tools`, `rust-src`, and `miri`. Both old toolchain files list `rustc-dev`, `llvm-tools-preview`, `rust-src`, and `miri`. The `llvm-tools-preview` to `llvm-tools` difference is **toolchain metadata only**; it does not show which components install, build, or run on a given host. The target adds `aarch64-unknown-linux-gnu` to its listed targets compared with both inspected old files, likewise only a source configuration observation.

The [release notes](https://github.com/AeneasVerif/charon/releases/tag/nightly-2026.09.30) mention multiple concurrent Charon versions and remembering starting items. Those changes were not mapped to any one of the 45 selected report claims through their determining implementation paths. A release note, package version bump, or toolchain pin change does not establish that extraction identity, LLBC serialization, Cargo closure, concurrency, interruption, cancellation, or any other frozen observation persists or changes. Consequently every matrix row uses `source_claim_result=unresolved_at_target`.

### Component identity and outcome bounds

The inspected official Charon source establishes the **new Rust channel and requested components**, but not full `rust-lang/rust` and `rust-lang/cargo` source checkout commits or installed executable hashes for that September 17 distribution. The matrix leaves `rustc_source_commit` and `cargo_source_commit` null, separately. It does not substitute stable Rust 1.98.1, a September 30 nightly, the old Cargo commit, or Aeneas's paired Charon commit. The old direct Rust and Cargo commits remain retrievable in each row's original subject graph, where actually present.

Each row has four independent outcomes: `source_claim_result=unresolved_at_target`, `current_runtime_result=unexecuted_in_this_review`, `compatibility_result=unresolved`, and `anneal_product_result=unassessed`. The original reports remain evidence for their own pinned subjects and fixtures. This source review does not revise an Anneal requirement, issue gate, or production guarantee.

## Boundaries

This is a **45-row reconciliation and narrow source metadata comparison, not a full source revalidation of 45 report claims**. The inspected files do not determine claim-specific behavior. No Charon, Rust, or Cargo binary was installed, downloaded, built, or run here. The target toolchain's rustc and Cargo source revisions, artifacts, and host compatibility were not established from the inspected official pages. No Charon output format, process lifecycle, Cargo unit graph, or Anneal integration was exercised.

The matrix records null old/new raw-source snapshot SHA-256 values. Its 40-hex old Git blob SHA-1 mentions, where present, are extracted from frozen report text; they are not new hashes of remotely inspected files. Public source pages were read without acquiring raw file bytes, so inventing a new content hash would overstate the evidence.
