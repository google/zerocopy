# Charon item spans in a retained generated Rust file

## Summary

One offline pinned Charon extraction included a `build.rs`-produced Rust file whose **actual `OUT_DIR/generated.rs` bytes were retained independently of LLBC**. Seven local item records in LLBC point to generated file ID 1. Each record's `source_text` is an exact, unique slice of those retained bytes at its serialized line. Their columns match a fixture-specific display-cell calculation over an emoji and a combining mark; UTF-8-byte, Unicode-scalar and UTF-16-unit calculations each disagree for some records.

This adds a generated-file source oracle to #3731 **I079**. The earlier [ASCII local-span report](../anneal-3731-i079-local-span-source-text-2026-09-29/REPORT.md) excluded **32 historical generated file-ID-1 records** because their original generated `.rs` file was not independently retained. The later [Unicode local-span report](../anneal-3731-i079-unicode-charon-spans-2026-09-30/REPORT.md) tested file-ID-0 items. This new fixture does **not** retroactively validate those 32 records or establish an Anneal source map.

## Applicability

The observed Charon, Cargo and rustc binary SHA-256 values are in [REPORT.json](REPORT.json), with Rust nightly `2026-05-31` on macOS arm64. Binary hashes identify the executables actually used; no source-build provenance for the installed Charon binary is established here. The dependency-free crate has one `build.rs` that copies checked-in [`generated_template.rs`](fixture/generated_template.rs) to `OUT_DIR/generated.rs`, and `src/lib.rs` includes that file with `include!`. The runner copied the exact generated output to [`generated.rs`](generated.rs) **before** deleting its private Cargo tree. The template, actual generated file and LLBC file-ID-1 embedded contents have the same 212 UTF-8 bytes and SHA-256 `d0ee5a2c97d8a1797c31955136c6f5dbf62cde9cdc4f88f7a5cf5f551ba2d0c8`.

The generated source places an emoji before `after_emoji` on line 1, a decomposed `e` plus combining acute before `after_combining` on line 2, and both sequences inside `generated_body` on line 3. Charon ran `cargo --preset aeneas --dest-file ... -- --package generated_span_probe --lib --offline --locked -v -j 1` with a private target, Cargo offline, incremental compilation off and one Rayon thread. The full argv/environment and raw output are retained. Both the build-script crate and library had their own `charon-driver rustc` line, and the build script executed between them.

## Findings

LLBC file ID 0 is `src/lib.rs`, containing only the `include!` line. File ID 1 is the generated `OUT_DIR/generated.rs`, named by the exact original path recorded before cleanup and containing the exact retained generated bytes. File IDs 2 and 3 are nonlocal standard-library files without embedded contents. All seven local generated records use file ID 1; five unique names appear because `EMOJI` and `COMBINING` are each serialized in both function and global arrays. One nonlocal `core::str::len` record points to file ID 2 and is excluded from the source-slice comparison. **Basis: execution.**

Across all seven serialized local records, mismatch counts are **7 UTF-8-byte, 6 scalar, 4 UTF-16-unit and 0 fixture display-cell** calculations. The comparator independently locates each `source_text` once on its generated-source line and checks the end-exclusive slice. The fixture display-cell oracle assigns width two to the emoji, zero to the combining mark, and width one to other characters here. It rejects a shifted start, inclusive end, wrong file ID 0, and a changed-template byte control. These are offline comparator controls; the changed template was not compiled as a second Charon run. **Basis: execution of the retained comparator and source/output bytes.**

The runner's preflight measured **34.4717%** estimated reclaimable host memory and **18,964,819,968 bytes** free disk. Across 28 samples, the minimum reclaimable estimate was **34.3567%**, minimum free disk **18,963,968,000 bytes**, maximum process-group RSS **152,224 KiB**, and maximum private scratch **1,100,850 bytes**. The command exited 0 in about 1.41 seconds; no 20%-memory, 10-GiB-disk, 512-MiB-RSS, 100-MiB-scratch or 15-second guard fired. Post-run process-group RSS was zero and the private work tree was removed. Sampling may miss shorter peaks. **Basis: execution.**

## Boundaries

This is one build-script copy, one `include!`, one tiny crate and one Charon binary. The observed display-cell agreement is an oracle for these specific characters, not a general Unicode width contract for generated files, tabs, grapheme clusters, multiline spans, macro expansion or other build-script output. The generated source bytes are independently retained, but the item metadata and file table still come from one Charon producer; this does not authenticate arbitrary rustc provenance or a Rust-to-Lean declaration mapping. The 32 older generated records lacked their original source oracle and remain unverified. The nonlocal standard-library record remains outside scope.

I079 remains **partial** at its existing **product** gate. The result does not attach real Anneal annotations, define a cache key, identify a generated Lean obligation, or prove editor coordinate conversion. I019/I025/I149 and #3730 A02/A08 are context at most; their residuals, statuses, gates and prerequisites are unchanged.
