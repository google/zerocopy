## Claim-mapped deltas

1. **R349, inherited default features.** At Cargo 1.98.1, [`src/cargo/util/toml/mod.rs`](https://github.com/rust-lang/cargo/blob/797e8a9bca276c1c9f9f738d2a20f484fa4eea9d/src/cargo/util/toml/mod.rs#L1209-L1267) ignores a member's `default-features = false` when the workspace enables or omits the setting; in Edition 2024 it raises an error, while earlier editions warn. At Cargo 1.99, the relocated [`src/workspace/parser/mod.rs`](https://github.com/rust-lang/cargo/blob/5f94df4789f005f9a352888e8355ffc645b7ed0e/src/workspace/parser/mod.rs#L1224-L1251) applies the member value first in Edition 2024 and keeps the warning path for earlier editions. Cargo [PR #17126](https://github.com/rust-lang/cargo/pull/17126), the [Rust 1.99 release notes](https://github.com/rust-lang/rust/releases/tag/1.99.0), and the [Cargo Book](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html#inheriting-a-dependency-from-a-workspace) corroborate the change. This is an input-manifest semantic change that can change active features for a specific Edition 2024 inherited edge. It does **not** negate R349's central distinction between contextual compilation-unit features and package-level `cargo metadata` output. The earlier 1.98.1 comparison's 17 mapped files did not include this manifest parsing path, so the addition is genuinely new to that crosswalk.

2. **R351, CI incremental default.** Cargo 1.98.1 [`src/cargo/core/profiles.rs`](https://github.com/rust-lang/cargo/blob/797e8a9bca276c1c9f9f738d2a20f484fa4eea9d/src/cargo/core/profiles.rs#L69-L75) falls from `CARGO_INCREMENTAL` straight to `build.incremental`. Cargo 1.99 [`src/workspace/profiles.rs`](https://github.com/rust-lang/cargo/blob/5f94df4789f005f9a352888e8355ffc645b7ed0e/src/workspace/profiles.rs#L73-L82) adds `.or_else(|| is_ci().then_some(false))` after the config value. Cargo [PR #17220](https://github.com/rust-lang/cargo/pull/17220), merged 2026-07-15, describes the priority `CARGO_INCREMENTAL`, `build.incremental`, inverse `CI`, then `profile.*.incremental`; its review shows a `tests/testsuite/build.rs` case with `CI=1`, `CARGO_INCREMENTAL` absent, and no incremental rustc flag. The [Rust 1.99 release notes](https://github.com/rust-lang/rust/releases/tag/1.99.0) corroborate the default. This changes the default opportunity for rustc incremental cache reuse on CI. It does **not** make Cargo freshness, rustc incremental compilation, and wrapper cache reuse one mechanism, nor does it attest any Charon/LLBC side effect.

The four exact-revision source files are retained next to this report. This is **source evidence, not local execution evidence**. The broad GitHub compare endpoint reports a diverged Cargo history with 369 commits ahead and 18 behind, and truncates its file list at 300; it is not used to claim a repository-wide or full Cargo change inventory. The narrow file pairs above directly establish the two described source changes.
