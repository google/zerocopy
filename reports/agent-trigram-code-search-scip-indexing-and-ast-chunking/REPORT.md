# Positional Trigram Code Search, SCIP Cross-Reference Indexing, AST-Aware Code Chunking, Hybrid Retrieval Fusion, and Git Merkle Index Invalidation

## Summary

Codebase search and retrieval-augmented generation (RAG) stacks combine five distinct indexing layers whose concrete invariants and implementation failure modes govern candidate recall, cross-file navigation precision, prompt-budget utilization, and incremental edit-loop freshness:

1. **Positional Rune-Trigram Indexing and Regular-Expression Lowering (`Russ Cox 2012`, `sourcegraph/zoekt@b55ce727`):**
   - Russ Cox's five-attribute inductive regular-expression analyzer `(emptyable, exact, prefix, suffix, match)` guarantees zero false negatives ($\mathcal{L}(e) \subseteq \text{Docs}(\text{match}(e))$) while extracting cross-concatenation boundary trigrams $\text{trigrams}(\text{suffix}(e_1) \times \text{prefix}(e_2))$ and saving trigram conjunctions before cardinality-bounding reductions. On `(se|ld)Config` across `Probe 1`'s deterministic 240-document Go repository, Cox's cross-boundary `seCo`/`ldCo` trigrams narrow verification scans to **`4 / 240` (`1.67%`)** documents, whereas `Zoekt`'s `regexpToMatchTreeRecursive` (`index/eval.go:621–698`) discards `<3`-rune concatenation arms and scans **`51 / 240` (`21.25%`, `12.75x` more files)**; similarly, on small bounded repetitions (`[01]{3}`, `(ab|cd){2}`), Cox emits exact `8`-arm and `4`-arm trigram disjunctions (`max_set = 8`) whereas `Zoekt`'s `OpRepeat` (`eval.go:639–650`) recurses on `r.Sub[0]` and collapses to `bruteForceMatchTree`.
   - `Zoekt` packs three Unicode scalar values into 63-bit `ngram` integers (`index/bits.go:171–173`) and elides pure-ASCII blocks in `makeRuneOffsetMap` (`bits.go:467–480`, `runeOffsetFrequency = 100`), consuming **`0` bytes** on a 2,500-rune ASCII file and **`192` bytes** (`24` entries $\times$ `8` bytes, `0` byte-offset recovery errors) on multi-byte UTF-8 (`2B` Greek, `3B` CJK, `4B` emoji). Four operational hazards affect automated callers: (i) case-insensitive `generateCaseNgrams` (`bits.go:27–48`) expands 3-element `unicode.SimpleFold` orbits (`'k'/'K'/'K'` [`U+212A`], `'s'/'S'/'ſ'` [`U+017F`]) into **$3^3 = 27$ posting lookups per trigram** (`3.375x` ASCII's $2^3 = 8$) and 4-element Greek prosgegrammeni `[U+0345, U+0399, U+03B9, U+1FBE]` into **$4^3 = 64$ lookups** (`8x` ASCII), whereas `query.LowerRegexp` (`query/regexp.go:26–46`) folds only ASCII `'A'..'Z'` (`'KSK' -> 'KsK'`); (ii) `<3`-rune content/filename substrings (`"id"`, `index/matchtree.go:1334–1341`) and alternations containing a `<3`-rune branch (`(parseConfig|id)`, `eval.go:687–690`) fall back to `bruteForceMatchTree` (**`240 / 240 = 100.0%`** shard scan), while `<3`-rune `Symbol` substrings (`matchtree.go:1205–1212`) scan every document's ctags symbol table; (iii) files with `< 3` bytes or `> 20,000` distinct trigrams (`SkipReasonTooSmall`, `SkipReasonTooManyTrigrams`, `shard_builder.go:706–738`, `builder.go:332–334`) are skipped; and (iv) experimental `scoreFileBM25` (`index/score.go:263–282, 391–425`) **treats inverse document frequency (`IDF`) as constant `1.0`** (`'err'*12 = 2.0000 > rare*1 = 1.0000`, inverting Robertson–Walker IDF `0.0042 < 5.0793`) and defaults to **shard-local byte-length averages** (`score.go:406–408`), shifting the identical 1,200-byte file's score by **`2.868x`** (`0.5519` vs. `1.5827` at `tf = 1`; **`1.766x`** at `tf = 3`) across shards.

2. **Streaming Symbol-Descriptor Protocols (`SCIP`) vs. Monotonic Vertex-ID Property Graphs (`LSIF v0.5.0` / `v0.6.0`):**
   - Across Sourcegraph production corpora (`over 45k` repositories, `more than 4k` LSIF uploads/day; `Geirsson 2022`), LSIF indexes are **`~5x` larger uncompressed** and **`4x` larger gzipped** than SCIP (`8x` smaller on disk, `3x` faster ingestion, and `~550` vs. `1,500` LOC in Meta's `Glean`). On `Probe 2`'s deterministic 20-document, 100-symbol, 1,200-occurrence workspace—encoding `Metadata` fields `1..4` (`text_document_encoding = UTF8` at field `4`, `scip.proto:53`) and per-`Document` `position_encoding = UTF8CodeUnitOffsetFromLineStart` at field `6` (`scip.proto:118`)—SCIP (`112,943` B raw / `5,060` B gzip) vs. normative `LSIF v0.5.0` (`426,200` B raw / `36,454` B gzip; `4,643` JSON-Lines graph elements: `1,722` vertices + `2,921` edges) achieves **`3.77x` raw** and **`7.20x` gzip** compression while bounding `IndexVisitor.ParseStreaming` (`bindings/go/scip/parse.go:29–122`) to **`5,642` bytes** (`1` `Document` buffer) rather than a global cross-file vertex-ID map.
   - `Document.position_encoding` (`scip.proto:118–146`) allows `UTF-8` (`1`), `UTF-16` (`2`, `scip-typescript`/`scip-java` and hardcoded `positionEncoding: 'utf-16'` in `LSIF v0.5.0`), or `UTF-32` (`3`) column units (`'W'` in `"🚀 Woo"` = **`5`**, **`3`**, **`2`**). Slicing a UTF-8 buffer directly with UTF-16 column offsets after `"🚀 ready"` shifts `verifyToken` left by 2 bytes to **`'n verifyTok'`**.

3. **AST Split-then-Merge Chunking (`cAST` / `astchunk`) and Code-RAG Benchmark Forensics:**
   - `cAST` (`Zhang et al., Findings of EMNLP 2025`, pp. 8106–8116) raises `StarCoder2-7B` RepoEval `Pass@1` by up to **`+6.7` points** (`51.2 -> 57.9` on `GIST-small-Embedding-v0`, `Table 1`) and `Claude-3.7-Sonnet` SWE-bench Lite `Pass@1` from **`14.0% -> 16.7%`** on `CodeSage-small-v2` (`Table 1`), whereas `Split-only` without sibling merging drops RepoEval retrieval `nDCG@5` by **`16.8–19.0` points** across `BGE`/`GIST`/`CodeSage` (`Table 2`) and doubling context from `4k` to `8k` tokens on `CodeSage-small-v2 + StarCoder2-7B` reduces `Pass@1` from **`73.2% -> 69.2%`** (`Table 3`).
   - Source audit of `yilinjz/astchunk@82029ada` uncovers **five implementation defects** reproduced in `Probe 3`: (A1) `preprocess_nws_count` (`preprocessing.py:90–94`) counts non-whitespace **UTF-8 bytes** (`64`) while `ASTChunk.chunk_size` (`astchunk.py:29`) counts Unicode **characters** (`32`), splitting a `32`-char CJK file at `max_chunk_size = 50` into `2` chunks; (A2) `rebuild_code` (`astchunk.py:82, 94`) replaces leading `\t` tabs with single `" "` spaces (`tab_preserved = False`) and mixes outer `" "` with inner `\t\t` on compound statements; (A3) `build_chunk_ancestors` (`astchunk.py:124–127`) filters only Python node types (`class_definition`, `function_definition`), returning **`0` ancestors** on Java/C#/TypeScript (`class_declaration`, `method_declaration`), while `apply_chunk_expansion` (`L189–194`) bakes `filepath` into `chunk_text` (invalidating `blob_sha` embedding caches across `git mv`); (A4) oversized atomic leaf AST nodes (`len(children) == 0`, `size > max_chunk_size`) emit **`0` chunks** (`astchunk_builder.py:121–126`; paper `Algorithm 1:16–29` also omits `else:`, retaining only `481 / 913` non-WS chars); and (A5) `add_window_overlapping(chunk_overlap=1)` (`L208–224`) ignores `max_chunk_size`, inflating a `115`-char budget to **`325` chars (`2.83x`)**.
   - Benchmark evaluation repositories contain compounding measurement defects: `CoSQA` paired web queries with top-1 `CodeBERT` functions under a `>50%` partial-demand rule, leaving **`~51%` mismatched pairs** (`Gong et al., arXiv:2406.11589v1, §1 C2`; `v7`/`IEEE TSE 2026` §I separately documents that **`63.2%`** of developer queries admit multiple valid implementations, where 1-to-1 `MRR` scores `0.25` vs. `v1` `MMRR = 1.00`), while `DeepSoftwareAnalytics/CoSQA_Plus@1ca33438` omits imported `model.py` and `metrics.py`; `Leolty/repobench@e0cfd34c` (`run.py:39–45, 61–67`) locks `in_multiline_comment = True` permanently on single-line `"""docstring"""` / `/* comment */` headers and grades indentation-broken Python via `pred.split() == gt.split()` (`metrics.py:24`); and `code-rag-bench@f9e100ca` (`generation/chunk.py:17–25, 73`) drops every chunk-boundary line, returns **`""`** when line `0` exceeds `num_tokens`, and tokenizes BM25 code via `doc.split(" ")` (`eval_beir_okapibm25.py:76`).

4. **Hybrid Lexical-Dense Retrieval Fusion (`Bruch et al., ACM TOIS 2023/2024` vs. `Cormack et al., SIGIR 2009`):**
   - By `Bruch et al.` `Lemma 4.2`, empirical min-max (`M2C2`), theoretical min-max (`TM2C2`), and `Z-Score` convex combinations are **strictly rank-equivalent on any single query** (`M2C2(0.72) == Z(0.7200) == TM2C2(0.9476)` on $N = 50$ candidates in `Probe 4`), yet diverge across multi-query workloads under one fixed global $\alpha$ (`Theorem 4.5`; validation-tuned $\alpha = 0.80$ in `§4.2` / `Table 2`, $\alpha \in [0.6, 0.8]$ in `§7`).
   - Substituting theoretical infima (`0` for BM25, `-1` for cosine) in `TM2C2` ($\frac{s - s_{\inf}}{M_q - s_{\inf}}$, Eq. 4) eliminates **narrow-band lower-bound noise amplification** ($m_q \approx M_q > s_{\inf}$, where `M2C2` and `Z-Score` drop from `1.000` to `0.631` `NDCG@10` in `Probe 4`), **not** upper-outlier $M_q$ compression: because both `M2C2` and `TM2C2` divide by empirical $M_q$, a generated mock file with 90 identifier hits ($M_q = 65 \gg s_{\text{gold}} = 11$) crushes runner-up lexical scores in *both* convex normalizers (`TM2C2 = 0.631` vs. rank-based `RRF(60) = 1.000`), whereas on genuine rare-identifier definitions `RRF(60)` discards `~7x` BM25 margins (`0.631` vs. `TM2C2 = 1.000`) and exhibits **`5,949.2x`** steeper local sensitivity under $2 \times 10^{-7}$ tie perturbations (`§5.2`).

5. **Git Merkle-Tree Incremental Invalidation and Dirty-Worktree Tombstone Overlays:**
   - On `Probe 5`'s real `1,024`-file Git repository (`145` trees), a 1-file commit advance (`git diff-tree -r`) prunes unchanged subtrees by 20-byte SHA-1 equality, visiting **`3 / 145` trees (`2.07%`)**, **`32 / 1,168` tree entries (`2.74%`)**, and **`8 / 1,024` blob entries (`0.78%`)** to re-index **`1 / 1,024` blobs (`99.90%` cache reuse)**. Default `zoekt-git-index` (`--incremental=true`, `--delta=false`, `IsDelta = false`, `index/builder.go:433`) returns `IndexStateContent` and rebuilds **`1,024 / 1,024`** files into new shards (while opt-in `--delta` falls back on submodules, `.gitignore` or branch-set changes, shard-count ceilings, or multi-repo shards), hard-fails above **`64` branches** (`shard_builder.go:422`), and never indexes uncommitted edits—resolved by a two-layer `(committed blob-SHA store + git status --porcelain -z -uall tombstone/dirty overlay)` (`0` stale hits, `2 / 2` dirty recall).

## Findings

### 1. Positional Trigram Regex Lowering and `Zoekt` Internals

`Basis: documentation + source + execution`

#### 1.1 Russ Cox's Five-Attribute Compiler vs. `Zoekt` `eval.go`

Given regular expression $e$, Cox (`2012`) computes `(emptyable(e), exact(e), prefix(e), suffix(e), match(e))` bottom-up so that $\text{match}(e)$ is a sound boolean trigram filter ($\mathcal{L}(e) \subseteq \text{Docs}(\text{match}(e))$, zero false negatives). Two invariants separate full cross-boundary trigram compilation from `sourcegraph/zoekt@b55ce727` (`index/eval.go:621–698`):

1. **Cross-Boundary Concatenation Products:** For concatenation $e_1 e_2$, Cox sets $\text{match}(e_1 e_2) = \text{match}(e_1) \land \text{match}(e_2) \land \text{trigrams}(\text{suffix}(e_1) \times \text{prefix}(e_2))$. Even when $e_1 = \texttt{(se|ld)}$ has 2-rune arms with $\text{match}(e_1) = \texttt{ANY}$, multiplying $\text{suffix}(e_1) = \{\texttt{"se"}, \texttt{"ld"}\}$ by $\text{prefix}(\texttt{Config}) = \{\texttt{"Config"}\}$ yields `("seC" AND "eCo" ...) OR ("ldC" AND "dCo" ...)`. On `Probe 1`'s 240-document synthetic repository (`51` `*Config` files), Cox narrows `(se|ld)Config` to the exact **`4 / 240` (`1.67%`)** matching files (and `(pa|bu)Config` to **`0 / 240`**), whereas `Zoekt`'s `regexpToMatchTreeRecursive` (`index/eval.go:651–685`) drops `bruteForceMatchTree` children inside `OpConcat` (`L671–673`) without suffix-prefix products, scanning **`51 / 240` (`21.25%`, `12.75x` more files)**.
2. **Information-Saving Reductions and `<3`-Rune Fallbacks:** Whenever `exact`, `prefix`, or `suffix` exceeds `max_set`, Cox pushes $\text{trigrams}(S)$ into `match(e)` *before* trimming affixes or clearing `exact = unknown`. On small bounded repetitions (`max_set = 8`), `[01]{3}` and `(ab|cd){2}` compile in Cox to exact **`8`-arm** and **`4`-arm** trigram disjunctions, whereas `Zoekt`'s `OpRepeat` (`index/eval.go:639–650`) recurses solely on `r.Sub[0]` (`r.Min >= 1`), collapsing both `[01]{3}` (`OpCharClass`) and `(ab|cd){2}` (`<3`-rune `OpAlternate`) to `bruteForceMatchTree` (`ANY`). (Large character classes such as `[0-9a-f]{8}` with $|[\texttt{0-9a-f}]| = 16 > \text{max\_set} = 8$ exceed `max_set` on a single character and collapse to `ANY` in Cox as well unless `max_set >= 16`.) Top-level `<3`-rune content or filename `Substring` queries (`"id"`, `index/matchtree.go:1334–1341`) and alternations with any `<3`-rune branch (`(parseConfig|id)`, `index/eval.go:687–690`) collapse to `bruteForceMatchTree` (**`240 / 240 = 100.0%`** shard scan in `Probe 1`), while `<3`-rune `Symbol` substring queries (`query.Symbol{Expr: Substring}`, `index/matchtree.go:1205–1212`) convert to `newSymbolRegexpMatchTree`, scanning every document's ctags symbol table rather than trigram postings. In addition, `Zoekt` skips indexing files with `< 3` bytes (`SkipReasonTooSmall`, `index/shard_builder.go:706–708`) or `> TrigramMax = 20,000` distinct trigrams (`shard_builder.go:736–738`, `index/builder.go:332–334`).

#### 1.2 UTF-8 Rune Offset Elision, `SimpleFold` $3^3 = 27$ / $4^3 = 64$ Fan-Out, and `scoreFileBM25` Distortions

- **63-Bit Rune Packing and Sparse Offset Interpolation (`index/bits.go:171–192, 467–512`):** `runesToNGram` packs `[3]rune` as `uint64(b[0])<<42 | uint64(b[1])<<21 | uint64(b[2])`, storing delta-varint corpus rune offsets (`shard_builder.go:208, 232–241`). `makeRuneOffsetMap` samples byte offsets every `runeOffsetFrequency = 100` runes (`shard_builder.go:193–195`) and omits entries where `byteOffset == expected` (`bits.go:471–475`), consuming **`0` bytes** (`0` entries) on `Probe 1`'s 2,500-rune ASCII file and **`192` bytes** (`24` corrections $\times$ `8` bytes at `bits.go:510–512`, `0` byte-recovery errors) across 2,500 multi-byte UTF-8 runes.
- **Two-Anchor Selective Distance Intersection (`index/indexdata.go:357–503`, `index/hititer.go:51–93`):** For an $L$-rune substring, `iterateNgrams` reads posting-list byte lengths (`ngrams.Get(v).sz`), short-circuits immediately on `freq == 0` (`L461`), separates overlapping anchors (`last.index - first.index < 3`, `L362–372`), and leapfrog-intersects only the **two rarest trigrams** via `distanceHitIterator` (`p1 + distance == p2`, `hititer.go:61–67`).
- **`SimpleFold` Posting Explosion vs. ASCII-Only `LowerRegexp` (`index/bits.go:27–48`, `query/regexp.go:26–46`):** Case-insensitive substring queries expand trigrams at query time over `unicode.SimpleFold` cycles. ASCII `"foo"` expands to $2^3 = \mathbf{8}$ trigrams, 3-element Latin/Kelvin orbits (`'k'/'K'/'K'` [`U+212A`], `'s'/'S'/'ſ'` [`U+017F`]) expand `"ksk"` to **$3^3 = \mathbf{27}$ posting lookups (`3.375x`)**, and 4-element Greek iota/prosgegrammeni `[U+0345, U+0399, U+03B9, U+1FBE]` (alongside theta `[U+0398, U+03B8, U+03D1, U+03F4]` and Cyrillic `[U+0422, U+0442, U+1C84, U+1C85]`) expands `"ιιι"` to **$4^3 = \mathbf{64}$ lookups (`8x` ASCII)**—whereas `query.LowerRegexp` folds only ASCII `'A'..'Z'`, mapping `'KSK'` to `'KsK'` (`Probe 1`).
- **Dual Scoring Distortions in `scoreFileBM25` (`index/score.go:263–282, 391–425`):** `Zoekt`'s experimental BM25 scorer ($k = 1.2, b = 0.75$) diverges from corpus-level Okapi BM25 in two ways:
  1. *Constant-IDF Omission (`L280–282, 391–394`):* `sumTFScores` explicitly treats IDF as constant `1.0`, summing $\frac{(k+1)f}{k(1 - b + bL) + f}$ unweighted across query terms. On `"err parseZigbeeFrame"` across 240 equal-length files in `Probe 1`, a file with `12` hits of ubiquitous `err` (`df = 240/240`) and `0` hits of `parseZigbeeFrame` scores **`2.0000`**, outranking the sole file defining `parseZigbeeFrame` (`tf = 1`, score **`1.0000`**)—inverting Robertson–Walker IDF BM25 (**`0.0042` vs. `5.0793`**).
  2. *Shard-Local `averageFileLength` Drift (`L405–408`):* When `BM25AverageFileLength <= 0`, `averageFileLength` defaults to `float64(d.boundaries[d.numDocs()]) / float64(d.numDocs())` within each shard. In `Probe 1`, the identical 1,200-byte file scores **`0.5519`** in a small-config shard (`mean = 402.0` B) vs. **`1.5827`** in a large-proto shard (`mean = 11,999.6` B)—a **`2.868x` score shift** at `tf = 1` (**`1.766x`** at `tf = 3`).

### 2. Compiler Cross-Reference Protocols: `SCIP` vs. `LSIF v0.5.0` / `v0.6.0`

`Basis: normative + documentation + source + execution`

1. **Context-Free Symbol Descriptors vs. Monotonic Graph IDs (`sourcegraph/scip@8fe50375` vs. `microsoft/language-server-protocol@6714b477`):**
   - Normative `LSIF v0.5.0` (`_specifications/lsif/0.5.0/specification.md`) emits each occurrence as a `range` vertex + `next` edge (`range -> resultSet`) + `item` edge (`definitionResult`/`referenceResult -> [range]` carrying `shard: docId`, renamed from `0.4.x`'s `document` at `L28, 261, 372`), alongside `resultSet`, `definitionResult`, `referenceResult`, `hoverResult`, `moniker`, and `contains` edges (`0.6.0` further replaces `Group` with `Source` and `textDocument/semanticTokens/full`, `0.6.0/specification.md:22–24`). Across `Probe 2`'s 20-document, 100-symbol, 1,200-occurrence workspace, `LSIF v0.5.0` emits **`4,643` JSON-Lines objects (`1,722` vertices + `2,921` edges, `426,200` B raw / `36,454` B gzip)** and couples cross-file emission through monotonic vertex IDs.
   - `SCIP` (`scip.proto:26–54, 76–120, 157–176`) replaces graph edges with context-free UTF-8 symbol descriptors (`<scheme> <manager> <pkg> <ver> (<descriptor>)+` or `'local ' <id>`), encoding `Index.metadata = 1` (`Metadata` fields `1..4`, with `text_document_encoding = UTF8` at field `4`, `scip.proto:53`) followed by `repeated Document documents = 2` (each carrying `Document.position_encoding` at field `6`, `scip.proto:118`). Because Protobuf wire-encodes repeated `Document` fields as concatenated `<0x12><varint len><Document bytes>`, `IndexVisitor.ParseStreaming` (`bindings/go/scip/parse.go:29–122`) streams arbitrarily large indexes in **`O(max |D_i|) = 5,642` bytes** (`112,943` B raw [**`3.77x` smaller**] and `5,060` B gzip [**`7.20x` smaller**] in `Probe 2`, consistent with Sourcegraph's production `~5x` raw / `4x` gzip across `over 45k` repositories and `more than 4k` daily LSIF uploads, `scip`'s `LSIF v0.4.3` converter, and Don Stewart's Meta `Glean` benchmark of `8x` smaller disk footprint, `3x` faster ingestion, and `~550` vs. `1,500` LOC; `Geirsson 2022`).
   - Inside uncompressed SCIP `Document` messages, inline `Occurrence.symbol` strings (`scip.proto:725`) represent **`78.6%`** of raw bytes on long monorepo package paths in `Probe 2` (eliminated by `gzip`/`zstd` LZ77 back-references), while packed 3-varint `range = 1` saves **`8.7%`** over nested LSP `Range` messages (`50%` on short/local-symbol corpora per `scip.proto:704`) and typed `SingleLineRange = 8` (`L717–722`) adds **`+3.19%`**.
2. **Cross-Language `PositionEncoding` Slicing Trap (`scip.proto:118–146`):**

### 4. Hybrid Lexical-Dense Retrieval Fusion: `TM2C2` vs. `M2C2`, `Z-Score`, and `RRF`

`Basis: documentation + derived + execution`

1. **Single-Query Affine Rank-Equivalence (`Lemma 4.2`) vs. Fixed-$\alpha$ Collection Drift (`Theorem 4.5`):**
   - In `Bruch, Gai, & Ingber (ACM TOIS, Vol. 42, Issue 1, Article 20, pp. 20:1–20:35, online 2023 / print 2024)`, `M2C2` ($\phi_{\text{mm}}(s) = \frac{s - m_q}{M_q - m_q}$), `TM2C2` ($\phi_{\text{tmm}}(s) = \frac{s - s_{\inf}}{M_q - s_{\inf}}$ with $\inf \text{BM25} = 0, \inf \cos = -1$, Eq. 4), and `Z-Score` ($\phi_z(s) = \frac{s - \mu_q}{\sigma_q}$, Eq. 5) are positive affine maps on any fixed query $q$. Reparameterizing $\alpha$ therefore induces identical document rankings (`Probe 4` verifies **`0` pairwise rank inversions** across $N = 50$ candidates at `M2C2(0.72) == Z(0.7200) == TM2C2(0.9476)`). Across an entire query distribution under **one fixed global $\alpha$** (`Theorem 4.5`), equivalence breaks whenever relative score dispersion $\lambda_q$ varies across query classes. Across all **`9 / 9`** text retrieval datasets in `Bruch et al.` `Table 2` (`3` in-domain: `MS MARCO`, `NQ`, `Quora`; `6` zero-shot BEIR: `NFCorpus`, `HotpotQA`, `FEVER`, `SciFact`, `DBPedia`, `FiQA`), validation-tuned `TM2C2` (`α = 0.8` in `§4.2` / `Table 2`; domain-knowledge interval `α ∈ [0.6, 0.8]` in `§7`) outperforms `RRF`. Meanwhile, in `Cormack, Clarke, & Büttcher (SIGIR 2009, pp. 758–759)`, `CombMNZ` edged `RRF(k = 60)` in mean average precision on `LETOR 3` (`583,850` pairs, `Table 3`: `CombMNZ = 0.6107` vs. `RRF = 0.6051`, difference **`-0.0056`**, $p \approx 0.2$; `Condorcet = 0.5917`, $p = 0.004$) and on `TREC 3` (`0.4381` vs. `0.4350`, `Table 2`), while `RRF` beat `CombMNZ` on `6 / 7` TREC collections (sign test $p \approx 0.04$) when component score scales were uncalibrated.
2. **Three-Regime Breakdown Across Code Queries (`[illustrative analytical model]`, `Basis: derived`, `Probe 4`):**
   - Evaluating fixed global $\alpha = 0.80$ (`Bruch et al.` `§4.2` / `Table 2` setting) against `RRF(k = 60)` across `3 × 16 = 48` deterministic synthetic code queries (`N = 20` candidates) separates three distinct failure modes:
     - *Regime A — Genuine Rare-Identifier Definitions (`BM25 = 38..44` vs. runner-up `5.4`):* `TM2C2`, `M2C2`, and `Z-Score` preserve the `~7x` lexical margin (**`NDCG@10 = 1.000`**), whereas `RRF(60)` discards score magnitude (`1/64 + 1/61 < 1/61 + 1/62`, dropping to **`0.631`**) and exhibits a **`5,949.2x`** steeper local step sensitivity than Lipschitz-continuous `TM2C2` (`Bruch et al. §5.2`) under a $2 \times 10^{-7}$ cosine tie perturbation.
     - *Regime B — Conceptual Natural-Language Queries with Narrow Positive Stopword Bands ($f_{\text{Lex}} \in [4.00, 4.06]$):* `M2C2` ($R_{\text{Lex}} = 0.06$) and `Z-Score` ($\sigma_{\text{Lex}} \to 0$) stretch `0.06` of stopword BM25 jitter across `[0, 1]` / `[-1.5, +2.6]`, overriding the gold snippet's cosine lead (**`NDCG@10 = 0.631`**), whereas `TM2C2` anchors the lower bound at $s_{\inf} = 0$, compressing `[4.00, 4.06]` into `[0.985, 1.000]` (**`NDCG@10 = 1.000`**).
     - *Regime C — Spurious Boilerplate/Mock Upper Outliers ($M_q = 65.0 \gg s_{\text{gold}} = 11.0$):* Because **both** `M2C2` and `TM2C2` divide by empirical maximum $M_q$, an auto-generated mock repeating a symbol 90 times compresses the legitimate `#2` lexical match to $11 / 65 = 0.169$ (**`TM2C2 = 0.631`**), whereas rank-based `RRF(60)` ignores $M_q$'s spike (**`RRF = 1.000`**). Overall `TM2C2` leads (`0.877` vs. `RRF = 0.754`, `M2C2 = 0.754`); pairing `TM2C2` with path/AST down-weighting of generated/vendor files or upper-tail winsorization prevents $M_q$ hijacking without sacrificing rare-symbol margins.

### 5. Incremental Git Merkle-Tree Invalidation and Dirty-Worktree Overlay

`Basis: source + execution`

1. **$O(d \cdot b)$ Merkle Subtree Pruning vs. Default `Zoekt` Whole-Shard Rebuild (`Probe 5`):**
   - Git hashes blobs as `sha1("blob <len>\0" || content)` and trees as `sha1("tree <len>\0" || sorted_entries)` (sorting directory entries as if suffixed with `'/'` per Git `base.c:df_name_compare`). On `Probe 5`'s real `1,024`-file Git repository (`16` package dirs $\times$ `8` subdirs $\times$ `8` `.go` files = `145` tree objects, `1,168` total tree entries), stdlib Merkle hashing matches `git rev-parse` bit-for-bit (`C1 = 607639f13c62`, `C2 = 59b66c2587af`).
   - Advancing `main` by a 1-file edit (`C1 -> C2`) skips all `15 / 16` unchanged top-level packages and `7 / 8` unchanged sibling directories by 20-byte tree-SHA equality: Merkle tree diffing (`git diff-tree -r`) visits **`3 / 145` trees (`2.07%`)**, **`32 / 1,168` tree entries (`2.74%`)**, and **`8 / 1,024` blob entries (`0.78%`)**, re-indexing **`1 / 1,024` blobs (`99.90%` cache reuse)**.
   - By contrast, in `sourcegraph/zoekt@b55ce727`, `Options.IndexState` (`index/builder.go:433–435`) returns **`'IndexStateContent'`** whenever `!reflect.DeepEqual(repo.Branches, o.RepositoryDescription.Branches)`. In **default `zoekt-git-index` (`--incremental=true`, `--delta=false`, `IsDelta = false`, `cmd/zoekt-git-index/main.go:44, 48`)**, `IndexStateContent` dispatches `prepareNormalBuild` (`gitindex/index.go:632–636`), rebuilding all **`1,024 / 1,024`** files into fresh `.zoekt` shards. Although `zoekt@b55ce727` also provides an opt-in experimental `--delta` mode (`IsDelta = true`, `gitindex/index.go:624–630, 951–1135`, `index/builder.go:702–765`) that calls `object.DiffTreeWithOptions` (`gitindex/index.go:1054`), writes delta shards for changed/added blobs (plus surviving versions on other branches, `L1102–1125`), and rewrites `.meta` JSON `FileTombstones` across prior shards (`builder.go:724–765`), `--delta` still falls back to a full shard rebuild whenever submodules are enabled (`L952`), `.gitignore` changes (`L1071, 1098`), the branch set changes (`L985`), shard count hits `DeltaShardNumberFallbackThreshold` (`L976`), or compound multi-repository shards (`len(repositories) > 1`, `builder.go:711`) are present—and `ShardBuilder` (`index/shard_builder.go:422–424`) hard-rejects `> 64` branches (**`'too many branches'`** at `65` branches due to `uint64` `branchMasks`).
2. **Two-Layer Committed Blob-SHA Base + Dirty Worktree Tombstone/Overlay Index:**
   - Neither `git diff-tree HEAD` nor `zoekt-git-index` (with or without `--delta`) indexes uncommitted worktree edits, untracked files, or unstaged deletions. Pairing (a) an immutable content-addressed `blob_sha -> (trigrams, cAST chunks, embeddings)` index for `HEAD` with (b) a live delta built from `git status --porcelain -z -uall` (`tombstones` masking modified/deleted paths + `dirty_overlay` indexing live worktree files) yields **`0` stale hits** on deleted/overwritten symbols and **`2 / 2` (`100%`) recall** on modified and untracked files in `Probe 5` without mutating committed index artifacts.
