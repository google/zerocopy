# Lean 4 Kernel Soundness Criticisms, Algorithmic `isDefEq` Pathologies, TCB Bypass Vectors, and External Checkers

## Summary

Lean 4 isolates logical validity inside a 7,464-line C++17 typechecker (`src/kernel/` across 23 `.cpp`/`.h` files in `leanprover/lean4`) intended to verify terms generated by an untrusted ~300+ KLoC Lean elaborator and metaprogramming frontend. However, primary-source inspection across `leanprover/lean4`, Mario Carneiro's formalization in `digama0/lean4lean`, and 2025–2026 kernel vulnerability disclosures shows four structural trust tensions that differentiate Lean 4 from smaller LCF or syntactic kernels:

1. **Undecidable ideal theory vs. non-transitive algorithmic `is_def_eq_core`**: Because Lean's type theory includes impredicative `Prop` with definitional proof irrelevance (`t-proof-irrel`), typing (`Γ ⊢ e : α`) and definitional equality (`Γ ⊢ e₁ ≡ e₂ : α`) are mutually inductive rather than stratified. Adding `Quot.lift` computation, `Nat`/GMP literal extensions, K-like singleton elimination, and structure/unit-like η makes ideal definitional equality undecidable and breaks syntactic strong normalization for open terms, forcing consistency proofs into set-theoretic models (`ZFC + n < ω` inaccessible cardinals). To preserve practical termination, the C++ kernel's algorithmic `is_def_eq_core` restricts η-expansion and unit-like contraction to top-level syntactic shapes (`try_eta_expansion`, `try_eta_struct`, `is_def_eq_unit_like`), making algorithmic definitional equality **provably non-transitive** (witnessed by issues `#2258` and `#12520`) and leaving unique typing (`IsDefEq.uniq`) and ∀-injectivity (`IsDefEqU.forallE_inv`) downgraded from proven theorems to open conjectures in `Lean4Lean` (`arXiv:2403.14064v3`).
2. **Complexity creep from Lean 3 to Lean 4**: Whereas Lean 3's kernel recorded zero soundness bugs across its release history by reducing nested/mutual inductives and projections in the elaborator, Lean 4 moved bignum `Nat` reductions, primitive `Expr.proj`, and nested/mutual inductive elimination into C++ for speed. This expansion produced concrete kernel soundness failures, culminating in `CVE-2026-72844` (`leanprover/lean4#14576`, July–October 2026)—the first CVE assigned to a proof assistant kernel soundness bug—where an AI-assisted formalization attempt (`CollatzLean`) exploited unchecked nested-inductive parametric arguments and unvalidated `Expr.proj` structure names alongside `Expr.hash` collision padding to prove `False` and `0 = 1` with `--trust=0` and zero reported axioms, followed days later by `#14613` (`Sort (imax 1 0)` failing syntactic `Prop` recognition).
3. **TCB expansion and `#print axioms` blind spots**: Compiler-facing mechanisms (`@[implemented_by]`, `@[extern]`, `@[csimp]`, and `native_decide`) pull the full compiler, IR optimizer, C backend, and native toolchain into the trusted computing base when invoked in verification paths. Under `leanprover/lean4#7463`, unsound axioms or `unsafe` self-recursion inside `@[csimp]` lemmas were not propagated by `native_decide` into `#print axioms` (`[Lean.ofReduceBool]`), while post-2025 `Lean.Meta.Native.nativeEqTrue` shifts `native_decide` to direct `Declaration.axiomDecl` emission via `unsafe evalConst`. Additionally, `.olean` deserialization via `mmap` compacted regions (`src/runtime/compact.cpp`) and C++17/GMP manual reference counting leave the host process exposed to memory corruption outside `--fresh` rechecking.
4. **Layered defense via external checkers**: No single re-checker closes every vector alone: `lean4checker` (`leanchecker` built into Lean ≥ v4.28.0) detects metaprogramming `Environment` bypasses (`addDecl` skipping) but shares C++ kernel bugs; `Lean4Lean` provides a verified-in-progress Lean-in-Lean kernel (~1.32x C++ runtime on Mathlib) that caught `#10475` (`infer_let` loose `fvar` bug) and `hasLooseBVars` bugs; `lean4export` (NDJSON v3.1.0) + `ammkrn/nanoda_lib` (Rust, multi-threaded, strict axiom allowlist) provides genuine implementation-language independence; and `SafeVerify` / `Comparator` close specification-tampering and attribute-smuggling gaps in untrusted AI-agent evaluation pipelines.

## Findings

### 1. Metatheoretic Foundations and Why Lean's Typing Judgment Defies Simple Stratification

Basis: normative (`digama0/lean-type-theory`, Carneiro `arXiv:2403.14064v3`) + source (`Lean4Lean/Theory/Typing/Basic.lean`).

Lean implements an intensional Calculus of Inductive Constructions (CIC) extended with universe polymorphism (`u` levels), an impredicative `Prop` (`Sort 0`, denoted `U_0`) with **definitional proof irrelevance**, quotient types (`Quot`, `Quot.mk`, `Quot.lift`, `Quot.ind`, `Quot.sound`), inductive types via generated recursors (`Dybjer` style rather than Rocq's primitive `fix`/`match` guard checker), primitive structure projections (`Expr.proj`), and η-rules for functions, structures, and unit-like types.

In `Lean4Lean/Theory/Typing/Basic.lean` (`VEnv.IsDefEq`, formalized as $\Gamma \vdash_{E,n} e \equiv e' : \alpha$ with $\Gamma \vdash e : \alpha \triangleq \Gamma \vdash e \equiv e : \alpha$), typing and conversion cannot be separated into an untyped conversion judgment followed by typing (as MetaRocq does for PCUIC). The obstruction is **`t-proof-irrel`**:

```text
Γ ⊢ p : U_0    Γ ⊢ h : p    Γ ⊢ h' : p
───────────────────────────────────────  (t-proof-irrel)
         Γ ⊢ h ≡ h' : p
```

Because `t-proof-irrel` only equates `h` and `h'` when both inhabit a `p : Sort 0`, definitional equality depends on typing `h` and `h'` and verifying their type lives in `Prop`. This mutual recursion triggers three deep metatheoretic consequences:

1. **Undecidability of ideal conversion and universe constraints**: Because `Quot.lift f h (Quot.mk r a) ≡ f a` reduces regardless of whether `h` is a canonical constructor proof—paired with proof irrelevance equating arbitrary proofs of `p : Prop` and impredicativity—ideal definitional equality and typechecking are undecidable (`Carneiro 2019`), and strong normalization fails on open or ill-typed terms (`Abel & Coquand, LMCS 2020`, `DOI: 10.23638/LMCS-16(2:14)2020`). Consistency cannot be proved via syntactic strong normalization; Carneiro establishes relative consistency via a set-theoretic ZFC model requiring $n$ inaccessible cardinals for $n < \omega$ nested universes.
2. **Co-NP-complete `imax` universe algebra**: Universe level expressions (`VLevel ::= zero | succ l | max l₁ l₂ | imax l₁ l₂ | param i`) have semantics $\llbracket \text{imax } a\ b \rrbracket_v = 0$ if $\llbracket b \rrbracket_v = 0$, else $\max(\llbracket a \rrbracket_v, \llbracket b \rrbracket_v)$, used by `t-all` ($\Pi x:\alpha.\beta : U_{\text{imax}(\ell_1, \ell_2)}$) so propositions quantified over large types stay in `Prop`. Deciding universal validity $\forall v,\, \llbracket \ell_1 \rrbracket_v \le \llbracket \ell_2 \rrbracket_v$ is co-NP-complete because `imax` introduces conditional zero-collapsing discontinuities that encode Boolean conjunctions over parameter-zero case splits (verified in Probe 1). Lean 4's C++ `kernel/level.cpp` uses incomplete heuristic normalization, whereas `Lean4Lean/Level.lean` (`NormLevel.le`, lines 163–175) implements a complete sublevel decomposition checking `C(E, L)` and `V(E, x, L)` dominators across condition sets `E ⊆ params`, accepting strictly more valid universe inequalities than C++.
3. **Downgraded structural metatheory (`arXiv:2403.14064v3`, Section 2.4)**: In Carneiro's 2019 Master's thesis, unique typing (`IsDefEq.uniq`: $\Gamma \vdash e : \alpha \land \Gamma \vdash e : \beta \implies \Gamma \vdash \alpha \equiv \beta : U_\ell$) and definitional inversion (`IsDefEqU.sort_inv`, `forallE_inv`) were proved via a height-stratified judgment $\vdash_i$ intended to break the mutual induction between typing and conversion. During formalization in `Lean4Lean`, Carneiro discovered a flaw in that proof: stratification does not preserve indices under substitution—given $\Gamma, x:\beta \vdash_i e : \alpha$ and $\Gamma \vdash_j e' : \beta$, substitution yields $\Gamma \vdash_{i+j} e[x \mapsto e'] : \alpha$ rather than $\max(i,j)$. Consequently, **Conjectures 2.7 (Unique Typing), 2.9 (Definitional Inversion), and 2.10 (Strengthening)** remain **unproven conjectures** in `Lean4Lean` (`arXiv:2403.14064v3`), though relative soundness in ZFC is unaffected.

### 2. Algorithmic `is_def_eq_core` Architecture, Non-Transitivity Witnesses, and `EquivManager` Divergence

Basis: source (`src/kernel/type_checker.cpp`, `type_checker.h`, `Lean4Lean/TypeChecker.lean`, `Lean4Lean/EquivManager.lean`, `Lean4Lean/divergences.md`) + execution (Probe 1).

Lean 4's C++ kernel decides conversion via `type_checker::is_def_eq_core` (`src/kernel/type_checker.cpp:1139–1214`) in ten ordered phases:

| Phase | C++ Implementation (`type_checker.cpp`) | Action / Early Return Condition | Transitivity / Completeness Hazard |
| :--- | :--- | :--- | :--- |
| 1 | `quick_is_def_eq` (lines 783–811, 1143) | Syntactic/pointer equality, `m_success` cache, structural `Lambda`/`Pi`/`Sort`/`Lit`/`MData` descent | `Lambda`/`Pi` immediately returns `l_false` (`DefDiff`) if binder domains or bodies fail syntactic/recursive checks |
| 2 | `eagerReduce` `Bool.true` shortcut (lines 1149–1153) | If `!has_fvar(t) \|\| m_eager_reduce` and `s == Bool.true`, runs `whnf(t)` | Asymmetric in `(t, s)` at entry; symmetric cases fall through to delta reduction |
| 3 | `is_def_eq_proof_irrel` (lines 906–913, 1156) | Checks `is_prop(infer_type(t))` and `is_def_eq(t_type, s_type)` | Prior to `#14613`, `is_prop` missed `Sort (imax 1 0)` |
| 4 | `whnf_core(·, cheap_rec=false, cheap_proj=true)` (lines 456–539, 1166) | Strips `MData`, beta/zeta/iota/quot reductions without unfolding `delta` defs or `whnf`-reducing projections | Avoids unfolding `instFoo.1` prematurely |
| 5 | `lazy_delta_reduction` (lines 1062–1082, 1173) | `is_def_eq_offset` (`Nat.succ`), `reduce_nat` (GMP), and height-ordered `lazy_delta_reduction_step` (`is_def_eq_args` shortcut at line 1011) | Returns `l_false` (`DefDiff`) immediately if `quick_is_def_eq` fails after delta step, skipping Phases 8–10! |
| 6 | Atomic `Const`/`FVar` & `lazy_delta_proj_reduction` (lines 1091–1108, 1177–1191) | Checks `const_name`/`levels`, `fvar_name`, or `Proj` struct/index unfolding | Pre-`#14631` `Lean4Lean` skipped `proj_sname` check; C++ keeps it redundantly |
| 7 | Full `whnf_core` (`cheap_proj=false`, lines 1194–1197) | Reduces stuck projections via `whnf`, recurses to `is_def_eq_core` if changed | Can re-enter Phases 1–6 |
| 8 | `is_def_eq_app` (lines 885–902, 1200) | Decomposes `f a₁...aₙ =?= g b₁...bₙ`, checks `is_def_eq(f, g)` and pairwise `is_def_eq(aᵢ, bᵢ)` | Fails when heads differ structurally (e.g., `Eq.rec ...` vs `a`) even if η-equivalent |
| 9 | `try_eta_expansion` & `try_eta_struct` (lines 830–880, 1203–1206) | η-expands `s` ONLY if `t` is manifest `Lambda`; expands `t` to `Ctor` fields ONLY if `s` has `Ctor` head of non-recursive 1-ctor structure | **Root cause of `#2258` and `#12520` non-transitivity**: never fires when *neither* side is a manifest `Lambda`/`Ctor` |
| 10 | `try_string_lit_expansion` & `is_def_eq_unit_like` (lines 1113–1137, 1209–1211) | Expands UTF-8 string literals to `List Char`; equates inhabitants of 0-field non-recursive structures | Fires ONLY at the top-level type, not through function domains or 1-field wrappers (`Foo { foo : Unit }`) |

#### Concrete Non-Transitivity and Cache Divergence
Because Phases 9 and 10 require syntactic witnesses on at least one side (`Lambda`, `Ctor`, or direct 0-field type), `is_def_eq_core` violates transitivity in three clean patterns reproduced by Probe 1:
- **Unit-like function and wrapper non-transitivity (`leanprover/lean4#2258`)**: For `p q : α → Unit`, `is_def_eq(p, fun _ => ())` succeeds (Phase 9 η-expands `p` -> `is_def_eq_unit_like(p x, ())`) and `is_def_eq(fun _ => (), q)` succeeds symmetrically, yet `is_def_eq(p, q)` returns `False` because neither side is a `Lambda` and `α → Unit` is not a structure. Identical failures hold for `structure Foo where foo : Unit` (`pf =?= Foo.mk ()` and `Foo.mk () =?= qf` hold, `pf =?= qf` fails) and `structure Bar : Type where bar : True` (`pb =?= Bar.mk True.intro` via proof irrelevance, yet `pb =?= qb` fails).
- **Partially applied recursor non-transitivity (`leanprover/lean4#12520`, open P-low)**: Given `a : true = true → Bool`, `A := @Eq.rec Bool true (fun _ _ => Bool) (a (Eq.refl true)) _` satisfies `A ≡ fun h => a h` (Phase 9 expands `A` under `Lambda`, then `Eq.rec` iota-reduces and `is_def_eq_proof_irrel` equates `Eq.refl true` and `h`) and `(fun h => a h) ≡ a`, yet `A ≡ a` returns `False` because neither `Eq.rec ...` nor `a` is a manifest `Lambda`.
- **Caching architecture hazard (`type_checker.h:31–38` vs `Lean4Lean/EquivManager.lean`)**: `type_checker.h` explicitly documents why the C++ kernel stores positive and negative results in plain unordered pair sets (`m_success`, `m_failure`) rather than union-find: *"taking a transitive closure of successful pairs would make its result depend on evaluation order."* By contrast, `Lean4Lean/TypeChecker.lean:183–187` calls `eqvManager.addEquiv t s` (a `Batteries.UnionFind` over expressions), making `Lean4Lean`'s conversion acceptance order-sensitive across queries—an intentional divergence trade-off for performance that can accept slightly more terms when intermediate bridges were previously cached.
- **Universe-parameterized projection divergence (`Lean4Lean/divergences.md`)**: For `MaybeProp.{u} : Sort u` with a `PUnit.{u}` field, `Lean4Lean` checks `isNeverZero(u)` (`false` for `Param u`) in `inferProj` and `toCtorWhenStruct`, matching the small-elimination-only recursor generated by `inductive.cpp`. Lean 4's C++ kernel checks `!isAlwaysZero(u)` (`true` for `Param u`), permitting `Expr.proj` even though the recursor cannot perform large elimination—a choice that remains sound in C++ only because `inductive.cpp` independently enforces constructor universe bounds (`inductive T.{u} : Sort u where mk : Bool → T` is rejected).

### 3. Taxonomy of Historical and 2025–2026 Lean 4 Kernel Soundness Bugs

Basis: source (`src/kernel/inductive.cpp`, `type_checker.cpp`, `environment.cpp`, `Lean4Lean/bugs-found.md`, `divergences.md`) + documentation (`CVE-2026-72844`, `oss-security`, GitHub issues `#10475`, `#14576`, `#14577`, `#14613`).

Lean 3's C++ kernel had zero reported soundness bugs during its lifetime because `Expr.proj` and nested/mutual inductive elimination were elaborated into primitive single inductives outside the kernel. Lean 4 moved these mechanisms into C++ (`inductive.cpp` 1,407 LoC, `type_checker.cpp` 1,303 LoC) for elaboration and kernel checking speed, creating an attack surface repeatedly exposed in 2025–2026 by formalization (`Lean4Lean`) and AI-assisted theorem proving:

This demonstrates that **multi-checker redundancy must be paired with adversarial fuzzing (`lean-kernel-arena`) and formal verification (`Lean4Lean`)**.

### 4. TCB-Bypassing Axioms, Compiler Attributes, and C++17 / GMP / `.olean` Memory-Safety Surface

Basis: source (`src/Lean/Meta/Native.lean`, `src/Lean/Compiler/CSimpAttr.lean`, `ImplementedByAttr.lean`, `ExternAttr.lean`, `src/runtime/compact.cpp`, `src/kernel/CMakeLists.txt`, `src/kernel/type_checker.cpp`) + documentation (GitHub issue `#7463`).

Even when the core C++ kernel rules are sound, Lean 4 exposes four major paths that expand the Trusted Computing Base beyond the 7.5 KLoC kernel:

1. **`native_decide` (`Lean.ofReduceBool` -> `Lean.Meta.Native.nativeEqTrue`)**:
   - In Lean 4 releases through ~v4.17–v4.19, `native_decide` relied on kernel normalizer extensions (`Lean.reduceBool` / `Lean.reduceNat`) backed by axioms `Lean.ofReduceBool` and `Lean.trustCompiler`, invoking compiled native evaluation directly inside kernel reduction.
   - At `dfc7769c` (`src/Lean/Meta/Native.lean:28–77`), Joachim Breitner's refactor moves `native_decide` and `bv_decide` out of the C++ kernel into `Lean.Meta.Native.nativeEqTrue`: it synthesizes a `meta def _native.native_decide.decl : Bool := e`, compiles it via `addAndCompile` (`Elab.async := false`, `compiler.postponeCompile := false`), runs `unsafe evalConst Bool`, and if `true`, registers a fresh `Declaration.axiomDecl` (`_native.native_decide.ax : e = true`).
   - Either design drags the **entire ~300+ KLoC Lean 4 compiler, IR lowering, C code generator, Clang/LLVM backend, and runtime** into the logical TCB whenever native evaluation is admitted. `Lean4Lean` explicitly refuses `reduceBool`/`reduceNat` (`Lean4Lean/TypeChecker.lean:453–459`) because supporting it faithfully would require verifying the entire Lean compiler.
2. **`@[csimp]` axiom and `unsafe` smuggling (`leanprover/lean4#7463`, open P-low)**:
   - While `@[implemented_by]` (`src/Lean/Compiler/ImplementedByAttr.lean`) is explicitly documented as unsafe because it only checks syntactic `declType == fnType` equality (`==` on `Expr`) and accepts arbitrary `unsafe` C/Lean bodies, `@[csimp]` (`src/Lean/Compiler/CSimpAttr.lean:64–112`) is promoted as a safer alternative requiring an equality theorem `@f = @g` (with zero parameters).
   - However, `CSimpAttr.lean` **does not forbid `unsafe` defs or extra axioms (`sorryAx`, `cheating : False`) inside the `@[csimp]` theorem proof** (`CSimpAttr.lean:94–96` explicitly warns of this!), and neither `Lean.ofReduceBool` (v4.17) nor `nativeEqTrue` (v4.38-pre) propagates axioms used by `@[csimp]` replacements during `evalConst`:
     ```lean
     def one := 1; def bad_one := 2
     axiom cheating : False
     @[csimp] theorem oops : one = bad_one := cheating.elim
     -- or: @[csimp] unsafe def oops : one = bad_one := oops
     theorem ohno : one = 2 := by native_decide
     -- On v4.17: `#print axioms ohno` prints `[Lean.ofReduceBool]`, hiding `cheating`!
     ```
     Thus any downstream auditor relying strictly on `#print axioms` that allows `Lean.ofReduceBool` can be spoofed to accept arbitrary smuggled axioms or non-terminating `unsafe` loops.
3. **`@[extern]` and `@[init]` FFI/metaprogramming surface**: `@[extern]` (`src/Lean/Compiler/ExternAttr.lean`) binds Lean declarations directly to arbitrary C/C++ symbols (`standard`, `inline`, `adhoc`), while environment extensions and `@[init]` hooks execute arbitrary C++/Lean code at module load (`import`) time inside the same OS process as the kernel, capable of invoking `Environment.addDeclWithoutChecking` (the exact class of bypass `lean4checker` was built to detect).
4. **C++17, GMP, and `.olean` `mmap` memory-safety surface**:
   - **`.olean` compacted regions (`src/runtime/compact.cpp`, 690 LoC)**: Compiled `.olean` files store serialized Lean heap object graphs reloaded via memory mapping and pointer relocation (`compact.cpp`). Reading a malformed or adversarial `.olean` bypasses kernel validation (unless `--fresh` replay is run) and exposes the host process to raw C++ pointer-relocation and object-tag memory corruption (`lean_object` manual RC `inc`/`dec` in multi-threaded runtime).
   - **GMP bignums & integer truncation**: `type_checker.cpp:602–691` evaluates `Nat` operations (`+`, `-`, `*`, `pow`, `gcd`, `mod`, `div`, bitwise `land`/`lor`/`xor`/shifts) directly via GMP-backed `lean::nat`. Denial-of-service / OOM risks are bounded by `LEAN_NAT_MAX_SIZE` (`check_nat_size` at `type_checker.cpp:259, 614`) and `UINT_MAX` shift/exponent guards (`get_count_arg`), while `src/kernel/CMakeLists.txt:21–23` enforces `-Werror=conversion` under Clang specifically because lossy `size_t` truncation can alias distinct bound-variable or projection indices.

### 5. External Checkers, Export Format, and Verification-Pipeline Defenses

Basis: source (`lean4export/format_ndjson.md`, `nanoda_lib/src/lib.rs`, `src/main.rs`, `Cargo.toml`, `lean4lean`, `lean4checker`, `Safeverify`) + documentation (`arXiv:2403.14064v3`, `lean-kernel-arena`).

## Boundaries

- **unknown**: Whether `Lean4Lean`'s open conjectures (**Conjecture 2.7 `IsDefEq.uniq`**, **Conjecture 2.9 `Definitional inversion`**, and **Conjecture 2.10 `Strengthening`** in `arXiv:2403.14064v3`) can be proved in Lean without redesigning the stratified typing judgment $\vdash_i$, and whether `Lean4Lean`'s `EquivManager` union-find divergence can cause a declaration accepted in one query order to fail in another on realistic Mathlib proofs.
- **unsupported**:
  - `Lean.reduceBool` / `Lean.reduceNat` (`native_decide` in pre-`nativeEqTrue` exports) is explicitly **unsupported** by `digama0/lean4lean` (raises an error in `reduceNative`).
  - `ammkrn/nanoda_lib` disables `nat_extension` and `string_extension` by default in `Config`, rejecting proofs relying on kernel bignum/string literal reduction unless explicitly enabled in configuration JSON.
  - Non-C++ `Environment` axiom hygiene inside `.olean` files is unsupported by `SafeVerify` without pairing it with source-level attribute banning (`@[implemented_by]`, `@[extern]`, `@[csimp]`) and sandboxing.
- **known not to apply**:
  - Checking `#print axioms` alone **does not guarantee** soundness on unpatched pre-July-2026 Lean 4 kernels (`CVE-2026-72844` `#14576` and `#14613` both reported **zero axioms** under `--trust=0`), nor when `Lean.ofReduceBool` is allowlisted (`#7463` `@[csimp]` smuggles `sorryAx` / `unsafe` with `#print axioms` reporting only `[Lean.ofReduceBool]`).
  - Running `lean4checker` without `--fresh` **does not recheck** imported `.olean` modules and therefore cannot detect poisoned transitive `.olean` dependencies.
  - `lean4checker` and `lean4lean` **do not check specification fidelity** against a challenge statement (an attacker can alter a definition or weaken a theorem signature); `SafeVerify` or explicit `lean4export` AST matching is required.
- **not examined**:
  - Dynamic fuzzing (`libFuzzer` / `AddressSanitizer`) of `.olean` compacted-region deserialization in `src/runtime/compact.cpp` (690 LoC) for out-of-bounds pointer-relocation memory corruption.
  - Line-by-line inspection of `ammkrn/nanoda_lib`'s internal `tc.rs` / `inductive.rs` post-July-2026 projection fix beyond `lib.rs`, `main.rs`, `Cargo.toml`, and `README.md`.

```python
#!/usr/bin/env python3
from dataclasses import dataclass
from typing import Dict, Tuple

@dataclass(frozen=True)
class Sort: level: tuple
@dataclass(frozen=True)
class Const: name: str
@dataclass(frozen=True)
class FVar: name: str; ty: object
@dataclass(frozen=True)
class Lam: var: str; dom: object; body: object
@dataclass(frozen=True)
class Pi: var: str; dom: object; cod: object
@dataclass(frozen=True)
class App: fn: object; arg: object
@dataclass(frozen=True)
class Ctor: ind: str; args: tuple
@dataclass(frozen=True)
class Proj: sname: str; idx: int; val: object
@dataclass(frozen=True)
class EqRec: motive: object; base: object; proof: object

class Lean4IsDefEqModel:
    def __init__(self):
        self.types: Dict[str, object] = {}
        self.structs: Dict[str, Tuple[int, bool, Tuple[object, ...]]] = {}
        self.props: set[str] = set()
    def add_prop_type(self, name: str):
        self.types[name] = Sort(("zero",)); self.props.add(name)
    def add_const(self, name: str, ty: object): self.types[name] = ty
    def add_struct(self, name: str, is_prop: bool, field_types: Tuple[object, ...]):
        self.structs[name] = (len(field_types), is_prop, field_types)
        if is_prop: self.props.add(name)
        self.types[name] = Sort(("zero",) if is_prop else ("succ", ("zero",)))
    def subst(self, e, var: str, rep):
        if isinstance(e, FVar): return rep if e.name == var else e
        if isinstance(e, App): return App(self.subst(e.fn, var, rep), self.subst(e.arg, var, rep))
        if isinstance(e, Lam): return e if e.var == var else Lam(e.var, self.subst(e.dom, var, rep), self.subst(e.body, var, rep))
        if isinstance(e, Pi): return e if e.var == var else Pi(e.var, self.subst(e.dom, var, rep), self.subst(e.cod, var, rep))
        if isinstance(e, Proj): return Proj(e.sname, e.idx, self.subst(e.val, var, rep))
        if isinstance(e, Ctor): return Ctor(e.ind, tuple(self.subst(a, var, rep) for a in e.args))
        if isinstance(e, EqRec): return EqRec(self.subst(e.motive, var, rep), self.subst(e.base, var, rep), self.subst(e.proof, var, rep))
        return e
    def infer_type(self, e):
        if isinstance(e, FVar): return e.ty
        if isinstance(e, Const): return self.types[e.name]
        if isinstance(e, Ctor): return Const(e.ind)
        if isinstance(e, Proj): return self.structs[e.sname][2][e.idx]
        if isinstance(e, Lam): return Pi(e.var, e.dom, self.infer_type(e.body))
        if isinstance(e, Pi): return Sort(("succ", ("zero",)))
        if isinstance(e, App):
            ft = self.whnf(self.infer_type(e.fn))
            assert isinstance(ft, Pi)
            return self.subst(ft.cod, ft.var, e.arg)
        if isinstance(e, EqRec): return e.motive
        raise ValueError(e)
    def is_prop(self, ty) -> bool:
        return isinstance(ty, Const) and (ty.name in self.props or self.types.get(ty.name) == Sort(("zero",)))
    def whnf(self, e):
        if isinstance(e, App):
            f = self.whnf(e.fn)
            if isinstance(f, Lam): return self.whnf(self.subst(f.body, f.var, e.arg))
            if isinstance(f, EqRec) and f.proof == Const("Eq.refl"): return self.whnf(App(f.base, e.arg))
            if f != e.fn: return self.whnf(App(f, e.arg))
        if isinstance(e, Proj):
            c = self.whnf(e.val)
            if isinstance(c, Ctor) and c.ind == e.sname: return self.whnf(c.args[e.idx])
        return e
    def quick_is_def_eq(self, t, s) -> str:
        if t == s: return "true"
        if isinstance(t, Lam) and isinstance(s, Lam):
            if not self.is_def_eq(t.dom, s.dom): return "false"
            fv = FVar(f"_x_{t.var}", t.dom)
            return "true" if self.is_def_eq(self.subst(t.body, t.var, fv), self.subst(s.body, s.var, fv)) else "false"
        return "undef"
    def is_def_eq_proof_irrel(self, t, s) -> str:
        t_ty = self.infer_type(t)
        if not self.is_prop(t_ty): return "undef"
        return "true" if self.is_def_eq(t_ty, self.infer_type(s)) else "false"
    def is_def_eq_app(self, t, s) -> bool:
        def unapp(x):
            args = []
            while isinstance(x, App): args.append(x.arg); x = x.fn
            args.reverse(); return x, args
        tf, targs = unapp(t); sf, sargs = unapp(s)
        return bool(targs) and len(targs) == len(sargs) and self.is_def_eq(tf, sf) and all(self.is_def_eq(a, b) for a, b in zip(targs, sargs))
    def try_eta_expansion(self, t, s) -> bool:
        def core(lam, other):
            if isinstance(lam, Lam) and not isinstance(other, Lam):
                oty = self.whnf(self.infer_type(other))
                if not isinstance(oty, Pi): return False
                fv = FVar("_eta", oty.dom)
                return self.is_def_eq(self.subst(lam.body, lam.var, fv), self.whnf(App(other, fv)))
            return False
        return core(t, s) or core(s, t)
    def try_eta_struct(self, t, s) -> bool:
        def core(other, ctor):
            if isinstance(ctor, Ctor) and ctor.ind in self.structs:
                nfields, _, _ = self.structs[ctor.ind]
                if not self.is_def_eq(self.infer_type(other), self.infer_type(ctor)): return False
                return all(self.is_def_eq(Proj(ctor.ind, i, other), ctor.args[i]) for i in range(nfields))
            return False
        return core(t, s) or core(s, t)
    def is_def_eq_unit_like(self, t, s) -> bool:
        t_ty = self.whnf(self.infer_type(t))
        if isinstance(t_ty, Const) and t_ty.name in self.structs and self.structs[t_ty.name][0] == 0:
            return self.is_def_eq(t_ty, self.infer_type(s))
        return False
    def is_def_eq(self, t, s) -> bool:
        q = self.quick_is_def_eq(t, s)
        if q != "undef": return q == "true"
        pi = self.is_def_eq_proof_irrel(t, s)
        if pi != "undef": return pi == "true"
        tn, sn = self.whnf(t), self.whnf(s)
        q2 = self.quick_is_def_eq(tn, sn)
        if q2 != "undef": return q2 == "true"
        return self.is_def_eq_app(tn, sn) or self.try_eta_expansion(tn, sn) or self.try_eta_struct(tn, sn) or self.is_def_eq_unit_like(tn, sn)

def eval_level(lvl, env):
    tag = lvl[0]
    if tag == "zero": return 0
    if tag == "succ": return eval_level(lvl[1], env) + 1
    if tag == "param": return env[lvl[1]]
    if tag == "max": return max(eval_level(lvl[1], env), eval_level(lvl[2], env))
    if tag == "imax":
        b = eval_level(lvl[2], env)
        return 0 if b == 0 else max(eval_level(lvl[1], env), b)
    raise ValueError(lvl)

def is_always_zero(lvl):
    if lvl[0] == "zero": return True
    if lvl[0] in ("param", "succ"): return False
    if lvl[0] == "max": return is_always_zero(lvl[1]) and is_always_zero(lvl[2])
    if lvl[0] == "imax": return is_always_zero(lvl[2])
    return False

def is_never_zero(lvl):
    if lvl[0] == "succ": return True
    if lvl[0] in ("zero", "param"): return False
    if lvl[0] == "max": return is_never_zero(lvl[1]) or is_never_zero(lvl[2])
    if lvl[0] == "imax": return is_never_zero(lvl[2])
    return False
```
