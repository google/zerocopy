### 2. The `Component` Lens Hierarchy, `Simple.lean` Unprovability Diagnosis, Memory Model, and Anneal Bridge

#### 2.1 Lens Laws, `WeakReadOverWrite`, and Three `Component` Algebra Findings

Both `s2n-bignum` (`common/components.ml`) and `cslib-community/bignum` (`Bignum/Component/Basic.lean:33-112`) organize component lenses (`structure Component (α : Type u) (β : Type v) where read : α → β; write : β → α → α`) into an 8-class Lean typeclass hierarchy: `ReadOverWrite`, `WeakReadOverWrite` (`∃ f : β → β, ∀ b a, cp.read (cp.write b a) = f b`), `WriteOverRead`, `WriteOverWrite`, `Valid := ReadOverWrite + WriteOverWrite`, `WeaklyValid := WeakReadOverWrite + WriteOverWrite`, `StronglyValid := Valid + WriteOverRead`, and `ExtensionallyValid := WeaklyValid + WriteOverRead`.
- Fixed-length slice lenses (`bytesLE addr len : Component (Memory w) ByteList`, `Bignum/Component/Extra.lean:89`) require `WeakReadOverWrite` because writing a `ByteList` whose length differs from `len` truncates/pads on readback.
- Upper-zeroing 32-bit sub-register lenses (`WREG i := XREG i :> .zerotop32`, `Bignum/Arm/Component.lean:16`) satisfy `ReadOverWrite` and `WriteOverWrite` (`Valid`), with `Assign_zerotop32 : ((cp :> .zerotop32) ≔ bv) = (cp ≔ bv.zeroExtend 64) := rfl` (`Bignum/Component/RelationalLemmas.lean:45-46`), but intentionally violate `WriteOverRead` because writing `WREG i` zeroes the upper 32 bits of `XREG i`.
- Zero-register and immediate pseudo-lenses (`rvalue b`, used for `XZR := .rvalue 0#64` and `WZR := .rvalue 0#32`) are `ExtensionallyValid` via constant `f _ := b`.

Our primary-source audit identified three gaps in `cslib-community/bignum`'s `Component` library at `92dc3ee58` and mechanized their fixes in [`support/cslib_bignum_component_and_ensures_probe.lean`](support/cslib_bignum_component_and_ensures_probe.lean):
1. **Accidental Homogeneous Restriction on `Orthogonal.symm` (`Bignum/Component/Basic.lean:111`):** While `class Orthogonal (cp₁ : Component α β) (cp₂ : Component α γ) : Prop` (line 105) is heterogeneous in `β` and `γ`, `Orthogonal.symm` (line 111) restricts `cp₁ cp₂ : Component α β` to the same codomain `β`. We generalize `Component.Orthogonal.symm` to `{cp₁ : Component α β} {cp₂ : Component α γ}`.
2. **Homogeneous List Typing of `MayChange` (`Bignum/Component/Relational.lean:26`):** Because `MayChange : List (Component α β) → Relation α α` requires all components in a list to share codomain `β`, frames spanning `BitVec 64` registers, `Bool` flags, `ByteList` memory slices, and `List (UArchEvent 64)` traces must be chained with `Relation.Seq` (`,,`), matching `s2n-bignum/arm/proofs/instruction.ml:655-658`.
3. **Missing `Orthogonal` Frame-Preservation Theorems (`Bignum/Component/RelationalLemmas.lean`):** We state and prove `Component.element_orthogonal`, `Component.orthogonal_compose_left`, `Component.orthogonal_compose_right`, `Component.Assigns_preserves_orthogonal`, `Component.MayChange_preserves_orthogonal` (`(∀ w ∈ cps, Orthogonal cp w) → MayChange cps a a' → cp.read a' = cp.read a`), and `Component.Seq_preserves_read`.

#### 2.2 Why `simple_spec` in `BignumTest/Tutorial/Simple.lean:16-28` is Unprovable at `92dc3ee58`

In `BignumTest/Tutorial/Simple.lean` (porting `s2n-bignum/arm/tutorial/simple.ml:1-32`), `simple` loads `0x8b000022` (`add x2, x1, x0`) and `0xcb010042` (`sub x2, x2, x1`), which belong to the AArch64 **Add/subtract (shifted register)** encoding class (`sf | op | S | 01011 | shift(2) | 0 | Rm(5) | imm6(6) | Rn(5) | Rd(5)`, `s2n-bignum/arm/proofs/decode.ml:858-866`). However, `Bignum/Arm/Decode.lean:36-47` at `92dc3ee58` implements **only** the **Add/subtract (immediate)** pattern (`[sf:1, op:1, S:1, 100010, sh:1, imm12:12, Rn:5, Rd:5]`). Because bits `[28:23]` of `0x8b000022` and `0xcb010042` are `0b010110 ≠ 0b100010`, `Decode.decode` returns `none` on both words (`Arm.upstream_decode_simple_word0_is_none`, `Arm.upstream_decode_simple_word1_is_none`), `s.decode (s.read PC)` is empty, and `upstreamArm` has no successor (`Arm.upstream_simple_stuck_at_entry : ¬ ∃ s', upstreamArm s s'`). Adding the shifted-register arm (`FixedDecode.decode`) allows `Arm.simple_spec_proven` and `Arm.simple_frame_preserves_abi_state` to be proved with zero `sorry`. #### 2.3 Memory Wrapping (`hk : k ≤ 2^w`), Microarchitectural `Safety`, Three-Way Comparison, and Anneal `SpecOn` Bridge

- **Forward vs. Reverse Multi-Byte Writes (`Bignum/Memory/Lemmas.lean:376-408`):** `cslib-community/bignum` defines `writeBytesNatLE` from `addr` upward, whereas `s2n-bignum` (`common/components.ml:458-466`) defines `write_bytes` from `addr + (k - 1)` downward (`writeBytesNatLE'`). Their equivalence theorem `writeBytesNatLE'_eq` requires `hk : k ≤ 2 ^ w` because when $k > 2^w$, `BitVec w` addresses wrap modulo $2^w$ and overwrite the same byte twice in opposite order.
- **Three-Way Comparison (`s2n-bignum` vs. `cslib-community/bignum` vs. `AeneasVerif/kraken`):** Unlike `AeneasVerif/kraken` (`c9aa45ee1`), which verifies an AST `Kraken.Directive Instr` without a binary instruction decoder from raw bytes or a microarchitectural event trace, `s2n-bignum` and `cslib-community/bignum` decode concrete bytes at `PC` at every step and track `events : List (UArchEvent 64)` (`EventLoad`, `EventStore`, `EventJump`).
- **Anneal Layer 1A/1B Bridge (`ensuresN_safety_refines_anneal_specOn`):** In [`support/cslib_bignum_component_and_ensures_probe.lean`](support/cslib_bignum_component_and_ensures_probe.lean), we prove (`mayChange_alone_cannot_exclude_unauthorized_load`) that `Ensures` with `MayChange` alone is unsound for Anneal's `SmallStepMachine` because `MayChange` only compares entry and exit states and cannot detect out-of-bounds reads (`EventLoad`) or transient out-of-bounds writes restored before exit.
