# Lifetime variance in a toy Rust-like language: soundness of the variance table, forced entries, and maximality of inferred struct variance

## Summary

This package mechanizes, in Lean 4 (no Mathlib), a toy imperative language with lifetimes, a variance table for its built-in type constructors (`&'a T`, `&'a mut T`, `Cell<T>`, `fn(T) -> U`, pairs, `PhantomData<T>`), the subtyping generated by such a table, a flow-sensitive type checker `chk`, and a fuel-bounded interpreter `exec` whose stuck results include a dangling access (a read or write of a location whose region has ended). It proves that every table at most as permissive as `safeTable` (the Rust table with the `PhantomData` entry made bivariant) is sound, that every single-entry change of the Rust table to a variance not at most as permissive as the Rust entry admits a dangling access (except at `PhantomData`), that occurrence-based struct variance inference is admissible, and that it is maximal for first-order data bodies; maximality over all `PhantomData`-free bodies is refuted by two proved counterexamples.

These are statements about the toy model; they neither establish nor refute the corresponding claims about Rust or rustc. Model–system relation: none proved (no embedding, abstraction or simulation between the toy and Rust is established). Every connection to Rust or rustc is a separate claim labelled `derived (modeling bridge)`.

One sentence per result (identifiers are defined verbatim under Findings):

- **R1** (`table_le_safeTable_typing_sound`). For every variance table `tbl` that is pointwise at most as permissive as `safeTable` (the Rust table `rustTable` with the `PhantomData` entry made bivariant), every program accepted by the checker `chk` with copies along `SubGen tbl NoAx` is safe: the interpreter `exec`, run with any fuel, never returns the dangling-access result or any other stuck result.
- **R1-sem** (`rustTable_subGen_implies_semSub`). For all types `S` and `T`, if `S ≤ T` is derivable in `SubGen rustTable NoAx`, then `SemSub S T` holds: adding `S ≤ T` as one more generator of the Rust-table subtyping keeps the toy type system sound, i.e. every program accepted by `chk` with that extended subtyping is safe under `exec`.
- **R2** (`refMut_covariant_in_T_admits_dangling_read`). With `&mut` made covariant in its pointee type and all other entries as in `rustTable`, the concrete program `progRefMutCo` is accepted by `chk` and `exec` with fuel 40 returns the dangling-access result.
- **R3** (`fn_covariant_in_arg_admits_dangling_read`). With `fn` made covariant in its argument and all other entries as in `rustTable`, the concrete program `progFnArgCo` is accepted by `chk` and `exec` with fuel 40 returns the dangling-access result.
- **R4** (`cell_covariant_admits_dangling_read`). With `Cell` made covariant and all other entries as in `rustTable`, the concrete program `progCellCo` is accepted by `chk` and `exec` with fuel 40 returns the dangling-access result.
- **R-forced** (`rustTable_entry_not_le_admits_dangling`, with corollary `rustTable_entry_not_le_unsound`). For every built-in position `p` other than `PhantomData` and every variance `v` that is not at most as permissive as `rustTable p` (strictly more permissive or incomparable), the single-entry modification `rustTable.set p v` admits a dangling access: some program accepted by `chk` with `SubGen (rustTable.set p v) NoAx` makes `exec` return the dangling-access result; hence that system is not sound.
- **R-iff** (`rustTable_entry_sound_iff`). For every built-in position `p` other than `PhantomData` and every variance `v`, the single-entry modification `rustTable.set p v` is sound (every program accepted by `chk` with its generated subtyping is safe under `exec`) iff `v` is at most as permissive as `rustTable p`.
- **R-phantom** (`phantom_entry_any_variance_sound`). For every variance `v` (including bivariant), replacing the `PhantomData` entry of `rustTable` by `v` gives a sound toy type system: every program accepted by `chk` with the generated subtyping is safe under `exec`.
- **R5a** (`inferVar_admissible`). For every table `tbl`, every body `F` and all types `A` and `B`: if `A` and `B` are related along the inferred variance `inferVar tbl F` in `SubGen tbl NoAx`, then `F[A] ≤ F[B]` is derivable in `SubGen tbl NoAx`.
- **R5b** (`bodyAx_le_inferVar_iff`). For every body `F`, every declared variance `v` that is at most as permissive as `inferVar rustTable F`, and all types `S` and `T`: `S ≤ T` is derivable in `SubGen rustTable (BodyAx F v)` iff it is derivable in `SubGen rustTable NoAx`.
- **R5b-at** (`bodyAx_inferVar_iff`). For every body `F` and all types `S` and `T`: `S ≤ T` is derivable in `SubGen rustTable (BodyAx F (inferVar rustTable F))` iff it is derivable in `SubGen rustTable NoAx`.
- **R5b-sound** (`bodyRule_le_inferVar_sound`). For every body `F` and every declared variance `v` that is at most as permissive as `inferVar rustTable F`, the system `SubGen rustTable (BodyAx F v)` is sound: every program accepted by `chk` with it is safe under `exec`.
- **R5c** (`bodyRule_not_le_inferVar_admits_dangling_of_dataBody`, with corollary `bodyRule_not_le_inferVar_unsound_of_dataBody`). For every first-order data body `F` (`F.dataBody = true`: built from `unit`, `nat`, the parameter, tuples, `&`, `&mut`, and `Cell` directly under `&`) and every declared variance `v` that is not at most as permissive as `inferVar rustTable F`, the subtyping `SubGen rustTable (BodyAx F v)` admits a dangling access: some program accepted by `chk` with it makes `exec` return the dangling-access result; hence that system is not sound.
- **R5c-ho** (`bodyRule_fnUnit_contra_admits_dangling_read`). For the non-data body `fn() -> T` (inferred covariant) declared contravariant, the concrete program `progStructFnUnitContra` is accepted by `chk` with `SubGen rustTable (BodyAx (fn() -> T) contra)` and `exec` with fuel 60 returns the dangling-access result.
- **R5c-refuted** (`not_bodyRule_not_le_inferVar_unsound_of_phantomFree`, with `bodyRule_prod_cell_co_sound` and `bodyRule_fn_fn_contra_sound`). The stronger maximality statement over all `PhantomData`-free bodies is false: the bodies `(Cell<T>, ())` at `co` and `fn(fn(T) -> ()) -> ()` at `contra` are `PhantomData`-free and beyond the inferred variance, yet their body rules are sound (every program accepted by `chk` with them is safe under `exec`). The refuted statement is recorded as a reference point; it is not a result of this package.
- **R-rigid** (`rigidLftTable_not_le_safeTable_sound`). The table `rigidLftTable` (lifetime positions and `PhantomData` invariant, every other position covariant) is not at most as permissive as `safeTable` and is sound: every program accepted by `chk` with its generated subtyping is safe under `exec`; so the hypothesis of R1 is sufficient, not necessary.

What each result does **not** show is listed first under Boundaries (non-claims per result).

## Applicability

**Model fidelity.** Every result is a theorem about the Lean model in namespace `Toy.Variance`; this is a toy model, not a mirror of production definitions. Model–system relation: none proved; the results neither establish nor refute the corresponding claims about Rust or rustc.

The definitions are meant to capture:

- Rust's built-in variance table for `&'a T` (covariant in `'a` and `T`), `&'a mut T` (covariant in `'a`, invariant in `T`), `Cell<T>` (invariant), `fn(T) -> U` (contravariant in `T`, covariant in `U`), tuples (covariant per component) and `PhantomData<T>` (covariant), as stated by the Rust Reference and the Rustonomicon (records under Evidence);
- subtyping generated from such a table by reflexivity, transitivity and one congruence rule per constructor, with an invariant position requiring subtyping in both directions;
- occurrence-based variance inference for a struct with one type parameter, unfolded to its body (`inferVar`), and a schematic rule (`BodyAx`) that accepts a declared variance for that body;
- type safety as "no execution reaches a dangling access or any other stuck state".

Known gaps between the toy and Rust (each is also a non-claim where it matters):

- straight-line programs with numbered variables; no loops and no syntactic recursion (a closure stored in a `Cell` can still call itself through the cell, so a well-typed program can diverge, i.e. exhaust every fuel bound; not proved here), no enums or other sum types, no destructors, no traits, no generics over lifetimes, no nominal struct types (a struct is represented by its unfolded body), no raw pointers, no `unsafe` code;
- lifetimes are `'static` and `till n` with a total outlives order driven by one clock; every region `till n` is live at time 0 and is ended by `endRegion n`;
- no borrow checker: aliases of `&mut` coexist; each heap location holds a whole immutable value tree, so aliasing alone causes no harm;
- the checker requires every lifetime in the type of a used variable to be live at the use, which is stronger than Rust's liveness constraints;
- closures capture one `'static`-typed value, their bodies allocate in `'static`, cannot end regions, and are checked without liveness constraints;
- a bare `Cell<T>` value can be copied out of a cell by `read`, paired, projected and stored again (in Rust `Cell<T>` is not `Copy`);
- `PhantomData<T>` values are `()` and play no other role (no drop check, no auto traits, no implied bounds);
- the interpreter is fuel-bounded; safety quantifies over every fuel.

**Toolchain.** Lean 4 `v4.34.1` (`leanprover/lean4:v4.34.1`), no Mathlib, no Lake dependencies. Every theorem depends only on the axioms `propext`, `Classical.choice` and `Quot.sound`.

**Subjects.** The Lean 4 toolchain release is the checker that establishes every `execution (Lean kernel check)` claim. The cited papers, specifications and the rustc source revision are prior art and the modelled reference; they enter through `derived (modeling bridge)` claims, which state their reasoning, and through the prior-art notes, never as premises of a kernel-checked statement. The package does not examine rustc's behaviour by running it.

**Scope of quantifiers over executions.** `Safe` and `AdmitsDanglingAccess` quantify over the runs of the interpreter `exec` from the initial state `St.init` and environment `Env.empty`; `Typed` quantifies over Boolean subtyping oracles contained in the given relation and over checker fuel for `chk`. Every plain claim about typing, safety, soundness or dangling access names `exec` and `chk`; the plain claims of R5a, R5b and R5b-at are statements about the generated subtyping alone and do not quantify over executions. No claim is made about any other semantics or checker.

#### Lifetimes

`Lft.live t l` says that lifetime `l` is live at clock time `t`; `Lft.outlives a b` says that `a` lives at least as long as `b`.

```lean
-- ToyVariance/Basic.lean:16-19
inductive Lft where
  | static
  | till (n : Nat)
  deriving DecidableEq, Repr

-- ToyVariance/Basic.lean:24-26
def live (t : Nat) : Lft → Bool
  | static => true
  | till n => decide (t ≤ n)

-- ToyVariance/Basic.lean:29-32
def outlives : Lft → Lft → Bool
  | static, _ => true
  | till _, static => false
  | till n, till m => decide (m ≤ n)
```

#### Variances

`fwd`/`bwd` say whether a variance requires the forward (`S ≤ T`) or backward (`T ≤ S`) direction. `v.le w = true` means "`v` is at most as permissive as `w`" (`v` requires every direction that `w` requires); `bi` is the most permissive and `inv` the least. `meet` takes the union of required directions and `comp` composes variances along a nested position. `Variance.Rel v R a b` relates `a` and `b` along `v`.

```lean
-- ToyVariance/Basic.lean:40-45
inductive Variance where
  | bi
  | co
  | contra
  | inv
  deriving DecidableEq, Repr

-- ToyVariance/Basic.lean:50-53
def fwd : Variance → Bool
  | co => true
  | inv => true
  | _ => false

-- ToyVariance/Basic.lean:56-59
def bwd : Variance → Bool
  | contra => true
  | inv => true
  | _ => false

-- ToyVariance/Basic.lean:62-66
def ofDirs : Bool → Bool → Variance
  | false, false => bi
  | true, false => co
  | false, true => contra
  | true, true => inv

-- ToyVariance/Basic.lean:71
def le (v w : Variance) : Bool := (!w.fwd || v.fwd) && (!w.bwd || v.bwd)

-- ToyVariance/Basic.lean:74
def meet (v w : Variance) : Variance := ofDirs (v.fwd || w.fwd) (v.bwd || w.bwd)

-- ToyVariance/Basic.lean:79-80
def comp (v w : Variance) : Variance :=
  ofDirs ((v.fwd && w.fwd) || (v.bwd && w.bwd)) ((v.fwd && w.bwd) || (v.bwd && w.fwd))

-- ToyVariance/Basic.lean:84-85
def Rel {α : Type} (v : Variance) (R : α → α → Prop) (a b : α) : Prop :=
  (v.fwd = true → R a b) ∧ (v.bwd = true → R b a)

-- ToyVariance/Basic.lean:90-91
def LRel (v : Variance) (a b : Lft) : Prop :=
  Variance.Rel v (fun x y => x.outlives y = true) a b
```

#### Tables

A table assigns a variance to each built-in position. `rustTable` is the Rust table; `safeTable` is `rustTable` with the `PhantomData` entry made bivariant; `Table.set` changes one entry; `Table.le` is the pointwise order "at most as permissive".

```lean

inductive Pos where
  | refLft
  | refTy
  | refMutLft
  | refMutTy
  | cell
  | fnArg
  | fnRes
  | prodL
  | prodR
  | phantom
  deriving DecidableEq, Repr

-- ToyVariance/Basic.lean:110
abbrev Table := Pos → Variance

-- ToyVariance/Basic.lean:115-125
def rustTable : Table
  | .refLft => .co
  | .refTy => .co
  | .refMutLft => .co
  | .refMutTy => .inv
  | .cell => .inv
  | .fnArg => .contra
  | .fnRes => .co
  | .prodL => .co
  | .prodR => .co
  | .phantom => .co

-- ToyVariance/Basic.lean:128-129
def Table.set (tbl : Table) (p : Pos) (v : Variance) : Table :=
  fun q => if q = p then v else tbl q

-- ToyVariance/Basic.lean:132
def Table.le (t₁ t₂ : Table) : Prop := ∀ p, (t₁ p).le (t₂ p) = true

-- ToyVariance/Basic.lean:135
```


#### Generated subtyping

`SubGen tbl ax` is the subtyping generated by reflexivity, transitivity, the extra generators `ax`, and one congruence rule per constructor whose premises are read off the table. `NoAx` is the empty set of extra generators.

```lean
-- ToyVariance/Basic.lean:217-248
inductive SubGen (tbl : Table) (ax : Ty → Ty → Prop) : Ty → Ty → Prop where
  | refl (T : Ty) : SubGen tbl ax T T
  | trans {S T U : Ty} : SubGen tbl ax S T → SubGen tbl ax T U → SubGen tbl ax S U
  | base {S T : Ty} : ax S T → SubGen tbl ax S T
  | ref {a b : Lft} {S T : Ty} : LRel (tbl .refLft) a b →
      ((tbl .refTy).fwd = true → SubGen tbl ax S T) →
      ((tbl .refTy).bwd = true → SubGen tbl ax T S) →
      SubGen tbl ax (.ref a S) (.ref b T)
  | refMut {a b : Lft} {S T : Ty} : LRel (tbl .refMutLft) a b →
      ((tbl .refMutTy).fwd = true → SubGen tbl ax S T) →
      ((tbl .refMutTy).bwd = true → SubGen tbl ax T S) →
      SubGen tbl ax (.refMut a S) (.refMut b T)
  | cell {S T : Ty} :
      ((tbl .cell).fwd = true → SubGen tbl ax S T) →
      ((tbl .cell).bwd = true → SubGen tbl ax T S) →
      SubGen tbl ax (.cell S) (.cell T)
  | fn {S S' U U' : Ty} :
      ((tbl .fnArg).fwd = true → SubGen tbl ax S S') →
      ((tbl .fnArg).bwd = true → SubGen tbl ax S' S) →
      ((tbl .fnRes).fwd = true → SubGen tbl ax U U') →
      ((tbl .fnRes).bwd = true → SubGen tbl ax U' U) →
      SubGen tbl ax (.fn S U) (.fn S' U')
  | prod {S S' U U' : Ty} :
      ((tbl .prodL).fwd = true → SubGen tbl ax S S') →
      ((tbl .prodL).bwd = true → SubGen tbl ax S' S) →
      ((tbl .prodR).fwd = true → SubGen tbl ax U U') →
      ((tbl .prodR).bwd = true → SubGen tbl ax U' U) →
      SubGen tbl ax (.prod S U) (.prod S' U')
  | phantom {S T : Ty} :
      ((tbl .phantom).fwd = true → SubGen tbl ax S T) →
      ((tbl .phantom).bwd = true → SubGen tbl ax T S) →
      SubGen tbl ax (.phantom S) (.phantom T)

-- ToyVariance/Basic.lean:251
def NoAx : Ty → Ty → Prop := fun _ _ => False
```

#### Variance inference, the schematic body rule, data bodies

`inferVar tbl F` is the variance of the parameter in the body `F`, computed bottom-up with `comp` and `meet` (unused parameter: `bi`). `BodyAx F v` is the schematic rule that a declaration `struct S<T>(F)` at declared variance `v` contributes, with the struct unfolded to its body: `F[A] ≤ F[B]` for closed `A`, `B` related along `v`. `Ty.dataBody` is the class of first-order data bodies used by R5c.

```lean
-- ToyVariance/Basic.lean:259-268
def inferVar (tbl : Table) : Ty → Variance
  | .unit => .bi
  | .nat => .bi
  | .ref _ T => (tbl .refTy).comp (inferVar tbl T)
  | .refMut _ T => (tbl .refMutTy).comp (inferVar tbl T)
  | .cell T => (tbl .cell).comp (inferVar tbl T)
  | .fn T U => ((tbl .fnArg).comp (inferVar tbl T)).meet ((tbl .fnRes).comp (inferVar tbl U))
  | .prod T U => ((tbl .prodL).comp (inferVar tbl T)).meet ((tbl .prodR).comp (inferVar tbl U))
  | .phantom T => (tbl .phantom).comp (inferVar tbl T)
  | .param => .co

-- ToyVariance/Basic.lean:278-280
def BodyAx (F : Ty) (v : Variance) (S T : Ty) : Prop :=
  ∃ A B : Ty, A.closed = true ∧ B.closed = true ∧ S = F.subst A ∧ T = F.subst B ∧
    Variance.Rel v (SubGen rustTable NoAx) A B

-- ToyVariance/Basic.lean:285-294
def Ty.dataBodyAt : Bool → Ty → Bool
  | _, .unit => true
  | _, .nat => true
  | _, .param => true
  | _, .prod A B => A.dataBodyAt false && B.dataBodyAt false
  | _, .ref _ T => T.dataBodyAt true
  | _, .refMut _ T => T.dataBodyAt false
  | underRef, .cell T => underRef && T.dataBodyAt false
  | _, .fn _ _ => false
  | _, .phantom _ => false

-- ToyVariance/Basic.lean:299
def Ty.dataBody (F : Ty) : Bool := F.dataBodyAt false
```

The interpreter `exec` costs one unit of fuel per statement and per call. A `read`, `write`, `cellGet` or `cellSet` of a location whose region is no longer live returns `Res.dangling`; a closure call runs the body in a fresh frame (argument in variable 0, capture in variable 1, result read from variable 2).

```lean
-- ToyVariance/Lang.lean:99-192
def exec : Nat → St → Env → List Stmt → Res
  | 0, _, _, _ => .outOfFuel
  | _ + 1, st, env, [] => .done st env
  | f + 1, st, env, s :: rest =>
    match s with
    | .nat x n => exec f st (env.set x (.nat n)) rest
    | .unit x => exec f st (env.set x .unit) rest
    | .copy x y _ =>
      match env y with
      | some v => exec f st (env.set x v) rest
      | none => .wrong
    | .alloc x l y =>
      match env y with
      | some v =>
        if l.live st.time then
          exec f { st with heap := st.heap ++ [(l, v)] } (env.set x (.ptr st.heap.length)) rest
        else .wrong
      | none => .wrong
    | .share x y =>
      match env y with
      | some v => exec f st (env.set x v) rest
      | none => .wrong
    | .newCell x l y =>
      match env y with
      | some v =>
        if l.live st.time then
          exec f { st with heap := st.heap ++ [(l, v)] } (env.set x (.ptr st.heap.length)) rest
        else .wrong
      | none => .wrong
    | .read x y =>
      match env y with
      | some (.ptr p) =>
        match st.heap[p]? with
        | some (r, v) => if r.live st.time then exec f st (env.set x v) rest else .dangling
        | none => .wrong
      | _ => .wrong
    | .write y z =>
      match env y, env z with
      | some (.ptr p), some v =>
        match st.heap[p]? with
        | some (r, _) =>
          if r.live st.time then exec f { st with heap := st.heap.set p (r, v) } env rest
          else .dangling
        | none => .wrong
      | _, _ => .wrong
    | .cellGet x c =>
      match env c with
      | some (.ptr p) =>
        match st.heap[p]? with
        | some (r, v) => if r.live st.time then exec f st (env.set x v) rest else .dangling
        | none => .wrong
      | _ => .wrong
    | .cellSet c z =>
      match env c, env z with
      | some (.ptr p), some v =>
        match st.heap[p]? with
        | some (r, _) =>
          if r.live st.time then exec f { st with heap := st.heap.set p (r, v) } env rest
          else .dangling
        | none => .wrong
      | _, _ => .wrong
    | .pair x y z =>
      match env y, env z with
      | some a, some b => exec f st (env.set x (.pair a b)) rest
      | _, _ => .wrong
    | .fst x y =>
      match env y with
      | some (.pair a _) => exec f st (env.set x a) rest
      | _ => .wrong
    | .snd x y =>
      match env y with
      | some (.pair _ b) => exec f st (env.set x b) rest
      | _ => .wrong
    | .phantom x _ => exec f st (env.set x .unit) rest
    | .lam x _ _ c body =>
      match env c with
      | some cv => exec f st (env.set x (.clo body cv)) rest
      | none => .wrong
    | .call x g y =>
      match env g, env y with
      | some (.clo body cap), some a =>
        match exec f st (Env.frame a cap) body with
        | .done st' env' =>
          match env' 2 with
          | some r => exec f st' (env.set x r) rest
          | none => .wrong
        | .halted => .halted
        | .dangling => .dangling
        | .wrong => .wrong
        | .outOfFuel => .outOfFuel
      | _, _ => .wrong
    | .endRegion n =>
      if st.time ≤ n then exec f { st with time := n + 1 } env rest else .wrong
    | .abort => .halted
```

#### Language: type checker

`chk fuel sub mode Γ P` is the flow-sensitive checker. `sub` is a Boolean subtyping oracle used by `copy` (the one statement that uses subtyping). At top level a variable can be used only when every lifetime in its type is live at the current clock; inside function bodies (`Mode.inBody`) no liveness check is made, regions cannot be ended and allocation is in `'static`. A closure (`lam`) needs a capture whose type mentions `'static` lifetimes and nothing else, closed and usable argument and result types, and a body that checks in body mode with final variable 2 of the result type (or that ends in `abort`).

```lean

-- ToyVariance/Lang.lean:199

  time : Nat
  inBody : Bool
```

```lean
-- ToyVariance/Lang.lean:226-301
def chk : Nat → (Ty → Ty → Bool) → Mode → Ctx → List Stmt → Option (Option Ctx)
  | 0, _, _, _, _ => none
  | _ + 1, _, _, Γ, [] => some (some Γ)
  | f + 1, sub, m, Γ, s :: rest =>
    match s with
    | .nat x _ => chk f sub m (Γ.set x .nat) rest
    | .unit x => chk f sub m (Γ.set x .unit) rest
    | .copy x y T =>
      match m.get Γ y with
      | some S =>
        if T.closed && T.liveIn m.lv && sub S T then chk f sub m (Γ.set x T) rest else none
      | none => none
    | .alloc x l y =>
      match m.get Γ y with
      | some T =>
        if m.lv l && (!m.inBody || l == .static) then chk f sub m (Γ.set x (.refMut l T)) rest
        else none
      | none => none
    | .share x y =>
      match m.get Γ y with
      | some (.refMut l T) => chk f sub m (Γ.set x (.ref l T)) rest
      | _ => none
    | .newCell x l y =>
      match m.get Γ y with
      | some T =>
        if m.lv l && (!m.inBody || l == .static) then chk f sub m (Γ.set x (.ref l (.cell T))) rest
        else none
      | none => none
    | .read x y =>
      match m.get Γ y with
      | some (.ref _ T) => chk f sub m (Γ.set x T) rest
      | some (.refMut _ T) => chk f sub m (Γ.set x T) rest
      | _ => none
    | .write y z =>
      match m.get Γ y, m.get Γ z with
      | some (.refMut _ T), some Z => if Z == T then chk f sub m Γ rest else none
      | _, _ => none
    | .cellGet x c =>
      match m.get Γ c with
      | some (.ref _ (.cell T)) => chk f sub m (Γ.set x T) rest
      | _ => none
    | .cellSet c z =>
      match m.get Γ c, m.get Γ z with
      | some (.ref _ (.cell T)), some Z => if Z == T then chk f sub m Γ rest else none
      | _, _ => none
    | .pair x y z =>
      match m.get Γ y, m.get Γ z with
      | some A, some B => chk f sub m (Γ.set x (.prod A B)) rest
      | _, _ => none
    | .fst x y =>
      match m.get Γ y with
      | some (.prod A _) => chk f sub m (Γ.set x A) rest
      | _ => none
    | .snd x y =>
      match m.get Γ y with
      | some (.prod _ B) => chk f sub m (Γ.set x B) rest
      | _ => none
    | .phantom x T =>
      if T.closed && T.liveIn m.lv then chk f sub m (Γ.set x (.phantom T)) rest else none
    | .lam x T U c body =>
      match m.get Γ c with
      | some C =>
        if C.allStatic && T.closed && U.closed && T.liveIn m.lv && U.liveIn m.lv then
          match chk f sub ⟨m.time, true⟩ (Ctx.frame T C) body with
          | some none => chk f sub m (Γ.set x (.fn T U)) rest
          | some (some Γb) => if Γb 2 == some U then chk f sub m (Γ.set x (.fn T U)) rest else none
          | none => none
        else none
      | none => none
    | .call x g y =>
      match m.get Γ g, m.get Γ y with
      | some (.fn T U), some A => if A == T then chk f sub m (Γ.set x U) rest else none
      | _, _ => none
    | .endRegion n =>
      if !m.inBody && decide (m.time ≤ n) then chk f sub ⟨n + 1, false⟩ Γ rest else none
    | .abort => some none
```

#### Typing, safety, soundness, dangling access, semantic subtyping

`Typed R P` holds when some Boolean oracle contained in `R` makes `chk` accept `P` at some fuel. `Safe P` says that `exec` never returns a stuck result (`dangling` or `wrong`) from the initial state, for any fuel. `Sound R` says that every program typed along `R` is safe. `AdmitsDanglingAccess R` says that some program typed along `R` reaches the dangling-access result. `SemSub S T` (contextual semantic subtyping) says that adding `S ≤ T` as one more generator of the Rust-table subtyping keeps the system sound.

```lean
-- ToyVariance/Lang.lean:304-305
def Checks (sub : Ty → Ty → Bool) (fuel : Nat) (P : List Stmt) : Bool :=
  (chk fuel sub ⟨0, false⟩ Ctx.empty P).isSome

-- ToyVariance/Lang.lean:309-310
def Typed (R : Ty → Ty → Prop) (P : List Stmt) : Prop :=
  ∃ sub : Ty → Ty → Bool, (∀ S T, sub S T = true → R S T) ∧ ∃ fuel, Checks sub fuel P = true

-- ToyVariance/Lang.lean:313-314
def Safe (P : List Stmt) : Prop :=
  ∀ fuel, (exec fuel St.init Env.empty P).isStuck = false

-- ToyVariance/Lang.lean:317
def Sound (R : Ty → Ty → Prop) : Prop := ∀ P, Typed R P → Safe P

-- ToyVariance/Lang.lean:322
def SemSub (S T : Ty) : Prop := Sound (SubGen rustTable (fun A B => A = S ∧ B = T))

-- ToyVariance/Lang.lean:327-328
def AdmitsDanglingAccess (R : Ty → Ty → Prop) : Prop :=
  ∃ P, Typed R P ∧ ∃ fuel, (exec fuel St.init Env.empty P).isDangling = true
```

#### Decision procedure for the generated subtyping

Some positive controls are stated with the Boolean procedure `subAlg`; `subGen_iff_subAlg` proves that `subAlg tbl true` decides `SubGen tbl NoAx` (soundness and completeness), so a `false` verdict is a refutation of derivability.

```lean
-- ToyVariance/Alg.lean:21-41
def subAlg (tbl : Table) : Bool → Ty → Ty → Bool
  | _, .unit, .unit => true
  | _, .nat, .nat => true
  | _, .param, .param => true
  | pol, .ref a S, .ref b T =>
    lrelB (tbl .refLft) pol a b && (!(tbl .refTy).fwd || subAlg tbl pol S T) &&
      (!(tbl .refTy).bwd || subAlg tbl (!pol) S T)
  | pol, .refMut a S, .refMut b T =>
    lrelB (tbl .refMutLft) pol a b && (!(tbl .refMutTy).fwd || subAlg tbl pol S T) &&
      (!(tbl .refMutTy).bwd || subAlg tbl (!pol) S T)
  | pol, .cell S, .cell T =>
    (!(tbl .cell).fwd || subAlg tbl pol S T) && (!(tbl .cell).bwd || subAlg tbl (!pol) S T)
  | pol, .fn S U, .fn S' U' =>
    (!(tbl .fnArg).fwd || subAlg tbl pol S S') && (!(tbl .fnArg).bwd || subAlg tbl (!pol) S S') &&
      (!(tbl .fnRes).fwd || subAlg tbl pol U U') && (!(tbl .fnRes).bwd || subAlg tbl (!pol) U U')
  | pol, .prod S U, .prod S' U' =>
    (!(tbl .prodL).fwd || subAlg tbl pol S S') && (!(tbl .prodL).bwd || subAlg tbl (!pol) S S') &&
      (!(tbl .prodR).fwd || subAlg tbl pol U U') && (!(tbl .prodR).bwd || subAlg tbl (!pol) U U')
  | pol, .phantom S, .phantom T =>
    (!(tbl .phantom).fwd || subAlg tbl pol S T) && (!(tbl .phantom).bwd || subAlg tbl (!pol) S T)
  | _, _, _ => false
```

### Modeling bridge to Rust and rustc

Basis: derived (modeling bridge). Each paragraph below is a separate claim about real systems, reasoned from the toy results and from the cited sources; none is a kernel-checked statement. Model–system relation: none proved; these paragraphs neither establish nor refute the corresponding claims about Rust or rustc.

- **Forced entries (R2, R3, R4, R-forced).** The witness programs use operations Rust also has: writing through `&mut`, `Cell::set`, coercing a function value, projecting a tuple field. They mirror the informal arguments that `&mut T` must be invariant in `T`, `Cell<T>` invariant, and `fn` contravariant in its argument ([TAPL] Sections 15.2 and 15.5; the [Nomicon] for `&mut` and `fn`). The toy differs from Rust in ways that matter for a transfer: `&mut` aliases are unrestricted (no borrow checker; in Rust the alias in `progRefMutCo` would be a reborrow), lifetimes are totally ordered, closures capture `'static`-typed data, every lifetime in a used type must be live, and bare `Cell` values can be copied. No claim is made that rustc rejects exactly what the toy rejects.
- **Variance inference (R5a, R5b, R5c).** `inferVar` mirrors occurrence-based inference (greatest lower bound with bivariant as top; composition along positions) for non-recursive structs with one type parameter, as described by the [Reference] and the [Nomicon] and implemented in rustc's variance pass ([rustc variance]). Its composition `Variance.comp` agrees with rustc's `Variance::xform` (transcribed as `Variance.xform`) whenever the inner variance is not bivariant (`Variance.comp_eq_xform_of_ne_bi`); a bottom-up recursion that uses `Variance.xform` in place of `Variance.comp` (`inferVarXform`) differs from `inferVar` on `(Cell<()>, T)` (`inferVar_vs_inferVarXform`). rustc generates constraints at parameter occurrences; how its solver treats parameter-free subterms is not modelled (not proved here).
- **Struct declarations (R5b, R5b-at, R5b-sound, R5c, R5c-ho, R5c-refuted).** `BodyAx F v` models accepting the declaration `struct S<T>(F)` at variance `v` with the struct unfolded to its body. Rust's struct types are nominal: two instances of `S` are related through the declared or inferred variance of `S`, not through structural coercions between unfolded bodies. The toy rule is not nominal (`bodyAx_inv_still_covariant`, `bodyAx_param_contra_coerces_bare_refs`), so any transfer to Rust structs is an analogy that this package neither establishes nor refutes (not proved here).
- **Soundness (R1, R-phantom).** rust-lang/rust#25860 (implied bounds on nested references combined with variance) is not modelled. In the toy every lifetime in the type of a used variable is checked live at each use; whether the absence of a comparable check is the cause of that issue is not established here (not proved here).

A unique, move-only owning pointer without reborrows (like `Box<T>`) or a type split into read-only and write-only capabilities (a source and a sink) can soundly be covariant (the source, `Box`) or contravariant (the sink) in its contents; such types are not modelled (not proved here).
- **R5c (data bodies).** Dropping `hF` defeats the result: `bodyRule_prod_cell_co_sound` (bare `Cell` field: bare `Cell` values are immutable copies and there is no shared projection from `&(A, B)` to `&A`), `bodyRule_fn_fn_contra_sound` (closures capture `'static`-typed data and allocate in `'static`), and `bodyRule_phantom_bi_sound` (`PhantomData<T>` at `bi`).
- **R-forced (`hp`).** The `PhantomData` entry is not forced: `phantom_bi_not_le_and_sound`.
- **All impossibility results.** They exhibit programs accepted by this checker `chk` and run by this interpreter `exec`. A stricter checker could reject a witness (for example, a borrow checker that rejects the coexisting `&mut` aliases used by `progRefMutCo`); such checkers are not covered (not proved here).

### Hypotheses with `unknown` tightness

None. Every hypothesis is either `tight` (with a named, kernel-checked counterexample and its witness class) or `harmless` (there is no hypothesis to drop: the statement is a concrete instance, or, for R-phantom and R5b-at, the statement quantifies over its variables without restriction).

### Disproved stronger statement (all `PhantomData`-free bodies; refuted reference point)

The stronger maximality statement over all `PhantomData`-free bodies reads: "for every `PhantomData`-free body `F` and every `v` not at most as permissive as `inferVar rustTable F`, `SubGen rustTable (BodyAx F v)` is not sound". It is **false**. Its negation is proved as `not_bodyRule_not_le_inferVar_unsound_of_phantomFree` (quoted under R5c-refuted), with two concrete counterexamples, both outside `Ty.dataBody`:

- `bodyRule_prod_cell_co_sound`: the bare-`Cell` body `(Cell<T>, ())` at `co` (inferred `inv`) is sound and admits no dangling access;
- `bodyRule_fn_fn_contra_sound`: the body `fn(fn(T) -> ()) -> ()` at `contra` (inferred `co`) is sound and admits no dangling access.

The refuted statement is not a result of this package. The proved maximality statement is R5c, which restricts the body by the hypothesis `hF : F.dataBody = true`.

### Dropped statements

None. Every stated result is proved.

### Unknown (considered, not resolved)

- Whether the body `fn() -> T` at `contra` admits a dangling access with first-order instantiations of `T` (R5c-ho uses a function type).
- A characterization of the bodies outside `Ty.dataBody` (function types, bare `Cell`, `PhantomData`) for which maximality holds.
- Whether `SemSub` is transitive, and a characterization of `SemSub`.

### Not examined

- Struct bodies with several type parameters, lifetime parameters of the struct, recursive structs, enums.
- Trait objects (`dyn Trait<T> + 'a`), raw pointers, slices and arrays, `Box<T>`, `Vec<T>`.
- Higher-ranked lifetimes and implied bounds.
- The behaviour of rustc itself (no rustc run is part of the evidence).

### Primary sources

Prior-art keys used in the results above. "Contains" records what the source says, checked at the cited revision or record; "Does not contain" records what the results above do not attribute to it.

- **[RustBelt]** R. Jung, J.-H. Jourdan, R. Krebbers, D. Dreyer. "RustBelt: Securing the Foundations of the Rust Programming Language." Proc. ACM Program. Lang. 2(POPL), article 66, pp. 66:1–66:34, 2018. doi:10.1145/3158154. Contains: semantic soundness, in the Iris separation logic, of a core Rust calculus with lifetimes, and proofs that libraries such as `Cell` are safe against their semantic types; the full development is in R. Jung, "Understanding and Evolving the Rust Programming Language", PhD dissertation, Saarland University, 2020. Cited for the existence of a mechanized soundness proof for a core Rust calculus; no claim is made here about which subtyping or variance rules that work states, and this package neither reuses nor mirrors its model.
- **[Nomicon]** The Rustonomicon, chapter "Subtyping and Variance" (`src/subtyping.md`), repository `rust-lang/nomicon`, commit `69c1421f159dceca565305de2bdd6cd1abd2e4f8` (committed 2026-02-27), https://github.com/rust-lang/nomicon/blob/69c1421f159dceca565305de2bdd6cd1abd2e4f8/src/subtyping.md. Contains: "There are three kinds of variance in Rust" (covariant, contravariant, invariant; bivariance is not discussed); a variance table for `&'a T`, `&'a mut T`, `Box<T>`, `Vec<T>`, `UnsafeCell<T>`, `Cell<T>`, `fn(T) -> U`, `*const T`, `*mut T`; informal explanations of why `&mut T` is invariant in `T` (a program assigning a short-lived `&str` through `&mut &'static str`, rejected by rustc) and why `fn` is contravariant in its argument (a `thread_local!` store of `&'static str`); the struct rule "If all uses of `A` are covariant, then MyType is covariant over `A`; If all uses of `A` are contravariant, then MyType is contravariant over `A`; Otherwise, MyType is invariant over `A`". Does not contain: `PhantomData` or tuples, a `Cell` program, counterexamples for contravariant `&`, `&mut`, `Cell`, `fn` results or tuples, or any statement about maximality of struct variance.
- **[Reference]** The Rust Reference, "Subtyping and Variance" (`src/subtyping.md`), repository `rust-lang/reference`, commit `49115e0d52bf24fb2ff39a4ca03e70870bdce4ec` (committed 2026-01-26), https://github.com/rust-lang/reference/blob/49115e0d52bf24fb2ff39a4ca03e70870bdce4ec/src/subtyping.md. Contains: `r[subtyping.variance.builtin-types]` (`&'a T` covariant in `'a` and `T`; `&'a mut T` covariant in `'a`, invariant in `T`; `fn() -> T` covariant; `fn(T) -> ()` contravariant; `UnsafeCell<T>` invariant; `PhantomData<T>` covariant); `r[subtyping.variance.user-composite-types]` ("If the parameter is used in positions with different variances then the parameter is invariant."); `r[subtyping.variance.builtin-composite-types]` (outside a `struct`, `enum` or `union`, variance is checked at each location separately, with a tuple example).
- **[rustc variance]** rustc variance inference, repository `rust-lang/rust`, commit `94add9677e2de57a2e414350bedcd13f07426a5e` (committed 2026-11-12): `compiler/rustc_hir_analysis/src/variance/solve.rs` (greatest lower bound `glb` over the variance lattice, solutions initialised to `Bivariant`), `compiler/rustc_hir_analysis/src/variance/constraints.rs` (constraints generated at parameter occurrences via `xform`), `compiler/rustc_hir_analysis/src/variance/terms.rs` (lang-item variances: `phantom_data` covariant, `unsafe_cell_type` invariant), `compiler/rustc_type_ir/src/lib.rs` `Variance::xform` (citing "Figure 1" of Altidor et al. 2011; `(Invariant, _) => Invariant`, including `(Invariant, Bivariant)`; transcribed as `Variance.xform` in `ToyVariance/Examples.lean`). Prose comparison only (derived, modeling bridge).
- **[TAPL]** B. C. Pierce. Types and Programming Languages. MIT Press, 2002. ISBN 978-0-262-16209-8. Chapter 15 (Subtyping): Section 15.2 (the subtype relation) gives the arrow rule, contravariant in the argument and covariant in the result; Section 15.5 (subtyping and other features) discusses references and why `Ref T` must be invariant. Textbook source for the invariance of mutable references and the contravariance of function arguments, in a calculus without lifetimes.
- **[JLS SE 21]** J. Gosling, B. Joy, G. Steele, G. Bracha, A. Buckley, D. Smith, G. Bierman. - **[Altidor et al. 2011]** J. Altidor, S. S. Huang, Y. Smaragdakis. "Taming the Wildcards: Combining Definition- and Use-Site Variance." PLDI 2011, pp. 602–613. doi:10.1145/1993498.1993569. ## Revalidation

Requirements: `elan` (so that `lake` uses the toolchain pinned in `lean/lean-toolchain`) and `python3`. Run from the package directory.

1. Full revalidation (build, banned-token scan, axiom audit, statement and closure hashes):

   ```bash
   python3 support/revalidate.py .
   ```

   The script copies `lean/` to a temporary directory, runs `lake build`, scans the Lean sources for `sorry`, `admit`, `native_decide` and `axiom` declarations, generates a small Lean audit program that computes `Lean.collectAxioms` for every declaration of the library and, for every Lean name referenced by `results.json` or recorded in `audit/statements.json`, prints the `repr` of its type and its definition closure (types and values of every package-local constant reachable from the statement; theorem bodies excluded). It then checks that only `propext`, `Classical.choice` and `Quot.sound` occur and that the SHA-256 of each statement and closure equals the value in `audit/statements.json`. It prints `REVALIDATED` and exits 0 on success.

2. Manual build and axiom spot-check of the main results, without the script:

   ```bash
   cd lean
   lake build
   cat > /tmp/toyvariance_axioms.lean <<'EOF'
   import ToyVariance
   #print axioms Toy.Variance.table_le_safeTable_typing_sound
   #print axioms Toy.Variance.rustTable_subGen_implies_semSub
   #print axioms Toy.Variance.refMut_covariant_in_T_admits_dangling_read
   #print axioms Toy.Variance.fn_covariant_in_arg_admits_dangling_read
   #print axioms Toy.Variance.cell_covariant_admits_dangling_read
   #print axioms Toy.Variance.rustTable_entry_not_le_admits_dangling
   #print axioms Toy.Variance.rustTable_entry_sound_iff
   #print axioms Toy.Variance.phantom_entry_any_variance_sound
   #print axioms Toy.Variance.inferVar_admissible
   #print axioms Toy.Variance.bodyAx_le_inferVar_iff
   #print axioms Toy.Variance.bodyAx_inferVar_iff
   #print axioms Toy.Variance.bodyRule_le_inferVar_sound
   #print axioms Toy.Variance.bodyRule_not_le_inferVar_admits_dangling_of_dataBody
   #print axioms Toy.Variance.bodyRule_fnUnit_contra_admits_dangling_read
   #print axioms Toy.Variance.not_bodyRule_not_le_inferVar_unsound_of_phantomFree
   #print axioms Toy.Variance.rigidLftTable_not_le_safeTable_sound
   EOF
   lake env lean /tmp/toyvariance_axioms.lean
   ```

   Each line must report a subset of `[propext, Classical.choice, Quot.sound]`.

3. Cheapest check after an upstream change. The results are about the Lean model, not about rustc, so a new Rust or rustc release does not change them. To re-check the modeling bridge, compare the variance tables in the Rust Reference and the Rustonomicon (`src/subtyping.md`) and rustc's `Variance::xform` (`compiler/rustc_type_ir/src/lib.rs`) at the new revision with `rustTable` and `Variance.xform` quoted above. To re-check the results under a new Lean release, change `lean/lean-toolchain` and rerun step 1; statement hashes may change with a different `repr`, in which case compare the quoted statements instead.
