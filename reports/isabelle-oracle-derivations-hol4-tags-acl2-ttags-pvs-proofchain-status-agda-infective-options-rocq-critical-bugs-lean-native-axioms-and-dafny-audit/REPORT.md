# Recording, propagating, and auditing dependence on unchecked results: Isabelle oracle sets, HOL4 tags, HOL Light axioms, ACL2 trust tags, PVS proof chains, Agda infective options, Dafny audit, Rocq assumptions and critical bugs, and Lean native-evaluation axioms

## Summary

- **Three record architectures.** (1) *Carried records*: every inference rule unions a per-theorem record, so dependence on an unchecked result survives any derivation (Isabelle oracle sets in derivation bodies; HOL4 theorem tags). (2) *Computed records*: nothing is carried in the theorem object; an audit command walks the dependency graph of a declaration on demand (Rocq `Print Assumptions`, Lean `#print axioms`, PVS proof-chain status). (3) *Boundary records*: dependence is recorded per book or module and checked when that unit is certified or imported (ACL2 certificate annotations and trust tags; Agda option compatibility; Lean `lake check` / `lake comparator` axiom allowlists). Dafny's `audit` is a fourth, weaker shape: a per-declaration *syntactic* finding list that is not propagated to callers.
- **Native or compiled evaluation is admitted in three different ways.** Rocq (`vm_compute`, `native_compute`) and the HOL4 kernel `compute` rule treat it as part of the trusted kernel: no assumption is recorded, and Rocq's `Print Assumptions` has no case for it. Lean at the examined head and in release v4.35.0 instead admits each `native_decide`/`bv_decide` result as a fresh *per-use auxiliary axiom* `<decl>._native.<tactic>.ax_…`, which `#print axioms` reports by name. The older Lean route (`Lean.reduceBool`, `Lean.ofReduceBool`, axiom `Lean.trustCompiler`) is present but deprecated in v4.29.1 and absent from v4.35.0 (`Unknown identifier`) — both observed by execution.
- **Records degrade at serialization boundaries.** HOL4 writes only the oracle strings of a tag to theory files, drops the axiom part, and adds a `DISK_THM` pseudo-oracle on reload. Lean at the examined head serializes a precomputed per-declaration axiom list into each `.olean`, and downstream `#print axioms` reads that table instead of walking imported bodies (exported bodies may be stripped). ACL2 certificates record `:skipped-proofsp` and `:axiomsp` only for the book itself (sub-books are found through the include-book post-alist), while `:ttags` include sub-books.
- **Audit commands report the admission point, not the root cause.** In a Lean v4.35.0 probe, a definition whose `@[implemented_by]` implementation disagrees with its logical body yields a kernel-accepted proof of `False` through `native_decide`; `#print axioms` names only the auxiliary axiom, never the `implemented_by` attribute. An upstream Dafny test expectation shows that `{:axiom}` on a method hides its `assume` statements and a bodiless `forall … ensures y != y` from the audit report. PVS `proved?` is true for any formula with a proof in a `<pvs-path>/lib/` library when viewed from another workspace.
- **Incident records.** Rocq's `dev/doc/critical-bugs.md` (pinned) has 103 entries; five describe a failure of `Print Assumptions` or of the independent checker's output to report a dependence, and two more describe trusted native-code evaluation accepting `False` with no assumption reported. Label counts (2026-11-21, GitHub search): `agda/agda` `false` 131 items (103 issues), `rocq-prover/rocq` `kind: inconsistency` 157 items (93 issues), `leanprover/lean4` `soundness` 3 items (all pull requests). Of the 93 Rocq labelled issues, 70 are referenced by number in the catalogue.

## Applicability

The findings describe nine proof systems at the exact source revisions listed in `REPORT.json`; they relate as a *comparison* of how each records and reports dependence on unchecked results. All repository pins were resolved through the GitHub API on 2026-11-21 and all quoted lines are from those revisions.

- **Executed:** only Lean. Release toolchains v4.35.0 (tag commit `eb6cafb7290e8bd5f2937522d8d804f58f02bafc`) and v4.29.1 (tag commit `f72c35b3f637c8c6571d353742168ab66cc22c00`) were run on an x86-64 Linux host (96 logical cores, Intel Xeon 2.60 GHz, about 236 GiB RAM). ## Findings

### 1. Carried records in LCF-style kernels

**Isabelle/Pure: oracle sets in derivations.** A theorem carries a derivation whose body is
`PBody {oracles: ((string * Position.T) * term option) Ord_List.T, thms: (serial * thm_node) Ord_List.T, zboxes, zproof, proof}` (`src/Pure/proofterm.ML:28-33`). Every two-premise rule goes through `deriv_rule2`, which computes `val oracles' = Proofterm.union_oracles oracles1 oracles2` (`src/Pure/thm.ML:791-807`, union at line 800); sort-constraint solving also unions the oracle sets of the class-relation and arity theorems it uses (`thm.ML:1052-1086`). `Thm.add_oracle (b, oracle_fn)` registers a name in the theory's oracle name space and returns an invocation function whose result has derivation `make_deriv [] [oracle] [] [] zproof proof` (`thm.ML:1237-1277`); the recorded element is `((name, Position.thread_data ()), SOME prop)` when `Proofterm.oracle_enabled proofs`, else `((name, Position.none), NONE)` (`thm.ML:1250-1253`), and `oracle_enabled proofs = not (proofs = 0 orelse proofs = 4)` (`proofterm.ML:494`). When a theorem is *named* (boxed as a `PThm` node), its oracles move inside the node and the outer body becomes `{oracles = [], thms = [thm], …}` (`proofterm.ML:2171`). Hence the transitive set is recovered by a walk: `Thm_Deps.all_oracles` folds over `thms`, joining each node's future body (`src/Pure/thm_deps.ML:23-33`), and the Isar command `thm_oracles` — "print all oracles used in theorems (full graph of transitive dependencies)" — prints it (`src/Pure/Pure.thy:1385-1393`). `sorry` is an oracle: `Skip_Proof` registers `Thm.add_oracle (Binding.make ("skip_proof", …), I)` and `cheat_tac` invokes it (`src/Pure/skip_proof.ML:28-42`); `Thm_Deps.has_skip_proof` tests for that name (`thm_deps.ML:35-36`). The `cheating` method refuses unless `Interactive.enabled () orelse Config.get ctxt quick_and_dirty` ("Cheating requires interactive or quick_and_dirty mode!", `src/Pure/Isar/method.ML:155-158`); `quick_and_dirty` and `skip_proofs` default to `false` (`etc/options:136-139`).
Basis: source.

**HOL4: tags.** `datatype tag = TAG of dep * string list * string Nonce.t list` — dependencies, oracle strings, axiom nonces (`src/prekernel/Tag.sml:25`). Kernel rules merge tags, e.g. modus ponens builds `Tag.merge o1 o2` (`src/thm/std-thm.ML:462`); `Tag.merge` takes the sorted union of oracle strings and the union of axioms (`Tag.sml:60-74`). `mk_oracle_thm tg (asl,c)` asserts boolean type, asserts `tg <> "DISK_THM"` ("invalid user tag"), and builds the theorem with `Tag.read tg` (`std-thm.ML:1237-1240`); `val mk_thm = mk_oracle_thm "MK_THM"` (`std-thm.ML:1243`). The `cheat` tactic is `Thm.mk_oracle_thm "cheat" g`, and the comment says "The tag is what Theory reads to mark a theory CHEAT, so it has to stay \"cheat\"" (`src/1/Tactical.sml:426-435`); `Theory.oracle_string_of` classifies a saved theorem as `CHEAT`, `FAST-CHEAT` (tag `fast_proof`) or `ORACLE thm` after removing `DISK_THM` (`src/postkernel/Theory.sml:620-627`). The documentation states that the tag "propagates in a hereditary fashion to any theorem derived from the tagged theorem" and "It is impossible to detach a tag from a theorem" (`help/Docfiles/Thm.mk_oracle_thm.smd:33-34,77`).
*Serialization:* "In a theory file, the list of oracles gets dumped out as a list of strings. The axioms are not currently dumped" (`Tag.sml:82-89`); `pp_to_disk` writes `(dep, oracle list)` only (`Tag.sml:91-116`). On reload `disk_thm` builds the tag with `Tag.read_disk_tag`, which adds `"DISK_THM"` to the oracle list (`std-thm.ML:1479-1484`, `Tag.sml:76-77`). A comment in `Theory.sml:540-543` confirms that `disk_thm` strips axiom nonces, while proof-trace replay keeps them.
*Doc/source discrepancy:* `Tag.read.smd:17` says the string "must be an alphanumeric", but `Tag.read` only rejects strings containing characters that fail `Char.isPrint` (`Tag.sml:45-51`).
Basis: source + documentation.

**HOL Light: a global axiom list, no per-theorem record.** `type thm = Sequent of (term list * term)` carries no tag (`fusion.ml:104`). `new_axiom tm` conses the new theorem onto `the_axioms`, and `axioms()` returns the list (`fusion.ml:571-579`). A user can see which axioms exist, not which a theorem uses. `compute.ml` (header: "Translated from HOL4 computeLib") builds its results with kernel rules such as `TRANS`, `MK_COMB`, `REFL` and `BETA_CONV`; a text search found no `new_axiom`, `mk_thm` or `Sequent` in it. Harrison's overview (DOI 10.1007/978-3-642-03359-9_4) describes the system; no claim here depends on its text beyond bibliographic identity.
Basis: source.

**Reconstruction versus oracle admission of an external solver.** Böhme and Weber's abstract (publisher page, DOI 10.1007/978-3-642-14052-5_14) states that they "present independent reconstruction of these proofs in the theorem provers Isabelle/HOL and HOL4", that their implementations "outperform previous LCF-style proof checkers for SMT, often by orders of magnitude", and that "LCF-style proof reconstruction can be faster than proof search in Z3." Reconstructed results carry no oracle, so the carried record stays empty; the alternative (`mk_oracle_thm` in HOL4, `Thm.add_oracle` in Isabelle) leaves a permanent tag/oracle entry.
Basis: documentation (abstract) + derived.

### 2. Boundary and on-demand records

**ACL2: trust tags and skipped proofs, recorded per book.** `defttag` "is essentially equivalent to `(table acl2-defaults-table :ttag :tag-name)`", is local to books and `encapsulate`, and attribution "is at the level of [books]; a book's [certificate] contains a list of ttags that are active in that book, or in a book that is included (possibly [local]ly)…" (`doc.lisp:29541-29563`, ANSI colour codes stripped). `certify-book` is illegal while a ttag is active (`doc.lisp:29586-29588`). Allowed ttags are governed by the `:ttags` argument: for `include-book` "an omitted `:ttags` argument or an argument of `:default` is treated as `:all`, except that warnings will occur…; but for `certify-book`, an omitted ttags argument is treated as nil" (`doc.lisp:29636-29642`). The documentation tells a "certifier" to re-certify user books from scratch and search for every `TTAG NOTE` line (`doc.lisp:29610-29617`). `skip-proofs` is "a quick way to introduce unsoundness"; certification of books containing it needs `:skip-proofs-okp t`, and including such books prints a warning that is an error if `:skip-proofs-okp` is nil (`doc.lisp:142559-142656`). `certify-book` defaults `:defaxioms-okp` and `:skip-proofs-okp` to nil (`doc.lisp:18065-18073`); `include-book` defaults all three `-okp` arguments to t, which means "a warning is printed but the processing to load the book is allowed to proceed" (`doc.lisp:57170-57178`). In source, the certificate annotations are `(cons :skipped-proofsp skipped-proofsp)`, `(cons :axiomsp axiomsp)` and `(cons :ttags ttags-seen)`, with comments that the first two cover "this book (not subbooks)" (`other-events.lisp:18522-18532`); sub-book skipped proofs are found by `skipped-proofsp-in-post-alist` over the include-book post-alist (`other-events.lisp:13508-13525`), and `chk-cert-annotations` turns each annotation into a warning or error according to the `-okp` keywords (`other-events.lisp:13246-13305`). Kaufmann and Moore (DOI 10.1023/A:1026517200045) is the design reference for books and encapsulation; no claim here depends on its text.
Basis: documentation + source.

**PVS: proof-chain status, computed on demand.** `pc-analyze` on a formula collects `refers-to`, `proof-refers-to`, assuming TCCs and possible judgements, then sorts dependencies into proved, unproved, axioms, definitions, assumptions (`src/status-cmds.lisp:851-881`). The chain is "COMPLETE" when there are no unproved dependencies and the formula is proved; otherwise "INCOMPLETE" with the unproved list; axioms are listed separately ("depends on the following axioms") and do not make a chain incomplete; possible judgements are an over-approximation ("may depend on the following judgements") (`status-cmds.lisp:886-929`; `pc-complete` returns `"circular"`, `"complete"` or `"incomplete"` at lines 623-658). Status strings: `"proved - complete"`, `"proved - incomplete"`, `"unchecked"`, `"unfinished"`, `"untried"`, `"proved - by mapping"` (`status-cmds.lisp:579-621`); `fe-proof-status-string` downgrades a stored complete/incomplete status to `"unchecked"` when the proof file is not valid (`status-cmds.lisp:584-592`). Entry points: `status-proofchain-theory`, `status-proofchain-pvs-file`, `status-proofchain-importchain` (`status-cmds.lisp:493-530`).
*Trusted libraries:* `proved?` returns true when the stored status is proved, when a mapped formula's source is proved, or when `(trusted-library-decl? fdecl)` (`src/pvs.lisp:2045-2052`); that predicate is true when the declaration has a proof and lives in a library under `<pvs-path>/lib/` that is not the current workspace (`src/context.lisp:1735-1772`, comment: "Libraries in <pvs-path>/lib/ … are trusted, as the core prelude is"). PVSio attachments carry a `primitive` field, "T when this attachment a primitive, i.e., trusted by the PVS theorem prover" (`src/PVSio/defattach.lisp:31`); whether proofs using such evaluation are marked in proof-chain output was not examined.
Basis: source.

**Agda: infective and coinfective options, recorded per module.** The manual: an *infective* option "if used in one module, must be used in all modules that depend on this module"; a *coinfective* option "if used in one module, must be used in all modules that this module depends on" (`doc/user-manual/tools/command-line-options.rst:2638-2689`). Implementation: `infectiveOption` checks `opt imported <= opt current`; `coinfectiveOption` checks `opt current <= opt imported` (`src/full/Agda/Interaction/Options/Base.hs:951-990`); the table `infectiveCoinfectiveOptions` lists `--safe`, `--without-K`, `--no-universe-polymorphism`, `--no-cumulativity`, `--level-universe` as coinfective and `--cubical…`, `--guarded`, `--irrelevance`, `--prop`, `--two-level`, `--rewriting`, `--local-rewriting`, `--sized-types`, `--guardedness`, `--flat-split`, `--polarity`, `--cohesion`, `--erasure`, `--erased-funext`, `--erased-propext`, `--erased-quotients`, `--erased-matches` as infective (`Base.hs:998-1042`). `checkOptionsCompatible` compares the current options with the imported interface's `iOptionsUsed` and raises `InfectiveImport` or `CoInfectiveImport` (`src/full/Agda/Interaction/Imports.hs:911-930`); both are in `errorWarnings` (`src/full/Agda/Interaction/Options/Warnings.hs:166-194`), so they are fatal by default. `--safe` disables "postulates, unsafe OPTIONS pragmas and `primTrustMe`" (`command-line-options.rst:1237-1244`); `unsafePragmaOptions` enumerates the unsafe flags, including `--type-in-type`, `--no-termination-check`, `--no-positivity-check`, `--sized-types`, `--rewriting`, `--cumulativity`, `--allow-exec` (`Base.hs:873-899`).
*Doc/source discrepancy:* the manual's lists omit cumulativity entirely, while the source makes `--no-cumulativity` coinfective; the manual's coinfective `--no-guardedness`/`--no-sized-types` are the contrapositive of the source's infective `--guardedness`/`--sized-types` (logically equivalent).
Basis: documentation + source.

**Dafny: `audit`, per declaration and syntactic.** The categories are the static members of `AssumptionDescription` (`Source/DafnyCore/Auditor/Assumption.cs:13-112`): explicit `{:axiom}`; `{:verify false}`; `{:extern}` function; `{:extern}` with `requires` / with `ensures`; `assume` and `assume {:axiom}` statements; `decreases *`; `{:termination false}`; `@AssumeCrossModuleTermination`; bodiless `forall` and bodiless loop; `{:assume_concurrent}` on reads/modifies; bodiless ghost/compiled declaration with `ensures`; temporary `{:only}` and `@VerifyOnly`. Four descriptions are `IsExplicit: true` (`{:axiom}`, `{:assume_concurrent}`, `{:only}`, `@VerifyOnly`). `AuditReport.AddAssumptions` keeps *only* the explicit findings of a declaration if it has any (`AuditReport.cs:38-45`). `BuildReport` skips members whose origin is an include directive ("Don't audit included code", `AuditReport.cs:176-200`). Bodiless declarations are reported only in concrete modules and only without `{:extern}`/`{:axiom}` (`Function.cs:67`, `MethodOrConstructor.cs:56`); auto-generated `{:axiom}`/`{:verify false}` are not reported (`Declaration.cs:63-70`). The upstream test `TestAuditor.dfy:135-146` declares `method {:axiom} AxiomWithStuffInIt` containing `assume x > 0;`, `assume {:axiom} x > 10;`, a bodiless `forall y : int ensures y != y` and a bodiless loop; its expected audit output contains a single finding for it, "Declaration has explicit `{:axiom}` attribute" (`TestAuditor.dfy.expect:31`; total "24 findings", line 37). Findings are not propagated to callers.
Basis: source + upstream test expectation (not executed here).

### 3. Native and compiled evaluation

**Rocq: trusted as kernel conversion.** `vm_compute` and `native_compute` add "a single explicit cast to the proof term to tell the kernel which reduction engine to use" (`doc/sphinx/proofs/writing-proofs/equality.rst:480-485`). `typing_flags` contains `enable_VM` ("If [false], all VM conversions fall back to interpreted ones") and `enable_native_compiler` ("If [false], all native conversions fall back to VM ones") (`kernel/declarations.mli:97-101`), but `Assumptions.assumptions` reports only unchecked guard, universes, eliminations, positivity, impredicative Set, UIP, indices-not-mattering, rewrite rules, unchecked opaque bodies, unreachable opaque bodies, axioms, and (optionally) opaque/transparent constants — no VM or native case (`vernac/assumptions.ml:381-510`). The manual matches: `Print Assumptions` reports axioms, parameters, variables, indices-not-mattering and disabled typing flags (`doc/sphinx/proof-engine/vernacular-commands.rst:465-473`); opaque proofs not checked under `Skip Qed Typecheck` are reported as axioms (`:490-492`), and bodies unavailable under `-vos` are reported as "Opaque proofs that could not be accessed" (`:478-489`). The checker's `set_local_flags` forbids overriding `enable_VM`/`enable_native_compiler` (`checker/checkFlags.ml:45-67`) and recompiles bytecode only when `-bytecode-compiler` is set (`checkFlags.ml:69-72`, `checker/mod_checking.ml:275-282`). Grégoire–Leroy (DOI 10.1145/581478.581501) and Boespflug–Dénès–Grégoire (DOI 10.1007/978-3-642-25379-9_26) are the designs of the VM and native machines.
Basis: source + documentation.

**HOL4: the kernel `compute` rule.** `Thm.compute` returns `make_thm Count.Compute (tag1, empty_hyp, eqn)` where `tag1` merges only the tags of the characteristic and code equations (`std-thm.ML:1532-1556`); evaluation by `Compute.term_compute` (Abrahamsson and Myreen, `src/thm/Compute.sig`) adds no tag of its own.
Basis: source.

**Lean: per-use auxiliary axioms.** `nativeEqTrue` compiles the closed Boolean in an auxiliary definition inside `withoutModifyingEnv`, evaluates it with `unsafe evalConst Bool auxDeclName`, and on `true` adds `Declaration.axiomDecl {name := auxAxiomName, type := e = true, …}` named by ``mkAuxDeclName <| `_native ++ tacticName ++ `ax`` (`src/Lean/Meta/Native.lean:37-87`; module doc: "asserting the result of that computation as an axiom", lines 18-22). On this path the kernel never runs compiled code; it only checks the axiom's type. In v4.29.1 the older route still exists but is deprecated "since 2026-02-01": `axiom trustCompiler : True`, `opaque reduceBool … := have := trustCompiler; b`, `axiom ofReduceBool (a b : Bool) (h : reduceBool a = b) : a = b` (`src/Init/Core.lean:2376-2435` at v4.29.1), with kernel support keyed on `Lean.reduceBool` (`src/kernel/type_checker.cpp:538-556` at v4.29.1). None of these names occurs in `Init/Core.lean`, `Init/Prelude.lean` or `type_checker.cpp` at v4.35.0 (text search).
*Axiom collection:* `collect` walks constants, adding `axiomInfo` names and recursing through types, values and constructors (`src/Lean/Util/CollectAxioms.lean:37-74`). For an imported constant it first consults `extFind?` (`:42-44`): the persistent extension `exportedAxiomsExt` whose "Entries are computed once by `beforeExportFn` when the olean is serialized … Downstream modules look up pre-computed entries for imported declarations, so axiom collection never crosses module boundaries" (`:113-146`). The upstream test package `tests/pkg/collectAxioms/` checks propagation through a definition "whose body is stripped" on export.
*Build-level gates:* `Lake.Check.checkAxioms` walks used constants from the target theorems over an exported environment and throws `Illegal axiom detected` for any axiom outside `legalAxioms` (`src/lake/Lake/Check/Axioms.lean:30-55,76-94`). `lake check` "replays the result through the kernel, erroring on any use of non-standard axioms", with `standardAxioms = #[propext, Classical.choice, Quot.sound]` (`src/lake/Lake/CLI/Check.lean:964-980`; help text `src/lake/Lake/CLI/Help.lean:571-620`). `lake comparator` takes a mandatory `permitted_axioms` list and can run `leanchecker-paranoid`, `lean4lean`, `nanoda`, `con-leche` and `con-ron` with `--paranoid` (`Help.lean:417-500`).
Basis: source + execution (below).

### 4. Execution probe (Lean)

Files: `support/lean-probe/` (two-module Lake project) and `support/lean-probe-v4291/ReduceBool.lean`; raw outputs under `support/outputs/`. `Probe/Base.lean` defines: **A** `2 ^ 20 % 7 = 4` by `native_decide`; **B** the same by `decide`; **C** `1 + 1 = 3 := sorry`; **D** from `axiom myAx : 2 + 2 = 5`; **E** `@[implemented_by flagImpl] def flag (_ : Nat) : Bool := false` with `flagImpl _ := true`, then `E1 : flag 0 = false := rfl`, `E2 : flag 0 = true := by native_decide`, `E3 : False` from E1 and E2; **F** depends on A through a definition and an intermediate theorem; **G** `Classical.em`. `Downstream.lean` imports the compiled module and adds **H** from F.

| Theorem | `#print axioms` in `Base.lean` (v4.35.0) | after import from `.olean` |
|---|---|---|
| A | `[A._native.native_decide.ax_1_1]` | same |
| B | does not depend on any axioms | same |
| C | `[sorryAx]` | same |
| D | `[myAx]` | same |
| E1 | does not depend on any axioms | — |
| E2, E3 | `[E2._native.native_decide.ax_1_1]` | same |
| F | `[A._native.native_decide.ax_1_1]` | same; new H also `[A._native.native_decide.ax_1_1]` |
| G | `[propext, Classical.choice, Quot.sound]` | — |

Basis: execution (Lean 4 v4.35.0). Observations: (a) the record is per use (two distinct auxiliary axioms, named after the *declaration* containing the call) and propagates transitively and across `.olean` import; (b) **E3 is a kernel-accepted proof of `False`** whose report names only the auxiliary axiom — the report does not identify `implemented_by` as the cause; (c) the kernel accepts E1 by reduction of the logical body, so the inconsistency exists only with the auxiliary axiom.

`ReduceBool.lean` on v4.29.1: `R : k = true := Lean.ofReduceBool k true rfl` reports `[Lean.ofReduceBool, Lean.trustCompiler]`; the same `implemented_by` pair via `ofReduceBool` gives `RE3 : False` also reporting `[Lean.ofReduceBool, Lean.trustCompiler]`; `native_decide` reports `[N._native.native_decide.ax_1_1]`. On v4.35.0 the same file fails with ``error(lean.unknownIdentifier): Unknown identifier `Lean.ofReduceBool` ``. Basis: execution (Lean 4 v4.29.1 and v4.35.0).

`lake check` (v4.35.0, sandboxed) on the probe exits 1 with `Axiom 'sorryAx' is not permitted; it is used by 'C'`, likewise for both auxiliary axioms and `myAx`, while also printing `Lean default kernel accepts the solution` and `Uses axioms: Classical.choice, propext, Quot.sound, sorryAx, A._native.native_decide.ax_1_1, E2._native.native_decide.ax_1_1, myAx`. Basis: execution. The gate is a *project-wide* allowlist over the export: the kernel replay alone accepts the inconsistent module.

`lake check --paranoid` (v4.35.0) on the same project: `Lean paranoid kernel accepts the solution`; `lean4lean` reports `checked 57932 declarations` and accepts; `nanoda` panics with `declaration not found in infer_const, sorryAx` (likewise for both auxiliary axioms and `myAx`) and is reported as rejecting; `con-leche` prints `not implemented yet: non-standard axiom (myAx)` and `con-ron` prints `declined: non-standard axiom`, both "rejected"; the run ends with `error: nanoda exited with 101`. Basis: execution. So two independent kernels accept the module that proves `False` (correctly: it is well typed relative to its axioms), and the three "rejections" are unsupported-feature refusals, not detections of the inconsistency. ### 8. Comprehensibility (C1) and conceptual simplicity (C2)

C1. The fewest concepts a reader must hold occur in Lean (everything unchecked is an axiom; one command) and in HOL4 (one tag); the cost is lost provenance: the Lean report names the *admission point* (`E2._native…`) rather than the cause (`implemented_by`), and HOL4's `DISK_THM` conflates "loaded from disk" with "used an oracle". Rocq's report mixes axioms, typing-flag exemptions and unreadable opaque bodies, which is more informative but requires knowing that VM/native trust is deliberately absent. Dafny's explicit-only filtering and ACL2's `include-book` warn-by-default are the main hidden footguns found (non-local reasoning: the reader must know a default or a filter rule).
Basis: derived.

C2. A single *assumption set* per declaration — a join-semilattice of entries `(kind, name, origin)` unioned by every rule and by import — models Isabelle oracle sets, HOL4 tags, Lean axiom closures, ACL2 `:ttags`, and Agda infective options (taint flows to dependents). It does **not** model coinfective options such as `--safe`: those are *guarantees required of dependencies*, i.e. a meet that flows the other way. Allowlist gates (ACL2 `:ttags`, Lean `lake check`/`comparator`, Agda `--safe`) are then a filter over the taint set at a trust boundary. Under this model the observed defects are ordinary cases: HOL4's on-disk axiom drop and ACL2's own-book-only annotations are non-homomorphic serialization; Dafny's audit lacks the union step; Rocq/HOL4 native trust and PVS library trust are entries never inserted. This is a conceptual model, not a mechanized result.
Basis: derived.
