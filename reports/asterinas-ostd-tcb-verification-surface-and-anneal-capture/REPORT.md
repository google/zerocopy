# Asterinas Framekernel TCB Surface, OSTD Verification Evidence, and Anneal MIR Capture Fit

## Summary

Asterinas ([`asterinas/asterinas`](https://github.com/asterinas/asterinas), pinned at `a97b435bf5b95f5839cc8acaa773e31463f04602`, `v0.19.0`) structures an entire Linux-compatible OS kernel around the **framekernel** split: a relatively small, unsafe-containing OS framework (`ostd`: `267` source files / `49,715` total lines / `29,834` code lines / `863` `unsafe {}` blocks in `ostd/src`, plus `35` files / `5,217` total lines / `32` `unsafe {}` blocks in `ostd/libs`) beneath `1,175` files (`209,913` total / `150,176` code lines) of kernel subsystems and drivers marked `#![deny(unsafe_code)]` with `0` `unsafe` blocks, tokens, or `asm!`. Unlike Rust for Linux (`torvalds/linux`), which bridges `439` `rust_helper_*` C shims over FFI, Asterinas contains no C subsystem kernel and executes across a pure-Rust plus inline/external-assembly TCB (`76` `asm!`, `33` `global_asm!`, `38` `extern "C"` declarations in `ostd/src`).

Evaluating `ostd` against Anneal ([`google/zerocopy`](https://github.com/google/zerocopy) `anneal/` at `8d60e1e085bdbce3d84e88a68b2bfcfcc6f8e0de`) and Asterinas's own Verus fork ([`asterinas/vostd`](https://github.com/asterinas/vostd) at `51b4459029c8f9dfa6e86fff26d13c49bfc29b51`) yields four central findings:

1. **Architectural boundary alignment vs. macro-bypass caveat:** `ostd` cleanly separates safe OS clients (`kernel`) from unsafe primitives, matching Anneal's safe-client soundness assumption (`what-soundness-means.md`), except that `kernel` uses `#![deny(unsafe_code)]` (`33` crates) rather than `#![forbid(unsafe_code)]` (`0` crates), leaving open proc-macro bypass vectors tracked in https://github.com/asterinas/asterinas/issues/2006.
2. **Immediate Profile v2 arithmetic feasibility (`frame_to_meta` verified end-to-end):** Scalar `usize`, overflow-checked arithmetic, `Option<T>`, `Range<usize>`, `checked_add`, `saturating_add`, and `--panic abort` modeling on `google/zerocopy@8d60e1e085bdbce3d84e88a68b2bfcfcc6f8e0de` (`Trusted.MirSemantics.SafeContractV2` / `CoreContracts`) directly match leaf MM and bounds-checking helpers in `ostd::mm` and `ostd::mm::frame::meta::mapping`. An end-to-end Profile v2 proof unit over the extracted `frame_to_meta` body compiles and passes Lean 4 audit (`status = selected_unit_verified`, `taint_reasons = []`, `axioms = ["propext"]`, `exactType = true`), proving both exact metadata virtual-address computation for `paddr < 2^51` and clean abort behavior under `-Coverflow-checks=yes` for `paddr >= 2^51`.
3. **Six structural gaps blocking direct whole-`ostd` capture:** At `google/zerocopy@8d60e1e085bdbce3d84e88a68b2bfcfcc6f8e0de`, direct capture of unmodified `ostd` is blocked by: (i) compiler pin drift (`asterinas` pins `nightly-2026-11-16` using `btree_cursors`, `riscv_ext_intrinsics`, `proc_macro_diagnostic`, and `unwinding-0.2.11`'s `core::intrinsics::abort_immediate`, which fail on Anneal's pinned `rustc 1.98.0-nightly`), (ii) missing multi-crate/bare-metal driver support (`--extern`, `-Zbuild-std=core,alloc`, named `--target` triples, `#[panic_handler]` + `#[alloc_error_handler]`), (iii) unmodeled Rust types and core calls (`struct`s, `Result`, `ControlFlow` from `?`, `ManuallyDrop`, `dyn Trait`, `ilog2`, `is_power_of_two`), (iv) unmodeled concurrency/interior mutability (`Atomic<T>`, `UnsafeCell`, `SyncUnsafeCell`, and Profile v2's `!bodyMixesRefsAndRawPtrsV2` ban), (v) hardware/linker constructs (`read_volatile`, `asm!`, `global_asm!`, `#[linkage = "weak"]`, multi-static ELF link sections), and (vi) `panic = "unwind"` default Cargo profiles in `dev`/`release`/`ktest` (only `release-lto` uses `panic = "abort"`).
4. **Why MIR-level verification complements `vOSTd`:** `asterinas/vostd` invests `26,011` LOC of Verus specifications in `ostd/specs/` and `117` `verus!` blocks in `ostd/src`, uncovering `13` formal-verification bugs tracked in https://github.com/asterinas/vostd/issues/645. Yet `ostd/src` in `vostd` still relies on `100` `external_body`, `29` `assume(`, and `4` `admit(` escapes and skips interrupt/hardware guards (`tlb.rs`), while independent Rust UB audits (https://github.com/asterinas/asterinas/issues/3920, https://github.com/asterinas/asterinas/issues/4252, https://github.com/asterinas/asterinas/issues/4262, https://github.com/asterinas/asterinas/issues/4265, https://github.com/asterinas/asterinas/issues/4271) uncovered `34` distinct soundness bugs involving `Send`/`Sync` markers, AP CPU-local alignment, Tree Borrows provenance, unwinding through `GlobalAlloc`, `Swap`-mediated UAF, and multi-static slice formation—classes that require Rust MIR/memory/concurrency/linker models rather than pure algorithmic specs.

## Findings

### 1. Framekernel Architecture, OSDK Build Topology, and Complete TCB Census

Basis: source + execution (`support/probe_asterinas_surface.py`)

Asterinas organizes the kernel into three distinct trust/build layers (`Cargo.toml`, `osdk/`, `book/src/ostd/soundness/`):

1. **OS Framework (`ostd` + `ostd/libs`):** Safe public abstractions enclosing unsafe hardware, memory, SMP, RCU, IRQ, and synchronization code. `book/src/ostd/soundness/what-soundness-means.md` defines `ostd` soundness explicitly: arbitrary safe downstream Rust crates—together with arbitrary userspace virtual memory faults and external peripheral behavior—must never trigger Rust UB or violate framework invariants. In `v0.19.0`, `ostd/src/bus/` was moved out of `ostd/` into `kernel/core/comps/*` (whereas `vostd` retains a `9`-file `bus/` module).
2. **Safe Kernel (`kernel/`):** `33` crates including `aster-core` (`kernel/core`) and `asterinas` (`kernel`), implementing POSIX/Linux semantics, filesystems, networking, and VirtIO/NVMe/PCI/DRM drivers atop `ostd`. Every inspected crate sets `#![deny(unsafe_code)]` (`33` files), yielding `0` `unsafe` blocks/functions/impls/traits and `0` `asm!`/`global_asm!`/`extern "C"` across `1,175` `.rs` files (`209,913` lines). Bare-metal `kernel/` crates use `#![deny(unsafe_code)]` rather than `#![forbid(unsafe_code)]` (`0` crates) because `ostd-macros` (`#[ostd::main]`, `#[ostd::global_frame_allocator]`, `#[ostd::global_heap_allocator]`, `#[ktest]`) expands Edition-2024 `#[unsafe(no_mangle)]` and `#[unsafe(link_section = ".ktest_array")]` inside downstream crates, which leaves open crate-level bypass vectors tracked in https://github.com/asterinas/asterinas/issues/2006. Separately, `#![feature(rustc_private)]` appears *exclusively* in `kernel/libs/comp-sys/cargo-component/{src/driver.rs:6, analysis/src/lib.rs:4}`, a standalone host CLI Cargo workspace not linked into the bare-metal `asterinas` kernel closure.
3. **OSDK Wrapper & Weak-Linkage Policy Injection (`osdk/`):** `66` files (`10,570` lines, `0` `unsafe`) that synthesize a top-level `#![no_std] #![no_main] #![feature(linkage)]` wrapper crate (`osdk/src/base_crate/main.rs.template`) depending on the target kernel crate. Crucially, `osdk` compiles with `-Zbuild-std=core,alloc,compiler_builtins -Zbuild-std-features=compiler-builtins-mem` (`osdk/src/commands/util.rs:7-10`), injects per-arch bare-metal targets (`x86_64-unknown-none`, `riscv64imac-unknown-none-elf`, `loongarch64-unknown-none-softfloat`, `aarch64-unknown-none-softfloat`), passes `-C link-arg=-T<arch>.ld -C relocation-model=static -C relro-level=off -C force-unwind-tables=yes -C no-redzone=y` (`osdk/src/commands/build/mod.rs:217-246`), and injects `#[linkage = "weak"]` globals `__GLOBAL_FRAME_ALLOCATOR_REF`, `__GLOBAL_HEAP_ALLOCATOR_REF`, `__global_heap_slot_info_from_layout`, and `#[panic_handler]` forwarding to `__ostd_panic_handler`.

### 2. Toolchain, Feature-Gate, Panic-Profile, and Bare-Metal Build Compatibility

Basis: execution (`support/probe_asterinas_surface.py`, direct `rustc` & `cargo check` probes) + source (`Cargo.toml`, `ostd/Cargo.toml`, `ostd/src/lib.rs`, `ostd/src/panic.rs`)

1. **Toolchain Pin Drift (`nightly-2026-11-16` vs. `1.98.0-nightly` 2026-05-30):** Asterinas enables `10` unstable feature gates in `ostd/` (`alloc_error_handler`, `btree_cursors`, `core_intrinsics`, `linkage`, `maybe_uninit_fill`, `min_specialization`, `negative_impls`, `proc_macro_diagnostic`, `ptr_metadata`, `sync_unsafe_cell`), plus `cfg_attr` target-specific gates (`riscv_ext_intrinsics`, `iter_advance_by`, `iter_next_chunk`, `macro_metavar_expr`), `25` unstable features across bare-metal `kernel/` crates, and `#![feature(rustc_private)]` solely in the host-only `cargo-component` CLI (`kernel/libs/comp-sys/cargo-component/{src/driver.rs:6, analysis/src/lib.rs:4}`). Compiling each feature independently under Anneal's pinned `rustc 1.98.0-nightly` (`f8a08b688cbe`) passes `23` features (`rc=0`), but fails `9` features (`error[E0635]: unknown feature`) because they were introduced or renamed between May and November 2026:
   - In `ostd/`:
     - `btree_cursors`: `2` call sites in `1` file (`ostd/src/util/range_alloc.rs:121,134`, `upper_bound_mut`/`lower_bound_mut`).
     - `proc_macro_diagnostic`: `2` `Diagnostic::spanned` sites in `ostd/libs/ostd-macros/src/lib.rs:511,533` (used only for `#[ktest]` redundant-prefix lints).
     - `riscv_ext_intrinsics`: `3` `core::arch::riscv64::sfence_vma_*` sites in `ostd/src/arch/riscv/mm/mod.rs:91,104,109`, gated behind `#![cfg_attr(target_arch = "riscv64", feature(riscv_ext_intrinsics))]` (`ostd/src/lib.rs:12`) and therefore inactive on `x86_64` and `aarch64`.
   - In `kernel/`: `alloc_io`, `btree_cursors`, `clone_from_ref`, `linked_list_cursors`, `linked_list_retain`, `proc_macro_diagnostic`, `thin_box`, `unique_rc_arc`.
   - **`core_intrinsics` (`8` call sites across `4` `ostd` files):** `ostd/src/mm/page_table/mod.rs:607,615` (`transmute_unchecked`), `ostd/src/mm/io/mod.rs:440,699` (`unaligned_volatile_{load,store}`), `ostd/src/mm/io/copy.rs:165,256` (`volatile_{copy,set}_memory`), and `ostd/src/arch/loongarch/mm/mod.rs:331,337` (`atomic_{load,cxchg}`).
   Additionally, running `cargo check --target riscv64imac-unknown-none-elf` on `ostd` under `nightly-2026-05-31` fails inside `unwinding-0.2.11/src/util.rs:40` with `error[E0425]: cannot find function abort_immediate in module core::intrinsics`. Meanwhile, Anneal's capture policy (`anneal/trusted/rustc-capture/src/capture.rs`) explicitly refuses `#![feature(core_intrinsics)]` and `#![feature(rustc_private)]` even under `--allow-unstable-feature` (`rustc_private` does not affect the bare-metal `asterinas` closure).
2. **Panic Strategy Split (`unwind` vs. `abort`):** Workspace `Cargo.toml` sets `panic = "unwind"` for `dev`, `release`, and `ktest`, switching to `panic = "abort"` only under `[profile.release-lto]`. `ostd` implements dual-mode panicking (`ostd/src/panic.rs:77-138`) using `unwinding::panic::{begin_panic, catch_unwind}` (`fde-gnu-eh-frame-hdr` on x86_64/loongarch64, `fde-static` on riscv64/aarch64) so `ktest` tests and `kernel` components (`kernel/core/src/lib.rs:17` enables `#![feature(panic_can_unwind)]`) can catch kernel panics across framekernel boundaries. Anneal's Profile v2 (`Trusted.MirSemantics.Boundary`) models `--panic abort` (`SafeContractV2`), while MIR cleanup edges (`UnwindAction::Cleanup(_)`, `UnwindResume`) and unwinding through `Drop`/`GlobalAlloc` (see https://github.com/asterinas/asterinas/issues/3910) fail closed.
3. **Host-vs-Bare-Metal Driver & Multi-Crate Inputs:** `ostd` builds only under `-Zbuild-std=core,alloc,compiler_builtins` against `x86_64-unknown-none`, `riscv64imac-unknown-none-elf`, `loongarch64-unknown-none-softfloat`, or `aarch64-unknown-none-softfloat` with custom `.ld` linker scripts, `#[alloc_error_handler]`, `#[panic_handler]`, and `#[linkage = "weak"]`. On `google/zerocopy@8d60e1e085bd`, `anneal-rustc-capture` checks `x86_64-unknown-linux-gnu` by default (`--allow-empty-sysroot` / `--extern` / bare-metal target JSON loading are not yet implemented in `origin/main` `capture.rs`), and `include_str!("../README.md")` in `ostd/src/lib.rs:3` and `ostd-pod/src/lib.rs:3` requires explicit `--source-file` allowlisting so the compiler read sanitizer does not fail closed with `undeclared compiler read`.

### 4. Real-World Soundness Failure Modes vs. `vOSTd` and OS Kernel Prior Art

Basis: source (`asterinas/asterinas`, `asterinas/vostd`) + primary issue trackers (`#3920`, `#3881`–`#3918`, `#4252`, `#4262`, `#4265`, `#4271`, `vostd#645`)

#### A. What Real Bugs Hit Asterinas (`#3920` Scan + Heap/Frame/CPU Audits)

Combining https://github.com/asterinas/asterinas/issues/3920 (`30` linked cross-boundary issues `#3881`–`#3882` and `#3891`–`#3918`, `15` closed / `15` open as of 2026-11-27) with subsequent standalone bugs (https://github.com/asterinas/asterinas/issues/4252, https://github.com/asterinas/asterinas/issues/4262, https://github.com/asterinas/asterinas/issues/4265, https://github.com/asterinas/asterinas/issues/4271; `3` closed / `1` open) classifies `ostd`'s real soundness bugs into **six concrete mechanisms**:

1. **Per-CPU & Concurrency Marker/Guard Errors:**
   - `CpuLocalCell<T>` implemented `Sync` without `T: Send`, allowing `&Cell<u64>` migration across CPUs and safe data races (https://github.com/asterinas/asterinas/issues/4265, closed).
   - CPU-local atomic-mode guards and custom lock guardians omitted `Sync` / `!Send` bounds (https://github.com/asterinas/asterinas/issues/3891, https://github.com/asterinas/asterinas/issues/3909, closed); out-of-order drops of nested `DisabledLocalIrqGuard` re-enabled IRQs prematurely inside an RCU critical section (https://github.com/asterinas/asterinas/issues/3896, closed); preemption-count wrap allowed premature RCU reclamation (https://github.com/asterinas/asterinas/issues/3895, open).
   - Safe concurrent `VmIo` writes to untyped memory could data-race (https://github.com/asterinas/asterinas/issues/3893, closed), and `CurrentTask` could yield a `'static &Task` outliving task deallocation (https://github.com/asterinas/asterinas/issues/3897, open).
2. **Allocator, Metadata Ownership, & Aliasing:**
   - https://github.com/asterinas/asterinas/issues/4252 (open): swapping two slabs' `SlabMeta` via safe `meta_mut()` leaves a page's free list pointing into another slab and causes use-after-free when dropped.
   - https://github.com/asterinas/asterinas/issues/4262 (closed): intrusive frame `LinkedList` captured raw pointers from `&mut frame.meta_mut()` and reused them across fresh `&mut` reborrows, violating Tree Borrows aliasing rules.
   - https://github.com/asterinas/asterinas/issues/3898 (closed): safe `VmReader::read_once` read allocator-permitted uninitialized bytes as an initialized Rust `T`.
   - https://github.com/asterinas/asterinas/issues/3910 (open): safe user-supplied heap-policy code can unwind across `GlobalAlloc` shim frames (`panic = "unwind"`).
   - https://github.com/asterinas/asterinas/issues/3911 (open): non-divisor `Slab` slot sizes trigger unaligned free-list writes; empty `Segment` kept dangling paddr provenance (https://github.com/asterinas/asterinas/issues/3892, closed).
3. **Alignment, Linker Sections, & Unaligned Boot/ABI Structs:**
   - https://github.com/asterinas/asterinas/issues/4271 (closed): per-CPU static variables aligned `> 4 KiB` became misaligned on secondary AP copies (`AP copy base + offset`), making safe `CpuLocal::get_on_cpu` form misaligned Rust references.
   - https://github.com/asterinas/asterinas/issues/3912 (open): `.ktest_array` constructs one contiguous `&[KtestItem]` Rust slice spanning distinct static allocations concatenated by the linker.
   - https://github.com/asterinas/asterinas/issues/3913 (closed), https://github.com/asterinas/asterinas/issues/3914 (closed), https://github.com/asterinas/asterinas/issues/3915 (open), https://github.com/asterinas/asterinas/issues/3916 (open): Multiboot/PVH/Linux boot protocols constructed Rust references or invalid `bool`/`enum` representations (e.g., all-zero boot structs) from untrusted boot memory.
4. **Architecture Assembly, Fallible Copy, Traps, & DMA/DTB Lifetime:**
   - Fallible userspace operations (`ptr::copy`, `write_bytes`, `atomic_load`, CAS) invoked Rust UB primitives on faultable user addresses rather than exception-table assembly (https://github.com/asterinas/asterinas/issues/3881, https://github.com/asterinas/asterinas/issues/3882 open; https://github.com/asterinas/asterinas/issues/3902, https://github.com/asterinas/asterinas/issues/3903 closed).
   - Kernel trap `.S` stubs passed `&mut TrapFrame` containing uninitialized fields into Rust on AArch64, RISC-V, and LoongArch (https://github.com/asterinas/asterinas/issues/3906, https://github.com/asterinas/asterinas/issues/3907, https://github.com/asterinas/asterinas/issues/3908, all closed).
   - x86 NMI inside a `SWAPGS` window (https://github.com/asterinas/asterinas/issues/3904, open), unrestricted DMA via `IoMem<Insensitive>` without active IOMMU (https://github.com/asterinas/asterinas/issues/3905, open), FDT/DTB/cmdline aliasing physical allocator memory (https://github.com/asterinas/asterinas/issues/3899 closed, https://github.com/asterinas/asterinas/issues/3900 closed, https://github.com/asterinas/asterinas/issues/3901 open), and provenance-bearing EFI arithmetic (https://github.com/asterinas/asterinas/issues/3918, open).

## Boundaries

1. **Snapshot Currency & Uncompiled Upstream `ostd`:** Census and compatibility measurements reflect `asterinas/asterinas@a97b435bf5b95f5839cc8acaa773e31463f04602` (`v0.19.0`) and `asterinas/vostd@51b4459029c8f9dfa6e86fff26d13c49bfc29b51` as of `2026-11-27`. Full `cargo check` of `ostd` on `rustc 1.98.0-nightly` fails before reaching later crates due to `unwinding-0.2.11` (`abort_immediate`) and `btree_cursors` / `riscv_ext_intrinsics` / `proc_macro_diagnostic`; additional crate-specific MIR gaps may appear once those front-end errors are bypassed or the compiler pin advances.
2. **E2E Verification vs. Unverified MIR Tiers:** `support/e2e_frame_to_meta/` provides a kernel-checked Lean 4 proof (`UnitTheoremV2`) for a monomorphic standalone extraction of `frame_to_meta` (replacing generic `PagingConstsTrait` with concrete 4 KiB / 64-byte slot constants) checked on an immediate pre-https://github.com/google/zerocopy/pull/4410 Profile v2 build whose scalar arithmetic semantics match `google/zerocopy@8d60e1e085bd`. All Profile v2 correspondence caveats reported in the receipt apply: Profile v2 does not yet have a `lean-miri` simulation theorem, omits intra-body Stacked/Tree Borrows aliasing (`!bodyMixesRefsAndRawPtrsV2`), and assumes raw-pointer provenance and valid reference arguments.
3. **Kernel `#![deny(unsafe_code)]` Scope:** Bare-metal `kernel` crates (`1,175` files) have `0` direct `unsafe` syntax tokens, but use `#![deny(unsafe_code)]` rather than `#![forbid(unsafe_code)]` because `ostd-macros` (`#[ostd::main]`, `#[ostd::global_frame_allocator]`, `#[ostd::global_heap_allocator]`, `#[ktest]`) expands Edition-2024 `#[unsafe(no_mangle)]` and `#[unsafe(link_section = ".ktest_array")]` inside downstream crates. Because `0` crates enforce `#![forbid(unsafe_code)]` and `kernel` uses several proc macros (`ostd-macros`, `#[ostd_pod::derive]`, `inherit-methods-macro`, `getset`), sound isolation of `kernel` relies on macro hygiene/audit (https://github.com/asterinas/asterinas/issues/2006). (Separately, `#![feature(rustc_private)]` is confined to the unlinked host CLI `kernel/libs/comp-sys/cargo-component/`.)
4. **Non-MIR Hardware & Linker Boundaries:** Inline `asm!`, `.S` files (`global_asm!`), MMIO (`volatile`), IOMMU/DMA isolation (https://github.com/asterinas/asterinas/issues/3905), `SWAPGS`/NMI windows (https://github.com/asterinas/asterinas/issues/3904), weak-linkage overrides (`osdk`), and contiguous linker-section concatenation (`.cpu_local`, `.sensitive_io_ports`, `.ktest_array`) sit outside pure single-crate MIR semantics and require explicit hardware/linker assumptions or cross-layer verification.
