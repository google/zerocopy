# Comparative Developer and AI Agent DX Audit Across 11 Formal Verification Ecosystems: Transferable Patterns and Asymmetric Bets for Anneal

## Summary

Across 11 formal verification ecosystems—Rust verifiers (`Verus`, `Kani`, `Aeneas`/`Charon`, `Creusot`, `Prusti`/`Flux`), deductive and interactive theorem provers (`Lean 4`/`Mathlib`, `Dafny`, `F*`/`Low*`/`Pulse`, `Rocq`/`coq-lsp`/`VsRocq`), and systems/industrial safety tools (`TLA+` `TLC`/`Apalache`, `CBMC`/`cbmc-viewer`, `Ada/SPARK` `gnatprove`)—a consistent division of bottlenecks emerges between **human spec auditability** and **automated proof search**. (`Basis: derived`)

Three cross-ecosystem laws govern developer UX and AI agent DX today:

1. **Unstable SMT quantifier heuristics create brittle "butterfly" proof loops, whereas kernel-checked deterministic discharge or concrete falsification scales predictably.** E-matching solver sensitivity in `Dafny`, `Verus`, and `F*` (`Mariposa` instability rates and `Axiom Profiler 2` trigger debugging) forces engineers into `--rlimit`, `--isolate-assertions`, `--mutations`, and `--quake` defensive loops (`Basis: source, documentation`). Conversely, pre-proof concrete counterexample replay (`Kani` `--concrete-playback`, `CBMC` `--trace`, `SPARK` `--check-counterexamples`, `Why3` Giant-Step RAC) and small, deterministic kernel-checked decision procedures/abstract domains (`Anneal.AiPcc`, `tools/anneal-mir-eval`) turn mysterious verification failures into crisp concrete bugs or finite arithmetic diagnoses (`Basis: source, documentation`).
2. **Inline annotations ease initial authoring but poison human reviewability and agent cheating boundaries unless paired with a single canonical spec closure.** Inline systems (`Verus`, `Creusot`, `Flux`, `Dafny`, `SPARK`) minimize cold-start friction by keeping contracts beside code, yet `VerusEval` (`arXiv:2610.26464`) shows only `42.3%` of 13,716 verifier-accepted LLM artifacts pass combined non-triviality, I/O, and equivalence checks, and `Verus` (`--no-cheating`), `Dafny` (`audit`), and `F*` (`--report_assumes error`) must bolt on assumption auditors after the fact (`Basis: source, documentation`). Separating untrusted proof work from reviewed specifications (`Spec.lean` vs. `Proof.lean`, `ExecSeal`, Receipt v3) eliminates proof-side reward hacking mechanically, while Anneal's Target Architecture **Always-Rendered Golden Spec Closures** (`docs/spec-core-and-golden-closure.md`) resolves the authoring-vs-review split (`Basis: source`).
3. **Cold CLI/build invocations wreck both human flow and agent token budgets; machine-native stateful proof servers plus bounded concrete outputs win.** Stateful LSP/JSON-RPC servers (`Lean 4` watchdog/worker `InfoTree`, `lean-lsp-mcp` `LEAN_MCP_MAX_OUTPUT_CHARS=6000` middle elision, `Rocq` `coq-lsp` + `Petanque`, `Pantograph`) cut feedback from multi-second batch runs to tens of milliseconds—provided cold `lake build` stalls and RSS blowups (`~473 MiB` monolithic `Init` vs. `~152 MiB` targeted `Init.*` in Lean; `~13 GiB` local Loogle index) are structurally bounded (`Basis: source, documentation`).

**Top "Steal / Avoid / Beat" Takeaways for Anneal (`google/zerocopy@0fd98bf034e1`):**

- **Steal:** `Kani` `--concrete-playback` + `Why3` Giant-Step RAC triage (surface shipped `tools/anneal-mir-eval` automatically on proof failure), `SPARK`'s Stone-to-Platinum adoption ladder + `Charon`/`Flux` selective inclusion (`--start-from`/`IncludePattern`), `F*` `--quake` / `Dafny` `measure-complexity --mutations` + `ProofDependencyWarnings`, `Aeneas` `step*?` script materialization + `verus-analyzer` Proof Actions, `coq-lsp`/`Petanque` decoupled JSON-RPC state handles, and `Apalache` `ITF` / `Kani`/`SPARK` SARIF + JSON outputs (`Basis: derived`).
- **Avoid:** Quantifier E-matching fragility (`Verus`/`Dafny`/`F*`), compiler-internal `rustc` driver lockstep without stabilization (`Prusti` stall, `Flux` zero releases, `verus-analyzer` proc-macro skew), unvalidated raw SMT counterexamples (`DafnyModel.cs:190`), silent unsound/incomplete flags (`Kani` `--no-unwinding-checks`/`autoharness` `LOOP_UNWIND_DEFAULT = 20`, pre-v6.0 `CBMC` unwinding defaults, `Verus` unflagged `assume(false)`, `Aeneas` `--checks` ~100x slowdown + `type_check_pure_code = false` + unwired `-lean-default-lakefile`), and cold MCP `lake build` timeouts (`Basis: source, documentation`).
- **Beat Every Peer:** Combine (1) **adversarial zero-trust elaboration and kernel replay** (`ExecSeal`, `TrustedBoundary`, Receipt v3 Uniform Flag-Driven Taint Law, and Target `5a/5b/5c` NDJSON Comparator), (2) **deterministic 0-TCB abstract interpretation certificates** (`Anneal.AiPcc`, already landed in `theory/Anneal/AiPcc/` on `main` and awaiting wiring into `theory/bundle-manifest.json`), (3) **zero-TCB exact captured-MIR concrete evaluation and UB probing** (`tools/anneal-mir-eval`), and (4) **`<1`-page `OWNERS`-gated Golden Spec Closures** uniting ergonomic spec authoring with a bounded human audit surface (`Basis: source, derived`).

### 2. Onboarding and First-Proof Friction

1. **Driver-to-toolchain coupling dictates Day-0 survival (`Prusti`, `Flux`, `Verus`, `Creusot`, `Aeneas`, `Anneal`):**
   - `Prusti` (`viperproject/prusti-dev@60417dcf`) and `Flux` (`flux-rs/flux@587a7bef`) bind directly inside unstable nightly `rustc` internals; `Prusti`'s own ownership analysis pivoted into the standalone `prusti/pcg@071783bf` library (`README.md:15-22`) using conditional compilation across nightly API changes, while `Flux` requires custom toolchain builds (`README.md`). Even `verus-lang/verus-analyzer@2ac834c8` explicitly warns in `README.md:6-12` that it is experimental with no dedicated engineering support and documents real proc-macro server API version mismatches (e.g., server API `6` vs. analyzer `4`, `README.md:130-153`), requiring manual toolchain pinning or disabling proc macros (`Basis: source, documentation`).
   - `Creusot` (`creusot-rs/creusot@a81df781`) requires installing `rustup`, OPAM OCaml packages (`Why3`, `why3find`), and running `./INSTALL` (`README.md:59-74`), while enforcing exact version equality between `cargo-creusot` and `creusot-std` (`cargo-creusot/src/main.rs:472-505`, `Basis: source`).
   - `Aeneas` (`AeneasVerif/aeneas@fb44cb40`) separates extraction (`AeneasVerif/charon@1477e69f` generating `.llbc` with mandatory `--preset=aeneas`) from Lean/F*/Coq/HOL4 translation (`src/Main.ml`), reducing `rustc` driver lockstep in proof scripts—yet `src/Main.ml:141-142` binds `-lean-default-lakefile` to `Arg.Clear lean_gen_lakefile` (inverted sense) and `-checks` activates ~100x slower sanity checks (`src/Main.ml:128-134`, `Basis: source`; see `aeneas-lean-backend-generated-signatures-and-wp-proof-tools`).
   - By comparison, **`Kani`** (`model-checking/kani@2425d3b2`) and **`Anneal`** (`google/zerocopy@0fd98bf034e1`) package self-contained toolchains (`cargo anneal setup` installs an omnibus archive bundling pinned `rustc` `f8a08b688cbe`, Lean `v4.34.1`, and `anneal-rustc-capture`, with `cargo anneal init` / `cargo anneal skill --example` scaffolding a runnable 4-file scalar example; `cli.rs:55-120`, `verify.rs:52`, `cargo-anneal/SKILL.md:33-59`, `Basis: source`).
2. **All-or-nothing subset rejection vs. structured on-ramps (`SPARK`, `Kani`, `CBMC`, `Anneal`):**
   - **`Ada/SPARK`** (`AdaCore/spark2014@e060dca7`) sets the gold standard for incremental first-proof onboarding via its four documented adoption levels (`stone_level.rst`, `bronze_level.rst`, `silver_level.rst`, `gold_level.rst`): *Stone* isolates valid `SPARK_Mode` code without proof (`GNATmetric` coverage), *Bronze* runs fast decidable flow analysis for initialization/aliasing/`Global` contracts, *Silver* proves Absence of Run-Time Errors (`AoRTE`) enabling `-gnatp`, and *Gold* verifies functional invariants (also testable dynamically via `-gnata`). Importantly, even *Silver* documents predictable failure modes (non-linear arithmetic and floats, `silver_level.rst:108-112`, `Basis: documentation`).
   - **`Kani`** achieves zero-spec Day-0 value via `cargo kani autoharness` (`autoharness/mod.rs`), automatically generating harnesses for eligible functions—while transparently printing `chosen` and `skipped` tables (`autoharness/mod.rs:190-203`), though capping loops at `LOOP_UNWIND_DEFAULT: u32 = 20` (`autoharness/mod.rs:25`) and modeling finite `Rc`/`Arc` refcounts (`REFCOUNT_NOTE`, `autoharness/mod.rs:31-33`, `Basis: source`).
   - **`Anneal`** Stage 0 (`google/zerocopy@0fd98bf034e1`) currently accepts only Profile v1 scalar MIR (plus experimental Profile v2 single-level `&`/`&mut`/`*const`/`*mut` to scalars/`[T]` that cannot mix references and raw pointers in one body, refusing mixed idioms such as `<&mut [u8] as SplitByteSlice>::split_at_unchecked`, `alpha.md:110-149`, `diagnostics.rs:50-80`, `Basis: source`). While `diagnostics.rs` gives helpful fail-closed hints and `--manifest-path` offers a Cargo shortcut for dependency-free crates, crates with build scripts, proc-macros, or normal dependencies must drop to `--request <file>` or `verify rustc` (`diagnostics.rs:26-49`, `Basis: source`).

### 3. Spec Authoring, Ergonomics, and Human Reviewability

1. **The inline-ergonomics vs. bounded-audit dilemma (`Verus`/`Creusot`/`Dafny`/`SPARK` vs. `Aeneas`/`Rocq`/`Anneal`):**
   - Inline systems (`Verus` `verus!`/`#[verus_spec]`, `Creusot` `#[requires]`/`#[ensures]`, `Flux` `#![flux::specs]`, `Dafny`, `SPARK` `.ads`) keep specifications right beside code so `rust-analyzer` / IDEs resolve symbols easily and developers don't duplicate signatures (`Basis: source, documentation`). However, `verus-analyzer/README.md:64-69` still notes `vstd` is not scanned unless explicitly added to `Cargo.toml`, and interleaving `proof` blocks, `broadcast` axioms, ghost types, and `assume`/`admit` inside code forces reviewers to audit an entire file (or whole crate) to understand what is assumed vs. proved (`Basis: source, documentation`). Empirical studies show where this breaks down: `VerusEval` (`arXiv:2610.26464`) audited 13,716 verifier-accepted LLM artifacts across 762 tasks and found only **`42.3%`** pass combined non-triviality, concrete I/O execution, and bounded contract equivalence (`23.6%` fail concrete I/O checks alone; `84.1%` of equivalence failures reflect completeness/weak-spec issues; see `counterexample-trace-shrinking-span-blame-assignment-and-agent-proof-repair`, `Basis: documentation`). Similarly, `alloy4fun-forge-sterling-misconceptions-tlaplus-audits-and-spec-review-effort` documents omission bugs in real verified systems (`IronFleet`, `Chapar`, `seL4`) and widespread quantifier polarity misunderstandings (`Alloy4Fun`: 373 wrong vs. 6 correct on `some x | A implies B`), noting that **`Kolyakov et al.`** (`agent-proof-search-architectures-auto-active-invariants-and-code-survival`) found 35 spec defects across 2,005 CBMC/Kani artifacts (`-0.85` Spearman correlation between coverage and repo scale) (`Basis: documentation, derived`).
   - Out-of-line proof assistants (`Lean 4`, `Rocq`, `Aeneas`) decouple proofs cleanly from runtime code, protecting human attention (`compiler-error-pedagogy-elm-rust-alloy-unsat-cores-and-proof-comprehension`), at the cost of manual name-mapping and cross-file Drift (`KVerus` ASE 2026 shows agent verification success drops from `80.2%` single-file to `51.0%` cross-file across 3 multi-file repos, with AutoVerus falling to `4.5%`; `Basis: documentation`).
   - **`Anneal`'s answer (`google/zerocopy@0fd98bf034e1`):** Shipped Stage 0 enforces strict file separation (`Spec.lean` vs. `Proof.lean`, `cargo-anneal/SKILL.md:73-90`) plus `"spec-preflight"` (`elaborator-containment-design.md:68-74`, `diagnostics.rs:288-308`) banning tactics, macros, `autoImplicit`, `Anneal.*`, and `sorry` inside `Spec.lean` so reviewers read pure Lean definitions/types. Furthermore, Anneal's Target Architecture (`docs/spec-core-and-golden-closure.md:38-45,236-260`) unifies ergonomic spec placement with bounded `<1`-page review by compiling all specifications + transitive meaning dependencies into a deterministic **Always-Rendered Golden Spec Closure** artifact gated by `CODEOWNERS`/`OWNERS` (`Basis: source, documentation`).
2. **Pre-proof spec sanity & assumption auditing (`Dafny`, `F*`, `SPARK`, `Verus`, `Kani`, `Anneal`):**
   - `Dafny` (`Source/DafnyDriver/Commands/AuditCommand.cs:16-31`, `Auditor.cs:18-159`, `AuditReport.cs:98-170`) ships a dedicated `dafny audit` subcommand outputting HTML, Markdown tables, IETF prose, or `--compare-report` golden CI diffs listing compiled vs. ghost declarations, explicit `{:axiom}`s, and `{:extern}` boundaries (`Basis: source`).
   - `Dafny` also runs `ProofDependencyWarnings.ReportSuspiciousDependencies` (`VerifyCommand.cs:223-233`) and `--verification-coverage-report` (`CommonOptionBag.cs:342`) to catch unused `requires` clauses or vacuous branches (`Basis: source`).
   - `SPARK` offers `--proof-warnings=on` (`how_to_run_gnatprove.rst:324-354`) to flag unreachable branches and contradictory assumptions (`X > 5 and X < 5`), plus structured `pragma Annotate` vs. `pragma Assume` audit trails (`how_to_use_gnatprove_in_a_team.rst:268-460`, `Basis: documentation`).
   - `F*` (`agentic_rubrics_templates_audits.rst:58-115`) introduces **SPOTs (Small Proof-Oriented Tests)**—tiny unit theorems checking spec behavior on concrete examples (`rev [1;2;3] == [3;2;1]`)—alongside `--report_assumes error` (`FStarC.Options.fsti:398`) (`Basis: documentation, source`).
   - `Kani` / `KaPilot` uses negation smoke tests (`#[kani::ensures(|_| false)]`) to catch vacuous harnesses (`agent-proof-search-architectures-auto-active-invariants-and-code-survival`, `Basis: documentation`).
   - **`Anneal`** encodes client-sufficiency checks and `[A4]` sanity in `anneal/skills/spec-authoring/SKILL.md:60-85`, and its Target Architecture specifies kernel-checked `PreInhabited` plus **Dual-Polar `MutationRefute`** (`auditing-and-comparator.md:295-326`), requiring both clean failure on a mutated Rust body (`Pole A`) and a kernel-checked refutation proof `⊢ ¬ CrateTheorem ⟨P_mut, Spec⟩` (`Pole B`) so brittle script crashes cannot masquerade as spec coverage (`Basis: source, documentation`).

### 4. Feedback Loops, Counterexamples, and Failure Diagnosis

1. **SMT opacity vs. concrete counterexample falsification:**
   - SMT-backed verifiers suffer from **false or ungrounded counterexamples**. `Dafny`'s `DafnyModel.cs:190` explicitly warns users that raw SMT counterexamples may be invalid models due to incomplete axiom instantiation or missing invariants (`type-error-localization-compiler-diagnostics-and-verification-ux`), and `SPARK` warns explicitly that `--counterexamples=on` with `--check-counterexamples=off` produces infeasible execution paths (`how_to_view_gnatprove_output.rst:400-419`). `SPARK` solves this better than most: by default (`--check-counterexamples=on`, `how_to_view_gnatprove_output.rst:387-399`), `GNATprove` replays cvc5 models (and falls back to boundary-value fuzzing) against the actual Ada program semantics to suppress spurious models, promote real failures from `medium` to `high`, and export an executable GNATtest reproducer (`how_to_run_gnatprove.rst:759-764`, `Basis: documentation`).
   - `Why3` (backing `Creusot` and `SPARK`) implements Giant-Step RAC classification (`NC` non-conformity / real bug, `SW` sub-contract weakness, `BAD_CE`, `INCOMPLETE`; `type-error-localization-compiler-diagnostics-and-verification-ux`, `Basis: documentation`).
   - `Kani` turns CBMC SAT counterexamples into copy-pasteable or auto-inserted Rust unit tests via `--concrete-playback=print|inplace` (`kani-driver/src/args/mod.rs:244-247,582-587`, `playback_args.rs`, `Basis: source`).
   - `CBMC 6.0+` flips historical unsound defaults: `set_default_analysis_flags` (`cbmc_parse_options.cpp:110-150`) now enables bounds/pointer/div-by-zero/signed-overflow/shift checks and `unwinding-assertions` by default unless `--no-standard-checks` or `--cover` is passed (`--cover` forces `unwinding-assertions = false`, line `178`), pairs `--trace` with experimental `--localize-faults` (`line 1054`), and relies on `model-checking/cbmc-viewer@bf452b2c` to convert XML reports into line-annotated HTML coverage + trace pages (`cbmc-viewer/README.md:35-63`, `Basis: source`).
   - `TLA+` splits cleanly into concrete vs. symbolic traces: `TLC.java:268-276,741-787,1494-1502` adds `-difftrace` (state deltas only), `-debugger`, `-generateSpecTE`, and `-dumpTrace` (`json`, `dot`, `cbor`, `tla`), while `Apalache` `ADR-015` (`015adr-trace.md:15-33,214-348`) standardizes **Informal Trace Format (`ITF`, `.itf.json`)** using explicit `{ "#bigint": "..." }`, `#set`, `#map`, `#tup`, and `#meta.varTypes` so non-TLA+ engineers and CI tools can replay traces directly (`Basis: source`).
