# Sail ISA Models, the Sail Lean 4 Backend and `archsem-lean` Ecosystem, RV64D Decoding and State Framing, and CompCert Access Foundations

## Summary

This report synthesizes five complementary investigations across the Sail ISA specification ecosystem, the Sail-to-Lean 4 compiler backend and `lean-sail`/`archsem-lean` concurrency stack, end-to-end Lean 4 kernel proofs of official Sail RV64D instruction execution and supplied-word decoding, and comparative ISA/memory access mechanisms across Sail, Islaris, and CompCert:

#### 1.2 `sail-tiny-arm` vs. `sail-tiny-arm-lean`: User vs. System Mode and Baseline Evolution

In `rems-project/sail-tiny-arm` (`98d904912620ddd74e76714b7ef8457192cb4e3a`), conditional compilation via `#ifdef SYSTEM_TINY_ARM` splits the model into two tiers:

1. **User-Mode Tier (`instrs-user.sail`, 759 LOC):**
   - Defines 34 registers (`registers.sail:6-41, 128-130`): general-purpose 64-bit registers `X0`..`X30 : bits(64)` (named with `R`-prefixes in Sail source and indexed via `let GPRs : vector(31, dec, register(bits(64)))`), `_PC : bits(64)`, `NZCV : bits(4)`, and `SP_EL0 : bits(64)`. ### 5. Sail, Islaris, and CompCert Mechanisms for Missing ISA and Access Obligations

1. **Sail Generation and Real-Number Configuration (`rems-project/sail` at `7e0e53d183cad75b8f36bfbbecc0ef75614a8418`):**
   - `src/sail_lean_backend/sail_plugin_lean.ml` (`lines 81, 175, 310, 325`) initializes `opt_lean_real_numbers` to `false` and selects `src/sail_lean_backend/Sail/FakeReal.lean` (`line 6`) unless real-number support (`Real.lean` + Mathlib) is explicitly enabled. `FakeReal.lean` maps `real` to IEEE-754 `Float`, `random_real` to a constant, and `undefined_real` to a default value. Proofs that rely on Sail `real` primitives must account for this configuration, whereas scalar integer proofs (`BitVec`) do not evaluate `real` operations.
2. **Islaris Trace Adequacy vs. Trace-to-ISA Validation (`rems-project/islaris` at `c978e10f50db5c40f0fdf113f5f76a779782c6f9`, PLDI 2022 DOI `10.1145/3519939.3523434`):**
   - `isla_adequacy` (`theories/adequacy.v:91`) proves that given an instruction trace table, initial memory and register maps, a trace specification `Pκs`, and an Iris proof using `instr_table`, `backed_mem`, `spec_trace`, and points-to resources, any `nsteps` execution yields non-stuck final threads and `Pκs κs`.
   - In `theories/opsem.v:504`, `ReadMem` and `WriteMem` carry explicit byte length `N`: a positive-length memory operation either accesses all present map bytes or, for a wholly disjoint absent range, emits an external MMIO read/write event with a no-overflow check (partially backed ranges are stuck, and memory tags/access kinds are ignored in those branches).
   - Crucially, `isla_adequacy` takes the Isla-generated trace table as a hypothesis; validating that the trace table soundly covers all feasible paths of the underlying Sail opcode is a separate theorem. While Islaris has a RISC-V translation-validation prototype (`sail-riscv/`), its experimental Arm-to-Sail directory (`sail/README.md`, `sail/sail_opsem.v:232`, `sail/test.v:441`) is unfinished work-in-progress that admits `sim_Write_reg`, `_admit`, interrupt simulation, and `sim_fetchA64`.
3. **CompCert Full-Width Memory Permission Predicates (`AbsInt/CompCert` 3.18 at `74cbdbf0e86ecbfa39a5ca8f248f77fb2f974cb6`) & Finite Predicate Separation (`support/access_models.py`):**
   - CompCert's `Mem.valid_access m chunk b ofs p` (`common/Memory.v:220`) enforces two conditions before `Mem.load` (`line 428`, requiring `Readable`), `Mem.store` (`line 534`, requiring `Writable`), or x86 `exec_load`/`exec_store` (`x86/Asm.v:577`, transitioning `None` to `Stuck`) can succeed: (a) `range_perm m b ofs (ofs + size_chunk chunk) Cur p` (every byte offset in the full access width has permission `p`), and (b) `(align_chunk chunk | ofs)` (alignment divides offset).
   - The executable Python probe [`support/access_models.py`](support/access_models.py) (results recorded in [`support/access_models.json`](support/access_models.json) and [`support/access_models.log`](support/access_models.log)) constructs a 64-byte mapped region with write authority on only the first 8 bytes, demonstrating that: (a) an 8-byte scalar write succeeds; (b) a 32-byte vector write fails full-width permission despite 100% map membership and VM accessibility; (c) a 64-byte boundary-crossing access fails map membership; and (d) an expired logical borrow/lifetime authority flag is independent of physical byte presence and VM permissions.
