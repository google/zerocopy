# Coupled Backend Seam Verification: Sub-Register `WriteMode`, CFG-Aware `vzeroupper`, Inline Stack Probes, 16-Byte Outlined Thunks, and `.eh_frame` / LSDA / `DW_OP_fbreg`

## Summary

Backend verification artifacts typically prove single-stage invariants in isolation: an instruction selector models 64-bit general-purpose sub-registers and leaf outlined thunks, a register allocator verifies parallel-move certificates over abstract symbolic lanes, a post-link validator scans flat disassembly for missing AVX-to-SSE transitions, and an unwind-table formalization tracks straight-line CFA increments. Composing three published backend reports—[`verified-instruction-selection-isle-crocus-and-unified-minimach-ir`](../verified-instruction-selection-isle-crocus-and-unified-minimach-ir/REPORT.md) (`555f11dfed36`), [`verified-ssa-register-allocation-coalescing-and-subregister-lane-liveness`](../verified-ssa-register-allocation-coalescing-and-subregister-lane-liveness/REPORT.md) (`dd77614d49fe`), and [`rustc-release-abi-drift-binary-validation-cfg-alignment-and-surviving-bounds-checks`](../rustc-release-abi-drift-binary-validation-cfg-alignment-and-surviving-bounds-checks/REPORT.md) (`d116b216ddcf5143b6b11a46e2f984ded2551254`)—against straight-line `.eh_frame` unwind models exposes **five concrete cross-stage composition breakages (`GAP-1` through `GAP-5`)** across `MiniMach` `Virt -> Alloc -> Layout -> Encoded` lowering on `x86-64`:

1. **`GAP-1` (SIMD Sub-Register `WriteMode` Discontinuity):** `MiniMach`'s 5-constructor GPR `LaneView` (`full64`, `lo32Zext`, `lo16Keep`, `lo8Keep`, `hi8Keep`) cannot express the opposite `YMM[255:128]` semantics of legacy SSE (`movdqu` preserves upper 128 bits) versus VEX-128 (`vmovdqu xmm` zeroes upper 128 bits), while symbolic `Nat`-lane allocator proofs lack a bit-vector bridge to hardware shift/mask semantics.
2. **`GAP-2` (Allocator Checker Missing-`else`, Unsafe Reload/Remat, and Narrow Scratch Saves):** Upstream `bytecodealliance/regalloc2@4eb655fa745fba271af74be8495154a4b0cac56f` (`src/checker.rs:545-562`) omits the `else` invalidation branch in `CheckerState::update`, allowing stale values to survive moves from unallocated locations; meanwhile naive VEX-128 reloads, 32-bit `movl` rematerializations, and narrow scratch saves silently zero live co-allocated `YMM[255:128]` or `RAX[63:32]` lanes.
3. **`GAP-3` (Linear `vzeroupper` Scanning vs. AVX2 CFG & `panic=unwind` Landing Pads):** Flat disassembly scanning falsely flags early scalar returns in multi-exit AVX2 kernels such as `memchr::find_avx2` (`0x12f924: retq`), yet misses dirty `YMM[255:128]` state leaking across `invoke -> landingpad -> _Unwind_Resume` edges or sibling tail calls (`jmpq *%rsi`), and single-register VEX-128 operations clear only one of sixteen `YMM` registers.
4. **`GAP-4` (Spill-Triggered Inline Stack Probes, Dynamic `%r11` CFA Switches, and Throwing Outlined Thunk 16-Byte Alignment):** Real `rustc 1.98.0-nightly` / `LLVM 22.1.6` `-C opt-level=2` codegen emits unrolled inline stack probes even with zero local arrays when live `__m256i` spills push frame size past `4,096` B (`4,752` B), switches `.eh_frame` CFA from `%rsp` to **`r11+36880`** (`DW_CFA_def_cfa_register: reg11`) in `>= 9`-page probe loops (`36,912` B), and places epilogues physically before cold landing pads with explicit CFA restoration. Crucially, `MiniMach`'s published `outlined_thunk_simulates_inline` (`spShift = 8#64`) holds strictly for leaf non-calling thunks: on System V AMD64, entering an outlined thunk via `call` shifts a 16-byte-aligned caller stack to `rsp % 16 = 8`, requiring an explicit `sub rsp, 8` (`spShift = 16#64`, `thunkFdeCfaOff = 16`) before any throwing call plus `.cfi_remember_state` / `.cfi_restore_state` around preceding epilogues (whose omission crashes live `std::panic::catch_unwind` with `SIGSEGV`, exit code `-11`).
5. **`GAP-5` (Straight-Line Unwind Models and Inflated DWARF Coverage Assumptions):** Unwind-table models restricted to straight-line code cannot validate CFG epilogue-to-landing-pad CFA restores, `.gcc_except_table` LSDA call-site dispatch, or `DW_CFA_def_cfa_register` transitions; real `rustc 1.99.1` DWARF measurements (`-O0` `98.4%` -> `-O3` `41.29%` 100%-covered locals, `44.43%` at `0%`) refute idealized high-optimization coverage assumptions and show why CFA-anchored `DW_AT_frame_base` (`DW_OP_call_frame_cfa`) is necessary for probe-invariant `DW_OP_fbreg` resolution.

All five seams are validated through coupled live `x86-64` compilation/execution canaries (`rustc 1.98.0-nightly`, `LLVM 22.1.6`, `GNU readelf 2.47`) and mechanized end-to-end in [`support/r2_probe_backend_seam.lean`](support/r2_probe_backend_seam.lean) (`1,958` lines, `66` total theorems = `37` public + `29` private, `32` `#print axioms`-audited theorems, `0` `sorryAx`, `0` `Lean.ofReduceBool`, `0` `Classical.choice`, `0` `omega`, `0` `bv_decide`, verified synchronously under `Lean v4.34.1` in `12.26 s` and `623.35 MiB` peak RSS).

### 2. Sub-Register `WriteMode` & Upper-Lane Preservation Across `ISLE` -> `Virt -> Alloc` (`GAP-1` & `GAP-2`)

#### 2.1 Primary-Source Root Causes in `MiniMach`, `regalloc2`, and LLVM

- `[published source]` In [`verified-instruction-selection-isle-crocus-and-unified-minimach-ir`](../verified-instruction-selection-isle-crocus-and-unified-minimach-ir/REPORT.md) (`555f11dfed36`), `MiniMach`'s `LaneView` defines five GPR constructors (`full64 | lo32Zext | lo16Keep | lo8Keep | hi8Keep`), capturing 32-bit zero extension (`xor32` `31f0`) and `AL`/`AH` byte disjointness, but omits vector registers (`XMM`/`YMM`/`ZMM`). On `x86-64`, the single architectural slice `.xmm128` exhibits opposite upper-lane semantics depending on instruction encoding: legacy SSE (`movdqu`, `addss`) preserves `YMM[255:128]`, whereas VEX-128 (`vmovdqu xmm`, `vaddss`) zeroes `YMM[255:128]`.
- `[published source]` In [`verified-ssa-register-allocation-coalescing-and-subregister-lane-liveness`](../verified-ssa-register-allocation-coalescing-and-subregister-lane-liveness/REPORT.md) (`dd77614d49fe`), `WriteMode` introduces upper-lane modes (`preserveUpper | zeroExtend64 | zeroExtend128 | zeroExtend512`) over symbolic `Nat`-valued lanes, leaving two open composition seams: (1) no bit-vector theorem connecting symbolic lane masks to `x86-64` shift/mask hardware semantics, and (2) no bridge to `MiniMach` forms, instruction lowering, or spill-induced stack-probe frame growth.
- `[published source]` Production allocators leave both hazards exposed:
  - `bytecodealliance/regalloc2@4eb655fa745fba271af74be8495154a4b0cac56f` (`v0.15.3`) encodes `PReg` as a flat 6-bit index (`src/lib.rs:110-145`), omits safepoint/`reftype` tracking outside dead fuzz fields (`src/fuzzing/func.rs:58`), panics in `Algorithm::Fastalloc` on `OperandConstraint::Limit(4)` (`src/fastalloc/mod.rs:670-672`), resolves parallel moves with `MoveAndScratchResolver` (`src/moves.rs:324-446`), and contains a live soundness defect in `CheckerState::update` (`src/checker.rs:545-562`): `if let Some(val) = self.get_value(&from).cloned() { self.set_value(*into, val); }` lacks an `else` branch evicting `into` when `from` is unallocated.
  - `llvm/llvm-project@984202b7bd448b1c8da65689ecd2dd27aa891175` keeps `TargetSubtargetInfo::enableSubRegLiveness() = false` (`llvm/include/llvm/CodeGen/TargetSubtargetInfo.h:354`, `X86RegisterInfo.td:280-288,383-403`) on X86 and defaults `-aarch64-enable-subreg-liveness-tracking = false` outside SME streaming mode (`AArch64Options.td:214-217`), because coalescing `SUBREG_TO_REG` discards implicit upper-lane zeroing and requires four unverified invariants `(A)`–`(D)` in `AArch64SRLTDefineSuperRegs.cpp:9-82` (notably Invariant `(B)`: rematerializing a narrow zero-extending definition must not clobber live upper lanes).

## Boundaries

- **Toy Formalization Scope (`[toy model]`):** `support/r2_probe_backend_seam.lean` is a standalone zero-import Lean `v4.34.1` model over `16` architectural registers (`Fin 16`), 10-lane `Reg256` values, finite list-encoded CFGs, and abstract stack memory (`BitVec 64 -> BitVec 64`). It does **not** import or refine an external machine ISA decoder (such as Sail or `x86-64` instruction byte encodings) or connect directly to `rustc` MIR/LLVM MIR ASTs.
- **Dynamic `%r11` Probe-Loop Mechanization Boundary (`not mechanized`):** While Table E1 measures LLVM's `>= 9`-page `%r11` inline probe loop (`frame_loop_probe_36864`, FDE `[0x60]` switching CFA to `r11+36880` via `DW_CFA_def_cfa_register: reg11`), Section 4 of `support/r2_probe_backend_seam.lean` mechanizes unrolled per-page probe sequences (`expandFrameProbes`) with `%rsp`-relative `trackFdeCfaOffsets`. Mechanizing the dynamic `%r11`-loop invariant and register-switching CFA state machine remains follow-on work.
- **Target & ABI Coverage (`not examined`):** Live measurements and Lean proofs cover `x86-64` System V ELF64 (`rustc 1.98.0-nightly` / `LLVM 22.1.6`, `GNU readelf 2.47`) with AVX2 (`YMM[255:128]`). AVX-512 `ZMM[511:256]` masking (`k0..k7`), AArch64 SVE/SME streaming-mode sub-register tracking, Windows x64 SEH / `__chkstk`, Mach-O compact unwind, and red-zone interactions are not examined here.
- **Unwind-Table Straight-Line Comparison Scope:** References to straight-line `.eh_frame` formalizations document architectural limits when single-path CFA-offset proofs (lacking branches, calls, dynamic register switches, and LSDA call-site tables) are composed with LLVM's real post-epilogue cold landing pads.
