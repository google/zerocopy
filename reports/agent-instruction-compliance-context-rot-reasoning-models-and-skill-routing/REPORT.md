# Agent Instruction Compliance, Long-Context Rot, Reasoning-Model Sensitivity, and Progressive-Disclosure Skill Routing

## Summary

Primary-source inspection of 45 peer-reviewed papers and technical reports (2022–2026), six pinned public repositories (`agentskills/agentskills`, `anthropics/skills`, `openai/skills`, `benchflow-ai/skillsbench`, `ShishirPatil/gorilla`, `chroma-core/context-rot`), and a deterministic three-probe verification suite establishes five operational invariants for designing agent instruction surfaces, reasoning prompts, and tool/skill catalogs:

1. **Simultaneous Constraints Decay Super-Geometrically via Per-Constraint Attention Dilution, Collapsing Multi-Turn Strict Compliance:** Independent constant-rate Bernoulli compounding ($p_1^n$) systematically over-predicts strict all-constraints-met compliance on `ManyIFEval` ($n = 1 \dots 10$) by a mean of **`+29.1 pp`** at $n = 10$ (`RMSE = 0.173`), whereas an exponential attention-dilution model $p(n) = p_0 e^{-\alpha(n-1)}$ trained **strictly out-of-sample on instruction-level rates** (`MANYIFEVAL_INST`, zero prompt-level fitting) cuts mean RMSE to **`0.023`**, beating even a 1-parameter in-sample constant-rate fit on **8/8 models** (`Probe 1A`, `[derived fit to published table]`). In real coding harnesses (`MTAC-IFBench`, `12.97` active constraints/turn), even the top model (`GLM-5.2` on `Claude Code`) achieves only **`12.7%`** strict `C-ISR` (`80.4%` `CSR`), and **`8/11` Claude Code models (`7/8` OpenCode)** hit **`0.0%` `C-ISR`** by Turns 7–8 (`9/11` and `8/8` by Turns 9–10). Maintaining $\ge 90\%$ strict compliance under mild–moderate dilution ($\alpha \in [0.004, 0.011]$) permits only **`1–4` simultaneous active constraints** at $p_0 \in [0.95, 0.99]$ (`Probe 1D`).
2. **Effective Semantic Context Collapses Far Below Advertised Windows, and Sharding Instructions Across Turns Triggers Irreversible Unreliability:** Across 17 long-context models claiming $\ge 32\text{K}$–$1\text{M}$ tokens (`RULER`), only half sustain effective context at `32K`; when literal lexical overlap is removed (`NoLiMa`), effective length collapses to **`2K–8K`** (`GPT-4o` `8K`, `Claude 3.5 Sonnet` `4K`, `Gemini 2.0 Flash` `4K`, `Gemini 1.5 Pro` and `Llama 3.1/3.3` `2K`), and logically coherent haystacks degrade accuracy *more* than shuffled sentences (`Chroma Context Rot`). Splitting identical requirements across conversation turns (`Lost in Conversation`, 200K+ dialogues) causes an average **`-39%`** performance drop driven by a **`+112%` unreliability surge** that `T = 0.0` fails to cure and turn-by-turn recapitulation (`Snowball`) recovers by only `15–20%`.
3. **Native Reasoning Models Require Goal-First Zero-Shot Specifications; Over-Prescription and Overthinking Degrade Agentic Resolution:** On RL-trained reasoning models, few-shot prompting consistently degrades `DeepSeek-R1`, and explicit `"think step by step"` prompting increases latency `20–80%` while hurting `Gemini 2.5 Flash` (`-3.3 pp` mean, **`-13.1 pp`** 100%-consistency) and yielding only `+2.9` to `+3.1 pp` on `o3-mini`/`o4-mini` (`Meincke et al.`). In agentic SWE-bench execution (`Cuadron et al.`), overthinking (analysis paralysis, rogue actions, premature disengagement) is higher in reasoning models (`3.505` vs. `2.228`) and strongly negatively predicts patch resolution ($\beta_1 = -7.894, R^2 = 0.892, p = 0.000$ for reasoning models; $\beta_1 = -15.938, R^2 = 0.839$ for non-reasoning models). Checklists reliably improve *verification, judging, and RL alignment* (`TICK`, `RLCF`), whereas rewriting front-loaded skill prose into low-abstraction checklists shows no statistically significant gain over high-abstraction principles (`Controlled-Granularity`, `+0.7 pp` `GPT-5.5` / `-6.7 pp` `DeepSeek V4-Flash`, CIs cross zero; 80% MDE `8.3–16.0 pp`).
4. **Always-Loaded `AGENTS.md` Overviews vs. Selectively Triggered `SKILL.md` Packs Diverge on Redundancy, Correctness Scope, and Token Accounting:** Reconciling `ETH AGENTS.md` (`+20%`/`+23%` LLM-gen cost, up to `+19%` Dev cost, null pass-rate change) against `Lulla AGENTS.md` (`-28.64%` median runtime, `-16.58%` median output tokens) shows that `Lulla` never evaluates functional correctness, tests a single model on small PRs (`<= 100 LoC`), and sees **non-significant** input-token changes (median input actually rose `+3.41%` while tail runs dropped), whereas `ETH` traces confirm agents follow `AGENTS.md` by running more repo tooling, tests, and reasoning tokens (`+14–22%` on `GPT-5.2`). By contrast, curated on-demand `SKILL.md` modules (`SkillsBench`, 87 tasks, 18 configs) raise test-verified pass rates by **`+16.6 pp`** (`33.9% → 50.5%`), with `1–3` focused modules (`+18.0` to `+19.0 pp`) outperforming `>= 4` modules (`+10.1 pp`), whereas **self-generated skills actively hurt all three tested harnesses (`-8.1` to `-11.5 pp`)**.
5. **Catalog Scaling, Active Query Disambiguation, and Compaction Protection Govern Progressive-Disclosure Reliability:** In `138,133` public `SKILL.md` files (`138K-SKILL.md`), **`67.0%`** exhibit routing-metadata (`R1`) defects (led by `52.3%` missing trigger guidance). Mechanistic sensitivity modeling (`Probe 2`, `[toy model / mechanistic surrogate]`) shows that **pure 2-level hierarchy without active-query disambiguation does not outperform passive Top-3 retrieval** under semantic overlap (`58.5%` vs. `59.8%` at $M = 100$); accuracy gains at scale require agent-authored structured queries (`MCP-Zero` `API-Bank` Table 1: `-98.24%` tokens on 48 flat tools, `95.2–96.6%` top-1 vs. `71.6%` raw-query retrieval). Across multi-turn sessions (`agentskills` spec + `Probe 3`, `[toy model / mechanistic surrogate]`), un-exempt skill/reference tool observations suffer silent compaction eviction, and splitting task-critical rules into `references/` introduces a pre-trigger blind spot whose breakeven pull-through recall $q_{\text{trig}}^*$ spans **`27.5%–97.7%`** depending on single-file bloat and unassisted baseline $p_{\text{prior}}$.

### 1. Multi-Constraint Scaling, Context Rot, Multi-Turn Decay, and Privilege Hierarchy

#### 1.1 Constraint-Count Compounding and Out-of-Domain Generalization

1. **Template Overfitting vs. Out-of-Domain Verifiable Constraints (`IFEval` `2311.07911v1` Table 3; `IFBench` `2507.02833v3` §1, Table 3):**

Adding 58 *unseen* verifiable constraint types (`IFBench`, 1–2 constraints/prompt) exposes severe template overfitting: `Tülu-DPO 8B` scores `81.1%` on `IFEval` vs. **`25.5%`** on `IFBench`, and frontier models including `Claude 4 Sonnet` and `Qwen3-32B` score **below `50%`**. GRPO RLVR training (`IF-RLVR`) lifts `Tülu-DPO 8B` to `44.6%` and `Qwen2.5-7B` to `53.7%` on `IFBench`, but pure constraint RLVR on `Qwen2.5-7B` causes severe collateral capability collapse (`GSM8K` `15.3%`, `BBH` `26.0%`, `Alpaca` `1.1%`).
2. **Sequential, Conditional, and Multi-Constraint Collapse (`FollowBench` `2310.20410v3` Table 2; `ComplexBench` `2407.03978v3` Table 5; `ManyIFEval` `2509.21051v1` App. F.1 Tables 8–9):**

3. **High-Density Keyword-Inclusion Scaling (`IFScale` `2507.11538v1` Appendix A Table 1, §4–5 & `Probe 1B`):**
   - Sweeping $k \in \{10, 20, \dots, 500\}$ **single-turn keyword-inclusion constraints** (five milestones printed in multi-page Appendix A Table 1) across 20 models reveals a `68.9%` ceiling at $k = 500$ and three decay shapes:

     2. **Linear decay:** `gpt-4.1` `98.0% → 98.8% → 95.4% → 74.0% → 48.9%`; `claude-opus-4` `100.0% → 100.0% → 94.6% → 67.9% → 44.6%`; `claude-sonnet-4` `100.0% → 98.0% → 94.4% → 77.2% → 42.9%`.    - Under rising $k$, errors shift decisively from modification to **omission** (`claude-3.5-haiku` omission:modification ratio `0.00 → 4.83 → 13.11 → 22.69 → 31.69` across $k = 10 \to 500$), accompanied by universal **primacy bias** (`1.5×–3.37×` in the mid-range $k = 100\text{–}250$, compressing toward `1.1×–1.7×` at $k = 500$).
4. **Derived Safe Simultaneous Active Constraint Budget $k_{\max}$ (`Probe 1D`, `[derived fit to published table]`):**
   - Solving $\max \{k : (p_0 e^{-\alpha(k-1)})^k \ge \text{SLA}\}$ across empirical `MANYIFEVAL_INST` dilution tiers shows that even at $p_0 = 0.98$, achieving $\ge 90\%$ strict all-met compliance allows at most **`5`** simultaneous constraints with zero dilution ($\alpha = 0$), **`3`** under mild LRM dilution ($\alpha = 0.004$, `DeepSeek-R1`/`o3-mini low`), **`2`** under moderate dilution ($\alpha = 0.011$, `GPT-4o`/`DeepSeek-V3`), and **`2`** under strong dilution ($\alpha = 0.026$, `Qwen2.5-72B`). At $p_0 = 0.95$, $\ge 90\%$ strict SLA collapses to **`1–2`** active constraints in every regime.

#### 1.2 Positional Bias and Effective Long-Context Rot

- **U-Shaped Positional Attrition (`Lost in the Middle` `2307.03172v3`, Tables 6–7):** In 20-document QA, `GPT-3.5-Turbo (16K)` drops from **`75.7%`** (position 0) to **`54.1%`** (middle position 9, below its `56.1%` closed-book baseline; **`-21.6 pp`**) and partially recovers to `63.1%` (position 19); at 30 documents, `73.4% → 50.5% → 63.7%`. `Claude-1.3 (100K)` shows a shallower U-curve (`59.1% → 54.9% → 60.0%` at 30 docs). Extended-context variants behave nearly identically to shorter-context counterparts at matched input lengths.
- **Claimed vs. Effective Context Size (`RULER` `2404.06654v3` Table 3; `NoLiMa` `2502.05167v3` Table 3):**
  - On `RULER` (17 models, 13 tasks, threshold `85.6%` `Llama2-7B` 4K baseline), only half sustain effective context at `32K`: `Gemini-1.5-Pro` (`1M` claimed $\to$ `>128K` effective: `96.7% → 94.4%`); `GPT-4` (`128K` $\to$ **`64K`**: `96.6% → 87.0% → 81.2%`); `Llama3.1-70B` (`128K` $\to$ **`64K`**: `96.5% → 88.4% → 66.6%`); `Qwen2-72B` (`128K` $\to$ **`32K`**: `96.9% → 79.8% → 53.7%`); `Command-R-plus` (`128K` $\to$ **`32K`**: `63.1%` at 128K); `GradientAI/Llama3-70B` (`1M` $\to$ **`16K`**).
  - On `NoLiMa` (13 models, **zero literal lexical overlap** between needle and question, effective length $\ge 85\%$ of short-context base), effective context collapses sharply: `GPT-4o` (`128K` $\to$ **`8K`**, `99.3% → 69.7%` at 32K); `Claude 3.5 Sonnet` (`200K` $\to$ **`4K`**, `87.5% → 29.8%`); `Gemini 2.0 Flash` (`1M` $\to$ **`4K`**, `89.4% → 41.0%`); `Gemini 1.5 Pro` (`2M` $\to$ **`2K`**, `92.6% → 48.2%`); `Llama 3.3 70B` (`128K` $\to$ **`2K`**, `97.3% → 42.7%`); `Llama 3.1 405B` (`128K` $\to$ **`2K`**, `94.7% → 38.0%`); `Command R+` and `GPT-4o-mini` (`128K` $\to$ **`<1K`**, `7.4%` and `13.7%` at 32K).
- **Non-Uniform Context Rot and Coherent-Haystack Penalty (`Chroma Context Rot`, Jul 14, 2025; `chroma-core/context-rot@af80a080`):** Across 18 models (`GPT-4.1`, `Claude 4`, `Gemini 2.5`, `Qwen3`): (1) lower needle-query semantic similarity and topically related distractors accelerate length decay; (2) counterintuitively, **logically coherent essay haystacks degrade retrieval *more* than shuffled-sentence haystacks**; (3) on `LongMemEval` (~300 focused tokens vs. ~113K full history with identical evidence), every model family drops substantially; and (4) even trivial repeated-word copying triggers family-specific failure modes (`GPT-4.1` `2.55%` refusals past ~2,500 words; `Claude Opus 4` `69/194,480 = 0.035%` empty `stop_reason="refusal"` in NIAH; `Gemini 2.5` unprompted random words past ~500–750 words; `Qwen3-8B` `4.21%` non-attempts around ~5,000 words).

#### 1.3 Multi-Turn Attrition, Sharding Unreliability, Harness Amplification, and Privilege Hierarchy

- **Multi-Turn System & Multilingual Decay (`Multi-IF` `2410.15553v2` Table 1; `SysBench` `2408.10943v2` Table 2):** On `Multi-IF` (3 turns, 8 languages), `o1-preview` drops **`0.877 → 0.783 → 0.707`** across Turns 1–3 (`Llama 3.1 405B` `0.707`, `o1-mini` `0.681`, `Llama 3.1 70B` `0.668`), and model rankings reshuffle (`Qwen-2.5 72B` drops from 4th to ~7th). On `SysBench`, system-prompt stability across consecutive turns (`SSR`) trails single-constraint rate (`CSR`) sharply: `GPT-4o` `87.1% CSR → 76.4% ISR → 54.4% SSR`; `Claude-3-Opus` `85.0% → 74.1% → 51.8%`; `Qwen2.5-72B` `80.4% → 66.2% → 42.8%`; `Llama3.1-70B` `76.6% → 60.3% → 36.6%`, with dependent turns decaying faster than parallel turns.
- **Sharded Multi-Turn Unreliability (`Lost in Conversation` `2505.06120v1` Tables 1–3, §§6–7):** Across 200,000+ dialogues (15 LLMs, 6 generation tasks, 10 runs/cell), sharding identical specifications across turns lowers mean performance by **`-39%`** relative to single-turn `Full` (whereas single-turn `Concat` preserves `95–100%` of `Full`). Both standard frontier models (`GPT-4.1`, `Gemini 2.5 Pro`, `Claude 3.7 Sonnet`) and LRMs (`o3`, `DeepSeek-R1`) drop `30–40%`. Aptitude ($A^{90}$) falls only `16%`, while **unreliability ($U_{10}^{90}$) jumps `+112%`** (50 pp best-vs.-worst gap). Setting $T = 0.0$ cuts single-turn unreliability `50–80%` **but fails in sharded dialogues** (`0%` reduction on `GPT-4o-mini`, `15–20%` on `GPT-4o`, leaving ~30% unreliability) because premature early-turn attempts anchor subsequent turns. Turn-by-turn recapitulation (`Snowball`) recovers only `15–20%` of the drop.
- **Agentic Coding Harnesses and All-8 OpenCode Audit (`MTAC-IFBench` `2609.14992v1` Tables 2 & 5, §3.4, §4.4, App. I & `Probe 1C`):**

By Turns 7–8, **`8/11` Claude Code models (`7/8` OpenCode)** hit `0.0%` C-ISR; by Turns 9–10, **`9/11` (`8/8` OpenCode)** hit `0.0%`.

### 2. Instruction Form, Formatting Sensitivity, Negation Polarity, and Checklists vs. Principles

`Basis: source + derived`

#### 2.1 Prompt Formatting and Serialization Non-Universality

- **Spurious Formatting Spread (`FormatSpread` `2310.11324v2` §§4.2–4.5; `ProSA` `2410.12405v1` Table 2):** Meaning-preserving changes (separators, casing, whitespace, option delimiters) create spreads up to **`76 pp`** on `LLaMA-2-13B`, with $\ge 15\text{ pp}$ spread on 20% of tasks across `LLaMA-2` settings; `LLaMA-2-70B` 1-shot across 320 formats retains a **median spread of `17.1 pp`** (`mean 22.1 pp`, `std 20.0 pp`). `24%` of atomic single-character/whitespace edits shift exact-prefix accuracy by $\ge 5\text{ pp}$ (`11%` under probability ranking). Format rankings correlate weakly across models, and neither scaling nor few-shot exemplars eliminate sensitivity (`ProSA` shows sensitivity inversely tracks decoding confidence).
- **No Universal Markup Winner (`He et al.` `2411.10541v1` Tables 2–4):** Identical content serialized as Plaintext, Markdown, YAML, or JSON varies up to `40%` on `GPT-3.5-turbo` code translation. On `HumanEval` (Table 4), `GPT-3.5-turbo-0613` spans `40.24%` (Plaintext) / `42.68%` (YAML) → `54.27%` (Markdown) → `59.76%` (JSON), while `GPT-4-1106-preview` is flat (`82.93%–86.59%`), **yet `GPT-4-32k-0613` collapses to `21.95%` on JSON** vs. `76.22%` Plaintext / `75.61%` Markdown. Serialization choice must be validated per target model family rather than assumed invariant.

#### 2.2 Negation Blindness in Pre-2025 Models vs. Frontier LRM Polarity Gap

- **Pre-2025 Negation Failures (`Jang et al.` `2209.12711v1` §3; `Truong et al.` `2306.08189v1` Tables 3–5; `Varshney et al.` `2406.05494v1` Table 6; `NCO` `2605.10065v2` Table 1):** On `GPT-3`, `OPT`, `T0`, and `InstructGPT`, scaling exhibited **inverse scaling** on negated prompts (`~50%` chance average across affirmative+negated pairs). `GPT-J-6B` assigned lower perplexity (`288.94`) to false negated statements than true affirmatives (`434.42`), and `LLaMA-2`/`Vicuna-v1.5`/`Orca-2` hallucinated **`72–73%`** on `not`-constrained fact generation (where naive knowledge augmentation worsened false-premise hallucination, whereas cautionary instructions + exemplars mitigated it). For hard finite/regex exclusions on 7B–14B non-reasoning models (`Llama 2/3.1`, `Qwen 2.5 7B`, `Phi-4 14B`), unconstrained profanity violation remains `11.6–17.0%`, motivating automaton decoding enforcement (`NCO`) when zero leakage is mandatory.
- **2025–2026 Frontier Audit (`ManyIFEval` App. E Tables 5–6; `IFBench` Table 2; `MTAC-IFBench` §4.4 & App. C):**
  - On `GPT-4o` single-constraint isolation (`ManyIFEval` Tables 5–6), simple lexical exclusion lag is small (`0–3 pp`: `Keywords to include` **`0.98`** vs. `Forbidden keywords` **`0.95`**; `Quotation marks` `1.00` vs. `Comma prohibition` `1.00`; `StyleMBPP` *avoid `== True/False/None`* `0.992`, *no tabs* `1.000`) and is **dwarfed by counting/length constraints** (`Specific char count` **`0.62`**, `Sentence count` **`0.73`**, `Var name length` `0.794`).
  - Across `ManyIFEval`, `IFBench`, `MTAC-IFBench`, and `NCO`, **no published primary benchmark reports a polarity-stratified positive-vs.-negative breakdown for 2025–2026 frontier LRMs** (`o3`, `DeepSeek-R1/V4`, `Claude 4.x`, `Gemini 2.5/3.1`): `MTAC-IFBench` bundles positive and negative rules inside the same categories and finds dominant failures in orchestration, global paradigm/naming consistency, exact counts, and constraint updates. Frontier LRM negation lag under load is therefore explicitly **`unknown`** (recorded in **Boundaries**).

#### 2.3 Ordering Primacy and the Verification vs. Prescription Split for Checklists

- **Positional Salience:** Both long-context QA (`Lost in the Middle`: up to `-21.6 pp` mid-context trough) and dense instruction sets (`IFScale`: `1.5×–3.37×` primacy advantage at $k = 100\text{–}250$) penalize critical rules buried in the middle or tail of long prompts.
- **Checklists Win for Evaluation, Critique, and RL Alignment (`TICK` `2410.03608v1` Tables 1 & 4; `RLCF` `2507.18624v2` Tables 2–3, 6):** Binary checklist decomposition raises LLM-judge pairwise human agreement from `0.293` (direct preference) / `0.464` (direct score) to **`0.522`** (`TICK` Table 4); checklist self-critique (`STICK`) lifts `Command-R+` LiveBench Reasoning by `+7.8 pp` (`29.2% → 37.0%`, vs. `+0.8 pp` unstructured `Self-Refine`), though `GPT-4o` gains are negligible (`+0.8 pp` Math, `0.0` Reasoning, `-0.5 pp` coding). In alignment (`RLCF`), checklist-decomposed feedback improves `IFEval`, `InFoBench`, and `FollowBench` where scalar reward models regress.
- **Null Result for Front-Loaded Operational Checklists in Agent Skills (`Controlled-Granularity` `2605.31408v1` Tables 2–4, §3.6):** On a frozen 30-task oracle-validated `SkillsBench` subset (1,800 runs, 5 trials/cell, task as inference unit), rewriting curated skills into low-abstraction operational checklists vs. high-abstraction principles+invariants yields **`+0.7 pp`** on `GPT-5.5` (`95% CI [-10.0, +12.0]`, $p = 1.00$) and **`-6.7 pp`** on `DeepSeek V4-Flash` (`95% CI [-14.7, +0.7]`, Holm $p = 0.2695$); adding one worked example yields `+0.7 pp` (`[-5.3, +6.0]`) and `+1.3 pp` (`[-6.0, +9.3]`). On `GPT-5.5`, `original_curated` (`67.3%`) beat all rewritten variants (`58.0–62.0%`, CIs cross zero). **Power boundary (§3.6):** 80% minimum detectable differences are **`8.3–16.0 pp`** across the four primary contrasts, so this rules out *large* (>10–16 pp) prescription-granularity gains, not modest `3–8 pp` effects.

### 3. Native Reasoning / Thinking-Model Sensitivity and Overthinking Pathology

`Basis: source + documentation`

#### 3.1 Zero-Shot Goal Specifications vs. Explicit CoT and Few-Shot Over-Prescription

- **Few-Shot Degradation on RL Reasoning Models (`DeepSeek-R1` `2501.12948v2` §5):** Directly observed in the primary technical report: *"When evaluating DeepSeek-R1, we observe that it is sensitive to prompts. Few-shot prompting consistently degrades its performance. Therefore, we recommend users directly describe the problem and specify the output format using a zero-shot setting for optimal results."*
- **Diminishing or Negative Value of Explicit CoT Prompting (`Meincke et al.` `2506.07142v1`, GPQA Diamond, 25 trials/question):** Adding `"think step by step"` to native reasoning models increases latency **`20–80%`** (10–20 s) while yielding only marginal mean lift on `o3-mini` (`+2.9 pp`, $p = .024$) and `o4-mini` (`+3.1 pp`, $p = .003$) and **significantly degrading `Gemini 2.5 Flash`** (`-3.3 pp` mean, $p = .005$; **`-13.1 pp`** on 100%-correct consistency, $p < .001$; `-7.1 pp` at 90% threshold, $p = .016$). On non-reasoning models, explicit CoT helps `GPT-4o` (`+6.9 pp`, $p = .003$) and `Gemini 2.0 Flash` (`+6.2 pp`, $p < .001$) with null effect on `Sonnet 3.5` (`-1.9 pp`, $p = .189$) and `GPT-4o-mini` (`+0.4 pp`, $p = .728$), while introducing errors on easy questions in 3/5 non-reasoning models (whereas *forbidding* CoT still hurts non-reasoning models).
- **Convergent Authoring Practice:** Vendor guidance (`anthropics/skills@e4bb5d96` `skills/skill-creator/SKILL.md` L139, L302; OpenAI reasoning guidelines) recommends stating goals, output contracts, and *why* constraints exist rather than rigid step-by-step CoT scripts or all-caps `ALWAYS`/`NEVER` imperatives.

#### 3.2 Overthinking Regimes: Math Efficiency, Rumination, Agentic Paralysis, and Contested Cliffs

- **Non-Agentic Overthinking (`Chen et al.` `2412.21187v2` Table 1):** On trivial `ASDIV` arithmetic, `Llama-3.3-70B-Instruct` spends `166.4` tokens (`95.6%` acc, `95.6%` outcome efficiency), whereas `QwQ-32B-Preview` spends `741.8` tokens (`41.9%` outcome efficiency, 3.5 solutions) and `DeepSeek-R1` spends **`845.0` tokens** (`45.9%` outcome efficiency, 4.5 solutions — including `901` tokens / `13` solutions on `2+3=?`). On `GSM8K`, `DeepSeek-R1` uses `1,056.3` tokens (`48.9%` outcome efficiency) vs. `Llama-3.3-70B`'s `220.3`.
- **Thought-Length Sweet Spot and Long-Context Rumination (`Thoughtology` `2504.07128v3` §§3–5):** `DeepSeek-R1` shows a problem-specific optimal reasoning-length sweet spot on AIME-24 and `7×7`–`11×11` multiplication; beyond that optimum, accuracy drops markedly as traces enter repetitive reconsideration loops (**rumination**). Under long context (NIAH), `DeepSeek-R1` scores `95%` (below `Gemini-1.5-Pro`'s `100%`) and occasionally ignores instructions or emits out-of-place Chinese passages.
- **Agentic Overthinking Directly Predicts Failure (`Cuadron et al.` `2502.08235v1` Tables 1–2, §5):** Evaluating 19 models inside `OpenHands` on **SWE-bench Verified** identifies three interactive pathologies where internal simulation crowds out environment feedback: **Analysis Paralysis**, **Rogue Actions**, and **Premature Disengagement**. Reasoning models exhibit higher overthinking scores (`3.505 ± 1.774`) than non-reasoning models (`2.228 ± 0.751`), and overthinking strongly negatively predicts resolution rate: **$\beta_1 = -7.894, R^2 = 0.892, p = 0.000$** (reasoning models) and **$\beta_1 = -15.938, R^2 = 0.839, p = 0.010$** (non-reasoning models). Raising `o1` reasoning effort from `low` to `high` increases cost **`3.5×`** (`$400 → $1,400`) for only `+8.1 pp` (`21.0% → 29.1%`), whereas trajectory selection favoring lower overthinking (`Lowest Overthinking@k`) improves resolution efficiency.
- **Contested Complexity Cliffs (`Shojaee et al.` `2506.06941v3` vs. `Lawsen` `2506.09250v2` and `Khan et al.` `2506.18957v1`):** `Shojaee et al.` report three complexity regimes (standard models beat LRMs at low complexity; LRMs win at medium complexity; LRMs collapse and emit fewer tokens at high puzzle complexity even when given the algorithm). However, `Lawsen` demonstrates three confounds in that benchmark: (1) Tower of Hanoi move sequences exceed max output token limits, (2) automated grading conflates output truncation with reasoning collapse, and (3) **River Crossing instances for $N \ge 6$ are mathematically impossible** under the benchmark's boat capacity. `Khan et al.` further reframe the failure as an **agentic tool-use gap** (unassisted single-turn text simulation without code/scratchpad tools) rather than an intrinsic reasoning ceiling.

### 4. Tool and Skill Catalog Routing, Progressive Disclosure Mechanics, and Harness Divergence

`Basis: normative + source + derived + execution`

#### 4.1 Tool Catalog Scaling, Active Discovery, and Upstream Evidence Quality

1. **Multi-Turn and Missing-Tool Cliff (`BFCL` `PMLR v267:patil25a` Table 1; `ShishirPatil/gorilla@6ea57973`):** Frontier models score `77–97%` on single-turn AST function calling, but **Multi-Turn Base** drops sharply (`GPT-4o FC` `62.5%`, `Claude-3.5-Sonnet FC` `55.0%`, `o1 FC` `52.5%`, `Qwen2.5-72B` `24.5%`, `Llama-3.3-70B` `9.0%`), and **Multi-Turn Missing Function** (abstaining when no tool applies) collapses (`GPT-4o FC` **`6.0%`**, `Claude-3.5-Sonnet FC` **`19.0%`**, `o1 Prompt` **`0.5%`**, `Gemini-2.0-Flash-Exp` **`3.0%`**). `ToolLLM` (`2307.16789v2`) established neural retrieval over monolithic injection at `16,464` REST APIs; `Less-is-More` (`2411.15399v1`) cuts edge latency `-15%` and power `-6%` via dynamic hierarchical pruning; `ToolLoad-Bench` (`2601.20412v1`, 500 tasks, 106 tools) separates intrinsic DAG load from extraneous prompt ambiguity (`GPT-4o` `68.0%`, `Qwen3-235B` `58.0%`, `Llama3.3-70B` `17.0%`, tool-specialized `xLAM2-32B` `78.8%`).
2. **Active Tool Discovery — Separating `API-Bank` Flat Retrieval from `MCP-tools` NIAH (`MCP-Zero` `2506.01056v4` §§5.2–5.3, Table 1, Figs. 5–6):**
   - **`API-Bank` Level-1 (Table 1 — 48 flat tools, NO server-level hierarchy):** Comparing standard full-pool schema injection against passive raw-query retrieval (`Q.Retrieval`) and agent-initiated structured requests (`MCP-Zero`):
     - *Single-turn Full:* Standard injection uses `6,308.2` tokens (`Claude-3.5` `69.23%`, `GPT-4.1` `94.71%`, `Gemini-2.5` `94.23%`); `Q.Retrieval` scores `71.63%`; **`MCP-Zero` uses `111.0` tokens (`-98.24%`)** and reaches **`95.19%` / `95.19%` / `96.63%`** top-1.
     - *Multi-turn Full:* Standard uses `6,402.2` tokens (`60.22%` / `93.01%` / `92.47%`); `Q.Retrieval` scores `65.05%`; **`MCP-Zero` uses `159.0` tokens (`-97.52%`)** with **`90.32%` / `92.47%` / `94.62%`**.
   - **`MCP-tools` NIAH (§5.2 Figs. 5–6 — 308 servers / 2,797 tools, mean `9.08` tools/server):** Under two-stage server $\to$ tool active discovery up to `2,797` tools, `Claude-3.5-Sonnet` and `Gemini-2.5-Flash` gain substantially in accuracy and all models slash token cost, **while `GPT-4.1` shows zero accuracy improvement over standard full-schema injection** across all tested pool sizes.
3. **Offline Vector Retrieval and Upstream Reporting Anomalies (`Vector-MCP` `2603.20313v1` Tables 1 & 6; `RAG-MCP` `2505.03275v1` Table 1 & §§4–5):**
   - `Vector-MCP` (`Table 1`, 121 tools across 5 MCP servers, 140 multi-relevant queries, **offline embedding retrieval only** with `text-embedding-ada-002`, no end-to-end LLM execution): sweeping $K = 1 \to 10$, `Precision@K` falls monotonically **`92.1% → 26.5%`**, `Recall@K` rises **`31.5% → 90.6%`**, `F1@K` peaks at $K = 3$ (**`58.4%`**, `P@3 = 57.6%`, `R@3 = 59.6%`), `Hit@K` climbs `85.0% → 97.1%` ($K = 3$) and plateaus (`98.6%` at $K = 10$), and `MRR` stabilizes at `0.9083` (`K = 3`). Semantically overlapping servers (`Filesystem`, `F1@3 = 49.3%`) underperform distinct schemas (`GitHub` `58.8%`, `MySQL` `52.0%`). **Upstream anomaly (excluded):** `Vector-MCP` reports a flat **`99.6%` token reduction across all $K \in \{1, 2, 3, 5, 10\}$** (`Table 1`) and `99.2%` at $K = 10$ on the 10-tool `Time/Weather` server (`Table 6`, where $K = 10$ retrieves 100% of tools), which is mathematically impossible against a 121-tool catalog (`1 - 10/121 = 91.7%` max) and is not used as a quantitative anchor.
   - `RAG-MCP` (`2505.03275v1`, **directional evidence only**): Table 1 reports `MCP-RAG` `43.13%` (`1,084` prompt tok) vs. keyword `Actual Match` `18.20%` (`1,646` tok) vs. `Blank` `13.62%` (`2,133.84` tok). However, §§4.1–5 contain severe internal contradictions—claiming to sample $N = 1 \dots 11{,}100$ distinct servers from a `4,400`-server registry, referring to `"MCP positions"` `below 30 / 31–70 / ~100` while alternating between prompt-bloat and retrieval interpretations, naming both `Deepseek-v3` and `"Llama as Judge"`, and reporting non-multiple-of-5% accuracy (`43.13%`) from `20` trials—so `RAG-MCP` is retained only as directional support that retrieval beats flat injection, never as a numeric calibration anchor.
4. **Mechanistic Routing Phase Transition and Active-Query Disambiguation (`Probe 2`, `[toy model / mechanistic surrogate]`):**
   - Modeling single-relevant queries across catalog sizes $M \in \{5, 15, 30, 50, 100, 200, 300\}$ under `Crisp + Exclusions` (`0%` `R1` defects) vs. `Pushy Overlap + 67% R1 Defects` (`ctx_rot = 0.022/1k tok`) reveals three structural mechanisms:
     1. **Pure 2-level hierarchy (`active_gain = 0.0`, equal-footed) does NOT beat passive Top-3 retrieval under semantic overlap:** At $M = 100$ (`Pushy`), `Flat` collapses to `25.5%` (`10,000` tok), `Passive Top-3` holds `59.8%` (`350` tok), and equal-footed `Hier(g=0)` scores **`58.5%`** (`1,350` tok; `43.5%` vs. `45.0%` at $M = 300$) because an unrecoverable Stage-1 cluster error hurts more than keeping 3 flat candidates alive.
     2. **Active structured-query disambiguation (`g > 0`, closing the raw-query-to-spec semantic gap) drives the accuracy leap:** Sweeping `active_gain` from `g = 0.0 → 0.5 → 1.0` at $M = 100$ (`Pushy`) lifts hierarchical accuracy **`58.5% → 82.8% → 93.5%`** (and `43.5% → 70.8% → 93.8%` at $M = 300$) while cutting flat tokens by `>90%`.
     3. **Crossover $M^*$ is parameter-sensitive and requires decoupled controls:** In the `Crisp` regime, `Flat < 90%` occurs at $M^* = 50$ (`rot = 0.040`), `100` (`0.022`), `200` (`0.010`), and `300` (`0.005`). Decoupled negative controls confirm that *both* length rot and description overlap independently degrade flat catalogs: `overlap = 0 & ctx_rot = 0` gives `100.0%` at $M = 300$, whereas `overlap = 0` *with* `ctx_rot = 0.022` still drops to `87.2%` (`M = 100`) and `8.8%` (`M = 300`), and `pushy overlap` *with* `ctx_rot = 0` still drops to `67.8%` (`M = 30`) and `63.2%` (`M = 100`).

#### 4.2 Normative 3-Tier Progressive Disclosure, Client Failure Seams, and Harness Divergence

- **Normative Architecture (`agentskills/agentskills@83021e2b`, `anthropics/skills@e4bb5d96`, `openai/skills@49f948fa`):**
  - `docs/specification.mdx` (L27–32, L216–234) and `docs/skill-creation/best-practices.mdx` (L83–98) specify 3-tier lazy loading: (1) **Metadata** (`name` $\le 64$ chars, `description` $\le 1024$ chars, ~50–100 tok/skill) loaded at startup; (2) **Instructions** (`SKILL.md` body, `< 500 lines` / `< 5,000 tokens` recommended) loaded only upon activation; (3) **Resources** (`scripts/`, `references/`, `assets/`) loaded conditionally on demand. `openai/skills` (`skills/.system/skill-creator/SKILL.md` L28–46, L127–139) frames context as a shared public good and prescribes matching **Degrees of Freedom** (prose heuristics vs. parameterized pseudocode vs. rigid executable scripts).
  - **Single-skill vs. catalog-scale description tension:** Both `anthropics/skills` (`skills/skill-creator/SKILL.md` L67) and `agentskills` (`docs/skill-creation/optimizing-descriptions.mdx` L23–26) advise making startup descriptions *"a little bit 'pushy'"* to counter single-skill undertriggering, noting only during refinement (L153) to add negative boundaries when near-miss queries false-trigger. At large catalog sizes, broad pushy descriptions increase inter-skill overlap (`Probe 2`).
- **Three Documented Client-Implementation Failure Seams (`agentskills@83021e2b:docs/client-implementation/adding-skills-support.mdx`, L22–326):**
  1. **No eager Stage-2→3 loading (L306):** Dedicated activation tools *"should not eagerly read"* `references/` or `scripts/`; pull-through relies on a second model-initiated file-read call guided solely by conditional pointers in `SKILL.md`.
  2. **Permission-dialog stalls (L310–312):** Failing to allowlist skill directories causes `references/` or `scripts/` reads to hit interactive approval prompts.
  3. **Silent compaction eviction (L318–326):** Because activated skill bodies enter as tool-call observations, naive context truncation or summarization silently evicts them mid-session (*"losing them mid-conversation silently degrades the agent's performance without any visible error"*) unless explicitly tagged and exempted from pruning.
- **Real-Harness Divergence (`benchflow-ai/skillsbench@f860ecf0:docs/harnesses/skill-invocation-surfaces.md` L34–285 & `SkillsBench` Table 14):**
  - Harnesses differ materially: `claude-code` exposes a dedicated `Skill(name=...)` tool with enforced `allowed-tools`, `paths`, `hooks`, and `context: fork`; `opencode` exposes a spec-strict `skill({name})` tool with `<available_skills>` inside the tool description and ignores `allowed-tools`; `openhands` CLI `1.15.0` lacked a first-class skill tool (relying on keyword-triggered microagent prompt injection; `invoke_skill` landed in `sdk 1.18.0+`); `codex` deliberately omits a skill tool and injects `<skill>` user-role text fragments via `$skill-name` or command matching, leaving no tool-call event in trajectories.
  - Behavioral impact (`SkillsBench` Table 14): the **same model** (`Gemini 3.1 Pro`) invokes task skills **`90.4%`** (`236/261`) in `Gemini CLI` (`60.8%` overall pass) vs. **`54.0%`** (`141/261`) in `OpenHands` (`52.8%` overall pass, despite `68.7%` conditional pass when invoked).
- **Pre-Trigger Blind Spot and Compaction Eviction Trade-Off (`Probe 3`, `[toy model / mechanistic surrogate]`):**
  - Modeling 4 required obligations (2 core + 2 task-critical details) over Turns `T = 1..8` (`p_guided = 0.96`, `gamma_turn = 0.015/turn`) quantifies two structural effects:
    1. **Compaction protection dominates long-horizon retention:** At `T = 8`, unprotected sliding-window eviction (`e_comp = 0.15/turn`) drops `Compact` single-file survival from **`54.0%`** (`e_comp = 0.00`) to **`35.6%`** (**`-18.4 pp`**). Under `Split` (`q_trig = 0.80`, `e_comp = 0.15`), modeling core and reference observations as **independent** evictions lowers `T = 8` survival an additional `-0.91 pp` below **coupled** shared-window eviction (`34.14%` vs. `35.05%`; analytical and 4,000-trial Monte Carlo agree within `0.41–1.44 pp`).
    2. **Breakeven pull-through recall $q_{\text{trig}}^*$ spans a broad parameter-dependent range:** Sweeping single-file bloat penalty $\delta \in [0.004, 0.040]$ and unassisted baseline $p_{\text{prior}} \in [0.50, 0.85]$ at $T = 1$ moves $q_{\text{trig}}^*$ across **`27.5%` to `97.7%`** (decreasing monotonically in both $\delta$ and $p_{\text{prior}}$). At low single-file bloat ($\delta = 0.008$, $p_{\text{prior}} = 0.72$), splitting into `references/` hurts whenever Stage-2→3 trigger recall $q_{\text{trig}} < 92.5\%$; at heavy bloat ($\delta = 0.145$), splitting wins at any $q_{\text{trig}} > 0\%$ (`34.1%` even at $p_{\text{prior}} = 0.50$). Thus compact skills should keep task-critical invariants inline and defer only genuinely optional or bulky reference material.

4. **Prior strength and selective procedural triggers (`SkillsBench` Table 3):** Mainstream Python SWE tasks benefit from strong pretraining priors (`+11.6 pp`), whereas non-inferable procedural workflows and executable scripts deliver much larger lifts in weaker-prior domains (`+18.9` to `+28.8 pp`) without paying an always-on context tax on unrelated tasks.

## Boundaries

- **`unknown` — Positive-vs.-Negative Constraint Polarity on 2025–2026 Frontier Reasoning Models:** Pre-2025 studies (`Jang 2022`, `Truong 2023`, `Varshney 2024`) document severe negation blindness on `GPT-3`/`InstructGPT`/`LLaMA-2`, while `ManyIFEval` App. E Tables 5–6 show only `0–3 pp` single-turn lexical prohibition lag on `GPT-4o`. However, none of `ManyIFEval`, `IFBench`, `MTAC-IFBench`, or `NCO` publish polarity-stratified accuracy for 2025–2026 frontier LRMs (`o3`, `DeepSeek-R1/V4`, `Claude 4.x`, `Gemini 2.5/3.1`) under multi-constraint or multi-turn load.
- **`unknown` — Empirical Stage-2→3 `references/` Pull-Through Rate ($q_{\text{trig}}$):** While `SkillsBench` Table 14 measures Stage-1 `SKILL.md` invocation (`46.4%–99.2%`) and `agentskills` recommends against eager `references/` reading, no controlled primary benchmark examined here directly measures empirical Stage-2→3 conditional file-read recall across harnesses or trigger phrasings.
- **`unknown` — Exact Causal Mechanism of the `Claude Code` vs. `OpenCode` Initial CSR Gap:** `MTAC-IFBench` measures the harness gap and observes flatter late-turn decay in OpenCode, but does not ablate which specific harness variable (policy-file injection format, tool schema, or compaction cadence) causes the initial Turn 1–2 CSR deficit.
- **`unknown` — `AGENTS.md` ROI on Low-Resource / Proprietary Toolchains:** Both `ETH AGENTS.md` (100% Python) and `Lulla AGENTS.md` (mainstream public GitHub repos) evaluate high-prior languages; whether always-loaded `AGENTS.md` yields positive correctness ROI on low-prior toolchains (e.g., proof assistants or custom build systems) is unmeasured by those studies.
- **`unknown` — Small (`3–8 pp`) Presentation-Granularity Effects in Skills:** `Controlled-Granularity` (`2605.31408v1` §3.6) has 80% minimum detectable differences of `8.3–16.0 pp`; its null result rules out large granularity effects, not subtle `3–8 pp` effects.
- **`known not to apply` — Single-Turn Benchmarks, `T = 0.0`, and Advertised Context Windows to Multi-Turn Agentic Horizons:** Single-turn compliance does not survive multi-turn sharding (`-39%`, `Lost in Conversation`) or 13-constraint coding horizons (`0%` C-ISR past Turn 6 for `8/11`–`9/11` models, `MTAC-IFBench`); lowering temperature to `T = 0.0` fails to cure sharded unreliability; advertised `128K–2M` windows collapse to `2K–8K` under zero-lexical-overlap semantic retrieval (`NoLiMa`).
- **`known not to apply` — Self-Generated Skills and Uncalibrated `SkillsBench Table 9` Causal Length Claims:** Self-generated skills degrade all three tested harnesses (`-8.1` to `-11.5 pp`, `SkillsBench`); `SkillsBench Table 9` (`Comprehensive` `N = 5`, `Standard` `19.8%` baseline) is observational and cannot be cited as an unconfounded causal length curve.
- **`known not to apply` — `MTAC-IFBench` Uniform Compounding Ratio Across All Models and Pure Hierarchy Without Active Queries:** `(CSR_OC/CSR_CC)^12.97` fails on 5/8 shared `MTAC-IFBench` models (including 2 sign reversals); in `Probe 2`, pure 2-level hierarchy (`active_gain = 0`) does not beat passive Top-3 under semantic overlap.
- **`unsupported` — Universal Markup Superiority, `Vector-MCP` `99.6%` Token Reduction, `RAG-MCP` Exact Breakpoints, and `138K-SKILL.md` as LLM Routing:** No single serialization format (`JSON`/`Markdown`/`YAML`/`Plaintext`) wins across checkpoints (`GPT-4-32k-0613` collapses to `21.95%` on JSON); `Vector-MCP`'s `99.6%` token reduction across `K = 1..10` (`99.2%` at `K = 10` on a 10-tool server) is mathematically inconsistent; `RAG-MCP`'s `N = 1..11,100` / `31–70` breakpoints suffer severe internal paper contradictions; `138K-SKILL.md`'s `88.5% vs. 82.6%` routing test uses lexical BM25 only; `ETH Table 7` category ablations cover `GPT-5.2` only; `MTAC-IFBench` Fig. 7 placement covers `N = 30` without significance tests; `Probe 2` and `Probe 3` are `[toy model / mechanistic surrogate]` parameter sweeps rather than live LLM measurements.
- **`not examined` — Multimodal Instruction Following, Non-English Skill Routing, Fine-Tuned Router Classifiers, and Adversarial Skill Registries:** Vision/video IF benchmarks, non-English skill catalogs, LoRA/classifier-based routers, and malicious prompt-injection payloads embedded in third-party skill registries were outside scope.
