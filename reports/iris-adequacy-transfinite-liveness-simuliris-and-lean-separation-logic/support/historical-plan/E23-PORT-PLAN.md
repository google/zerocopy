# E23 proof-port frontier after the existing-artifact replay

This is a plan, not an executed proof or failed-port outcome. Existing source here is the exact Simuliris archive. Its calculus functions and resource rules are real proof subjects; identifying a Rust API implementation with them requires a separate relation. No source-to-MiniRust or Rust safe-client link is assumed.

| Requested port | Existing source interface to audit | Concrete next proof and discriminating obligation |
| --- | --- | --- |
| Allocation + initialization | `step_laws/steps_local.v:322 sim_alloc_local`; `examples/lib.v:35 sim_new_place_local`; `:67 new_place_safe_reach` | Fix the exact owned calculus `new_place` body and an input-value/length contract. Prove preservation of both source/target heaplets and returned tag/range resources with nonvacuous safe initial witnesses. Preserve the fact that the existing source-safe reach lemma extracts length under an assumed-safe execution; it does not prove arbitrary initialization safety. A wrong size must fail the intended API premise rather than be hidden by a false source-safety assumption. |
| Split/recombine | `logical_state.v:851–867 list_to_heaplet`, `array_tag`, `array_tag_map`; `:1226 ghost_map_array_tag_update` | Define an actual subrange resource/view and its relation to the authoritative heaplet, with disjoint ranges and a recombination inverse. The current single `(tag,block)` ghost-map element carries a whole offset map, not one separable resource per element. Do not assert an ordinary array-append split without a new resource argument. An overlapping/duplicated exclusive subrange is the negative contract. Record whether the required representation/rule can be derived or needs an invariant extension. |
| Recursive reborrow + protector end | `step_laws/steps_retag.v:67 sim_retag_default`, `:304 sim_retag_fnentry`; `loc_controlled_laws.v:380 loc_controlled_read_after_reborrow_creates`; `step_laws/steps_opt.v:310 sim_protected_unprotect` | Fix a concrete two-level reborrow body, sizes, call IDs and activation phases. Preserve the related-pointer/value premises, per-call protector map, lengths and the value relation required at unprotection. Show which parent/child capability becomes usable after each end call. Wrong call ID, omitted protector ownership or premature restoration are distinct controls; their rejection has not been executed here. |
| Cell + reentrant/unknown callback | `bor_semantics.v:793 retag_perm`; `loc_controlled_laws.v:356–366` tag mappings; the two selected unknown-code contextual examples | A shared `InteriorMut` retag is semantically `Cell`; the owned tag mapping for it is `None`, and all unprotected `InteriorMut` mappings are `None`. The existing rule with `pointer_kind_to_tag_unprotected ... = Some tk` cannot simply be reused as a Cell ownership rule. Design a Cell invariant/callback protocol and prove its actual calculus behavior, including reentrancy and allowed mutation, before claiming the API port. A frozen-value frame across a mutating callback is a required negative contract. The archive's closure environment is an explicit argument, not Rust closure elaboration. |
| Returned reference/resource | `logical_state.v:1256 sc_rel`; `tree_borrows/behavior.v:12–29 obs_scalar/obs_result`; actual retag/unprotect interfaces | Specify the returned pointer together with range, value relation, ownership phase and surviving call/lifetime resources. A contextual refinement that treats pointer details as unobservable does not itself return a unique heaplet or prove a lifetime. End-call restoration and retained aliases must be explicit. Returning an observationally related pointer with no required resource is the negative contract. |

For every new port, preserve the precise implementation body and hash, parameters/monomorphization, source/target syntax, initial-state/resource predicates, postcondition, proof term and actual assumptions. If a proof attempt fails, retain its original statement, proof state, diagnostics and reason before changing the design. Do not turn a requested API into a weaker scalar/table theorem or use an admission to obtain a passing artifact. No invalid Rust execution is necessary for these logical negative controls.

Suggested sequence: replay the existing 78-module closure first; then audit the allocation, retag and single-element heaplet interfaces; select one genuinely new allocation/range resource proof with the parent; and schedule splitting, recursive reborrow, Cell/callback and returned-resource extensions as separately reviewable ports. Their choice of resource interpretation may require E20 work. Actual MiniRust/calculus transition correspondence remains E18, and universal Rust safe-client/implementation/trait transport remains E24. E23 is not closed by this plan or by replay of the existing optimization examples.
