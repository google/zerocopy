# ASL, L3, LNSym, and Multi-Prover ISA Verification Frameworks: Architecture, Proof Boundaries, and Lean 4 Adaptation for Anneal

## Summary

This report synthesizes six complementary investigations spanning hardware architecture description languages (Arm's **ASL** and Anthony Fox's **L3**), native Lean 4 AArch64 symbolic simulation (**`leanprover/LNSym`**), non-Lean machine-code verification frameworks across **Rocq, F\*, ACL2, HOL4, and Isabelle/HOL** (`Isla`/`Islaris`/`CN2Islaris`, `riscv-coq`/`bedrock2`, `CompCert`, `Jasmin`, `Vale`, `ACL2 x86isa`, `K x86`, `HOL4 L3`/`CakeML`/`HolBA`, and `seL4 l4v`), and the end-to-end proof, TCB, concurrency, constant-time, and platform-extension boundaries of assembly and ISA verification:

1. **ASL (`mra_tools`, `asl-interpreter`, `asl_to_sail`, `herdtools7/asllib`) vs. L3 (`coruus/L3`) Translation Strategies:**
   - **ASLv0 vs. ASLv1 Type-Checking and Getter/Setter Reference Semantics:** Arm's Machine Readable Architecture (MRA) XML specifications are extracted by `mra_tools/bin/instrs2asl.py` and `bin/reg2asl.py` into ASLv0 (`rems-project/asl-interpreter` at `8cfc0b27002d282da55568e3462868e9dfd8c3bd`), where bitvector types `bits(E)` carry arbitrary AST expressions `E` checked by unification (`libASL/tcheck.ml:811-955`) and external Z3 queries (`check_constraints`, `libASL/tcheck.ml:761-790`, which unconditionally rewrites `(a DIV b) * b` to `a` at lines `725-727, 743-754`). ASLv0 array-like setters (`Decl_ArraySetterDefn`) permit `Formal_InOut(ty, id)` reference parameters (`&vector`, e.g., `Elem[bits(N) &vector, integer e, integer size] = bits(size) value` in `asl-interpreter/prelude.asl:68-77`). While `libASL/tcheck.ml:1588-1676` elaborates nested slice assignments on getters/setters into `LExpr_ReadWrite`, `asl-interpreter`'s evaluator (`libASL/eval.ml:595-601, 972-981`) invokes `eval_proccall` by value on `LExpr_Write`, binding `Formal_InOut` parameters to local variables in the callee environment and discarding the callee frame on return without writing back to the caller's l-expression. Arm's modern ASLv1 (`herd/herdtools7/asllib` at `6bea2e8131feaeb497a7bf86d52d94cdd8721a6c`) eliminates both hazards: integer constraints are tracked statically (`constraint_kind = UnConstrained | WellConstrained of int_constraint list * precision_loss_flag | PendingConstrained | Parameterized`, `asllib/AST.mli:255-273`), bitvector widths must evaluate to static constants or constrained symbolic expressions (`asllib/Typing.ml:568-573`, `Interpreter.ml:696-700`), `&` reference setter parameters are replaced by paired `accessor_pair` definitions (`asllib/desugar.ml:212-248`), and partial setter assignments (`Setter(args).field[slice] = rhs`) are desugared by `desugar_setter` (`asllib/desugar.ml:126-162`) into a 3-statement read-modify-write sequence using a fresh `__setter_v1_temporary`.
   - **`asl_to_sail` Z3 Constraint Repair & Manual Patching (`rems-project/asl_to_sail` at `78242b8d60a507fab18d9b4f225bfc7bd33e62b3`):** Converts `Formal_InOut` setter parameters into pure return values (`lib/translate_asl.ml:1762-1784, 3082-3117`), expands slice writes via `SetSlice`/`vector_update_subrange` (`lines 2038-2065`), hoists SVE/SME runtime vector lengths (`CurrentVL.read()`, `PL.read()`) into existential type variables (`lines 257-342`) or `-mono_vl` case splits (`lines 2900-2910`), runs a 3-pass fixed-point abstract interpreter (`intConstraintsClass`, `lines 1038-1194, 3149-3179`), and wraps `Libsail.Type_check.check` in a 50-iteration feedback loop (`iterate_check` in `bin/main.ml:731-770`, invoking `Sail_to_sail.rewrite_add_constraint` in `lib/sail_to_sail.ml:844-925`) supplemented by manual `.sail` and `.val.sail` override patches (`bin/main.ml:780-829`).
   - **L3's Closed Functional Compilation Pipeline (`coruus/L3` at `d6558e679a25ffaaf16a47a3189f8f8111e45e0c`):** Restricts bitwidths to concrete integers (`BV of int`) or finite-set type variables (`BVV of string` with `Constrain.constraints` in `L3/Base.sml:263-429`, monomorphized by `Expand.expandDefns` in `L3/Export.sml:435-610`), compiles bit-string pattern matching via `Matches.boolifyMatches` (`L3/Matches.sml:435-483`) and balanced decision trees `Convert.boolMatchConv` (`L3/Export.sml:1213-1323`) with static exhaustiveness checking (`Term.checkMatch`, `L3/Base.sml:3198-3278`), and lowers imperative state and exceptions via `Exception.buildExceptionDatatype` (`L3/Export.sml:36-54`), `Monadify.monadifyDefn` (`lines 843-1013`), and beta-reduction `Monadify.deMonadifyDefn` (`lines 1026-1121`) into flat pure functions `state -> val * state`.
   - **Mechanized ASL/L3-to-Lean 4.34.1 Bridge (`support/asl_l3_to_lean_bridge_probe.lean`):** 1,161 lines checked with zero `sorryAx` and zero custom axioms, mechanizing lawful indexed lenses (`X`, `V`, `Elem`), proving `asl_to_sail_Elem_write = asllib_desugar_rmw` by `rfl` and `asl_interpreter_by_value_bug_loses_write`, proving that `ConstrainUnpredictable` with `Constraint_UNDEF` collapses Anneal's demonic `BehaviorOf.defined` to `False` (`constrained_unpred_with_undef_not_defined`, `l3_load_imm_unpred_not_defined`) whereas non-faulting constraints preserve `BehaviorOf.defined` (`constrained_unpred_nonfaulting_is_defined`), and verifying a 4-instruction AArch64 L3 prototype (`decodeA64_encodeA64_roundtrip`, `testProg_four_step_rfl`, `testProg_refines_spec`).

2. **`leanprover/LNSym` AArch64 Symbolic Simulator, Tactic Architecture, and Memory Framing (`5c05220ff970e3bdd7813ad0c9ef3741522c8b92`):**
   - **Harvard State Split & Unified `r`/`w` Algebra (`Arm/State.lean`, `Arm/Exec.lean`):** `ArmState` separates instruction storage (`program : Map (BitVec 64) (BitVec 32)`) from data memory (`mem : BitVec 64 → BitVec 8`) and accesses/updates all 70 non-memory fields (`32` GPRs, `32` 128-bit SIMD/FP registers, `PC`, `4` `PState` flags, `StateError`) via `@[irreducible]` `r` and `w` functions with `@[state_simp_rules]`.
   - **Four Primary-Source Bugs/Anomalies Uncovered and Machine-Checked (`support/lnsym_architecture_and_bridge_probe.lean`, 1,390 lines, zero `sorryAx`):** (1) `LDST.mayModifiedRegs` (`Arm/Decode.lean:260-308`) inverts the AArch64 load/store bit (`opc[0]` and `L`), returning `[]` for loads (`LDR`/`LDP`/`LD1`) and `[Rt, Rn]` for stores (`STR`/`STP`/`ST1`) (`bug1a_ldst_mayModifiedRegs_omits_ldr_destination`, `bug1b_ldst_mayModifiedRegs_falsely_reports_str_registers`); (2) `BR.mayModifiedRegs` (`Arm/Decode.lean:103-109`) omits `x30` (`LR`) on `BL` (`bug2_br_mayModifiedRegs_omits_bl_link_register`); (3) `Reg_imm.lean:109-113` and `Reg_pair.lean:103-105` advance `PC` by `4` even when `CheckSPAlignment` sets `StateError.Fault` (`anomaly3_ldst_reg_imm_fault_still_advances_pc`); and (4) `BitVec.enumFrom` (`Tests/ELFParser/SymbolContents.lean:46-50`) increments instruction addresses by `+1` byte instead of `+4` bytes per 32-bit word.
   - **Two-Phase Symbolic Simulation (`#genStepEqTheorems` + `sym_n`/`sym_block`) & Half-Open Memory Framing (`Arm/Memory/`):** `mem_legal'`, `mem_separate'`, `mem_subset'`, `mem_omega`, and `simp_mem` discharge byte-slice framing. Because unaugmented `ArmState.mem` is a total map without permissions or access traces, `lnsym_unaugmented_state_blind_to_dead_load_and_self_store` proves that unaugmented `ArmState` cannot distinguish a valid 8-byte swap from a dead out-of-bounds load or an unauthorized self-store; wrapping `exec_inst` with `instMemAccesses` + `FootprintPolicy` in `footprintLNSymMachine` rejects both OOB programs with `.failed .ub` while proving `swap_tgt_well_formed` and `swap_compiles`.

3. **Rocq, HOL4, Isabelle/HOL, ACL2, K, and F\* ISA Verification Frameworks & Lean 4 Adaptation (`support/islaris_trace_and_riscv_typeclass_lean_probe.lean`, 936 lines, zero `sorryAx`):**

   - **`CN2Islaris` (`f34f9a2f0a9b75a6b342aa966d0d14daca58c466`) & `cerberus` (`3bdd8cb8e2805d46c22725d7651a2ed90b012837`):** Translates CN `Owned<unsigned long>` and 1D arrays into Islaris points-to assertions discharged by Lithium (`liARun`), but relies on `dwarfData.get_max_stack_depth` (`backend/cn/dwarfData.ml:49-71`), which diverges on recursive call graphs.
   - **`mit-plv/riscv-coq` (`45dc8dfc17c77aabb433355b9d39edc6bfd429ae`) & `bedrock2` (`757f17c6083bf8d43b5293a0db545c8d0aa32a13`):** Decouples pure `decode` from `execute` parameterized over `RiscvProgram`, `RiscvProgramWithLeakage`, `RiscvMachine`, and `PrimitivesParams`. ## Findings

### 1. ASL, L3, and Architecture DSL-to-Lean 4 Translation Strategies

#### 1.1 MRA XML Extraction, ASLv0 Unification, and the `Formal_InOut` By-Value Bug (`mra_tools`, `asl-interpreter`, `herdtools7/asllib`)

1. **MRA XML Extraction into ASLv0 (`rems-project/mra_tools` at `941317606f36580f668498889abc6301ed8222d8`):**
   - `bin/reg2asl.py` (blob `238501b36cd1bebb0e4bd462fc25d3eb20dea0d3`, `lines 115-248`) parses `<reg_fieldset>` and `<field>` XML tags to emit `__register bits(width) { hi:lo field_name, ... } reg_name;` declarations (`Decl_RegDefn` in `asl.ott:268`), where field accesses (`SCTLR_EL1.M`) elaborate into bit-slice reads and writes (`LExpr_BitTuple` / `LExpr_Slices`).
   - `bin/instrs2asl.py` (blob `e89baa62a8356d3ac8bbc604c43d8a2e873bcb5e`, `lines 110-245, 480-590`) inspects `<box>` elements in `<regdiagram>`, relaxing constrained `(0)` and `(1)` bits to `'x'` in `__opcode` masks and emitting explicit `__unpredictable_unless <bit_index> == '<0|1>';` guards (`lines 157-180`). Each instruction page becomes a `Decl_InstructionDefn` (`asl.ott:295-307`) with `__encoding`, `__postdecode`, and `__execute` blocks, dispatched by `__decode` trees (`DecoderCase_Case` in `asl.ott:310-325`) generated from `encodingindex.xml`.
2. **ASLv0 Dependent Bitvectors and Unsound Integer Division Normalization (`rems-project/asl-interpreter` at `8cfc0b27002d282da55568e3462868e9dfd8c3bd`):**
   - In `libASL/asl.ott:82-119` and `libASL/tcheck.ml` (blob `fab728a7e8a1ceeb17a4a73a5b2648367a4d10bb`, `lines 811-955`), bitvector types `Type_Bits(expr)` carry arbitrary AST expressions unified syntactically at call sites (`instantiate_Rule`) to synthesize explicit type arguments `tes : expr list`.
   - Before invoking Z3 (`check_constraints`, `tcheck.ml:761-790`), `simplify_ValidationExpr` (`tcheck.ml:715-755`) unconditionally rewrites `(a DIV b) * b` to `a` (`lines 725-727, 743-754`, with the comment `Warning: the following rule is unsound for arbitrary integers, (e.g., (x DIV 8) * 8 == x is only true when x is a multiple of 8)`). In Lean 4, `BitVec ((datasize / 8) * 8)` is not definitionally equal to `BitVec datasize`, creating explicit divisibility proof obligations at byte/lane boundaries.
3. **The `Formal_InOut` By-Value Setter Bug in `asl-interpreter` vs. ASLv1 `desugar_setter` (`herdtools7/asllib`):**
   - In `asl-interpreter/prelude.asl:68-77`, `Elem[bits(N) &vector, integer e, integer size] = bits(size) value` declares `&vector` as `Formal_InOut`. When `A[i]` appears inside a nested slice (`X[n][31:0] = v`), `tc_slice_lexpr` (`tcheck.ml:1540-1565`) emits `LExpr_Slices(LExpr_ReadWrite(getter, setter, tes, args), slices)`, which `eval.ml:603-631` evaluates via getter read + slice modify + setter call. However, when `Elem[V[n], e, 64] = v` is a top-level assignment LHS, `tc_lexpr2` (`tcheck.ml:1653-1676`) emits `LExpr_Write(setter, tes, args)`, and `eval.ml:595-601, 972-981` evaluates all `args` by value into `vargs`, binds `Formal_InOut` to a local variable in the callee's local scope `lenv`, and discards `lenv` on return—silently losing the write to `V[n]`!
   - ASLv1 (`herd/herdtools7/asllib` at `6bea2e8131feaeb497a7bf86d52d94cdd8721a6c`) eliminates `&` setter parameters in favor of `accessor_pair` blocks (`asllib/desugar.ml:212-248`), desugars partial setter writes via `desugar_setter` (`asllib/desugar.ml:126-162`) into a 3-statement read-modify-write sequence with `__setter_v1_temporary`, classifies integer constraints statically via `constraint_kind` (`asllib/AST.mli:255-273`, `Typing.ml:568-573`), and enforces loop/recursion fuel limits (`asllib/Interpreter.ml:261-275, 1171-1212`).

#### 1.2 `asl_to_sail` Translation Passes vs. L3's Closed Functional Pipeline

1. **Five Core Passes in `rems-project/asl_to_sail` (`78242b8d60a507fab18d9b4f225bfc7bd33e62b3`):**
   - `Formal_InOut` elimination (`lib/translate_asl.ml:1762-1784, 3082-3117`): converts `Formal_InOut` setter parameters into tuple return values (`LE_tuple(lexps) = setter(in_args, rhs)`).
   - Slice RMW expansion (`lib/translate_asl.ml:2038-2065`): rewrites `LExpr_Slices(LExpr_ReadWrite ...)` using `SetSlice` / `vector_update_subrange`.
   - SVE/SME `VL`/`PL` hoisting (`lib/translate_asl.ml:257-342, 2900-2910`, `prelude.sail:319-325`): hoists `CurrentVL.read()` to `let 'VL = GetCurrentVL()` (`'vl in {128, 256, 512, 1024, 2048}`) or case-splits via `-mono_vl`.
   - 3-pass fixed-point decode constraint inference (`lib/translate_asl.ml:482-513, 1038-1194, 3149-3179`): infers `IC_Set` / `IC_Range` bounds (`{'n, 'n in {8, 16, 32, 64}. int('n)}`).
   - 50-iteration Z3 feedback loop & manual patches (`bin/main.ml:731-829`, `lib/sail_to_sail.ml:844-925`): `iterate_check` intercepts `Err_unresolved_quants` and `Err_failed_constraint` to inject constraints/assertions, followed by manual `-patch` `.sail` and `.val.sail` overrides.
2. **L3's Closed Non-Dependent Pipeline (`coruus/L3` at `d6558e679a25ffaaf16a47a3189f8f8111e45e0c`):**
   - Finite bitwidth polymorphism (`L3/Base.sml:263-429`): `Type.bty` restricts bitvectors to concrete `BV(n)` or finite-set `BVV("N")` (`with N in 8, 16, 32, 64` in `isa-models/arm-v8/v8-base.spec:104, 240`), monomorphized by `Expand.expandDefns` (`L3/Export.sml:435-610`).
   - Bit-string pattern compilation (`L3/Base.sml:3198-3278`, `L3/Matches.sml:435-483`, `L3/Export.sml:1213-1323`): `Term.checkMatch` verifies exhaustiveness/irredundancy, `Matches.boolifyMatches` explodes $N$-bit scrutinees into $N$-tuples of booleans, and `Convert.boolMatchConv` synthesizes balanced `if-then-else` decision trees (`bestSplit`).
   - Exception field & state-monad beta-reduction (`L3/Export.sml:36-74, 682-1121`, `L3/HolExport.sml:505-676`): `Exception.buildExceptionDatatype` folds exceptions into `state.exception`, `Monadify.monadifyDefn` introduces `m'const`/`m'bind`/`m'read`/`m'write`/`m'extend`, and `Monadify.deMonadifyDefn` beta-reduces all monadic combinators away into pure `state -> val * state` functions.

### 4. End-to-End Assembly/ISA Proof Boundaries (2013–2026) and TCB, Concurrency, Constant-Time, and Platform Frontiers

#### 4.1 The Seven-Stage Post-Compiler Artifact Chain (`CompCert 3.18`, `seL4` PLDI 2013, `CakeML/Silver` PLDI 2019)

A compiler or machine-code correctness theorem must identify which of the seven physical/semantic stages it actually reaches (`boundary-matrix.json`, `source-map.json`):
1. **Assembly AST (`CompCert 3.18`, `AbsInt/CompCert` at `74cbdbf0e86ecbfa39a5ca8f248f77fb2f974cb6`, `driver/Compiler.v`):** Proves whole-program semantic preservation down to target assembly ASTs (`Asm.program`), but explicitly leaves printing assembly text, assembling, and linking outside its formal proof (`Source proof → verified compiler → formal assembly semantics → unverified assembler/linker → executable → assumed ISA-conforming CPU`).
2. **Printed Assembly Text** & **3. Object File** & **4. Linked Executable Image (`seL4` Binary Translation Validation, Sewell et al., PLDI 2013):** Validates compilation (including optimizations) and linking for a concrete C-compiled kernel binary by proving refinement from verified C to binary ISA semantics, while explicitly omitting hand-written assembly routines and volatile hardware-control accesses (`Source proof → concrete binary validation → formal ISA execution → assembly/device routines excluded`).
5. **Loaded Memory Image** & **6. ISA-Level Execution** & **7. Concrete Hardware Execution (`CakeML` + `Silver`, Lööw et al., PLDI 2019, DOI `10.1145/3314221.3314622`):** Aligns CakeML's compiler backend semantics with the verified Silver processor's ISA interface to obtain an end-to-end hardware execution theorem, scoped specifically to the verified Silver core (`Source proof → verified compiler → formal machine semantics → verified Silver processor → hardware-level theorem`).

| Missing Obligation | Candidate Mechanism | Required Additional Bridge for Anneal |
|---|---|---|
| **AST to decoded bytes** | `x86isa` decode path; HOL/`L3`/`HolBA` lifting (`BST_AssertionViolated` exclusion guard); `s2n-bignum` object byte import | Exact byte/entry/layout relation and initial-state domain |
| **Instruction disagreement** | `K x86-64` / `LNSym` hardware co-simulation | Finite test corpus cannot replace universal ISA refinement |

#### 4.2 TCB Taxonomy, Concurrency (`weak_memory_probe.py`), Constant-Time, and Platform Frontiers (`EnvironmentContracts.lean`)

1. **Five Internal Trust Classes:**
   - (a) **Proof admission** (kernel implementation, theorem axioms, `ofReduceBool` reflection vs `sorryAx`); (b) **Semantic definition** (ISA operations, UB, byte/permission/provenance rules); (c) **Import and binding** (parser, AST, decoder, layout, ELF symbol/byte identity); (d) **Language boundary** (Rust type/resource interpretation, `FnAbi`, callbacks); and (e) **Physical/environment** (hardware configuration, loader, OS, devices).
2. **Atomic Compatibility & Finite Store-Buffering Probe ([`support/weak_memory_probe.py`](support/weak_memory_probe.py)):**
   - Rust 1.99.0 (`rust-lang/rust` at `b940084d7eb6a299eb4bfeb8e34901bc051e7ac4`, `library/core/src/sync/atomic.rs`; `rust-lang/reference` at `2dafab96d919d6ab2884488e970bf95610ff83eb`, `src/inline-assembly.md`) defines access-based atomic ordering rules distinct from raw hardware instructions or compiler barriers.

3. **Constant-Time Noninterference vs. Functional Equality:**
   - Checked Lean 4.34.1 witnesses (`fixed_trace_noninterference` and `same_result_can_leak`) and `awslabs/s2n-bignum` (`4d1356a7470663c752660a59375dc3a9ef548428`, `SOUNDNESS.md`) separate functional equivalence from constant-time control/memory-address trace equivalence and hardware-specific `Intel DOIT` data-operand-independent timing assumptions.

## Boundaries

1. **L3 Armv8 Coverage vs. MRA/ASL Coverage:** Upstream `coruus/L3/isa-models/arm-v8/` stubs out FP/SIMD instructions as `NoOperation` (`v8-iset.spec:2329-2365`); full Armv9-A / SVE / SME coverage requires Arm's MRA XML / ASLv1 specifications.
2. **`leanprover/LNSym` (`5c05220`) Scope and Unfinished Proof Files:** `LNSym` models sequential `EL0` AArch64 execution without MMU/page tables, atomics (`LDXR`/`STXR`, `CAS`), barriers, or `BR Xn`/`BLR Xn`/`TBZ`/`TBNZ`/`SDIV`/`UDIV`/`LDR` (register offset or literal), and `Tactics/PruneUpdatesLogic.lean:624-625` contains 2 `sorry`s (not used by `#genStepEqTheorems` or `sym_n`).
3. **Unverified OCaml/Rust Toolchain in Standard `Islaris` & `CN2Islaris`:** Standard AArch64 Islaris proofs trust `isla-sail/jib_ir.ml`, `isla/src/footprint.rs`, and `islaris/frontend/decomp.ml` event stripping; `CN2Islaris` (`cerberus/backend/cn/dwarfData.ml:49-71`) diverges on recursive call graphs and supports only initialized 8-byte scalars and 1D arrays.
4. **Toolchain Suffix, Concurrency, and Side-Channel Boundaries:** `CompCert 3.18` leaves assembly printing, assembling, and linking unverified; `seL4` PLDI 2013 binary validation omits assembly routines and volatile hardware accesses; `CakeML/Silver` PLDI 2019 is scoped to the Silver processor; and the finite store-buffering (`support/weak_memory_probe.py`), MMIO quantifier (`support/response_contract.py`), and `nonmem_load` (`support/EnvironmentContracts.lean`) artifacts are discriminating model probes rather than full hardware or Rust concurrency/device proofs.
