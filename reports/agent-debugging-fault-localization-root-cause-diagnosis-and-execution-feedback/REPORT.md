# Agent Debugging, Fault Localization, Root-Cause Diagnosis, Automated Bisection, and Execution-Feedback Repair

## Summary

Primary-source inspection of 26 peer-reviewed papers and preprints (2023–2026), nine pinned public repositories (`microsoft/debug-gym`, `plasma-umass/ChatDBG`, `AutoCodeRoverSG/auto-code-rover`, `FloridSleeves/LLMDebugger`, `coinse/autofl`, `fishmingyu/OrcaLoca`, `ozyyshr/RepoGraph`, `acorn421/san2patch`, and `coinse/fonte`), and a deterministic four-probe verification suite establishes five operational invariants governing runtime debugging, fault localization (`FL`), commit bisection, and patch verification in software engineering agents:

1. **Real Execution State Beats Simulated Mental Traces, With a Basic-Block Granularity Optimum (`Self-Debugging`, `LDB`, `ChatDBG`, `ROBIN`):** Prompting an LLM to mentally dry-run code alongside unit-test results (`Self-Debugging` `UT+Trace`, `2304.05128v2` Table 2) degrades `TransCoder` repair relative to `UT` alone on `3/4` models (`Codex` `-3.7 pp`, `StarCoder` `-2.8 pp`, `GPT-3.5` `-0.4 pp`; `GPT-4` `+0.7 pp`, trailing `UT+Expl` on `4/4` models) while offering small positive lift on `MBPP` (`3/4` models). Replacing mental traces with real Python control-flow-graph (`CFG`) basic-block entry/exit snapshots (`LDB`, `2402.16906v6` Table 1 & Tables 5–6) lifts `HumanEval` (`GPT-3.5` `73.8% → 82.9%`, `CodeLlama-34B` `49.4% → 55.5%`, scaling to `84.1%` at `T = 20` in `Figure 7`) and `TransCoder` (`CodeLlama-34B` `69.8% → 79.6%`, `StarCoder-15B` `61.8% → 69.8%`) while outperforming both finer line-level (`CodeLlama` `53.7%` at `72K` tok vs. block `55.5%` at `52K` tok) and coarser function-level (`53.7%`, `54K` tok) granularity. Pinned source inspection (`FloridSleeves/LLMDebugger@49ac191f`) reveals that `LDB` uses deterministic head+tail slicing—not uniform/selective sampling—and exposes an upstream threshold discrepancy (`App. E` states `25 + 25 = 50` lines vs. `py_generate.py:L208–221` `[:15] + [-15:] = 30` lines + `model.py:L117` `3,097`-token cap), causing fixed-window traces to miss mid-loop corruptions at $N \ge 50$ (`Probe 3A`). On unmanaged C/C++ memory crashes (`ChatDBG`, `2403.16354v5` Table 5), interactive post-mortem inspection yields **`55%` proximate crash-symptom mitigations** (`strncpy`/`snprintf` truncation, replacing `assert` with an in-callee `if` guard on `YAML2`) vs. **`36%` true root-cause fixes**.
2. **Interactive Debuggers Lose as Shell Substitutes (`Pdb or Not to Be`) and Win Only via Context-Isolated Subagent Encapsulation at Higher Total Token Spend (`Debug2Fix`, `VulDebugger`):** Replacing a general shell (`run_bash`) with stateful `pdb` + per-relay edit gating (`2611.08666v1` Table 1) cuts SWE-bench Verified `pass@1` by `-7.1 pp` (`56.7% → 49.6%`, `Nemotron-3-Ultra`) and `-16.4 pp` (`56.7% → 40.3%`, `GPT-OSS-120B`, roughly doubling token cost per solved problem). Under Magnuson, Kitanidis, and Lee's unbiased multi-seed cross-agent estimator $\widehat{\text{pass}}_X@k$ (`Eq. (3)`, `Eq. (5)`), two `bash` runs (`pass@2(bash, bash) = 62.7% / 64.7%`) strictly dominate `bash + pdb` (`60.3% / 60.0%`), proving single-seed `20–24` "exclusive" `pdb` solves arise from Bernoulli variance (`Probe 3B`: `17.8/500` illusory solves even when $p_{\text{pdb}}(j) < p_{\text{bash}}(j)\;\forall j$). Earlier `debug-gym` gains (`+11.2` to `+19.5 pp`, `2503.21557`) stem from a shell-less, `grep`-less `10`-rewrite baseline with pre-committed `test_patch` (`swe_bench_debug.py:L9–16`). Exposing raw debugger tools alongside `bash` (`Debug2Fix` `Debug Tools Only`, `2602.18571v2`) suffers `9%` voluntary invocation and a `-11.2 pp` drop on `Claude Sonnet 4.5` (`75.7% → 64.5%`). Isolating `JDB`/`PDB` inside an edit-free `Debug Subagent` (`≤25` steps/call) + pre-edit gate lifts `GitBug-Java` `pass@1` by `+9.8` to `+12.9 pp` (`Sonnet 4.5` `75.7% → 85.5%`) and `VulDebugger` C CVE `pass@3` from `28.0%` (`4` SE + `10` P) to `60.0%` (`19` SE + `11` P)—**specifically by preserving $O(1)$ main-agent context (`Probe 3A`: `1,320` tok across $N \in \{1..250\}$), while increasing total end-to-end token spend `1.13×–2.87×`** (`Debug2Fix` Table 1, single-seed `n = 1`; `Pdb or Not to Be` Table 2's 1-seed `oracle` subagent pilot did not beat `bash` on Python SWE-bench Verified).
3. **Standalone Fault Localization Lifts Open-Loop Pipelines ($r_0 = 0$) Yet Anchors and Degrades Clue-Rich Autonomous Agents (`Shi, Yang, & Chen 2026`, `Probe 1`):** Classical Spectrum-Based Fault Localization (`SBFL`: `Ochiai`, `DStar`, `Tarantula`, `Op2`, `Barinel`) assigns zero score spread across non-branching call chains $f_1 \to \dots \to f_m$ (`Fonte` `rank_max = m`) and suffers `8.23×` `Ochiai` dilution from unrelated Python module imports (`Probe 1A`). In procedural open-loop repair (`Agentless-1.5` + `OrcaLoca`, `2502.00350`), unretrieved functions have baseline solve rate $r_0 = 0\%$ ($\Delta_- = 0 \implies r^* = 0.0\%$), so `+20` newly matched functions yield `+6.33 pp` (`+3.94 pp` at fixed `59.09%` baseline conversion + `+2.39 pp` precision lift, `Probe 1B`). Conversely, across `16,248` autonomous `mini-swe-agent` trajectories (`2610.25826v1` Tables 2–4), prepending 6 standalone FL tools lowers `pass@1` in **`17/18` settings** (`0/18` significant after 18-way Holm adjustment) and inflates total tokens in `13/18` (up to `+129.8%`): without FL, the agent already reaches gold files on `88.6%–99.4%` of tasks, so `RR = 1` Top-1 hits gain only `+0.85 pp` (`GPT-5.6 Luna + OrcaLoca`) whereas non-Top-1 cases (`RR < 1`: `-9.40 pp` pooled across `0 < RR < 1` `8.6%`, `-2.33 pp` and `RR = 0` `21.2%`, `-12.26 pp`) anchor initial exploration (`97.5%` on completely wrong files), requiring **$r^*_{\text{pooled}} = 91.66\%$** (`93.48%` when $p_{0<\text{RR}<1} = 0$) Top-1 accuracy to break even (`Probe 1B`). Oracle `Gold symbol + bug cause` lifts clue-stripped `LR-issues` `+13.0 pp` (`-47.9%` tokens, `186.9K → 97.4K`) and Multimodal `+8.8 pp`, **except** on distributed `SWE-bench Pro` (`3.85` files/patch) where `Gold symbol` (`53.8%`) beats `Bug cause` (`52.9%`).
4. **Hard-Cut `git bisect` Collapses Exponentially Under Flaky Tests, Whereas Laplace-Smoothed `Fonte` Bayesian Bisection Concentrates Budget (`Fonte`, `Time Travel`, `Probe 2`):** Standard `git bisect` requires $d = \log_2 N$ consecutive error-free pivots, collapsing to $(1 - \bar{\epsilon})^7 = 39.27\%$ uniform (`40.08%` newest-weighted DGP) at flake rates $(\epsilon_0, \epsilon_1) = (0.10, 0.15)$ over $N = 128$ commits. Under a strictly matched `B = 21` test-execution budget across shared $b^*$ draws (`Probe 2A`), Burnashev–Zigangirov Bayesian posterior-median bisection (`90.33%` uniform prior; **`97.50%`** under a rank-perturbed, miscalibrated `Fonte` prior; `99.17%` exact-DGP `Fonte` ceiling) beats `3×` restarted (`57.17%`) and `3`-repeat majority-vote (`73.33%`) `git bisect`. In noiseless mode (`NC-2A`), `Fonte` Algorithm 1 (`2502.12922v2`, `11.0%` candidate retention) averages **`3.74` exact steps** across its full prior (`3` steps top-1, `5` steps tail vs. `4.00` unweighted on $C_{\text{BIC}}$ and `7.00` full history, explaining `Fig. 8`'s `8.3%` within-$C_{\text{BIC}}$ tail regressions), while a soft Laplace floor ($\gamma = 0.05$) rescues off-support configuration/build BICs from `0.0%` to `98.8%` (`NC-2B`).
5. **Narrow Reproducer Tests Certify Plausible Symptom Masks, Requiring Full-Repo Suites and Zero-Oracle Metamorphic/AST Gates (`PatchDiff`, `San2Patch`, `SpecRover`, `Probe 4`):** Across benchmarks, `34.6%` (`ACR`) and `39.8%` (`SpecRover`) of SWE-bench Lite passing patches, `7.8%` of SWE-bench Verified passing patches on unmodified repo test suites and `29.6%` under oracle-guided `PatchDiff` (`2503.15223v2`: `11.0%` estimated certainly incorrect; `66.2%` of suspicious patches uncertain due to under-specified issues), and `8.8%–26.1%` of `San2Patch` (`71.4%` static `ACR`) security patches overfit proximate crash symptoms. Because `PatchDiff` requires the human reference patch $P_o$, autonomous repair loops must enforce **zero-$P_o$ gates** (`Probe 4`): full untouched repository regression suites (`django-13279`), `inspect.getsource` AST guard-monotonicity checks blocking bare flag gates around safety `raise`/`assert` statements (`sympy-22714`, `ChatDBG` `chatdbg_pdb.py:L199–205`), parameterized length/injectivity postconditions (`San2Patch` `CVE-2017-6965`, `ChatDBG` `strncpy`), and dual-skeptic test+patch review (`SpecRover` `agent_reviewer.py:L17–24`).

## Findings

### 1. Runtime-State Grounding, Debugger Granularity, and the SWE Debugger Paradox

`Basis: source + execution + derived + documentation`

#### 1.1 Simulated Mental Traces vs. Real CFG Basic-Block Snapshots (`Self-Debugging`, `LDB`, `ChatDBG`, `ROBIN`)

1. **`Self-Debugging` (`Chen, Lin, Schärli, & Zhou`, ICLR 2024, `arXiv:2304.05128v2`, `[published measurement]`):**
   - Without unit tests (`Spider` SQL dev, `Table 1`), rubber-duck natural-language explanation (`+Expl`) lifts `Codex` (`code-davinci-002`) by **`+2.8 pp` (`81.3% → 84.1%`; `+9.0 pp` `63.9% → 72.9%` on extra-hard queries)** and `GPT-3.5`/`GPT-4`/`StarCoder` by `+1.1 / +0.4 / +0.2 pp`.
   - With real unit-test execution (`UT`, `Table 2`), `+Trace` prompts the LLM to *mentally simulate* execution without interpreter instrumentation (`§3`). On **`TransCoder`** ($N = 560$), `UT+Trace` **degrades accuracy below bare `UT` on `3/4` models** (`Codex` `91.6% → 87.9%`, `-3.7 pp`; `StarCoder` `76.4% → 73.6%`, `-2.8 pp`; `GPT-3.5` `92.7% → 92.3%`; `GPT-4` edges up `88.8% → 89.5%`, while `UT+Expl` beats `UT+Trace` on all `4/4` models: `92.5%`, `76.4%`, `93.9%`, `90.4%`). Conversely, on simpler single-function **`MBPP`** ($N = 500$, `Table 2c`), `UT+Trace` **improves over `UT` on `3/4` models** (`Codex` `69.4% → 70.8%`, `GPT-3.5` `72.2% → 72.8%`, `StarCoder` `52.2% → 53.2%`; `GPT-4` `80.6% → 80.2%`). Forward mental tracing fails specifically when complex control flow causes the model to hallucinate intended rather than executed branch transitions.
2. **`LDB` (`Zhong, Wang, & Shang`, Findings of ACL 2024, `arXiv:2402.16906v6`; `FloridSleeves/LLMDebugger@49ac191f`):**
   - *Pinned source architecture:* `divide(prog)` (`programming/tracing/tracer.py:L19–28`) builds basic blocks via `staticfg.CFGBuilder`; `get_trace()` (`L57–96`) executes `python3 -m trace -t` (`timeout=5`, `L65`); `parse_runtime_value_simple_block()` (`L138–176`) pairs entry/exit states $(V_{i-1}, B_i, V_i)$ and truncates serialized state strings $\ge 100$ chars to `values[:50] + "..." + values[-50:]` (`L152`, `0.09 s` profiling overhead).
   - *Deterministic head+tail slicing & paper-vs.-repo discrepancy (`source`):* Contrary to summaries describing `LDB` as uniform/selective sampling, `LDB` performs **deterministic head+tail slicing**: `[:5] + [-5:]` for basic blocks ($N_b = 10$). Moreover, whereas `2402.16906v6 Appendix E` (`L888–916`) states that line-level and function-level modes retain the **first `25` + last `25` lines ($N_b = 50$)**, pinned `programming/generators/py_generate.py:L208–221` (and `L292–304`) sets **`max_num_blocks = 30` (`[:15] + [-15:]`)** for `level == "line"` and truncates `level == "function"` at `30` lines (`[:15] + ["..."] + [-15:]`), while `model.py:L117` enforces `change_messages(..., 3097)`.
   - *Camera-ready `v6` measurements (`Table 1`, `Appendix E Tables 5–6`, `Appendix G Figure 7`):* Across 10 iterations, `LDB` beats `SD+Expl` and `SD+Trace` on **HumanEval** (`GPT-3.5` `73.8% → 82.9%` vs. `SD+Trace` `80.5%`; `CodeLlama-34B` `49.4% → 55.5%` vs. `54.3%`; `StarCoder-15B` `39.0% → 39.6%`; `Reflexion + GPT-4o` `91.5% → 98.2%`; continuing to **`84.1%` at `T = 20` in `Figure 7`**) and **TransCoder** (`GPT-3.5` `82.3% → 87.7%`; `CodeLlama-34B` `69.8% → 79.6%` vs. `SD+Trace` `76.4%`; `StarCoder-15B` `61.8% → 69.8%`). Basic-block granularity is strictly Pareto-optimal over line and function granularity (`GPT-3.5`: Block **`82.9%`** / `23K` tok / `6.2` turns vs. Line `80.5%` / `24K` / `6.4t` vs. Function `79.9%` / `27K` / `8.1t`; `CodeLlama-34B`: Block **`55.5%`** / `52K` tok / `7.8t` vs. Line `53.7%` / **`72K` tok (`1.38×`)** / `9.1t` vs. Function `53.7%` / `54K` / `9.3t`).
3. **Post-Mortem & Human-in-the-Loop Triage (`ChatDBG` `2403.16354v5` & `plasma-umass/ChatDBG@8ca3cd61`; `ROBIN` `2402.06229v1`):**
   - `ChatDBG` enriches up to `max_initial_locations_to_send = 3` frames with `[-10, +9]` source windows and stack-overflow hints at `total_frames > 1000` (`stacks.py:L65–105`), hides library frames and caps Python stacks at `30` (`chatdbg_pdb.py:L181–197`), injects `"The code \`assert ...\` is correct and MUST remain unchanged in your fix."` (`L199–205`), sandboxes `p` expressions (`sandbox_eval`, `L286–300`), and runs `ipyflow` dynamic backward slicing in notebooks (`do_slice`, `L383–436`). On 22 Python scripts/notebooks, autonomous steering + follow-up reaches `85%` (`~10K` tok, `$0.12`/query), **but on 8 unmanaged C/C++ memory bugs (`Table 5`), `55%` of runs emit proximate symptom masks** (`strncpy`/`snprintf` silent truncation on `BC`/`POLY`, ignoring null pointers on `PEG`, or replacing `assert` with an in-callee `if` guard on `YAML2`) vs. **`36%` root-cause fixes**.
   - `ROBIN` (`Bajpai, Chopra, et al.`, IEEE VL/HCC 2024; $N = 12$ C# developers, **`60`-minute** Visual Studio sessions) uses a Hardness Classifier and conversation-analytic insert-expansions to elicit breakpoint/variable checks before suggesting edits, lifting localization `5/12 → 11/12` and multi-method resolution **`2/12 → 11/12`** ($\chi^2 = 13.594, p < 0.05$).

- **`unknown` — Multi-Seed, Compute-Matched Net Subagent Debugger Lift on Uncontaminated Repos:** `Debug2Fix` (`2602.18571v2`) is single-seed (`n = 1`), closed-source, and spends `1.13×–2.87×` total tokens on `GitBug-Java` (`+0.8 pp` un-gated on `Sonnet 4.5` `SWE-Bench-Live`), while `Pdb or Not to Be` (`2611.08666v1` Table 2) tested only a 1-seed preliminary `oracle` subagent on Python SWE-bench Verified (`< bash`); multi-seed (`n ≥ 3`) equal-dollar performance remains unestablished.
