# Anneal Acceptance Frontier, ISA Integration Roadmap, MiniRust Synthesis, and Verifier Bibliography

## Summary

This report synthesizes the acceptance-frontier design, source-safety reflection theorems, consumer-owned receipt and producer-containment protocols, instruction-set architecture (ISA) integration roadmap, MiniRust and assembly semantic coverage, and primary verifier bibliography across the Anneal research corpus:

1. **Acceptance obligations, replaceable trusted frontier, and source-safety reflection (`Accept(Q, c)`):** Anneal's mandatory undefined-behavior-freedom and explicit trust principles require separating untrusted proof search and certificate generation from consumer-owned acceptance checking. A small logical kernel removes tactic search from internal authority, but an end-to-end acceptance gate `Accept(Q, c)` must independently establish five conjuncts over a consumer-fixed query `Q` and producer artifact `c`: logical validity (`Checked(c)`), subject and statement binding (`Bound(Q, c)`), permitted assumption closure (`Assumptions(c) ⊆ Permitted(Q)`), entry and call-graph coverage (`Covered(Q, c)`), and source-safety transfer (`Transfer(Q, c)`). Kernel-checked Lean 4.34.1 theorems (`support/source-safety-reflection-probes/Reflection.lean`) and an AArch64 `rustc 1.99.0` optimization probe (`support/source-safety-reflection-probes/erased_ub.rs`) prove that standard defined-execution preservation (`DefinedPreservation`) fails to transfer safety from target model to source (`ordinary_preservation_does_not_reflect_safety`), because an optimizer can legally erase a reachable `std::hint::unreachable_unchecked` branch at `-O3`. Sound safety transfer requires **source-failure exposure** (`FailureReflection(source, model) ∧ Safe(model) ⇒ Safe(source)`, proved in `failure_reflection_transfers_safety` and `failure_reflection_composes`) and full safe-caller domain coverage (`narrowed_domain_is_safe`). Against the promoted-MIR admission prototype, all 18 mutation controls (`support/acceptance-frontier-and-trust-reduction/run_admission_controls.py`, `support/acceptance-frontier-and-trust-reduction/admission-results.json`) pass.
2. **Consumer-owned statements, reusable receipts, and native producer containment:** A producer process or cached receipt must never be allowed to define or mutate the consumer's expected proposition. Statement comparison (`leanprover/comparator`) must check declaration headers, transitive definitions, universes, typeclass instances, and local hypotheses against an independently constructed challenge, while fresh replay of data-only certificates excludes producer build scripts, tactics, and native plugins from the checking boundary. On macOS `arm64` (`Darwin 27`), a native `/usr/bin/sandbox-exec` containment control (`support/data-receipts-caches-and-producer-isolation/sandbox_probe.py`, `support/data-receipts-caches-and-producer-isolation/sandbox-results.json`) verified that a restricted producer process can write its designated output file while any attempt to overwrite the consumer's protected challenge file raises `PermissionError` (`errno 1`), leaving the challenge digest intact.
3. **Split Contract-and-Trace Bridge Architecture for ISA and `core::arch::asm!` integration:** Full ISA decoders (`leanprover/LNSym` at ~35,000 LOC or `rems-project/sail` + `lean-sail` at 15,000–150,000 LOC) cannot be imported into Anneal's 561-line human-auditable trusted kernel (`trusted/lean/Trusted/` in `joshlf/anneal` at `c065b55a3a143ec3f6a4f9c8166bd9e6a4c4633b`). The standalone 2,289-line Lean 4.34.1 mechanization in `support/isa-integration-architecture-and-roadmap/AnnealIsaBridgeSynthesis.lean` (zero `sorryAx`, zero custom axioms) resolves this tension via a **Split Contract-and-Trace Bridge**:
   - *Minimal `@[candidate inline_asm]` Trusted Boundary (~140 LOC in `trusted/`):* Adds `PhysReg` (`.x0`..`.x3`, `.sp`, `.nzcv`), `RegClass` (`.fixed r`, `.gpr`), `AsmOperand` (`.inReg`, `.outReg`, `.inoutReg`), `InlineAsmOptions`, `AsmAccessEvent` (`.readNA`, `.writeNA`, `.atomicLoad`, `.stackTouch`), `AsmContract`, `Terminator.inlineAsm`, and `evalInlineAsm`, which demonically quantifies (`StepResult.choice .demonic`) over all pairwise-distinct general-purpose register allocations (`validRegAllocs`) and background register seeds (`initRegSeeds`), checks `[asm.register-preservation]`, and replays `AsmAccessEvent` traces against Anneal's timestamped `MemState`.
   - *Untrusted ISA Backends in `theory/Anneal/Isa/` (0 Trusted LOC):* Proves refinement into `evalAsmKernel` from three external ISA paradigms: (a) `AeneasVerif/kraken` structured assembly ASTs paired with `StrictObserve` (`kraken_strict_observe_eq_kernel1`), after proving Kraken's permissive `MemModel.All` unsound for unaligned or out-of-footprint accesses (`kraken_all_unsound_on_unaligned_or_oob`); (b) `leanprover/LNSym` + `cslib-community/bignum` byte-decoded `BitVec 32` AArch64 machine words (`[0xf9400002#32, 0x8b010042#32, 0xf9000002#32]`), orthogonal `Component` lenses (`regComponent_orthogonal`), and secret-independent `UArchEvent` constant-time leakage traces (`bignum_lnsym_words_eq_kernel1`); and (c) `rems-project/sail` + `lean-sail` + `archsem-lean` Tier-1 `FreeM SailEffect` monadic execution proved equivalent to an `opencompl/riscv-lean`-style Tier-2 pure `BitVec 64` summary (`sail_tier1_equiv_tier2_summary`).
   - *End-to-End Mixed Rust MIR + `asm!` Verification & Negative Canaries:* Discharges `verify_crate_with_inline_asm` and axiom-free `non_vacuity_at_every_depth` for a 4-block Rust function `checked_mmio_accum` across all 48 demonic `(alloc, seed)` branches, and proves 5 negative adequacy canaries (`canary_undeclared_clobber_ub`, `canary_readonly_write_ub`, `canary_nomem_read_ub`, `canary_unaligned_access_ub`, `canary_demonic_reg_aliasing_ub`).
4. **Research agendas, MiniRust/assembly synthesis, verifier adoption comparison, and primary bibliography:** Across the 136-item earlier recommendation audit (`support/recommendation-coverage-audit/recommendation-matrix.md`), the 364-question formal-methods / TCB / proof-producing-compilation research agenda (`support/research-agenda/research-questions.json`, `support/research-coverage-and-acceptance-synthesis/question-crosswalk.json`), the 52-bundle MiniRust and assembly agenda (`support/minirust-assembly-research-agenda/questions.json`, `support/minirust-assembly-coverage-and-adoption/coverage-matrix.json`), the 49 follow-on execution and proof milestones (`support/execution-milestones-and-acceptance/milestones.json`), and the 81+3 primary bibliography and licensing audit (`support/adoption-and-primary-bibliography/bibliography.json`, `support/adoption-and-primary-bibliography/source-identities.json`), the corpus establishes a staged, reversible adoption plan with explicit kernel-version (Lean `v4.31.0`/`v4.30.0-rc2` nested-inductive parameter validation defect fixed in `v4.32.2`/`v4.34.1`), representation-coherence (MiniRust enum variant stability and wide-pointer union chunk truncation), and distribution-licensing boundaries.

## Findings

### 1. Acceptance Frontier, Source-Safety Reflection, and Consumer-Owned Receipts

#### 1.1 Five-Gate Acceptance Factorization and Replaceable Trusted Frontier
For a consumer-owned verification request `Q` (specifying source/configuration identity, target ABI, permitted caller domain, mandatory finite-prefix safety, user postcondition, and permitted assumptions) and an untrusted producer certificate `c`, acceptance requires:
```text
Accept(Q, c) ==>
  Checked(c)                          -- logical validity of proof/certificate in the kernel
  Bound(Q, c)                         -- exact match on source, definitions, target, and claim
  Assumptions(c) <= Permitted(Q)      -- transitive axiom/import closure obeys policy
  Covered(Q, c)                       -- all reachable callees, drops/unwinds, and caller inputs covered
  Transfer(Q, c)                      -- modeled safety/postcondition entails source safety/postcondition
```
Each initially trusted pipeline component (compilation-input selector, parser/MIR importer, ULLBC-to-LLBC pass transformations, memory/library models, obligation generator, tactic/SMT search, and verdict aggregator) can leave the internal trusted computing base **only** when replaced by a kernel-checked theorem or per-run certificate that discharges the old unchecked premise without introducing an equally powerful unverified wrapper (`support/research-agenda/anneal-obligations.json`). Against the promoted-MIR admission implementation, all 18 mutation controls (`support/acceptance-frontier-and-trust-reduction/run_admission_controls.py`, `support/acceptance-frontier-and-trust-reduction/admission-results.json`, `support/acceptance-frontier-and-trust-reduction/admission.stdout.txt`, `support/acceptance-frontier-and-trust-reduction/admission.stderr.txt`)—testing unregistered functions, uninspected transitive callees, generic/supertrait dispatch, unsupported instantiations, elided drop/unwind effects, raw storage, weakened signature guards, compiler flag overrides, and missing pre-pass ULLBC snapshots—pass.

#### 1.2 Kernel-Checked Source-Safety Reflection vs. Compiler UB Erasure
In `support/source-safety-reflection-probes/Reflection.lean` (checked under Lean `v4.34.1`, `support/source-safety-reflection-probes/lean-check.stdout.txt`, `support/source-safety-reflection-probes/results.json`):
- **Counterexample to ordinary forward preservation (`ordinary_preservation_does_not_reflect_safety`):** `DefinedPreservation source model` requires outcome equality only when `source input ≠ .ub`. For `brokenSource` (which triggers `.ub` on `false` and returns `7` on `true`) and `constantModel` (which always returns `7`), `DefinedPreservation brokenSource constantModel` and `Safe constantModel` both hold, yet `¬ Safe brokenSource`. In `support/source-safety-reflection-probes/erased_ub.rs`, `rustc 1.99.0` (`b940084d7eb6a299eb4bfeb8e34901bc051e7ac4`) preserves the `input == 0` branch to `std::hint::unreachable_unchecked()` in `-O0` LLVM IR (`support/source-safety-reflection-probes/erased-ub-o0.ll`) but completely erases the branch at `-O3` (`support/source-safety-reflection-probes/erased-ub-o3.ll`), emitting identical AArch64 `mov w0, #7; ret` bodies for `broken_safe_api` and `always_seven`. Thus, extracting from an already-optimized representation without source-failure reflection is unsound for UB verification.
- **Safety transfer via failure reflection (`failure_reflection_transfers_safety`, `failure_reflection_composes`):** Requiring `FailureReflection source model` (`∀ i, source i = .ub → model i = .ub`) guarantees `FailureReflection source model ∧ Safe model → Safe source` (proved with zero axioms) and composes transitively across compiler passes.
- **Caller-domain narrowing hazard (`narrowed_domain_is_safe`):** Proving a safe Rust function only on a restricted decoder subdomain (`{true}`) yields a valid conditional theorem while leaving permitted safe callers (`false`) unprotected.

#### 1.3 Consumer Statement Authority, Cache Applicability, and Native Sandbox Containment
- **Independent statement comparison and fresh replay:** Using `leanprover/comparator` (`865edc14486c3388e9225daa971da8e157488c3e`) and fresh environment replay separates producer search from acceptance. Because Lean's `.olean` import path maps compacted regions without re-checking proof terms in the kernel and can load native plugins, untrusted certificates must be checked via data-only representations or external kernel replay against a consumer-owned challenge.
- **Native macOS producer containment (`support/data-receipts-caches-and-producer-isolation/sandbox_probe.py`, `support/data-receipts-caches-and-producer-isolation/sandbox-results.json`, `support/data-receipts-caches-and-producer-isolation/coverage.json`):** Running a producer inside `/usr/bin/sandbox-exec` with a profile denying network access and restricting `file-write*` to a dedicated producer output directory allowed the producer to write `out.txt` while blocking its attempt to overwrite the consumer's challenge file (`PermissionError: [Errno 1] Operation not permitted`), preserving the challenge SHA-256 digest (with the initial nested-sandbox `sandbox_apply` exit `71` recorded separately in `support/data-receipts-caches-and-producer-isolation/sandbox-results.first-failed.json`).

**Basis:** Kernel-checked Lean 4.34.1 proofs, `rustc 1.99.0` LLVM/assembly emission, 18-case admission test execution, and macOS `sandbox-exec` execution.

#### 2.2 Machine-Checked Split Contract-and-Trace Bridge (`support/isa-integration-architecture-and-roadmap/AnnealIsaBridgeSynthesis.lean`)
In `joshlf/anneal` (`c065b55a3a143ec3f6a4f9c8166bd9e6a4c4633b`), the entire trusted verification kernel in `trusted/lean/Trusted/` (`Refinement.lean`, `StepResult.lean`, `Memory.lean`, `MirAst.lean`, `MirSemantics.lean`) totals 561 lines of Lean 4 enforced by `TrustedBoundary.lean` (zero `sorryAx`, zero user axioms, zero `unsafe`/`partial`/`@[extern]`). To preserve human auditability, `support/isa-integration-architecture-and-roadmap/AnnealIsaBridgeSynthesis.lean` (2,289 lines, SHA-256 `0aea81289fb1cc881a7e492796f0cd40035fb8498c560ad767550eff07ad2a70`) places only the ~140-LOC `@[candidate inline_asm]` contract inside `trusted/` and keeps all ISA decoders and simulators in `theory/Anneal/Isa/`:

1. **Normative Rust Reference `[asm.*]` enforcement in `evalInlineAsm`:**
   - Evaluates `.inReg` and `.inoutReg` MIR operands left-to-right (failing to `StepResult.failed .ub` on uninitialized locals).
   - Demonically branches (`StepResult.choice .demonic`) over **all pairwise-distinct GPR allocations** (`validRegAllocs`, excluding `.sp` and `.nzcv` from `RegClass.gpr`) and **unconstrained caller register/flag seeds** (`initRegSeeds = [0, 0xdeadbeef]`).
   - Enforces `[asm.register-preservation]` (`checkRegisterPreservation`): every non-output, non-clobbered physical register (and `.nzcv` when `preserves_flags = true`) must equal its pre-state value.
   - Replays `AsmAccessEvent` traces (`replayAsmEvents`) directly against `MirState.mem : MemState`, enforcing `options(nomem | readonly | nostack)`, natural alignment (`width > 0 && loc % width == 0`), caller spatial footprint (`(loc, width) ∈ allowedFootprint`), and happens-before read/write/atomic view timestamps.
2. **Sixteen machine-checked theorems across three ISA backends, a 4-block mixed MIR+`asm!` function, and 5 negative canaries:**

   - *Backend 2 (`LNSym` + `bignum` `BitVec 32` decode, `Component` lenses, and `UArchEvent` constant-time trace):* `regComponent_orthogonal` proves lens orthogonality for `r₁ ≠ r₂`; `bignum_lnsym_words_eq_kernel1` decodes and executes the concrete AArch64 machine words `[0xf9400002#32, 0x8b010042#32, 0xf9000002#32]` (`ldr x2, [x0]; add x2, x2, x1; str x2, [x0]`), proving both exact equivalence to `evalAsmKernel 1` and secret-independence of the microarchitectural leakage trace `[.memRead addr 8, .aluRegOp, .memWrite addr 8]`.
   - *Backend 3 (`Sail` + `lean-sail` + `archsem-lean` Tier-1 `FreeM SailEffect` to `opencompl` Tier-2 `BitVec 64` summary):* `sail_tier1_equiv_tier2_summary` proves that interpreting the 7-bind monadic `sailAccumMonadic` program equals the pure `BitVec 64` summary `sailAccumSummaryBv` and lifts to `evalAsmKernel 1`.
   - *Mixed 4-block Rust MIR + `asm!` verification (`checked_mmio_accum`):* `evalInlineAsm_accum_all_branches`, `checkedMmio_safe_and_returns`, `checkedMmioBody_refines_spec`, `verify_crate_with_inline_asm`, and axiom-free `non_vacuity_at_every_depth` verify both the `delta == 0` safe-Rust fast path and the `delta != 0` inline-assembly path across all 24 GPR allocations $\times$ 2 register seeds (48 demonic branches).
   - *Five negative adequacy canaries:* `canary_undeclared_clobber_ub`, `canary_readonly_write_ub`, `canary_nomem_read_ub`, `canary_unaligned_access_ub`, and `canary_demonic_reg_aliasing_ub` each step to `.failed .ub` at budget 1 and refute `MirLang.WellFormedOn`.

### 3. MiniRust, Assembly Coverage, and Research Agenda Synthesis

#### 3.1 MiniRust and Assembly Semantic Findings (52 Research Bundles & 49 Execution Milestones)
Synthesizing the 52 MiniRust (`MR01`–`MR24`) and assembly (`AS01`–`AS28`) research bundles (`support/minirust-assembly-research-agenda/questions.json`, `support/minirust-assembly-coverage-and-adoption/coverage-matrix.json`, `support/minirust-assembly-coverage-and-adoption/question-crosswalk.md`) and the 49 follow-on execution and proof milestones (`support/execution-milestones-and-acceptance/milestones.json`, `support/execution-milestones-and-acceptance/baseline-frontiers.json`) establishes three concrete semantic constraints on adoption:
1. **MiniRust enum variant stability and wide-pointer union chunk truncation:** Current MiniRust type well-formedness (`WF`) alone permits an enum encoding whose discriminant changes variant across storage round-trips unless generic codec laws enforce tagger/discriminator coherence. Furthermore, in the generated MiniRust interpreter (`5` generated files, `288,411` bytes built under Rust `1.97` nightly, `23` upstream tests + `8` owned core cases), overwriting a wide-pointer union field with a shorter chunk drops provenance metadata.
2. **Byte/alias trace agreement vs. empty-range data-race differences:** Across `81,915` per-location alias traces and `6,400` race-range pairs, owned transcriptions agree on non-empty accesses but expose `198` empty-range differences that must be normalized before sharing proof libraries.
3. **Kraken vector access width mismatch and AArch64/x86-64 ABI differences:** While `1,290` scalar AArch64 cases (including `NZCV` flags) and `8,292` arithmetic pairs across inline and naked assembly routes at `-O0`/`-O3` agree between the model, oracle, and native hardware, Kraken's default `MemModel.All` ignores permissions and selected vector helpers check only an 8-byte footprint before accessing wider SIMD registers. Moreover, scalar leaf return conventions differ across backends (`RAX`/`X0` direct return vs. `s2n-bignum`'s output-pointer store + carry return in `RAX`), requiring explicit ABI resource-and-value adapters.
