# Non-Memory-Safety Sandbox Guarantees and Formal Proof Discharge Mechanisms

## Summary

Formal proofs of spatial/temporal memory safety and undefined-behavior (UB) freedom do **not** establish parity with OS-level process or VM sandboxes. Production sandboxes enforce at least six security and availability properties beyond memory-corruption containment: ambient-authority confinement (blocking unintended filesystem, network, and subprocess syscalls), resource-exhaustion containment (stack, heap/OOM, CPU/algorithmic DoS), crash/abort containment for co-located workloads, cross-tenant storage and microarchitectural isolation, defense against compiler/linker/supply-chain defects, and multi-layer defense-in-depth.

1. **Disjointness of Memory Safety and Sandbox Coverage:** Memory-safe languages and memory-safe parsers remain vulnerable to ambient-authority exploits (FFmpeg HLS `concat`/`subfile` local-file exfiltration `CVE-2016-1897`/`CVE-2016-1898`/`CVE-2017-9993`, ImageMagick delegate execution `CVE-2016-3714`, Ghostscript `-dSAFER` bypass `CVE-2023-36664`, Java JNDI RCE `CVE-2021-44228`), algorithmic DoS (safe-Rust `regex` compilation blowup `CVE-2022-24713`, XML Billion Laughs `CVE-2003-1564`), crash-loop availability failures in shared address spaces, logic/validator bypasses, and supply-chain build/linker backdoors (`CVE-2024-3094`). Conversely, classic process sandboxes (`seccomp-bpf` + namespaces, Sandbox2/SAPI, Minijail, in-process heap sandboxes) do **not** prevent same-privilege logic bugs, uninitialized-memory leaks into authorized outputs, cryptographic timing channels, or hardware transient-execution attacks (Spectre v1, `CVE-2017-5753`) without hardware/OS address-space isolation plus microarchitectural mitigations (e.g., Site Isolation, KVM + kernel address-space isolation + core scheduling).
2. **Which Non-Memory-Safety Guarantees Formal Verification Can Discharge Statically:**
   - *Ambient authority (for pure compute/parsing components):* Fully sealable at compile and link time with zero runtime IPC overhead by combining `#![no_std]` + capability-passing APIs + closed crate-wide `extern` symbol auditing + post-link ELF/object verification proving absence of dynamic loaders (`PT_INTERP`/`DT_NEEDED`) and raw `syscall`/`svc`/`ecall` instructions.
   - *Crash/panic/unwind/abort containment:* Fully dischargeable via effect-indexed contracts requiring `noUnwind = true` and `noAbort = true` (proving every MIR `Assert`, `Unreachable`, `UnwindTerminate`, and aborting allocator path unreachable), canonical masked floating-point control (`MXCSR`/`FPCR`), and post-link trap-absence checks.
   - *Stack overflow, OOM, and algorithmic amplification:* Stack depth is statically verifiable via `-Z emit-stack-sizes` plus acyclic call-graph checking; OOM is eliminated via `#![no_std]` or fallible bounded-region allocators; infinite loops and super-linear amplification are bounded via termination measures (`EffectMask.terminates`) and constructive byte/step-credit algebras (`steps <= K * input_len + C`).
   - *Uninitialized reads and cross-tenant storage leaks:* Discharged by byte-level initialization masks (`InitMask`), spatial read/write framing (`SpatialPin`/memory framing), and post-link verified volatile zeroization surviving dead-store elimination.
3. **Where Formal Proofs Alone Hit Hard Boundaries:**
   - *Tight wall-clock WCET:* Architectural MIR or retired-instruction step bounds do not bound physical execution time across caches, DRAM, and page faults; cheap OS cgroup/rlimit/deadline watchdogs remain more economical than cycle-exact WCET proofs for large codecs or parsers.
   - *Specification-to-intent alignment:* Formal proofs establish `Implementation |= Spec`, never `Spec |= HumanIntent`; flawed specifications pass kernel checks silently.
   - *Hardware transient execution (Spectre):* Architectural MIR and ISA semantics do not prevent speculative out-of-bounds reads past verified bounds checks; cross-trust-domain secrets still require hardware MMU/process/VM isolation (or explicit post-link speculative hardening where applicable).
   - *Compile-time execution of build scripts and proc-macros:* Post-expansion MIR verification audits all *runtime* code injected by macros, but does not sandbox *compile-time* execution of `build.rs` or procedural macros, which still requires hermetic sandboxed build actions.
4. **Proof-Carrying Minimal Isolation Spectrum:** Replacing sandboxes is not a binary choice between full VMs and unprotected shared processes. Combining formal verification (memory safety + ambient-authority sealing + panic/stack/OOM/amplification bounds + multi-kernel proof replay) with cheap, zero-IPC outer OS/hardware guardrails (cgroup CPU/RAM caps, deadline watchdogs, and trust-domain MMU boundaries separating secret-bearing services from untrusted-input workers) achieves a Pareto frontier that eliminates high-tax per-call IPC, namespace lock contention, and cross-process buffer copies without sacrificing defense-in-depth.

## Applicability

This report synthesizes the general programming-languages, formal-verification, and systems-security taxonomy comparing OS/hardware sandboxes against static formal verification for systems software (specifically Rust/MIR verifiers paired with optional post-link ELF/ISA auditing, grounded in `google/zerocopy` `anneal/` at commit `a5c88c87ce08e97b0576165f898d2866710d03f5` and complementary public ISA/compiler/sandbox baselines listed in `REPORT.json`).

- **Relationships among subjects:** The Linux sandboxing primitives (`seccomp-bpf`, Landlock, namespaces, cgroups), `google/sandboxed-api`, `google/gvisor`, and Chromium's `docs/security/rule-of-2.md` establish the operational threat model of production sandboxes. The listed MITRE/NVD CVEs provide concrete historical witnesses of non-memory-safety exploits across memory-unsafe and memory-safe languages. `google/zerocopy` (`anneal/`), `google-deepmind/code-verification` (`arm64-semantics`), and the `rust-lang/rust` LLVM `23.1.5` baseline characterize what source-level MIR proofs, post-link binary/ISA checks, and multi-kernel proof checkers can and cannot discharge.
- **Scope:** Findings apply to compiled native systems code (parsers, demuxers, codecs, serializers, cryptographic kernels, and co-located userspace services) executing on mainstream 64-bit hardware (`x86_64`, `aarch64`, `riscv64`) under Linux or capability-based OS kernels. Workloads that execute arbitrary attacker-supplied code by design (e.g., JavaScript JITs, multi-tenant cloud VMs, arbitrary WebAssembly hosts) remain outside pure proof-replacement scope and require hardware/VM isolation layers.

### 2. Detailed Discharge Mechanics and Hard Limits per Class

#### 2.1 Ambient Authority Elimination vs. Dynamic Syscall Filtering

`Basis: documentation + source + derived`

Memory-safe languages with standard libraries (`std::fs`, `std::net`, `std::process`, `std::env` in Rust; JNDI/reflection/`Runtime.exec` in Java; `os`/`net` in Go) grant ambient authority by default. Consequently, rewriting a media demuxer or document parser in safe `std` Rust does not prevent XXE, SSRF, or local file exfiltration (`CVE-2016-1897`, `CVE-2016-1898`, `CVE-2017-9993`).

For pure computational and parsing components, static ambient-authority sealing eliminates this class more tightly than runtime `seccomp-bpf` or mount namespaces, at zero runtime IPC cost:
1. **Compile-time capability restriction:** Compile as `#![no_std]` with explicit data/capability arguments (`&[u8]`, `&mut [u8]`, caller-supplied chunk reader or bounded arena) rather than path strings or URLs.
2. **Closed transitive `extern` audit:** At MIR capture over the full crate closure, verify that the set of reachable foreign `extern` declarations is empty (or restricted strictly to an explicitly audited allowlist of non-I/O math/allocator primitives). Any transitive third-party dependency introducing `openat`, `socket`, `connect`, `execve`, `dlopen`, or `getenv` fails closed.
3. **Post-link ELF/object verification:** Scan the final compiled object/archive/ELF to confirm zero dynamic loader headers (`PT_INTERP`, `DT_NEEDED`), zero undefined OS I/O symbols, zero unexpected `IFUNC` resolvers (`STT_GNU_IFUNC`), and zero raw syscall instructions (`syscall`, `sysenter`, `int 0x80` on x86-64; `svc` on AArch64; `ecall` on RISC-V) anywhere in executable `.text`. For components that legitimately invoke a capability kernel (e.g., non-blocking IPC syscalls via a verified vDSO), replace raw `noSyscalls` with relational handle-confinement proofs (`EventConfinedTo H_i` under opaque fresh handle allocation, preventing sibling handle forgery).

**Boundary:** Static sealing eliminates *unintended* authority (e.g., an image decoder opening TCP sockets). When a component legitimately holds network or filesystem capabilities by design, enforcing fine-grained URL/path policies remains a functional-specification or OS-policy (Landlock/netns) problem.

#### 2.2 Resource Bounds: What Static Proofs Discharge vs. Where OS Watchdogs Win

`Basis: source + execution + derived`

Resource exhaustion decomposes into four sub-properties with distinct verification economics:
- **Stack overflow (high ROI, static):** Compiling with `-Z emit-stack-sizes`, enforcing call-graph acyclicity (or explicitly bounded iterative traversal stacks replacing unbounded recursion on nested atoms/elements), and computing exact worst-case reachable stack usage post-link (after pruning unreachable trap sinks) statically certifies strict stack ceilings (e.g., `<= 32 KiB` for 64 KiB fiber stacks) with zero runtime overhead.
- **Heap OOM / decompression bombs (high ROI, static):** Prohibiting aborting global allocators (`#![no_std]` or fallible bounded-region `TryVec`/`TryBox`/arena handles) paired with specification invariants bounding allocated bytes as a function of input/output parameters (`allocated_bytes <= K_mem * input_len + C_mem`) rules out exponential expansion bombs (`CVE-2003-1564`) and `handle_alloc_error` aborts.
- **Non-termination and algorithmic complexity (medium ROI, static):** Effect-indexed contracts with `EffectMask.terminates = true` require either acyclic call-graph stratification or strictly decreasing well-founded measures across every cyclic strongly connected component (preventing unsound circular mutual-recursion termination proofs). Constructive amortized step-credit algebras (`steps <= K * input_len + C`) discharge quadratic/exponential backtracking (`CVE-2022-24713`) and parser rescanning bombs.
- **Physical wall-clock WCET (low ROI for general parsers; compose with OS):** As mechanized in companion report `rustc-llvm-constant-time-codegen-dit-contracts-and-step-vs-wcet-honesty-ladder`, architectural MIR or retired-instruction step counts do not bound wall-clock time under cache misses, TLB/page faults, DRAM contention, and frequency scaling. For complex decoders or parsers, proving stack ceilings, bounded allocation, panic-freedom, and coarse anti-amplification in the verifier while relying on an `O(1)` OS cgroup CPU/memory limit and RPC deadline watchdog for wall-clock availability is strictly more economical than cycle-exact WCET verification.

#### 2.3 Panic, Unwind, and Abort Containment

`Basis: source + derived`

Removing process boundaries collapses fault isolation: under `-C panic=abort` (standard in bare-metal, microkernel, and embedded systems) or uncaught Rust panics crossing C FFI, a single panic terminates all co-located services or request threads sharing that address space.

Effect-indexed MIR contracts (`EffectMask { terminates, noUnwind, noAbort }`) discharge this directly by requiring proofs that every `TerminatorKind::Assert` (bounds checks, integer overflow, division by zero, alignment), `Unreachable`, `UnwindTerminate`, and panic/abort callee is unreachable for all type-valid inputs (`FullValid`). Safe functions must satisfy UB-freedom unconditionally regardless of behavioral preconditions (`safetyPre`/`behaviorPre` split), and floating-point consumers must enforce canonical masked exception bits (`MXCSR[12:7]`/`FPCR`) to rule out hardware `#XM`/`SIGFPE` traps. Where unwinding is permitted across library boundaries (`noUnwind = false`), encapsulation invariants must be preserved across both normal return (`.returned`) and unwind (`.unwound`) exits so `catch_unwind` callers cannot observe torn invariants.

#### 2.4 Logic Bugs and the Specification-to-Intent Boundary

`Basis: documentation + derived`

A frequent category error in sandbox-replacement debates is citing memory-safe logic bugs (authentication bypasses, broken authorization predicates, fail-open schema validators, cryptographic signature errors) as arguments for keeping a sandbox around the buggy component. Sandboxes do not fix same-privilege logic bugs: a sandboxed authentication service with a broken token check still authenticates the attacker; a sandboxed validator with a parser differential still admits the smuggled payload. Sandboxes limit only *post-compromise lateral movement* outside the component's granted privileges.

Formal verification goes further than sandboxing whenever a canonical specification exists: proving protocol state machines, access-control allowlists, bijective parse-and-serialize round-trips (eliminating parser differentials), or `SIMD == Scalar` functional equivalence eliminates logic bugs directly. However, formal verification permanently hits the **specification-to-intent boundary**: a theorem prover checks `Implementation |= Spec`, never `Spec |= HumanIntent`. Mitigating flawed specifications requires isolating all specification surfaces into a compact, trap-checked human audit manifest (rejecting silent proof-assistant traps such as `autoImplicit` or truncating `Nat.sub`), pairing formal specs with differential testing and specification mutation testing, and keeping component privileges minimal so a spec defect has bounded blast radius.

#### 2.5 Information Leaks, Constant-Time Lowering, and Hardware Transient Execution

`Basis: source + execution + derived`

Information-flow threats split sharply across three levels:
1. **Uninitialized memory and cross-tenant architectural storage leaks (dischargeable):** Byte-level `InitMask` tracking forbids reading uninitialized stack/heap/padding bytes into typed scalars, vectors, or output slices (closing uninitialized-buffer disclosure strictly better than dynamic sandboxes, which permit the sandboxee to return uninitialized bytes in its own outputs). For co-located compartments sharing an address space, spatial read-and-write framing (`readSet_i ⊆ R_RO ∪ R_i ∪ R_stack` and write confinement to `R_i ∪ R_stack`) plus turn-boundary `InitMask = uninit` resets and post-link verified volatile zeroization (surviving LLVM dead-store elimination) establish storage-level noninterference.
2. **Architectural timing / cache channels in cryptography (post-link binary required):** Empirical probing of `rustc 1.102.0-nightly` / LLVM `23.1.5` (detailed in `rustc-llvm-constant-time-codegen-dit-contracts-and-step-vs-wcet-honesty-ladder`) proves that single-trace-refining compiler optimizations silently destroy source- and MIR-level constant-time code (turning a 16-entry constant-time table scan into 16 conditional `jne` branches at `-O2`, lowering 32-byte `select_unpredictable` to secret-addressed loads across `x86_64`/`aarch64`/`riscv64`, spilling `black_box` secrets to stack red zones, and emitting hardware `div` at `-Oz`). Sound constant-time claims therefore require post-link relational 2-safety verification over machine instructions (`CtProduct`) combined with an explicit `FEAT_DIT`/`DOITM`/`Zkt` opcode allowlist and OS context-switch preservation contract.
3. **Hardware transient execution (Spectre v1/v2, BTB/RSB, DMP, L1TF, MDS — outside architectural proofs):** Neither MIR proofs nor architectural ISA proofs prevent speculative execution from reading past a verified bounds check (`CVE-2017-5753`) and exfiltrating co-resident secrets through microarchitectural state. Critically, **process-only sandboxes (`seccomp-bpf` + namespaces, Sandbox2/SAPI, Minijail, in-process heap sandboxes) also fail to stop Spectre** without additional hardware/OS mitigations (Site Isolation, KVM + kernel address-space isolation + core scheduling as in gVisor KVM, or hardware virtualization). The sound architectural rule is **trust-domain address-space partitioning**: never co-locate secrets (keys, cross-tenant credentials) in the same hardware address space (`CR3`/`TTBR0`) as untrusted-input parsers unless separated by an explicit MMU/VM trust-domain boundary (or dedicated stateless worker processes holding zero cross-tenant secrets).

#### 2.6 Below-MIR, Toolchain, and Supply-Chain Seams

`Basis: source + documentation + derived`

Five distinct attack surfaces lie below or outside MIR semantics:
1. **Inline/external assembly and SIMD kernels:** Closed by pairing MIR-level `core::arch` intrinsic verification with compiled-object `.o` ISA certificates (`IsaCert`) anchored to pinned ISA formalizations (e.g., `arm64-semantics`, `sail-arm`, `s2n-bignum`, `sail-riscv`, `SpecTec`), proving both memory safety and bit-exact `SIMD == Scalar` equivalence.
2. **Compiler and linker miscompilation (`rustc`/LLVM/`lld`):** Handled on an honest two-stage ladder: Stage 1 explicitly records `rustc`/LLVM/`lld` lowering in a machine-readable receipt's audited TCB manifest (`unmodeled_downstream`) while enforcing mechanical post-link ELF sanity checks (stack sizes, zero traps/syscalls, zero unexpected mutable globals/relocations); Stage 2 shrinks the TCB via certifying MIR-to-ISA translation validation or direct binary verification for compact `#![no_std]` binaries.
3. **Cross-language C/C++ FFI boundaries:** Unverified C/C++ linked into the same address space invalidates whole-binary memory safety; safe coexistence requires either keeping the unverified C/C++ behind a process boundary or proving an explicit byte-and-permission coupling relation across the `extern "C"` boundary (bridging initialization, alignment, allocator-kind, and aliasing mismatches) plus single-fetch/single-store volatile copying over hostile shared memory.
4. **Malicious `proc_macro`, `build.rs`, and supply-chain tampering (`CVE-2024-3094`):** A critical distinction separates *runtime* from *compile-time* effects. Because MIR capture runs *after* macro expansion over the entire compiled crate and post-link ELF checks inspect final symbol/relocation/IFUNC tables, runtime backdoors injected by procedural macros or generated code are caught fail-closed. However, *compile-time* execution of `build.rs` or `proc_macro` crates can still compromise the build host unless compilation runs inside hermetic, network-free build sandboxes with pinned toolchain digests.
5. **Verifier and proof-elaborator tampering:** Interactive theorem provers allow metaprogramming during elaboration and binary artifact serialization (`.olean`). Closing this seam requires sandboxed elaboration containment (`ExecSeal` or hermetic build actions), static preflight bans on specification-distorting attributes, and independent multi-kernel replay from clean serialized proof terms (e.g., Lean `v4.35.0` `leanexport` NDJSON replayed through independent kernels under the positive 3-axiom ceiling `{propext, Classical.choice, Quot.sound}`).

### 3. Defense-in-Depth: The Five-Tier Proof-Carrying Minimal Isolation Spectrum

`Basis: documentation + derived`

Security engineering does not face a binary choice between heavy multi-process/VM sandboxes and raw unisolated execution. Ordering isolation tiers by cost and threat coverage reveals a five-tier Pareto frontier:

| Tier | Architecture | Runtime/OS Primitives Retained | Heavy Primitives Eliminated by Proof | Threat Coverage & Role |
| :---: | :--- | :--- | :--- | :--- |
| **Tier 0** | **Full VM / Dual-Layer Sandbox** (KVM micro-VM, gVisor KVM + kASI + core scheduling) | Hardware virtualization, separate kernel, kASI, core scheduling, cgroups | None | Mandatory for arbitrary untrusted code execution by design (JS/Wasm engines, multi-tenant cloud workloads, hostile binaries) |
| **Tier 1** | **Classic Process Sandbox** (`seccomp-bpf` + Mount/PID/Net/User NS + IPC marshaling, e.g., Sandbox2/SAPI) | Separate process, full namespace suite, per-call IPC, buffer copies, rlimits | None | Legacy memory-unsafe C/C++ parsers (`Rule of 2` containment; does **not** stop Spectre) |
| **Tier 2** | **Lightweight OS Sandbox** (Landlock LSM + cgroups + seccomp, dropping Mount/PID NS) | Separate process, Landlock, cgroups, User/Net NS, seccomp | Mount-table cloning & PID-namespace kernel lock contention (trading intra-user signal DoS) | Transitional high-QPS containment for legacy unsafe C/C++ binaries |
| **Tier 3** | **Proof-Carrying Minimal Isolation** (Verified Rust/SIMD + Ambient-Authority Seal + Outer Container/Watchdog) | Zero-IPC outer container/trust-domain boundary (zero cross-tenant secrets in worker AS), OS cgroup CPU/RAM cap, deadline watchdog | Per-library/per-call child processes, IPC marshaling, cross-process buffer copies, namespace churn | **Pareto-optimal for verified high-throughput parsers/codecs:** Memory & SIMD safety + static `noSyscalls` (stops XXE/SSRF) + panic/stack/OOM/amplification proofs + outer cgroup/deadline + trust-domain Spectre boundary + multi-kernel proof replay |
| **Tier 4** | **Verified Shared-Address-Space Co-Location** (Single-process multi-component pack within one trust domain) | Per-trust-domain MMU boundary (Single-Base ASLR), zero unverified code in pack | Per-component MMU page tables, per-component OS kernel thread stacks, cross-process IPC syscalls | Same-trust-domain 1P services (boot/control-plane/embedded packs) proving spatial read/write framing, opaque handle partitioning, panic/stack containment, and bounded cooperative steps |

Tier 3 demonstrates why formal verification and defense-in-depth are complementary rather than antagonistic: proofs eliminate the *expensive inner isolation mechanisms* (per-call process spawning, IPC serialization, cross-process memory copies, per-component kernel stacks) while retaining *near-zero-cost outer OS/hardware boundaries* (cgroups, deadlines, and trust-domain MMU separation) to hedge compiler TCB, specification-intent, and microarchitectural Spectre risks.

## Boundaries

- **Known not to apply:**
  - *Arbitrary code execution by design (e.g., untrusted JS/Wasm/user scripts):* Static source/MIR verification of an interpreter or JIT cannot replace Tier 0 hardware/VM isolation when the workload executes arbitrary attacker programs; formal verification there strengthens the sandbox implementation itself rather than removing it.
  - *Cross-trust-domain secret co-location under Spectre:* Architectural MIR and ISA proofs do not establish transient-execution noninterference; co-locating secret keystores with untrusted-input parsers inside one `CR3`/`TTBR0` remains unsound without hardware/OS separation.
  - *MIR-only constant-time claims:* Proven broken under optimizing LLVM lowering (`rustc 1.102.0-nightly` / LLVM `23.1.5`); requires post-link binary verification plus hardware `DIT`/`DOITM`/`Zkt`.
- **Unsupported / unverified assumptions in Stage 1 MIR verifiers:**
  - Until certifying MIR-to-ISA translation validation is deployed, `rustc` MIR optimization, LLVM codegen, and `lld` linking remain explicit TCB entries (mitigated but not eliminated by post-link ELF checks).
  - Compile-time execution of `build.rs` and `proc_macro` crates is not confined by MIR verification and requires hermetic build-system sandboxing.
- **Not examined:**
  - Hardware fault-injection attacks (Rowhammer, voltage/clock glitching, physical EM/power side channels), which lie outside both software formal verification and OS process sandboxing.
  - Formal verification of dynamic capability languages (Java/JVM, Python, Go) with reflection/dynamic class loading; this report addresses native compiled systems Rust and its C/ASM seams.
- **Attractive stronger conclusions not established:**
  - Proving memory safety, panic-freedom, and `noSyscalls` does **not** prove freedom from domain logic bugs or flawed specifications.
  - Proving a finite step bound `steps <= K * input_len + C` does **not** establish a hard real-time physical WCET bound in nanoseconds.
  - Eliminating a per-library child-process sandbox does **not** eliminate the need for outer container/trust-domain boundaries when a service handles mutually distrusting tenants' secrets.
