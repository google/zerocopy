# Frame-Limited Reuse, Fully In-Place Calculi, Second-Class Values, and Representation Kinds for Unboxed Immediates

## Summary

Language runtimes and verified compiler IRs repeatedly confront a fundamental architectural question: can freely duplicable, metadata-free, mutation-isolated, space-bounded immediate values be unified with region-addressed memory capabilities, or must a core language maintain a primitive distinction between immediates and addressed storage? Direct examination of four pinned upstream codebases (`koka-lang/koka`, `TiarkRompf/scala-escape`, `ghc/ghc`, `dotnet/csharplang`) and nine primary papers establishes five load-bearing findings:

1. **No examined memory-management mechanism simultaneously gives all five immediate-value properties via pure region-addressed capabilities.** Across Perceus reference-counting reuse (`koka`), Fully in-Place calculi (`FP²` / `CheckFBIP.hs`), second-class stack-bound values (`scala-escape` `STLCs 1/2`, C# `ref struct` / `scoped`), and scoped immutable arenas, every region- or heap-addressed strategy surrenders at least one of: (a) `0`-bit per-value runtime metadata, (b) free duplication without counter mutations or borrowing restrictions, (c) isolation from later writes to source storage, (d) first-class escapability across call returns, or (e) `O(1)` peak memory across a `k`-step sequential chain within one scope. Only **representation-kinded unboxed immediates** (`GHC PrimRep`, Koka `DataDefValue`, C# plain `struct`) satisfy all five simultaneously—precisely because they are classified statically as a distinct register/by-value representation sort rather than heap/region-addressed storage.
2. **Under Felleisen's macro-expressibility criterion (SCP 1991), none of the four mechanisms eliminates the need for an extra sort, storage class, or reduction rule.** Each mechanism relies on a non-macro-expressible extension to a pure region-capability calculus:
   - **Perceus / Frame-Limited Reuse** adds an `8`-byte per-block header (`kk_header_t` with 32-bit atomic `refcount`, `scan_fsize`, `_field_idx`, `tag` in `kklib.h:136-141`) plus runtime uniqueness-testing and cell-recycling reduction rules (`kk_block_is_unique`, `dropru`/`alloc_at`), and *still* separates raw value types (`DataDefValue`, `size == 0`, `needsDupDropData = False`) from heap blocks (`Parc.hs:649-658`, `ParcReuse.hs:364-367`).
   - **Fully In-Place (`FP²`)** adds static reuse-credit accounting (`Fip`/`Fbip` in `Syntax.hs:572-616`, `CheckFBIP.hs:321-626`) enforcing linear ownership and tail-call constraints; in Koka it compiles onto the same `64`-bit `kk_header_t` heap blocks for recursive constructors while still excluding `DataDefValue` raw types from reuse tokens (`CheckFBIP.hs:552, 594`).
   - **Second-Class Stack-Bound Values** add a second privilege class (`First | Second` in `scala-escape/coq/stlc1.v:111-122`), an explicit LIFO call stack storage class (`heap` + `stack`, `st_ptr := S0 | Si` in `stlc2.v:28-46`), or a `ref struct` type category with a 4-level safe-context lattice (`declaration-block < function-member < return-only < caller-context` in `csharplang/low-level-struct-improvements.md`). Moreover, when a `ref struct` holds a `ref` field (like `Span<T>`), it does **not** isolate reads from later mutation of the referent storage!
   - **Representation Kinds (`TYPE r`, `RuntimeRep`, `PrimRep`)** explicitly make the immediate-vs.-addressed split a **kind-level sort distinction** (`BoxedRep (Maybe Levity)` vs. `IntRep`/`WordRep`/`AddrRep`/`FloatRep`/`DoubleRep`/`VecRep` in `ghc/compiler/GHC/Core/TyCon.hs:1788-1805`, `GHC/Internal/Types.hs:785-815`), enforced by `Core Lint`'s fixed-representation check (`typeHasFixedRuntimeRep` at `Lint.hs:1466, 1839-1842`) because calling conventions cannot be polymorphic over unknown register layouts (Eisenberg & Peyton Jones PLDI 2017; Downen et al. ICFP 2020).
3. **Production compilers consistently represent immediates via two complementary mechanisms—static kind/type classification AND tagged-word dynamic boxing for polymorphism.** Koka uses `DataDefValue` (`Parc.hs:653`) for monomorphic unboxed structs/scalars (0 header bytes) AND a 1-bit LSB pointer/value tag (`kk_box_t`, `box.h:26-49`, 63-bit values + exponent-compressed 64-bit doubles) across polymorphic boundaries. GHC uses `RuntimeRep` / `PrimRep` (`isGcPtrRep`, `TyCon.hs:1877-1879`) with zero runtime tag bits on unboxed types, forbidding levity-polymorphic binders/arguments (`Lint.hs:1466, 1839`). C# uses ECMA-335 value types (`struct`, copied by value, 0 object header) versus managed reference types (`class`, GC-traced heap pointer) versus stack-only `ref struct` (`IsRefLikeAttribute`, `ELEMENT_TYPE_BYREF` fields).
4. **Published space guarantees rely on sharp, distinct proof assumptions:** Perceus's *garbage-free* theorem assumes precise last-use static analysis and acyclic heaps; Lorenzen & Leijen's *frame-limited* theorem (ICFP 2022, Theorems 4–5) relaxes strict garbage-freeness to allow bounded dead-cell retention (`≤ garbage_free + c · stack_depth`) across reuse tokens; `FP²` (`fip(0)`, ICFP 2023) proves `0` heap allocation and `O(1)` stack space assuming uniquely owned inputs, matching constructor sizes, no non-tail recursion, and only total/`div`/`exn` effects (`CheckFBIP.hs:291-301`); `STLCs 1/2` (`scala-escape/coq/stlc2.v`, `stlc4.v`) proves stack-based LIFO lifetimes assuming second-class values never escape return boundaries; Xhebraj et al. (ECOOP 2022) relax return non-escape via delayed frame popping (`10–25%` execution speedup, bounded by the next first-class return).
5. **Measured runtime and memory trade-offs are substantial:** Perceus with reuse matches C++ `std::map` within `~10%` on `rbtree` (`2.41×` faster than non-reuse Perceus) and cuts peak RSS by `> 40%` vs. OCaml on `cfold`/`deriv` (PLDI 2021); delayed stack popping yields `10–25%` speedups over heap allocation (ECOOP 2022); yet Koka's heap constructors still pay `8` bytes of `kk_header_t` metadata per block (`kklib.h:136-143`), whereas unboxed immediates pay `0` bytes.

### 2. Felleisen Macro-Expressibility Analysis and Production Compiler Representations

Basis: normative + source + derived (`Felleisen SCP 1991`, `koka-lang/koka`, `TiarkRompf/scala-escape`, `ghc/ghc`, `dotnet/csharplang`)

#### 2.1 Applying Felleisen's Macro-Expressibility Criterion

In Felleisen (*"On the Expressive Power of Programming Languages,"* SCP 1991, `10.1016/0167-6423(91)90036-W`), an extension $\mathcal{L}_1$ of a base calculus $\mathcal{L}_0$ is **macro-expressible** in $\mathcal{L}_0$ iff there exists a *local, homomorphic syntactic translation* $M[\cdot] : \mathcal{L}_1 \to \mathcal{L}_0$ (leaving existing $\mathcal{L}_0$ constructs untouched and requiring no whole-program CPS/store-passing rewrite) that preserves termination and observational equivalence—and **crucially, without adding new reduction rules, new runtime storage classes/tags, or a new syntactic/typing sort** to $\mathcal{L}_0$.

Evaluating each of the four candidate mechanisms against a base calculus $\mathcal{L}_{\text{cap}}$ whose *only* value storage is region-addressed capabilities (no separate immediate sort, no storage-class tag on capabilities, no new operational reduction rules):

1. **Perceus Reference-Counting Reuse (`koka`):** **NOT macro-expressible in $\mathcal{L}_{\text{cap}}$.**
   - *Why:* Perceus requires (a) mutable per-cell `refcount` runtime metadata (`kklib.h:140`), (b) dynamic uniqueness-branching reduction rules (`dropru` checks `kk_block_is_unique(b)` at runtime: if `rc == 0`, return a reuse token pointing to `b`'s raw memory without freeing; if `rc > 0`, decrement `rc` and return `NULL` so `alloc_at` falls back to `malloc`), and (c) global reverse-liveness insertion (`Parc.hs:17`), which is not a local macro expansion. Furthermore, when reuse falls back under sharing, peak space is no longer `O(1)` in `k`; and Koka itself does **not** use Perceus RC for scalars—it relies on a separate value-type classification (`DataDefValue`, `Parc.hs:653`).
2. **Fully In-Place Calculi (`FP²` / `fip`):** **NOT macro-expressible in $\mathcal{L}_{\text{cap}}$ for freely duplicable immediates.**
   - *Why:* `FP²` replaces dynamic GC with linear reuse credits, which requires either (a) the same runtime uniqueness/reuse reduction rules as Perceus (in Koka's implementation, `CheckFBIP.hs` is a static verification pass on top of `ParcReuse`), or (b) an explicit linear-ownership typing discipline with destructive reuse transitions in the operational semantics (eliminating free duplication of heap constructors!). In neither case can a single region-capability encoding provide *both* free duplication *and* `0`-metadata in-place reuse.
3. **Second-Class Stack-Bound Values (`scala-escape` / ECOOP 2022 / C# `ref struct`):** **NOT macro-expressible in $\mathcal{L}_{\text{cap}}$.**
   - *Why:* As `TiarkRompf/scala-escape/coq/stlc1.v` and `stlc2.v` prove directly by construction, second-class values require adding:
     - a **second typing privilege/sort** (`Inductive class := First | Second`, dual contexts `(G1, G2)`, and `sanitize_env` at `stlc1.v:113-121`), AND
     - a **second runtime storage class** (`stack` of LIFO frames alongside `heap`, with `st_ptr := S0 | Si` in `stlc2.v:28-46`)—or, in ECOOP 2022, a new **delayed-popping reduction rule** on call returns.
   - Similarly, C#'s `ref struct` requires a distinct type category (`IsRefLikeAttribute`, `span-safety.md:39`) plus a 4-level lifetime lattice (`declaration-block`, `function-member`, `return-only`, `caller-context`) and still fails **mutation isolation** whenever the `ref struct` stores a `ref` field (`low-level-struct-improvements.md:130`).
4. **Representation Kinds for Unboxed Immediates (`GHC RuntimeRep` / `PrimRep`):** **IS explicitly a second sort (at the kind level), NOT a macro-encoding into region capabilities!**
   - *Why:* Peyton Jones & Launchbury (FPCA 1991), Eisenberg & Peyton Jones (PLDI 2017), and Downen et al. (ICFP 2020) show that unboxed immediates (`Int# :: TYPE 'IntRep`) and heap-addressed boxed values (`Int :: TYPE ('BoxedRep 'Lifted)`) have **incompatible calling conventions and operational reduction rules** (strict register evaluation vs. lazy heap-thunk allocation; GC-traced pointers `isGcPtrRep = True` vs. raw bit patterns `isGcPtrRep = False`). GHC unifies them syntactically under one parameterized kind constructor `TYPE (r :: RuntimeRep)`—which *is* a kind-level storage-class tag isomorphic to maintaining disjoint sorts whenever `r` is instantiated! And because hardware registers cannot execute code polymorphic over an unknown `RuntimeRep`, GHC Core **must** enforce `typeHasFixedRuntimeRep` at every binder and call argument (`Lint.hs:1466, 1839-1842`).

**Synthesis (Derived):** Adding a storage-class tag (`Immediate | Addressed`) to capabilities or indexing a unified `TYPE` kind by `RuntimeRep` is **structurally isomorphic** to maintaining two sorts—with the crucial engineering difference that kind-indexed representations (`TYPE r`, Downen et al. 2020) let *polymorphic type signatures* (like `(->)`, `error`, `($)`) abstract over the tag at compile time while forcing monomorphic/fixed specialization before code generation.

#### 2.2 How Production Compilers Represent Immediates vs. Addressed Storage

Basis: source (`koka-lang/koka`, `ghc/ghc`, `dotnet/csharplang`)

1. **Koka (`koka-lang/koka` @ `b66091b2a5a7ea20c5ed9498ad1e1f03caee9589`):**
   - **Static value-type bypass (`src/Backend/C/Parc.hs:649-658`, `src/Backend/C/ParcReuse.hs:357-367, 886-903`):** Every datatype carries a `DataInfo` with `DataDefValue vr` (unboxed value structs/scalars) versus heap-allocated constructors. `needsDupDropData` returns `False` for raw value types (`DataDefValue vr | valueReprIsRaw vr`, `Parc.hs:653`) and zero-field structs (`ValueRepr 0 0 _`, `Parc.hs:656`), emitting **zero** `dup`/`drop` calls. In `ParcReuse.hs:364-367`, `ruIsReusable` treats `size == 0` as `NotReusable`, and `getFixedDataAllocSize` (`ParcReuse.hs:896-897`) returns `Nothing` whenever `dataDefIsValue ddef` is true.
   - **Heap object header (`kklib/include/kklib.h:106-162`):** Every heap-allocated constructor starts with a 64-bit `kk_header_t`:
     ```c
     typedef struct kk_header_s {
       uint8_t   scan_fsize;            // scannable pointer fields (0xFF => first field holds full count)
       uint8_t   _field_idx;            // stackless-free cursor / constructor-context path / lazy state
       uint16_t  tag;                   // constructor tag
       _Atomic(kk_refcount_t) refcount; // int32_t: 0 = unique, >0 = local shared, <0 = thread-shared, INT32_MIN = stuck/static
     } kk_header_t;
     ```
     Initializing `refcount = 0` for unique objects (`KK_HEADER`, `kklib.h:146`) makes uniqueness testing a single zero-check (`kk_block_is_unique`, `kklib.h:306-308`) and thread-sharing detection a sign-bit test (`rc < 0`, `kklib.h:109-111`), avoiding atomic instructions on thread-local objects!
   - **Polymorphic tagged-word boxing (`kklib/include/kklib/box.h:16-49`):** When an unboxed immediate crosses a polymorphic boundary (`kk_box_t`), Koka uses the **least-significant bit (LSB)** as a dynamic immediate-vs.-pointer tag: LSB `0` = 2-byte-aligned `kk_block_t*` heap pointer (zero-cost boxing of pointers); LSB `1` = 63-bit immediate `n * 2 + 1`. For 64-bit IEEE-754 `double`s, default strategy `A1` (`KK_BOX_DOUBLE64 = 1`, `box.h:32-44`) encodes doubles with 10-bit exponents (`|x| ∈ [2⁻⁵¹¹, 2⁵¹²)` plus `0`, subnormals, `NaN`, `±∞`) unboxed in 63 bits and heap-allocates only extreme-exponent doubles; on 128-bit CHERI pointers (`box.h:22-24`), `kk_box_t` is 128 bits with immediate arithmetic in the low 64 bits.
2. **GHC Core (`ghc/ghc` @ `83038fbee5efea8e3ebd5090b2ff5537462e169d`):**
   - **User-visible kind hierarchy (`libraries/ghc-internal/src/GHC/Internal/Types.hs:255-277, 785-838`):** Every inhabited type has kind `TYPE (r :: RuntimeRep)`, where `RuntimeRep` enumerates `BoxedRep Levity` (`Lifted` vs. `Unlifted`), `TupleRep [RuntimeRep]`, `SumRep [RuntimeRep]`, `IntRep`, `Int8Rep`..`Int64Rep`, `WordRep`, `Word8Rep`..`Word64Rep`, `AddrRep`, `FloatRep`, `DoubleRep`, and `VecRep VecCount VecElem`. `Type = TYPE ('BoxedRep 'Lifted)`, `UnliftedType = TYPE ('BoxedRep 'Unlifted)`, and `ZeroBitType = TYPE ('TupleRep '[])`.
   - **Backend primitive layout (`compiler/GHC/Core/TyCon.hs:1788-1880`, `compiler/GHC/Types/RepType.hs:189-190, 525-571`):** `runtimeRepPrimRep` flattens a type-level `RuntimeRep` into `[PrimRep]` (`isZeroBitTy = null . typePrimRep`, `RepType.hs:190`). `isGcPtrRep (BoxedRep _) = True; isGcPtrRep _ = False` (`TyCon.hs:1877-1879`) directly tells the STG/Cmm code generator and garbage collector which register/stack/closure slots are heap pointers vs. raw bit-pattern immediates! Notice `AddrRep` is explicitly documented (`TyCon.hs:1801`) as `"A pointer, but /not/ to a Haskell value"` (`isGcPtrRep AddrRep = False`), distinguishing raw foreign addresses from GC-managed heap objects.
   - **Core Lint enforcement (`compiler/GHC/Core/Lint.hs:1463-1470, 1839-1842`):** Both `lintValArg` (at every function application argument) and `lintIdBndr` (at every non-join binder) verify `typeHasFixedRuntimeRep`, statically guaranteeing that no value with an abstract `r :: RuntimeRep` is ever moved into a register or stack slot without knowing its exact bit width and GC-pointer status.
3. **C# / ECMA-335 Ref-Safety (`dotnet/csharplang` @ `fad8344d2d115bed96c5e559c1f281bfc49f4d6a`):**
   - **Three-tier value/storage classification:**
     1. *Plain value types (`struct`, primitives):* stored inline in registers/stack/enclosing objects, `0`-byte GC header, freely copyable by value, always `safe-context = caller-context` (`low-level-struct-improvements.md:267`: `"a non ref struct is always safe to return"`).
     2. *Reference types (`class`, arrays):* GC-heap allocated, `ref-safe-context` of any field `ref e.F` is `caller-context` (`low-level-struct-improvements.md:144`).
     3. *Stack-only ref-like types (`ref struct`, marked with `[IsRefLikeAttribute]` + legacy `[Obsolete]` guard, `span-safety.md:39-56`):* allowed to embed `ELEMENT_TYPE_BYREF` (`ref`) fields (`low-level-struct-improvements.md:72`), forbidden from boxing, heap fields, arrays, lambdas, iterators, and async state machines (`span-safety.md:30`), and governed by two interacting contexts—**`ref-safe-context`** (lifetime of the *location* referenced by a `ref`) and **`safe-context`** (lifetime of the *value/ref-fields* held inside a `ref struct`), maintaining the invariant `ref-safe-context ≤ safe-context` (`low-level-struct-improvements.md:212`) across the 4-point order `declaration-block < function-member < return-only < caller-context` (`10, 341-345`)!
   - **`scoped` unifies `this` and non-escaping borrows (`low-level-struct-improvements.md:203-267`):** Applying `scoped` restricts `ref-safe-context` (on a `ref`) or `safe-context` (on a `ref struct`) to `function-member`, allowing `struct`'s `this` parameter to be modeled uniformly as `scoped ref T` (`line 237`) rather than a special-cased rule! Meanwhile, `default`-initialized `ref struct`s yield `null` `ref` fields (`lines 74-103`), requiring explicit `Unsafe.IsNullRef` runtime guards.

Basis: normative + documentation + source (`Reinking et al. PLDI 2021`, `Lorenzen & Leijen ICFP 2022`, `Lorenzen et al. ICFP 2023`, `Xhebraj et al. ECOOP 2022`, `kklib.h`)

(2016) achieved near-zero runtime overhead for statically checked non-escaping capabilities/closures on the JVM (`scala-escape` plugin); Xhebraj et al. ### 5. Human Comprehensibility and Conceptual Simplicity / Model Refinement (`C1–C2`)

Basis: source + normative + derived

#### 5.1 Human Comprehensibility & Mental-Model Ergonomics (`C1`)

- **Hidden Footguns and Local vs. Nonlocal Reasoning:**
  - **Perceus / `fip` (`koka`):** Writing pure functional code with automatic Perceus RC gives the lowest cognitive load for correctness—until a programmer relies on `fip(0)` for hard bounded-space guarantees. At that point, **dynamic sharing becomes a silent performance/space cliff**: `CheckFBIP.hs` checks static linearity *inside* the function body, NOT whether an external caller passed a shared (`rc > 0`) argument, and explicitly ignores big-integer allocation (`CheckFBIP.hs:257`)! A human auditing a `fip(0)` signature can easily misread it as an unconditional zero-allocation guarantee when it is actually conditional on caller uniqueness and fixed-width integers.
  - **C# `ref struct` + `scoped` (`dotnet/csharplang`):** The 4-level safe-context lattice (`declaration-block`, `function-member`, `return-only`, `caller-context`) plus the interaction between *two* lifetimes (`ref-safe-context` vs. `safe-context`), four `readonly`/`ref` field modifier combinations (`ref`, `readonly ref`, `ref readonly`, `readonly ref readonly`, `low-level-struct-improvements.md:105-128`), and `default`-null `ref` fields (`lines 74-86`) creates a high working-memory load (`low-level-struct-improvements.md` spends `580` lines in `Examples and Notes` explaining subtle traps like `"Preventing tricky ref assignment from readonly mutation"` and `"Silly cyclic assignment"`!). Crucially, however, making the rules **declaration-based and intra-procedural** keeps error diagnostics strictly local to one method.
  - **GHC Levity Polymorphism (`ghc/ghc`):** Keeping unboxed primitives distinct via `TYPE r` prevents silent boxing/allocation footguns, but leaks backend calling-convention constraints (`"Binder does not have a fixed runtime representation"`, `Lint.hs:1841`) directly into user-facing type errors whenever a programmer abstracts over `TYPE r` carelessly.
  - **Second-Class Values (`scala-escape` / ECOOP 2022):** The mental model ("`@local` values cannot escape their scope") is crisp and intuitive for `STLC 1/2`, with minimal surface concepts (`First` vs. `Second`). In ECOOP 2022's delayed-popping extension, stack growth across chains of stack-returning calls becomes a **nonlocal space-reasoning burden** unless developers know where the next enclosing first-class return boundary sits.

#### 5.2 Conceptual Simplicity, Orthogonality & Universal Model Refinement (`C2`)

- **Core Semantic Invariant vs. Realization-Medium Quirks:**
  - Separating **by-value immediates** (immutable bit patterns copied freely into registers with `0` runtime metadata and no addressable identity) from **addressed storage capabilities** (identifiable mutable or shared regions with lifetime/aliasing/reclamation obligations) is **not** an accidental artifact of x86 or JVM hardware—it reflects an irreducible semantic split between *values without store identity* and *locations with store identity*.
  - By contrast, several features in production systems *are* realization-medium quirks rather than core invariants:
    - Koka's 10-bit-exponent `double` squeezing (`KK_BOX_DOUBLE64 = 1`, `box.h:32-44`) and `_field_idx` overloading (stackless free cursor + constructor context path + atomic lazy sentinel `0xFF`, `kklib.h:124-138`) are C/64-bit micro-optimizations.
    - C#'s `[Obsolete]` metadata attribute hack (`span-safety.md:45-56`) and `default`-null `ref` fields (`low-level-struct-improvements.md:74-86`) are backward-compatibility artifacts of ECMA-335/CLR.
    - GHC's separation of `BoxedRep Lifted` vs. `BoxedRep Unlifted` is specific to call-by-need laziness (a strict language needs only boxed-pointer vs. unboxed-immediate representations).
- **Minimal Universal Abstraction (Ousterhout Deep-Module & Felleisen Test):**
  - Downen et al.'s *"Kinds Are Calling Conventions"* (ICFP 2020) identifies the cleanest minimal model: classify every type by a **representation/calling-convention kind** (`Immediate(bits)` vs. `Addressed(cap/region)`), rather than trying to fake immediates via heap capabilities or sprinkling ad-hoc `isValueType`/`IsRefLike`/`First|Second` checks across compiler passes. Notice that unifying `this` via `scoped ref T` in C# 11 (`low-level-struct-improvements.md:237`) is an exact real-world example of Ousterhout model refinement—deleting a special-case rule by expressing it cleanly in the underlying lifetime lattice.

### 6. End-to-End Solution & Implementation Validation (`V1–V4`)

Basis: source + normative + documentation

- **V1 (Specification Adequacy, Mutation & Non-Vacuity Validation):**

Validating that an `fip(0)` function truly performs zero allocations requires runtime allocator-counter assertions (e.g., hooking `kk_malloc` / mimalloc allocation counters during execution), not static `CheckFBIP` alone!

## Boundaries

- **Live Compiler Execution Benchmarks (`not examined`):** Local execution of `koka`, `ghc`, `scalac`, `dotnet`, or `coqc` was not performed on this host; all empirical throughput and RSS numbers (`~10%` of C++, `2.41×`, `> 40%` RSS reduction, `10–25%` delayed-pop speedup) come directly from the cited peer-reviewed papers (PLDI 2021, ICFP 2022, ECOOP 2022, ICFP 2023), while exact header layouts (`64`-bit `kk_header_t`, `1`-bit `kk_box_t` LSB tag) and LoC metrics come from direct inspection of pinned upstream source files.

- **Non-Exhaustiveness of Informal Separation Arguments (`unknown`):** While none of the four examined published mechanisms (Perceus reuse, `FP²`, second-class stack values, GHC representation kinds) macro-expresses an immediate value inside a pure region-addressed capability calculus without adding a new reduction rule, runtime metadata/storage class, or second sort, this report does **not** supply a mechanized meta-theorem quantifying over *all possible* translations into arbitrary region calculi (cf. Felleisen's negative expressibility proofs, which require fixing an exact formal base calculus $\mathcal{L}_0$ and proving a representation-preserving contextual-equivalence obstruction).
- **C# 13 `allows ref struct` Generic Anti-Constraint (`not examined`):** `proposals/csharp-13.0/allows-ref-struct.md` was not present at that path in `dotnet/csharplang` @ `fad8344d2d115bed96c5e559c1f281bfc49f4d6a`; findings cover C# 7.2 (`span-safety.md`) and C# 11 (`low-level-struct-improvements.md`).
