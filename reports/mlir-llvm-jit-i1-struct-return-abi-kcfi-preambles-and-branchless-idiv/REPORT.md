# MLIR/LLVM JIT `{i64, i1}` Struct-Return UB, Zero-Waiver KCFI Preambles, Branchless `#DE`-Free Division, and Two-Tier Verified JIT Sealing

## Summary

Calling MLIR- or LLVM-generated x86-64 query kernels from verified Rust exposes three concrete ABI, control-flow-integrity, and hardware-exception hazards on `x86_64-unknown-linux-gnu`, all reproducible on silicon and preventable by a single narrow runtime sealing boundary:

1. **SysV AMD64 `{i64, i1}` struct-return Rust `bool` UB:** In LLVM (`llc 21.1.8 -O2`), returning `{ i64, i1 }` produced by `trunc i64 %flags to i1` copies `%rsi` to `%rdx` and returns without masking bits `[7:1]` of `%dl` (`movq %rsi, %rdx; leaq 10(%rdi), %rax; retq`). When Rust (`rustc 1.102.0-nightly -Copt-level=2`) receives that return as `#[repr(C)] struct NullableI64 { val: i64, is_null: bool }` (which lowers `bool` with `range(i8 0, 2)` validity metadata) and `%rsi = 2`, a single returned struct simultaneously evaluates `if r.is_null` as `2` (`zext %dl`), `if !r.is_null` as `1` (`(~2) & 1`), and volatile `Some(r).is_none()` as `true` (`1`, because `2` collides with `Option<NullableI64>::None`'s niche value). Widening the LLVM return field to `{ i64, i8 }` with `zext i1 %bit to i8` forces `andb $1, %dl` and restores `(0, 1, 0)`.
2. **Zero-waiver `-Zsanitizer=kcfi` indirect calls into W^X JIT pages:** `rustc -Zsanitizer=kcfi` checks the 32-bit little-endian `xxh64(seed = 0, mangled_itanium_typeid) as u32` tag at `[entry - 4 .. entry)` before every indirect call (`mov -<tag>, %r10d; add -4(%r11), %r10d; je +2; ud2`), faulting with `SIGILL` (`4`) on untagged C++ `mlir::ExecutionEngine` buffers. Allocating a private `PROT_READ | PROT_WRITE` buffer, writing `[0x90; 11] ++ [0xb8] ++ le32(tag)` at `[base .. base + 16)` and kernel machine code at `entry = base + 16`, and flipping permissions via `mprotect(PROT_READ | PROT_EXEC)` passes KCFI natively (`rc = 0`) with zero `#[no_sanitize(cfi)]` waivers. Under Itanium substitution numbering, a non-`void` return type registers `S_` before parameter types are scanned: `extern "C" fn(*const i64, *const i64, *mut i64, usize)` mangles as `_ZTSFvPKu3i64S1_PS_u5usizeE` (`0x1b4623d2`), whereas `extern "C" fn(*const i64, *const i64) -> i64` mangles as `_ZTSFu3i64PKS_S1_E` (`0xb11990e8`).
3. **Speculative `idiv` `#DE` (`SIGFPE`) and error-channel gating:** Unmasked x86-64 `cqo; idiv` over dead or SQL `NULL` columnar lanes traps in hardware with `#DE` (`SIGFPE = 8`) whenever stale or frozen memory holds divisor `0` or `(i64::MIN, -1)`. Branchless `cmov` divisor blending to `1` whenever `!active || anyNull || den == 0 || (num == i64::MIN && den == -1)` executes trap-free on silicon (`rc = 0`) and refines SQL 64-bit integer `DIV`. Separately, fallible projection operators must remain gated behind filter evaluation (`semWhereRow`), and β-inlining a materialized subquery column into an error-catching predicate (`ISERROR` / `TRY`) is sound if and only if wrapped in an uncatchable `CheckNotError` barrier (`escapedErr`) so outer subquery failures are not swallowed.
4. **Two-tier verified JIT over a single `seal_x86_64_kernel<Sig>` TCB:** Static Rust MIR capture (`joshlf/anneal`) cannot verify runtime-generated bytes without an explicit execution primitive, while raw FFI to C++ `mlir::ExecutionEngine` imports ~3M LoC into the TCB. A small TCB sealer over fixed x86-64 byte semantics (`SealedJitKernel`) supports both a verified pure-Rust direct template/register compiler (Tier J1, zero runtime verifier overhead) and an optional untrusted MLIR/LLVM optimizer paired with a verified single-pass binary validator that falls back cleanly to Tier J1 on certificate rejection (`compileTwoTier_sound_and_kcfi_safe`).

## Findings

### 1. SysV AMD64 `{i64, i1}` Struct-Return High-Bit Poison vs. Rust `bool` Validity and `Option` Niche Layout

`Basis: source + execution + formal`

MLIR scalar/row dialects commonly represent nullable scalar values as two-element structs `(T, i1)` and lower them to LLVM IR `{ i64, i1 }`. On `x86_64-unknown-linux-gnu`, `llc -O2` (`Debian LLVM 21.1.8`) compiles `support/abi_trunc.ll` into markedly different instructions depending on whether the second field is `i1` or `i8`:

```llvm
define { i64, i1 } @mlir_trunc_ret_i1(i64 %a, i64 %flags) {
  %v = add i64 %a, 10
  %bit = trunc i64 %flags to i1
  %r0 = insertvalue { i64, i1 } poison, i64 %v, 0
  %r1 = insertvalue { i64, i1 } %r0, i1 %bit, 1
  ret { i64, i1 } %r1
}

define { i64, i8 } @mlir_ext_ret_i8(i64 %a, i64 %flags) {
  %v = add i64 %a, 10
  %bit = trunc i64 %flags to i1
  %ext = zext i1 %bit to i8
  %r0 = insertvalue { i64, i8 } poison, i64 %v, 0
  %r1 = insertvalue { i64, i8 } %r0, i8 %ext, 1
  ret { i64, i8 } %r1
}
```

In x86-64 assembly (`llc -O2` on `support/abi_trunc.ll`):
- `mlir_trunc_ret_i1` emits `movq %rsi, %rdx; leaq 10(%rdi), %rax; retq`—leaving bits `[7:1]` of `%dl` unmasked because LLVM's internal x86-64 `i1` return convention treats upper bits of `%dl` as undefined.
- `mlir_ext_ret_i8` emits `movq %rsi, %rdx; leaq 10(%rdi), %rax; andb $1, %dl; retq`—explicitly clearing bits `[7:1]`.

On the caller side, `rustc` lowers `bool` fields inside `#[repr(C)] pub struct NullableI64 { pub val: i64, pub is_null: bool }` as `i8` annotated with `range(i8 0, 2)` validity metadata, and exploits niche values `2..=255` in `is_null` to represent `Option<NullableI64>::None` without extra size (`size_of::<Option<NullableI64>>() == 16`, niche tag `2` for `None`). Calling `mlir_trunc_ret_i1(32, 2)` from `rustc 1.102.0-nightly -Copt-level=2` (`support/probe_kcfi_abi_idiv.rs`) produces `0x00020101` (`(t, f, some_is_none) = (2, 1, 1)`):
- `if black_box(r.is_null) { t += 1; }` folds the branch into `movzbl %dl, %eax` (`t = 2` from a `+= 1` increment!);
- `if black_box(!r.is_null) { f += 1; }` flips bit `0` (`(~2) & 1 == 1`), so both `r.is_null` and `!r.is_null` execute their `true` effects on the same struct value;
- `write_volatile(&mut slot, Some(r)); read_volatile(&slot).is_none()` returns `true` (`1`), silently turning `Some(r)` into `None` because byte `2` matches the `None` discriminant niche!

Calling `mlir_ext_ret_i8(32, 2)` produces `0x00000100` (`(t, f, some_is_none) = (0, 1, 0)`). Any C/JIT kernel boundary interfacing with Rust must either pass `u8` (`0` / `1` masked via `zext i1 ... to i8`) or packed `u64` validity bitmasks—never raw LLVM `i1` struct fields (`llvmTruncRetDl_violates_rustBool_on_2` and `llvmZextRetDl_always_valid` in `support/ColumnarJitBoundary.lean`).

### 2. MLIR `StridedMemRefType<T, 1>` Layout and Zero-Waiver `-Zsanitizer=kcfi` W^X JIT Preambles

`Basis: source + execution`

In `llvm/llvm-project@faf262703dfc53f2fc7a877c32a1ba8c462ed343` (`mlir/include/mlir/ExecutionEngine/CRunnerUtils.h:131-137`), MLIR's `convert-func-to-llvm` pass lowers ranked `memref<...xT>` arguments to `StridedMemRefType<T, N>`:

```cpp
template <typename T, int N>
struct StridedMemRefType {
  T *basePtr;
  T *data;
  int64_t offset;
  int64_t sizes[N];
  int64_t strides[N];
};
```

For rank-1 columnar buffers (`N = 1`), this 40-byte descriptor (`5 × 8` bytes; passed on the stack in SysV AMD64 unless unpacked into 5 scalar registers by bare-pointer or C-wrapper conventions) separates allocation base (`basePtr`) from aligned slice payload (`data + offset`). Passing a flat `#[repr(C)]` batch-context pointer (`extern "C" fn(*const BatchCtx) -> u32`) avoids the 5-argument per-column register pressure while keeping a single stable C function signature per kernel arity.

When the host Rust crate compiles under `-Zsanitizer=kcfi` (`rustc 1.102.0-nightly`), every indirect call to `unsafe extern "C" fn(...)` loads the 4-byte tag immediately preceding the callee entry address (`[entry - 4 .. entry)`) and executes `ud2` (`SIGILL`, signal `4`) on mismatch. `rustc` computes the tag as the low 32 bits of `xxHash64(seed = 0, mangled_typeid)` over the Itanium C++ ABI typeinfo-name (`_ZTSF...E`) using Rust's vendor-extended primitive encodings (`u3i64`, `u5usize`, etc.). Two structural details govern JIT preamble synthesis (`support/probe_kcfi_abi_idiv.rs`):

1. **Itanium return-type substitution numbering:** In `_ZTSF<ret><args...>E`, a non-builtin vendor-extended return type such as `u3i64` (`i64`) is itself registered as substitution `S_` (`0`) *before* parameter types are encoded, whereas `v` (`void` / `()`) is builtin and registers no substitution:
   - `unsafe extern "C" fn(*const i64, *const i64, *mut i64, usize)` encodes `u3i64` -> `S_`, `Ku3i64` -> `S0_`, `PKu3i64` -> `S1_`, yielding `_ZTSFvPKu3i64S1_PS_u5usizeE` with `xxh64_seed0(...) as u32 == 0x1b4623d2` (verified identical to `rustc`'s emitted preamble on `ref_batch`).
   - `unsafe extern "C" fn(*const i64, *const i64) -> i64` registers return type `u3i64` as `S_`, `KS_` as `S0_`, and first parameter `PKS_` as `S1_`, yielding `_ZTSFu3i64PKS_S1_E` with `xxh64_seed0(...) as u32 == 0xb11990e8` (verified identical to `rustc`'s emitted preamble on `ref_div`). Computing `_ZTSFu3i64PKu3i64S1_E` without substituting `S_` for `u3i64` produces the wrong hash and traps with `SIGILL`.
2. **16-byte aligned W^X preamble layout:** Allocating an anonymous private page (`mmap(..., PROT_READ | PROT_WRITE, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0)`), writing 11 `NOP` bytes (`0x90`) at `[base .. base + 11)`, opcode `0xb8` (`mov eax, imm32`, matching LLVM's `X86AsmPrinter::emitKCFITypeId`) at `base + 11`, the 4 little-endian tag bytes at `[base + 12 .. base + 16)`, copying kernel machine code to `entry = base + 16`, and transitioning to `PROT_READ | PROT_EXEC` via `mprotect` satisfies `-Zsanitizer=kcfi` (`kcfi_tagged_call_sum = 0x0000002a`, `rc = 0`) while rejecting a 1-bit corrupted tag `tag ^ 1` with `SIGILL` (`0x00000004`).

### 3. Branchless `#DE`-Free Division, Filter-Before-Projection Gating, and Two-Channel `ISERROR` / `CheckNotError` Inlining

`Basis: execution + formal`

Vectorized and branchless columnar kernels frequently evaluate arithmetic over full batches where inactive or SQL `NULL` rows contain arbitrary initialized slack values (`llvm.freeze` over recycled buffers). On x86-64, signed 64-bit `cqo; idiv r/m64` raises an uncatchable hardware `#DE` fault (`SIGFPE = 8`) both when `divisor == 0` and when `dividend == i64::MIN && divisor == -1`—irrespective of whether downstream select masks discard the lane's quotient (`raw_idiv_div0_sig = 0x00000008` and `raw_idiv_min_neg1_sig = 0x00000008` in `support/probe_kcfi_abi_idiv.rs`).

Blending the hardware divisor to `1` via branchless `cmove`/`cmovne` (`blended_idiv` in `support/probe_kcfi_abi_idiv.rs`, 52 bytes / 16 x86-64 instructions, zero conditional jumps) executes trap-free on `(42, 0)` (`0x0000002a`), `(i64::MIN, -1)` (`0x00000000` low 32 bits of `i64::MIN`), and `(42, 6)` (`0x00000007`). In `support/ColumnarJitBoundary.lean`:
- `execBranchlessDivLane_never_traps` proves `(execBranchlessDivLane laneActive x y).trapped = false` for all `laneActive : Bool` and `x y : RawCell` (arbitrary payloads, including `0` and `intMin64`).
- `execBranchlessDivLane_refines_sqlDiv` proves that on active lanes (`laneActive = true`), `execBranchlessDivLane` matches SQL 64-bit integer `DIV` on `isNull` (where `NULL` inputs suppress arithmetic errors: `NULL / 0` yields `NULL`, not `divByZero`), `err` (`divByZero` vs. `overflow` vs. `none`), and exact truncating quotient `quot` whenever `isNull = false ∧ err = .none`.
- `hoistedFallibleOp_leaks_error_on_filtered_row` proves that hoisting `100 / col_1` outside a row filter `col_0 > 0` turns a valid `err = .none` batch (`col_0 = 0, col_1 = 0`) into a spurious `divByZero` abort.
- `naiveSubqueryInline_swallows_error` and `checkNotErrInline_preserves_subquery_abort` formalize the two-channel error distinction required when β-reducing materialized scalar/table subqueries into error-catching expressions (`ISERROR(subq_col + 2)`): `ISERROR` catches `catchableErr` (`divByZero` -> `true`) while propagating `escapedErr`. Naive substitution `ISERROR((1 / 0) + 2)` swallows the subquery's error and returns `val = 1, totalErr = .none`, whereas wrapping the inlined subquery expression in `.checkNotErr` promotes `catchableErr` into `escapedErr` (`totalErr = .divByZero`) while preserving exact column-reference equivalence on error-free rows (`checkNotErr_materialized_col0_equiv`).

### 4. Minimal `seal_x86_64_kernel<Sig>` TCB and Two-Tier Verified JIT Composition

`Basis: source + formal + derived`

In `joshlf/anneal@c131b320eeeb26ef692e5afd5ec8db49ee518613` (`docs/trust-model.md`, `trusted/lean/Trusted/MirSemantics.lean`), static MIR verification proves properties of compiled Rust functions prior to execution and preserves Statement-Origin Separation (theorem statements reference only `Init.*` and `Trusted.*`). Supporting runtime-compiled native query kernels without importing LLVM/MLIR into the TCB requires adding a single runtime sealing boundary `seal_x86_64_kernel<Sig : JitAbiSignature>(code_bytes: &[u8]) -> Result<SealedKernel<Sig>, JitError>` whose TCB specification over fixed x86-64 machine-code semantics enforces eight invariants:

1. **Statement-Origin Separation:** Theorem obligations quantify over a fixed `Trusted` x86-64 decoder/operational semantics, never user-supplied `Anneal.*` proof helpers.
2. **Decode and control-flow containment:** Every reachable instruction offset in `[0, code_bytes.len())` decodes cleanly, branch targets land on verified instruction boundaries within `[0, code_bytes.len())`, indirect jumps/calls and syscalls are rejected, and backward branches carry a bounded loop trip-count fuel.
3. **Signature-bound KCFI/CET header:** The sealer itself synthesizes `Sig::KCFI_TYPEID` into `[base + 12 .. base + 16)` (and `endbr64` at `base + 16` when CET IBT is active) so untrusted `code_bytes` cannot forge a tag.
4. **SysV AMD64 ABI & return bit-validity:** `rbx`, `rbp`, `r12`–`r15`, `rsp + 8`, `DF = 0`, and `MXCSR` control bits are preserved on exit, and sub-word/aggregate return registers satisfy Rust bit-validity (`0 | 1` for `bool`, eliminating the `{i64, i1}` hazard).
5. **Memory framing:** Reads stay within bounds of input column descriptors in `BatchCtx`; writes stay strictly within disjoint mutable output column slices.
6. **Anti-TOCTOU W^X & RAII lifetime:** `code_bytes` is copied into a private anonymous `RW` buffer *before* validation or derived from verified pure-Rust emission, flipped once via `mprotect(PROT_READ | PROT_EXEC)`, and invoked only via `SealedKernel::call(&self, ...)` so `Drop` (`munmap`) cannot race with in-flight calls.
7. **CPUID / XCR0 gating:** Vector extensions (such as AVX2/BMI2) are checked once at seal time against hardware `CPUID` and OS `XGETBV` (`XCR0.SSE | XCR0.AVX`).
8. **Cross-core I-cache serialization:** Sealing executes `membarrier(MEMBARRIER_CMD_PRIVATE_EXPEDITED_SYNC_CORE)` before publishing `&SealedKernel<Sig>` across worker threads (`Arc`).

Above this single TCB primitive (`sealKernelTcb` in `support/ColumnarJitBoundary.lean`), two compilation tiers compose cleanly via `compileTwoTier`:
- **Tier J1 (Verified Direct Compiler):** A pure-Rust expression-to-x86-64/AVX2 compiler verified once via Anneal MIR capture to satisfy `∀ b, isaDecodeExec (tier1 b_ir) b = some (spec b_ir b)` with zero runtime validator overhead and microsecond compile latency.
- **Tier J2 (Certifying Optimizer Fallback):** An optional untrusted MLIR/LLVM `-O3` backend emitting candidate machine code `optCode` inspected by a verified single-pass binary checker `certCheck`; on any unproved optimization or corrupted lowering, `compileTwoTier` falls back deterministically to Tier J1 (`compileTwoTier_sound_and_kcfi_safe` and concrete witness `concrete_twoTier_corruptOpt_rejected_and_falls_back`).

## Boundaries

- **Known not to apply (Windows x64 and AArch64 PCS return conventions):** The `{i64, i1}` `%dl` register-pair assembly (`movq %rsi, %rdx`) is specific to the System V AMD64 two-eightbyte struct return rule; Windows x64 returns 16-byte non-scalar structs via hidden pointer (`rcx`), and AArch64 PCS uses `x0`/`x1` with target-specific `i1` lowering. However, Rust's `bool` `0..=1` bit-validity rule applies across all targets.
- **Not examined (`-Zsanitizer=cfi` LLVM LTO CFI vs. `-Zsanitizer=kcfi`):** Silicon execution tested `-Zsanitizer=kcfi` (kernel/operand-bundle hash preambles at `entry - 4`), not jump-table `-Zsanitizer=cfi` (which requires cross-language LTO jump tables incompatible with dynamic `mmap` code generation).
- **Not examined (hardware CET IBT `ENDBR64` enforcement):** The probe host did not enforce user-space Intel CET Indirect Branch Tracking (`ENDBR64` `f3 0f 1e fa` at `entry`); on CET-enforced Linux kernels, `entry = base + 16` must begin with `f3 0f 1e fa` immediately after the 16-byte KCFI preamble.
- **Unsupported in `joshlf/anneal@c131b320eeeb26ef692e5afd5ec8db49ee518613` without extension:** Anneal's current `Trusted/MirSemantics.lean` has no runtime `seal_x86_64_kernel` primitive yet; `SealedJitKernel` in `support/ColumnarJitBoundary.lean` mechanizes the exact architectural contract and soundness composition for that extension.
- **Attractive stronger conclusion not established:** Passing KCFI preamble checks (`rc = 0`) proves only that the indirect call target carries the expected 32-bit signature hash on an executable page—it does *not* validate the body's memory safety or ABI preservation, which still require either Tier J1 compiler verification or Tier J2 binary validation.
