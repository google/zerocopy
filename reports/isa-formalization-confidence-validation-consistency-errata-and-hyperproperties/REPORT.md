# ISA Formalization Confidence: Specification Validation, Silicon Alignment, Self-Consistency, Bug Hunting, and Security Hyperproperties

*Authored by an AI agent acting on joshlf's behalf.*

## Summary

Formal verification against an Instruction Set Architecture (ISA) specification shifts trust from the verified software or microarchitecture into the ISA model itself. Building confidence in a formal ISA specification requires five distinct assurance pillars that do not substitute for one another:

1. **Alignment with non-formal specifications:** Only WebAssembly (`SpecTec`), Arm instruction pseudocode (`AArchMRS`/ASL, excluding English prose macro-invariants), and RISC-V (`sail-riscv`, alongside `riscv-unified-db` schema efforts) provide machine-readable primary sources; x86-64 has no single formal authoritative manual, requiring multi-oracle triangulation across decoding tables (`XED`), independent semantics (`x86isa`, `s2n-bignum`), and hardware probes.
2. **Alignment with real silicon:** Functional user-mode emulators silence critical hardware realities: a direct probe on `GenuineIntel` Family `6` Model `106` Stepping `6` shows `qemu-x86_64 11.1.2` (`-cpu max`) replacing `RCPSS(3.0f) = 0x3eaaa000` with exact IEEE division `0x3eaaaaab` and raising `SIGILL` on EVEX `VRCP14SS`, while single-threaded emulators hide weak memory relaxations and vendor manuals mark inputs like `BSF(0)` as undefined where physical Intel hardware preserves the destination register (`0xdeadbeef`). Sound ISA models must therefore use relational, one-way hardware-to-spec refinement (`I_hw ⊆ I_spec`) over explicit nondeterminism/undefinedness sets rather than symmetric equality or over-narrow determinism.
3. **Internal consistency, totality, and anti-vacuity:** Gödel's Second Incompleteness Theorem (`G2`) does *not* bar proving consistency, totality, or model existence of an object-level ISA model inside Lean 4 (`CIC + propext + Quot.sound + Classical.choice`), because Lean's metatheory sits strictly above the object ISA. Real consistency failures stem from unverified `extern`/`axiom` seams, `@[implemented_by]`/`native_decide`/`ofReduceBool` kernel bypasses, empty-choice vacuity (`select {}`), non-total decoders, and statement-cone spoofing—all addressed by kernel replay (`Lean.replay`), total 4-way step outcomes, decoder uniqueness theorems, positive witness canaries, and transitive cone verification.
4. **Inverting ISA specs to find silicon and microarchitectural bugs:** Formal specs regularly uncover real hardware and assembler/linker defects across three distinct regimes: pre-silicon RTL bounded model checking (`ISA-Formal`, `riscv-formal`, `CheckMate`), post-silicon architectural spec-vs-CPU fuzzing (`Sandsifter`, `Rosenbridge`, `SiliFuzz`, `GhostWrite`, `Cascade`), and microarchitectural leakage fuzzing (`Revizor`, `SpecDoctor`, `Osiris`, `Absynthe`). Conversely, verified software remains exposed to post-compilation errata mutations (`SKX102`, Cortex-A53 `835769`/`843419`) unless checked by a decidable post-link byte validator.
5. **Security hyperproperties vs. functional ISA semantics:** Functional correctness is a 1-safety trace property; constant-time noninterference is a 2-safety hyperproperty that fails under arbitrary refinement of architectural nondeterminism (McLean's refinement paradox). Guaranteeing side-channel freedom requires augmenting the functional transition relation with an explicit hardware-software leakage contract checked against lowered machine code, qualified by hardware mode preconditions (`FEAT_DIT`, `DOITM`, `Zkt`) and bounded against known data-predictor (`GoFetch`, `SLAP`, `FLOP`), misaligned-access (`UPEC-DIT`), DVFS (`Hertzbleed`), and physical/fault exclusions.

## Applicability

This synthesis applies when designing, importing, auditing, or scoping formal ISA models and target-machine verification boundaries—specifically in proof assistants such as Lean 4, Rocq, HOL4, Isabelle/HOL, and ACL2—where high-assurance systems code, compilers, cryptographic kernels, or verification frameworks (such as `google/zerocopy`'s `anneal/` architecture) must justify why theorems proved against a formal ISA specification carry weight on real processors and satisfy non-functional assurance claims. It applies across Armv8/v9 (`AArch64`), `x86-64` / `i386`, `RISC-V`, and `WebAssembly` targets.

It does *not* provide an end-to-end equivalence proof between a specific silicon mask stepping and any Lean model, nor does it establish physical fault-resistance or electromagnetic security without dedicated netlist/physical evaluation.

## Findings

### 1. Alignment with Non-Formal Specifications and Prose-vs-Formal Drift

- **Asymmetry of authoritative sources across architectures:**
  - **WebAssembly (`SpecTec`):** Eliminates manual-to-formal drift by authoring one declarative single source of truth (`SpecTec`, PLDI 2024) that generates both typeset specification rules and executable interpreters passing `100%` of the official Wasm 2.0 test suites while surfacing historical bugs and proposal errors; `P4-SpecTec` extends this pattern to executable type checking. However, external implementations can still diverge from the relational spec (for example, reference interpreter `eval_vec.ml` collapsing nondeterministic `relaxed-simd` lane choices into one fixed implementation).
  - **Arm (`AArchMRS` / ASL / `sail-arm` / `LNSym`):** Arm provides machine-readable ASL inside XML packs (`mra_tools`, ASLv0/ASLv1, and BSD-3-Clause-Clear `sail-arm` for Armv9.4-A at `464,212` LOC covering `100%` of `94` Rust AArch64 features). Nevertheless, English prose outside instruction ASL continues to govern macro-level security boundaries, exception priority, memory-model axioms, and `CONSTRAINED UNPREDICTABLE` / `IMPDEF` envelopes. Reid (*Who Guards the Guards?*, OOPSLA 2017) encoded high-level prose security invariants for Arm v8-M into SMT checks (Z3) against ASL and uncovered **`12` bugs (`2` security bugs)** in a heavily reviewed industrial specification. Synthesized corpus audits also document ASLv0 semantic bugs (`(a DIV b) * b -> a` unsound Z3 rule, `Formal_InOut` by-value bug fixed in ASLv1 `asllib` via `accessor_pair`/`desugar_setter`), a `sorry` fallback in `sail-arm` (`arm-v9.4-a/lean/ArmExtras.lean:18-22` because `termination_measures.sail` is `$iftarget coq`), and four bugs in native Lean `LNSym` (`LDST.mayModifiedRegs`, `BL` `x30`, fault PC increment, `+1` ELF stride).
  - **RISC-V (`sail-riscv` vs. `riscv-unified-db`):** `sail-riscv` serves as the golden executable ISA model, while `riscv/riscv-unified-db` (UDB) uses versioned JSON schemas (`inst_schema.json`, `csr_schema.json`, ~`90%` instruction coverage) to drive manuals, simulators, and compiler metadata. Because UDB currently maintains its own IDL separate from `sail-riscv`, keeping prose/JSON descriptions aligned with `sail-riscv` relies on ongoing cross-group unification (UnifiedDB SIG and Golden Model TWG). Extracted Lean artifacts carry independent translation risks: `opencompl/sail-riscv-lean` (`161` files, `173,776` LOC) introduces `75` extern `axiom`s and `2.47 GiB` peak elaboration RSS (`InstsEnd.lean` reaches `43.75 MiB`), `lean-sail`'s sequential interpreter collapses `FinChoice := 0` and ignores `8` effects, and `sail-riscv`'s `match_reservation`/`AGNOSTIC` vector tail/mask behaviors require care against under-approximation.
  - **x86-64 / i386 (No normative formal source):** `Intel SDM` (`325462`) and `AMD APM` are multi-thousand-page informal manuals with documented specification errors and vendor divergences (`SYSRET` non-canonical `#GP` privilege escalation `CVE-2012-0217`; `MOV SS`/`POP SS` `#DB` interrupt-shadow divergence `CVE-2018-8897`). Automated specification mining has directly exposed manual defects: **STRATA** (Heule et al., PLDI 2016) uncovered **`58` instruction variants** with discrepancies or bugs against the Intel SDM via stratified synthesis; **K-X86-64** (Dasgupta et al., PLDI 2019) evaluated `3,155` Haswell variants (`774` mnemonics) against `>7,000` instruction tests and GCC torture suites, revealing both Intel SDM inaccuracies and `RFLAGS` undefined-flag modeling flaws in STOKE. Consequently, x86-64 decoding trusts `intelxed/xed` (`1,995` ICLASSes, `9,149` blocks, `62` LOCKABLE instructions) while semantics must cross-check `acl2/x86isa` (`91,363` LOC), `s2n-bignum` (`163` x86 ctors, `44` `UNDEFINED_VALUES` sites, `x86_decode_unique`), and measured silicon probes rather than unmaintained (`kframework/X86-64-semantics`), incomplete (`ghidra` SLEIGH's `1,716` opaque `pcodeop`s), or impure (`sail-tiny-x86`'s RIP-relative offset bug) models.

### 2. Alignment with Real Silicon and Hardware

- **Concrete host vs. emulator divergences (`GenuineIntel` Family `6` Model `106` Stepping `6` vs. `qemu-x86_64 11.1.2`):** Direct differential execution of an inline-assembly C probe compiled with `gcc 15.2.0 -O2 -mavx512f` establishes:

  | Probe operation | Native Intel Xeon Ice Lake-SP | `qemu-x86_64 11.1.2 -cpu max` | Alignment implication |
  |---|---|---|---|
  | `bsf(0xdeadbeef, 0)` | `0xdeadbeef` | `0xdeadbeef` | Intel SDM marks `dst` Undefined; real hardware preserves `dst` (AMD-documented, stepping-sensitive if relied upon without Intel guarantee) |
  | `bsr(0xdeadbeef, 0)` | `0xdeadbeef` | `0xdeadbeef` | Same silent concrete preservation across vendor-documented Undefined case |
  | `rcpss(3.0f)` | `0x3eaaa000` | `0x3eaaaaab` | QEMU silently computes exact IEEE `1.0f / 3.0f` instead of hardware 12-bit reciprocal approximation (`2.7e-3` relative difference masked) |
  | `vrcp14ss(3.0f)` | `0x3eaaaa80` | `SIGILL` (signal `4`) | Real Ice Lake-SP executes EVEX 14-bit reciprocal approximation; QEMU `11.1.2 -cpu max` aborts with illegal instruction |

- **Why single-oracle testing fails:** Comparing a formal model only against QEMU masks floating-point approximations, instruction coverage holes (`SIGILL`), and weak memory behaviors (`2.70M` native x86 litmus runs documented in sibling corpus reports observe `495 / 300,000` `SB_Relaxed` reorderings hidden by functional emulation). Conversely, overfitting to one CPU stepping turns vendor-specific accidental outcomes (`BSF(0)` preservation) into false invariants.
- **Validation stack required for hardware alignment:**
  1. *Symbolic corner generation:* `ISLA` (`isla-footprint` for taint/register/memory footprints; `isla-axiomatic` for joint semantic + `.cat` weak-memory solving over Sail IR) and full-branch path exploration (`PokeEMU` reaching `100%` of instruction semantic branches).
  2. *RTL / ISS lock-step differential harnesses:* RISC-V combines `riscv-arch-test` (`RISCOF` / `ACT4`) directed compliance against `sail-riscv` with constrained-random generators (`riscv-dv`) and fast lock-step ISS trace checkers (`Whisper`, `Spike`).
  3. *Fleet-scale silicon proxy testing:* `SiliFuzz` ("fuzzing by proxy", `Centipede` + emulator/disassembler -> self-contained binary snaps) captures both subtle specification/emulator corner cases and real-hardware manufacturing/aging Silent Data Corruption ("mercurial cores", Hochschild et al., HotOS 2021; Dixit et al.).
  4. *One-way relational semantics:* Models must enforce **one-way refinement ($I_{\text{hw}} \subseteq I_{\text{spec}}$)** using explicit set-valued/relational post-states for hardware-legal nondeterminism (`UNDEFINED_VALUES`, `CONSTRAINED UNPREDICTABLE`, `IMPDEF`, approximate reciprocal error bounds, RISC-V `vta`/`vma` agnostic lanes, `LR/SC`), failing closed on software reliance on undefined outputs.

### 3. Internal Consistency, Totality, Non-Vacuity, and Determinism

- **Rigorous scope of Gödel's Second Incompleteness Theorem (`G2`):** By `G2` and the Hilbert-Bernays-Löb derivability conditions (`D1`–`D3`) / Montague syntactical modality barriers (`SC1`–`SC6`, which show naive internal reflection schemas collapse via diagonalization), a consistent sufficiently expressive system $T$ cannot prove its own consistency $\text{Con}(T)$. However, proving internal consistency, progress, or **model existence / relative consistency (`Lean ⊢ ∃ M, Models(M, S_ISA)`)** of an *object-level ISA specification $S_{\text{ISA}}$ inside Lean 4* completely bypasses `G2`, because Lean 4 (`CIC` + `{propext, Quot.sound, Classical.choice}`) acts as a strictly stronger metatheory exhibiting a concrete witness for $S_{\text{ISA}}$.
- **Real failure modes in proof-assistant ISA models (and exact checks):**
  - *Kernel bypasses & silent axioms:* Extern axioms (`sail-riscv-lean`'s `75` externs), `sorry` termination fallbacks (`sail-arm` `ArmExtras.lean:18-22`), `@[implemented_by]`, `@[extern]`, `@[csimp]`, `native_decide` (`Lean.ofReduceBool` — also emitted by `bv_decide`), and `Lean.trustCompiler` can trivialize proofs without visibly breaking `#print axioms` unless audited by full kernel replay. `google/zerocopy`'s `anneal/trusted/audit/TrustedBoundary.lean` enforces this via `Lean.replay` over authenticated `foundation-lock.json` (`leanprover/lean4@5045d0056413266e57c625dcd7c365b10e377c52`) and `anneal/vendor/lean-miri/UPSTREAM_PIN.json` (`proofs-rs/lean-miri@c92d1d9754c9dd585b6b9d6949ae67e5e4665d6a`, `160`-module `ExecutionMachine` closure).
  - *Vacuity collapse & inverted polarity:* Returning empty choice sets (e.g., `select {}` / `MinimalMMIO`), collapsing nondeterminism (`FinChoice := 0` in `lean-sail`), omitting effect branches, or inverting halting/non-halting polarity (`seq_nb_state` hazards) renders universal safety properties vacuously `True`. Mandatory defenses are a **total 4-way `StepOutcome`** (`.step` / `.trap` / `.halted` / `.undef`), **constructive positive-reachability witnesses** across representative instruction classes, and **negative sanity canaries** verifying defective specs fail checks.
  - *Decoder partiality & ambiguity:* Overlapping prefix encodings (`41 90` REX.B+`NOP` vs `XCHG`), `ILLEGAL` collisions (`ZICBOP`/`ORI`), or state-dependent `decode` (`sail-tiny-x86`) break uniqueness. High-assurance decoders prove totality + prefix uniqueness (`x86_decode_unique` / `list_linear_decode`) returning explicit `.illegal` faults on unallocated encodings.
  - *Statement-cone spoofing:* Traversals like `coq-dpdgraph` (`Proj` bug) or prelude name collisions can mask hidden axioms unless guarded by whole-cone semantic comparison (`leanprover/comparator`, independent checker `lean4lean`).

### 4. Inverting ISA Specs to Hunt Hardware Bugs and Handle Silicon Errata

- **Pre-silicon formal RTL equivalence (Bounded Model Checking):** Arm *ISA-Formal* (Reid, CAV 2016) compiled ASL assertions into commercial BMC over `8` Arm processor cores (including `Cortex-A53`, `A57`, `R52`), proving instruction equivalence and exposing corner-case pipeline bugs. Open-source *riscv-formal* (Wolf) uses the **RISC-V Formal Interface (RVFI)** per-cycle retirement monitor to catch illegal compressed `C`-extension decoding, CSR permission bugs, `rvfi_valid` hazard skew, and subword sign-extension defects in `PicoRV32`, `VexRiscv`, and `Ibex`. *CheckMate* (Trippel et al., MICRO 2018; building on *PipeCheck*) applies microarchitectural happens-before ($\mu$hb) graphs to verify or synthesize transient-execution PoCs.
- **Post-silicon architectural spec-vs-CPU fuzzing:**
  - *Sandsifter* (Domas, 2017) uses page-fault-bounded length probing to discover undocumented x86 instructions and decoder flaws; *Rosenbridge* (Domas, 2018) uncovered a hidden secondary coprocessor ("God Mode") gated behind undocumented VIA C3/Nehemiah instructions and MSR state.
  - *GhostWrite* (`CVE-2024-44067`): Auditing T-Head XuanTie C910/C920 vector stores against RISC-V architectural guarantees exposed `vse128.v` bypassing virtual memory translation from user space to overwrite arbitrary physical RAM (requiring RVV disablement on affected parts).
  - *RTL architectural fuzzers:* Progression from *DifuzzRTL* and *TheHuzz* to CSR-aware *ProcessorFuzz*, dynamic *MorFuzz* (USENIX Sec 2023, `17` bugs / `13` CVEs), and *Cascade* (USENIX Sec 2024, `37` bugs / `28–29` CVEs across `5` RISC-V cores via asymmetric ISA simulation entangling data and control flow) demonstrates how golden ISA execution can systematically fuzz deep pipeline control states.
- **Microarchitectural leakage fuzzing and post-link errata exposure:**
  - *Revizor* (Oleksenko et al., `microsoft/sca-fuzzer`), *SpecDoctor*, *Osiris*, and *Absynthe* invert ISA + leakage contracts or hardware contention templates to expose silicon speculative bugs including *Downfall* (`CVE-2022-40982`, Intel `gather`), *Zenbleed* (`CVE-2023-20593`, AMD Zen 2 `vzeroupper`), and *Reptar* (`CVE-2023-23583`, Intel redundant prefix state corruption), while *EntrySign* (`CVE-2024-56161`) showed compromised microcode signature checks (`RDRAND` returning `4`) breaking foundational ISA trust.
  - **Software verification boundary (`JCC` `SKX102` & `Cortex-A53` `835769`/`843419`):** Compilers and linkers rewrite machine instructions after IR/object-file emission (x86 prefix/NOP padding in `X86AsmBackend`; AArch64 linker veneers in `LLD`/`BFD`). Any source/MIR/object-level proof leaves final linked machine bytes unverified against errata unless paired with a decidable post-link errata byte validator and an explicit TCB assumption of sound microcode/silicon.

### 5. Architectural ISA Formalizations vs. Security Hyperproperties

- **1-Safety vs. 2-Safety & McLean's Refinement Paradox:** Functional ISA refinement ensures 1-safety ($\forall t \in \llbracket P \rrbracket, \phi(t)$) and preserves trace inclusion, whereas constant-time noninterference (`CTNoninterference`) is a **2-safety hyperproperty** over trace pairs ($\forall t_1, t_2, \text{lowEq}(t_1, t_2) \implies \text{leak}(t_1) = \text{leak}(t_2)$). Because hyperproperties are not downward-closed under trace refinement (McLean 1994), an architectural ISA spec that models caches or timing nondeterministically permits compliant refining implementations whose hardware or compiler choices depend on secrets—silently destroying security guarantees. As mechanized with zero axioms (`[]`) in `support/IsaConfidenceSpecCheck.lean` under pinned `Lean 4.34.1` (`mclean_paradox_refutes_same_choice_ni`), naive same-choice 2-safety (`∀ s₁ s₂ c, pub s₁ = pub s₂ → leak s₁ c = leak s₂ c`) is refuted by a refining hardware choice `c := secret`, whereas **Dual-Choice Leakage Noninterference (`DualChoiceLeakNI`: `∀ s₁ s₂ c₁ c₂`)** provably transfers deterministic noninterference to every refining hardware implementation (`hw_leak_ni_of_dualChoiceLeakNI`). Alongside this, `silicon_safe_of_hardwareRefines_and_softwareSafe`, `end_to_end_staged_isa_transfer`, and `verifyPostLinkBytes_sound` mechanize the exact quantifier polarity across Pass-1 software safety, Pass-2 staged ISA correspondence (`I_ref ⊆ I_core`), physical silicon refinement (`I_hw ⊆ I_ref`), and total post-link binary certificate validation.
- **Hardware-software leakage contracts (`Step_arch` + `Leak(s, i)`):** Practical verification factors security into (a) an augmented architectural step + leakage function (`ValNI ≺ ArchCT ≺ VarTimeCT ≺ SpecCT ≺ DmpCT` lattice), (b) RTL/silicon conformance proofs or fuzzers (`LeaVe`, `ProSpeCT`, `UPEC-DIT`, `Revizor`), and (c) 2-safety software verification against that contract (`ct-verif`, `Spectector`, `Blade`, `Jasmin` SpecCT).
- **Real-hardware gaps in ISA timing modes (`FEAT_DIT`, `DOITM`, `Zkt`):**
  1. *Instruction exemptions & RTL bugs:* Division (`UDIV`/`DIV`) and similar instructions are excluded or conditional; *UPEC-DIT* (2024–2025) formal RTL checking revealed misaligned memory accesses violating DIT guarantees on open RISC-V cores.
  2. *Data-memory prefetchers & data-flow speculation:* Apple M1/M2 Data Memory-dependent Prefetchers (DMP) ignored `PSTATE.DIT` (`Augury`, `GoFetch` USENIX Sec 2024; M3+ honors `DIT` for DMP), while 2025 *SLAP* (Load Address Predictor on M2+) and *FLOP* (Load Value Predictor on M3+) demonstrated data-flow speculation attacks bypassing type/bounds checks—with *FLOP* evaluators reporting `PSTATE.DIT` neutralizes LVP leakage (~`4.5%` browser overhead).
  3. *Physical & compiler-lowering layers:* `Hertzbleed` (`CVE-2022-23823` DVFS), hardware glitch/transition coupling (`CocoAlma`, `SILVER`), fault injection (`FIVER` SIFA), and LLVM optimizations introducing secret-dependent branches break source-level timing invariants unless verified after lowering under explicit hardware/physical boundary preconditions.

  - *Erratum qualification on sibling binary-validator report:* The sibling report `decidable-machine-code-well-formedness-and-errata-byte-validator` carries a `2026-11-20` `REFUTED` epistemic audit erratum on its Python throughput script (`validate_tier1_binaries.py` estimated instruction counts via `size // 14` outside `libcore` and hardcoded `0` violations for 6 of 8 invariants, classifying its `78.67 MB/s` / `0`-violation empirical headline as `[toy model]`). - **Unreachable / negative architectural domains:**
  - *Machine-independent ISA security proofs:* Functional ISA refinement without a specified leakage contract is **known not to apply** to constant-time or transient-execution side-channel claims due to McLean's refinement paradox.
  - *Pure source/MIR verification across errata & codegen mutations:* Source- and MIR-level proofs are **unsupported** for catching post-emission assembler/linker rewrites (`SKX102`, `A53-835769/843419`), silicon mask errata (`FDIV`, `GhostWrite`), or microcode corruption (`CVE-2024-56161`) without a post-link validator and hardware TCB assumptions.

- **Quarterly or whenever importing a new ISA target/toolchain into `google/zerocopy`'s `anneal/` boundary:**
