# Heterogeneous Model-Routing Cascades, Speculative Tool Execution, Repository-Scale API Migrations, Semantic Merge-Conflict Resolution, and Root-Cause Crash Deduplication

## Summary

Primary-source inspection of 33 peer-reviewed papers and preprints (2012–2026), line-level source audits of 19 immutable GitHub repository revisions (`lm-sys/RouteLLM`, `stanford-futuredata/FrugalGPT`, `automix-llm/automix`, `Aider-AI/aider`, `naimengye/speculative-action`, `guanyilin428/Dynamic-Speculative-Planning`, `ualberta-smr/PyMigBench`, `amazon-science/MigrationBench`, `DeepSoftwareAnalytics/RepoTransBench`, `HKU-System-Security-Lab/ConGra`, `benedikt-schesch/Merge-Bench`, `benedikt-schesch/LLMerge`, `gems-uff/sbcr_study`, `google/clusterfuzz`, `HexHive/Igor`, `squaresLab/SemanticCrashBucketing`, `akhvorov/S3M`, `ZhangShurong/rebucket`, and `Fraunhofer-AISEC/gptrace-artifacts`), and a deterministic three-probe Python 3.10+ standard-library verification suite (`support/verify_routing_migrations_merge_crash_dedup_probes.py`) establish five architectural invariants for multi-tier agent execution, multi-file migrations, conflict integration, and failure triage:

1. **Pre-Query Routing and Sequential Cascades Invert Under Out-of-Distribution Shift and Downstream Rework (`RouteLLM`, `FrugalGPT`, `AutoMix`, `Probe 1`):** Preference-trained single-call routers (`RouteLLM`, `ICLR 2025`, `arXiv:2406.18665v4`; `lm-sys/RouteLLM@0b64fdafe049`) reduce `GPT-4` calls to `13.40%` at `95%` `GPT-4` quality on in-distribution `MT-Bench` (`3.66×` lower cost relative to the random router baseline, `Table 6`), yet `D_arena`-only routers fall to near-random or worse out-of-distribution on `MMLU` (`APGR = 0.473–0.524` vs. `Random = 0.500`) and `GSM8K` (`APGR = 0.438–0.475` vs. `Random = 0.497`, `CPT(50%) = 53.59%–58.78%`) without domain-matched synthetic augmentation (`D_gold` / `D_judge`). Similarly, domain-trained cascades (`FrugalGPT`, `TMLR 2024`, `arXiv:2305.05176v1`; `stanford-futuredata/FrugalGPT@2b23e6acbd4b`) cut single-turn in-domain costs by `59.2%–98.3%`, yet drop out-of-domain to `0.0` (`Llama-2-13B`) and `14.3` (`GPT-3.5`) mean $\Delta\text{IBC}$ versus `AutoMix`'s `31.5` and `70.9` (`NeurIPS 2024`, `arXiv:2310.12963v5`; `automix-llm/automix@531af3ee3c4e`), which suppresses escalation on `HOPELESS` queries where both weak ($M_w$) and strong ($M_s$) models fail. Under monotone strong-model dominance ($P(M_w = 1, M_s = 0) = 0$) where an undetected weak-tier defect triggers downstream CI/debugging rework cost $R_c > c_s$, a pre-query router costs more than `Always-Strong` whenever
   $$R_c > R_c^{*,\text{router}} = \frac{(1 - \bar{\alpha})(c_s - c_w) - c_r}{\pi_N (1 - \alpha_N)}$$
   (`R_c^* = 8.5958 c_s` at `92.94%` pre-rework relative accuracy in `Probe 1.1`), and a sequential cascade loses unless its critic's false-negative accept rate $\beta_{\text{FN}} = P(\text{accept } M_w \mid \mathsf{NEEDY})$ satisfies
   $$\beta_{\text{FN}} < \beta_{\text{FN}}^* = \frac{\bigl[\pi_G(1 - \alpha_{\text{FA}}) + \pi_H(1 - e_H)\bigr] c_s - (c_w + c_v)}{\pi_N (R_c - c_s)}$$
   (`0.1917` under monotone thresholding vs. `0.2488` when a `POMDP` meta-verifier avoids escalating `HOPELESS` queries at $R_c = 8 c_s$ in `Probe 1.2`).
2. **Role-Split `Architect + Editor` Pipelines Outperform Query-Level Weak Routing, While Speculative Tool Execution Demands Separate Fork, Commit, and Recovery Accounting (`Aider`, `PASTE`, `TomasuLLM`, `Speculative Actions`, `DSP`, `Probe 1.4`):** Rather than routing entire coding tasks to a weak model, `Aider`'s `ArchitectCoder` (`Aider-AI/aider@5dc9490bb35f`, `aider/coders/architect_coder.py:6–48`) keeps change synthesis on a reasoning `Architect` and delegates mechanical diff formatting to a fresh-context `Editor` (`cur_messages = []`, `L38–39`). On `Aider`'s Python-only 133-task Exercism editing benchmark (`docs/benchmarks.md:83`), `o1-preview + o1-mini` lifts `pass@2` from `79.7%` (`$63.92`, `80.9 s`/case, `93.2%` well-formed) to **`85.0%` (`$36.21`, `39.7 s`/case, `100.0%` well-formed)** (`o1-preview + deepseek`: `85.0%`, `$35.3152` vs. `$63.9190`, `-44.8%`); on the 225-task polyglot benchmark, `DeepSeek-R1 + Claude 3.5 Sonnet` reaches **`64.0%` (`144/225`) at `$13.29`** vs. solo `o1` at `61.7%` (`139/224` executed cases, `24` malformed responses) and `$186.50` (**`14.03×` cost reduction, `+2.3 pp` accuracy**, though latency rises to `251.6 s`/case vs. `113.7 s` solo `R1` / `133.2 s` solo `o1`). Speculative tool execution (`PASTE`, `arXiv:2603.18897v3`: `-43.5%` completion time, `1.8×` tool speedup; `Speculative Actions`, `arXiv:2510.04371v2`: up to `55%` action accuracy and `20%` latency cut; `TomasuLLM`, `arXiv:2609.38201v2`: `47%` gross hidden serial latency / `42%` net wall-clock reduction after `~5%` speculation overhead, catching `20/20` injected hidden-dependency faults including `10/10` via read-set validator $V_{\text{dep}}$) yields net latency savings iff hit rate $h$ satisfies
   $$h > h^* = \frac{\ell_{\text{fork,crit}} + \ell_{\text{rec}}}{\Delta \ell_{\text{tool}} - \ell_{\text{commit}} + \ell_{\text{rec}}} \qquad (\Delta \ell_{\text{tool}} > \ell_{\text{fork,crit}} + \ell_{\text{commit}})$$
   raising $h^*$ for a `6.0 s` tool from `1.32%`–`7.69%` (overlapped zero-commit read-only overlay) and `8.92%`–`9.67%` (critical-path `0.08 s` CoW fork + `0.50 s` recovery/commit) to **`76.92%`–`83.33%`** on `4.50 s` private data-copy forks—and strictly unprofitable once $\ell_{\text{fork,crit}} + \ell_{\text{commit}} \ge \Delta \ell_{\text{tool}}$ (`Probe 1.4`).
3. **Function-Local AST Rewrites Collapse on Repository-Scale Library and Language Migrations (`PyMigBench`, `LLM-PyMig`, `MigrationBench`, `RepoTransBench`, `Probe 1.5`):** Across `LLM-PyMig`'s `314` evaluated Python migrations (`7` of `321` excluded for client syntax errors; `2,910` changes across `134` library pairs in `34` domains; pinned `ualberta-smr/PyMigBench@d8ffb982` is `v2.0` with `335` migrations, `3,096` changes, `141` pairs), `GPT-4o` reaches **`94%` (`1,867/1,996`) conditional per-change accuracy** on non-failed files (`64.2%` unconditional `1,867/2,910`) yet drops to **`57%` (`179/314`) strict whole-migration correctness** (`74.5%` = `234/314` including `Correct w/ non-refactorings`), with `34%` of library pairs involving higher-cardinality changes (`84%` `GPT-4o`) and `Argument transformation` lowest at `77%` (`Table III`). On `MigrationBench`'s `300`-repo `Java 8 -> 17` `selected` subset (averaging **`6.6` modules, `168.4` Java files, `110.6` tests**, vs. `2.4 / 65.1 / 34.8` in `full`; ACM SIGKDD 2026 `10.1145/3770855.3817526`), deterministic `OpenRewrite` rules reach only **`16.33%` minimal / `2.00%` maximal** (`mvn clean verify` + bytecode major `61` + direct `pom.xml` dependency-tree checks), whereas closed-loop `Claude 4.5 Sonnet` (`+PE+RAG` / `Hybrid`) reaches **`71.67%` minimal / `53.33%` maximal**. On `RepoTransBench` (`arXiv:2412.17744v2`), single-pass `TranslationOnly` scores `0.0%` `SR` on `7/8` models and **`0.2%` `SR` on `o3-mini`** (`10.9%–33.3%` `CR`, `1.5%–19.6%` `APR`), rising to **`32.8%` `SR`** for both `Claude` (`54.8%` `CR`, `44.8%` `APR`) and `GPT-4.1` (`53.3%` `CR`, `45.4%` `APR`) only under iterative `RepoTransAgent` build/test feedback (with closed-source `C->Rust` reaching `47.5%`–`67.2%`).
4. **Clean Syntax and Conflict-Marker Removal Mask High Rates of Unverified or Semantically Divergent 3-Way Merges (`Schesch et al. 2024`, `Merge-Bench`, `GitGoodBench`, `Shen 2026`, `ConGra`, `Probe 3`):** Across `5,983` Java merge scenarios (`Schesch et al.`, `ASE 2024`), structured mergers inflate silent build/test-failing ("incorrect") clean merges by **`4.10×–18.90×`** over `Git ort` (`157` = `3%`), hitting **`643` (`11%`) in `Spork`** and **`2,967` (`50%`) in `IntelliMerge`**. On `Merge-Bench` (`ICPR 2026`, `arXiv:2605.25890v1`), aggressive frontier resolvers emit marker-free code while leaving **`27.6%–35.5%` `Different code`** on Java (`Fig. 5`, `806` hunks, `51.2%–62.5%` code-normalized match incl. `LLMergeJ 14B`) and **`34.5%–42.1%` `Different code`** across all 11 languages (`Fig. 6`, `7,938` hunks, `44.8%–52.6%` match). On `ConflictBench` (`Shen`, `arXiv:2607.27674v1`), deterministic structural/AST validity hits **`95.8%` (`92/96`)** on true conflicts while a `100%`-precision, **`64.6%`-recall** (`64/181` FN) strict developer-match judge confirms `55.1%` (`OpenAI`) and `61.7%` among-resolved / `59.2%` overall (`Gemini`; `58.3%` pooled)—making the **`37.5 pp` gap an upper bound on unconfirmed or non-developer-matching structurally valid outputs** rather than a proven `37.5%` error rate. On `GitGoodBench Lite` (`120` tasks; `60` MCR), `GPT-4o` solves `21.11%` overall and only **`13.33%` MCR (`0.00%` hard)** despite `76.67%` workflow completion (`Table 2`). `Probe 3` audits live metric bugs in `ConGra@c33fc916` (`src/metrics.py` + `src/main.py:127–130` silent `-1` coercion) and demonstrates on an unweighted 14-case suite that universal AST delta-retention catches unilateral drops, partial multi-call drops, and `if`-predicate inversions, while explicit ordering false-negative controls and a synthesized-expression false-positive control prove that static AST gates must pair with two-branch executable tests.
5. **Stack-Hash Deduplication Simultaneously Over-Splits `1` Bug Into `46–6,349` Tasks and Over-Merges `16%` of Distinct Bugs, Compounded by Live Defects in `ClusterFuzz`, `S3M`, and `ZhangShurong/rebucket` (`Klees 2018`, `ReBucket`, `SCB`, `Igor`, `GPTrace`, `Probe 2`):** In `cxxfilt` (`Klees et al.`, `CCS 2018`), `57,142` (`§1`; `57,044` excluding `98` unfixed inputs in `§7`) AFL coverage-unique crashes collapsed to `9` bugs (`6,349×` / `6,339×`), while call-stack hashes still yielded `595` buckets (`66×` overall; `~46`/trial) with `~16%` cross-bug collisions masking `5` single-crash bugs. Source audit of `google/clusterfuzz@ff2e60f0` confirms three live-reachable flaws across `crash_comparer.py:72–124` and `grouper.py:389–413` (`LCS >= 2` wrapper merging, `min(len_1, len_2)` `1`-frame prefix-truncated Levenshtein merging, and `id1 > id2` order-dependent `'FuzzerHash='` asymmetry), while `akhvorov/S3M@1d16f575` (`rebucket.py:62` `+ 1` off-by-one breaking threshold calibration in *both* directions around `d = 0.490001`), `ZhangShurong/rebucket@2e6d5845` (`rebucket.cpp:63` `stack_len == 1` guard + `kThreshold = 0.06` single-pass over-splitting), and `Dang (2012)`'s own `min(n1, n2)` denominator edge (`Sim(["parse_chunk"], 3-frame) = 1.0000`) motivate max-norm IDF-weighted `ReBucket`, multi-view ASan+stack clustering (`GPTrace`, main-track `ICSE 2026`: `14` targets, `50` bugs, `327,071` traces, `98%` P / `94%` IP / `94%` F vs. `Crashwalk` `76%`, `DeFault` `82%`, `Igor` `72%`), and post-patch bucket replay (`SCB`, `ASE 2018`: `754 -> 1` AFL, `1,037 -> 2` Honggfuzz; `BCubed F1 = 1.000`, `0` masked bugs in `Probe 2`).

## Findings

### 1. Heterogeneous Model-Routing Cascades, `Architect + Editor` Decomposition, Speculative Tool Execution, and Rework Breakeven Bounds

#### 1.1 Pre-Query Preference Routers (`RouteLLM`, `Ong et al., ICLR 2025`, `arXiv:2406.18665v4`; `lm-sys/RouteLLM@0b64fdafe049`)

`Basis: source + documentation + derived`

1. **Audited Router Architectures and Calibration Mechanics (`source`):**
   - `Controller._get_routed_model_for_completion` (`routellm/controller.py:105–118`) routes **strictly on the final user message** (`messages[-1]["content"]`), invoking `Router.route(prompt, threshold, routed_pair)` (`routellm/routers/routers.py:41–45`), which selects `routed_pair.strong` iff `calculate_strong_win_rate(prompt) >= threshold`. Thresholds are quantile-calibrated offline on `lmsys/lmsys-arena-human-preference-55k` via `thresholds_df[router].quantile(q=1 - args.strong_model_pct)` (`routellm/calibrate_threshold.py:51–58`).
   - All four learned routers in `routellm/routers/routers.py` estimate $P(M_s \succ M_w \mid q)$:
     1. **Matrix Factorization (`mf`, `MatrixFactorizationRouter`, `routers.py:210–243` & `matrix_factorization/model.py:74–126`):** Embeds `num_models = 64` Arena models (`MODEL_IDS`, `model.py:6–71`) via `self.P` (L2-normalized at `L110`), projects prompt vectors through bias-free `nn.Linear(text_dim, dim)` (`self.text_proj`, `L91–93, 118`—checkpoint dimensions `dim = 128`, `text_dim = 1536` verified in HuggingFace `routellm/mf_gpt4_augmented/model.safetensors`: `P.weight [64, 128]`, `text_proj.0.weight [128, 1536]`, rather than hardcoded in `model.py`), scores bilinear Hadamard interaction `self.classifier(model_embed * prompt_embed)` (`L120`), and returns Bradley–Terry win probability $\sigma(s(M_s, q) - s(M_w, q))$ (`L123–126`).
     2. **Similarity-Weighted Elo Ranking (`sw_ranking`, `SWRankingRouter`, `routers.py:133–207` & `similarity_weighted/utils.py:14–91`):** Partitions the 64 models into `num_tiers = 10` minimum-variance Elo tiers via **$O(n^3 m)$ dynamic programming** (`compute_tiers`, `utils.py:14–51`, executing 4 nested loops `tier × i × j × l` at `L27–34`), computes cosine similarity between `text-embedding-3-small(q)` and stored Arena battle embeddings (`L190–193`), weights battles exponentially via $w_i = 10 \cdot 10^{s_i / \max_j s_j}$ (`get_weightings`, `L173–175`), fits weighted tie-split Bradley–Terry MLE via `LogisticRegression(fit_intercept=False, penalty=None)` **per request at inference time** (`compute_elo_mle_with_tie`, `L196`, driving its `2.9 req/s` throughput in `Table 7`), and returns $1 - (1 + 10^{(R_s - R_w)/400})^{-1}$ (`L202–206`).
     3. **BERT Classifier (`bert`, `BERTRouter`, `routers.py:106–131`):** Fine-tunes `bert-base-uncased` over `num_labels = 3` (`strong wins`, `tie`, `weak wins`) and returns $1 - (p_{\text{tie}} + p_{\text{weak}})$ (`L128–130`).
     4. **Causal LLM Classifier (`causal_llm`, `CausalLLMRouter`, `routers.py:51–103`):** Fine-tunes `meta-llama/Meta-Llama-3-8B` (`L60`) to emit 5 Likert tokens `[[1]]..[[5]]` (`score_threshold = 4`, `L56–57`), returning `1 - output["binary_prob"]` (defaulting fail-safe to `1` -> `strong` on malformed output, `L98–102`).

   - Routing between `gpt-4-1106-preview` (`$24.7 / 1M` blended tokens) and `mixtral-8x7b-instruct-v0.1` (`$0.24 / 1M` tokens), `RouteLLM` measures `CPT(x%)` (% strong calls needed to recover $x\%$ of the `GPT-4 - Mixtral` performance gap `PGR`) and `APGR` (area under the `PGR`-vs.-cost curve). #### 1.3 Closed-Form Downstream Rework Breakeven Laws (`Probe 1.1` & `1.2`)

`Basis: derived + execution (standalone Python 3.13 stdlib analytical phase-diagram and equilibrium verification in Probe 1.1–1.2)`

Static QA benchmarks penalize an unescalated $M_w$ error by bounded unit loss $\le 1$. In autonomous software engineering, landing a broken $M_w$ patch triggers **downstream rework** $R_c = \gamma_c c_s > c_s$ via failed CI runs, revert/bisect loops, or frontier debugging. Under monotone strong-model dominance ($P(M_w = 1, M_s = 0) = 0$; see **Boundaries** for `FrugalGPT Fig. 4` exceptions) over priors $(\pi_G, \pi_N, \pi_H)$ with $\pi_G + \pi_N + \pi_H = 1$:

1. **Pre-Query Router Rework Breakeven:** With strong-routing probabilities $(\alpha_G, \alpha_N, \alpha_H)$ and aggregate strong-call rate $\bar{\alpha} = \pi_G \alpha_G + \pi_N \alpha_N + \pi_H \alpha_H$, $E[C_{\text{router}}] = c_r + (1 - \bar{\alpha}) c_w + \bar{\alpha} c_s + [\pi_N(1 - \alpha_N) + \pi_H] R_c$ vs. $E[C_{\text{strong}}] = c_s + \pi_H R_c$. Routing to $M_w$ **increases total expected cost** whenever:
   $$R_c > R_c^{*,\text{router}} = \frac{(1 - \bar{\alpha})(c_s - c_w) - c_r}{\pi_N (1 - \alpha_N)}$$
   In `Probe 1.1` ($\pi_G = 0.55, \pi_N = 0.30, \pi_H = 0.15, c_r = 0.002 c_s, \alpha_G = 0.20, \alpha_N = 0.80, \alpha_H = 0.70 \implies \bar{\alpha} = 0.455$, `92.94%` pre-rework relative accuracy), $R_c^{*,\text{router}}$ drops from `8.9592 c_s` ($c_w/c_s = 0.01$) through **`8.5958 c_s`** ($c_w/c_s = 0.05$) and `8.1417 c_s` ($0.10$) to `6.7792 c_s` ($0.25$); at $c_w/c_s = 0.05$ and $R_c = 12 c_s$, exact `E[C_router] = 3.00425` exceeds `E[C_strong] = 2.80000` (`+0.20425` net penalty despite `51.58%` naive savings at $R_c = 0$).
2. **Sequential Cascade Critic False-Negative Ceiling:** With verifier cost $c_v$, false-alarm escalation $\alpha_{\text{FA}}$ on $\mathsf{GOOD}$, false-negative accept $\beta_{\text{FN}}$ on $\mathsf{NEEDY}$, and hopeless escalation $e_H$ on $\mathsf{HOPELESS}$, $E[C_{\text{casc}}] < E[C_{\text{strong}}]$ requires (for $R_c > c_s$):
   $$\beta_{\text{FN}} < \beta_{\text{FN}}^* = \frac{\bigl[\pi_G(1 - \alpha_{\text{FA}}) + \pi_H(1 - e_H)\bigr] c_s - (c_w + c_v)}{\pi_N (R_c - c_s)}$$
   In `Probe 1.2` ($\alpha_{\text{FA}} = 0.15, c_w = 0.05 c_s, c_v = 0.03 c_s$): at $R_c = 8 c_s$, a monotone threshold ($e_H = 0.90$) requires **$\beta_{\text{FN}} < 19.17\%$**, whereas suppressing `HOPELESS` escalation ($e_H = 0.10$) raises the ceiling to **`24.88%`** (`12.20% -> 15.83%` at $R_c = 12 c_s$; `7.06% -> 9.17%` at $R_c = 20 c_s$). On a 5-bin non-monotone verifier distribution at $R_c = 6.0$, `POMDP` policy `(0, 1, 0, 1, 0)` cuts expected cost to **`1.6600`** vs. `1.8450` for the best monotone threshold `(1, 1, 1, 1, 0)` and `2.0110` for `Always-Strong`.

### 3. Automated Crash and Test-Failure Root-Cause Deduplication ("Bucketing")

#### 3.1 The Dual Failure Physics of Heuristic Bucketing: Over-Splitting vs. Over-Merging

`Basis: source + documentation + execution (standalone Python 3.13 stdlib reproduction of ClusterFuzz CrashComparer and grouper.py in Probe 2.1–2.2) + derived`

When $M$ true root-cause bugs emit $N \gg M$ failing traces grouped into $K$ buckets upstream of autonomous repair dispatch:
- **Over-splitting (`Inverse Purity` / `BCubed Recall` collapse, $1 \text{ bug} \to k \text{ buckets}$):** Spawns $k - 1$ redundant repair agents on the same bug, multiplying compute burn and causing self-inflicted merge conflicts.
- **Over-merging (`Purity` / `BCubed Precision` collapse, $m \text{ bugs} \to 1 \text{ bucket}$):** Silently masks $m - 1$ distinct bugs whenever the controller dispatches one agent per bucket and closes suppressed bucket members without post-patch replay.

1. **Empirical Ground-Truth Magnitude (`Klees, Ruef, Cooper, Wei, & Hicks`, ACM CCS 2018, pp. 2123–2138, `10.1145/3243734.3243804`, `arXiv:1808.09700v2`, `§1 & §7`):**
   - Applying ground-truth patches to `binutils` `cxxfilt` (`ASAN + UBSAN`), `§1` reports **`57,142` AFL coverage-unique crashes addressed by `9` patches (`6,349×` over-splitting)**, while `§7` excludes `98` unfixed inputs to report **`57,044` crashing inputs across `9` bugs (`6,339×`)**.
   - Call-stack hashing produced **`595` distinct stack hashes across all runs (`66×` over-splitting; averaging `~46` per trial vs. `~500` AFL coverage buckets)** while simultaneously suffering **`~16%` cross-bug hash collisions**—including **`5` single-crash bugs whose hashes collided with other bugs**, silently erasing all evidence of those 5 bugs.
2. **Audited `ClusterFuzz` Deduplication Invariants and Three Live-Reachable Flaws (`google/clusterfuzz@ff2e60f0f75e`, `Probe 2.1`–`2.2`):**
   - *Exact `crash_state` construction (`source`):* `stack_analyzer.get_crash_data` (`src/clusterfuzz/_internal/crash_analysis/stack_parsing/stack_analyzer.py:54–85`) symbolizes twice—keeping inline frames for display (`enable_inline_frames=True`, `L72`) while **stripping inline frames for deduplication (`enable_inline_frames=False`, `L74`)**—applies `stack_frame_ignore_regexes` (`L84`), strips hex addresses/line numbers (`stacktraces/__init__.py:344`), caps lines at `LINE_LENGTH_CAP = 80` (`constants.py:740`, `__init__.py:355`), and retains at most **`MAX_CRASH_STATE_FRAMES = 3` non-ignored top frames** (`constants.py:741`, `__init__.py:302–304`).
   - *Audited `CrashComparer.is_similar()` (`crash_comparer.py:72–124`) & Live Transitive `grouper.py:386–413`:* Within the same `(project_name, security_flag)`, `_group_testcases_with_similar_states` (`grouper.py:386–413`) loops over `(testcase_1_id, testcase_2_id)`, skips `testcase_1_id <= testcase_2_id` (`L394`), invokes `CrashComparer(state_1, state_2).is_similar()`, and performs **pairwise transitive group merging** (`combine_testcases_into_group`, `L130–165, 412`). Three live-reachable defects follow:
     1. **`LCS >= 2` wrapper false-merging (`crash_comparer.py:75, 108–110`):** Any two distinct bugs sharing two unignored top wrapper/assertion frames (`["assert_nonnull", "check_ptr", "<bug_specific>"]`) merge, and transitive pairwise grouping chains `["w1","w2","x"] ~ ["w1","w2","y"] ~ ["z","w2","y"]` into a single group (`Probe 2.1`);
     2. **`min(len_1, len_2)` prefix-truncated Levenshtein (`L74, 114–124`):** Because the loop stops at `min(len_1, len_2)` and divides by `lines_compared = min(len_1, len_2)`, any unwinder-truncated `1`-frame stack `["parse_chunk"]` scores `similarity_ratio_average = 1.0 > 0.8` against every `3`-frame stack beginning with `"parse_chunk"` (`Probe 2.1`);
     3. **Live-reachable `'FuzzerHash='` asymmetry (`crash_comparer.py:100` + `grouper.py:394`):** `L100` checks `if 'FuzzerHash=' in self.crash_state_1: return False` without checking `crash_state_2`. Because `grouper.py:394` only compares pairs with `id1 > id2`, `["a","b","c"]` (`id1`) vs. `["a","b","FuzzerHash=bbb"]` (`id2`) returns `True` (merging them into `1` group), whereas the reversed ID order returns `False` (`2` groups; verified in `Probe 2.1`).

#### 3.2 Call-Stack Alignment (`ReBucket`, `TraceSim`, `S3M`) vs. Semantic, CFG, and Multi-View Embedding Clustering (`SCB`, `Igor`, `GPTrace`)

`Basis: source + documentation + execution (standalone Python 3.13 stdlib upstream ReBucket/S3M/ZhangShurong/ClusterFuzz ports, 8-bug/40-trace BCubed benchmark, max-norm IDF-ReBucket, and SCB replay in Probe 2.1–2.2) + derived`

1. **`ReBucket` Position-Dependent Model (`Dang et al., ICSE 2012`, `10.1109/ICSE.2012.6227111`) and Audited Open-Source Port Bugs (`Probe 2`):**
   - Over stacks $S_1 = \langle f_0, \dots, f_{N_1-1}\rangle$ and $S_2 = \langle g_0, \dots, g_{N_2-1}\rangle$ indexed $0$-based from the crashing top frame, `ReBucket` computes optimal damped alignment via $O(N_1 N_2)$ dynamic programming:
     $$M(i, j) = \max\!\begin{cases} M(i-1, j-1) + e^{-c \min(i-1, j-1)} e^{-o |i - j|} & \text{if } f_{i-1} = g_{j-1}, \\ M(i-1, j), \\ M(i, j-1), \end{cases} \qquad \text{Sim}(S_1, S_2) = \frac{M(N_1, N_2)}{\sum_{k=0}^{\min(N_1, N_2) - 1} e^{-c k}}$$
     where $c \ge 0$ damps deeper frames and $o \ge 0$ penalizes alignment offset, followed by agglomerative average-linkage clustering (`~0.88–0.91` F-measure on Windows/Office corpora vs. `~0.76` PrefixMatch/Cosine).

## Boundaries

- **`known not to apply` — Single-Turn QA Cost Savings Under Multi-Turn Rework and Non-Monotone Model Diversity:** `RouteLLM`'s `3.66×` `MT-Bench` savings (vs. random), `FrugalGPT`'s `98.3%` `HEADLINES` savings, and `AutoMix`'s QA $\Delta\text{IBC}$ lifts assume $R_c = 0$; above $R_c^{*,\text{router}}$ or $\beta_{\text{FN}}^*$ (Section 1.3), cheap-tier routing increases total cost. Conversely, Section 1.3's closed-form rework laws assume monotone strong-model dominance ($P(M_w = 1, M_s = 0) = 0$), which `FrugalGPT Fig. 4` shows can fail on `6%` (`HEADLINES`) to `13%` (`COQA`) of queries where a cheaper model beats `GPT-4`—requiring an added positive diversity term in ensembles rather than strict weak/strong cascades.
- **`unsupported` / `not examined` — Speculative Side Effects Beyond Isolated CoW Sandboxes:** `TomasuLLM` (`arXiv:2609.38201v2`) measures local E2B overlay rollback (`0.08 s` CoW fork; `0.5–5 s` commit/recovery). Speculating over **irreversible external side effects** (PR comments, remote RPC mutations, shared database writes) is `unsupported` without transactional escrow or dry-run isolation; live multi-turn SWE-Bench speculative mutation rollbacks were `not examined` directly here.
- **`known not to apply` — Static AST Delta-Retention Gates as Standalone Semantic Merge Oracles:** `Probe 3.3`'s universal subset check (`add_a <= f_m` and `add_b <= f_m` over `sig`, `dec`, `if`, `raise`, `assert`, `call+kwargs`, `assign`, `augassign`, `return`) catches unilateral drops, partial multi-call drops, and literal `if`-predicate inversions, **yet suffers both false negatives** (reordered runtime state mutations or side effects hoisted above guards: `Case_FN_DynamicOrder`, `Case_FN_SideEffectOrder`) **and false positives** (valid synthesized expressions reconciling conflicting assignment RHSes: `Case_FP_SynthAssignExpr`). Static AST gates are triage/escalation detectors that complement—never replace—two-branch unit-test execution.
- **`unsupported` — C/C++ Binary Tracers and C Patch Templates on Managed or Multi-Language CI Logs:** `Igor`'s Intel Pin dynamic CFG tracer (`HexHive/Igor@12639e90ce2e`, `smart_tracer/pintool/calltrace.cpp`) and `SCB`'s `presto.exe` C AST patcher do not apply to JVM/Python/Rust-macro CI failure logs directly, whereas stack-alignment (`ReBucket` / max-norm IDF-`ReBucket`), multi-view diagnostic+stack embeddings (`GPTrace`), and post-patch bucket replay generalize across languages.
- **`not examined` — Live Execution of Upstream Repositories:** All 19 pinned upstream repositories were audited at source (`Basis: source`) rather than executed against live LLM APIs, Maven builds, Intel Pin, or compiled C++ binaries; `Basis: execution` applies strictly to `support/verify_routing_migrations_merge_crash_dedup_probes.py`.
