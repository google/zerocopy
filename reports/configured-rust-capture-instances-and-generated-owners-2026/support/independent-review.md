## Why this answers the bounded E04 capture question

The selected source, configuration, root/signature and tool profile belong to
the independently supplied caller request. Candidates do not select compiler
commands or weaken that request. The consumer checks source graphs, snapshots,
tool identities and fresh observation before exact packet equality. Unknown
fields, duplicate keys, invalid locals/blocks and inconsistent/dangling
dependency edges reject; the final equality compares all opaque rendered and
provenance fields too.

The baseline contains 24 configured local definitions, ten local body templates,
ten concrete/constant/glue instances and ten represented dependency edges.
I independently checked the full edge set: root calls generated/selected/
generic/closure bodies, separately records closure construction and Drop glue;
generic selects the u8 Step implementation; Step links SHIFT then BIAS; glue
calls the actual local destructor. The constant value 3 and distinct
`Runtime(PostCleanup)`/`Runtime(Optimized)` phases are recorded. The census
includes the macro declaration, generated function, selected cfg alternative,
closure and late lifetime parameter. The uncalled decoy remains in definitions
and templates but is absent from root's selected instance graph. Other exact
selections have the report's stated counts, including the two-file module.

The operation-only candidate changes one BitXor to BitOr while preserving the
caller/source labels; the coherent Drop-erasure candidate remains schema-valid
with eight instances/eight edges; the uncalled-owner omission also remains
well-shaped. All three reject **after** actual compiler success and full fresh
comparison. This demonstrates a stronger discriminator than a name/hash roster.
The historically named `omitted-macro-owner` control removes the macro-expanded
`generated` function owner; it should not be interpreted as a separate test
deleting the `make` macro declaration. A dead-local destructor store is not a
claim that every equivalent Drop erasure is unsafe: the tested contract is
representation fidelity, not semantic optimization equivalence.

## Loader failure and corrected replay qualification

One earlier review attempt copied the unchanged observer to unrelated scratch.
It aborted in dyld with exit −6 before analysis because its LC_RPATH resolves
relative to `@loader_path`. No semantic capture or native subject ran in that
attempt. Original and copied binary hashes were identical; the original path's
resolved driver exists and matches the selected driver hash. The parent
confirmed the diagnosis and authorized the explicit-original-path recovery.
No symlink, binary patch, rebuild, library override or schema change was used.

The declared selected driver is under `lib/`; this exact observer actually
resolves a byte-identical copy under the target library directory. Both were
independently bound during replay. Arbitrary relocated dynamic dependencies and
system runtime closure are not thereby verified. This was a required correction
to the original copied-observer replay instructions, not a Rust unsupportedness
or semantic rejection result.

The distinct publication helper `run_controls_explicit_observer.py` is
**source-reviewed only** (its CLI was separately checked by the parent); its full
matrix has not been executed. It adds required explicit observer selection and
records its own new helper identity. The historical `run_controls.py` and its
archived hash remain unchanged. The completed 34-call replay belongs to the
different fixed-input independent harness, not to this newly added helper.
The corrected public REPORT/REPLAY text accurately makes these distinctions.

An independent projection-reader bookkeeping failure is also preserved: the
first reader deliberately excluded the invalid duplicate-key control from JSON
semantic parsing but expected a count including it. Before any extraction or
compiler call, it stopped. Direct diagnosis established 51+1, both duplicate
controls were strictly rejected, and the corrected reader retained every byte
and field restriction. No subject or grammar was changed.

## Semantic and environmental premises that remain

E04 asks for a configured capture prototype with instance/owner/dependency
binding and rejecting controls; the observed implementation meets that bounded
request. It does not prove that arbitrary configured Rust is captured, that
unparsed HIR/type/enum debug renderings denote a formal semantics, or that every
source memory/resource invariant survives lowering. The request, cooperative
filesystem, rustc queries/metadata/runtime, observer and reader remain trusted.
Hash/physical-path checks are not hostile same-user isolation.

The configured functions use post-lowering optimized MIR even with MIR opt
level zero. Region erasure and imported semantics remain explicit premises.
E10's source-safety theorem, P127's proved end-to-end pre-optimization-fragment
capture, and P131's actual memory-operation/byte/initialization correspondence
are not discharged. Unsupported65, rejected data/preflight, loader failure and
unexamined features remain different results. No universal frontend, arbitrary
client, lifetime/alias, target, runtime or source-to-native theorem is claimed.

The corrected projection has passed exact manifest/privacy/delta checks and its
static package audit. The final attachment-only delta will be checked separately;
publication and canonical milestone decisions remain with the parent.
