# Typed-Hole Static Contextualization, Compiler-Diagnostic Repair Loops, Typestate and Code-Health Representations, and Dependency-Graph Edit Planning

## Summary

Primary-source inspection of 25 peer-reviewed programming-languages, software-engineering, and machine-learning studies (1986–2026), 18 immutable commits across 17 public repositories, and a deterministic four-probe Python 3.10+ verification suite establishes four governing invariants for repository-scale code synthesis and refactoring:

1. **Proactive Typed-Hole Static Contextualization and Semantic Token Constraining Separate Structural Plan Selection from Local Type Validity (`Synchromesh`, `Blinn et al. 2024`, `ChatLSP`, `Probe 2`):**
   - In `Synchromesh` (`Poesia et al., ICLR 2022`, `arXiv:2201.11227v1`; `kanishkg/synchromesh@799e93b9`), **Target Similarity Tuning (`TST`)** aligns few-shot retrieval to normalized Zhang–Shasha AST tree-edit similarity (lifting `Codex 175B` SMCalFlow exact match from `45%` to `63%`), whereas **Constrained Semantic Decoding (`CSD`)** enforces context-free grammar and context-sensitive scope/type/schema invariants at subword boundaries via Brzozowski-derivative Completion Engines (`73% -> 85%` valid SQL, `87% -> 99%` valid Vega-Lite, `79% -> 97%` valid SMCalFlow at `8%` mean sampling overhead; combined `CSD + TST` reaches `64%` Spider SQL execution accuracy and `63%` exact match / `99%` validity on SMCalFlow).
   - In `Blinn, Li, Kim, & Omar` (*PACMPL / OOPSLA 2024*, `doi:10.1145/3689728`, `arXiv:2409.00921v1`; `fplab/chatlsp@c07132bd`, `HongweiRuan/ctxextract-llm@040ddbe6`), extracting the expected hole type, transitive component type definitions (`Relevant Types`), and 2-level arrow/product type-consistent bindings (`Relevant Headers`, excluding unaliased `Bool`/`String`/`Int` base types) averages `890` empirical prompt characters (`1,370` chars for `Exhaustive`) yet outperforms configured `900`-char (`6 × 150`-char chunk) `text-embedding-ada-002` `Vector RAG`. Without `Relevant Types`, function headers and compiler error rounds yield near-zero gains on hallucinated ASTs; once type definitions scaffold the hole (`~10×` gain on `StarCoder2-15B`), `Relevant Headers` multiply passed tests **`3×` in `Hazel` and `1.5×` in `TypeScript`** (`GPT-4-0613`, `+50%` relative on `StarCoder2-15B` despite recency distraction on `BO`/`TO`), and up to `2` static error rounds multiply passed tests **`2×` in `Hazel`** (`4×` on types-only, `1.5×` on types+headers) and **`1.2×` in `TypeScript`**.
2. **Compiler-Diagnostic Repair Converges on Local Errors (`93.33%`) Yet Induces Stub Suppression (`27%–55%`), Silent Non-Stub Corruption (`6.72%`), and Test-Repair Build Regression (`-5` to `-20 pp`) Without Interface Locks and Behavioral Oracles (`RustAssistant`, `CRUST-Bench`, `Probe 4`):**
   - `RustAssistant` (`Deligiannis et al., ICSE 2025`, `doi:10.1109/ICSE55347.2025.00022`: **`252/270 = 93.33%`** micro-benchmark test-verified fixes at `GPT-4, N=5` vs. `250/270 = 92.59%` in 4-author preprint `arXiv:2308.05177v1`; `37/50 = 74%` on Stack Overflow at `N=1`; `134/182 = 73.63%` compiling top-100 crate commits and `846/925 = 91.46%` fixed errors vs. `25/270`, `1/50`, and `1/182` for `cargo fix`) relies critically on per-error-group rollback. Yet among its `134` compiling crate commits (`Table V`), alongside `29/134` (`21.64%`) behavior-preserving syntactic variants (such as `const`/`pub`/trait-bound edits), **`9/134` (`6.72%`) silently alter runtime behavior** (deleting statements, rewriting unrelated functions, or inventing wrong non-exhaustive `enum` `match` arms) without using `unsafe` or `todo!()`.
   - In repository-level C-to-safe-Rust transpilation (`CRUST-Bench`, `Khatry et al., COLM 2025`, `arXiv:2504.15254v3`), `3` rounds of compiler-only repair lift build rates (`OpenAI o3`: `35% -> 68%`, `Claude Opus 4`: `43% -> 78%`, `OpenAI o1`: `32% -> 69%`) while leaving wide build-to-test gaps (`31%`, `29%`, `28%` test pass) driven by `unimplemented!()`/`todo!()` stubs (`27%` of `o3`, `46%` of `Claude 3.7`, `55%` of `Claude 3.5`). Follow-on `3`-round test repair raises test pass rates to `48%`, `40%`, and `37%` **while regressing build rates by `5` to `20 pp`** (`o3`: `68% -> 63%`, `Opus 4`: `78% -> 65%` [`-13 pp`], `o1`: `69% -> 54%`, `o1-mini`: `47% -> 27%`) as semantic edits re-introduce borrow/type errors. As our parameterized absorbing Markov analysis (`Basis: derived`, `Probe 4`) and AST gate tests verify, rejecting `todo!`/`unimplemented!`/`panic!`/`unsafe` and signature mutations eliminates stub bypass (`0.00%`) **yet leaves `6.72%` (`9/134`) conditional non-stub semantic corruption** (such as trivial `{ Ok(()) }` body deletion, which passes syntactic checks and requires held-out behavioral contract tests).
3. **Explicit Typestate Semilattices Eliminate `>91%` Illegal Product States, Cut Human Protocol Search Time `2.17×`, and High `CodeHealth` (`CH >= 9`) Cuts Unsupervised LLM Refactoring Breakage by `15%–31%` (`Strom & Yemini 1986`, `Plaiddoc`, `CodeScene`, `SWE-Refactor`, `Probe 3`):**
   - Encoding protocol state via $b$ boolean flags and $m$ nullable fields inflates concrete states from $\sum_{v \in V} \prod_{f \in \text{fields}(v)} |D_f|$ to $2^b \prod_{i=1}^m (|D_i| + 1)$ (**`915/1,000 = 91.50%`** illegal states on a 4-state transactional connection and **`239/256 = 93.36%`** on a 5-state result cursor, `Probe 3`), whereas `Strom & Yemini (1986)` lower-semilattice `meet` ($\bigsqcap$) inserts sound pre-operation, normal-edge, and per-throw-site downward cleanup coercions statically. More than `8%` of Java Standard Library classes/interfaces define object protocols (`>3×` type-parameter prevalence; `Beckman, Kim, & Aldrich, ECOOP 2011`, `doi:10.1007/978-3-642-22655-7_2`).    - Across `30,737` production files in `39` codebases (`Tornhill & Borg, TechDebt 2022`, `doi:10.1145/3524843.3528091`), `Alert` (`CodeHealth < 4`) files carry **`15×` more defects**, **`+124%` longer average development time** (`+78%` in `Warning`), and **`9×` longer maximum cycle times** than `Healthy` (`CH >= 9`) files, with cubic increasing returns from `CH = 8` to `10` (`Borg et al., TechDebt 2024`, `doi:10.1145/3644384.3644471`). While human-supervised AI feature authoring in `Echoes of AI` (`Borg et al., EMSE 2026`, `doi:10.1007/s10664-026-10889-1`, `arXiv:2507.00788v3`, $N = 151$) sped up Phase-1 implementation by `30.7%` median without degrading Phase-2 human maintainability, unsupervised LLM refactoring (`Borg et al., FORGE 2026`, `arXiv:2601.02200v1`: `5,000` Python files on `5` open-weight LLMs + `1,000`-file stratified subset on `Claude Sonnet 4.5` and `Claude Code`) breaks tests **`8.58` to `15.12 pp` less often** on `Healthy` vs. `Unhealthy` files across all `5` open-weight LLMs (`15%–31%` relative risk reduction, $p < 0.001$; `Sonnet` `86.77%` vs. `84.03%`, non-significant $p = 0.439$ at `CH = 9`, plateauing down to `CH ≈ 8`), with `CH` carrying **`1.40×–7.33×` the decision-tree importance of token perplexity** (`5.36×` to `>500×` over `SLOC`, tree `AUC = 0.544–0.565`, logistic OR `1.215–1.420` per `+1 SD`). Multi-file refactoring collapses from `82.6%` atomic to `39.4%` compound on `GPT-5.1-Codex` (`SWE-Refactor`, `arXiv:2602.03712v1`) and to **`28/520 = 5.4%`** on whole-repository migrations (`SWE Refactor Bench`, `arXiv:2608.23564v1`).

## Findings

### 1. Semantic-Constrained Decoding, Typed-Hole Static Contextualization, and Compiler-Diagnostic Repair Loops

#### 1.1 `Synchromesh`: Orthogonal Failure Suppression by `TST` and `CSD`

`Basis: normative + documentation + source`

`Synchromesh` (`Poesia et al., ICLR 2022`, `arXiv:2201.11227v1` §§2–4, `Tables 1–3`; `kanishkg/synchromesh@799e93b9`) separates **plan-level structural/conceptual mismatches** (addressed pre-decoding by `TST`) from **token-level syntax, scope, schema, and type errors** (eliminated online by `CSD`):

- **Target Similarity Tuning (`TST`):** Frozen surface utterance embeddings retrieve examples with matching English phrasing (`"highest elevation"`) whose target AST lacks required `GROUP BY` / `COUNT(*)` structure, inducing column hallucination (`NumberOfAirports`). Given training pairs $D_i = (p_i, u_i)$ and normalized Zhang–Shasha AST tree-edit similarity $S(p_a, p_b) \in [0, 1]$, `TST` trains encoder $f_\theta$ on $\mathcal{L}_{\text{TST}}(\theta) := \mathbb{E}_{i,j \sim D}[(f_\theta(u_i, u_j) - S(p_i, p_j))^2]$.
- **Completion Engines (`CE`) and Subword Alignment (`CSD`):** For base alphabet $\Sigma$, target lexical tokens $\Sigma_L \subseteq \Sigma^*$, and valid language $L \subseteq \Sigma_L^*$ with prefix-closure $L^c$, a Completion Engine $C_L : \Sigma_L^* \rightharpoonup \mathcal{R}(\Sigma)$ returns a regular expression over $\Sigma$ at completion points satisfying: **(A1)** $\varepsilon \in \operatorname{dom}(C_L)$ and $\forall p \in L,\, C_L(p) = r_{\text{stop}}$; **(A2)** maximal match $t$ of $C_L(s)$ yields $st \in \operatorname{dom}(C_L)$; and **(A3)** $s = t t_0 \in \operatorname{dom}(C_L) \implies t \in \operatorname{dom}(C_L)$ and $C_L(t)$ matches $t_0$. Because LLM BPE subwords $V \subseteq \Sigma^*$ straddle lexical token boundaries, `StreamingCSD` (`synchromesh/synchromesh.py:13-95`, `predict_constrained` `L97-203`, `is_prefix_valid` `L206-234`, `CompletionEngine` `completion_engine.py:7-13`, `LarkCompletionEngine` `L15-50`, `trie.py`) advances across maximal matches via Brzozowski derivatives $\partial_c R$ and prunes $V$ via prefix anti-monotonicity ($u \notin L^c \implies \forall w,\, uw \notin L^c$), adding `8%` mean GPT-3 sampling latency:

| :--- | :---: | :---: | :---: |
| **GPT-3 13B** (unconstrained $\to$ `+CSD` $\to$ `+TST` $\to$ `+CSD+TST`) | `16%/43%/0.42` $\to$ `20%/66%/0.44` $\to$ `14%/48%/0.42` $\to$ `19%/72%/0.43` | `14%/55%/0.51` $\to$ `17%/100%/0.48` (no `TST`) | `38%/76%/0.43` $\to$ `40%/95%/0.40` $\to$ `60%/88%/0.22` $\to$ **`63%/98%/0.17`** |

On SMCalFlow (`Codex 175B`), `CSD` alone lifts validity `+18 pp` (`79% -> 97%`) yet accuracy by only `+1 pp` (`45% -> 46%`) because constrained subwords cannot repair an incorrect high-level API plan, whereas `TST + CSD` achieves both `63%` exact match and `99%` validity. (SQL validity under `CSD` stays `< 100%` only on max-token truncation or left-to-right `JOIN` dead ends lacking unbounded lookahead.)

#### 1.2 Typed-Hole Static Contextualization (`ChatLSP`, `ctxextract-llm`, and `MVUBench` Factorial Ablation)

`Basis: normative + documentation + source`

`ChatLSP` (`fplab/chatlsp@c07132bd`, `src/scripts/lspMethodSpecs.ts:1-147`) and `ctxextract-llm` (`HongweiRuan/ctxextract-llm@040ddbe6`, `out/context-extractor/src/core.js:26-576`, `typescript-driver.js:1-491`, `ocaml-driver.js:1-483`, `ocaml-type-checker.js:1-287`; cf. `hazelgrove/hazel@f7257dd4` `AgentContext.re:1-61` and `hazel@ea05f3ba` `SuggestionsExp.re:1-356`) define five typed-hole RPCs:
1. **`textDocument/expectedType` (`lspMethodSpecs.ts:2-28`):** Returns $\tau_{\text{hole}}$ at cursor (emulated in TypeScript via `declare function _<T>(): T` and hovering over `_()`, `arXiv:2409.00921v1` §3.1).
2. **`textDocument/relevantTypes` (`L30-56`, `extractRelevantTypes` at `core.js:315-409`):** Transitively unfolds type aliases, records, and sum/union definitions reachable from $\tau_{\text{hole}}$ via `Go to Type Definition` + `Hover`.
3. **`textDocument/relevantHeaders` (`L58-84`, `extractRelevantHeaders` `core.js:414-435`, `getTargetTypesHelper` `L442-469`, `extractRelevantHeadersHelper` `L472-510`):**
   - Decomposes $\tau_{\text{hole}}$ up to `2` levels across arrow return types ($\tau_1 \to \tau_2 \implies \{\tau_1 \to \tau_2, \tau_2, \dots\}$) and product components, **filtering out unaliased base types** (`Bool`, `String`, `Int`) so ubiquitous standard-library primitives do not flood the prompt (§2.6.1).
   - Selects typing-context bindings $(x : \sigma)$ where $\sigma$, its return type, or a product component is type-consistent with a target type (checked in TypeScript/OCaml via synthetic probe `const checker = (h: HTyp): TTyp => return h`), weighting incomplete gradual types (`?`) by known-to-total type constructors (`[?]` $\mapsto 0.5$, §2.6.3).
4. **`llmCompletion` (`L86-113`) & `llmCompletionResolveErrors` (`L115-139`):** Coupled synthesis and bounded (`<= 2`-round) localized static-diagnostic repair.

Across `MVUBench` (`Blinn et al., OOPSLA 2024`, `doi:10.1145/3689728`, pp. 468–498; `5` MVU apps `Todo`, `Room Booking`, `Emoji Painter`, `Playlist Manager`, `Password Strength Checker`, `2×2×2` factorial × `20` trials = `320` completions per model/language at `T = 0.6`):
- **Types-first gating:** Without `Relevant Types` (`no/*/*`), `GPT-4-0613` and `StarCoder2-15B` hallucinate nonexistent constructors and foreign OCaml syntax (`Fig. 8–9`), rendering both `Relevant Headers` and compiler-error rounds ineffective. Providing `Relevant Types` lifts `StarCoder2-15B` accuracy by **`~10×`** (`§2.10`).
- **Super-additive header & error multipliers:** Given `Relevant Types`, adding `Relevant Headers` multiplies passed tests **`3×` in `Hazel` and `1.5×` in `TypeScript`** on `GPT-4-0613` (`+50%` relative overall on `StarCoder2-15B`, though `StarCoder2-15B` regresses on `BO` and `TO` from recency bias toward type-compatible irrelevant tail helpers, `§2.10`), while up to `2` static error-repair rounds multiply passed tests **`2×` in `Hazel`** (`4×` on types-only; `1.5×` on types+headers) and **`1.2×` in `TypeScript`** (`§2.9, §3.2`).
- **Matched-budget superiority over `Vector RAG`:** Static hole contextualization averages **`890` empirical characters** (`§2.9`; `Exhaustive` averages **`1,370` chars**), outperforming `Vector RAG` configured at a **`900`-char cap** (`6 × 150`-char `text-embedding-ada-002` chunks over the `~1,000`-line combined repo, `§2.8.5`), which retrieves colliding sibling `Model`/`Action` definitions (`Fig. 12`) and slices AST declarations mid-line.

#### 1.3 Strongly Typed Compiler-Diagnostic Repair Loops: Local Convergence vs. Symptom Suppression (`Probe 4`)

`Basis: documentation + source + derived + execution`

1. **`RustAssistant` (`Deligiannis et al., ICSE 2025`, `doi:10.1109/ICSE55347.2025.00022`, pp. 3097–3109, 5 authors adding `Rishi Poddar`; vs. 4-author preprint `arXiv:2308.05177v1`, *"Fixing Rust Compilation Errors using LLMs"*):**
   - *Algorithm:* Extracts primary and `note:` spans (`±50` lines with `[N]` line prefixes), forbids `unsafe` and `#![feature(...)]` in prompt text, enforces `(FixDescription, OriginalCode@L1-L2, FixedCode@L1-L3)` changelogs, ranks $N \in \{1, 5\}$ samples by `rustc` error count, and tracks per-seed **error group** $g \leftarrow \text{check}(\text{project}) - \text{errs}$, rolling back to snapshot `snap` whenever $|g|$ stalls or exceeds `100` unique errors (ablating rollback causes cascading multi-error blow-ups).
   - *Version-resolved benchmarks:*

### 2. Typestate Semilattice Coercions, Human Protocol Search, `CodeHealth`, and Multi-File Refactoring

#### 2.1 Sum-vs-Product State Explosion, `Strom & Yemini` Coercions, and `Plaiddoc` Trials (`Probe 3`)

`Basis: documentation + derived + execution` (`Strom & Yemini 1986` via `[abstract + secondary]`)

- **Illegal-State Cardinality & Sound Semilattice Coercions (`Strom & Yemini 1986`, `doi:10.1109/TSE.1986.6312929` `[abstract + secondary]`; `Aldrich et al., Onward! 2009`, `doi:10.1145/1639950.1640073`; `Sunshine et al., OOPSLA 2011`, `doi:10.1145/2048066.2048122`; `Probe 3`):**
  - Encoding disjoint protocol variants $V$ via $b$ boolean flags and $m$ nullable fields (`Option<D_i>`) creates $|S_{\text{illegal}}| = 2^b \prod_{i=1}^m (|D_i| + 1) - \sum_{v \in V} \prod_{f \in \text{fields}(v)} |D_f|$ representable illegal states: **`915 / 1,000` (`91.50%`)** on `TransactionalConnection` ($b = 3, |D_i| = 4$, `85` valid sum states) and **`239 / 256` (`93.36%`)** on `ResultSetCursor` ($b = 4, |D_i| = 3$, `17` valid sum states), verified algebraically and by exhaustive Cartesian enumeration in `Probe 3`.
  - Over a finite lower semilattice $(\mathcal{S}_T, \preceq, \sqcap, \bot)$ (`Closed < OpenConn < {ReadSnapshot, WriteStaged}` and `WriteStaged < PreparedCommit`), sound compile-time typestate checking requires **three** distinct downward cleanup coercion sites (`Probe 3`): **(i) inter-block normal merge edges** (`B_read->B_join(normal): ['release_snapshot_pin']`, `B_write->B_join(normal): ['unprepare_tx', 'rollback_staged_write']` toward `ReadSnapshot ⊓ PreparedCommit = OpenConn`, plus loop entry `<entry>->L_head: ['release_snapshot_pin']`), **(ii) intra-block pre-operation coercions** whenever an instruction's required state satisfies $s_{\text{req}} \prec s_{\text{cur}}$ (`B_abort_inline[2]:explicit_close(pre): ['unprepare_tx', 'rollback_staged_write']`), and **(iii) per-throw-site exception coercions** from each throwing instruction's `exc_post` down to handler entry `in_state[B_exc]` (`B_write[1]:prepare_commit->B_join(exc): ['rollback_staged_write']`, preventing the staged-transaction leak that occurs if exception states across `begin_write_tx` [`OpenConn`] and `prepare_commit` [`WriteStaged`] are merged before coercion synthesis), while statically rejecting `B_join[0]:finalize_commit requires PreparedCommit, actual=OpenConn`.
- **Protocol Prevalence & Human State-Search Speedup (`Beckman, Kim, & Aldrich, ECOOP 2011`, `doi:10.1007/978-3-642-22655-7_2`, pp. 2–26; `Sunshine, Herbsleb, & Aldrich, ECOOP 2014`, `doi:10.1007/978-3-662-44202-9_7`, KiltHub `10.1184/R1/6625919.v1`; `ICPC 2015`, `doi:10.1109/ICPC.2015.17`, pp. 82–93):**
  - More than **`8%` of Java Standard Library classes and interfaces define object protocols**—over **`3×`** as many as define generic type parameters (`Beckman et al., 2011`). In observational think-aloud sessions (`ICPC 2015`, $N = 6$ professionals), developers spent **`71%` of total session time (`82%` of assigned protocol-task time, `§III-B`)** on four state-search queries (`object -> state`, `state -> valid ops`, `op -> required states`, `state X -> state Y`).
