The pinned Islaris/Coq/old-Sail metadata request has a witnessed **offline opam dry-run solution: 74 packages, including all 35 exact roots**. opam 2.1.6 returned status 0 in 9.078333 seconds with networking disabled. The real switch's installed-package and pin lists remained empty. No package was installed, built or proved. This crosses the earlier report's unsolved metadata gate. It does not establish source availability, build compatibility or an Islaris/Sail proof replay. The solver selects modern transitive packages alongside old Sail, including Menhir 20260209, Lem 2026-05-01 and Yojson 3.0.0; satisfying metadata is not evidence that those APIs build together.

### Version and filter semantics materially affect the solution

opam 2.1.6's `src/format/opamFile.ml:3098–3123` reads identity from the repository directory and replaces explicit name/version fields after warning about a mismatch. Thus dated Iris/stdpp repository entries retain upstream `version: "dev"` text while their actual selected identities and `version` dependency variables are dated. This is observed in the selected raw metadata and solution. No upstream formula or version field was rewritten.

`src/state/opamPackageVar.ml:121–130` classifies these checksum-free fixed-commit Git URLs as development packages. The numeric Sail version does not make `dev=false`: **libsail's bisect_ppx dependency is active**, and bisect_ppx 2.8.3 is selected. `pinned=false` is separate: the actual pin set is empty. Lithium/Islaris commands guarded by `pinned` would therefore not run in a later repository installation; this result does not silently claim equivalence to source pinning. `pin-depends` is inert for repository packages (Manual.md:1114–1128); the separately materialized isla-lang entry binds its required source commit. Tests/docs are false, not deleted from metadata. Build dependencies remain installation requirements, and post dependencies affect ordering rather than permitting Sail sibling omission. The complete preserved opam source/docs and unchanged original/derived overlay records are in [overlay and primary inputs](support/overlay-and-primary-inputs.tar.gz).

### Setup failures were operational, not UNSAT

The original command proposal placed global flags before the verb. Actual opam 2.1.6 rejected init-specific options with status 2 before root creation; help-only probes isolated verb ordering. Those failed argv/help streams remain preserved. An earlier bind-mounted input copy also failed with “Operation not permitted”; the separately authorized copied-input environment changed transport, not metadata. A later census controller accidentally placed an actual NUL byte in argv; it failed before launching find, after successful copies, and did not authorize recopying or solving. A subsequent read-only census used the intended literal escape.

Initialization also encountered a fatal unhandled “Cannot remove” while removing its own copied repository cache: copied read-only directory modes made the consumer-owned cache undeletable. Work stopped; the old root and 4,028,311-byte stderr remain preserved. This was a filesystem ownership/mode failure, not a metadata contradiction, solver UNSAT, build failure or changed dependency formula. The parent ran a small native ownership regression: root-owned 0755/0644 source inputs remain unwritable to the consumer while its cache copies permit owner writes/removal. That oracle passed. All **19,429 input file hashes** (19,399 main plus 30 overlay files) remained unchanged. A separately authorized fresh root then initialized successfully and produced the dry solution; the failed root was not reused or deleted. ## Boundaries

- **Established:** this exact platform/filter/repository request returned the complete 74-package dry solution; root identities and exported CUDF consistency were checked; actual installed/pin sets remained empty.
- **Unknown:** full source acquisition, checksum verification of package archives, Git-tree completeness, external/depext realization, a compatible exact old-Sail Z3 and executable closure, installation costs and build compatibility. Modern selected Menhir/Lem/Yojson versions make actual compilation a material next question, not a resolved implication of SAT.
- **Not executed:** package installation, old Sail/RISC-V generation, Isla trace production, Coq compilation, Islaris proof replay, coqchk or per-theorem Print Assumptions. Both RV64 and RV32 build targets remain in old coq-sail-riscv metadata; this solution does not remove their eventual work.
- **Known not to follow:** dry-run action order is not a realized installation; selected source URLs/checksums are not verified source bytes; a dependency solution is not a theorem, ABI/resource bridge, source-origin trace proof or hardware claim. The selected future upstream ADDI bridge remains distinct from two-input ADD or Rust resource composition.

## Revalidation

First verify package/archive/member hashes. Extract the native archive and run `support/audit_cudf.py` against `native/native-islaris-1.cudf` and the preserved raw native JSON, writing a fresh output outside this package. Confirm the same selected identities, synthetic invariant, 240/104/35 counts and rejecting missing-Iris control. This cheap host-only check revalidates the exported-instance audit, not the opam translator or build behavior.

To revalidate native solving, a separately authorized fresh network-disabled environment must bind the actual opam binary/image, exact metadata, source permissions, repository priority, platform/filter values and all 35 roots. Reuse the successful **verb-first** controller argv from the native receipts, with new owned output/cache roots. Verify empty real package/pin sets before and after; preserve raw JSON duplicates, full CUDF, actions, status and streams. Stop and diagnose a first unexpected failure rather than changing pins or formulas. This report authorizes no runtime action.

Source realization is a later gate: acquire every selected archive/Git tree/extra source at its declared identity, verify hashes and full trees, inspect build/depext scripts and choose/bind old Sail's external Z3. Then freeze actual executable outputs and run the unchanged selected upstream files, recursive coqchk and individual Print Assumptions under a separately reviewed allocation. The first real compiler/proof failure is useful boundary evidence; this successful metadata solve does not predict its outcome.
