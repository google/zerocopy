# FFmpeg libswscale Pixel-Format Matrix, 14-Bit Polyphase Rescaling Bounds, SwsOp Optimizer Soundness, and SPIR-V/CMS Parity

## Summary

FFmpeg's `libswscale` (`FFmpeg/FFmpeg@7ddf7bc8a482cf28b4fab2e63b7093ba35cb6a80`) contains two architecturally disjoint image-processing engines behind a single public C API:

1. **`SWS_BACKEND_LEGACY` (`SWS_BACKEND_STABLE`, `1 << 0`):** A fixed-function 15-bit (`int16_t`) and 19-bit (`int32_t`) fixed-point YUV/RGB pipeline (`swscale.c`, `swscale_unscaled.c`, `input.c`, `output.c`, `yuv2rgb.c`, `rgb2rgb.c`, `slice.c`, `bayer_template.c`) coupled to an L1/L2-resident double-mapped vertical ring buffer and an x86 MMXEXT runtime RWX JIT (`x86/hscale_fast_bilinear_simd.c`, `jit.c`). Across `AV_PIX_FMT_NB = 270` (`17` hardware-accelerated opaque descriptors and `253` software descriptors), the legacy backend supports **`234 / 253` (`92.5%`) software inputs** and **`210 / 253` (`83.0%`) software outputs**.
2. **`SwsGraph` / `SwsOp` (`SWS_BACKEND_UNSTABLE`, `libswscale/ops*.c`, `uops_tmpl.c`, `x86/ops*.c`, `aarch64/ops.c`, `vulkan/ops.c`):** A declarative pixel-operation compiler that lowers format conversion, ITU-T H.273 linear color matrices, transfer functions, dither, and separable polyphase filters into an intermediate representation (`SwsOpList`), optimizes it over 64-bit rationals (`AVRational64`), splits horizontal and vertical convolutions across full-frame planar intermediate buffers (`SwsPassBuffer`), and compiles fusion passes into either continuation-passing-style (CPS) ahead-of-time SIMD micro-kernel chains (`SWS_BACKEND_X86`, `SWS_BACKEND_AARCH64`) or runtime-assembled binary Vulkan compute shaders (`SWS_BACKEND_SPIRV`). `SwsOp` currently supports **`133 / 253` (`52.6%`) software inputs** and **`132 / 253` (`52.2%`) software outputs**, rejecting **100% of chroma-subsampled planar (`0 / 49`), semi-planar (`0 / 25`), Bayer (`0 / 12`), half-float `F16` (`0 / 12`), and CIE `XYZ12` (`0 / 4`) formats** (`format.c:968-1036`).

For clean-room media engineering and formal verification, four findings govern design and soundness:

- **Polyphase Indexing & NaN Tail-Padding Safety:** Both backends quantize separable resampling kernels to **14-bit signed fixed point (`SWS_FILTER_SCALE = 1 << 14 = 16384`)** with error diffusion and cap per-pass tap count at `256`, cascading steeper downscales across multi-pass graphs. Legacy `initFilter` (`utils.c:215-631`) allocates `filterPos[dstW + 3]` with `0 <= filterPos[i] <= max(0, srcW - filterSize)` and uses a `3 * N` line-pointer vertical ring buffer (`slice.c:217-315`) whose middle `[N .. 2N-1]` slice mirrors `[0 .. N-1]` for wrap-free vertical SIMD reads. Modern `ff_sws_filter_generate` (`filters.c:71-325`) enforces strict `filter_size <= src_size` and `0 <= offsets[i] <= src_size - filter_size`, tracks exact per-plane SIMD gather overread (`SwsImplResult.over_read[i]`), and **must ignore caller buffer tail padding (`in->padding[idx]`) whenever horizontal filtering operates on IEEE-754 float inputs** (`ops_dispatch.c:229-231`) because `0.0f * NaN = NaN` would poison zero-padded boundary taps if uninitialized padding bytes contain `NaN` or `±Inf`.
- **Algebraic Unsoundness in `ops_optimizer.c` and `AVRational64`:** `AVRational64` (`rational64.c:117-147`) silently truncates exact 128-bit reduced rationals via continued-fraction convergents whenever `|num| > INT64_MAX` or `den > INT64_MAX`, breaking ring associativity and distributivity once denominators exceed $\lfloor\sqrt{2^{63}-1}\rfloor = 3,037,000,499$ (verified by executable counterexample). In `ops_optimizer.c`, transitive `SWS_OP_CONVERT` collapsing (`lines 582-587`), `UNPACK + PACK` cancellation on formats with unmasked upper padding bits such as `RGB555`/`RGB444` (`lines 437-445`), and commuting spatial filters past `SWS_OP_DITHER` (`line 187`) require explicit precondition guards to be semantically sound.
- **CMS Domain Skew and Vulkan SPIR-V vs CPU Precision Divergence:** `cms.c` and `lut3d.c` map HDR/SDR gamut transformations through Ebner-Fairchild `IPT`/`ICh` into a `65 × 65 × 65` tetrahedral 3D LUT, but legacy `lookup_input16` (`lut3d.c:110-120`) indexes `uint16_t` inputs at `65535 / 65536` of the `[0 .. 64]` grid (stopping at knot `63 + 1023/1024`), whereas `SwsOp` (`format.c:1767`) scales `[0, 1]` `f32` by `64.0f` to reach knot `64` directly. Furthermore, `SWS_BACKEND_SPIRV` (`vulkan/ops.c:722-756`) accumulates integer-source horizontal filter taps in `f32` (`OpConvertUToF` + `OpFMul` + `OpFAdd`) without `SpvDecorationNoContraction` even under `SWS_BITEXACT`, diverging from CPU C and AVX2 (`uops_tmpl.c:353-366`, `x86/ops_float.asm:147-289`), which accumulate exact integers (`int32_t`/`int64_t` or `pmaddwd`) before a single `f32` conversion.

## Applicability

This report characterizes `libswscale` and `libavutil` pixel-format descriptors in `FFmpeg/FFmpeg` at commit `7ddf7bc8a482cf28b4fab2e63b7093ba35cb6a80`, comparing its `SwsGraph`/`SwsOp` architecture against `sekrit-twc/zimg` at commit `67e0603271c080e22c8429856dd4a8a56587e61e` and evaluating its runtime SPIR-V emitter (`libswscale/vulkan/spvasm.h`, `libswscale/vulkan/ops.c`) against `KhronosGroup/SPIRV-Headers` at commit `50184103b19027f5c7080060712d6a9470cf59ee` and the Khronos SPIR-V 1.6 Revision 4 specification. Colorimetric equations and chroma-sample siting rules are evaluated against ITU-T H.273 (07/2024), ITU-R BT.2100-2 (07/2018), and SMPTE ST 2084:2014.

Scope and invocation distinctions:

- **Entry-Point Dispatch Coupling:** Callers invoking legacy stateful slice APIs (`sws_getContext`, `sws_init_context`, `sws_scale`) unconditionally execute `SWS_BACKEND_LEGACY`. Only stateless frame-level callers (`sws_alloc_context` + `sws_scale_frame` in `libswscale/graph.c:809-1052`) enter `SwsGraph`, and even there `prefer_ops_backend` (`graph.c:736-743`) selects `SwsOp` ahead of `SWS_BACKEND_LEGACY` only when `(ctx->flags & SWS_UNSTABLE)` is explicitly enabled or either endpoint carries `AV_PIX_FMT_FLAG_FLOAT`.
- **Companion Corpus Boundaries:** High-level `SwsContext` audio/video kernel census items appear in `aac-mp3-opus-flac-ac3-audio-codecs-imdct-and-swresample-swscale-kernels`; `AVFrame`/`AVBufferRef` reference counting and `vf_scale` filtergraph negotiation are covered in `libavfilter-graph-scheduling-frame-threading-and-avbufferref-lifetime-invariants`; general SIMD-vs-scalar proof tactics and floating-point interval/Gappa certificates are covered in `verified-simd-vs-scalar-equivalence-for-media-dsp-kernels-and-asm` and `formal-verification-of-media-parsers-fixed-point-dsp-and-panic-free-rust`. This report provides the deep format-matrix, rescaling-bound, `SwsOp` compiler soundness, CMS, and SPIR-V parity specifications absent from those packages.

## Findings

### 1. Dual-Backend Dispatch Architecture: `SWS_BACKEND_LEGACY` vs `SwsGraph` / `SwsOp`

`Basis: source`

`libswscale/swscale.h:110-129` defines the backend selection bitmask `SwsBackend`:

| Flag | Bit Value | Implementation Files | Execution Model |
| --- | --- | --- | --- |
| `SWS_BACKEND_LEGACY` (`SWS_BACKEND_STABLE`) | `1 << 0` (`0x01`) | `swscale.c`, `swscale_unscaled.c`, `hscale.c`, `vscale.c`, `input.c`, `output.c`, `yuv2rgb.c`, `rgb2rgb.c` | Monolithic special-case unscaled converters + coupled 15/19-bit fixed-point YUV444 ring-buffer scaler; optional x86 MMXEXT RWX JIT |
| `SWS_BACKEND_C` | `1 << 1` (`0x02`) | `ops_backend.c`, `uops.c`, `uops_tmpl.c` | Portable C micro-op (`SwsMicroOp`) interpreter/CPS chain over `[SWS_BLOCK_SIZE]` pixel blocks |
| `SWS_BACKEND_MEMCPY` | `1 << 2` (`0x04`) | `ops_memcpy.c` (`backend_murder`) | Zero-compute planar byte-copy / pointer-swizzle fast path when `SwsOpList` reduces to pure `READ` + `SWIZZLE` + `WRITE` |
| `SWS_BACKEND_X86` | `1 << 3` (`0x08`) | `x86/ops.c`, `x86/ops_common.asm`, `x86/ops_int.asm`, `x86/ops_float.asm` | CPS tail-chained SSE4.1 / AVX2 / FMA / AVX-512 static `.text` micro-kernels over `SwsOpChain` |
| `SWS_BACKEND_AARCH64` | `1 << 4` (`0x10`) | `aarch64/ops.c`, `aarch64/rasm.c`, `aarch64/ops_entries.c` | CPS tail-chained NEON static `.text` micro-kernels emitted ahead-of-time via custom register-assembler DSL (`rasm.h`) |
| `SWS_BACKEND_SPIRV` | `1 << 5` (`0x20`) | `vulkan/ops.c`, `vulkan/spvasm.h` | Runtime in-memory binary SPIR-V compute shader generation dispatched on `AV_PIX_FMT_VULKAN` storage images |

`SWS_BACKEND_UNSTABLE` is the union `(0x02 | 0x04 | 0x08 | 0x10 | 0x20) = 0x3E`, and `SWS_BACKEND_DEFAULT = 0` resolves to `SWS_BACKEND_ALL` (`0x3F`) (`swscale.h:126-128`, `graph.c:716-718`).

#### Graph Construction and Fallback Semantics

When `sws_scale_frame()` executes (`graph.c:990-1052`), `ff_sws_graph_create()` (`graph.c:809-948`) decomposes the conversion into an acyclic sequence of `SwsPass` nodes:

1. **Interlaced Field Splitting (`graph.c:839-862`):** If `SWS_FLAG_INTERLACED` or field mismatch applies, `SwsGraph` splits top and bottom fields (`FIELD_TOP`, `FIELD_BOTTOM`) into independent sub-graphs with halved height, doubled stride, and field-adjusted vertical chroma siting (`ff_sws_chroma_pos`), eliminating legacy interlaced vertical scaler quirks.
2. **Dynamic HDR / ICC Color Management (`graph.c:870-895`):** Inserts Gamut/Tone-Mapping 3D LUT passes (`ff_sws_Lut3d` in `lut3d.c`) when `ff_sws_color_map_noop(&color_map)` is false (primaries mismatch, HDR PQ/HLG tone-mapping, or explicit intent).
3. **Backend Preference & Mutual Fallback (`graph.c:706-763`):** `init_passes()` evaluates `prefer_ops_backend = (ctx->flags & SWS_UNSTABLE) || isFloat(fmt_in.fmt) || isFloat(fmt_out.fmt)` (`lines 736-743`). It attempts the preferred family first; if `compile_ops()` returns `AVERROR(ENOTSUP)` (for example, `NV12` or `YUV420P`), it falls back to `add_legacy_sws_pass()` (`graph.c:570-673`), and vice versa (for example, `XV30BE` or `RGB4`, which legacy rejects). Note that `AV_PIX_FMT_VULKAN` forces `SWS_BACKEND_SPIRV` exclusively (`graph.c:719-725`); if any generated `SwsOp` is unsupported on SPIR-V, no CPU fallback occurs without explicit `av_hwframe_transfer_data`.

#### Continuation-Passing SIMD (`SwsOpChain`) vs Legacy MMXEXT Runtime RWX JIT

A critical security and verification divide separates horizontal scaling dispatch in the two backends:

- **Legacy Self-Modifying MMXEXT RWX Codegen (`libswscale/x86/hscale_fast_bilinear_simd.c:30-250`, `libswscale/jit.c:40-60`):** When `SWS_FAST_BILINEAR` runs on x86 without `SWS_BITEXACT`, `ff_init_vscale_pfn` / `ff_getSwsFunc` allocates executable pages via `VirtualAlloc(..., PAGE_READWRITE)` or `mmap(..., PROT_READ | PROT_WRITE, MAP_PRIVATE | MAP_ANONYMOUS)` (`jit.c:44-49`), copies inline-assembly instruction templates (`0:`..`9:` labels in `ff_init_hscaler_mmxext`, `hscale_fast_bilinear_simd.c:66-135`) byte-by-byte into `lumMmxextFilterCode` / `chrMmxextFilterCode`, patches `pshufw` immediate bytes in place according to `(xpos >> 16)` step strides, appends `0xC3` (`RET`), and transitions pages to `PROT_READ | PROT_EXEC` (`jit.c:56-59`). Worse, during execution on x86-64 (`hscale_fast_bilinear_simd.c:205-232`), because the generated stub ends in `RET` while `%rsp` has not been adjusted as a normal ABI call site when tail-jumping across fragments, the inline assembly manually saves `-8(%rsp)` (inside the System V AMD64 red zone) into a local `uint64_t retsave` (`mov -8(%%rsp), %0`, `line 210`) before `call *%4` and restores `-8(%rsp)` afterward (`line 215`). Any W^X enforcement (`MemoryDenyWriteExecute=yes`, SELinux `execmem`, hardened iOS/macOS/Fuchsia/console kernels) causes `ff_jit_alloc` to fail, silently degrading `SWS_FAST_BILINEAR` to scalar C.
- **Modern `SwsOpChain` Continuation-Passing Style (`libswscale/ops_chain.h:42-119`, `x86/ops_common.asm`, `aarch64/rasm.c`):** `SwsOp` eliminates runtime code generation completely. `ff_sws_op_chain_alloc()` allocates a `1024`-byte aligned read-only-after-setup descriptor array `SwsOpImpl impl[SWS_MAX_OPS + 1]` (`SWS_MAX_OPS = 16`, `ops_chain.h:66-81`), statically asserting `offsetof(SwsOpImpl, priv) == 8` (`ops_chain.c` / `ops_chain.h:62`). Each `SwsOpImpl` holds an ahead-of-time `.text` function pointer `cont` and a `32`-byte inline `SwsOpPriv` payload (weights pointer, linear matrix constants, clamp bounds, or shuffle mask). Micro-kernels keep 4 pixel-channel SIMD register pairs (`mx/mx2`, `my/my2`, `mz/mz2`, `mw/mw2`, processing `SWS_BLOCK_SIZE` pixels per loop turn) live in vector registers and end with an indirect tail jump (`jmp [impl_ptr]` on x86-64, `br xN` on AArch64) advancing `impl_ptr += sizeof(SwsOpImpl)`. All executable instructions reside permanently in static `.text` (`ops_float.asm`, `ops_int.asm`, `aarch64/ops_entries.c`), satisfying strict W^X, CFI-compatible table membership (all targets come from static `SwsOpTable` registries), and modular per-micro-kernel verification.

### 2. Complete 270-Format `AVPixelFormat` Coverage Matrix Across `AVPixFmtDescriptor` Classes

`Basis: source + execution`

#### Architectural Boundary of Packed Broadcast `v210`

Broadcast SDI/QuickTime `v210` packs **three 10-bit unsigned components (`Cb0, Y0, Cr0` / `Y1, Cb2, Y2` / `Cr2, Y3, Cb4` / `Y4, Cr4, Y5`) into four 32-bit little-endian words (16 bytes per 6 horizontal luma pixels, with 2 unused MSB padding bits `[31:30]` per 32-bit word)**. Because `AVPixFmtDescriptor` (`libavutil/pixdesc.h:59-99`) restricts each `AVComponentDescriptor` to an affine byte/bit stride `step` per single pixel or 2-pixel pair (`8 / 3` bytes/pixel is non-integral), FFmpeg **cannot represent `v210` as an `AVPixelFormat`**. Instead, `v210` is modeled as a raw uncompressed codec (`AV_CODEC_ID_V210` / `AV_CODEC_ID_V210X` in `libavcodec/v210dec.c` and `libavcodec/v210enc.c`, with dedicated AVX2/AVX-512 `vpshufb`+`vpmulhuw`/`vpsrlvd` unpackers in `libavcodec/x86/v210.asm`) that decodes into planar 10-bit `AV_PIX_FMT_YUV422P10LE` before entering `libswscale`. By contrast, 1-pixel-periodic 10-bit 4:4:4:4 `XV30` / `V30X` (`4` bytes/pixel) and 2-pixel-periodic 10/12/16-bit 4:2:2 `Y210` / `Y212` / `Y216` (`4` bytes/pixel, `8` bytes per 2 pixels, matching `UYVY422` topology) fit `AVPixFmtDescriptor` directly. A clean-room Rust image pipeline should expose macro-pixel block descriptors (`block_width_px = 6, block_bytes = 16`) so `v210` unpacks directly inside fused horizontal scaling without an extra full-frame `YUV422P10LE` intermediate copy.

### 3. Separable 14-Bit Polyphase Rescaling, `AVChromaLocation` Siting, `filterPos`, and Ring-Buffer Bounds

`Basis: normative + source`

Both `SWS_BACKEND_LEGACY` (`initFilter` in `libswscale/utils.c:215-631`) and `SwsOp` (`ff_sws_filter_generate` in `libswscale/filters.c:71-325`) implement 2D scaling as two orthogonal 1D polyphase FIR convolutions with **14-bit signed fixed-point tap weights (`SWS_FILTER_SCALE = 1 << 14 = 16384`)**.

#### `AVChromaLocation` Subsample Siting Equations (ITU-T H.273)

`ff_sws_chroma_pos()` (`libswscale/format.c:578-617`) maps `enum AVChromaLocation` (`ITU-T H.273` Clause 8.3 `Chroma420SampleLocType` plus `4:2:2`/`4:1:0` generalizations) into `1/256`-pixel fixed-point sub-pel offsets `(x_pos, y_pos)` relative to top-left luma sample `(0, 0)`:

1. `av_chroma_location_enum_to_pos(&x_pos, &y_pos, pos)` maps `AVCHROMA_LOC_UNSPECIFIED -> AVCHROMA_LOC_CENTER = (128, 128)` (`0.5, 0.5`), `LEFT = (0, 128)` (`MPEG-2/H.264 default`), `TOPLEFT = (0, 0)` (`UHDTV BT.2020/BT.2100 Type 2`), `TOP = (128, 0)`, `BOTTOMLEFT = (0, 256)`, and `BOTTOM = (128, 256)`.
2. Offsets scale across arbitrary subsampling shifts `sub_x = log2_chroma_w`, `sub_y = log2_chroma_h` (`format.c:591-592`):
   $$x_{\text{chroma}} = x_{\text{loc}} \cdot (2^{\text{sub\_x}} - 1), \qquad y_{\text{chroma}} = y_{\text{loc}} \cdot (2^{\text{sub\_y}} - 1)$$
   For `4:2:0` (`sub_x = 1, sub_y = 1`), `CENTER` sits at `(128, 128)` (`+0.5` luma px horizontally and vertically); for `4:1:0` (`sub_x = 2, sub_y = 2`), `CENTER` sits at `(384, 384)` (`+1.5` luma px).
3. **Interlaced Field Siting (`format.c:599-612`):** When splitting an interlaced frame into fields (`field == FIELD_TOP` or `FIELD_BOTTOM`), `FIELD_BOTTOM` adds `(256 << sub_y) - 256` (`+1.0` luma row for `4:2:0`, `+3.0` luma rows for `4:1:0`) because bottom-field luma row `0` is frame row `1`, and then **both fields halve vertical siting (`y_pos >>= 1`, `line 612`)** because the vertical distance between adjacent field luma rows is `2` frame rows.

In continuous sample coordinates (`filters.c:232-246`), destination sample $i \in [0, D - 1]$ maps to source sample center:
$$x_{\text{src}}(i) = \frac{(i + 0.5 + \Delta_{\text{dst}}) \cdot S}{D} - 0.5 - \Delta_{\text{src}}$$
where $\Delta_{\text{src}}, \Delta_{\text{dst}} \in \mathbb{Q}$ are the normalized siting offsets (`pos / 256.0` divided by `1 << sub`). Note that legacy `SWS_FAST_BILINEAR` (`utils.c`, `swscale.c`) ignores fractional negative/boundary phase shifts and fixes `xInc = ((srcW - 2) << 16) / (dstW - 1) - 20` (unless `SWS_FULL_CHR_H_INP`), sacrificing sub-pel siting accuracy for non-branching 2-tap interpolation.

#### Polyphase Kernel Families and 14-Bit Error-Diffused Quantization

| --- | --- | --- | --- |

When downscaling (`dst < src`), filter support widens by `scale = src / dst` and tap arguments divide by `scale` to low-pass filter above the output Nyquist limit. Both engines quantize double-precision raw weights $f_j$ to `int16_t` `w_j` summing to `16384`, but **differ in final-tap rounding**:

- **Legacy `initFilter` (`utils.c:601-606`):** Accumulates floating/64-bit fixed cumulative error `error` and sets `v = filter[i * filterSize + j] * 16384 + error; intV = ROUNDED_DIV(v, sum); outFilter[...] = intV; error = v - intV * sum;`. Because `ROUNDED_DIV` rounds the final tap `j = filterSize - 1` rather than assigning the exact residual, pathological symmetric half-way ties can leave $\sum_j w_{i,j} = 16384 \pm 1$ before `SWS_ACCURATE_RND` normalization.
- **Modern `quantize_row` (`filters.c:97-143`):** Tracks `sum_pos` and `sum_neg` separately across `0 .. K - 2`, updates `err += w - v`, and **assigns the final tap deterministically as `out[K - 1] = (1 << 14) - (sum_pos + sum_neg)` (`line 133`)**, guaranteeing the exact algebraic invariant:
  $$\forall i \in [0, D - 1]: \quad \sum_{j = 0}^{K - 1} w_{i, j} = 16384 \quad \text{and} \quad w_{i, j} \in [-32768, 32767]$$
  `filters.c:137-141` additionally stores `weights->sum_positive = max_i(sum_pos)` and `weights->sum_negative = min_i(sum_neg)`, exposing tight worst-case fixed-point overshoot bounds $[B_{\min}, B_{\max}]$ to downstream IR passes: for unsigned $b$-bit inputs $x \in [0, 2^b - 1]$, the unshifted dot product satisfies $(2^b - 1)\cdot \text{sum\_negative} \le \sum_j w_{i,j} x_j \le (2^b - 1)\cdot \text{sum\_positive}$.

Both backends enforce a hard per-pass tap ceiling **`MAX_FILTER_SIZE = SWS_FILTER_SIZE_MAX = 256`** (`swscale_internal.h:59`, `filters.h:41`). Extreme downscales (e.g., `7680 -> 32` with `Lanczos-3`, which would require $6 \times 240 = 1440 > 256$ taps) are factored into multi-stage cascades: legacy `swscale.c` returns `RETCODE_USE_CASCADE` to build `cascaded_context[0..2]`, while `SwsOp` (`format.c:1728-1735`) recursively inserts an intermediate resize at the geometric mean $\lfloor\sqrt{S \cdot D}\rfloor$.

### 4. `SwsOp` IR Optimizer and `AVRational64` Rewrite Soundness Conditions

`Basis: source + execution + derived`

During compilation, `format.c` emits an unoptimized sequence of up to `SWS_MAX_OPS` typed pixel operations (`READ`, `SWAP_BYTES`, `UNPACK`, `CONVERT`, `EXPAND`, `SWIZZLE`, `CLEAR`, `SHIFT`, `SCALE`, `LINEAR`, `CLAMP`, `DITHER`, `FILTER_H`, `FILTER_V`, `LUT_3D`, `PACK`, `WRITE`), annotated via abstract interpretation (`ff_sws_op_list_update_comps` in `ops.c`) with per-channel `SwsComps` metadata: exact rational interval bounds `[min, max] : AVRational64` and `flags` (`SWS_COMP_GARBAGE`, `SWS_COMP_EXACT`, `SWS_COMP_ZERO`, `SWS_COMP_SWAPPED`). `ff_sws_op_list_optimize()` (`libswscale/ops_optimizer.c:96-1045`) iteratively rewrites this IR until fixed point.

#### Soundness Defect 1: `AVRational64` Silent Continued-Fraction Truncation Breaks Ring Laws

`libswscale/rational64.h` represents constants and `5 × 5` homogeneous affine color matrices (`SWS_OP_LINEAR`: $4 \times 4$ linear transform + $4 \times 1$ offset column) using signed 64-bit numerator/denominator pairs `AVRational64 { int64_t num, den; }`. In `libswscale/rational64.c:71-240`, `ff_add_q64` and `ff_mul_q64` compute exact 128-bit intermediate products (`AVInt128` / `__int128`) and divide out `gcd128(|num|, den)` inside `reduce64(..., int64_t max = INT64_MAX)`. However, **whenever the reduced exact numerator or denominator exceeds `INT64_MAX` ($2^{63} - 1 = 9,223,372,036,854,775,807$), `reduce64` (`rational64.c:117-147`) silently replaces the exact rational with its best bounded continued-fraction convergent** $p_k / q_k$ satisfying $|p_k|, q_k \le 2^{63}-1$.

Because continued-fraction truncation is non-homomorphic, **`AVRational64` violates both ring associativity and distributivity whenever pairwise denominator products exceed $2^{63} - 1$** (i.e., denominators exceeding $\lfloor\sqrt{2^{63}-1}\rfloor = 3,037,000,499$). Compiling and executing `libswscale/rational64.c` directly with prime denominators $p_1 = 3,037,000,507$ and $p_2 = 3,037,000,537$ (`p_1 * p_2 = 9,223,372,155,709,329,559 > INT64_MAX`) yields a concrete distributivity counterexample:

- Let $a = \frac{1}{3037000507}$, $b = \frac{1}{3037000537}$, and $k = \frac{3037000507}{1}$.
- `ff_add_q64(a, b)` truncates $\frac{6074001044}{9223372155709329559}$ to convergent $\frac{4832205275}{7337704971293076596}$, so:
  $$\texttt{ff\_mul\_q64}(k, \texttt{ff\_add\_q64}(a, b)) = \frac{9223372034368182397}{4611686039961594777} \approx 1.9999999901218324$$
- Distributing first keeps every intermediate exact ($k \cdot a = 1/1$ and $k \cdot b = 3037000507 / 3037000537$):
  $$\texttt{ff\_add\_q64}(\texttt{ff\_mul\_q64}(k, a), \texttt{ff\_mul\_q64}(k, b)) = \frac{6074001044}{3037000537} \approx 1.9999999901218326$$
- The two `AVRational64` results differ in both rational identity (`ff_cmp_q64 != 0`) and IEEE-754 `binary64` evaluation (`1` ULP = $2.2204 \times 10^{-16}$). Furthermore, `ff_inv_q64` (`rational64.h:131`) negates `x.num` directly (`x.num < 0 ? -x.num : x.num`), which invokes C signed-overflow UB if an unreduced caller ever constructs `x.num == INT64_MIN`.

**Mechanized Soundness Condition for `AVRational64` Rewrites:** During standard ITU-T H.273 YCbCr $\leftrightarrow$ RGB + Bradford XYZ matrix composition (`csputils.c`), source denominators have small decimal/power-of-two factors ($10^4 \cdot 255 \cdot 219 \ll 2^{31}$), keeping denominators below $10^{14} < 2^{63}-1$. A verified compiler must replace silent convergent truncation with **checked exact `i128` / `BigRational` arithmetic** during IR optimization and perform convergent/float rounding **once** at backend lowering (`q64_to_float`).

### 5. Color Management System (CMS), 3D LUT Interpolation, and Vulkan SPIR-V vs CPU SIMD Parity

`Basis: normative + source`

#### Perceptual Gamut Mapping (`cms.c`) and 3D LUT Topology (`lut3d.h`, `lut3d.c`)

Unlike legacy `libswscale` — which historically supported only linear $3 \times 3$ YCbCr $\leftrightarrow$ RGB matrices (`ITU-T H.273` `MatrixCoefficients` `1` BT.709, `5/6` BT.601, `9` BT.2020 NCL, `10` BT.2020 CL, `0` GBR, `7` SMPTE 240M, `8` YCgCo) without EOTF/OETF linearization or gamut mapping — `SwsGraph` includes a full Color Management System (`libswscale/cms.c`, `lut3d.c`, `csputils.c`):

1. **Color Appearance Space (`cms.c:60-210`):** Linearized tristimulus CIE XYZ (`D65`-adapted via Bradford cone-response matrix when `AVColorPrimaries` white points differ, e.g., SMPTE C / DCI-P3 Theater `DCI` white $\to$ `D65`) is transformed through the Hunt-Pointer-Estevez `LMS` matrix and **SMPTE ST 2084 PQ nonlinearity** ($m_1 = \frac{2610}{16384}, m_2 = \frac{2523}{32} = 78.84375, c_1 = \frac{3424}{4096}, c_2 = \frac{2413}{128}, c_3 = \frac{2392}{128}$, `ITU-R BT.2100-2` Table 4) into Ebner-Fairchild **`IPT`** opponent coordinates and cylindrical **`ICh`** (Intensity $I$, Chroma $C = \sqrt{P^2 + T^2}$, Hue $h = \operatorname{atan2}(T, P)$), preserving constant perceived hue lines without BT.2020 $\to$ BT.709 blue-to-purple hue shifts.
2. **Four Rendering Intents (`cms.c:350-560`):** Supports `SWS_INTENT_PERCEPTUAL` (SMPTE ST 2094-10 spline knee dynamic tone-mapping + Möbius rational `softclip` gamut compression along constant-$h$ rays), `SWS_INTENT_RELATIVE_COLORIMETRIC` (hard/clipping white-point-adapted projection), `SWS_INTENT_SATURATION`, and `SWS_INTENT_ABSOLUTE_COLORIMETRIC` (unadapted colorimetric white).
3. **3D LUT Discretization & Legacy vs `SwsOp` Domain Skew (`lut3d.h:33-60`, `lut3d.c:110-185`, `uops_tmpl.c:910-954`):**
   - `ff_sws_lut3d_generate()` bakes static gamut/EOTF transforms into a **`65 × 65 × 65` tetrahedral input 3D LUT** (`INPUT_LUT_BITS = 6`, `INPUT_LUT_SIZE = (1 << 6) + 1 = 65`, `1,098,500` `v3u16_t` bytes $\approx 1.65\text{ MiB}$), an optional **`257`-entry dynamic HDR 1D tone-mapping LUT** (`TONE_LUT_SIZE = 257`, updated per frame without rebuilding the 3D cube when `AVDynamicHDRPlus` / `AVMasteringDisplayMetadata` changes), and a `129 × 129 × 65` trilinear `IPT -> RGB` output LUT (`OUTPUT_LUT_SIZE_I = 129`, `OUTPUT_LUT_SIZE_PT = 65`).
   - **Tetrahedral Domain Asymmetry:** In the legacy wrapper pass (`lut3d.c:110-120`), `lookup_input16(const SwsLut3D *lut, v3u16_t rgb)` splits 16-bit `RGBA64` components via `Rx = rgb.x >> 10` (`[0 .. 63]`) and fractional weight `Rf = rgb.x & 0x3FF` (`[0 .. 1023]`, denominator `1024`). Consequently, **full-scale white `rgb = 65535` (`0xFFFF`) evaluates at `63 + 1023/1024 = 65535 / 65536 = 0.99998474` of the `[0 .. 64]` LUT grid**, interpolating `1023/1024` of knot `64` with `1/1024` of knot `63`! Conversely, in `SwsOp` (`format.c:1767`, `uops_tmpl.c:910-954`), normalized `[0.0f, 1.0f]` float channels are scaled by `INPUT_LUT_SIZE - 1 = 64.0f`, so `1.0f * 64.0f = 64.0f` lands directly on knot `64` with zero residual (`Rf = 0.0f`), producing a `1–2` LSB discrepancy in 16-bit output highlights between `SWS_BACKEND_LEGACY` and `SwsOp`.

#### Runtime SPIR-V Code Generator (`vulkan/spvasm.h`) vs CPU SIMD Parity (`vulkan/ops.c`)

`libswscale/vulkan/spvasm.h` implements a zero-dependency in-memory binary SPIR-V 1.6 assembler (`SpvAsm`) storing raw `uint32_t` words across five ordered section streams (`SPV_SECT_HEADER`, `SPV_SECT_DEBUG`, `SPV_SECT_DECORATIONS`, `SPV_SECT_GLOBALS`, `SPV_SECT_CODE`, matching Khronos SPIR-V Specification Section 2.4 Logical Layout and `KhronosGroup/SPIRV-Headers@50184103b19027f5c7080060712d6a9470cf59ee` opcodes). `libswscale/vulkan/ops.c` emits `32 × 32 × 1` `GLCompute` workgroups reading and writing `OpTypeImage` planes (`SpvCapabilityStorageImageReadWithoutFormat` / `WriteWithoutFormat`). Auditing `vulkan/ops.c` against `uops_tmpl.c`, `x86/ops_float.asm`, and `aarch64/ops.c` exposes four concrete parity boundaries:

1. **Horizontal Filter Tap Accumulation Precision Divergence (`vulkan/ops.c:213-214, 722-756` vs `uops_tmpl.c:353-366` and `x86/ops_float.asm:147-289`):**
   - **CPU C & x86 AVX2:** When filtering `U8` or `U16` source planes horizontally (`SWS_OP_FILTER_H` fused with `READ`), scalar C (`uops_tmpl.c:355-363`) accumulates `int32_t` (for `U8`, max $255 \times 32767 \times 256 < 2^{31}$? Note: for `U8`, `255 * sum_pos` is $\le 255 \times 32768 < 2^{24}$, exact in `int32_t`; for `U16`, `uops_tmpl.c:354` uses `int64_t sum = 0`) and converts **once** at the end: `(float)sum * (1.0f / (1 << 14))`. Note that multiplying by $2^{-14}$ in IEEE-754 `binary32` is an exact exponent subtraction (`exp -= 14`, zero mantissa rounding beyond the single `int -> f32` cast). x86 AVX2 (`x86/ops_float.asm:147-289`) similarly biases unsigned `uint16_t` pixels by `-0x8000`, executes exact integer `vpmaddwd` (`int16 × int16 -> int32` pairwise horizontal add), compensates `+0x8000 * 16384 = 1 << 29`, and performs one `vcvtdq2ps` + `vmulps` by `1.0f / 16384.0f`.
   - **Vulkan SPIR-V:** `emit_read_filtered()` (`vulkan/ops.c:722-756`) converts **every individual source integer pixel** to `f32` via `OpConvertUToF`, multiplies by the pre-normalized float weight `w_j / 16384.0f` via `OpFMul`, and accumulates sequentially via `OpFAdd` — **without attaching `SpvDecorationNoContraction` even when `SWS_BITEXACT` is enabled**. On 16-bit integer sources (`U16`) convolved with multi-lobe kernels (`Lanczos`, `Spline`, `Bicubic`) where positive sums reach $\approx 1.3 \times 65535 \approx 85,000$ before negative lobe cancellation, 24-bit `f32` significands suffer up to $K - 1$ intermediate roundings (and vendor-dependent FMA contraction on NVIDIA/AMD/Intel GPUs), diverging by `1–3` ULPs (up to `±1` code value after 16-bit quantization) from CPU `SWS_BITEXACT`.
2. **Linear `5 × 5` Matrix Evaluation Order & `SpvDecorationNoContraction` (`vulkan/ops.c:567-643`):**
   - Without `SWS_BITEXACT`, `insert_vmat_linear()` (`lines 567-588`) emits `OpMatrixTimesVector` followed by `OpFAdd(offset, prod)` (adding the affine offset **last**, allowing driver FMA reordering). Meanwhile, CPU AVX2 (`x86/ops_float.asm:610-720`) and AArch64 NEON (`aarch64/ops.c:239`) seed accumulators with the affine `offset` **first** and chain `vfmadd231ps` / `fmla`.
   - With `SWS_BITEXACT`, `insert_bitexact_linear()` (`vulkan/ops.c:590-643`) matches scalar C (`uops_tmpl.c:848-855`) by starting from `offset` and decorating every `OpFMul` (`line 623`) and `OpFAdd` (`line 626`) with **`SpvDecorationNoContraction`**. Even then, strict IEEE-754 bit-identity across Vulkan drivers requires `VK_KHR_shader_float_controls` (`shaderRoundingModeRTEFloat32` and `shaderDenormPreserveFloat32`), because baseline SPIR-V 1.6 allows subnormal `binary32` flush-to-zero (`FTZ`).
3. **Clamping & Out-of-Range Float-to-Integer Conversion (`vulkan/ops.c:515-565`):** SPIR-V `GLSL.std.450` `FClamp(x, minVal, maxVal)` (`min(max(x, minVal), maxVal)`) has implementation-defined result when `x` is `NaN` (`NClamp` propagates non-NaN bounds), whereas x86 SSE/AVX `vmaxps(src, lo)` returns the **second** operand (`lo`) when `src` is `NaN`, sanitizing `NaN -> lo` if ordered carefully, while `vcvttps2dq` maps `NaN` or $> 2^{31}-1$ to `0x80000000` (which truncates to `0x00` in `U8` if unclamped!) vs SPIR-V `OpConvertFToU` (undefined value on negative or out-of-range inputs per Khronos SPIR-V Spec §3.53.12). Thus `SWS_OP_CLAMP` before float-to-integer `SWS_OP_CONVERT` is a **soundness-critical safety barrier**, not merely a perceptual clamp.
4. **Unsupported SPIR-V IR Operations (`vulkan/ops.c:1127-1226`, `graph.c:795`):** `SWS_BACKEND_SPIRV` returns `AVERROR(ENOTSUP)` on `SWS_OP_LUT_3D` (3D LUT textures are not bound into `vulkan/ops.c`), sub-byte `READ_BIT`/`WRITE_BIT`/`READ_NIBBLE`/`WRITE_NIBBLE`, `READ_PALETTE` (`PAL8`), and `RW_SHUFFLE`.

### 6. Clean-Room Verification Priority Stack and Rust Rewrite Architecture

`Basis: derived`

Synthesizing the source, execution, and specification findings across the four-level media verification stack establishes concrete design invariants for a clean-room Rust `libswscale` replacement:

1. **Level 1 — Undefined-Behavior (UB) Freedom:**
   - **Eliminate Runtime RWX Codegen:** Never port `jit.c` / `hscale_fast_bilinear_simd.c`; AOT CPS micro-kernel tables (`SwsOpChain` style, implemented in safe Rust as `&[StepFn]` slices or enum-dispatched tile loops over `core::arch` intrinsics) match or exceed MMXEXT JIT speed while preserving strict W^X and stack red-zone invariants.
   - **Bound SIMD Gather & Filter Tail Overreads:** Enforce `1 <= filter_size <= src_size` and `0 <= offsets[i] <= src_size - filter_size` at filter-table construction (`filters.c` model, never legacy `filterSize > srcW`). Split every row/tile loop into a vector body `[0 .. safe_simd_end]` where `offsets[i] + simd_lane_span <= src_size` and a scalar/masked tail `[safe_simd_end .. dst_size]`, eliminating caller `64`-byte `AV_INPUT_BUFFER_PADDING_SIZE` preconditions on Rust `&[u8]` slices.
   - **Sanitize `NaN` at Float Ingress & Before `f32 -> int` Casts:** Never multiply uninitialized padding bytes by `0.0f` (`ops_dispatch.c:229-231` hazard), and require a verified non-NaN clamping stage (`x.clamp(0.0, max_val)` with explicit NaN-to-zero lowering) immediately preceding any float-to-unsigned conversion.
2. **Level 2 — Panic-Freedom:**
   - Encode polyphase index bounds in a constructive witness struct `VerifiedPolyphaseWeights { filter_size: NonZeroUsize, offsets: Box<[u32]>, weights_q14: Box<[i16]> }` checked once during setup (`src_size >= filter_size`, `offsets.iter().all(|&o| o as usize + filter_size <= src_size)`, `weights_q14.len() == offsets.len().checked_mul(stride)`), allowing inner scanline kernels to use `get_unchecked` with machine-checked proof obligations (Lean 4 MIR slice bounds; see `formal-verification-of-media-parsers-fixed-point-dsp-and-panic-free-rust`).
   - Replace `AVRational64` with checked `i128` rational arithmetic (`Option<Rational128>`) that falls back cleanly to arbitrary-precision `BigRational` or explicit dyadic rounding rather than overflows or silent continued-fraction drift.
3. **Level 3 — Behavioral Equivalence to FFmpeg & Verified SIMD-vs-Scalar Equivalence:**
   - **Fixed-Point Kernels (`U8`/`U16` horizontal FIR & `solve_shuffle`):** Prove bit-exact SIMD-vs-scalar equivalence over bitvectors (`vpmaddwd` + `0x8000` bias == scalar `i64` sum; `pshufb`/`vtbl` == byte provenance spec; see `verified-simd-vs-scalar-equivalence-for-media-dsp-kernels-and-asm`).
   - **Floating-Point Linear & Transfer Kernels:** Separate two explicit contract modes: (a) **`BitExact` mode** using uncontracted IEEE-754 `binary32` operations in fixed left-to-right accumulation order (`offset + c0*m0 + c1*m1 + c2*m2 + c3*m3`), matching scalar C and `insert_bitexact_linear` (`NoContraction`), and (b) **`FastFma` mode** proved within a bounded ULP envelope ($\le \epsilon$ ULPs, zero overflow on finite clamped domains) against the exact $\mathbb{R}$ rational specification.
4. **Level 4 — Normative Specification Conformance & Cache-Optimal Modular Architecture:**
   - Rather than copying `SwsGraph`'s two biggest limitations — (a) **0% subsampled/semi-planar format support** in `SwsOp` and (b) **full-frame DRAM `SwsPassBuffer` intermediates** between `FILTER_H` and `FILTER_V` — a clean-room Rust engine should combine **`SwsOp`'s typed micro-op compiler** with **`sekrit-twc/zimg`'s L2-resident power-of-two plane ring buffers (`16–32` scanlines per plane)** and **first-class per-plane subsampling ratios `(sub_x, sub_y)` + macro-pixel block unpackers (`NV12`, `P010`, `UYVY422`, `v210`, Bayer CFA, `F16`, `XYZ12`)**. In that unified graph, chroma planes run their own horizontal/vertical `SwsOp` filter passes at `src_chroma -> dst_chroma` with `ff_sws_chroma_pos` phase offsets before fusing into the final output packing/matrix stage, achieving 100% coverage of all `253` software formats (+ `v210`) in a single memory-safe architecture.

- **Live GPU Shader Execution (`not examined`):** This investigation audited `libswscale/vulkan/spvasm.h` and `libswscale/vulkan/ops.c` at source and opcode level against `KhronosGroup/SPIRV-Headers@50184103b19027f5c7080060712d6a9470cf59ee` and the Khronos SPIR-V 1.6 specification, but did not execute generated shaders on physical discrete/integrated Vulkan hardware (`AMD RADV`, `NVIDIA`, `Intel ANV`, `Lavapipe`).
