# Secret-Leak Detection, Git Object Persistence, Entity-Level PII Anonymization, and Contextual-Integrity Minimization for Tool-Using Agents

## Summary

Primary-source inspection of ten peer-reviewed studies (2019–2025), five pinned open-source repositories (`Yelp/detect-secrets@5e141933554a0b74e7341841f318be21e895339c`, `gitleaks/gitleaks@5f6ec56cfa6f8c67648d863582c7ae2f206d5c1c`, `trufflesecurity/trufflehog@4ef51f69ca6347aaa76a5e64a87eac9c0c909f71`, `microsoft/presidio@61fde811ebee29493a3b8c608d25d2f96e072f26`, and `NorskRegnesentral/text-anonymization-benchmark@558e09e26d6b36f5f78440074e6a233946d98bd9`), and a deterministic five-probe Python 3.10+ verification suite (`scripts/verify_secret_scanning_pii_redaction.py`) establishes five engineering invariants for credential sanitization, Git history hygiene, PII anonymization, and outbound user-vault disclosure in tool-using LLM systems:

1. **Scalar Shannon Entropy Cannot Separate Hexadecimal Credentials from Source Identifiers, Default Scanner Pipelines Harbor `.env` and Passphrase Blind Spots, and Offline Checksum Gating Eliminates Classic-PAT Noise:** Unnormalized character Shannon entropy $H(X) = -\sum_{c \in \Sigma} p_c \log_2 p_c$ is bounded above by $\log_2 |\Sigma|$, capping every hexadecimal key or SHA-256 digest at $4.0000$ bits/char (`3.8509` on a synthetic 64-hex digest), strictly below benign mixed-case identifiers over $|\Sigma| = 52$ (`"ThisIsAReallyLongString"`, $H = 4.0888$), while `gitleaks`'s `shannonEntropy` (`detect/utils.go:127`) divides rune counts by UTF-8 byte length (`len(data)`), reporting `2.0000` instead of `3.0000` bits/rune on 8 distinct 2-byte UTF-8 runes. Across `SecretBench` (`Basak, Neil, Reaves, & Williams, MSR 2023`, `84.53%` false positives across `97,479` candidates) and `Basak, Cox, Reaves, & Williams (ESEM 2023)` (`Gitleaks` `P = 0.46, R_1 = 0.86`; default `TruffleHog` `P = 0.06`), regex/entropy scanners suffer both severe false-positive noise and silent parser gaps: in `detect-secrets@5e141933`, `scan_file` short-circuits after Pass 1 (`if has_secret: break` at `scan.py:162-163`), preventing `EagerConfigFileTransformer` from running whenever a `.env` file contains even one quoted password or `ghp_` token and dropping `100%` of remaining unquoted secrets in that file, while `scan_diff` (`scan.py:169-179, 283-306`) runs zero file transformers; in `gitleaks@5f6ec56c`, `generic-api-key` (`config/gitleaks.toml:637-2128`) unconditionally allowlists `^[a-zA-Z_.-]+$` (`lines 655-657`), suppressing high-entropy digit-free passphrases (`"correct-horse-battery-staple-alpha"`, $H = 3.5581 > 3.5$). Adding an offline Base62 IEEE 802.3 CRC-32 check on 40-character classic GitHub tokens (`ghp_`/`gho_`/`ghu_`/`ghs_`/`ghr_`, while routing stateless `>40`-character `ghs_` installation tokens and `github_pat_` through format-appropriate validators) eliminates **`200/200` (`100%`)** un-checksummed placeholder false positives ($62^{-6} \approx 1.76 \times 10^{-11}$ uniform random Base62 acceptance; $2^{-32} \approx 2.33 \times 10^{-10}$ payload CRC-32 collision) with **`50/50` (`100%`)** recall on CRC-valid tokens at zero network cost, while static data-flow pairing (`AssetHarvester`, `Basak, English, Ogura, Kambara, Reaves, & Williams, ICSE 2025`, `DOI: 10.1109/ICSE55347.2025.00067`) reaches `97%` precision and `90%` recall (`94%` F1) on context-dependent database credentials.
2. **Amended and Rebased Secrets Evade Both Working-Tree Scanners and `--all` Git History Walkers Until Object-Store Pruning:** Deleting a committed credential via `git rm` (the predominant remediation observed by `Meli, McNiece, & Reaves, NDSS 2019`, where `81%` of leaked GitHub secrets remained exposed at `HEAD` after 16 days) hides the token from working-tree scanners (`detect-secrets` `scan_file`) while leaving it visible to `gitleaks` (`git log -p -U0 --full-history --all --diff-filter=tuxdb`) and `trufflehog` (`git rev-list --full-history --all`). Overwriting a committed credential via `git commit --amend`, `git rebase`, or `git push --force` hides the dangling commit from **both** working-tree scanners **and** `gitleaks`/`trufflehog` `--all` ref walks, yet leaves the cleartext blob recoverable via `git cat-file --batch-all-objects` and direct commit-SHA lookup (`git show <sha>`) until reflog expiration plus `git gc --prune=now`.
3. **Token-Level PII Recall Masks Catastrophic Direct-Identifier Entity Leakage (`ER_di`), Compounded by Two Live `TAB@558e09e2` Evaluator Defects:** Under `TAB`'s conjunctive `is_masked` oracle (`Pilán et al., Computational Linguistics 2022`; `evaluation.py:420-433`), leaving a single coreferent mention unmasked exposes the entity across the entire document. On `TAB` Test (`echr_test.json`), default `Presidio` achieves `0.707` token recall ($R_{di+qi}$) and `0.758` quasi-identifier entity recall ($ER_{qi}$), **but direct-identifier entity recall collapses to `ER_di = 0.460`** (`0.463` with `+ORG`) because `echr_test.json` `DIRECT` entities (`1,157` total) split almost evenly between `PERSON` (`575`, `49.7%`, `24.52%` multi-mention up to $m = 15$, suffering $r_1 \cdot r_{\text{anaphor}}^{m-1}$ coreference decay) and unrecognized structured `CODE` case/application numbers (`572`, `49.4%`), with `ORG` comprising only `5 / 1,157` (`0.43%`). Direct source and dataset inspection at `TAB@558e09e2` also uncovers two live `evaluation.py` defects: `line 405` freezes `is_direct` on an entity's first mention (misclassifying `26` `QUASI -> DIRECT` entities across `echr_{dev,test,train}.json`: `3` dev, `4` test, `19` train), and `line 236` (`_get_mask_counts`) iterates `entity.mentions` instead of the uncalled `AnnotatedEntity.mentions_to_mask` property (`lines 92-94`), treating `332` explicitly `"NO_MASK"` mentions across `145` mixed-masking entities in `echr_test.json` (`859` corpus-wide) as recall false negatives when left unmasked.
4. **`Presidio@61fde811` Checksum `MAX_SCORE` Clobbering and Context-Enhancer Asymmetries Cause Simultaneous False Positives and Missed SSNs:** `PatternRecognizer.__analyze_patterns` (`pattern_recognizer.py:257-261`) overwrites base pattern confidence (`0.3`) with `MAX_SCORE = 1.0` whenever `validate_result` returns `True`, causing modulo-10 Luhn validation in `CreditCardRecognizer` to promote **`998 / 10,000` (`9.98%`)** of contextless 16-digit CI/trace IDs (`ci_build_trace_id=4...`) to maximum confidence `1.0` and rendering `CreditCardRecognizer.CONTEXT` dead code. Meanwhile, `UsSsnRecognizer` (`us_ssn_recognizer.py:18-88`) scores invalid SSA `900–999` prefixes (`"900-12-3456"`) at `0.50` while capping context-boosted undelimited 9-digit SSNs (`SSN4`) at `0.40`, and `LemmaContextAwareEnhancer` defaults to `context_matching_mode="substring"` (boosting `"duplicate job 84729104"` from `0.01` to `0.40` via `"lic" in "duplicate"`), `context_suffix_count=0` (missing `"234567891 (ssn)"` at `0.05`), and punctuation-stripped `keywords` (`nlp_artifacts.py:54-61`, allowing `"ssn# 234567891"` to match `"ssn"` at `0.40` while `"ss# 234567891"` [`iss:1452`, `us_ssn_recognizer.py:33`] stays at `0.05` even if `"ss#"` is added to `CONTEXT`).
5. **Contextual-Integrity Protection Requires Pre-Interaction Minimization $M_d(D, c_0)$ Paired with a Trusted Escalation Gate:** LLMs leak memorized credentials (`CodexLeaks`, `~8%` / `43` prompts; `Huang et al., PACMSE/FSE 2024`, `2,702 / 8,127` plausible Copilot completions including `2` live secrets) and violate Contextual Integrity norms in multi-step tool actions despite `94.3%–100%` static QA accuracy (`ConfAIde` `39%–57%` vignette leaks; `PrivacyLens` `25.68%–38.83%` $LR_h$; `AirGapAgent` `94% -> 45%` protection drop under single-query context hijacking, restored to `97%` by pre-interaction minimization $M_d(D, c_0)$). Over a **5-scenario constructive separation matrix** (`Probe 5`), static NER span scrubbers fail both utility (`0/5`) and non-NER relational privacy (`2/5` leaked), unisolated ReAct trajectories leak across hijacks, implicit norms, and spoofed branches (`3/5` leaked), strict one-shot $M_d(D, c_0)$ sacrifices legitimate conditional multi-hop tasks (`4/5` utility, `0/5` leaked), and permissive conditional pre-release re-opens adaptive branch spoofing (`5/5` utility, `1/5` leaked); only pairing $M_d(D, c_0)$ with a **Verified Escalation Gate** (trusted-source attestation or explicit user step-up confirmation) achieves `5/5` utility with `0/5` leakage.

### 2. Shannon-Entropy Alphabet Ceiling, Scanner Filter/Transformer Seams, and Offline Checksum Verification

`Basis: source + derived`

#### 2.1 Alphabet Entropy Inversion and `gitleaks` Multi-Byte UTF-8 Distortion

- **Alphabet Ceiling Theorem:** For any string $X$ drawn from an alphabet $\Sigma$, unnormalized character Shannon entropy $H(X) = -\sum_{c \in \Sigma} p_c \log_2 p_c$ satisfies $H(X) \le \log_2 |\Sigma|$. Every hexadecimal API key, HMAC key, or SHA-256 digest ($|\Sigma| = 16$) satisfies $H(X) \le \log_2 16 = 4.0000$ bits/char (`H = 3.8509` on `Probe 1`'s synthetic 64-character SHA-256 hex digest), strictly below benign mixed-case source identifiers over $|\Sigma| = 52$ (`"ThisIsAReallyLongString"` yields **`H = 4.0888`**). Scalar entropy gates without alphabet normalization or structural prefixes inevitably misclassify either hexadecimal keys (false negatives when threshold $> 4.0$, such as `detect-secrets`'s `Base64HighEntropyString` `limit = 4.5`) or camelCase identifiers and path fragments (false positives when threshold $\le 3.5$).
- **`gitleaks` UTF-8 Byte-Length Denominator Bug (`detect/utils.go:117-134`):** In `gitleaks@5f6ec56c`, `shannonEntropy(data string)` iterates `for _, char := range data` (counting Unicode **runes**) but sets `invLength := 1.0 / float64(len(data))` at `line 127` (dividing by **UTF-8 byte length** rather than rune count) and enforces `if entropy <= r.Entropy { return }` (`detect/detect.go:547`). On 8 distinct 2-byte UTF-8 runes (`"\u00e9\u00fc\u00f1\u00f8\u00e5\u00df\u00e7\u00eb"`, byte length `16`), `shannonEntropy` computes $8 \times \frac{1}{16} \log_2 16 = \mathbf{2.0000}$ instead of the true rune entropy $\log_2 8 = \mathbf{3.0000}$ (`Probe 1`), artificially depressing calculated entropy whenever non-ASCII characters appear inside a captured candidate.

#### 2.2 `Yelp/detect-secrets@5e141933` Plugin, Filter, and `.env` Transformer Seams

Under `default_settings()` (`detect_secrets/settings.py:63-75, 126-155`), `detect-secrets` enables all **27 concrete `secret_type` plugins** alongside **12 default filters** (`heuristic.py`) and file transformers (`scan.py:140-179, 253-307`, `transformers/config.py:18-123`):

1. **Numeric-Hex Penalty Redundancy vs. Single-Hex-Letter Escape (`high_entropy_strings.py:168-197` vs. `heuristic.py:38, 220-225`):** `HexHighEntropyString.calculate_shannon_entropy` subtracts `1.2 / log2(len(data))` when `int(data)` succeeds, pushing 10-digit `"0123456789"` below threshold (`H = 2.9607 <= 3.0`) while leaving non-sequential 20-digit `"90817263541357924680"` above threshold at the plugin layer (`H = 3.0443 > 3.0`). Under `default_settings()`, however, `is_not_alphanumeric_string` (`heuristic.py:220-225`, enabled at `settings.py:145`) rejects every candidate lacking `[A-Za-z]` (`default_alerts = 0`), rendering the `int(data)` penalty redundant on pure digits. Conversely, replacing a single digit with one hex letter `a–f` (`"9081726354135792468a"`) simultaneously causes `int(data)` to raise `ValueError`—jumping unpenalized `ds_hex_shannon_entropy` to **`3.4219 > 3.0`**—and satisfies `is_not_alphanumeric_string`, producing a false-positive alert (`19d+1hex_alerts = 1` in `Probe 1`).
2. **Three Unquoted `.env` Bypasses (`scan.py:153-179, 253-306`, `util/filetype.py:27-54`, `transformers/config.py:18-103`):** While YAML (`YAMLTransformer`) and INI/CFG (`ConfigFileTransformer`) rewrite unquoted assignments into synthetic `key = "value"` lines on Pass 1, `determine_file_type(".env")` returns `FileType.OTHER` (`filetype.py:27-54`). On `.env`, Pass 1 runs raw lines against quote-requiring `HighEntropyStringsPlugin` (`high_entropy_strings.py:59-70`) and `QUOTES_REQUIRED_DENYLIST_REGEX_TO_GROUP` (`keyword.py:243-260`). Only when Pass 1 finds **zero** secrets (`has_secret == False`) does `scan_file` rewind and run Pass 2 `EagerConfigFileTransformer` (`config.py:29-40, 66, 90-103`), prepending `[global]\n` and catching pure unquoted `.env` files (`env_pure_caught = True`):
   - *Pass-1 Short-Circuit Shadowing (`scan.py:162-163`):* Because `scan_file` executes `if has_secret: break` immediately after Pass 1, **if even one quoted password or quote-agnostic `ghp_` token appears anywhere in a `.env` file, `EagerConfigFileTransformer` never executes**, silently dropping **`100%`** of remaining unquoted high-entropy and keyword secrets in that file (`env_shadowed_caught = False` in `Probe 1`).
   - *`scan_diff` Zero-Transformer Gap (`scan.py:169-179, 283-306`):* `scan_diff` feeds `unidiff` `line.value` strings (`scan.py:300`, stripped of leading `'+'`) directly to plugins without calling `get_transformed_file`, missing **`100%`** of unquoted `.env` entropy/keyword secrets in pre-commit and CI diff scans (`env_diff_caught = False` in `Probe 1`).
   - *`ConfigParser` Crashes, Keyword Omissions, and Lock/Template Gaps:* Shell `export KEY=val` lines or unescaped `%` interpolation characters raise `configparser.Error -> ParsingError` (`config.py:94, 103`); `KeywordDetector.DENYLIST` (`keyword.py:43-62`) omits `token` and `bearer`; `GitHubTokenDetector` (`github_token.py:9-16`) matches `(ghp|gho|ghu|ghs|ghr)_[A-Za-z0-9_]{36}` while omitting fine-grained `github_pat_`; and while `is_lock_file` (`heuristic.py:204-217`) hardcodes `12` basenames and `is_non_text_file` (`heuristic.py:86-88, 118, 128`) already excludes all `.lock` and `.sum` extensions (`uv.lock`, `bun.lock`, `flake.lock`), non-`.lock` artifacts **`pnpm-lock.yaml`**, **`npm-shrinkwrap.json`**, and **`.env.example`** (`FileType.EXAMPLE`, `filetype.py:31`) remain un-excluded.

#### 2.3 `gitleaks@5f6ec56c` `generic-api-key` Structure (`config/gitleaks.toml:637-2128`)

In `gitleaks@5f6ec56c`, the `[[rules]]` `id = "generic-api-key"` block spans **`config/gitleaks.toml:637-2128`** (`github-app-token` begins at `line 2130`):

- **Capture Regex & Entropy Gate (`lines 640-641`):** Matches case-insensitive credential identifiers (`(?i)...(?-i:[Aa]pi|API)...`) followed by capture group 1 `([\w.=-]{10,150}|[a-z0-9][a-z0-9+/]{11,}={0,3})` with `entropy = 3.5`. Passwords containing symbols excluded from `[\w.=-]` before a closing quote (such as `'!'`) fail regex capture outright, while 10-character alphanumeric passwords such as `"Summer2025"` match `\w{10}` and are suppressed by **`gitleaks_shannon_entropy("Summer2025") = 2.9219 <= 3.5`** (`alerts = 0` in `Probe 1`).

#### 2.4 Offline Checksum Verification vs. `trufflehog@4ef51f69` Active HTTP Verification Hazards

- **Offline Base62 IEEE CRC-32 Gate for 40-Character Classic GitHub Tokens:** Classic 40-character GitHub tokens (`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`) consist of a 4-character prefix, a 30-character Base62 payload (`token[4:34]`), and a 6-character big-endian `'0'`-padded Base62 encoding (`token[34:40]`, over `0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz`) of the unsigned 32-bit IEEE 802.3 CRC-32 (`zlib.crc32`) of the 30-character ASCII payload. Neither `detect-secrets` (`github_token.py:15`), `gitleaks` (`gitleaks.toml:2144-2168`), nor `trufflehog` (`pkg/detectors/github/v2/github.go:37-116`) checks this checksum offline.
  - *Exact Acceptance vs. Collision Probability:* Because `base62_encode_u32(crc32(payload), 6)` maps each 30-character payload to **1** canonical 6-character string in `["000000", "4gfFC3"]` ($2^{32} = 4{,}294{,}967{,}296$ reachable `u32` encodings out of $62^6 = 56{,}800{,}235{,}584$ 6-character Base62 trailers), a uniform random 36-character Base62 string matching `ghp_[0-9A-Za-z]{36}` passes offline verification with probability **$62^{-6} \approx 1.76 \times 10^{-11}$** ($13.2\times$ lower than the $2^{-32} \approx 2.33 \times 10^{-10}$ CRC-32 payload collision probability across two distinct payloads that already carry valid `u32` trailers). In `Probe 1`, `detect-secrets` and `gitleaks` flag **`200/200`** un-checksummed synthetic `ghp_` test fixtures, whereas `verify_ghp_offline_crc32` reduces fixture false positives to **`0/200` (`0%`)** while retaining **`50/50` (`100%`)** recall on CRC-valid tokens.
  - *Stateless `>40`-Character `ghs_` and `github_pat_` Qualification:* As reflected in `trufflehog@4ef51f69` (`pkg/detectors/github/v2/github.go:37` `keyPat` `(?:ghp|gho|ghu|ghs|ghr)_[a-zA-Z0-9_]{36,255}` and `github_test.go:26-32`), GitHub server-to-server (`ghs_`) installation tokens also include newer stateless `>40`-character tokens alongside 40-character classic CRC-32 tokens. Offline 6-character Base62 CRC-32 gating must therefore be scoped to **40-character** classic `ghp_`/`gho_`/`ghu_`/`ghs_`/`ghr_` tokens, routing `>40`-character `ghs_` tokens and `github_pat_` tokens through format-specific structural validation rather than rejecting `len != 40`.
- **Active HTTP Verification Hazards (`trufflehog@4ef51f69`):** `trufflehog` models verification as a tri-state outcome on `detectors.Result` (`Verified: bool`, `VerificationSkipped: bool`, private `verificationError: error` via `SetVerificationError` at `pkg/detectors/detectors.go:112-183`), gated downstream by `FilterUnverified` (`pkg/engine/engine.go:127-140`). While active verification (`VerifyGithub` at `pkg/detectors/github/v1/github_old.go:151-183`) distinguishes live from revoked CRC-valid tokens (`6% -> 90%` precision in `Basak et al., ESEM 2023`), relying on `--only-verified` introduces two operational hazards in agentic sandboxes: (1) outbound proxy blocks or transient network errors set `Verified: false` + `verificationError != nil`, silently converting live leaked credentials into **false negatives** under `--only-verified`; and (2) detectors implementing `EndpointCustomizer` (`UseFoundEndpoints: true`, `detectors.go:26-45, 90-97`) send live authentication probes to URLs extracted from untrusted source files, risking **canary/honeytoken tripwire alerts** and **SSRF egress**.

### 7. Architectural Synthesis for Sanitization and Disclosure Pipelines

`Basis: derived`

1. **Layered Secret Detection (Prefix + Offline Checksum/Structure $\to$ Data-Flow Pairing $\to$ Isolated Opt-In Active Verification):**
   - Never gate hexadecimal secrets on unnormalized scalar Shannon entropy alone, and never rely on `detect-secrets` `scan_diff` (or mixed-content `.env` Pass-1 `scan_file`) to catch unquoted `.env` secrets.
   - Enforce **offline deterministic structural/checksum validators first**: 6-character Base62 IEEE CRC-32 on **40-character** classic `ghp_`/`gho_`/`ghu_`/`ghs_`/`ghr_` tokens (while routing stateless `>40`-character `ghs_` installation tokens and `github_pat_` tokens through format-specific validators), ISO 7064 mod-97 on IBANs, and ASN.1 DER consistency on PEM keys; pair contextless passwords and database URIs with static data-flow asset pairing (`AssetHarvester`).
   - Run active HTTP verification (`trufflehog`) strictly in egress-isolated environments with `UseFoundEndpoints = false` by default, and treat `verificationError != nil` as **indeterminate (requires offline/human review)** rather than clean.
2. **Pre-Push Git Object-Graph Hygiene and Post-Push Credential Rotation:**
   - Pre-push sanitizers must scan **both** reachable commit diffs (`git log --all -p`) **and** unreachable/amended objects (`git cat-file --batch-all-objects`) whenever local history was amended or rebased; once any credential reaches a remote ref or pull-request commit SHA, mandate immediate **credential revocation and rotation** rather than `git rm` or `git commit --amend`.
3. **Entity-Level Coreference Propagation (`ER_di`) and Hardened `Presidio` Configuration:**
   - Gate PII anonymizers on conjunctive entity-level recall (`ER_di`, `ER_qi`), propagate every detected entity across **all coreferent surface forms** (bare-surname anaphors, dropped honorifics) within the document window, register domain-specific structured `CODE` recognizers (case/ticket/account IDs), and emit **consistent per-entity pseudonyms (`<PERSON_1>`, `<PERSON_2>`)** when downstream reasoning requires multi-party disambiguation.
   - When deploying `Presidio`, cap checksum `validate_result` boosts below `score_threshold` unless corroborated by `whole_word` bidirectional (`context_suffix_count > 0`) context, reject SSA `900–999` prefixes in `UsSsnRecognizer`, and handle punctuation-split context tokens (`"ss"` + `"#"`).
4. **Two-Stage Air-Gapped Contextual Integrity Minimization:**
   - Compute $M_d(D, c_0)$ over the user's trusted initial request $c_0$ before ingesting untrusted tool outputs, and gate any conditional multi-hop attribute escalation behind **trusted-channel attestation or explicit user step-up confirmation**, never untrusted third-party tool claims.

## Boundaries

- **`known not to apply` — Unnormalized Scalar Shannon Entropy as a Hexadecimal-Secret Classifier:** Unnormalized Shannon entropy cannot separate hexadecimal secrets ($H \le 4.0000$) from mixed-case identifiers (`"ThisIsAReallyLongString"`, $H = 4.0888$) without alphabet normalization or structural prefixes.
- **`known not to apply` — Unconditional 40-Character Base62 CRC-32 Gating on All `ghs_` Tokens or `github_pat_`:** Requiring `len == 40` + Base62 CRC-32 across all `ghs_` prefixes causes false negatives on newer stateless `>40`-character `ghs_` server-to-server tokens (`[a-zA-Z0-9_]{36,255}` in `trufflehog` `pkg/detectors/github/v2/github.go:37`); the 6-character Base62 CRC-32 check applies specifically to 40-character classic `ghp_`/`gho_`/`ghu_`/`ghs_`/`ghr_` tokens.
- **`known not to apply` — Pure-Digit `HexHighEntropyString` Alerts Under `detect-secrets` Defaults or `.lock`-Extension Blindness:** Under `detect-secrets@5e141933` `default_settings()`, `is_not_alphanumeric_string` suppresses all pure-digit strings (`[0-9]+`), so end-to-end numeric false positives require at least one hex letter `a–f` (`"9081726354135792468a"`, $H = 3.4219$); similarly, `is_non_text_file` already excludes every `.lock` and `.sum` filename (`uv.lock`, `bun.lock`, `flake.lock`), restricting un-excluded lock/template exposure to non-`.lock` names such as `pnpm-lock.yaml`, `npm-shrinkwrap.json`, and `.env.example`.
- **`known not to apply` — `git log --all` / `git rev-list --all` Cleanliness as Object-Store Cleanliness, or Quantitative Equivalence Between Synthetic Fixtures and Live Neural Benchmarks:** Passing `gitleaks` or `trufflehog` `--all` scans does not establish that `.git/objects` or remote forge stores are free of `--amend`/rebased secrets (`Probe 2`). Likewise, `Probe 3`'s 300-entity synthetic fixture (`mention_recall = 0.720`, `token_level=False`) and `Probe 5`'s 5-scenario constructive matrix (`0/5` through `5/5`) establish mechanistic and structural separation rather than empirical NLP or LLM sampling rates.
- **`unsupported` — Transformer Pre-Processing in `detect-secrets` `scan_diff`, Unshadowed Multi-Pass `.env` Scanning, `github_pat_` in `detect-secrets`, and `"ss#"` / Trailing Context in Default `Presidio`:** `detect-secrets@5e141933` does not run file transformers in `scan_diff` (`scan.py:169-179`), aborts `.env` `EagerConfigFileTransformer` when Pass 1 matches any secret (`scan.py:162-163`), and omits `github_pat_` (`github_token.py:15`); `presidio@61fde811` `LemmaContextAwareEnhancer` strips `"#"` from `keywords` (breaking `"ss#"` even if uncommented at `us_ssn_recognizer.py:33`, `iss:1452`) and defaults to `context_suffix_count = 0`.
- **`unknown` — Open-World Utility Loss of Schema-Free $M_d(D, c_0)$ Minimizers and Exact Leaderboard Shift Under Patched `TAB` `evaluation.py`:** Available evidence does not resolve the exact false-withholding rate of LLM-parameterized $M_d(D, c_0)$ minimizers on underspecified open-domain tasks lacking structured conditional schemas, nor the exact point shift across published `TAB` model outputs if `evaluation.py:236` (`332` `NO_MASK` mentions in `echr_test.json`) and `evaluation.py:405` (`4` `QUASI -> DIRECT` test entities) are patched simultaneously on original raw prediction files.
- **`not examined` — Native Go/spaCy Binary Execution, Live Third-Party Verification Endpoints, Closed-Source Commercial Scanners, and General Control-Flow Taint Tracking:** This investigation did not execute compiled Go `gitleaks`/`trufflehog` binaries, spaCy neural NER models, live third-party credential APIs, or proprietary closed-source scanners (`SpectralOps`, `Commercial X`), and did not examine general prompt-injection control/data-flow taint tracking (`CaMeL`, `FIDES`) or non-credential CWE static vulnerability detection.
