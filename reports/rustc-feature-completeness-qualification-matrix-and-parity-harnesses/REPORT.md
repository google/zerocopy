### 2. Dual-Mode Qualification Architecture (Mode A Standalone Replacement vs. Mode B Codegen Backend)

Basis: derived from `compiler/rustc_driver_impl`, `compiler/rustc_codegen_ssa/src/traits/backend.rs`, and `support/surface_to_harness_map.json`.

To prove **zero unverified blind spots**, let $\mathcal{S}$ denote the complete set of observable `rustc` + `rustdoc` compiler behaviors over all inputs $(P, \vec{f}, E, T)$ (program source $P$, CLI flags $\vec{f}$, tracked environment $E$, and target tuple $T$). Partition $\mathcal{S}$ into four disjoint components:

$$\mathcal{S} \;=\; \mathcal{S}_{\text{FE}} \;\sqcup\; \mathcal{S}_{\text{HYB}} \;\sqcup\; \mathcal{S}_{\text{BE}} \;\sqcup\; \mathcal{S}_{\text{LLVM}}$$

1. **Frontend & Middle-End Surface ($\mathcal{S}_{\text{FE}}$):** CLI `getopts`/argfile parsing, `17` frontend-only `--print` queries, lexing/parsing across `5` Editions, macro & `proc_macro::bridge` expansion, name resolution, `589` feature gates, `202` typed attributes, trait solving (`NextSolverConfig`), type checking, `rustc_pattern_analysis`, NLL/Polonius borrow checking, `292` lints, `518` diagnostic codes, JSON error serialization, `.rmeta` v12 encoding/decoding, `mir-opt` passes, `make_shim` MIR synthesis for all `13` `ShimKind`s, and `rustdoc` HTML/JSON generation.
2. **Hybrid Driver–Backend Seam Surface ($\mathcal{S}_{\text{HYB}}$):** Surfaces where the driver and backend co-compute a single observable contract:
   - *Seam H1 (`target_config` $\rightarrow$ `cfg(target_feature)` & `--print cfg`/`check-cfg`):* Backend queries target/host CPU features (`-Ctarget-cpu=native`, `-Ctarget-feature=...`), validates unknown feature names, and feeds active features back into `Session` *before* conditional compilation and macro expansion! If a Mode B backend returns a stub `TargetConfig`, `#[cfg(target_feature = "avx2")]` takes the wrong branch in `core`/`std`/user crates.
   - *Seam H2 (`CodegenBackend::print` / `has_zstd` / `has_mnemonic`):* Supplies `8` `--print` queries (`target-cpus`, `target-features`, `code-models`, `relocation-models`, `tls-models`, `stack-protector-strategies`, `backend-has-zstd`, `backend-has-mnemonic:<m>`). Cargo, `build.rs` scripts, and `compiletest` query these directly.
   - *Seam H3 (Host `proc-macro` Shared-Library Compilation & In-Process `dlopen`):* Even in Mode B, compiling a workspace with `#[proc_macro]` crates invokes the backend to emit a host `.so`/`.dylib`/`.dll` exporting `__rustc_proc_macro_decls_<StableCrateId>__` and supporting `std::panic::catch_unwind` across the `proc_macro::bridge` boundary.
   - *Seam H4 (`MonoItem` Collection & `ReifyReason` KCFI Type-IDs):* `rustc_monomorphize` collects `MonoItem::{Fn, Static, GlobalAsm}`, while backend symbol mangling and KCFI (`SanitizerSet::KCFI`) must distinguish `ShimKind::Reify(_, Some(ReifyReason::FnPtr))` from `Some(ReifyReason::Vtable)`.
   - *Seam H5 (`UnwindAction` Lowering Across `-Cpanic={unwind,abort}`):* Even under `-Cpanic=abort`, `rustc`'s `AbortUnwindingCalls` MIR pass emits `UnwindAction::Terminate(Reason::Abi)` landing pads on nounwind `extern "C"` functions calling `extern "C-unwind"` targets. Lowering `Terminate` to `Unreachable` while emitting `.eh_frame` CFA tables silently corrupts RFC 2945 abort barriers (Section 3.5).
   - *Seam H6 (`.rlib` Archive Packing & `.rustc` Dylib Metadata Sections):* Backend linker orchestration (`CodegenBackend::link`) packs `lib.rmeta` + `.rcgu.o` members into `ar` archives and embeds `.rustc` metadata sections into `--crate-type=dylib`.
3. **Pure Backend & Runtime Execution Surface ($\mathcal{S}_{\text{BE}}$):** `Runtime(PostCleanup)` MIR lowering, `210` mandatory `#[rustc_intrinsic]`s + `core::arch` SIMD intrinsics, `FnAbi` register/stack/sret marshaling across `ExternAbi`, `InlineAsmArch` `asm!` / `global_asm!` / `#[unsafe(naked)]`, `InstanceKind::Virtual` vtable calls, TLS models, atomics & memory model fences, stack probes (`StackProbeType`), debuginfo (DWARF/CodeView), sanitizers, LTO (`ThinLocal`/`Thin`/`Fat`), and native object/relocation emission (`--emit=obj,asm,link`).
4. **LLVM-Internal Representation Surface ($\mathcal{S}_{\text{LLVM}}$):** Textual LLVM IR (`--emit=llvm-ir`), LLVM bitcode (`--emit=llvm-bc`, `thin-link-bitcode`, `-Clinker-plugin-lto`), and raw LLVM pass-manager CLI flags (`-Cllvm-args`, `-Cpasses`, `-Zllvm-plugins`).

**Qualification Completeness Equations:**
- **Mode A (Standalone `rustc` + `rustdoc` Replacement $\mathcal{C}_A$):** Must verify **$\mathcal{S}_{\text{FE}} \sqcup \mathcal{S}_{\text{HYB}} \sqcup \mathcal{S}_{\text{BE}}$** (`100%` of language, CLI, diagnostic, metadata, `mir-opt`, `rustdoc`, and backend execution contracts). Only $\mathcal{S}_{\text{LLVM}}$ (plus GCC-specific heuristic `tests/assembly-gcc`) is outside the black-box Rust contract—and any security/optimization property previously checked via `FileCheck` in `tests/codegen-llvm` or `tests/assembly-llvm` (such as bounds-check elimination, `noalias` preservation, or stack-protector emission) must be re-anchored to binary/assembly or execution parity harnesses.
- **Mode B (Drop-In `-Z codegen-backend` $\mathcal{C}_B = \mathcal{F}_{\text{upstream}} \circ \mathcal{B}_{\text{cand}}$):** Because $\mathcal{F}_{\text{upstream}}$ is bit-for-bit identical to the host `rustc` frontend pinned at the same commit SHA, $\mathcal{S}_{\text{FE}}$ holds by construction *provided* $\mathcal{B}_{\text{cand}}$ satisfies **$\mathcal{S}_{\text{HYB}} \sqcup \mathcal{S}_{\text{BE}}$**. By $\mathcal{S} \setminus \mathcal{S}_{\text{LLVM}} = \mathcal{S}_{\text{FE}} \sqcup (\mathcal{S}_{\text{HYB}} \sqcup \mathcal{S}_{\text{BE}})$, verifying $\mathcal{F}_{\text{upstream}}$'s SHA identity plus $100\%$ of $\mathcal{S}_{\text{HYB}} \sqcup \mathcal{S}_{\text{BE}}$ leaves **zero unverified behavioral seams**.
