# Lean 4 Tactic Extension APIs, Simplifier and Unused-Argument Linter Semantics, Omega Linear Arithmetic, and Grind Proof Search

## Summary

Across Lean `v4.30.0-rc2` (`leanprover/lean4@3dc1a088b6d2d8eafe25a7cd7ec7b58d731bd7cc`) and Lean `v4.34.1` (`leanprover/lean4@5045d0056413266e57c625dcd7c365b10e377c52`), Lean 4's proof automation and tactic-extension infrastructure is organized into five complementary subsystems whose operational and trust boundaries directly govern Anneal's generated and user-authored proof scripts:

1. **Custom Tactic Extension Pipeline (`syntax`, `macro_rules`, `elab_rules : tactic`)**: Custom tactics combine parser registrations (`parserExtension` in `Lean/Parser/Extension.lean`), syntax-to-syntax expanders (`Lean.Macro` in `MacroM`), and goal-manipulating elaborators (`Lean.Elab.Tactic.Tactic := Syntax → TacticM Unit`, where `TacticM := ReaderT Tactic.Context (StateRefT Tactic.State TermElabM)` and `Tactic.State` holds `List MVarId`). In `evalTactic` (`Lean/Elab/Tactic/Basic.lean`), Lean tries **all registered macros before all registered tactic elaborators** for a syntax node kind, restoring saved elaboration/goal state across failed candidates (`Exception.error`, unsupported syntax, and abort-tactic exceptions). Parser and `KeyedDeclsAttribute` registrations serialize declaration names rather than closures into `.olean` files, reconstructing executable parsers and elaborators upon module import.
2. **Simplifier (`simp`, `simp!`, `simp_all`, `simp_all!`) Context and Reduction Semantics**: `simp` (`evalSimp` at `Lean/Elab/Tactic/Simp.lean:788` in `v4.34.1`) and `simp_all` (`evalSimpAll` at `Lean/Elab/Tactic/Simp.lean:802` in `v4.34.1`) share the core rewrite engine (`Lean/Meta/Tactic/Simp/Main.lean`, 962 lines in `v4.34.1`, default `maxSteps := 100000`, `maxDischargeDepth := 2`, `failIfUnchanged := true`) but differ fundamentally in context ingestion: plain `simp` uses `Simp.Config` (`contextual := false`), whereas `simp_all` uses `Simp.ConfigCtx` (`contextual := true`), seeds the active simp theorem set with every local proposition hypothesis, and runs a fixed-point loop (`SimpAll.loop`) that repeatedly simplifies nondependent proposition hypotheses and the target while temporarily erasing each hypothesis's own rule to prevent self-trivialization. `simp only [...]` discards the imported `[simp]` and default simproc sets (retaining only `eq_self` and `iff_self` plus explicit entries), while `simp!` and `simp_all!` enable `autoUnfold := true`.
3. **Unused Simp Argument Linter (`linter.unusedSimpArgs`) and `v4.30.0-rc2` → `v4.34.1` Hint Delta**: Enabled by default (`Lean/Elab/Tactic/Simp.lean:675, 797, 815` in `v4.34.1`), `linter.unusedSimpArgs` is an origin-based usage tracker rather than a counterfactual proof minimizer. It tracks `.addEntries`, `.addSimproc`, and `.addLetToUnfold` origins in `Simp.UsedSimps`, treats `.erase`, `.eraseSimproc`, `.ext`, `.star`, and `.none` as unconditionally used, collapses equation theorems (`foo.eq_1`) to their parent declaration via `usedThmIdOfSimpTheorem`, aggregates multiple executions of the same `Syntax.Range` by elementwise logical OR, skips macro-expanded calls lacking a range, and is bypassed whenever `tactic.simp.trace` is enabled or `simp` aborts before post-execution tracking. Direct runtime execution across `v4.30.0-rc2` and `v4.34.1` on 4 batch fixtures confirms identical warning locations, severities, and explanations, with one exact diagnostic-rendering delta: `v4.34.1` sets `diffGranularity := .none` in `Lean/Linter/UnusedSimpArgs.lean`, rendering code-action hints as `Hint: Omit it from the simp argument list. [apply] simp` instead of a struck-through diff.
4. **Linear Integer and Natural Arithmetic (`omega`)**: `omega` (`Lean/Elab/Tactic/Omega/Frontend.lean`, 714 lines in `v4.34.1`, `omega` at line 672) converts the goal to a contradiction problem via `falseOrByContra`, reflects `Nat`, `Int`, and `Fin` equalities, inequalities, disequalities, and constant-modulus divisibility/division/remainder into integer linear combinations over canonicalized atoms (treating nonlinear variable-variable products as opaque atoms without AC normalization), defers disjunctions (`splitDisjunctions`, `splitNatSub`, `splitNatAbs`, `splitMinMax`, all `true` by default in `OmegaConfig`) until the straight-line linear pass fails, solves equalities via unit-coefficient or balanced-modulo variable elimination, and runs Fourier–Motzkin **real-shadow** elimination. Because dark and grey shadows are intentionally omitted, `omega` is a sound proof-producing prover (wrapping its proof in `mkAuxTheorem`) but an **incomplete** decision procedure. Direct runtime execution across `v4.30.0-rc2` and `v4.34.1` on 3 batch fixtures (`linear.lean`, `nonlinear.lean`, `no-constraints.lean`) produces **byte-identical** `lean --json` stdout/stderr streams and exit codes.
5. **Bounded SMT-Style Proof Search (`grind`)**: `grind` (`Lean/Meta/Tactic/Grind/Main.lean`, 501 lines in `v4.34.1`, `Grind.main` at line 396) combines congruence closure, E-matching instantiation, case splitting, model-based theory combination (`mbtc`), and registered theory solvers (`cutsat`/`lia`, `linarith`, `ring`, `order`, `ac`) inside a continuation-passing `Action` loop (`solvers <|> instantiate <|> splitNext <|> mbtc`, default `maxIterations := 10000`, `splits := 9`, `ematch := 5`, `gen := 8`, `instances := 1000`, `canonHeartbeats := 1000`). While `register_grind_attr` isolates E-matching, case-split, extensionality, function-congruence, and injectivity rules per attribute, normalization rules, symbol priorities, `SolverExtension` slots, and builtin propagators are shared globally across all grind attributes. `grind only` removes default E-matching and injectivity theorems while retaining default case-split types, function-congruence symbols, extensionality declarations, global normalizers, and active theory solvers.

## Findings

### 1. Tactic Extension APIs (`syntax`, `macro_rules`, `elab_rules : tactic`, and `evalTactic`)

Basis: **source** + checked-in **execution** fixtures (`src/Lean/Elab/Tactic/Basic.lean`, `src/Lean/Elab/Term/TermElabM.lean`, `src/Lean/Elab/Util.lean`, `src/Lean/KeyedDeclsAttribute.lean`, `src/Lean/Elab/ElabRules.lean`, `src/Lean/Elab/MacroRules.lean`, `src/Lean/Elab/Syntax.lean`, `src/Lean/Parser/Extension.lean`, `src/Lean/Parser/Term/Basic.lean`, `src/Lean/Elab/Tactic/BuiltinTactic.lean`, `tests/elab/macroElabRulesIssue1.lean`, `tests/elab/extensibleTacticBug.lean`, `tests/elab/evalTacticBug.lean`).

#### 1.1 Three Independent Extension Layers: Parser, Macro, and Elaborator
A custom tactic in Lean 4 is constructed from up to three independent layers:
1. **Grammar registration (`syntax ... : tactic`)**: Registers a parser in the extendable dynamic `tactic_parser` category (`Lean/Parser/Term/Basic.lean`, `Lean/Elab/Syntax.lean`). `parserExtension` (`Lean/Parser/Extension.lean`) is a `ScopedEnvExtension` whose `.olean` entry (`ParserExtension.OLeanEntry`) stores only the category name, declaration name, and numeric priority; on module import, `mkParserOfConstant` reconstructs the executable parser from the named declaration. `local` declarations do not export across modules, and `scoped` declarations require activating the namespace.
2. **Syntax-to-syntax macro expansion (`macro` / `macro_rules`)**: Attaches a `Lean.Macro` (`Syntax → MacroM Syntax`) to a syntax node kind via `macroAttribute` (`Lean/Elab/MacroRules.lean`, `Lean/Elab/Util.lean`). Pattern mismatches throw `Macro.Exception.unsupportedSyntax`, enabling fallback across multiple `macro_rules` declarations (`tests/elab/extensibleTacticBug.lean`, `tests/elab/evalTacticBug.lean`). Because `MacroM` has no access to the `TacticM` goal list, macros perform purely syntactic lowering.
3. **Goal-state tactic elaboration (`elab` / `elab_rules : tactic`)**: Attaches a `Lean.Elab.Tactic.Tactic` (`Syntax → TacticM Unit`) to a syntax node kind via `tacticElabAttribute : KeyedDeclsAttribute Tactic` (`builtin_tactic` / `tactic` in `Lean/Elab/Tactic/Basic.lean`, `Lean/Elab/ElabRules.lean`). Here:
   - `TacticM := ReaderT Tactic.Context (StateRefT Tactic.State TermElabM)`
   - `Tactic.State` holds `goals : List MVarId` (manipulated via `getGoals`, `setGoals`, `getMainGoal`, `replaceMainGoal`, `pushGoal`, `appendGoals`).
   - `Tactic.Context` holds the executing elaborator declaration name and `recover : Bool` (default `true`).
   - `KeyedDeclsAttribute.OLeanEntry` (`Lean/KeyedDeclsAttribute.lean`) serializes only the syntax-kind key and declaration name into `.olean` files, reconstructing the `Tactic` function on import via `evalConstCheck`. Note that `syntax (priority := ...)` sets the Pratt parser priority, whereas `KeyedDeclsAttribute` prepends new same-key handlers to a list without numeric priorities.

#### 1.2 Backtracking, Macro-Before-Elaborator Precedence, InfoTree Provenance, and Incrementality in `evalTactic`
- **Macro-before-elaborator dispatch and state backtracking**: For a non-null tactic syntax node `stx`, `evalTactic` retrieves both `macroAttribute.getEntries env stx.getKind` and `tacticElabAttribute.getEntries env stx.getKind`, saves the tactic/elaboration state once, and calls `expandEval`, which **tries all macro candidates before any tactic elaborator** (`tests/elab/macroElabRulesIssue1.lean`). When a candidate fails, Lean restores the saved state before trying the next candidate:
  - Normal `Exception.error` and internal abort-tactic exceptions are retained in the failure list and trigger fallback to the next candidate.
  - Internal unsupported-syntax exceptions trigger fallback without being retained in the failure list.
  - Consequently, calling `throwError` inside a custom tactic elaborator does **not** prevent fallback if an older/earlier rule for the same syntax kind remains in the chain.
- **InfoTree and module-use provenance**: `evalTactic` wraps execution in `mkTacticInfo` (recording the elaborator declaration name, syntax, `MetavarContext` before/after, and `goals` before/after) and invokes `recordExtraModUseFromDecl (isMeta := true)` for non-builtin macro/elaborator declarations.
- **Opt-in incrementality and error recovery**: Before executing a tactic elaborator, `evalTactic` checks `isIncrementalElab evalFn.declName` (`Lean/Elab/Term.lean`, recognizing `@[incremental]` or `@[builtin_incremental]`); non-incremental user tactics run under `withoutTacticIncrementality`. Because `Tactic.Context.recover` defaults to `true`, core recovery helpers can assign a labeled `sorryAx` to unsolved goals after logging an error unless wrapped in `withoutRecover`.

### 2. Simplifier (`simp`, `simp!`, `simp_all`, `simp_all!`) Context and Reduction Semantics (`v4.30.0-rc2` & `v4.34.1`)

Basis: **source** (`src/Lean/Elab/Tactic/Simp.lean`, `src/Lean/Meta/Tactic/Simp/SimpAll.lean`, `src/Lean/Meta/Tactic/Simp/Main.lean`, `src/Lean/Meta/Tactic/Simp/Rewrite.lean`, `src/Lean/Meta/Tactic/Simp/SimpTheorems.lean`, `src/Lean/Meta/Tactic/Simp/Attr.lean`, `src/Init/MetaTypes.lean`, `src/Init/Meta.lean`).

#### 2.1 Context Construction (`mkSimpContext`), `simp only`, and Explicit Arguments
In both `v4.30.0-rc2` (`3dc1a088b6d2`) and `v4.34.1` (`5045d0056413`, where `Lean/Elab/Tactic/Simp.lean` is 864 lines with `evalSimp` at line 788 and `evalSimpAll` at line 802, and `Lean/Meta/Tactic/Simp/Main.lean` is 962 lines):
- Plain `simp` initializes `mkSimpContext` from `getSimpTheorems` (populated by `@[simp]`) and `Simp.getSimprocs`.
- `simp only [...]` replaces the default theorem set with a minimal set containing only `eq_self` and `iff_self` and initializes an empty simproc set before elaborating explicit `[...]` entries. However, `simp only` still runs all configuration-enabled reductions (`beta`, `iota`, `proj`, `zeta`, `zetaUnused`, `zetaHave`, `dsimp` on dependent arguments, and congruence closure).
- Explicit simp arguments (`elabSimpArgs`, `SimpTheorems.lean`) support forward rules, reversed equality/iff rules (`← thm`, which also erases the forward rule from the active set), rule/simproc erasure (`- name`), definition equation/unfolding entries (preferring generated equation theorems ordered from specific to catch-all), custom simp/simproc extensions, and `*` (which adds all current local proposition hypotheses as rewrite rules). Propositions added to the simp set are normalized so equalities/iffs become rewrites, positive propositions `P` rewrite to `True`, negations `¬ P` rewrite to `False`, and conjunctions split into component rules.

#### 2.2 Comparing `simp [*]`, `simp at *`, and `simp_all`
The three local-context forms have distinct operational semantics:

| Tactic Form | Default Config (`Init/MetaTypes.lean`) | How Local Hypotheses Enter the Active Simp Set | Which Locations Are Rewritten and Reasserted | Iteration Model |
| :--- | :--- | :--- | :--- | :--- |
| **`simp [*]`** | `Simp.Config` (`contextual := false`) | `applyStarArg` adds all local proposition hypotheses as simp rules once before simplifying. | Simplifies only the target (or explicitly named `at h₁ h₂` locations). | Single target/location pass (with internal expression loop `singlePass := false`). |
| **`simp at *`** | `Simp.Config` (`contextual := false`) | Does **not** add local hypotheses to the simp set; simplifies each nondependent proposition hypothesis (temporarily erasing itself) and the target. | All nondependent proposition hypotheses and the target. | Single pass over each selected location. |
| **`simp_all`** | `Simp.ConfigCtx` (`contextual := true`) | Seeds the simp set with **all** local proposition hypotheses (both dependent and nondependent), plus new assumptions introduced when descending under `p → q` (`contextual := true`). | Tracks and rewrites **nondependent** proposition hypotheses and the target (`SimpAll.initEntries`, `SimpAll.loop`). | Outer fixed-point loop (`SimpAll.loop`): each round simplifies every tracked nondependent hypothesis (with itself temporarily removed so `h` cannot simplify itself to `True`), updates its rule in the simp set on change, and simplifies the target until no change occurs or the goal closes; hypotheses simplified to `True` are dropped. |

#### 2.3 `Simp.Config` Defaults, Termination Guards, Dischargers, and `simp!` / `simp_all!`
- **Default `Simp.Config` parameters (`src/Init/MetaTypes.lean`)**: `maxSteps := 100000`, `maxDischargeDepth := 2`, `contextual := false` (`true` in `ConfigCtx`), `memoize := true`, `singlePass := false`, `zeta := true`, `beta := true`, `eta := true` (marked unimplemented in source docstring), `iota := true`, `proj := true`, `decide := false`, `arith := false`, `autoUnfold := false`, `dsimp := true`, `failIfUnchanged := true`, `unfoldPartialApp := false`, `zetaDelta := false`, `index := true`, `implicitDefEqProofs := true`, `zetaUnused := true`, `catchRuntime := true`, `zetaHave := true`, `locals := false`, `instances := false`.
- **Loop and permutation guards (`Simp/Rewrite.lean`, `Simp/SimpTheorems.lean`)**: Candidates retrieved from the discrimination tree (`index := true`) are tried in descending priority order. Rewrites that yield a term structurally equal to the input after metavariable instantiation are rejected; permutation rules (identical up to variable permutation) apply only if the right-hand side decreases under `acLt`.
- **Conditional rule discharge**: Propositional side conditions try typeclass synthesis and then the discharger (up to `maxDischargeDepth := 2`), rolling back `Simp.UsedSimps` on failure. Plain `simp` supports custom `(discharger := ...)` syntax and `at ...` locations; `simp_all` rejects both in `mkSimpContext`.
- **`simp!` and `simp_all!` (`src/Init/Meta.lean`)**: Built-in macros that expand to `simp` / `simp_all` with `autoUnfold := true`, unfolding pattern-matching definitions whenever a pattern matches.
- **Goal closure and `failIfUnchanged`**: Simplifying the target to `True` or any selected hypothesis to `False` closes the goal immediately. When the goal metavariable is unchanged and `failIfUnchanged := true`, `simpGoal` throws `` `simp` made no progress `` and `simpAll` throws `simp_all made no progress`.

### 3. Unused Simp Argument Linter (`linter.unusedSimpArgs`) and `v4.30.0-rc2` → `v4.34.1` Runtime Comparison

Basis: **source** + **execution** (`src/Lean/Elab/Tactic/Simp.lean`, `src/Lean/Linter/UnusedSimpArgs.lean`, `src/Lean/Linter/Basic.lean`, `tests/elab/simpUnusedArgs.lean`, `tests/elab/12559.lean`; [`support/lean-unused-simp-args-linter/source-map.json`](support/lean-unused-simp-args-linter/source-map.json), [`support/lean-unused-simp-hints-runtime-may-september/results.json`](support/lean-unused-simp-hints-runtime-may-september/results.json), [`support/lean-unused-simp-hints-runtime-may-september/analysis.json`](support/lean-unused-simp-hints-runtime-may-september/analysis.json), [`support/lean-unused-simp-hints-runtime-may-september/source-diff.patch`](support/lean-unused-simp-hints-runtime-may-september/source-diff.patch)).

#### 3.1 Two-Phase Architecture, Tracked vs. Untracked Argument Classes, and False-Negative/False-Positive Boundaries
1. **Option registration and precedence**: `register_builtin_option linter.unusedSimpArgs` (`Lean/Elab/Tactic/Simp.lean:675` in `v4.34.1`) defaults to `true`. `Lean.Linter.Basic.getLinterValue` checks an explicit `linter.unusedSimpArgs` setting first, then an explicit `linter.all` setting (`tests/elab/12559.lean`), then linter sets, and finally the option default.
2. **Tactic-side mask recording (`warnUnusedSimpArgs` at `Simp.lean:797, 815` in `v4.34.1`)**: After `evalSimp` (line 788) or `evalSimpAll` (line 802) succeeds, if `tactic.simp.trace` is `false` and `linter.unusedSimpArgs` is `true`, `warnUnusedSimpArgs` inspects `stats.usedTheorems : Simp.UsedSimps` and writes a Boolean mask into an `UnusedSimpArgsInfo` node in the `InfoTree`:
   - **Tracked argument variants**: `.addEntries` (marked used if any contributed theorem/unfolding origin is in `UsedSimps`, with equation theorems `foo.eq_1` mapped to their parent declaration `foo` by `usedThmIdOfSimpTheorem`), `.addSimproc` (checks simproc origin), and `.addLetToUnfold` (checks local `FVarId` origin).
   - **Untracked argument variants (always return `true` / "used")**: `.erase` (`-thm`), `.eraseSimproc`, `.ext`, `.star` (`*`), and `.none`.
   - **Known false-negative paths**: (a) Untracked variants above; (b) equation-theorem origin collapsing (`simp [foo.eq_1, foo.eq_2]` treats both as used if either equation of `foo` fires); (c) duplicate explicit arguments (`simp [some_def, some_def]` marks both used if `some_def` fires once); (d) macro-expanded `simp` calls where `info.range?` is `none`; (e) enabling `set_option tactic.simp.trace true`, which takes the `if` branch (`traceSimpCall`) and skips the `else if` branch (`warnUnusedSimpArgs`); and (f) any `simp` call that throws before reaching the post-execution hook (such as default `failIfUnchanged := true` no-progress calls).
   - **Known non-redundancy caveat (reversed rules `← thm`)**: Because `simp [← thm]` also erases the forward rule `thm` from the active simp set, deleting `← thm` when its reverse rewrite went unused can re-enable the forward rewrite and break the proof (`tests/elab/simpUnusedArgs.lean` issue 9909). `warnUnused` attaches an explicit note recommending `-thm` when only erasure was intended.
3. **Command-linter aggregation (`Lean.Linter.UnusedSimpArgs.unusedSimpArgs`)**: Walks the command's `InfoTree`s, skips nodes without `info.range?`, groups `UnusedSimpArgsInfo` masks by `Syntax.Range`, combines masks across repeated executions (e.g., `all_goals simp [...]`) via **elementwise logical OR**, and calls `warnUnused` only for arguments whose bit is `false` across every execution of that source range.

### 4. `omega` Linear Integer/Natural Arithmetic and `v4.30.0-rc2` → `v4.34.1` Runtime Continuity

#### 4.1 Contradiction Reduction, Fact Extraction, Reflection, and Delayed Disjunction Splitting
In both `v4.30.0-rc2` (`3dc1a088b6d2`) and `v4.34.1` (`5045d0056413`, where `Lean/Elab/Tactic/Omega/Frontend.lean` is 714 lines with `omega` at line 672):
1. **Entry point (`evalOmega`, `omegaTactic`)**: Unless `debug.terminalTacticsAsSorry` (`Lean/Meta/Tactic/Util.lean`, default `false`) is enabled, `evalOmega` first tries `assumption`, then calls `falseOrByContra` (leaving `False` unchanged, introducing `P` for `¬ P`, introducing `x = y` for `x ≠ y`, and replacing other goals `P` with `¬¬ P` to introduce `¬ P`), collects all local hypotheses, runs `omega` to construct a proof of `False`, and wraps the resulting proof term in an auxiliary theorem via `mkAuxTheorem`.
2. **Logical shell and fact extraction (`MetaProblem.addFact`)**: Weak-head-normalizes hypothesis types and extracts equalities (`=`), inequalities (`<`, `≤`, `>`, `≥`), disequalities (`≠`), and divisibility (`∣`) over `Int`, `Nat`, and `Fin`, plus negations normalized by `pushNot`, implications (converted to disjunctions), conjunctions, existentials, subtypes, `Iff` (converted to two-branch truth-assignment disjunctions), `Prod.Lex`, and disjunctions (when `splitDisjunctions := true`).
3. **Linear combination reflection (`asLinearComboImpl`, `OmegaM.lookup`)**: Addition, subtraction, and negation compose `LinearCombo` vectors directly. Multiplication `e₁ * e₂` is expanded only if at least one factor has a zero coefficient vector (i.e., is constant with respect to discovered atoms); if both factors contain variables, reflection state is restored and the product is interned as an opaque atom via `Lean.Meta.Canonicalizer` (up to definitional equality, **without** associativity/commutativity normalization—so `a * b` and `b * a` become distinct atoms).
4. **Casts, constant division/remainder, and `OmegaConfig` splits**:
   - `((x : Nat) : Int)` atoms contribute non-negativity (`0 ≤ x`), while `Fin.val` and `BitVec.toNat` casts contribute their upper bounds.
   - Division and remainder by constants recognized by `groundNat?` / `groundInt?` introduce quotient atoms with linear remainder bounds (`0 ≤ r < d`, `x = d * q + r`).
   - `OmegaConfig` (`src/Init/Meta/Defs.lean`) enables four Boolean flags by default: `splitDisjunctions := true`, `splitNatSub := true` (splitting `((a - b : Nat) : Int)` into `b ≤ a` vs. `a < b`), `splitNatAbs := true`, and `splitMinMax := true`.
   - Disjunctions are queued FIFO in `MetaProblem` and split via `splitDisjunction` (`Or.elim`) **only after** the non-branching linear solver fails to find a contradiction.

#### 4.2 Equality Elimination, Real-Shadow Fourier–Motzkin Incompleteness, and `v4.30.0-rc2` → `v4.34.1` Runtime Verification

## Boundaries

- **Cross-version stability of tactic metaprogramming and search (`known not to apply` / `unsupported`)**: Tactic extension APIs (`TacticM`, `evalTactic` fallback order, `KeyedDeclsAttribute` merge order across unrelated imports), `simp` equal-priority tie-breaking, `omega` undocumented frontend rewrites (`Fin`, `BitVec.toNat`, `if`), and `grind` search paths (`grind.warning` explicitly notes `grind` behavior may change, and `tests/elab/grind_heartbeats.lean` documents nondeterministic timeout locations between `whnf` and `isDefEq`) are not frozen cross-version contracts.
- **`simp only` and `grind only` as hermetic sandboxes (`known not to apply`)**: `simp only` still runs built-in reductions (`beta`, `iota`, `proj`, `zeta`, `dsimp`), congruence closure, and conditional discharge; `grind only` retains default case-split types, `funCC` symbols, `[grind ext]` theorems, global normalizers, local hypotheses, and all configured theory solvers (`ring`, `lia`, `linarith`, `order`, `ac`).
- **`linter.unusedSimpArgs` warnings vs. semantic redundancy (`known not to apply`)**: An unused-argument warning proves only that no tracked origin (`.addEntries`, `.addSimproc`, `.addLetToUnfold`) was recorded in `Simp.UsedSimps`; deleting a reversed rule `← thm` can alter proof behavior by re-enabling the forward rule `thm`. Conversely, absence of a warning does not prove necessity due to untracked variants (`.erase`, `.star`, `.ext`), equation-theorem collapsing (`usedThmIdOfSimpTheorem`), duplicate arguments, macro range suppression, and `tactic.simp.trace` suppression.
- **`omega` completeness for Presburger arithmetic (`known not to apply` / `unsupported`)**: Because `omega` omits dark and grey shadows during non-exact Fourier–Motzkin elimination and treats variable-variable products as opaque atoms without AC normalization, `omega` failure does not establish satisfiability or a valid counterexample. Furthermore, `bv_omega` was `not examined` in the `omega` package.
- **Tactic elaboration success vs. axiom-free kernel proof (`known not to apply` without audit)**: `Tactic.Context.recover` (`true` by default) and `debug.terminalTacticsAsSorry` can admit goals via `sorryAx`; final theorems must still be audited via `#print axioms`.
