# Minimal ownership delta - source-only proposal

**Recursive chown of registered immutable store objects is not required by the inspected normal-build path.** Prefer UID 1000 ownership of storeDir itself, required mutable metadata and existing output locks. Keep cached read-only outputs, sources and .drv objects root-owned. Explicitly disable automatic optimisation and automatic GC. This is a source-supported candidate for a fresh-output probe, not evidence these particular dependencies already work as nonroot.

This delta supersedes the broad store and /root ownership recommendations in PLAN.md for method selection only; PLAN.md remains untouched. No environment/native/build/Git/cleanup effects or nested delegation occurred. Parent's preserved-original -> new owned clone -> separately audited removal of 11 empty HOME directories remains the preparation route. Root `/` stays root:root 0755; `/homeless-shelter` stays absent. Actual Nix/build processes remain UID:GID 1000:1000, cap-drop-ALL, NNP, network none, no host mounts or daemon.

## Smaller finite ownership scope

| Location | Proposed preparation |
|---|---|
| `/nix/store` directory inode only | chown 1000:1000; retain mode, verify owner write/search and writable filesystem. Parents remain traversable and non-symlinked |
| `/nix/store/.links` directory inode only | chown 1000:1000 if present; do not traverse/chown hash-named entries. Automatic optimisation is off; owning these entries is unnecessary for this route. If absent, nonroot can create it below owned storeDir |
| Existing required top-level `/nix/store/<output-or-scratch>.lock` files | Enumerate exact regular files and exclude symlinks/active holders; chown only their inodes, retaining owner-write mode. Enumerating all actual top-level Nix output lock files in this owned clone is an acceptable finite alternative; no recursive glob |
| `/nix/var/nix` mutable subtree | chown exact state tree, including DB/db.sqlite/WAL/SHM/big-lock/schema/reserved, gcroots/profiles/temproots/builds and mutable locks. Deliberately account for existing 0700 root-owned build directories |
| `/nix/var/log/nix` mutable subtree | chown log tree including existing drvs log parents/files |
| Assigned mutable paths under `/work` | parent creates/chowns exact client, working and output directories. Read-only source/input paths can remain root-owned when readable/traversable |
| Registered `/nix/store/<hash>-...` trees/files, including cached EasyCrypt, source, .drv and pinned executable | No chown/chmod/write. Verify readability, traversal, registration and content identity. Owning storeDir does not make root-owned 0555 descendant directories writable |
| `/root`, `/`, `/etc`, `/nix` ancestors | No chown. Ancestors need traversal only; exact required writable descendants must exist or be created by bounded preparation |

Use a **new client environment**: HOME=/work/nix-client/home; XDG_CACHE_HOME=/work/nix-client/cache; XDG_CONFIG_HOME=/work/nix-client/config; XDG_DATA_HOME=/work/nix-client/data; XDG_STATE_HOME=/work/nix-client/state; USER=LOGNAME=nixbuilder; NIX_USER_CONF_FILES=/dev/null. Parent creates/chowns these exact directories with owner write/search, using 0700 for private state/home and a traversable non-world-writable `/work` parent. Reject inherited NIX_CACHE_HOME/NIX_CONFIG_HOME/NIX_DATA_HOME/NIX_STATE_HOME that override XDG, plus remote/store relocation settings. Keep `--store local`, NIX_REMOTE=local, empty build-users-group/builders, auto-allocate-uids=false and explicit sandbox/fallback policy. This is a disclosed client HOME change; **builder HOME remains /homeless-shelter and fixed .drv bytes remain unchanged**. Client HOME ownership and XDG resolution are in primary/src/libutil/unix/users.cc:12-61 and primary/src/libutil/users.cc:15-80.

## Gates and unknowns

1. Reobserve clone identity, original preservation, root mode/mounts/ACLs, exact HOME removal, 18 derivations/19 output validity/content identities and free space. Enumerate locks and **unregistered residual output/scratch paths**: root-owned invalid directories may require deletion/chmod during normal work and defeat this smaller scope. Preserve and return mismatches; do not silently expand chown to cached trees.
2. After preparation verify only declared ownership changes plus exact empty-HOME removal occurred; compare immutable executable/.drv/NAR hashes. Avoid recursively walking immutable trees for ownership conversion. Reduced overlay copy-up is a hypothesis, not a measured saving: actual Docker storage/metacopy behavior is unknown, and DB/log copy-up plus new builds still consume space.
3. As UID 1000 with exact restriction profile, confirm effective auto-optimise-store=false, min-free=0, local-store URI/config and absence of daemon/concurrent clients. A normal store query/open must successfully use SQLite and locks; preserve first permission failure.
4. Use a fresh-output owned probe that reads a root-owned store input and creates/registers a UID-owned output. Verify UID/GID, fixed builder HOME and denied mkdir(/homeless-shelter); require continued absence. Capture actual builder startup/completion, unchanged input hash/owner/mode, and new output hash/owner/registration. Cached success invalidates this probe.
5. A package may itself hardlink root-owned input files into its output or try to chmod/write its input tree. protected_hardlinks may reject linking; even if a link succeeds, canonicalization can attempt lchown of the root-owned inode and fail without CAP_CHOWN, or earlier chmod/xattr operations can fail. Disabling Nix optimisation does not change builder scripts. The inspected generic source does not establish whether these fixed builders avoid that pattern. A real new target build is the discriminator; stop and analyze its first failure before any broader ownership/capability decision.

This mixed-owner store proposal does not promise arbitrary GC/repair/rebuild support. Cached EasyCrypt success cannot test its new nonroot behavior. Neither source inspection nor the tiny probe establishes theorem completion, full dependency completion, reproducibility or an inner Nix namespace sandbox.
