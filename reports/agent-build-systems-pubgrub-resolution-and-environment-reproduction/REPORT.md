# Agentic Environment Provisioning, CDCL Version Solving (PubGrub), Universal Marker Forking, and Temporal Build-Reproducibility Decay

## Summary

Primary-source synthesis across 16 peer-reviewed papers, preprints, and packaging specifications (2006–2025), line-level source inspection of 9 pinned public repositories (`dart-lang/pub`, `pubgrub-rs/pubgrub`, `astral-sh/uv`, `sarugaku/resolvelib`, `JetBrains-Research/EnvBench`, `bytedance/Repo2Run`, `microsoft/SetupBench`, `sola-st/ExecutionAgent`, `SWE-bench/SWE-smith`), and a deterministic Python 3.10+ standard-library verification suite (`scripts/verify_build_env_pubgrub.py`) establishes five technical results governing software environment provisioning and dependency resolution:

1. **CDCL Interval Version Solving (`PubGrub`) Eliminates Exponential Pointwise Backtracking, While Deep Proof Trees Require Heap-Iterative Traversal (`dart-lang/pub@fe190660`, `pubgrub-rs/pubgrub@65355b4a`, `astral-sh/uv@264d8b4a`, `sarugaku/resolvelib@223f4bdc`, `Probe 1`):** Flat single-version package installation is NP-complete even without explicit conflicts, alternatives, or features (`Abate et al., JSS 2012`, Theorem 3). On diamond conflict families (`root -> {a, mid1, mid2, b} -> shared` with $M \in \{3, 4, 5, 6, 8\}$ versions per package), a pointwise-exclusion backjumping model of `resolvelib` (`resolution.py:397`) scales quartically (`120 -> 340 -> 780 -> 1,554 -> 4,680` pin attempts under both safe and optimistic backjumping with insertion-order preference; under `pip`-style `backtrack_causes` + minimum-candidates preference, complexity remains quartic `4,688` at $M = 8$ when `mid1, mid2` precede the conflicting sink lexically, dropping to quadratic `80` when `b` precedes `mid1`), whereas `PubGrub` merges identical dependency ranges (`core.rs:450–488`), widens version intervals (`1` contiguous interval vs. $M$ singleton intervals), and proves unsatisfiability in **constant `8` decisions** (`7` when the sink sorts last; **`585×`** fewer steps at $M = 8$, and **`9` vs. `1,300`** on satisfiable fallback at $M = 6$), compressing failure diagnostics by **`207.8×`** (`106` vs. `22,032` tokens). Because `pubgrub-rs` formats and drops `Arc<DerivationTree>` recursively (`report.rs:69–130, 419–555`), deep version-rejection chains overflow thread call stacks; `uv`'s 4-state heap `IterativeReporter` (`pubgrub/report.rs:80–225`, tested to depth `100,000` inside a `256 KiB` stack thread at `L3151–3170`) and iterative `drop_derivation_tree` (`error.rs:231–244`) preserve character-identical output (`1,251` pairwise-folded lines at depth `2,500` in `Probe 1C` under a `1,000`-frame Python recursion cap).
2. **Universal Multi-Environment Lockfiles Rely on `Fork::set_env` Disjoint-Marker Pruning and Forward Marker Fixpoints (`astral-sh/uv@264d8b4a`, `PEP 508`, `Probe 2`):** Un-forked `PubGrub` enforces at most one version per package name, so a flat single-host lock resolved on `(linux, x86_64, py3.11)` fails on **`14 / 18` (`77.8%`)** target environments across `{linux, darwin, win32} × {x86_64, arm64} × {py3.10, py3.11, py3.12}`. In `uv` (`resolver/mod.rs:3880–4160, 4289–4352`), `Fork::set_env` (`L4148–4160`) intersects inherited dependencies against narrowed fork environments (`(sub_mask & dep.marker) != 0`, pruning disjoint specs such as `darwin and arm64` from Linux forks), while the single-spec no-fork rule (`L3880–3899`), `requires-python` disjointness pruning (`L3961–3965`), and the dominated single-conflict fast path (`L4013–4053`) reduce satisfiable `(environment, conflict-group)` partitions in `Probe 2` from **`72` atomic grid cells (`3.00×`)** and **`32` unoptimized non-empty marker-split forks (`1.33×`)** to **`24` forks** (cutting `N + 1` conflict-split operations from `40` to `6`), with forward BFS marker propagation (`find_environments`, `L4289–4352`) achieving **`0 / 18`** target installation failures even across cyclic dependency graphs.
3. **2025 Environment-Setup Benchmark Spread (`6.69%` to `86.0%`) Reflects Filtering and Grader Soundness Gaps (`EnvBench`, `Repo2Run`, `SetupBench`, `ExecutionAgent`, `SWE-smith`, `Probe 3`):** Apparent capability disparities across 2025 Python benchmarks stem primarily from repository pre-filtering (`EnvBench` removes baseline-solvable repos, leaving `6.69%` Python pass@1) and verifier shortcuts (`Repo2Run`'s `86.0%` EBSR measures `pytest --collect-only` and passes `returncode == 5`, falling by `-52.0 pp` to **`34.0%`** [`17/50`] when actual test suites execute in Appendix E Table 8). Source and execution audits expose silent reward-hacking and export defects across five pinned harnesses: `EnvBench@1ba26950` `source ./bootstrap_script.sh` early `exit 0` false passes on both JVM and Python (`analysis_utils.py:180–219` awards `100%` clean pass while `analyze_results.py:42` drops the repo) plus `|| true` + `grep -c "FAILURE"` false passes/fails; `Repo2Run@65042aa2` `sandbox.py:545` explicit `return_code == 5` rollback whitelisting, `/repo/pyproject.toml` diff and `rm -rf /repo/tests` basename-filter bypasses, and an undefined `outer_command` `NameError` at `integrate_dockerfile.py:323`; `SetupBench@041a412f` `decide_success` ignoring `exit_code` whenever stdout contains `"Setup successful"`; `SWE-smith@9b74ac08` reverting target test files via `git checkout -- {test_files}` (`utils.py:226–238`) while scoring `pytest.xfail()` injected into library code or `conftest.py` as `PASSED` (`grading.py:95–99`); and `ExecutionAgent@8fb16de8` `trace_to_bash.py:53–56` prematurely closing `bash -c '...'` via `<<'"'"'EOF_FILE'"'"''` so `/bin/bash -n` fails unconditionally on every container file write.
4. **Historical Build Breakage Is Dominated by Post-Commit Registry Drift and Mitigated by Per-Release `--exclude-newer` Timestamp Cuts (`Tufano 2017`, `BugSwarm 2019`, `astral-sh/uv@264d8b4a`, `PEP 700`, `Probe 4`):** Across `219,395` Apache Maven snapshots (`Tufano et al., 2017`), only `38.13%` mean (`29.60%` median, dropping from `46.56%` Q4 to `12.39%` Q1) compile, with `58%` of failures caused by dependency/artifact resolution (`32%` `DependencyResolutionException` + `26%` `ArtifactResolutionException`); in `BugSwarm` (`ICSE 2019`), only `5.56%` (`3,091 / 55,586`) of historical CI fail-pass pairs reproduce (`3.47%` Python, `9.52%` Java). In `Probe 4`'s `120`-repository synthetic competing-risks simulation, 5-year build survival falls to `20.0%` (`pipreqs`) and `23.3%` (unlocked manifest), whereas a single `PubGrub` call with per-distribution `upload_time < commit_ts` filtering (`uv` `resolver/mod.rs:2754–2785`) eliminates `100%` of post-commit version drift on PEP-700-timestamped releases and sustains **`80.0%`** 5-year survival (`+56.7 pp`), compared with `81.7%` for live-registry lockfiles (exposed to external link-rot/yanks) and `100.0%` for lockfiles paired with content-addressed artifact mirrors and pinned container toolchains.
5. **Transactional Sandbox Rollback and Clean-Container Synthesis Prevent Absorbing State Pollution (`Repo2Run`, `SetupBench`, `Probe 5`):** Interactive agents waste `38.17%–68.77%` of shell steps during environment setup (`SetupBench` Table 4), and ablating `Repo2Run`'s dual-environment clean synthesis drops EBSR by `-44.3 pp` (`86.0% -> 41.7%`, Table 3). In `Probe 5`'s parameterized discrete-time Markov chain (`DTMC`), in-place shell execution saturates at `12.11%` yield due to absorbing container corruption and single-container exit-code rollback saturates at `44.08%` due to silent zero-exit wrong-version mutations, whereas verified dual-environment synthesis makes `s_done` the unique reachable absorbing state in the absence of external blockers, with per-command rollback accelerating finite-budget convergence from `49.12% -> 98.60%` at $B = 24$ and `74.55% -> 100.00%` at $B = 48$ (bounded in real repositories by external timeouts, missing GPUs, and source defects).

### 2. Complexity of Flat Version Resolution, CDCL `PubGrub`, and Stack-Safe Proof Reporting

`Basis: normative + source + derived + documentation + execution (Probe 1)`

#### 2.1 Computational Complexity and Classical SAT/CUDF Encodings

- **Forward Encodings vs. NP-Completeness Boundaries (`Mancinelli et al., ASE 2006`; `Abate et al., JSS 2012`; `Argelich et al., EPTCS 2010` — `derived + documentation`):**
  - `Mancinelli et al. (2006)` formalize repository $R = (P, D, C)$, subrepository completeness (Proposition 1, p. 6), and **forward reductions** from package installability *into* Boolean SAT (Sec. 3.1, p. 6) and finite-domain constraint programming (Sec. 3.2, Proposition 2, pp. 6–7), establishing NP membership; generic finite-domain CP (`Mozart-Oz`) diverges exponentially on large graphs (Sec. 4.5, p. 8), whereas DPLL `rpmcheck`/`debcheck` verify Mandriva (`4,211` pkgs, `42` broken) in **`8 s` vs. `55 s`** generic SAT and full Debian in **`43 s` vs. `18m 13s`** generic SAT, isolating `123` uninstallable Debian packages (`111` missing dependencies, `12` conflict cycles, Sec. 5 p. 9).
  - `Abate et al. (2012)` establish the exact reverse 3-SAT hardness boundaries: **Theorem 1 (p. 5)** proves upgradeability with conflicts and disjunctive dependencies is **NP-complete**; **Theorem 2 (p. 6)** proves **non-flat** empty-environment installability is **in PTIME** when either conflicts are absent (dual Horn clauses) or disjunctive dependencies, features, and multi-versions are absent (2-SAT); and **Theorem 3 (p. 7)** proves **flat** installability (at most one version per package name, the standard semantics of Python `site-packages`, Dart `pub`, and Cargo non-renamed dependencies) is **NP-complete** even *without* explicit conflicts, alternatives, or virtual features, admitting $2^n$ valid flat solutions (`Example 1`, p. 8). #### 2.2 `PubGrub` Interval CDCL vs. `resolvelib` Pointwise-Exclusion Backjumping

- **Four Departures of `PubGrub` from Atomic SAT (`dart-lang/pub@fe190660`, `doc/solver.md:84–433, 1165–1233` — `normative`; `pubgrub-rs/pubgrub@65355b4a` — `source`):**

### 3. PEP 508 Marker-Algebra Forking for Universal Lockfiles (`astral-sh/uv@264d8b4a`)

`Basis: normative (PEP 508) + source + execution (Probe 2)`

- **Why Flat Lockfiles Break Across Peer Environments:** A container-local `pip freeze` or single-target resolver evaluates PEP 508 markers (`sys_platform`, `platform_machine`, `python_version`) against one host tuple and emits a flat package map. - **`ForkState` Partitioning, `Fork::set_env` Invariant, and Fast-Path Pruning (`crates/uv-resolver/src/resolver/mod.rs:2938–2980, 3880–4160, 4289–4352`):**
  1. *`Fork::set_env` Disjoint-Marker Invariant (`mod.rs:4102–4103, 4148–4160`):* Whenever a fork's Boolean `MarkerEnvironment` narrows to `sub_mask != 0`, `Fork::set_env` enforces `self.dependencies.retain(|dep| self.env.included_by_marker(dep.package.marker()))` (and prunes `self.conflicts`). Without this retention filter, a single-spec dependency visited while a parent fork covers `posix` (`linux | darwin`)—such as `metal_kern` (`darwin and arm64`)—would illegally survive inside child `linux` forks when a subsequent dependency (`torch_backend` on `linux`) splits `posix` into `linux` and `darwin`.
  2. *Three Domain Pruning Rules (`mod.rs:3880–4053`):* (a) **Single-spec / uniform-marker no-fork rule (`L3880–3930`)**: when a dependency name appears once (or all specs share one marker) and its `requires-python` floor does not exceed the project floor, `uv` attaches it without splitting the fork (e.g., keeping `darwin` unified across `x86_64` and `arm64` despite `metal_kern ; darwin and arm64`); (b) **`requires-python` disjointness pruning (`L3961–3965`)**: drops sub-forks disjoint from the project Python floor; and (c) **Conflicting extras/groups `N + 1` splitting & dominated single-conflict fast path (`L3985–4080`)**: splits mutually exclusive group sets $C = \{g_1, \dots, g_N\}$ into `Fork 0` ($\forall j, \neg g_j$) plus `Forks 1..N` ($g_i \wedge \bigwedge_{j \ne i}\neg g_j$), but skips inactive conflict sets (`L3991–3994`) and short-circuits (`L4013–4053`) when `< 2` non-excluded groups remain and none participates in another active conflict set.
  3. *Honest Fork-Reduction Factors & Cycle-Safe Marker Fixpoint (`Probe 2`):* With Boolean satisfiability (`sub_mask != 0`) unconditionally enforced so zero impossible `env_mask == 0` contradictions are ever counted, `uv`'s rules reduce the `Probe 2` fixture (`18` atomic environments $\times$ `4` valid conflict-group assignments over `{cpu, cu121, rocm}` and `{cu121, rocm}`) from **`72` atomic grid cells (`3.00×` reduction)** and **`32` unoptimized non-empty marker-split forks (`1.33×` reduction)** to **`24` pruned forks**, while cutting `N + 1` conflict-split operations from **`40` to `6` (`6.67×`)**. Solving each of the `24` forks once with `PubGrub` and computing lockfile package markers via `find_environments` (`mod.rs:4289–4352`, forward BFS union-of-intersections fixpoint over cyclic graphs, verified on `pkg_a <-> pkg_b` converging to exact `7` environments) achieves **`0 / 18` (`0.0%`)** installation failures across all target environments.

### 6. Architectural Trade-Offs and Verifier Soundness Invariants

`Basis: derived (synthesized from Sections 1–5)`

1. **Temporal CDCL Preceding Interactive Shell Exploration:** On unlocked historical commits, a single timestamp-bounded CDCL resolution pass (`upload_time < commit_ts`) resolves PEP-700-indexed version constraints deterministically in milliseconds, avoiding the `47.1–74.3` interactive trial-and-error steps (`1.23M–1.85M` tokens) observed on `SetupBench` Dependency Resolution while leaving only `sdist` build-backend failures, missing-timestamp/VCS dependencies, and OS/native library installation to iterative agent repair.
2. **Marker-Partitioned Lock Graphs vs. Single-Host `pip freeze`:** Exporting flat host-specific pins discards conditional PEP 508 branches (`77.8%` cross-platform failure rate in `Probe 2`), whereas `ForkState` + `Fork::set_env` + forward `find_environments` propagation preserves multi-target satisfiability in one lock graph.
3. **Heap-Allocated Proof Traversal in Embedded Resolvers:** Embedding recursive `DerivationTree` formatters or `Arc` destructors exposes resolver tooling to deterministic stack overflow on deep pre-release/patch chains; explicit heap state machines (`IterativeReporter` + iterative child-pointer unlinking) bound stack usage to $O(1)$ frames (`256 KiB` verified at depth `100,000` in `uv`).
4. **Transactional Exploration Separated from Clean-Image Verification:** Per-command container rollback prevents non-zero failed commands from wedging package-manager state (`dpkg`/`apt`), while rebuilding a fresh verification container from structured dependency/file-write state (using host-side collision-safe `__EA_FILE_{index}__` heredocs rather than `trace_to_bash.py`-style nested `bash -c` quoting) eliminates silent zero-exit `site-packages` pollution.
5. **Five Discriminating Conditions for Sound Environment Graders:** Benchmark and CI verifiers avoid the false passes and false failures cataloged in Section 4 if and only if: (a) bootstrap scripts execute in an isolated **child process** rather than via `source` in the parent grader shell; (b) build/test pass criteria inspect **actual process exit codes** rather than `|| true` + log substring `grep` or stdout `"Setup successful"` substrings; (c) grading executes the **runtime test suite** with `collected_tests > 0` and baseline test-count parity rather than `pytest --collect-only` or `returncode == 5`; (d) repository integrity checks verify **tracked-file immutability (`git diff --name-only HEAD`) combined with absence of untracked test-runner or import-hook overrides** (`conftest.py`, `pytest.ini`, `setup.cfg`, `pyproject.toml`, `sitecustomize.py`, `usercustomize.py`, `.pth` files) rather than basename-only `test_*`/`*_test.py` filters (while still permitting legitimate untracked build outputs such as `build/`, `target/`, `*.egg-info/`, or `.venv/`); and (e) `TestStatus.XFAIL` counts as non-passing unless already `XFAIL` in the pre-patch baseline.

## Boundaries

- **Paywalled build-repair papers — `not examined`:** *Macho, McIntosh, & Pinzger (`BuildMedic`, IEEE SANER 2018, DOI `10.1109/SANER.2018.8330201`)* and *Hassan, Mostafa, Lam, & Wang (ACM/IEEE ESEM 2017, DOI `10.1109/ESEM.2017.11`)* were not open-access retrievable; neither paper is cited for any metric or parameter in this report.
- **Distributed remote build execution and content-addressed store skipping — `not examined`:** Bazel Remote Execution API (REAPI), Merkle-tree action caches, and Nix input-closure skipping are excluded by scope.
- **Live upstream Rust/Dart compilation and Docker-daemon benchmark execution — `not examined`:** All nine repositories were audited at exact pinned Git blobs and verified through standalone Python/POSIX-bash ports in `scripts/verify_build_env_pubgrub.py`, rather than compiling `uv`/`pubgrub-rs` or running live Dockerized LLM trajectories.
- **Prevalence of accidental false passes in published benchmark leaderboards — `unknown`:** Source inspection and `Probe 3` prove that `EnvBench`, `Repo2Run`, `SetupBench`, and `SWE-smith` accept the documented non-adversarial/adversarial failure states (`exit 0`, invalid `JAVA_HOME`, `returncode == 5`, `"Setup successful"` before crash, library `pytest.xfail()`), but determining how frequently released baseline trajectories triggered them unintentionally requires auditing raw per-run logs.
- **Scope limits of `--exclude-newer` and idealized DTMC models — `known not to apply`:**
  - Single-pass `--exclude-newer <commit_ts>` CDCL resolution does **not** prevent failures from deleted/yanked registry artifacts (`BugSwarm` `29.4%` of unreproducible jobs; `Tufano` `26%` `ArtifactResolutionException`), legacy indexes lacking PEP 700 `upload-time` metadata or unpinned Git branch URLs (`uv` `resolver/mod.rs:2754, 2766`), unconstrained `setup.py` `sdist` build-time dependencies, or missing system `apt`/C/CUDA libraries and Git submodules (`ExecutionAgent` `2/9`).
  - The survival percentages in `Probe 4` and finite-budget yield curves in `Probe 5` are outputs of their stated synthetic hazard and transition parameters, not universal empirical constants.
- **Un-forked single-pass universal locking — `unsupported`:** Classical un-forked `PubGrub` (`dart-lang/pub`, `pubgrub-rs`) enforces a single flat assignment per package name and cannot natively resolve mutually incompatible platform/Python-minor dependency branches into one universal lockfile without an outer marker-partitioning scheduler (`astral-sh/uv` `ForkState`).
