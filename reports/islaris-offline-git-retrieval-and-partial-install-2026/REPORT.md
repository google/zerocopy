# Offline Islaris source retrieval after a partial install: local Git transport and a collection-limit stop

## Summary

A verified Git object cache was insufficient for an offline opam install: opam 2.1.6 still fetched the original remotes for unpinned Git sources before checking freshness. The first install completed 53 of the selected 74 package actions, then returned 40 with 21 source-fetch failures. A separate, audited, read-only local Git provider subsequently served the same eight fixed commits without changing metadata URLs, versions, pins or development filters.

The next actual offline `--download-only` operation returned 0 and emitted successful retrieval messages for all 21 pending source consumers. Its exact selection and all scheduled postconditions passed. **The enclosing controller nevertheless returned 1:** redundant solver-graph copying exceeded its monitored 256 MiB host-artifact threshold. The exact container was stopped successfully, without retry. This is a useful source-readiness observation inside an overall partial operational outcome, not a full-gate success, completed 74-package installation or Islaris theorem result.

## Findings

### A source cache and an installer-ready offline transport are different inputs

Basis: source + execution + derived.

The first offline install's raw native JSON reports exactly 53 distinct successful install actions and 21 source-download failures. The later stopped-state identity and recovery state agree with those 53 versions. The disjoint union is the original exact 74-package selection. The install took 760.237923 seconds at the recorded native phase scope; its enclosing controller recorded 771.301710 seconds. The native status was 40, with original-remote Git/DNS failures under network none. These failures concern 21 consumers of eight fixed Git source artifacts, including all 12 old Sail siblings; they do not establish absent source objects or a compiler incompatibility. The installed set includes Coq 8.19.0, Dune 3.9.1, Menhir 20260209, Lem 2026-05-01, Yojson 3.0.0 and bisect_ppx 2.8.3. Their successful package actions do not show that the old Sail/Islaris combination builds.

The inspected backend explains the failure. `OpamRepository.pull_tree` cannot use the checksum-addressed file-cache route for these checksumless Git source coordinates. `OpamVCS.pull_url` follows clean → fetch → freshness even for an existing repository. `OpamGit.fetch` uses the object-sharing cache but still requests the original base URL/full commit; a failing fallback fetch can abort before later commit handling. `--skip-updates` suppresses source-pinned pre-updates, not this unpinned retrieval path. `--reuse-build-dir` does not remove Fetch vertices. Source-directory pins or a `--working-dir` bypass were not used. Narrow source coordinates and hashes are in [PRIMARY.json](support/PRIMARY.json); relevant symbols are `src/repository/opamRepository.ml:98–109,240–281`, `opamVCS.ml:76–102`, `opamGit.ml:64–117`, and `src/client/opamAction.ml:240–275` at the pinned opam revision.

### Local file transport preserved the source and filter subject

Basis: documentation + source + execution.

A complete separate copy of the audited bare cache became `/solve/offline-git-origin`, made read-only after preparation. It was not the mutable consumer cache and was not a new mirror selecting different commits. Exact eight-base-URL `insteadOf` mappings routed normal Git requests to that provider while preserving the original opam metadata URLs/full commit fragments. The exact mapping is retained with the transport inputs. Git runtime controls disabled hooks, fsmonitor, untracked-cache use, prompting, system configuration and every protocol except file; packing used one thread. PATH was explicitly `/usr/bin:/bin`, direct Git commands used `/usr/bin/git`, and inherited container GIT_* variables were rejected.

The Git-only gate returned 0 in 48.987434 seconds at parent invocation scope. Eight independent bare fetch probes retained the exact commit/tree/ref identities, non-shallow status, no alternates and successful strict fsck. The controller checked 4,935 globally distinct selected object identities in the provider and 4,998 per-repository object comparisons across the eight probes; these are different counts. Its complete source/cache/config/state checks passed. This establishes readiness of the required current commit/tree closure, not an independent proof of upstream history, Git correctness or package build compatibility. The [transport receipt review](support/transport-review.json) rehashed retained records and ledgers, not a second native streaming of most object bodies.

### The actual download-only operation succeeded within the partial state

Basis: source + execution + derived.

The recovery preflight dry solve returned 0 in 10.405360 seconds; actual download-only returned 0 in 9.661343 seconds. Both actual native JSON requests and both exported CUDF requests retained **all 35 roots**; their planned solution was exactly the 21 pending installs. Installed 53 plus pending 21 equalled the original 74. The guard checked the current installed/root/pin context, selected dependency/conflict/request formulas and the exact switch-invariant node. Current filtered libsail still depended on bisect_ppx. It did not assume empty-switch CUDF numbering or filters were unchanged. These are bounded executable checks of exported CUDF; opam's metadata/filter conversion and checker correctness remain trust boundaries.

A producer-contract correction was necessary before this run. In this opam version, `opamSolution.ml:454–472` removes every non-Fetch vertex for download-only; `:677–714` then deliberately excludes Fetch vertices from JSON `results`. Successful output therefore has **`results: []`**, not 21 fabricated JSON Fetch entries. `opamAction.ml:240–296` emits the successful per-package retrieval messages. The actual run had exactly 21 distinct messages, one for every pending consumer, and no download-failures field. All 21 actual messages said `no changes`; the evidence records successful retrieval of already-current sources, not newly transferred bytes. Session hooks remain possible in download-only (`opamSolution.ml:1235–1268`), so both root and switch configs were checked to contain no pre/post/wrap command field. The no-Build/Install interpretation rests on that trusted client control flow, exact CLI and recorded postconditions, rather than a blanket assertion about all processes the client could execute.

All scheduled postchecks completed before collection stopped: exact installed 53/root 14/pins zero and root/switch config bytes; 19,429 protected metadata file hashes; 21 full Git source trees with important refs/config/HEAD and non-shallow identity; original cache and read-only provider contents/modes; 4,935 provider object identities again; and 11,962 installed-prefix file hashes plus entry inventories. The full source checks totalled 55,642 file-hash comparisons across two passes. All 21 Git bookkeeping changes were `FETCH_HEAD` changes; the worktrees and protected refs/config did not change. They are normal disclosed retrieval bookkeeping, not a claim that every `.git` byte stayed identical. See [DOWNLOAD-GATE.json](support/DOWNLOAD-GATE.json), [FILTER-CONTEXT.json](support/FILTER-CONTEXT.json), [GIT-BOOKKEEPING-DELTA.json](support/GIT-BOOKKEEPING-DELTA.json) and the [host fan-in](support/fan-in-results.json).

### Artifact collection failed after the useful operation and its postchecks

Basis: execution + derived.

The enclosing controller returned **1 after 80.135147 seconds**. While redundantly copying native solver outputs to host, phase 270 successfully read `download.dot`, then the controller's whole-native-run artifact predicate raised. The monitored 256 MiB ceiling had been exceeded; **final retained native-run artifacts totalled 274,060,624 bytes** after diagnostic/stop records. That final total is not an exact sampled trigger bytecount. Three identical 64,689,921-byte DOT payload copies and six identical 7,498,481-byte CUDF copies dominated the retained data. These copies came from the collector, not package installation or a new source failure.

The exact-CID stop command returned 0. All 270 recorded native phase receipts have status 0, including the final `cat`; the host controller's resource failure remains decisive. No full-gate `RESULTS.json` or final success inspection was produced. The most recent recorded running-state observation had SizeRw 447,180,800 bytes and no OOM flag; the 1 GiB native layer threshold was not the stopping condition. A separate preserved parent post-stop inspection confirms the same exact CID/image is stopped, with no OOM flag and SizeRw 447,180,800 bytes; the independent reviewer verified that receipt. No peak-memory claim follows. The run's total wall cap was 900 seconds, native phase cap 120 seconds plus 5-second kill grace, host-free floor 12 GiB and artifact sampling interval five seconds. These are observational stop thresholds, not filesystem quotas; streams and final diagnostic records can cross a threshold between samples.

The unexecuted v1 draft's incorrect Fetch-results guard was preserved; v2 corrected the producer contract; v3 changed host resource controls only. An initial host fan-in attempt also miscounted repeated phase labels as unique phase receipts; a separate corrected collector passed without changing the subject. Rejected records are preserved, with the narrow diagnosis. Neither correction converts the final collection failure into success.

## Boundaries

- **Known partial outcome:** 53 package installations were reported successful; all 21 missing source consumers were later retrieved offline at their fixed identities. The remaining 21 packages were not installed by the download-only operation, and no Islaris project theorem was checked here.
- **Not established:** old Sail compatibility with the selected modern transitive versions or Z3 4.15.3; remaining memory/disk/time cost; RV32/RV64 model generation or Coq proof completion; independent solver, Git, opam or compiler correctness. The old RISC-V package's later build/install covers both RV32 and RV64 and uses `-dcoq_undef_axioms`; those generated axioms remain load-bearing proof obligations, as documented by the earlier source report. A source identity check cannot discharge them.
- **No broader package-process claim:** the download-only client's Fetch-only graph, absent configured session/wrapper fields and unchanged installation state support the scoped interpretation above. This investigation did not record a syscall-level trace proving that no executable associated with any package could ever run.
- **Evidence projection:** public support omits graph payloads and duplicate CUDF copies while retaining their exact sizes/hashes and one complete CUDF. Private host workspace/tool prefixes are explicitly replaced with role placeholders. Original hashes and public hashes are separate; the projected controller is evidence, not a portable or authorized reproduction driver. No raw external extra-source body, package/source binary, OCI image, source mirror or whole metadata archive is included. Full source/object-body replay still requires the original cache or reacquisition. The archive projection does not alter the experiment or earlier source-audit publication.
- **Review limit:** the host fan-in rehashed 536 recorded streams, replayed the exported JSON/CUDF checks and recomputed source/ref/cache/prefix/bookkeeping ledger correspondences.
