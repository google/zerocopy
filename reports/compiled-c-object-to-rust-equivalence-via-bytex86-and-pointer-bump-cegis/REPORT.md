1. **Immediate-precedence `REX` prefix rule (`40 2E 88 DF` vs. `2E 40 88 DF`):** Under Intel SDM Vol. 2A §2.2.1, a `REX` byte (`0x40..0x4F`) is active **only** when it immediately precedes the primary opcode (or `0x0F` escape). A legacy segment/branch-hint prefix (`0x2E`) placed *after* `0x40` (`40 2E 88 DF`) nullifies `REX`, causing `rm = 7` to address high-byte `%bh` (`rbx = 0x112233445566AA77` on silicon) rather than `%dil`; reversing the prefix order (`2E 40 88 DF`) activates `REX`, leaving `%rbx` untouched and writing `%dil = 0xAA`. Both `ByteX86Gcc.scanPrefixes` and `VendorX86GccRef.scanLegacyAndRex` reset `rex := none` whenever any legacy group-1..4 prefix follows an earlier `REX` byte.
2. **15-byte maximum instruction length (`#GP(0)` vs. `#UD`):** Overlong prefix sequences exceeding `15` bytes (`14`×`0x66` + `0F 1F 00` = `17` bytes) raise `#GP(0)` (`trapno = 13`), whereas `LOCK`-prefixed `NOP` (`F0 0F 1F 00`) raises `#UD` (`trapno = 6`). Enforcing `pos + dispBytes + immBytes <= 15` inside `finishDecode` matches hardware fault classification across all `10` boundary `NOP` vectors.
3. **Legacy SSE2 preserve-upper vs. VEX zero-upper `YMM[255:128]` semantics:** On `gcc -O2`, `c_dot_u8_u16` emits legacy `66 0F EF C0` (`pxor xmm0, xmm0`), which preserves `YMM0[255:128]` (`0xCAFEBABE...` on silicon), whereas `gcc -O3 -mavx2` emits VEX `C5 E9 EF D2` (`vpxor xmm2, xmm2, xmm2`), which zeroes `YMM2[255:128]`. Parameterizing `writeXmm128 (zeroUpper : Bool)` by `SimdMode` (`false` on `.legacy128`, `true` on `.vex128`) captures both behaviors and enables exact tracking of missing-`vzeroupper` AVX-SSE transition hazards (`UpperYmmCleanOrPreserved`).
4. **Universal Pass-2 decoder commutation and step simulation (`ByteX86GccPass2.lean`):** Over all $2^{128}$ 16-byte instruction windows (`bs.length = 16`), `decodeRef_commutes_of_len16` proves `mapOutcome (decodeRef bs) = decodeX64 bs`, `decodeX64_prefix_invariant` proves decoded prefixes independent of trailing bytes, and `stepRef_simulates` proves `ByteX86Gcc.stepX64` refines `VendorX86GccRef.stepRef` across every non-faulting architectural state (`3,970` constants replayed in `2,391 ms` with `0` axioms on the standalone ISA core).

### 3. Safe-Rust `Tree Borrows` Alias-Guard Discharge and Shrink-Wrapped Frame Separation

`Basis: normative + source + derived`

In `c_xor_stream(uint8_t *dst, const uint8_t *src, size_t len, uint8_t key)` (intentionally written **without** C99 `restrict`), `gcc 15.2.0 -O3 -mavx2` emits at offset `0x459`:

```text
459: 48 8d 47 ff          lea    rax, [rdi - 1]
45d: 49 89 d0             mov    r8, rdx
460: 48 29 f0             sub    rax, rsi
463: 48 83 f8 1e          cmp    rax, 0x1e
467: 0f 86 5b 01 00 00    jbe    5c8 <c_xor_stream+0x178>
```

Unsigned `((dst - 1) - src) <= 30` tests whether `dst` lies in `[src + 1, src + 31]` (modulo $2^{64}$), where a `32`-byte store to `dst` would clobber unread bytes of the current `32`-byte load from `src` (`dst == src` wraps to `0xFFFF_FFFF_FFFF_FFFF > 30` because in-place `dst == src` is safe for streaming XOR). Under Rust's `&mut [u8]` / `&[u8]` FFI precondition (`XorStreamPre 16` in [`support/lean/RustFfiSpecs.lean`](support/lean/RustFfiSpecs.lean)):

- `NoWrapSlice dst len`, `NoWrapSlice src len`, and `DisjointSlices dst len src len` (`dst + len <= src ∨ src + len <= dst`) imply `((dst - 1) - src).toNat > 30` whenever `len >= 32`, `0 < dst.toNat`, and `src.toNat + 31 < 2^64` (`disjoint_slices_discharges_gcc_overlap_guard` in [`support/lean/UntrustedCObjHints.lean`](support/lean/UntrustedCObjHints.lean)).
- Consequently, `c_xor_stream_o3_avx2_overlap_guard_discharged` proves `(runX64 cFfiKernelsO3Avx2Obj 7 nd s0).rip = 0x40046d#64` (the `32`-byte AVX2 preheader), while `prove_c_xor_stream_o3_avx2` also proves the `0x5c8` scalar fallback so `CObjectMatchesRustContract` holds unconditionally even for `dst == 0` or `len < 32`.
- Meanwhile, `c_xor_stream -O3 -mavx2` leaves `%rsp` untouched (`sp_delta = 0`) across `len = 0`, the `0x5c8` scalar loop, the `32`-byte AVX2 loop, and the `16`-byte VEX-128 epilogue when `16 | len`, executing `push rbp; mov rbp, rsp; push rbx` (`sp_delta = -16`) at `0x531` **only** when `(len % 16) != 0` so it can use `%bl`/`%bh` (`88 DF`: `mov bh, bl`) to splat `key` into `%bx` before `pop rbx; leave; ret` at `0x602`. Modeling `DisjointFromStack ptr len rsp0 16` and `InPrivateStackWindow addr rsp0 16` (`[rsp0 - 16, rsp0)`) frames out the temporary `[rsp0 - 16, rsp0)` spill slots while proving caller memory at `>= rsp0` (including the return address) and all non-`dst` heap/slice bytes strictly unchanged.

### 4. Width-Independent 1-Bit Mealy Pointer-Bump Slicing and `Pass1GmpLrat` Certificate Compression

`Basis: execution + source + derived`

When `gcc -O2` / `-O3` eliminates an explicit loop counter `k` in favor of a pointer-bump cursor `ptr = base + k * U` (`add rdi, 1; cmp rdi, rsi; jne`), a naive bit-blasted step verification condition over $W$-bit bitvectors must simultaneously prove:

1. **Step associativity:** `(base + done) + U = base + (done + U)`, and
2. **Exit cancellation:** `((base + done') = (base + len)) <-> (done' = len)`.

Under CDCL resolution (`CaDiCaL 2.1.2 --lrat --no-elim --binary=false`), monolithic 16-bit ripple-carry encoding of these two obligations produces `302,812–728,167 B` of packed `Pass1GmpLrat` proof text per function (`5,416,802 B` total across the `12` functions), exceeding per-module size caps and Lean `v4.34.1`'s `by rfl` elaboration budget. Even narrowing `W` to `8` bits still requires `835` trimmed RUP steps (`98.1 KB`) for pointer-bump alone, whereas narrowing the `c_xor_stream -O3` disjoint-slice guard to `W = 6` (`0..63`) silently makes `len >= 32 ∧ dst > 0 ∧ DisjointSlices` **vacuously UNSAT** (`1 + 32 + 32 = 65 >= 64`).

Combining this width-independent transducer with each kernel's bit-accurate data/control obligation (`W = 7` `0..127` for `xor_avx2_32_alias`, preserving exact GCC constants `32`, `31`, `30`) and **mechanically asserting precondition satisfiability (`CaDiCaL exit 10`) before negating the conclusion** yields `14x–27x` smaller non-vacuous `Pass1GmpLrat` certificates across all `8` distinct machine-code kernels (`12 / 12` functions):

## Boundaries

- **Relocations, PLT/GOT calls, and multi-TU linking (`not examined`):** All `16` functions in `c_ffi_kernels.c` and `c_ffi_bugs.c` are self-contained leaf `.text` functions without ELF relocations (`R_X86_64_PLT32`, `R_X86_64_PC32`), external `call` instructions, thread-local storage (`%fs:0`), or `.rodata` jump tables. Extending `X64ObjImage` to linked multi-object archives or `.rodata` constant pools requires modeling symbol/relocation resolution and `call`/`ret` stack-depth composition.
- **Floating-point, AVX-512 (`EVEX`), and atomic/system instructions (`unsupported`):** `ByteX86Gcc` and `VendorX86GccRef` fail closed (`.fault .unsupported`) on x87/SSE/AVX scalar/packed IEEE-754 floating-point opcodes, `EVEX` (`0x62`) prefixes, `LOCK`-prefixed RMW atomics (`lock cmpxchg`, `lock xadd`), and `syscall`.
- **Full automatic synthesis of end-to-end `ByteX86Gcc` Lean tactic proofs (`known not to apply`):** While `verify_c_obj_rust_equiv.py` automatically extracts `.o` CFG metadata, checks precondition non-vacuity, and synthesizes `0`-manual-invariant-LOC `Pass1GmpLrat` certificates (`AutoCert*.lean`) checked by `rfl`, bridging those certificates to full `ByteMem` + 64-bit `ByteX86Gcc.runX64` theorems (`UntrustedCObj*.lean`) currently uses structured per-kernel Lean proof scripts (`UntrustedCObjScalarLoops.lean`, `UntrustedCObjMutLoops.lean`, `UntrustedCObjDotSimd.lean`, `UntrustedCObjDotAvx2*.lean`, `UntrustedCObjXorAvx2*.lean`). Fully automatic proof-term emission from `CObjEquivCert` to `CObjectMatchesRustContract` over `ByteX86Gcc` was not built here.
- **Sub-page cross-page vector over-read faults on `c_dot_u8_u16` / `c_xor_stream` (`not examined` in `ByteMem`):** `ByteX86Gcc.ByteMem` is a total map `BitVec 64 -> BitVec 8` (modeling flat virtual memory without per-page `PROT_NONE` permissions), whereas `gcc 15.2.0`'s vector loops strictly bound all loads within `[ptr, ptr + byteLen)` (`done + 32 <= len` for `vmovdqu ymm`, `done + 16 <= len` for `vmovdqu xmm`, `done + 8 <= len` for `vmovq`). Speculative cross-page vector loads on unaligned tails (such as `pcmpeqb` `strlen`) require pairing `ByteX86Gcc` with a page-permission predicate.
- **Compiler flag sensitivity (`known not to apply` without re-extraction):** Adding `-fstack-protector-strong`, `-fcf-protection=full` (`endbr64`), Clang/LLVM `-O3` unrolling, or `-march=x86-64-v4` changes the emitted `.text` byte stream and requires re-extracting `CompiledCObjImages.lean` (and adding `F3 0F 1E FA` `endbr64` if CET is enabled).
