# LLVM 23.1.1 Interprocedural, Link-Time, and Machine Code Generation Optimizations: Closed-World Assumptions, Algorithms, and Proof Obligations

## Summary

Interprocedural optimizations (IPO), Link-Time Optimization (`ThinLTO` and `FatLTO`), and backend `MachineFunction` code-generation passes in LLVM 23.1.1 (`1b9c0d5ff9bbe7634aead059efe6b11a7eeba145`) introduce verification obligations that fundamentally differ from intra-procedural scalar/loop passes:

1. **Interprocedural and Link-Time Optimizations (`llvm/lib/Transforms/IPO/`, `support/ipo_lto_codegen_pass_metrics.json`)**:
   - **Closed-World Scope Gating**: Every interprocedural transformation that alters a function's calling signature (`ArgumentPromotion`, `DeadArgumentElimination`), folds constant arguments across call sites (`IPSCCP`, `FunctionSpecialization`), shrinks or promotes global variables (`GlobalOpt`), or deletes unreferenced symbols (`GlobalDCE`) is gated by linkage visibility predicates (`GlobalValue::hasLocalLinkage()`, `hasExactDefinition()`, and `!GlobalValue::isInterposable()`).
   - **How `rustc` Supplies the Closed-World Boundary (`lto.rs` and `PassWrapper.cpp`)**: Before running `ThinLTO` or `FatLTO`, `rustc` (`compiler/rustc_codegen_llvm/src/back/lto.rs:250-580`, `PassWrapper.cpp:1144-1157`) computes an explicit export list (`exported_symbols` + linker-plugin symbol resolution + compiler runtime symbols) and internalizes (`internalizeModule` / `thinLTOInternalizeModule`) every non-exported symbol to `internal` linkage.
   - **Inliner Scope Metadata Translation (`InlineFunction.cpp`, `3,574` LOC)**: The single most critical soundness step during inlining (`AddAliasScopeMetadata`) translates every `noalias` pointer parameter of the callee (which `rustc` emits on all `&mut T` and `&T` parameters) into a fresh per-callsite `!alias.scope` metadata domain attached to callee memory accesses and `!noalias` metadata attached to all other callee accesses. Without this translation, inlining erases Rust's reference aliasing guarantees; if the translation is misapplied across recursive or cloned blocks, it causes silent miscompilations.

2. **Code-Generation (`MachineFunction`) Passes (`llvm/lib/CodeGen/` and `llvm/lib/Target/{X86,AArch64}/`)**:
   - Lowering transitions through three IR representations: late LLVM IR (`CodeGenPrepare` `9,478` LOC, `AtomicExpand`, `DwarfEHPrepare`), selection graphs (`SelectionDAGISel` + `DAGCombiner` `36,636` LOC + `X86ISelLowering` `64,729` LOC / `AArch64ISelLowering` `35,375` LOC, or `GlobalISel` `39,686` LOC at AArch64 `-O0`), and `MachineFunction` / `MCInst` (`RegisterCoalescer` `4,234` LOC, `RAGreedy` + `SpillPlacement` + `SplitKit` `6,341` LOC, `MachineScheduler` `4,361` LOC, `PrologEpilogInserter` `1,546` LOC, `ShrinkWrap` `1,105` LOC, `MachineBlockPlacement` `3,646` LOC, `BranchFolding` `2,068` LOC, `TailDuplicator` `1,134` LOC, `MachineOutliner` `1,671` LOC, `CFIFixup`/`CFIInstrInserter` `646` LOC, and target peephole/pairing passes such as `AArch64LoadStoreOptimizer` `3,357` LOC and `X86OptimizeLEAs` `986` LOC).
   - **Verification Split**: `MachineScheduler` and `MachineBlockPlacement` are pure schedule/layout permutations whose correctness reduces to data/memory hazard preservation and branch condition inversion. Register allocation (`RegisterCoalescer` + `RAGreedy`) reduces to an a posteriori live-range homomorphism checker (verified in CompCert `RegAlloc` / IRC and Rideau-Leroy parallel move lowering). The primary semantic proof burden in codegen resides in `SelectionDAG` / `DAGCombiner`, `PrologEpilogInserter` + `ShrinkWrap` (stack-frame separation and callee-saved register restoration), and `AArch64LoadStoreOptimizer` (`ldp`/`stp` pairing across potential aliasing or volatile/unaligned boundaries).

## Applicability

These findings apply to `rustc` `1.99.1` (`58cf8f9c35b355199727627d07ae34a4e2846d67`) and its bundled LLVM 23.1.1 (`1b9c0d5ff9bbe7634aead059efe6b11a7eeba145`) across `-O0`..`-O3`/`-Os`/`-Oz` and all LTO modes (`No`, `ThinLocal`, `Thin`, `Fat`). Exact LOC and mutation metrics are preserved in `support/ipo_lto_codegen_pass_metrics.json`.

### 1. Interprocedural and Link-Time Optimizations (IPO & LTO)

**Basis: source + normative + derived**

#### 1.2 Algorithm and Proof Obligations of Key IPO Passes

1. **The Inliner (`Inliner.cpp` + `InlineCost.cpp` + `InlineFunction.cpp`)**:
   - **Cost Model (`InlineCostCallAnalyzer`, `3,465` LOC)**: Simulates the callee body under known constant/sroa/jump-threading arguments from the call site, summing instruction costs (`InstrCost = 5`) minus simplified dead-block savings against thresholds (`DefaultThreshold = 225` at `-O2`, `275` at `-O3`, `75` at `-Os`, `5` at `-Oz`, scaled by `0.1` for `cold` callees).
   - **Transformation (`llvm::InlineFunction`, `3,574` LOC, `67` mutation sites)**:
     1. Clones callee basic blocks into the caller (`CloneAndPruneFunctionInto`), mapping parameters to actual arguments and remapping `ret` instructions to branch to a `AfterCallBB` (with a `PHINode` if multiple `ret`s exist).
     2. Hoists static `alloca`s from the callee's entry block into the caller's entry block and brackets them with `@llvm.lifetime.start` and `@llvm.lifetime.end` (`emit_lifetime_markers`) so stack space is reused across sequential calls!
     3. Propagates unwind edges: if the call site is an `invoke ... unwind label %lpad`, rewrites every `call` inside the inlined body that may unwind into an `invoke ... unwind label %lpad`, and merges inner `resume` instructions into `%lpad`.
     4. **Scoped `noalias` Translation (`AddAliasScopeMetadata`)**: For every callee pointer parameter carrying `noalias`, generates a fresh metadata scope `!scope_i` and attaches `!alias.scope !{!scope_i}` to all memory instructions inside the callee that may access that parameter's provenance, and `!noalias !{!scope_i}` to all memory instructions inside the callee that cannot be derived from that parameter (`PointerMayBeCapturedBefore`). Note that `rustc` explicitly sets `-preserve-alignment-assumptions-during-inlining=false` (`llvm_util.rs:136`), so `AddAlignmentAssumptions` is skipped.
   - **Bug history (including Alive2)**:
     - **`byval` parameter inlining without copy when pointee is modified (`llvm/llvm-project#48980`)**: Inlining a callee with `ptr byval(%T) %p` requires allocating a fresh temporary `alloca %T` and `memcpy`ing the caller's argument unless the callee is proven `readonly` on `%p` AND no other pointer in the callee can write to the caller's underlying object during the call!
     - **`noalias` metadata scope duplication on recursive/loop inlining**: If an inlined block containing `!alias.scope` is later unrolled or jump-threaded without cloning the scope (or without `@llvm.experimental.noalias.scope.decl`), two distinct dynamic invocations share the same `!alias.scope` and falsely claim `NoAlias` with each other.
   - **Derivation facts needed**: Beta-reduction / call-stack frame flattening simulation (`CompCert` `Inliningproof.v` uses a prefix frame-injection `mem_inject` embedding callee stack blocks into the caller's stack block), plus a provenance Partition Check verifying that every instruction tagged with `!noalias !{!scope_i}` in the inlined body is provably independent of parameter $i$.

2. **Attribute Inference (`PostOrderFunctionAttrs` / `RPOFunctionAttrs`, `2,283` LOC)**:
   - **Algorithm**: Over each CGSCC $S = \{f_1, \dots, f_k\}$, computes a summary of memory effects (`MemoryEffects`: `none`, `read`, `write`, `argmem`, `inaccessiblemem`, `other`), pointer capture (`PointerCaptures`: `captures(none)`, `captures(address)`, `captures(read_provenance)`), `nounwind`, `willreturn` (requires every loop in $f_i$ to have a bounded trip count or `mustprogress` and no recursion within $S$), `nofree`, `nosync`, and `nonnull` return values.
   - **Proof obligation**: Coinductive/inductive summary soundness over the SCC call graph. **Bug history**: Inferring `willreturn` or `readnone` on mutually recursive functions or loops that can diverge (`llvm/llvm-project#50146`), which subsequently allows `ADCE` or `DeadStoreElimination` to delete calls to the diverging function!

3. **`ArgumentPromotion` (`967` LOC) & `DeadArgumentElimination` (`1,119` LOC)**:
   - **Algorithm**: `ArgumentPromotion` (`-O3` only) inspects `ptr` parameters of `internal` functions. If the pointer is only loaded (never stored or captured) at constant byte offsets $\{o_1, \dots, o_m\}$, and either the loads execute unconditionally on entry (`isSafeToExecuteUnconditionally`) or the pointer is `dereferenceable(max_offset)` and `aligned`, it lifts the loads into every caller before the call and passes the loaded scalars by value.
   - **Proof obligation**: For `ArgumentPromotion`, speculative load safety in the caller: if the callee only loaded `*p` under `if (cond)`, hoisting the load of `*p` unconditionally to the call site is sound **only** if `p` is `dereferenceable` and `align`ed at the call site and no write aliases `*p` before the conditional load in the callee!

### 2. Code-Generation (`MachineFunction`) Passes

**Basis: source + execution + derived**

#### 2.1 Pre-ISel IR Preparation: `CodeGenPrepare` (`lib/CodeGen/CodeGenPrepare.cpp`, `9,478` LOC, `199` mutation sites)
- **Algorithm**: Runs late on LLVM IR immediately before Instruction Selection (`SelectionDAGISel` / `GlobalISel`) to expose target-specific idioms across basic-block boundaries (since `SelectionDAG` operates on one basic block at a time):
  1. **Addressing-Mode Sinking (`optimizeMemoryInst`)**: Pattern-matches `GEP` + `add`/`mul`/`sext`/`zext` address calculations dominating a load/store and sinks/clones them into the load/store's basic block (`AddressingModeMatcher`) so `SelectionDAG` folds them into a single `[base + index * scale + disp]` instruction.
  2. **Extends/Truncates Placement (`optimizeExtUses`, `TypePromotion`)**: Moves `zext`/`sext` to match free target load-extend instructions.
  3. **Select-to-Branch Conversion (`optimizeSelectInst`)**: Converts `select` back into a diamond `br` when `TargetLowering::isPredictableSelectExpensive` holds.
  4. **Tail-Call Return Duplication (`dupRetToEnableTailCallOpts`)**: Duplicates a `ret` block into predecessors ending in a `tail call` so ISel can emit a `TAILJMP`.
- **Proof obligation**: Standard LLVM IR local equivalence (`AddressingModeMatcher` clones pure arithmetic expressions into dominated blocks; `dupRet` is a 1-block CFG tail duplication).

#### 2.2 Instruction Selection: `SelectionDAGISel` (`4,637` LOC) + `DAGCombiner` (`31,999` LOC, `181` `CombineTo` sites) vs `GlobalISel` (`39,686` LOC, `274` mutation sites)
- **Algorithm**:
  - **`SelectionDAGISel`**:
    1. `SelectionDAGBuilder` (`12,922` LOC) lowers one basic block of LLVM IR into a SelectionDAG (where nodes carry value edges, `Chain` token edges for ordering memory/side-effecting operations, and `Glue` edges for adjacent flag-setting instructions).
    2. Iterative Legalization & Combining: alternates `DAGCombiner` (`31,999` LOC) with `LegalizeTypes` (`10,636` LOC: promotes/expands/scalarizes non-native integer, float, and vector types, e.g., `i128` $\to$ pair of `i64`s), `LegalizeVectorOps`, and `LegalizeDAG` (`5,637` LOC: expands unsupported operations into target custom lowerings `X86ISelLowering.cpp` `64,729` LOC / `AArch64ISelLowering.cpp` `35,375` LOC or runtime libcalls).
    3. `SelectCodeCommon` (`X86ISelDAGToDAG.cpp` / `AArch64ISelDAGToDAG.cpp` + TableGen bytecode matcher `MatcherTable`): matches target `SDNode` patterns bottom-up into target `MachineSDNode`s.
    4. `ScheduleDAGRRList` (`3,275` LOC): linearizes the DAG back into sequential `MachineInstr`s respecting `Chain`, `Glue`, and register pressure constraints.
  - **`GlobalISel` (`lib/CodeGen/GlobalISel/`, `39,686` LOC)**: Runs on whole `MachineFunction`s in 5 passes: `IRTranslator` (LLVM IR $\to$ generic `G_*` `MachineInstr`s) $\to$ `PreLegalizerCombiner` $\to$ `Legalizer` $\to$ `PostLegalizerLowering` $\to$ `RegBankSelect` (assigns GPR vs FPR register banks) $\to$ `InstructionSelect` (TableGen/C++ matcher from `G_*` to target opcodes). In `rustc` `1.99.1`, `GlobalISel` is used by default **only at `-O0` on AArch64** (`support/codegen_aarch64-unknown-linux-gnu_O0.txt`).
- **Bug history**:
  - **`DAGCombiner` `Chain` cycle and alias bugs**: Dropping or miswiring a `Chain` token edge when combining two loads or forwarding a store to a load allows `ScheduleDAGRRList` to reorder a load past an aliasing store!
  - **Undef/Poison freeze drop in `SelectionDAG`**: Because `SelectionDAG` represents both `undef` and `poison` as `ISD::UNDEF` (`ISD::FREEZE` was added later), `DAGCombiner` folds on `ISD::UNDEF` have historically reintroduced multi-use `undef` inconsistencies after IR-level `freeze`.
- **Verified precedents**: CompCert `Selectionproof.v` (verified maximal-munch instruction selector over Cminor $\to$ CminorSel); CakeML `instruction_selection`; Cranelift `veri-isle` (SMT verification of ISLE instruction selection rules against Sail/ASL ISA semantics).
- **Derivation facts needed**: Symbolic DAG-to-MachineBB symbolic evaluation (or rule-by-rule `CombineTo` / `SelectNodeTo` step witnesses) proving that for every basic block, the linear sequence of emitted `MachineInstr`s refines the input LLVM IR basic block on live-out virtual registers and memory `Chain` state.

#### 2.3 Register Coalescing (`RegisterCoalescer`, `4,234` LOC), `RAGreedy` (`3,407` LOC), `SpillPlacement` (`406` LOC), and `VirtRegMap` (`719` LOC)
- **Algorithm**:
  1. `PHIElimination` (`774` LOC) + `TwoAddressInstructionPass` (`2,021` LOC) lower SSA `PHI`s into predecessor `COPY` instructions and tie 2-address operands (`%dst = OP %dst, %src` on x86).
  2. `RegisterCoalescer` (`lib/CodeGen/RegisterCoalescer.cpp`) eliminates `COPY %v1, %v2` by merging `LiveInterval`s when their live ranges do not interfere (or when values are identical along overlapping sub-ranges, including subregister lane masks).
  3. `RAGreedy` (`lib/CodeGen/RegAllocGreedy.cpp`) allocates virtual registers to physical registers using a priority queue ordered by allocation stage (`RS_Assign`, `RS_Split`, `RS_Spill`) and size:
     - Attempts direct physical assignment (`tryAssign`);
     - Evicts lower-weight interfering virtual registers (`tryEvict`);
     - Splits live ranges across loop/cold boundaries using `SplitKit` (`2,528` LOC) and Hopfield-network global spill placement (`SpillPlacement.cpp`, `406` LOC: `tryRegionSplit`, `tryBlockSplit`, `tryLocalSplit`);
     - Spills to `StackSlot`s via `InlineSpiller` when splitting cannot reduce pressure, followed by `VirtRegRewriter` (`VirtRegMap.cpp`, `719` LOC) which replaces virtual registers with assigned physical registers and materializes stack reload/spill instructions.
- **Correctness argument & Verified Precedents**: Register allocation does **not** require verifying the heuristics of `RAGreedy` or `SpillPlacement`. As established in CompCert (`backend/Allocproof.v` and IRC `regalloc`) and Rideau, Serpette & Leroy ("Tilting at Windmills with Coq: Formal Verification of Parallel Move Lowering", JAR 2008), a **translation validator for register allocation** only checks a lightweight dataflow equation system $\Phi(p)(\text{vreg}) \in \text{PhysReg} \cup \text{StackSlot}$ at every program point $p$:
  1. Every live virtual register $v$ at point $p$ is held in location $\Phi(p)(v)$;
  2. Distinct simultaneously live virtual registers $v_1 \neq v_2$ map to disjoint physical registers/stack slots ($\Phi(p)(v_1) \cap \Phi(p)(v_2) = \emptyset$);
  3. Every instruction / spill / reload / parallel-move sequence preserves the homomorphism $\Phi$.

## Boundaries

- **Attributor pass**: Although `Attributor.cpp` (`3,607` LOC) and `AttributorAttributes.cpp` (`13,294` LOC) total `16,901` LOC in `llvm/lib/Transforms/IPO/`, `PassBuilderPipelines.cpp:296` disables `Attributor` by default (`cl::init(AttributorRunOption::NONE)`). Thus a drop-in `rustc` replacement or certifying pipeline does **not** need to verify `Attributor` for standard `-O0`..`-O3`/`-Os`/`-Oz` or LTO builds; only `PostOrderFunctionAttrsPass` and `ReversePostOrderFunctionAttrsPass` (`FunctionAttrs.cpp`, `2,283` LOC) run.
- **Cross-language Linker-Plugin LTO (`-C linker-plugin-lto`)**: When `rustc` emits bitcode for `lld`/`gold` linker-plugin LTO alongside C/C++ Clang bitcode, the post-link closed-world symbol resolution is supplied by the system linker's `lto::Config` resolution table rather than `rustc`'s internal `lto.rs`.
