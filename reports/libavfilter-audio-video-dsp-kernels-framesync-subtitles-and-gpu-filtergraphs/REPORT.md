# FFmpeg `libavfilter` Audio/Video DSP Kernels, `FFFrameSync`, Subtitle Rendering, and GPU Filtergraphs

## Summary

At commit `7ddf7bc8a482cf28b4fab2e63b7093ba35cb6a80`, FFmpeg's `libavfilter` registers exactly **601 `FFFilter` nodes** (`392` video `vf_*`, `141` audio `af_*`, `32` video sources `vsrc_*`, `17` multimedia `avf_*`, `11` audio sources `asrc_*`, `3` multimedia sources `avsrc_*`, `2` video sinks, `2` audio sinks, and `1` video-to-audio `vaf_spectrumsynth`) across `831` files in `libavfilter/`, while the repository as a whole embeds **94 GPU shader source files** (`47` in `libavfilter/` and `47` in `libavcodec/vulkan/`). Unlike `libavcodec`, CPU SIMD coverage in `libavfilter` is heavily skewed toward `x86_64` (`42` NASM `.asm` modules in `libavfilter/x86/`), with only **4 AArch64 NEON assembly modules** (`vf_bwdif`, `vf_colordetect`, `vf_nlmeans`, `vf_threshold`), **3 RISC-V Vector (RVV) assembly modules** (`af_afir`, `scene_sad`, `vf_blackdetect`), and **zero** subdirectories for 32-bit ARM, PowerPC VSX, LoongArch LSX/LASX, MIPS, or WebAssembly SIMD128.

A clean-room, formally verified Rust media filter subsystem must separate five structural invariants from historical C implementation artifacts:

1. **Multi-input synchronization (`FFFrameSync`, `libavfilter/framesync.c`):** `framesync_advance` enforces an all-inputs 1-frame lookahead barrier (`have_next == 1` across every non-EOF pad) that avoids requesting frames on already-populated pads (`framesync.c:344-346`) yet experiences unbounded upstream `FFFrameQueue` growth across split-merge diamonds with asymmetric branch latency, contains a signed 64-bit subtraction overflow UB hazard in `TS_NEAREST` mode (`framesync.c:211`), and silently defeats zero-copy in-place compositing in `ff_framesync_init_dualinput` (`framesync.c:286, 384`) unless `eof_action=pass` (`repeatlast=0`) clears `in[1].sync`.
2. **Zero-copy view and SIMD-alignment tension (`vf_crop`, `vf_pad`, `vf_zscale`):** `vf_crop` mutates `AVFrame.data[p]` interior pointers without buffer reallocation (`vf_crop.c:320-336`), routinely destroying 32/64-byte base alignment and forcing downstream `zimg`-backed `vf_zscale` (`ZIMG_ALIGNMENT = 64`) into full-frame reallocation and `memcpy` (`vf_zscale.c:663-687`). `vf_pad` achieves zero-copy padding via upstream `get_video_buffer` over-allocation plus forward pointer shift (`vf_pad.c:235-262`) followed by negative pointer rewind (`out->data[i] -= ...`, `vf_pad.c:381-386`)—a pattern that violates Rust narrowed-slice provenance under Stacked/Tree Borrows unless modeled as an immutable parent allocation handle paired with explicit `(offset, stride, width, height)` view coordinates.
3. **High-SIMD video and audio DSP arithmetic:** `vf_nlmeans` computes 2D summed-area tables in `uint32_t` (`vf_nlmeans.c:52, 262`), wrapping modulo $2^{32}$ up to `125` times on a 4K UHD frame while remaining algebraically exact via $(\mathbb{Z}/2^{32}\mathbb{Z}, +)$ 4-corner cancellation for all patch widths $P \le 257$ (well above FFmpeg's `patch_size <= 99` ceiling). Conversely, `af_biquads` (`af_biquads.c:201-601`) runs recursive IIR loops without IEEE-754 subnormal flushing (`FTZ`/`DAZ`), incurring a measured **`13.55x` throughput collapse** (`68.107 ns/sample` vs `5.025 ns/sample`) during decay into silence and undefined `(int32_t)NaN` / `(int16_t)NaN` casts on unstable poles, while `af_atempo` (`af_atempo.c:268-273, 1016-1025`) triggers an unconditional `av_assert0` process abort when `sample_rate < 24` and `0.0 / 0.0` `NaN` window poisoning when `24 <= sample_rate < 48`.
4. **Heterogeneous GPU filtergraphs (`94` shaders across Vulkan, CUDA, OpenCL, Metal):** FFmpeg compiles Vulkan `.comp.glsl` (`22` in `libavfilter/vulkan/`, `47` in `libavcodec/vulkan/`) offline to SPIR-V (`%.spv.c`), CUDA `.cu` (`10` in `libavfilter/`) offline to PTX, Metal `.metal` (`1` in `libavfilter/metal/`) offline to `.metallib`, and JIT-compiles OpenCL `.cl` (`14` in `libavfilter/opencl/`) from C strings at runtime. Vulkan `bwdif.comp.glsl` operates on normalized `vec4` floats with epsilon thresholds (`unit * 0.75`, `unit * 0.5`) and therefore diverges by $\pm 1$ ULP from integer-exact CPU `bwdifdsp.c` and CUDA `vf_bwdif_cuda.cu`.
5. **Subtitle decoding and rendering (`dvbsub`, `pgssub`, `ccaption`, `webvtt`, `libass` vs `fontations` + `harfruzz`):** `libavcodec/dvbsubdec.c` fails to advance `destbuf` on `non_modifying_colour_flag == 1` (`bits == 1`) pixels and runs across all 2/4/8-bit RLE readers (`dvbsubdec.c:505-511, 539-578, 627-656`), desynchronizing horizontal coordinates against ETSI EN 300 743 §7.2.5.2. Replacing `libass`'s C FreeType + HarfBuzz stack with safe Rust `googlefonts/fontations` (`read-fonts`, `skrifa`) and `harfbuzz/harfruzz` (`harfrust`) eliminates the font-table and OpenType shaping memory-safety surface, but leaves ASS override-tag parsing, 3D perspective outline projection (`\frx/\fry/\frz`), analytic Bézier stroking (`\bord`), BiDi reordering, and tile-based SIMD analytic rasterization (`ass_rasterizer.c`, `ass_blur.c`) to be clean-room authored in Rust.

### 2. `FFFrameSync`: Multi-Input Timestamp Alignment, Choke Bounds, and Zero-Copy Pitfalls

`Basis: source + derived`

Multi-input video filters (`vf_overlay`, `vf_blend`, `vf_lut2`, `vf_maskedmerge`, `vf_xstack`, `vf_hstack`, `vf_vstack`, `vf_remap`, `vf_displace`, `vf_convolve`, `vf_libvmaf`, `vf_psnr`, `vf_ssim`) delegate pad activation and timestamp matching to `FFFrameSync` (`libavfilter/framesync.h:102-232`, `libavfilter/framesync.c:70-424`).

#### 2.1 State Machine and All-Inputs Lookahead Barrier
Each input stream `i in 0..nb_in` maintains a 3-state automaton (`STATE_BOF = 0`, `STATE_RUN = 1`, `STATE_EOF = 2`, `framesync.c:70-74`), a current retained frame `(frame, pts)`, and a 1-frame lookahead slot `(frame_next, pts_next, have_next)` rescaled into a common `fs->time_base` (`av_gcd_q` across active sync inputs, falling back to `AV_TIME_BASE_Q`, `framesync.c:160-177`).

In `framesync_advance` (`framesync.c:187-236`), event progression is gated by `consume_from_fifos(fs)` (`framesync.c:313-350`):
1. For every pad `i` where `!have_next && state != STATE_EOF`, `consume_from_fifos` attempts `ff_inlink_consume_frame`. If empty, it checks `ff_inlink_acknowledge_status`; if neither a frame nor EOF is present, `nb_miss++`.
2. **Strict barrier:** If `nb_miss > 0`, `consume_from_fifos` returns `0` (or `FFERROR_NOT_READY` if `nb_miss == nb_active && !ff_outlink_frame_wanted(ctx->outputs[0])`) after issuing `ff_inlink_request_frame(ctx->inputs[i])` **exclusively on missing pads (`!have_next && state != STATE_EOF`)** (`framesync.c:344-347`). `framesync_advance` never compares timestamps until **every** non-EOF input holds `have_next == 1`.
3. Once all non-EOF inputs hold `have_next == 1`, `pts = min_i(in[i].pts_next)` (`framesync.c:198-201`). Every stream `i` whose `pts_next == pts`—or under `TS_NEAREST` (`framesync.c:208-211`) whose `pts_next` is strictly closer to `pts` than its current `in[i].pts`, or where `before == EXT_INFINITY && state == STATE_BOF`—promotes `frame_next -> frame`, sets `have_next = 0`, and if `in[i].sync == fs->sync_level && in[i].frame != NULL`, sets `fs->frame_ready = 1` (subsequently suppressed at lines 228–232 if any input remains in `STATE_BOF` with `before == EXT_STOP`).

#### 2.2 Three Verification and Systems Hazards in `FFFrameSync`

1. **Unbounded diamond-DAG queue growth (`choke` hazard, `Basis: source + derived`):**
   While `consume_from_fifos` avoids pulling pads that already have `have_next == 1` (`framesync.c:345`), upstream fan-out filters (`vf_split` / `af_asplit`) push incoming frames unconditionally to **all** output links whenever **any** downstream branch requests a frame. In a diamond graph `split -> [branch0 (0-frame delay), branch1 (D-frame delay or +Delta_T PTS shift)] -> overlay`:
   - `overlay` pulls `in[1]` (`branch1`) because `in[0].have_next == 1` and `in[1].have_next == 0`.
   - Each pull on `branch1` causes `split` to enqueue another `AVFrame*` into `branch0`'s `FFFrameQueue` (`AVFilterLink.fifo`).
   - Neither `FFFrameSync` nor `FFFrameQueue` enforces a bounded capacity (`max_queued_frames`), so a delay of $D$ frames buffers $D$ full-resolution frames in `in[0]`'s link FIFO, and an uncompensated timestamp skew $\Delta T$ (or an upstream demuxer delivering interleaved packets with bursty audio/video muxing drift) grows `FFFrameQueue` proportionally to $\Delta T \cdot f_{\text{fps}}$ until heap exhaustion (`ENOMEM`). A clean-room Rust scheduler should expose explicit per-edge queue high-water marks returning a typed `GraphStall::BoundedQueueFull` error rather than unbounded allocation.

2. **Signed 64-bit subtraction overflow UB in `TS_NEAREST` (`framesync.c:208-211`, `Basis: source + derived`):**
   ```c
   (fs->in[i].ts_mode == TS_NEAREST &&
    fs->in[i].have_next &&
    fs->in[i].pts_next != INT64_MAX && fs->in[i].pts != AV_NOPTS_VALUE &&
    fs->in[i].pts_next - pts < pts - fs->in[i].pts)
   ```
   `framesync_inject_frame` (`framesync.c:251`) rescales timestamps with `AV_ROUND_PASS_MINMAX`, permitting `AV_NOPTS_VALUE` (`INT64_MIN`) or large negative/positive `int64_t` values into `pts_next` and `pts`. Even on finite timestamps (e.g., `in[i].pts = -5_000_000_000_000_000_000` and `pts = 5_000_000_000_000_000_000`, or non-monotonic input where `in[i].pts_next = INT64_MIN`), `pts - fs->in[i].pts` or `fs->in[i].pts_next - pts` overflows signed `int64_t` (C11 §6.5/5 UB; Rust panic under overflow checks). Widening timestamp distance comparisons to `i128` (after rejecting `AV_NOPTS_VALUE` on both `pts` and `pts_next`) makes `TS_NEAREST` unconditionally total and panic-free.

3. **Defeated zero-copy in `ff_framesync_init_dualinput` (`framesync.c:281-296, 372-388, 410-424`, `Basis: source + derived`):**
   `ff_framesync_init_dualinput` configures:
   - `in[0]` (main): `sync = 2`, `before = EXT_STOP`, `after = EXT_INFINITY`
   - `in[1]` (secondary): `sync = 1`, `before = EXT_NULL`, `after = EXT_INFINITY`
   When `vf_overlay` invokes `ff_framesync_dualinput_get_writable` (`vf_overlay.c:854`), `ff_framesync_get_frame(fs, 0, &mainpic, /*get=*/1)` (`framesync.c:284-294`) checks whether `fs->in[0].frame` must be retained inside `FFFrameSync`:
   ```c
   pts_next = fs->in[in].have_next ? fs->in[in].pts_next : INT64_MAX;
   for (i = 0; i < fs->nb_in && !need_copy; i++)
       if (i != in && fs->in[i].sync &&
           (!fs->in[i].have_next || fs->in[i].pts_next < pts_next))
           need_copy = 1;
   ```
   Because `in[1].sync` is initialized to `1` (so that if `in[0]` reaches EOF while `shortest == 0`, `framesync_sync_level_update` at `framesync.c:113-135` demotes `fs->sync_level` from `2` to `1` and repeats the final `main` frame across remaining `overlay` frames!), on **every synchronized frame pair** where both `in[0]` and `in[1]` advance together (`in[0].have_next == 0` and `in[1].have_next == 0`), `!fs->in[1].have_next` is true and `fs->in[1].sync` is `1`. Consequently, `need_copy` evaluates to `1`, `av_frame_clone` increments `mainpic`'s buffer reference count from `1` to `2`, and `ff_inlink_make_frame_writable` (`framesync.c:417`) **allocates a new full-frame buffer and `memcpy`s the entire `main` picture on every frame**—even for a $32 \times 32$ corner logo on 4K60 video! Only when the caller sets `eof_action=pass` or `repeatlast=0` does `ff_framesync_configure` (`framesync.c:149-154`) set `fs->in[1].sync = 0`, eliminating `av_frame_clone` when `in[0]` and `in[1]` advance in lockstep (or when `in[0]` runs at a higher frame rate than `in[1]`). A clean-room design can avoid this clone in the common `STATE_RUN` fast path whenever `in[0].have_next == 1` (proving `in[0]` has NOT reached EOF at the next step!) by checking `fs->in[i].sync >= fs->sync_level` whenever `fs->in[in].have_next && fs->in[in].frame_next != NULL`.

### 3. Video DSP Kernels and Zero-Copy Pointer-Offset Invariants

#### 3.1 Deinterlacing: `vf_yadif` vs `vf_bwdif` (`Basis: source + derived`)
Both `vf_yadif` (`libavfilter/vf_yadif.c:36-226`) and `vf_bwdif` (`libavfilter/vf_bwdif.c:53-185`, `libavfilter/bwdifdsp.c:47-226`) share `YADIFContext` (`yadif.h`) and require a 3-frame temporal window (`prev`, `cur`, `next`, introducing a mandatory 1-frame lookahead latency), copying unchanged parity lines via `memcpy` and synthesizing opposite-parity lines `(y ^ parity) & 1`:

- **Spatial-temporal tap geometry and border safety:**
  - `vf_yadif` evaluates a 5-angle horizontal edge-directed spatial score over `x + [-3..+3]` on neighbor lines `cur[mrefs .. prefs]` (`CHECK(-1)`, `CHECK(-2)`, `CHECK(1)`, `CHECK(2)` at `vf_yadif.c:36-63`). Because SIMD vector loads over `[x-3 .. x+3+V-1]` would step out of bounds on the leftmost 3 pixels and rightmost `3 + MAX_ALIGN/df - 1` pixels, `filter_slice` (`vf_yadif.c:199-220`) splits each interpolated scanline into an interior SIMD call `s->filter_line(dst + pix_3, ..., td->w - edge, ...)` (`edge = 3 + MAX_ALIGN / df - 1`, i.e., `10` pixels for 8-bit when `MAX_ALIGN = 8`) and a scalar `s->filter_edges` pass covering `[0, 3)` (with `is_not_edge = 0`), `[w - MAX_ALIGN/df + 1, w - 3)` (with `is_not_edge = 1`), and `[w - 3, w)` (with `is_not_edge = 0`). Vertically, `y == 0` and `y == h - 1` mirror `mrefs`/`prefs` inward (`y ? -refs : refs`), while `y == 1 || y + 2 == h` forces `mode = 2` to suppress `2 * mrefs` / `2 * prefs` spatial-temporal clamping reads (`vf_yadif.c:65-72, 210`).
  - `vf_bwdif` implements the BBC R&D PH-2071 (Weston 3-field) vertical-temporal filter with **zero horizontal offsets** (`x` only, making every horizontal SIMD lane completely independent!) and vertical taps reaching `±1, ±2, ±3, ±4` scanlines (`mrefs..mrefs4`, `prefs..prefs4`). Border scanlines `y < 4 || y + 5 > td->h` dispatch to `filter_edge` (`vf_bwdif.c:85-91`), while interior lines `4 <= y <= td->h - 5` dispatch to `filter_line`—or on AArch64 NEON (`libavfilter/aarch64/vf_bwdif_neon.S`), to **`filter_line3`** (`vf_bwdif.c:92-96`), which processes three interpolated lines (`y, y+2, y+4`) simultaneously to reuse overlapping `±4*refs` vertical vector loads in registers! Note `vf_bwdif.c:177` still rejects `chroma_w < 3` alongside `chroma_h < 4`—a harmless horizontal vestige inherited from `yadif`.
- **Q13 fixed-point dynamic range in `bwdifdsp.c` (`bwdifdsp.c:47-93`):**
  The Q13 coefficients `coef_lf = {4309, 213}` ($2(4309 - 213) = 8192 = 2^{13}$), `coef_hf = {5570, 3801, 1016}` ($2\cdot 5570 - 4\cdot 3801 + 4\cdot 1016 = 0$), and `coef_sp = {5077, 981}` ($2(5077 - 981) = 8192$) preserve exact unity DC gain on constant fields. For 16-bit inputs (`clip_max = 65535`), the worst-case positive numerator before `>> 2` in `bwdifdsp.c:87-89` is $5570 \cdot 2 \cdot 65535 + 1016 \cdot 4 \cdot 65535 = 996,394,140 < 2^{31} - 1$, and after `>> 2` plus `4309 * 2 * 65535` is $249,098,535 + 564,780,630 = 813,879,165 < 2^{31} - 1$. Thus 32-bit signed scalar/SIMD accumulators (`pmaddwd` on SSE2/AVX2, `smull`/`smlal` on NEON) never overflow across 8–16 bit depths, whereas 16-bit lane accumulators overflow immediately and can only hold pre-added 8/9/10-bit pixel pairs (`<= 2046`).

#### 3.2 Alpha Compositing and Blending: `vf_overlay` and `vf_blend` (`Basis: source + derived`)
- **`vf_overlay` (`libavfilter/vf_overlay.c:353-740`):** Specializes 4 alpha-premultiplication combinations (`_ss`, `_sp`, `_ps`, `_pp` at `vf_overlay.c:768-772`) across planar YUV (`420`, `422`, `444` at 8-bit and 10-bit), `GBRAP`, and packed RGB. Exact rounding division by 255 uses `FAST_DIV255(x) = (((x) + 128) * 257) >> 16` (`vf_overlay.c:355`). Writing $x = 255q + r$ with $0 \le q \le 255$ and $0 \le r \le 254$ gives $257(x + 128) = 65536q + (257r + 32896 - q)$, where $257(127) + 32896 - q = 65535 - q < 65536$ for $r \le 127$ and $257(128) + 32896 - q = 65792 - q \ge 65537$ for $r \ge 128$; hence `FAST_DIV255(x)` is **bit-identical** to $\lfloor(x + 127)/255\rfloor$ across the entire product domain $x \in [0, 65279]$ (covering $255^2 = 65025$). When blending straight-alpha overlay onto straight-alpha main (`main_straight == 1`), `UNPREMULTIPLY_ALPHA(x, y)` (`vf_overlay.c:362`) divides by $255(x+y) - xy$, which vanishes solely at $(x, y) = (0, 0)$ and is guarded by `alpha == 0` / `alpha == 255` branches prior to evaluation.
- **Silent OOM data corruption in `vf_blend` (`libavfilter/vf_blend.c:208-215`):** In `blend_frame`, if `ff_get_video_buffer` returns `NULL` or `av_frame_copy_props` returns `< 0` (`ENOMEM`), `blend_frame` returns the unblended `top_buf` instead of `NULL`, causing `blend_frame_for_dualinput` (`vf_blend.c:248-249`) to emit an uncomposited frame downstream with status `0` rather than propagating `AVERROR(ENOMEM)`. A clean-room implementation must return `Result<Frame, FilterError>` so allocation failures cannot masquerade as valid media output.

#### 3.3 Color 3D LUTs (`vf_lut3d`) and `zimg` Scaling (`vf_zscale`) (`Basis: source`)
- **`vf_lut3d` (`libavfilter/vf_lut3d.c:110-390`, `libavfilter/x86/vf_lut3d.asm`):** Supports nearest, trilinear, tetrahedral, and pyramid interpolation over $N \times N \times N$ `rgbvec` (`f32x3`) tables (`MAX_LEVEL = 256`, `256^3 * 12 B = 192 MiB`). Tetrahedral interpolation partitions each unit cube $[0,1]^3$ into $3! = 6$ simplices ordered by fractional coordinates $(d_r, d_g, d_b)$ (e.g., $d_r > d_g > d_b$), requiring only **4 table gathers and 3 FMA weights** per pixel instead of trilinear's 8 table gathers and 7 lerps, while preserving exact diagonal grayscale neutrality ($d_r = d_g = d_b$ interpolates solely along $(0,0,0) \to (1,1,1)$). On `x86_64`, `vf_lut3d.asm` accelerates 16-bit and `f32` planar `GBRP` via AVX2 `vgatherdps` (`aarch64` has no gather instruction in base NEON without SVE, making scalar-load + 4-lane transpose faster on NEON).
- **`vf_zscale` (`libavfilter/vf_zscale.c:594-690`) and `sekrit-twc/zimg` (`67e0603271c080e22c8429856dd4a8a56587e61e`):** `zimg` compiles a tiled scanline ring-buffer graph combining chroma upsampling, EOTF transfer linearization (BT.709, sRGB, SMPTE ST 2084 PQ, ARIB STD-B67 HLG), $3 \times 3$ CIE XYZ gamut adaptation, OETF re-encoding, and resize convolution, keeping intermediate working sets inside L2 cache (`zimg_filter_graph_get_tmp_size`, `vf_zscale.c:647`). However, `zimg` enforces a hard `ZIMG_ALIGNMENT` (`64`-byte) contract on every plane base pointer and stride (`vf_zscale.c:672`), forcing `realign_frame` to allocate and copy whenever upstream `vf_crop` or unaligned decoders produce unaligned `data[p]` pointers. Additionally, `realign_frame` (`vf_zscale.c:669-671`) loops `plane = 0 .. nb_planes - 1` and indexes `desc->comp[plane].plane`, conflating component indices with plane indices on packed-plus-planar pixel formats.

#### 3.4 Non-Local Means (`vf_nlmeans`): Modular $\mathbb{Z}/2^{32}\mathbb{Z}$ Integral Image Proof (`Basis: source + derived + execution`)
`vf_nlmeans` (`libavfilter/vf_nlmeans.c:52-60, 236-340`) denoises 8-bit planes by shifting the image across every displacement $(dx, dy) \in [-r, r]^2 \setminus \{(0,0)\}$, building a 2D summed-area table `uint32_t *ii` of squared pixel differences $(I(x,y) - I(x+dx, y+dy))^2 \in [0, 65025]$, evaluating each $(2p+1) \times (2p+1)$ patch SSD in $O(1)$ via 4-corner inclusion-exclusion:
$$\text{SSD}(x, y) = \bigl(\text{ii}_E - \text{ii}_D - \text{ii}_B + \text{ii}_A\bigr) \bmod 2^{32}$$
and mapping `SSD` through a precomputed exponential lookup table `weight_lut` bounded by `max_meaningful_diff` (`-log(1/255.0) * h^2`).

Because `ii` uses `uint32_t`, cumulative prefix sums exceed $2^{32} - 1$ after $\lceil 2^{32} / 65025 \rceil = 66,052$ worst-case pixels (less than a single $320 \times 240$ QVGA frame). In our standalone C verification probe (`run_probes.c`, compiled with GCC 15.2.0 `-O2` on `x86_64`), a $3840 \times 2160$ 4K UHD frame reaches a true total sum of `539,343,360,000`—wrapping modulo $2^{32}$ **`125` times**—yet `uint32_t` modular evaluation `iie - iid - iib + iia` yields **zero bit error** against 64-bit exact arithmetic for every patch side length $P = 2p + 1 \le 257$, breaking down at **`P = 258`** ($258^2 \times 65025 = 4,328,324,100 > 2^{32}$). Because `vf_nlmeans.c:68-69` clamps `patch_size` to $[0, 99]$ ($99^2 \times 65025 = 637,310,025 < 2^{30}$), modular cancellation in $(\mathbb{Z}/2^{32}\mathbb{Z}, +)$ is unconditionally exact. In Rust, `ii` accumulation and 4-corner differences **must** use explicit `.wrapping_add` / `.wrapping_sub` (`Wrapping<u32>`) rather than checked `+`/`-`, and formal verification discharges exactness via the `BitVec 32` ring identity paired with the range bound $P \le 257$.

#### 3.5 Zero-Copy `vf_crop` and `vf_pad` View-Provenance Invariants (`Basis: source + derived`)
- **`vf_crop` (`libavfilter/vf_crop.c:311-340`):** For software frames, `vf_crop` modifies `frame->width`, `frame->height`, and increments `frame->data[p]` in place (`data[0] += y * linesize[0] + x * max_step[0]`; chroma `data[1..2] += (y >> vsub) * linesize[i] + ((x * max_step[i]) >> hsub)`) **without** requiring `av_frame_is_writable(frame)`, because each `AVFrame` struct owns its pointer array while sharing immutable read access to the underlying `AVBufferRef` slabs. For `AV_PIX_FMT_FLAG_HWACCEL` surfaces, `vf_crop` leaves `width`/`height`/`data` untouched and accumulates `crop_top`, `crop_left`, `crop_bottom`, `crop_right` metadata (`vf_crop.c:311-316`).
- **`vf_pad` (`libavfilter/vf_pad.c:235-388`):** Implements upstream zero-copy padding via a two-step pointer-dance:
  1. `get_video_buffer` (`vf_pad.c:235-262`) intercepts upstream buffer allocation, allocates an outer buffer of dimensions `(w + s->w - s->in_w) x (h + s->h - s->in_h + (s->x > 0))`, and shifts `frame->data[plane]` **forward** into the interior rectangle.
  2. When the populated `AVFrame` returns to `filter_frame`, `frame_needs_copy` (`vf_pad.c:265-328`) checks `av_frame_is_writable(in)` and verifies in `buffer_needs_copy` that rewinding `start` by `req_start` and extending `end` by `req_end` remains inside `[buf->data, buf->data + buf->size]` (`vf_pad.c:296-298`), has sufficient positive `linesize` (`vf_pad.c:294`, automatically rejecting negative bottom-up `vflip` strides), and does not cross any sibling plane sharing the same `AVBufferRef` (`vf_pad.c:300-311`). If valid, `vf_pad` rewinds `out->data[i] -= req_start` (`vf_pad.c:384-385`) and fills only the 4 border strips (`ff_fill_rectangle`).
  3. **Rust memory-model implication:** Under Rust's Stacked Borrows and Tree Borrows aliasing models, handing an upstream producer a narrowed `&mut [u8]` subslice covering only the inner rectangle strips write provenance over the outer border bytes; subtracting `req_start` from that narrowed pointer to write border pixels is immediate provenance Undefined Behavior. A sound zero-copy Rust media frame type (`VideoFrame`) must store the **full backing `Arc<AlignedBuffer>`** alongside per-plane `PlaneView { offset: usize, stride: isize, width: u32, height: u32 }` coordinates, deriving mutable slice views from the root `AlignedBuffer` provenance at each filter step.

### 4. Audio DSP Kernels: `af_afir`, `af_loudnorm`, `af_biquads`, and `af_atempo`

#### 4.1 Non-Uniform Partitioned FFT Convolution (`af_afir`, `Basis: source`)
`af_afir` (`libavfilter/af_afir.c:320-410`, `libavfilter/afir_template.c:98-246`) implements low-latency long-impulse-response convolution (e.g., room reverberation and cabinet IRs of $10^4$–$10^6$ taps) by decomposing the IR into `nb_segments` power-of-two uniform partition stages (`AudioFIRSegment`) of geometrically increasing `part_size` from `min_part_size` (default latency quantum) up to `max_part_size`. Within each segment (`fir_quantum`, `afir_template.c:140-246`):
- Real-to-complex forward RDFT (`AV_TX_FLOAT_RDFT` / `AV_TX_DOUBLE_RDFT` of length `2 * part_size`) writes into a per-channel circular **Frequency-Domain Delay Line (FDL)** `seg->blockout` indexed by `seg->part_index[ch]`.
- Inner frequency-domain convolution iterates across `nb_partitions` (`afir_template.c:199-215`), accumulating `s->afirdsp.fcmul_add(sumin, blockout, coeff, part_size)` (`x86/af_afir.asm` SSE3/AVX/FMA3/AVX2; `riscv/af_afir_rvv.S` RVV; scalar C on AArch64), followed by inverse RDFT and **overlap-add** via `seg->buffer` (`afir_template.c:217-222`).
- **SIMD tail-padding invariant:** `afir_template.c:91, 170, 236` passes `FFALIGN(nb_samples, 4)` (`float`) or `FFALIGN(nb_samples, 8)` (`double`) to `vector_fmul_scalar` / `vector_dmul_scalar`, requiring all audio plane allocations (`norm_ir`, `seg->input`, `out`) to provide at least 32–64 bytes of accessible tail padding past `nb_samples`.

#### 4.2 ITU-R BS.1770-4 Gated Loudness and True-Peak Limiting (`ebur128.c`, `af_loudnorm.c`, `Basis: normative + source`)
- **BS.1770-4 K-weighting and dual gating (`libavfilter/ebur128.c:106-195, 575-690`):** `ebur128_init_filter` bilinear-transforms the normative 2-stage K-weighting cascade—a $+4.0\text{ dB}$ high-shelf pre-filter ($f_0 = 1681.97445\text{ Hz}, Q = 0.707175237$) convolved algebraically into a single 4th-order IIR (`b[0..4], a[0..4]`) with the RLB high-pass ($f_0 = 38.13547\text{ Hz}, Q = 0.500327037$)—so arbitrary sample rates work without hardcoded 48 kHz tables. Mean-square energy is integrated over `400 ms` blocks (`75%` overlap = `100 ms` hop, `ebur128.c:75-78`) with channel weights `1.0` (`L, R, C`), `0.0` (`LFE`), and `1.41` ($+1.5\text{ dB}$ on `Ls, Rs`), quantized into a 1000-bin logarithmic histogram (`histogram_energies`, `ebur128.c:103`) to evaluate both the **$-70\text{ LKFS}$ absolute gate** and the **$-10\text{ LU}$ relative gate** (`RELATIVE_GATE = -10.0`, `ebur128.c:64`) as well as EBU Tech 3342 Loudness Range (`LRA`, 10th-to-95th percentile above $-20\text{ LU}$ relative threshold, `ebur128.c:671-690`) in $O(1)$ memory regardless of stream duration.
- **Dynamic vs linear `af_loudnorm` (`libavfilter/af_loudnorm.c:140-360, 693-829`):** Unless two-pass `linear=true` parameters satisfy `measured_tp + (target_i - measured_i) <= target_tp && measured_lra <= target_lra` (`af_loudnorm.c:820-824`), `query_formats` (`af_loudnorm.c:740-753`) forces `192000 Hz` `AV_SAMPLE_FMT_DBL` (4x oversampling for inter-sample true-peak detection), buffers `3000 ms` (`576,000` samples/ch) for Gaussian-smoothed (`21`-tap, $\sigma = 3.5$ over `100 ms` hops) dynamic gain adaptation, and applies a `10 ms` (`1920`-sample) lookahead state-machine true-peak brickwall limiter (`OUT -> ATTACK -> SUSTAIN -> RELEASE`, `af_loudnorm.c:236-360`).

#### 4.3 Biquad IIR Topologies, IEEE-754 Subnormals, and `NaN` Cast UB (`af_biquads.c`, `Basis: source + execution + derived`)
`libavfilter/af_biquads.c` (`1697` lines) backs **18 distinct `FFFilter` nodes** (`biquad`, `equalizer`, `bass`, `treble`, `bandpass`, `bandreject`, `allpass`, `highpass`, `lowpass`, `highshelf`, `lowshelf`, `tiltshelf`, etc.) across four sample precisions (`s16`, `s32`, `flt`, `dbl`) and six filter realizations (`df1` Direct Form I, `dii` Direct Form II, `tdii` Transposed Direct Form II, `lat` Lattice, `svf` Cytomic State Variable Filter, and `zdf` Zero-Delay Feedback trapezoidal integrator at `af_biquads.c:201-602`).

Two critical verification and performance defects exist in `af_biquads.c`:
1. **Measured `13.55x` IEEE-754 subnormal stall (`Basis: source + execution`):** None of the six C filter loops in `af_biquads.c` set `MXCSR` Flush-To-Zero / Denormals-Are-Zero (`FTZ`/`DAZ`) or add an anti-denormal offset. Executing the exact `biquad_dii_flt` recurrence (`w0 = in + a1 * w1 + a2 * w2`) in `run_probes.c` (GCC 15.2.0 `-O2`, Intel Xeon @ 2.20 GHz) on a 262,144-sample zero tail following a unit impulse ($r = 0.9992, \theta = 0.2\text{ rad}$, producing `151,865` subnormal `f32` samples in $[2^{-149}, 2^{-126})$) measured **`68.107 ns/sample`** under default IEEE-754 rounding versus **`5.025 ns/sample`** with `FTZ|DAZ` (`_mm_setcsr(mxcsr | 0x8040)`)—a **`13.55x` real-time CPU stall** triggered whenever audio fades to digital zero. Because thread-global `MXCSR` mutation is non-local and hazardous across FFI boundaries, a verified clean-room Rust IIR kernel on non-FTZ targets should either flush state magnitudes $|w_k| < 2^{-120}$ (`1.0e-36f32`) once per block (zero per-sample overhead when $|w_k|$ decays smoothly!) or execute inside a scoped `aarch64` `FPCR.FZ` / `x86_64` `MXCSR` guard restored via RAII `Drop`.
2. **Jury stability absence and `(int32_t)NaN` UB (`af_biquads.c:228-236, 584-592`, `Basis: source + derived`):** Generic `af_biquad` accepts arbitrary user denominator coefficients `(a0, a1, a2)` without enforcing the discrete-time Jury stability triangle ($|a_2/a_0| < 1 \land |a_1/a_0| < 1 + a_2/a_0$). Divergent poles overflow `float`/`double` to `±Inf` and `Inf - Inf = NaN`. In the `s16` and `s32` clipping ladders (`if (out < min) ... else if (out > max) ... else obuf[i] = out;`), IEEE-754 unordered `NaN` comparisons evaluate both branches as `false`, executing `(int16_t)NaN` or `(int32_t)NaN`—C11 §6.3.1.4 Undefined Behavior. Safe Rust's saturating `as i16` / `as i32` semantics map `NaN -> 0` and clamp `±Inf -> MIN/MAX` deterministically without UB.

#### 4.4 `af_atempo` WSOLA and Low-Sample-Rate Abort / `NaN` Bugs (`Basis: source + derived`)
`af_atempo` (`libavfilter/af_atempo.c:186-380, 960-1190`) implements Waveform Similarity Overlap-Add (WSOLA) time-scale modification over interleaved PCM (`U8`, `S16`, `S32`, `FLT`, `DBL`) by cross-correlating Hann-windowed mono-downmixed fragments via pair-of-real-FFTs (`AV_TX_FLOAT_RDFT` of size `2 * window`, `af_atempo.c:296-304`) to locate the phase-coherent splice offset around the nominal hop.
- **Unconditional `SIGABRT` on `1 <= sample_rate <= 23` (`af_atempo.c:268-273, 1016-1025`):** `config_props` passes `inlink->sample_rate` directly to `yae_reset` without validation. For `sample_rate < 24`, `atempo->window = sample_rate / 24` evaluates to `0`, `nlevels = av_log2(0) = 0`, `pot = 1`, and line 273 executes **`av_assert0(pot <= atempo->window)` (`1 <= 0`), aborting the host process**.
- **`0.0 / 0.0 = NaN` Hann-window poisoning on `24 <= sample_rate <= 47` (`af_atempo.c:268-278, 326-330`):** When `sample_rate in [24, 47]`, `atempo->window == 1` (`pot == 1 == window`), so line 327 evaluates `double t = (double)0 / (double)(1 - 1)` = `NaN`, setting `atempo->hann[0] = NaN` and corrupting every output frame (inducing float-to-int UB on `U8`/`S16`/`S32` formats). Enforcing `sample_rate >= 96` (guaranteeing `window >= 4` and `window / 2 >= 2`) eliminates both defects at configuration time.

**Cross-backend equivalence analysis (`vf_bwdif` CPU vs CUDA vs Vulkan, `Basis: source + derived`):**
Comparing `libavfilter/bwdifdsp.c:61-108`, `libavfilter/vf_bwdif_cuda.cu:61-109`, and `libavfilter/vulkan/bwdif.comp.glsl:76-112` exposes a fundamental architectural split:

Clean-room Rust GPU filters targeting `wgpu` / Vulkan (`WGSL` or `rust-gpu` SPIR-V) that require strict bit-exactness with CPU SIMD should bind planes as **`r8uint`/`r16uint` storage images or `u32` storage buffers (`SSBO`)** rather than normalized float images, unifying the CPU and GPU arithmetic specifications over identical `BitVec 32` semantics.

### 6. Bitmap and Text Subtitles: RLE Bounds vs Safe Rust (`fontations` + `harfruzz`)

#### 6.1 Bitmap Subtitles (`dvbsubdec.c`, `pgssubdec.c`) (`Basis: normative + source`)
- **DVB Subtitles (`libavcodec/dvbsubdec.c`, ETSI EN 300 743 V1.6.1 §7.2.5):** Decodes page, region, CLUT (`4`/`16`/`256`-entry YCrCbT), and object segments containing 2-bit, 4-bit, and 8-bit RLE pixel strings (`dvbsub_read_{2,4,8}bit_string`, `dvbsubdec.c:420-669`) plus heuristic palette synthesis when CLUT segments are missing (`compute_default_clut`, `dvbsubdec.c:671-734`).
  - **Conformance bug on `non_modifying_colour_flag == 1` (`dvbsubdec.c:505-511, 539-578, 627-656`):** Under ETSI EN 300 743 §7.2.5.2, when `non_modifying_colour_flag == 1`, pseudo-colour `1` is transparent ("do not modify underlying region pixel; advance X coordinate"). In `dvbsubdec.c`, every `non_mod == 1 && bits == 1` branch increments `pixels_read += run_length` (or `pixels_read++` for 1-pixel tokens at lines 505–511 and 627–633) **without advancing `destbuf += run_length` (or `destbuf++`)**! While `pixels_read < dbuf_len` still bounds total writes so `destbuf` cannot overflow the scanline buffer, `destbuf` lags behind the true X coordinate by the cumulative count of skipped `non_mod` pixels on that scanline, shifting all subsequent glyphs on the line leftward. Indexing `destbuf[pixels_read]` directly by `pixels_read` eliminates this two-variable state desynchronization by construction.
- **Blu-ray PGS Subtitles (`libavcodec/pgssubdec.c:162-322`):** Reassembles fragmented Object Definition Segments (`MAX_EPOCH_OBJECTS = 64`, bounded by 24-bit `rle_bitmap_len` and canvas dimensions `width <= avctx->width, height <= avctx->height`, `pgssubdec.c:249, 287-304`) and decodes byte-aligned RLE in `decode_rle` (`pgssubdec.c:162-220`). Note that `rect->data[0]` is allocated uninitialized via `av_malloc_array(rect->w, rect->h)` (`line 170`): memory-disclosure safety relies critically on the post-loop check `if (pixel_count < rect->w * rect->h) return AVERROR_INVALIDDATA;` (`lines 212-215`), whereas short lines (`run == 0` when `pixel_count % rect->w > 0`, `lines 201-208`) log an error without advancing `pixel_count` to the next row start (contrary to the comment on line 199) unless `AV_EF_EXPLODE` is set.

#### 6.2 Closed Captions and Text Subtitles (`ccaption_dec.c`, `webvttdec.c`, `ass_split.c`) (`Basis: normative + source`)
FFmpeg normalizes all non-bitmap subtitle codecs (`ccaption_dec.c` for Line 21 / ATSC A/53 CEA-608 byte-pair state machines over $15 \times 32$ roll-up/pop-on/paint-on character grids; `webvttdec.c` for W3C WebVTT `<b>`/`<i>`/`<u>`/`<c>` tags; `movtextdec.c` for 3GPP TS 26.245 `tx3g` style boxes; `subripdec.c` for SRT) into **internal ASS/SSA dialogue events** (`libavcodec/ass.c`), which `vf_subtitles` / `vf_ass` (`libavfilter/vf_subtitles.c:142-245`) feed into `libass` (`ass_process_chunk`) and composite onto video frames via `ff_blend_mask` (`vf_subtitles.c:220-233`, converting `libass`'s inverted transparency byte `AA(c) = 0xFF - (c & 0xFF)`). Note that CEA-708 DTVCC service-block packet extraction (`AV_FRAME_DATA_A53_CC`) exists in codecs/filters (`ccfifo.c`), whereas `ccaption_dec.c` itself decodes only the 2-byte EIA/CEA-608 compatibility triplets (`cc_type == 0/1`), not full CTA-708 Window/Pen DTVCC commands.

#### 6.3 Clean-Room ASS/SSA Architecture: `libass` vs `fontations` + `harfruzz` (`Basis: source + derived`)
In upstream FFmpeg + `libass/libass@a6613d2554daff9e1b5ddf2dbfb3fc31b61b9448`, `vf_subtitles` pulls in ~250 KLOC of C/C++ attack surface (`FreeType2`, `HarfBuzz`, `FriBidi`, `Fontconfig`, and `libass`'s 23 `.c` + 13 `.asm`/`.S` files)—historically a major source of untrusted MKV-embedded-font CVEs (`ass_set_extract_fonts(ass->library, 1)` at `vf_subtitles.c:154` automatically loads embedded TrueType/OpenType attachments from untrusted Matroska files!).

## Boundaries

- **Long-tail CPU filters not individually audited (`not examined`):** While all 601 `FFFilter` registrations in `allfilters.c` and all 42 `x86`, 4 `aarch64`, and 3 `riscv` assembly modules were inventoried, source-level arithmetic proofs in this report cover the high-complexity exemplars (`framesync`, `bwdif`, `yadif`, `overlay`, `blend`, `lut3d`, `zscale`, `nlmeans`, `crop`, `pad`, `subtitles`, `afir`, `loudnorm`/`ebur128`, `biquads`, `atempo`). Specialized DNN filters (`libavfilter/dnn/`, 16 files wrapping TensorFlow/OpenVINO/libtorch C APIs) and external-library wrappers (`vf_libplacebo`, `vf_frei0r`, `vf_vidstab*`, `af_rubberband`, `af_lv2`) were not audited at line level.
- **GPU driver shader compiler soundness (`unknown` / `outside TCB`):** Offline SPIR-V (`glslc`) and PTX (`nvcc`) compilation eliminates target-host GLSL/CUDA source parsing, but Vulkan ICD drivers, NVIDIA PTX-to-SASS JIT compilers, and OpenCL runtime compilers execute closed or unverified vendor machine-code generators outside any host Rust/Lean TCB. Hardware GPU filter verification therefore stops at SPIR-V/WGSL semantics and host descriptor/buffer bounds unless paired with runtime CPU spot-checking.
- **CTA-708 full DTVCC rendering (`unsupported` in upstream `ccaption_dec.c`):** Upstream FFmpeg's `ccaption_dec.c` decodes only EIA/CEA-608 2-byte closed-caption channels embedded in 608/708 packets; full CTA-708 DTVCC Window/Pen command rendering is unsupported in `ccaption_dec.c` at `7ddf7bc8a482cf28b4fab2e63b7093ba35cb6a80`.

### Executed Micro-Probes (`2026-11-20`, Linux `7.1.6` `x86_64`, Intel Xeon @ 2.20 GHz, GCC `15.2.0 -O2`)
