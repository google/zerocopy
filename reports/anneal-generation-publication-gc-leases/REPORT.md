# Generation Publication Atomicity, Cross-Layer Identity Fences, and Cooperative Garbage Collection Leases

## Summary

Across an interactive Rust-to-Lean verification pipeline, multi-file generated model transitions, asynchronous stage completions, and concurrent reader sessions require explicit separation between *realizing artifacts*, *selecting the current generation*, and *reclaiming retired generations*. In bounded finite-state exploration (`76,502` reachable states and `305,537` transitions in the multi-stage publication model; `2,710` states and `11,060` transitions in the response-provenance and two-writer mutation model; `65,536` states in the 16-dimension cross-layer identity ablation model; and `48` matched edit/cancellation schedules in the snapshot-versus-scheduler comparison) together with causally gated macOS/APFS process and real Lean `v4.30.0-rc2` (`3dc1a088b6d2d8eafe25a7cd7ec7b58d731bd7cc`) artifact trials, removing any single publication fence or reader lease condition admits stale, mixed, or prematurely deleted state:

1. **Multi-File Snapshot Coherence and Atomic Generation Selection:** Sequential per-file read-and-revalidate across an `A -> B -> A -> B` symlink swap falsely accepts a mixed `(left-0, right-1)` snapshot that never existed in any single generation, and unfenced double-scan status/garbage-collection checks suffer the same ABA ambiguity unless gated by a monotonic generation epoch (`support/snapshot-capture-jobs/probe.py`, `support/aba-pointer-swap-double-scan/aba_double_collect.py`). Over a real seven-file Charon/Aeneas/Lean model family (`current.llbc`, `Current/Types.{lean,olean}`, `Current/Funs.{lean,olean}`, `Current.{lean,olean}`), coordinated in-place overwriting exposes four mixed `A`/`B` intermediate states where fresh `lean --json` still accepts the old proof because `Current/Funs.olean` has not yet been replaced even though `current.llbc` and `Current/Funs.lean` already contain `B` (`support/real-generation-publication-v4-30-0-rc2/probe.py`). Staging each complete generation in a private immutable directory, validating its full file manifest and SHA-256 inventory, and switching a single `current` symlink via `os.replace` ensures readers resolving `current` once observe either complete `A` (`bc62fce5...`) or complete `B` (`62005531...`) across all preparation gates and `SIGKILL` boundaries (`support/generation-recovery/probe.py`, `support/real-generation-publication-v4-30-0-rc2/probe.py`).
2. **Post-Completion Publication Fences and Cross-Layer Identity:** Neither completion order nor subscriber cancellation suffices to authorize publication. When an older epoch-1/epoch-3 worker finishes after a newer epoch-2/epoch-4 worker has already published, last-completion-wins overwrites the current generation with obsolete output (`support/snapshot-capture-jobs/probe.py`, `support/fault-model/replay.py`). Exhaustive 16-dimension ablation (`support/cross-layer-identity-ablation-model/check.py`) establishes three distinct minimal identity tuples: **3 dimensions** (`lake_env`, `import_artifact`, `proof_bytes`) for elaboration content reuse; **12 dimensions** (adding Cargo subject, source bytes/revision, Charon configuration, LLBC digest, Aeneas configuration, generated tree/generation, and document generation) for strict cross-stage lineage; and **16 dimensions** (adding server worker epoch, file-worker epoch, RPC session, and RPC request ID) for current-request admission. Removing any single dimension produces an explicit one-field collision counterexample.
3. **Cooperative Reader-Owned Leases for Garbage Collection:** An already-open Lean `--server` worker continues to return cached `no goals` from in-memory state even after its underlying generation directory is deleted on disk, so cached server responses cannot serve as a retention oracle (`support/real-generation-gc-lease-v4-30-0-rc2/probe.py`). When each independent reader process acquires its own shared `flock(LOCK_SH)` on `<generation>/lease.lock` after resolving `current` and before spawning fresh `lean --json` imports, nonblocking `flock(LOCK_EX)` garbage collection safely defers reclamation across `A -> B` publication and across the `SIGKILL` crash of one sibling reader, reclaiming the retired `44,471` logical bytes of `A` only after the last surviving reader exits (`support/reader-owned-generation-lease-v4-30-0-rc2/probe.py`).

## Applicability

The reported evidence combines deterministic Python 3.14.7 finite-state models, synthetic multi-process APFS fault-injection harnesses, and real Lean `v4.30.0-rc2` (`leanprover/lean4@3dc1a088b6d2d8eafe25a7cd7ec7b58d731bd7cc`, binary SHA-256 `b48bc5ab229bd8b320a224b87e20fc428dba6fa8a1c054bd4fa6def846e19997`, Lake binary SHA-256 `9a89b2af1bddb7e6d5a8dbb2c715288bcb4f24b9129132640cee950734366bcb`) execution over retained Charon/Aeneas/Lean seven-file model families on macOS 26.6.2 (`Darwin 25.6.0` arm64, APFS data volume). Architectural alignment is evaluated against the Anneal workspace in `google/zerocopy` (`bd0956be95c5f798f0c0484921b9b9d1fc6e9988`).

The real seven-file model families (`A` digest `bc62fce58f5d7edca726224f9174b1bc41ed706a4ced9bca8bafaededd6da2a9` for `wrapping_add(1)` and `B` digest `620055318c21f7616fb671ce0c33f3f289b9a6f237d21aeddb48c0fa5c5d4e4b` for `wrapping_add(2)`) were produced by pinned Charon `0.1.210` and Aeneas `nightly-2026.06.03` and checked with fresh `lean --json` batch runs (`LEAN_NUM_THREADS=1`) and `lean --server` sessions. All process-death experiments use OS-level `SIGKILL` against child processes and advisory `fcntl.flock` locks on APFS; they characterize userspace crash and concurrency boundaries rather than kernel panic or power-loss disk durability.

## Findings

### 1. Snapshot Capture Coherence and ABA Pointer-Swap Hazards

In [`support/snapshot-capture-jobs/probe.py`](support/snapshot-capture-jobs/probe.py) (`support/snapshot-capture-jobs/raw-results.json`), two complete immutable two-file directories `A = (left-0, right-0)` and `B = (left-1, right-1)` are published via `os.replace` of a `current` symlink:

- **Per-File Revalidation Failure under `A -> B -> A -> B`:** When a reader opens `current/left.txt` while `current -> A`, the publisher switches `current -> B`, and the reader opens `current/right.txt`, the captured pair is `(left-0, right-1)`—a mixed cross-generation state that never existed in `A` or `B`. If the reader revalidates by reopening `current/left.txt` after the pointer flips back to `A` and reopening `current/right.txt` after the pointer flips back to `B`, both byte comparisons succeed (`capture_aba_false_accept: true`), falsely certifying a mixed snapshot.
- **Pinned Immutable Directory Resolution:** Resolving `current` once (`os.path.realpath`) to the immutable generation directory `A` and opening both files relative to that resolved path yields `(left-0, right-0)` deterministically even after `current` switches to `B`.
- **Double-Scan ABA False Quiescence (`support/aba-pointer-swap-double-scan/`):** [`support/aba-pointer-swap-double-scan/aba_double_collect.py`](support/aba-pointer-swap-double-scan/aba_double_collect.py) (`support/aba-pointer-swap-double-scan/aba-double-collect-results.json`, verified by `support/aba-pointer-swap-double-scan/check_aba_double_collect.py`) demonstrates the dual hazard for garbage collectors and status monitors that infer quiescence when two consecutive full scans return the same target set `[A-x, B-y]`. Under rapid `A -> B -> A -> B -> A` pointer swaps between scan 1 and scan 2, both unfenced scans observe `[A-x, B-y]` while an active reader has pinned an intermediate transition. Attaching a monotonic generation epoch counter to the pointer metadata eliminates the false quiescence across all tested schedules.

### 2. Staged vs. In-Place Publication Over a Real Seven-File Model Family

[`support/real-generation-publication-v4-30-0-rc2/probe.py`](support/real-generation-publication-v4-30-0-rc2/probe.py) (`support/real-generation-publication-v4-30-0-rc2/results.json`, verified offline by `support/real-generation-publication-v4-30-0-rc2/check.py`) compares staged immutable directory publication against coordinated in-place file replacement over the seven-file `golden_vertical` model family (`current.llbc`, `Current/Types.lean`, `Current/Types.olean`, `Current/Funs.lean`, `Current/Funs.olean`, `Current.lean`, `Current.olean`):

- **Entry `.olean` Invariance Trap:** Between generation `A` (`wrapping_add(1)`, theorem `golden_vertical.inc 0#u32 = .ok 1#u32`) and generation `B` (`wrapping_add(2)`, theorem `golden_vertical.inc 0#u32 = .ok 2#u32`), the top-level entry module artifact `Current.olean` is byte-identical (`34547467aa8017d1ff0efebc746e14a1b50ef6cb446e9aa1404d09cc0ffef149`), whereas `Current/Funs.olean` changes (`2320c0125c0e...` -> `57bcadabf179...`). Watching or hashing only the root module `.olean` misses the semantic change completely.
- **In-Place Replacement Exposes Mixed States that Pass Stale Proofs:** When overwriting `generations/A` in place in the order `current.llbc` (`write-0`), `Current/Types.lean` (`write-1`), `Current/Types.olean` (`write-2`), `Current/Funs.lean` (`write-3`), `Current/Funs.olean` (`write-4`), `Current.lean` (`write-5`), and `Current.olean` (`write-6`), gates `write-0` through `write-3` have mixed `A`/`B` inventories (matching neither `bc62fce5...` nor `62005531...`). At `write-3`, both `current.llbc` and `Current/Funs.lean` are already `B`, but `Current/Funs.olean` is still `A`; a fresh `lean --json` batch check still accepts the old `A` proof (`.ok 1#u32`) with standard axioms `[propext, Classical.choice, Quot.sound]` and zero `sorryAx`, and rejects the `B` proof until `write-4` replaces `Current/Funs.olean`.
- **Staged Directory Publication and `SIGKILL` Boundaries:** When `B` is staged in a private directory, validated against its seven-file manifest and fresh Lean oracle, moved to `generations/B`, and published via `os.replace(current.next, current)`, readers observe exact `A` (`bc62fce5...`) at all seven copy gates, `validated`, `generation-moved`, and `before-publish`, and observe exact `B` (`62005531...`) at `after-publish`. Injecting `SIGKILL` at `before-publish` leaves `A` selected; injecting `SIGKILL` at `after-publish` leaves `B` selected.

| Publication Protocol / Gate | Observed 7-File Inventory | Fresh `lean --json` Old Proof (`.ok 1#u32`) | Fresh `lean --json` New Proof (`.ok 2#u32`) | Selected Generation ID |
| --- | --- | --- | --- | --- |
| Staged `copy-0` .. `before-publish` | Complete `A` | Pass (`no sorryAx`) | Fail (`Tactic rfl failed`) | `bc62fce5...` (`A`) |
| Staged `after-publish` | Complete `B` | Fail (`Tactic rfl failed`) | Pass (`no sorryAx`) | `62005531...` (`B`) |
| Staged `SIGKILL` at `before-publish` | Complete `A` (orphan `B` unselected) | Pass (`no sorryAx`) | Fail | `bc62fce5...` (`A`) |
| Staged `SIGKILL` at `after-publish` | Complete `B` | Fail | Pass (`no sorryAx`) | `62005531...` (`B`) |
| In-place `write-0` .. `write-3` (`llbc`, `Types`, `Funs.lean` updated; `Funs.olean` still `A`) | Mixed `A`/`B` | Pass (stale `Funs.olean` used!) | Fail | None (`mixed`) |
| In-place `write-4` .. `write-6` (`Funs.olean` updated) | Complete `B` | Fail | Pass (`no sorryAx`) | `62005531...` (`B`) |

### 3. Nine-Phase `SIGKILL` Recovery and Output-Set Shrinkage on APFS

[`support/generation-recovery/probe.py`](support/generation-recovery/probe.py) (`support/generation-recovery/results.json`) tests nine causally gated `SIGKILL` injection points during multi-file generation staging where generation `A` includes a legacy module (`Model.lean`, `Proof.lean`, `Legacy.lean`, `Model.olean`, `Proof.olean`) that is deleted in generation `B` (output-set shrinkage):

- Across all eight `SIGKILL` boundaries prior to `os.replace` (`model_source`, `proof_source`, `model_artifact`, `proof_artifact`, `manifest_write`, `manifest_validated`, `publication_lock_acquired`, and `stage_moved_to_generations_B`), `current` continues to select complete `A`, and startup reconstruction removes the incomplete or unselected `staging/B` / `generations/B` directory.
- At the ninth `SIGKILL` boundary (`current_symlink_replaced`), `current` selects complete `B` (which omits `Legacy.lean` and rejects any residual stale file not in `B`'s manifest), and startup cleanup removes retired `A`.
- Repeating three consecutive `SIGKILL` / restart / cleanup cycles (`B2`, `B3`, `B4` killed after move into `generations/` but before pointer swap) idempotently removes the unselected complete directories while keeping `A` intact until `B5` completes publication. Re-reading the authoritative `current` symlink and manifest also recovers the true epoch (`B`) when filesystem watcher notifications for `B` are dropped and a duplicate `A` event is delivered late.

### 4. Finite Orchestration Models, Publication Fences, and Cross-Layer Identity Ablation

Four complementary finite-state models isolate the exact guards required to prevent stale publication, lost updates, and cross-layer cache collisions:

1. **Snapshot Engine vs. Versioned Stage Scheduler (`support/snapshot-vs-versioned-scheduler/`):** [`support/snapshot-vs-versioned-scheduler/snapshot_vs_versioned_models.py`](support/snapshot-vs-versioned-scheduler/snapshot_vs_versioned_models.py) (`support/snapshot-vs-versioned-scheduler/snapshot-vs-versioned-results.json`) replays all `12` valid interleavings of `("edit_B", "cancel_A", "finish_A", "finish_B")` across `4` change classes (`proof_edit`, `source_edit`, `model_change`, `import_change`; `48` schedules total) plus `2` shared-reader cancellation orders (`cancel_1,finish_A` and `finish_A,cancel_1`). When publication is fenced on `desired == finishing_request` and cancellation removes only the cancelling subscriber, both the minimal immutable-snapshot engine and the stage-memoizing scheduler produce identical published selections across all `48` schedules (`0` stale publications) and preserve the surviving subscriber in `2/2` shared-reader schedules. Without the completion fence, `16/48` schedules (`4` per variant) publish stale `A` over `B`; with `cancel_all`, `2/2` shared-reader schedules lose the surviving reader. Stage memoization halves backend translation calls on `proof_edit` (`1` vs. `2`) without changing observable publication safety.
2. **Eleven-Fence Mutation Model and Subprocess Replay (`support/fault-model/`):** [`support/fault-model/model.py`](support/fault-model/model.py) (`support/fault-model/results.json`) explores `76,502` reachable states and `305,537` transitions up to depth 7 with zero safety violations under the full 11-guard publication contract. Mutating each guard individually yields a minimal breadth-first counterexample (`72,060` to `107,870` states per mutant): removing the revision fence selects an old revision; removing the digest fence accepts replaced bytes under a reused revision; removing the stage-generation, worker-epoch, or RPC-epoch fence accepts stale pipeline/worker/session output; removing the owner fence publishes a fully cancelled job; removing the status fence publishes a failed/timed-out job whose result arrived late; removing the completeness fence publishes a partial generation; removing the request-echo fence misattributes a response; omitting disk reconciliation trusts a lagging watcher state after a lost external-edit notification; and cancelling on any owner kills a shared job while another subscriber remains active. [`support/fault-model/replay.py`](support/fault-model/replay.py) (`support/fault-model/replay-results.json`) replays the out-of-order completion schedule with two real gated Python subprocesses (`epoch 1` digest `A` finishing after `epoch 2` digest `B` published), confirming that `epoch 2` (`9d7b7af5...`) stays selected while `epoch 1` (`8a72f357...`) is classified `stale-generation`.
3. **Response-Provenance and Two-Writer CAS Patch Model (`support/identity-state-mutation-model/`):** [`support/identity-state-mutation-model/model.py`](support/identity-state-mutation-model/model.py) (`support/identity-state-mutation-model/results.json`, `support/identity-state-mutation-model/state-space.json`, verified by `support/identity-state-mutation-model/check.py`) explores `2,710` states and `11,060` edges. While the full response stamp has `0` unsafe states (`0/1`), weaker composite guards fail at depth 1: `URI + version + cancellation` accepts `451/452` unsafe states (`external-replace-B-unnoticed`, plus `A -> B -> A` followed by `close-reopen-version-1`); `physical path + cancellation` accepts `1,519/1,520` unsafe states (`same-path-subject-alias-test`); `stage generation + cancellation` accepts `823/824` unsafe states (`editor-write-B`); and `cancellation alone` accepts `1,519/1,520` unsafe states (`artifact-replace-Y`). In the 6-permutation two-client patch model and 4 two-thread barrier runs, `URI + version` overwrites the first client's applied patch in all `4/6` overlapping capture-before-apply schedules, whereas full compare-and-swap (checking source revision/digest, open epoch, and generation) rejects the stale second patch (`0` lost updates).
4. **Exhaustive 16-Dimension Cross-Layer Identity Ablation (`support/cross-layer-identity-ablation-model/`):** [`support/cross-layer-identity-ablation-model/check.py`](support/cross-layer-identity-ablation-model/check.py) (`support/cross-layer-identity-ablation-model/results.json`) exhaustively checks all `2^16 = 65,536` binary states across 16 candidate identity dimensions while holding all five file/URI locators (`src/lib.rs`, `out/Probe.llbc`, `generated/Probe/`, `Probe.Funs`, `file:///work/Proof.lean`) constant:

| Policy Tier | Minimum Required Dimensions | Required Identity Fields | One-Dimension-at-a-Time Ablation Result |
| --- | ---: | --- | --- |
| Elaboration content reuse | 3 | `lake_env`, `import_artifact`, `proof_bytes` | Removing any of the 3 collides (`3/3`); the other 13 lineage/transport dimensions can differ without changing the elaborated Lean goal when inputs converge. |
| Strict cross-stage lineage | 12 | `source_subject`, `source_bytes`, `source_revision`, `charon_config`, `llbc_bytes`, `aeneas_config`, `generated_tree`, `generated_generation`, `lake_env`, `import_artifact`, `proof_bytes`, `document_generation` | Removing any of the 12 collides (`12/12`); distinguishes `A -> B -> A` source returns, same-path Cargo subjects, and distinct build histories that converge on identical `.olean` bytes. |
| Current-request admission | 16 | All 12 lineage fields plus `worker_epoch`, `file_worker_epoch`, `rpc_session`, `rpc_request` | Removing any of the 16 collides (`16/16`); prevents delayed responses from superseded workers or reused JSON-RPC request IDs from entering the active session. |

### 5. Cooperative Garbage Collection Leases with Live and Crashing Lean Readers

Across [`support/generation-recovery/probe.py`](support/generation-recovery/probe.py), [`support/real-generation-gc-lease-v4-30-0-rc2/probe.py`](support/real-generation-gc-lease-v4-30-0-rc2/probe.py), and [`support/reader-owned-generation-lease-v4-30-0-rc2/probe.py`](support/reader-owned-generation-lease-v4-30-0-rc2/probe.py), garbage collection of retired generation directories is tested against live Lean `--server` sessions and gated delayed `lean --json` batch readers:

- **Why Open Lean Workers Are Not a Retention Oracle:** In `support/real-generation-gc-lease-v4-30-0-rc2/results.json`, a `lean --server` process that opened an `A` proof document before `current` switched to `B` continues to respond `no goals` to `$/lean/rpc/call` (`Lean.Widget.getInteractiveGoals`) even after `generations/A` is completely deleted from disk in the unleased control. However, any process that resolves `current -> generations/A` before the switch and opens `Current.olean` / `Current/Funs.olean` *after* unleased GC fails immediately with `unknown module prefix 'Current'` (or `FileNotFoundError`).
- **Parent-Held vs. Reader-Owned Shared `flock` Leases Across `SIGKILL`:** In [`support/reader-owned-generation-lease-v4-30-0-rc2/probe.py`](support/reader-owned-generation-lease-v4-30-0-rc2/probe.py) (`support/reader-owned-generation-lease-v4-30-0-rc2/results.json`, verified by `support/reader-owned-generation-lease-v4-30-0-rc2/check.py`), two independent reader wrapper processes (PIDs `15964` and `15965`) each open `generations/A/lease.lock` and acquire their own shared advisory lock (`flock(LOCK_SH)`) before pausing prior to launching Lean; the parent process holds no lease descriptor. After `current` is atomically switched from `A` (`bc62fce5...`) to `B` (`62005531...`):
  1. First GC run (PID `15966`) attempts nonblocking `flock(LOCK_EX)` on `A/lease.lock` and records `deferred-reader-lease`.
  2. Reader 1 (PID `15964`) is killed with `SIGKILL` and reaped (`-SIGKILL`).
  3. Second GC run (PID `15967`) attempts nonblocking `flock(LOCK_EX)` and still records `deferred-reader-lease` because Reader 2 (PID `15965`) holds its independent shared lock.
  4. Reader 2 spawns fresh `lean --json` processes against pinned `generations/A`: the `A` proof (`.ok 1#u32`) succeeds (`no sorryAx`) and the `B` proof (`.ok 2#u32`) fails (`Tactic rfl failed`), with the result explicitly stamped with generation `bc62fce5...` (`stale_relative_to_selected: true`).
  5. Third GC run (PID `15973`) while Reader 2 remains paused after import still records `deferred-reader-lease`.
  6. Reader 2 exits cleanly, releasing the last `LOCK_SH` handle; fourth GC run (PID `15974`) acquires `LOCK_EX` and removes `generations/A`, reclaiming all 7 files (`44,471` logical bytes), while fresh `B` proofs continue to pass.

## Boundaries

- **Userspace `SIGKILL` vs. Power-Loss Durability:** All crash and recovery trials (`support/generation-recovery/`, `support/real-generation-publication-v4-30-0-rc2/`, `support/reader-owned-generation-lease-v4-30-0-rc2/`) inject `SIGKILL` into userspace processes on a live macOS APFS volume. Power-loss durability, `fsync` / `F_FULLFSYNC` directory-entry ordering, Windows file-Delete-on-close semantics, and network filesystems (NFS/SMB) where `flock` or `os.replace` semantics differ were **not examined**.
- **Cooperative Advisory Locking:** The `fcntl.flock` protocol requires every reader that resolves `current` for later file opens (including worker restarts, scratch proof forks, and background batch verifiers) to acquire `LOCK_SH` before re-checking or pinning the generation path, and requires all collectors to honor nonblocking `LOCK_EX`. Non-cooperative readers or external tools that bypass `lease.lock` are **unsupported** by advisory locks.
- **Model vs. Product Implementation:** The finite state-space explorations (`support/fault-model/`, `support/identity-state-mutation-model/`, `support/cross-layer-identity-ablation-model/`, `support/snapshot-vs-versioned-scheduler/`) verify the internal completeness of the specified guard predicates and synthetic stage harnesses; they do not establish that the Anneal workspace in `google/zerocopy` (`bd0956be95c5f798f0c0484921b9b9d1fc6e9988`) already implements these orchestrator structures.
