# Cross-Compiler Verification Soundness, Normative Forwards-Compatibility, and Multi-Commit Reference Correspondence

## Summary

Verifying a program under one compiler revision $v_{\text{verify}}$ does not silently transfer either **runtime soundness** or **proof compilation** to a distinct deployment or future compiler $v_{\text{ship}} \neq v_{\text{verify}}$. Primary-source audits across 13 formal verification and mechanized specification systems (`CompCert`, `CakeML`, `SPARK/GNATprove`, `Frama-C`, `seL4` binary translation validation, `AutoCorres`, `VST`, `Verus`, `Creusot`, `MiniRust`, `Sail`, `WasmCert`, and the `K` framework), live empirical execution across nine `rustc` toolchains (`1.78.0` through `1.102.0-nightly`, plus `-Zrandomize-layout`), and 25 zero-axiom theorems kernel-checked in Lean 4 `v4.34.1` establish four governing results:

1. **Cross-Compiler Assurance Divides Strictly Into Exact-Compiler Binding vs. Parametric Target/Dialect Envelopes:**
   - Verified code generators (`CompCert` via compile-time `<arch>/Archi.v` + `transf_c_program_correct`; `CakeML` via in-logic HOL4 self-compilation `cake_compiled_thm`) and per-binary translation validators (`seL4` `graph-refine` across pinned `GCC 4.5.1`–`14` builds with `-fno-partial-inlining -fno-ipa-cp -fno-ipa-sra`) bind soundness to one concrete compiled artifact; recompiling the verified source with an unverified host compiler severs all formal links.
   - Source/IR verifiers decoupled from the deployment compiler (`SPARK/GNATprove` DO-330 TQL-5 `gnat2why` vs. flight `GNAT Pro`; `Frama-C` WP vs. cross-compilers) preserve soundness across compilers **only** by ingesting explicit target/compiler descriptors (`-gnateT=target.atp` + `-gnatR2js` JSON representation files; Frama-C 53-field YAML `Machdep.mach`), rejecting compiler-specific evaluation-order dependencies (`--pedantic`; `UnspecifiedSequence`), and leaving post-IR optimizer/codegen bugs explicitly scoped to deployment compiler qualification.

2. **Empirical & Mechanized Refutation of Silent Cross-Compiler Proof Transfer ($v_{\text{verify}} \neq v_{\text{ship}}$) in Rust:**
   - Because `rustc` enforces exact `CFG_VERSION` `.rmeta` equality (`error[E0514]` in `locator.rs:927-932`), $v_{\text{ship}} \neq v_{\text{verify}}$ cannot reuse a verified `.rlib` and must recompile source from scratch through $v_{\text{ship}}$'s frontend, `core`/`alloc` sysroot, MIR optimizer, and LLVM backend (`18.1.2` $\to$ `23.1.6`).
   - Live execution across nine `rustc` releases (`1.78.0`–`1.102.0-nightly`) demonstrates concrete runtime and compile-time divergences on identical `--edition=2021` Rust code:
     1. Aliasing `pub type Infallible = !` (`dd132214ed3e2415da4292fec21f564f4496baa5`, `1.100.0`) flips `TypeId::of::<Infallible>() == TypeId::of::<!>()` at runtime from **`false`** (`1.78.0`–`1.99.1`) to **`true`** (`1.100.0`+) and changes `any::type_name::<Infallible>()` from `"core::convert::Infallible"` to `"!"`.
     2. Unspecified `#[repr(Rust)]` field order and padding expand `#[repr(align(8))]` `(u8, u32, u16, u8)` from **`8` to `16` bytes** and `(u8, u32, u64, u16, u8)` from **`16` to `24` bytes** (`+8` uninitialized padding bytes) under `-Zrandomize-layout -Zlayout-seed=7`—and under identical `-Zrandomize-layout -Zlayout-seed=42` flags, surrounding item declarations in the same file flip `(u8, u32, u64, u16, u8)` between **`16` bytes (`0` padding)** and **`24` bytes (`8` padding)** due to per-item PRNG state, which `zerocopy`'s compile-time `PaddingFree<Self, PADDING>` trait bound catches fail-closed (`E0277`).
     3. Stdlib precondition enforcement tightens across releases (`core::slice::from_raw_parts` `assert_unsafe_precondition!` in `1.78.0`, aborting with `SIGABRT` on null zero-length slices, followed by compile-time `invalid_null_arguments` in `1.93.1+`), while generic dead-branch `const { ... }` blocks trigger post-monomorphization errors (`E0080`) on `1.84.0+`.
   - Kernel-checked theorems in `support/AssuranceTheorems.lean` (`strict_receipt_implies_compiler_safety`, `unverified_compiler_rejected_by_strict_audit`, `mismatched_ship_toolchain_rejected`) prove that discharging a compiler-pinned claim without extra axioms requires exact 5-tuple `(compilerCommit, binarySha256, sysrootSha256, targetTriple, flagsDigest)` identity (`pinnedVerified`); unmapped or mismatched compilers (`unverifiedCompiler`) must fail closed unless explicitly waived in the TCB audit log.

3. **$O(1)$ Per-`SemProfile` Reference Correspondence vs. $O(N)$ Per-Compiler Proof Explosion:**
   - Across `24` `rust-lang/rust` releases (`2.54` years, `1.78.0`–`1.102.0-nightly`) and `591` commits touching `rustc_const_eval/src/interpret/` and `core`/`alloc` primitives, `97.3%` are internal refactors, leaving **`16` genuine operational runtime semantic transitions** (`0.696` per release)—and point releases (`1.99.0` == `1.99.1`) preserve identical Git blob/tree SHA-1s across `mir/syntax.rs`, `const_eval/src/interpret`, `rustc_abi/src`, and `core/src/convert/mod.rs`.
   - Quotienting $N$ compiler commits into $K \ll N$ semantic equivalence classes (`SemProfile`, mirroring `MiniRust` `Target`/`Memory::Params`, `Sail` `config`, `WasmCert` host/extension classes, and `K` `C-SETTINGS` profiles) and lowering per-commit MIR directly via hub-and-spoke drivers into a monotonic superset trunk IR (`spoke_lowering_refines_reference_class`, `same_profile_normalized_mir_reuses_proof`, vs. lossy pairwise chains in `linear_chain_unsound_or_incomplete`) reduces reference-model correspondence proofs (`lean-miri` / `MiniRust`) from $O(N)$ copies to **$O(1)$ per `SemProfile`**, with automatic zero-edit proof reuse whenever two compilers emit identical normalized trunk MIR in the same `SemProfile`.

4. **Normative Forwards-Compatibility & Drift-Resilient Verification Interfaces (`support/NormativeForwardsCompatibility.lean`):**
   - Partitioning Rust's contract (`google/zerocopy` `POLICIES.md`, RFC 1122, RFC 1105, `rust-lang/reference`, `core::option`) into **Category A (Normatively Guaranteed Invariants — `9/9` live pass)**, **Category B (Conforming-Compiler Degrees of Freedom)**, and **Category C (SemVer Carve-Outs & Edition Opt-Ins)** yields a monotonic refinement preorder `NormativeEnvelope ⊑ PinnedCompilerProfile c`:
     - **Theorem 1 (`forwards_compatible_envelope_transfer`):** Zero-waiver proofs over `NormativeEnvelope` transfer soundness automatically to every conforming compiler `c` without claiming soundness over compiler bugs outside `ConformingCompiler`, paired with **Theorem 2 (`non_normative_layout_countersample`)** refuting transfer when specs inspect `#[repr(Rust)]` offsets, `TypeId`/`type_name`, or private stdlib fields, and `non_normative_assumption_logged_or_compile_guarded` enforcing `zerocopy`'s two-route rule (compile-time `constGuard` or non-empty TCB `waivers`).
     - **Theorems 3 & 4 (`trunk_addition_preserves_existing_wp` & `profile_flag_preserves_unaffected_wp`, plus `wp_invariant_under_temp_and_cfg_refactoring`):** A soundness-proved total weakest-precondition reducer (`evalWP`, combining `AutoCorres`'s in-kernel `ac_corres_chain` TCB discipline with `Creusot`'s temporary elimination) preserves existing user proof terms unchanged under Lean 4 kernel $\beta/\iota$ reduction when adding new `TrunkStmt` constructors (`evalExt`), adding orthogonal `SemProfile` flags, or renumbering temporaries and splitting CFG blocks (`mir_c1 ≠ mir_c2`, whereas raw block-indexed certificates break in `raw_cfg_cert_breaks_on_block_split`).
     - **Theorems 5 & 6 (`callee_impl_drift_breaks_inlined_body` vs. `opaque_normative_contract_absorbs_stdlib_drift`):** Sealing `core`/`alloc` calls behind opaque Category-A contracts (`CallsSatisfyNormativeSpec`, analogous to `Creusot` `extern_spec!` and `Verus` `assume_specification`) completely insulates user proofs from internal stdlib MIR refactors (`AtomicU* -> Atomic<T>`, `Unique<T> -> BoxRaw<T>`, `#[derive(Debug)]` field-string concatenation).

#### Key Primary-Source Mechanisms Behind the 13-System Survey

1. **CompCert's Three Severed Links Under Host GCC/Clang (`AbsInt/CompCert@2685140bf72c959446981fb99b5e44a8975021bc`):**
   - `driver/Compiler.v:446-452` proves `transf_c_program_correct` (`transf_c_program p = OK tp -> backward_simulation (Csem.semantics p) (Asm.semantics tp)`), lifted to safety-enforcing specifications in `driver/Complements.v:151-171`. Both `common/AST.v:22` and `cfrontend/Ctypes.v:21` execute `Require Archi.`, baking target/ABI constants directly into source semantics: `Archi.ptr64` (`AST.v:52`, `Ctypes.v:948`), `Archi.big_endian` (`Clight.v:219-248` bitfields), `Archi.align_int64` (`8%Z` on `x86_64/Archi.v:27` vs. `4%Z` on `x86_32/Archi.v:27`), `Archi.win64` (`x86/CBuiltins.ml:21-31` switching `__builtin_va_list` between `8` and `24` bytes), and `Ctypes.layout_struct_rec` (`Ctypes.v:688-725`).
   - `clightgen` (`export/ExportDriver.ml:43-65`) parses `.c` via CompCert's OCaml frontend and runs `SimplExpr.transl_program` + `SimplLocals.transf_program` to fix one evaluation order and concrete `Archi` struct offsets. Compiling that `.c` file with host GCC or Clang severs (a) implementation-defined ABI/bitfield layout agreement, (b) `SimplExpr`'s linearized evaluation order vs. unsequenced C subexpressions, and (c) `transf_c_program p = OK tp` across unverified middle/backend optimizations.
2. **CakeML's In-Logic Bootstrap (`CakeML/cakeml@ae0f9538560c769b9b1b567ceb280eccd798e9ab`, DOI `10.1017/S0956796818000229`):**
   - Rather than extracting compiler ML code to an unverified host ML/C compiler, `ml_translator` certifies `Decls_FRONT_compiler_x64_prog` (`compiler/bootstrap/compilation/x64/proofs/replProofScript.sml:37-60, 230-255`), HOL4 evaluates `compiler$compile` inside the logic on its own AST, and `x64BootstrapProofScript.sml:65-80, 409` (`cake_compiled_thm`, audited by `check_thm`) instantiates `compile_correct_gen_determ` (`compiler/proofs/compilerProofScript.sml:105-128`) directly over the emitted x64 machine-code bytes, leaving only `basis_ffi.c` and ELF linking outside HOL4.
3. **SPARK/GNATprove's Decoupled Avionics Qualification & Fail-Open `-gnateT` Hazard (`AdaCore/spark2014@d737789cf270fb29659d176793c9a40b7ae16714`):**
   - `docs/ug/en/usage_scenarios.rst:1014-1019` explicitly scopes `GNATprove` (DO-330 TQL-5 verification tool) to source semantics, requiring independent object-code assurance for flight `GNAT Pro`. To synchronize target representations between `gnat2why` and flight `GNAT Pro`, `src/gnatprove/configuration.adb:1247-1299` passes `-gnateT=target.atp` (`23` scalar/alignment constants + float descriptors, `testsuite/gnatprove/tests/1519__alignment/target.atp:1-28`) and `configuration.adb:1696-1736` invokes the target compiler with `-gnatR2js` (`Data_Rep_Files`) for record bit-offsets, while `--pedantic` (`portability_issues.rst:101-123`) rejects compiler-dependent `a + b + c` expression reordering. ## Boundaries

To prevent over-generalization by downstream consumers, the following negative-space boundaries apply:

1. **Compiler Optimizer and Codegen Bugs in Unverified $v_{\text{ship}}$ (`known not to apply`):**
   Theorem 1 (`forwards_compatible_envelope_transfer`) transfers soundness across all *conforming* compilers (`ConformingCompiler c`, i.e., compilers faithfully implementing Category-A Rust Reference and `core`/`alloc` contracts). Source or MIR verification under `NormativeEnvelope` is **known not to apply** to miscompilations in an unverified $v_{\text{ship}}$'s MIR optimizer passes or LLVM codegen backend (`LLVM 18.1.2`–`23.1.6`); closing backend miscompilation requires either verified compilation (`CompCert`/`CakeML`) or per-binary translation validation (`seL4` `graph-refine`).
2. **Silent Reuse of Compiled `.rlib` Artifacts Across `rustc` Releases (`unsupported`):**
   Linking a verified `.rlib` built by $v_{\text{verify}}$ directly into $v_{\text{ship}} \neq v_{\text{verify}}$ is **unsupported** by `rustc`, which unconditionally rejects version-mismatched `.rmeta` payloads with `error[E0514]` (`compiler/rustc_metadata/src/locator.rs:927-932`), except across raw `extern "C"` staticlib/cdylib C-ABI boundaries (`not examined` for generic Rust APIs, which cannot cross `extern "C"`).
3. **Unsettled Upstream Rust Aliasing and Non-ZST Union Validity Corner Cases (`unknown`):**
   As documented in `rust-lang/reference@c9cc32825b03fc206d9c6fe73e9ca6a2f3576d6c` (`src/behavior-considered-undefined.md:24-41, 145-147`), exact operational boundaries between Stacked Borrows and Tree Borrows (`r[undefined.alias]`) and bit-validity of unions lacking ZST variants (`r[undefined.validity.union]`) remain **unknown** (unsettled upstream in normative Rust). Normative-mode proofs must stay within the settled Reference floor (shared immutability outside `UnsafeCell`, unique `&mut T` while live, in-bounds provenance) or declare an explicit `SemProfile`.
4. **Non-`x86_64-linux` Live Execution & Cyclic Loop Invariant Anchoring (`not examined`):**
   Live `rustc` binaries in `support/*.py` were executed only on `x86_64-unknown-linux-gnu` (`64`-bit little-endian); live execution on 32-bit, big-endian, or Windows MSVC targets was **not examined** (target dependence is modeled parametrically via `TargetLayoutEnv` and audited statically in `CompCert`/`SPARK`/`Frama-C`/`MiniRust`). Likewise, `NormativeForwardsCompatibility.lean` unrolls finite acyclic/bounded-fuel `MirBody` CFGs over `Nat` stores rather than mechanizing cyclic loop-header cutpoint invariants (`wpWhile`) or byte-addressed provenance heaps, which are covered in dedicated MIR program-logic reports.
