# Rust Aliasing Models Compared: Stacked Borrows, Tree Borrows, MiniRust, and LLVM Attribute Lowering

## Summary

A drop-in verified `rustc` replacement must choose an operational aliasing model at the MIR boundary that simultaneously (1) accepts real-world `unsafe` Rust idioms, (2) justifies the LLVM pointer attributes emitted by `rustc` (`noalias`, `readonly`, `dereferenceable`, `writable`, `dead_on_unwind`, `captures`, and scoped `!noalias` metadata after inlining), and (3) decomposes into local separation-logic or per-allocation proof obligations.

Comparing **Stacked Borrows** (POPL 2020; Miri's default tracker), **Tree Borrows** (PLDI 2025; Miri `-Zmiri-tree-borrows` and `minirust/minirust` `TreeBorrowsMemory<T>`), **Tree Borrows with implicit function-entry writes** (`-Zmiri-tree-borrows-implicit-writes`), and the **no-aliasing-model baseline** (`-Zmiri-disable-stacked-borrows`, checking only bounds, alignment, initialization, and type validity) establishes six decisive trade-offs:

1. **Incomparable acceptance sets (`SB` vs. `TB`):** Tree Borrows is **not** a strict superset of Stacked Borrows. Tree Borrows accepts two-phase `Reserved` mutable references whose parent raw pointer is read before activation (`case1_sb_fails_tb_passes`), which Stacked Borrows rejects as UB by popping the `Unique` tag. Conversely, Stacked Borrows accepts writing to a raw pointer cast from `&mut T`, reading the parent root variable, and writing to the raw pointer again (`case2_sb_passes_tb_fails`) because `&mut`-to-`*mut` pushes `SharedReadWrite` that survives parent reads, whereas Tree Borrows lacks a dedicated raw-pointer retag (`Retag` is only emitted for references and `Box`) so the raw pointer inherits its parent `&mut T` tag (`Unique`), transitions to `Frozen` on the parent root read, and faults on the second write.
2. **LLVM `writable` requires `-Zmiri-tree-borrows-implicit-writes`:** Under default Tree Borrows, a function-entry `&mut T` (`T: Unpin`) starts in `ReservedFrz { conflicted: false }` with a `StrongProtector`. If a foreign pointer reads the location during the call (`ReservedFrz { conflicted: true }`) and the function returns without ever writing through `&mut T`, default Tree Borrows permits the execution (`case4_protected_reserved_foreign_read_no_write`). That behavior is **unsound** under LLVM's `writable` attribute (which licenses speculative stores at function entry and dead-store elimination on unwind/return); enabling `-Zmiri-tree-borrows-implicit-writes` initializes `FnEntry` mutable references in `Unique` (or performs an implicit entry write) so foreign reads trigger immediate `ProtectedDisabled` UB. Currently, `rustc` 1.99.1 gates `writable` on `&mut T` behind `-Zllvm-writable` (`compiler/rustc_ty_utils/src/abi.rs:378-390`) and only emits `writable` + `dead_on_unwind` unconditionally on indirect `sret` return pointers (`compiler/rustc_codegen_llvm/src/abi.rs:503-511`).
3. **Sub-object `UnsafeCell` and `!Unpin` exemptions:** Unlike the 2020 Stacked Borrows paper (which disabled `SharedReadOnly` across an entire struct containing any `UnsafeCell`), Miri's production Stacked Borrows, Miri's Tree Borrows, and MiniRust's `TreeBorrowsMemory` all perform **byte-precise** field projection via `FreezeVisitor` (`src/tools/miri/src/borrow_tracker/mod.rs:285-395`; `spec/mem/tree_borrows/reborrow_settings.md:62-125`): bytes outside `UnsafeCell` receive `SharedReadOnly` / `Frozen` while bytes inside `UnsafeCell` receive `SharedReadWrite` / `Cell` (`case6` vs. `case7`). However, `rustc` only emits LLVM `noalias`, `readonly`, and `dereferenceable` on `&T` when the **entire** `T: Freeze`, and only emits `noalias` and `dereferenceable` on `&mut T` when `T: Unpin` (`compiler/rustc_ty_utils/src/abi.rs:366-415`).
4. **MIR inlining vs. LLVM inlining for scoped `!noalias`:** `rustc`'s MIR inliner (`compiler/rustc_mir_transform/src/inline.rs`) strips the callee prototype without translating `FnEntry` retags into LLVM `!alias.scope` / `!noalias` metadata; only LLVM's middle-end `InlinerPass` converts callee `noalias` parameters into `llvm.experimental.noalias.scope.decl` intrinsics and per-instruction `!alias.scope` / `!noalias` metadata (`support/llvm_attributes_probe.rs`, `raw_caller_mut`).
5. **Coverage gaps across concurrency, exposed provenance, FFI, and inline assembly:** MiniRust's `TreeBorrowsMemory::expose` and `int2ptr` are `unimplemented!()` (`spec/mem/tree_borrows/memory.md:122-130`), whereas Miri's Stacked Borrows (`BorTag::Wildcard` / `untagged` in `stack.rs:37-62`) and Tree Borrows (`wildcard.rs:1-295`) implement sound wildcard tracking for `expose_provenance` / `with_exposed_provenance_mut` (`case5_exposed_provenance`). Neither Simuliris (POPL 2020 / PLDI 2025) nor MiniRust couples aliasing state transitions to weak-memory write-propagation graphs (`AtomicMemory` in `spec/mem/concurrent.md:1-177` is orthogonal to `TreeBorrowsMemory`).
6. **Mechanization and proof-step locality:** The PLDI 2025 Simuliris Rocq development (`simuliris` at `e3abfcdce1aa4e26f1398e3efebad5258ddcc11c`, 49 `.vo` modules, verified zero-axiom by `coqchk` under Rocq 9.0.0) proves contextual refinement for `Frozen` read movement, `Reserved` read-write reordering, and `Protected` `Active` write-overwrite elimination. In Lean 4, `proofs-rs/lean-miri` (`c92d1d9754c9dd585b6b9d6949ae67e5e4665d6a`) mechanizes neither Stacked Borrows nor Tree Borrows, whereas the corpus's factored prefix-map representation of Tree Borrows (93 Lean 4.34.1 modules, 1,026 theorems) decomposes node accesses and protector release into local per-allocation prefix updates.

#### Empirical Miri 7-Case Discriminator Matrix (`support/miri_aliasing_matrix.rs`)
Running Miri (`rustc 1.102.0-nightly` `3ef0c22cdb86ac42dc6b8f0f1ec36857daa6f2a1`) across the 7 discriminator cases in `support/miri_aliasing_matrix.rs` confirms the exact operational boundaries recorded in `support/aliasing_models_comparison.json`:
- **Case 1 (`case1_sb_fails_tb_passes`):** Creating an unused `let r: &mut u8 = unsafe { &mut *raw };`, reading `*raw`, and then passing `r` to `empty_mut(r)` (which triggers a `FnEntry` retag on `r`) **fails under Stacked Borrows** (`trying to retag from <tag> for SharedReadWrite permission, but that tag does not exist in the borrow stack` because reading `*raw` popped `r`'s `Unique` item) and **passes under Tree Borrows** (because `r` starts in `ReservedFrz` and survives parent reads until written).
- **Case 2 (`case2_sb_passes_tb_fails`):** Casting `let ptr = mref as *mut u8;` from `mref: &mut root`, writing `*ptr = 0`, reading `root`, and writing `*ptr = 0` again **passes under Stacked Borrows** (because `mref as *mut u8` triggers a `RetagKind::Raw` retag that pushes `SharedReadWrite`, which is not popped by a parent read of `root`) and **fails under Tree Borrows** (`write access through <tag> is forbidden ... the accessed tag has state Frozen`, because `ptr` shares `mref`'s tag, which became `Unique` on the first write and `Frozen` on the parent read of `root`).
- **Case 3 (`case3_protected_reserved_foreign_read_then_write`):** Inside `case3_callee(x: &mut u8, raw: *const u8)`, reading `*raw` (a foreign read relative to `x`'s protected `FnEntry` tag) and then writing `*x = 42` **fails under both models at different program points**: Stacked Borrows faults immediately on the foreign read `*raw` (`not granting access ... because that would remove [Unique for <tag>] which is strongly protected`), whereas Tree Borrows transitions `x` to `ReservedFrz { conflicted: true }` on `*raw` and faults on the subsequent local write `*x = 42` (`write access through <tag> is forbidden ... has state Reserved (conflicted)`).
- **Case 4 (`case4_protected_reserved_foreign_read_no_write`):** Inside `case4_callee(_x: &mut u8, raw: *const u8)`, reading `*raw` and returning without ever accessing `_x` **fails under Stacked Borrows**, **passes under default Tree Borrows** (`ReservedFrz { conflicted: true }` emits only a ghost exit read on protector release, which `conflicted: true` allows), and **fails under `-Zmiri-tree-borrows-implicit-writes`** (because `_x` is `Unique` at function entry, so `*raw` triggers `ProtectedDisabled`).
- **Case 5 (`case5_exposed_provenance`) & Cases 6–7 (`Pair(u8, UnsafeCell<u8>)`):** Both Stacked Borrows and Tree Borrows accept `expose_provenance` + `with_exposed_provenance_mut` (`case5`), reject writing to the non-`UnsafeCell` byte 0 of `&Pair` (`case6`), and accept writing to the `UnsafeCell` byte 1 of `&Pair` via raw byte-offset arithmetic (`base.add(1)`) without calling `UnsafeCell::get()` (`case7`).

### 2. LLVM Attribute Justification and Optimization Proofs

#### 2.2 Scoped `!noalias` Metadata After Inlining (`MIR` vs. `LLVM`)
Comparing `rustc +1.99.1 -Copt-level=3 -Zinline-mir=yes` (`attrs_1991_mir_inline.ll`) against `rustc +1.99.1 -Copt-level=3 -Zinline-mir=no` (`attrs_llvm_inline.ll`) on `raw_caller_mut(x: *mut u64, z: *mut u64) -> u64 { inline_callee_mut(&mut *x, &mut *z) }` (where `inline_callee_mut(a: &mut u64, c: &mut u64)` writes `*a = 1; *c = 2; *a`) reveals a critical lowering gap:
- When **LLVM's `InlinerPass`** inlines `inline_callee_mut` (`-Zinline-mir=no`), LLVM translates the callee's `noalias` parameters `a` and `c` into `tail call void @llvm.experimental.noalias.scope.decl(metadata !30)` and `!33`, annotates `store i64 1, ptr %x, !alias.scope !30, !noalias !33` and `store i64 2, ptr %z, !alias.scope !33, !noalias !30`, and forwards `ret i64 1`.
- When **`rustc`'s MIR inliner** inlines `inline_callee_mut` (`-Zinline-mir=yes`), `compiler/rustc_mir_transform/src/inline.rs` splices the callee CFG into `raw_caller_mut` and converts `FnEntry` retags into ordinary `RetagKind::Default` statements (which are erased before LLVM codegen). Consequently, `attrs_1991_mir_inline.ll` emits unannotated `store i64 1, ptr %x`, `store i64 2, ptr %z`, and `load i64, ptr %x` (`ret i64 %_0`), losing the inlined `noalias` optimization!

#### 2.3 Formal Statements of the Optimization Proofs (Stacked Borrows & Tree Borrows)
Both the POPL 2020 Stacked Borrows development (`Jung et al., POPL 2020`, DOI `10.1145/3371109`) and the PLDI 2025 Tree Borrows development (`Villani et al., PLDI 2025`, DOI `10.1145/3735592`; Rocq archive `simuliris` at `e3abfcdce1aa4e26f1398e3efebad5258ddcc11c`) prove contextual refinement ($e_t \sqsubseteq_{\text{ctx}} e_s$) in **Simuliris** over an idealized $\lambda$-calculus with tagged pointers and explicit `InitCall`/`EndCall` protector delimiters:
- **Relational simulation and adequacy (`simuliris` `e3abfcdce1aa4e26f1398e3efebad5258ddcc11c`):**
  - `sim_expr_adequacy` (`theories/simulation/simulation.v:306`) and `prog_rel_adequacy` (`theories/simulation/behavior.v:383`) establish that simulation in the Simuliris program logic implies closed whole-program behavioral refinement (`ctx_refines`: if the source has no UB, every target termination or divergence behavior is exhibited by the source).
  - `open_prog_rel_adequacy` (`theories/simulation/behavior.v:418`) and `typed_progs_are_related` (`theories/tree_borrows/logical_state.v:1239`) prove the fundamental theorem of the logical relation (`log_rel`): arbitrary syntactically well-typed open contexts preserve relational simulation across `InitCall`/`EndCall`, justifying optimizations across unknown external function calls.
- **Concrete Tree Borrows optimizations verified in `simuliris` (`e3abfcdc`):**
  1. **Moving/duplicating reads across unknown calls (`Frozen_Read_Ref_Ctx_Refinement` at `theories/tree_borrows/examples/no_protector/frozen_read_ref.v:53`):** Once a shared reference (`Frozen`) has been read, a second read after an arbitrary unknown call can be replaced by the first read's value even **without** a protector.
  2. **Reordering reads and writes on activated mutable references (`Reserved_Reorder_Read_Write_Activated_Ref_Ctx_Refinement` at `theories/tree_borrows/examples/no_protector/reserved_reorder_read_write_activated_ref.v:107`):** Once a `Reserved` reference is activated (`Active`/`Unique`) by a write, subsequent reads and writes commute across unknown code while `Unique` holds.
  3. **Dead-write elimination on protected mutable references (`Active_Write_Overwrite_Protected_Ref_Ctx_Refinement` at `theories/tree_borrows/examples/protected/active_write_overwrite_protected_ref.v:106`):** Under a function-entry protector (`InitCall`), an initial write to `&mut T` followed by an arbitrary unknown call and a second overwriting write refines to performing only the second write (because the ghost exit write at `EndCall` preserves the `Unique` transition and any foreign access during the call is UB in the source).
  4. **Mixed protected and disabled aliases (`disabled_Write_Ref_Ctx_Refinement` at `theories/tree_borrows/examples/protected/mixed_protected_unprotected.v:185`):** Eliminates redundant operations when an unprotected sibling alias is known to be `Disabled` by a protected `Active` access.
- **What the Simuliris proofs assume:** All theorems in `simuliris` (`e3abfcdc`) assume sequential execution (or fair non-atomic thread interleaving without weak-memory reordering), no integer-to-pointer casts (`expose_provenance`), and explicit `InitCall`/`EndCall` delimiters around protected lifetimes.

### 3. Coverage of Concurrency, FFI, Inline Assembly, and Exposed Provenance

**Basis: source (`src/tools/miri/src/borrow_tracker/tree_borrows/wildcard.rs:1-295`, `src/tools/miri/src/concurrency/data_race.rs`, `minirust` `spec/mem/{concurrent.md,intptrcast.md,tree_borrows/memory.md}`).**

1. **Concurrency and Weak Memory:**
   - **Miri (`1.99.1` / `1.102.0-nightly`):** Runs the borrow tracker (`stacked_borrows` or `tree_borrows`) sequentially on each global interpreter step alongside the vector-clock C++20 release/acquire data-race detector (`src/tools/miri/src/concurrency/data_race.rs`). Both trackers treat atomic reads (`AtomicUsize::load`) as ordinary read accesses and atomic writes/RMWs as ordinary write accesses on the underlying bytes (`SharedReadWrite` / `Cell` inside `UnsafeCell`), without modeling multi-copy atomic store buffers or out-of-order weak-memory visibility.
   - **MiniRust (`063d784186d3`):** Defines `AtomicMemory<M: Memory>` (`spec/mem/concurrent.md:1-177`) as a race-Detecting wrapper over an inner sequential `Memory` trait `M` (tracking `last_atomic_read`, `last_atomic_write`, `last_na_read`, and `last_na_write` per byte per thread in a sequentially consistent global step order). Neither `minirust` nor `simuliris` defines a weak-memory axiomatic or operational composition of Tree Borrows with C++20/RC11/Promising execution graphs.
2. **Exposed Provenance (`ptr2int` / `int2ptr`):**
   - **Stacked Borrows (`stacked_borrows/stack.rs:37-62`):** Maintains a per-stack `exposed: bool` flag (`Stack::set_unknown_bottom`). When a pointer with `Provenance::Wildcard` accesses a byte, Stacked Borrows searches the stack from top to bottom for the highest item whose tag is in `global.exposed_tags` and grants the access if that item (and any intervening items) permits it.
   - **Tree Borrows (`tree_borrows/wildcard.rs:1-295`):** Tracks `WildcardState` on each tree node (`AccessRelatedness` bounding the minimum and maximum distance to an `is_exposed` node in the subtree/ancestors). A wildcard access succeeds if and only if **at least one** `is_exposed` node in the tree can perform the access without violating its own state machine (`ChildAccessForbidden`), and applies only the **mandatory** foreign transitions needed by all exposed candidates.
   - **MiniRust (`spec/mem/tree_borrows/memory.md:122-130`):** Explicitly leaves `expose` and `int2ptr` as `unimplemented!()` in `TreeBorrowsMemory<T>`; MiniRust's `IntPtrCast` module (`spec/mem/intptrcast.md:1-43`) only wraps `BasicMemory` via angelic nondeterministic `predict`.
3. **FFI and Inline Assembly (`asm!`):**
   - Neither Stacked Borrows, Tree Borrows, nor MiniRust models arbitrary machine-code side effects across FFI calls or `core::arch::asm!`. When an address is passed to an external C function or `asm!` block, a sound compiler or verifier must either (a) know the callee's exact footprint and treat its accesses as occurring through the passed pointer's tag, or (b) treat the pointer as having called `expose_provenance()` before the FFI/`asm!` boundary so foreign writes through reconstructed pointers are accounted for via wildcard provenance.

#### Normative Standing (`t-opsem`, `rust-lang/reference`, `rust-lang/unsafe-code-guidelines`)
- **The Rust Reference (`bcd62f35e8bf`, `src/behavior-considered-undefined.md`):** Declares that breaking the pointer aliasing rules is Undefined Behavior, and explicitly states after the rules list: *"Note: Mutable references and boxes (`&mut T` and `Box<T>`) currently have `noalias` attributes emitted for them (except when `T` is `!Unpin`), and shared references (`&T`) have `readonly` and `noalias` attributes emitted for them (except when `T` contains an `UnsafeCell<U>`). However, the exact aliasing model is still under active discussion; Stacked Borrows and Tree Borrows are two candidate models."*
- **`t-opsem` FCP Archive (`rust-lang/opsem-team` `d46208581403`, `fcps.md`) and UCG (`d809f91e6296`):** Neither Stacked Borrows (`wip/stacked-borrows.md`) nor Tree Borrows (`wip/tree-borrows.md`) has been adopted as normative by a `t-opsem` or `t-lang` FCP. Both `t-opsem` and Miri diagnostics explicitly warn that Tree Borrows is experimental, while Miri supports both models (`-Zmiri-stacked-borrows` default; `-Zmiri-tree-borrows` opt-in).

#### Fit with Local Verification Derivations (`Factored Prefix Map` vs. `Stack` vs. `Recursive Tree`)
For a verified compiler (`MIR -> AnLLVM`) and program logic in Lean 4:
1. **Why Stacked Borrows fits poorly with local derivations:** Because a parent read pops all `Unique` items above the parent on the per-byte stack (even if those child `&mut` pointers are never used again or were created for two-phase borrows), every raw/parent read requires global reasoning about the entire stack suffix above the accessed tag.
2. **Why coupled recursive `Node` trees (`MiniRust` `tree.md`) require a factored representation:** In MiniRust's recursive `Node` representation, a single byte access or `release_protector` traverses the entire tree—computing `PathStep::ThisChild(idx)` on ancestors and `PathStep::OtherChild` on all complement subtrees. In the **factored prefix-map representation** (`TreeFactoredMemory`: mapping each `Path` in the allocation to its per-byte `NodeState`), every `reborrow`, `access`, and `release_protector` decomposes into pointwise updates over paths:
   - **Child vs. foreign partition:** A node at path $p'$ sees a `This` (`Child`) access if and only if $p'$ is a prefix of the accessed path $p$ ($p' \preceq p$), and sees a `Foreign` (`OtherChild`) access if and only if $p' \not\preceq p$.
   - **Localizing proof steps:** Because `Reserved -> Unique -> Frozen -> Disabled` is monotone on non-cell bytes and `Cell` (`ReadWrite`) is an absorbing fixed point under both `This` and `Foreign` reads/writes, any separation-logic points-to token for a protected `Unique` (`&mut T`, `T: Unpin`) or protected `Frozen` (`&T`, `T: Freeze`) reference locally entails that all foreign accesses in the allocation step to `None` (UB), discharging LLVM `noalias`, `readonly`, `dereferenceable`, and (with `FnEntry` activation) `writable` as local per-allocation lemmas without walking unrelated allocations.

## Boundaries

1. **Empirical Crate-Corpus Permissiveness and Compilation Overhead (**not examined** here):** This report characterizes the exact state-machine rules, LLVM attribute soundness conditions, and mechanized metatheory of Stacked Borrows, Tree Borrows, MiniRust `TreeBorrowsMemory`, and the no-aliasing baseline. Quantitative pass/fail rates across large crate suites under Miri and runtime/compile-time benchmarks of borrow-tracking overhead are outside the scope of this package.
2. **Weak-Memory + Aliasing Composition (**unknown** in upstream literature):** Neither the POPL 2020 Stacked Borrows paper, the PLDI 2025 Tree Borrows paper (`simuliris` `e3abfcdce1aa4e26f1398e3efebad5258ddcc11c`), nor MiniRust (`063d784186d3252bee242217f218223205c0b568`) defines an operational or axiomatic semantics that combines per-byte borrow-tag transitions with out-of-order weak-memory executions (such as C++20/RC11 release/acquire graphs or Promising Semantics views). Miri and MiniRust both evaluate borrow-tracker transitions sequentially at each global machine step.
3. **Exposed Provenance in MiniRust `TreeBorrowsMemory` (`unsupported`):** In `minirust/minirust` at `063d784186d3252bee242217f218223205c0b568`, `TreeBorrowsMemory::expose` and `TreeBorrowsMemory::int2ptr` (`spec/mem/tree_borrows/memory.md:122-130`) are explicitly `unimplemented!()`. Wildcard provenance for Tree Borrows is implemented only in Miri's Rust source (`src/tools/miri/src/borrow_tracker/tree_borrows/wildcard.rs:1-295`) and is omitted from the PLDI 2025 Simuliris Rocq mechanization.
4. **Default Tree Borrows vs. LLVM `writable` (**known not to apply** without `implicit_writes`):** Default Tree Borrows (`-Zmiri-tree-borrows`) does **not** justify emitting LLVM's `writable` attribute on `&mut T` (`T: Unpin`), because a protected `ReservedFrz` reference that is never written by the callee allows foreign reads (`case4_protected_reserved_foreign_read_no_write`). Emitting `writable` on `&mut T` requires either Stacked Borrows or Tree Borrows with `-Zmiri-tree-borrows-implicit-writes`.
5. **Unique (`&unique T`) or Place-Based Aliasing Proposals (**unknown** / unmechanized):** Proposals discussed in `rust-lang/unsafe-code-guidelines` issues (such as deferring uniqueness until first use on `&mut T` while introducing a distinct `&unique T`, or tracking provenance at the level of MIR places rather than runtime pointers) have neither an executable implementation in Miri nor a formal specification in MiniRust at the observed revisions.
