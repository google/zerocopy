# Neural and Multi-Agent Proof-Search Architectures, Auto-Active Loop-Invariant and Bounded Model-Checking Harness Synthesis, and Longitudinal AI-Generated Code Survival

## Summary

Primary-source inspection of 16 pinned public GitHub repository revisions, 39 peer-reviewed or archival technical papers (`36` version-pinned arXiv preprints plus `3` non-arXiv studies, 2022–2026), and a deterministic standalone Python 3.10+ stdlib verification suite (`support/verify_proof_search_autoverus_code_survival_probes.py`) establishes three architectural and methodological invariants across formal theorem proving, auto-active/bounded program verification, and longitudinal empirical software engineering:

1. **Proof-Search Regime Dominance Depends on Depth, State Re-Encoding Cost, Diagnostic Localization, and Sketch Validity (`DSP`, `Baldur`, `LEGO-Prover`, `DeepSeek-Prover-V2`, `Prover Agent`, `Hilbert`, `Aristotle`, `Probes 1A–1B`):**
   - Whole-proof generation avoids step-wise proof-state re-encoding (`Baldur` generates `64` Isabelle proofs in `~35 s` on 8 TPUv3 cores vs. `Thor`'s `216 s` per theorem, a `6.17x` accelerator ratio excluding CPU proof checking) and complements interactive search (`Baldur 8B w/ context` `47.5%` $\cup$ `Thor` `57.0%` reaches **`65.7%`** union across `6,336` PISA theorems, `+8.7 pp` over `Thor`, `overlap ~38.8%`, `Jaccard ~0.59`). Conditioning whole-proof repair on Isabelle compiler diagnostics beats equal-compute plain generation (`2,305` proven = `36.28%` on `data.tex` `N = 6,354` / `36.38%` on Table 1 `N = 6,336` at cost `14.33` vs. `2,207` = `34.73%` / `34.83%` at cost `16.00`), whereas **blind repair without error messages degrades strictly below plain generation** (`2,171` = `34.17%` / `34.26%` at cost `14.33`).
   - Hierarchical sketching and subgoal decomposition convert exponential monolithic depth decay ($p^d$) into shallow subgoal discharges: informal sketching + `Sledgehammer` lifts Isabelle `miniF2F-test` from `10.4%` (`Sledgehammer`) and `29.9%` (`Thor`) to `39.3%` (`DSP`), growing lemma skill libraries reach `50.0%` (`LEGO-Prover`), recursive subgoal RL lifts Lean 4 `miniF2F-test` to `88.9%` (`DeepSeek-Prover-V2-671B` CoT vs. `78.3%` non-CoT) and `PutnamBench` from `15/658` to `47/658` (`3.1x`), recursive informal-reasoner + specialist-prover + semantic-retriever orchestration with per-subgoal verification pruning (`Hilbert`) reaches `99.2%` on `miniF2F` and `462/660` (`70.0%`) on `PutnamBench`, and `Aristotle` solves `5/6` IMO 2025 problems from human-formalized statements without `sorry` (`4` verified in Lean 4 + Mathlib [`P1, P3, P4, P5`] and `1` plane-geometry problem [`P2`] machine-verified outside Lean via the C++ `Yuclid` DD/AR engine).
   - In a derived discrete-budget crossover model (`Probe 1B`, equal per-step accuracy $p = 0.72$, zero dedup double-counting, zero fractional exponents), **all three paradigms own distinct optimal regimes** at `6x` step re-encoding overhead: error-localized whole-proof repair wins on shallow or non-decomposable moderate proofs (`d = 4..12, p_sketch = 0.10`), hierarchical AND/OR decomposition with early-abort pruning dominates decomposable moderate-to-deep proofs (`d = 8..20, p_sketch >= 0.35`), and closed-loop best-first tactic tree search with prefix sharing and dead-end backtracking wins outright on deep non-decomposable tactical proofs (`d = 16, 20, p_sketch = 0.10`: `39.28%` and `37.04%`), surging to `97.88%–100.00%` when KV-cached incremental servers reduce re-encoding overhead to `2x`.
2. **Placeholder Localization, Error-Code-Dispatched Repair Graphs, Kani `N + 1` Unwinding Checks, and Post-State Negation Oracles Govern Auto-Active and BMC Reliability (`Laurel`, `AutoVerus`, `SAFE`, `Vericoding`, `Kani`, `KaPilot`, `Kolyakov et al.`, `Probes 2A–2C`):**
   - Across `145` real-world Dafny missing-assertion tasks (`33,054` LOC in `Libraries`, `Cedar`, and `DafnyVMC`, `Laurel`, OOPSLA1 2025), bare prompting solves only `6.2%` (`k = 10`) due to assertion misplacement (median `2.8` lines). Inserting an AST-derived `<assertion>` placeholder lifts verification to **`34.4%`** (whereas appending raw Dafny error text *regresses* to `26.2%`, `-8.2 pp`, by anchoring the model to echo the failing postcondition); combining placeholder localization with maximal subtree-similarity (`MSS`) retrieval (`m = 6`) reaches **`56.6%`** (`82/145`).
   - In Rust/Verus (`AutoVerus`, OOPSLA2 2025), combining preliminary inference (`78/150`), `Houdini` maximal-inductive-subset pruning + candidate ranking (`+22`), and **9 error-specific repair agents plus 1 `Default` fallback (`10` total; `7` invoked LLM specialists + `1` `Default` fallback in Table 2, `377/657 = 57.4%`)** lifts `Verus-Bench` (`150` tasks) from `44.7%` (`67/150`) to **`91.3%` (`137/150`)**—whereas collapsing Phase 3 to a single generic debugging agent drops Phase-3 solves from `37/37` to `17/37`. Across `Vericoding` (`10,868` compilable of `12,504` heterogeneous specs), off-the-shelf multi-model union verification drops with proof explicitness from **`82.2%` in Dafny (`2,334` tasks)** to **`44.2%` (prose) / `44.3%` (Table 2) in Verus/Rust (`2,166` tasks)** to **`26.8%` in non-`FVAPPS` Lean 4 (`2,362` tasks, excluding `4,006` weaker-spec `FVAPPS` tasks at `41.8%` union)**.
   - Across `2,005` production CBMC/Kani artifacts in `24` C/Rust projects (`Kolyakov et al. 2026`), `97.2%` (`1,948/2,005`) complete within allocated limits (`98%` median within-harness coverage), yet repository function coverage declines sharply with size (Spearman $\rho = -0.85$ across `23` projects), `54%` (`1,082` artifacts across `20` projects) enforce explicit finite loop bounds, and `35` artifacts across `10` projects exhibit specification defects including `8` incorrect domain predicates (`E9`) and `3` vacuous/contradictory guards (`E10`). Under Kani/CBMC's **`N + 1` unwinding rule**, `LOOP_UNWIND_DEFAULT = 20` permits at most **`19` loop body iterations** (`Probe 2C`: `20` post-states, `12` truncated paths in `0..=31`); passing `--no-unwinding-checks` silently hides bugs past iteration `19` (`naive_bmc_pass = True`), and `KaPilot`'s negation smoke check (`#[kani::ensures(|_| false)]`) separates post-state vacuity from harness entry reachability (`entry_reachable = True`, `negation_smoke_falsified = False`).
3. **Longitudinal AI Code-Survival Verdicts Turn on Within-Repository Stratification, Cluster-Robust SEs, `-M -C` Identity Tracking, Calibrated Intent Labels, and Def-Use `SZZ` (`Rahman et al.`, `Song et al.`, `Yeverechyahu et al.`, `Kondo et al.`, `AgenticSZZ`, `Probes 3A–3C`):**
   - Across `854,139` lines in `2,802` merged PRs across `215` `AIDev` repositories (`Rahman, Begoug, & Shihab 2026`, `>=5m` follow-up, sensitivity windows to `>=10m`/`300d`), unclustered cross-repo line SEs produce `15/22` significant "Devin modified sooner" specs, collapsing to **`3/22`** under repository-clustered SEs and **`0/22`** under within-repository stratification (`HR = 1.059`, 95% CI `[0.409, 2.076]`), while human-supervised `GitHub Copilot` survives **longer** within repositories (`HR = 0.653`, 95% CI `[0.459, 0.954]`, $p = 0.015$) and humans author **`87.7%`** (`1,816/2,070`) of post-merge modifying commits (`88.2%` under `Sawada`-design file-level emulation).
   - Naive line-number tracking inflates modification rates by `1.83x–2.56x` over `git blame -M -C` identity tracking and suppresses Devin's unadjusted HR from **`1.294` (identity) down to `0.992` (line-number)**; keyword intent rules ($\kappa = 0.38$) distort corrective shares compared to human-calibrated multi-LLM ensembles ($\kappa = 0.69\text{--}0.72$, `22.9%` supervised / `23.2%` Devin / `22.3%` human, $p = 0.31\text{--}0.93$). Staggered DiD panels (`>12m`) show Copilot raises OSS contributions (`+5.9%` in `Song et al.`, `+28%–40%` in `Yeverechyahu et al.`, skewed toward incremental exploitation) while lengthening PR coordination time (`+8.0%`). Classical blame-seeded `SZZ` misses cross-file omission bug-inducing commits (`Probe 3C`), motivating unconstrained commit-history and temporal-knowledge-graph `SZZ` agents (`0.938` F1 on the reconstructed `DIO-V` oracle in `Kondo et al.`).

## Applicability

These findings govern the architectural design, verifier-harness engineering, and empirical evaluation of: (1) interactive neural and multi-agent theorem provers (Isabelle/HOL and Lean 4), (2) auto-active SMT loop-invariant/assertion synthesizers (Dafny and Verus/Rust) and bounded model-checking harnesses (Kani/CBMC), and (3) longitudinal post-merge code-survival, churn, and bug-inducing-commit (`SZZ`) pipelines on AI-assisted and agent-authored software (`observed_at`: `2026-11-22`).

Three structural mechanisms are directly established (`Probe 1A`):
1. **Per-unique-failed-attempt deduplication (`repairPaper.tex:808`):** Average costs scale identically as `14.33 / 8 = 28.66 / 16 = 1.79125` (constant unique-failure ratio `0.79125`). Skipping all failed attempts on already-solved theorems (`1,976/6,354` at `8` samples, `2,207/6,354` at `16` samples) would cap average cost at `13.512 < 14.33` and `26.443 < 28.66` (`Probe 1A`), confirming that `Baldur` deduplicates duplicate failed proofs and issues one repair per unique failed attempt rather than skipping theorems solved by another sample.
2. **Compiler diagnostic localization is the causal driver of repair:** Stripping the Isabelle error string (`generateandrepairblind.csv`) falls below equal-cost plain generation at every budget (`-1.01 pp` at cost `2.00`; `-0.57 pp` at cost `14.33` vs. `16.00`).
3. **Accelerator vs. CPU decoupling and portfolio complementarity:** Interactive tree search (`Thor`) pays `60 TPU-h / 1,000` theorems (`216.0 s` on 8 TPUv3 cores) vs. `Baldur`'s `~35.0 s` for `64` whole proofs (`6.17x` TPU ratio, excluding CPU proof checking). #### 1.4 Stylized Discrete-Budget Proof-Search Crossover Model (`Probe 1B`)

`Basis: derived + execution (standalone Python 3.13 exact discrete-budget dynamic programming in Probe 1B; stylized sensitivity model illustrating crossover mechanics rather than confirming empirical cross-paper benchmarks)`

Normalizing total inference compute to an integer budget $C$ whole-proof units (`1` unit = one $d$-step proof) with shared underlying per-step accuracy $p \in (0, 1)$, exact discrete dynamic programming eliminates fractional-exponent renewal approximations and deduplication double-counting:

- **Monolithic whole-proof sampling (`dp_monolithic`):** Draw 1 is fresh (succeeds w.p. $p_0 = p^d$); each subsequent draw duplicates a prior failed draft w.p. $1 - \eta$ (cost `1`, **`0` new success probability**) or is a fresh draw w.p. $\eta$ (cost `1`, succeeds w.p. $p_0$).
- **Deduplicated whole-proof repair (`dp_repair`):** Duplicate failed drafts (prob $1 - \eta$ after draw 1) save `1` repair unit AND receive **`0` initial and `0` repair trials** (strictly enforcing `dp_repair(..., r_fix=0) <= dp_monolithic(...)`). Fresh failed drafts spend `1` repair unit if remaining budget $\ge 1$, recovering single-fault mass $p_1 = d p^{d-1}(1-p)$ with conditional probability $\frac{p_1}{1-p_0} r_{\text{fix}}$, where $r_{\text{fix}} = r_{\text{loc}}$ (error-localized) vs. $r_{\text{loc}}/d$ (blind).
- **Closed-loop best-first tactic tree search (`dp_closed_loop_tree`):** Uses the **same** base per-step accuracy $p$. Each interactive tactic call re-encodes proof state at cost $\kappa_{\text{reencode}}/d$ whole-proof units, giving discrete budget $M = \lfloor C d / \kappa_{\text{reencode}} \rfloor$ calls. At verified prefix depth $h < d$: w.p. $p(1 - \beta_{\text{trap}})$ the tactic advances to $h + 1$ (preserving prefix `0..h`); w.p. $1 - p$ the verifier rejects immediately (cost `1`, prefix kept); w.p. $p \beta_{\text{trap}}$ the search enters a syntactically valid dead-end subtree costing $w_{\text{bt}}$ extra calls before backtracking to $h$ (total cost $1 + w_{\text{bt}}$).
- **Hierarchical AND/OR subgoal decomposition (`dp_andor`):** Uses discrete quanta $\Delta = 1/m$ (`C * m` total quanta; sketch costs $m$ quanta; each subgoal attempt costs `1` quantum with $q_{\text{sub}} = p^{d/m}$ and independent per-subgoal provability $v = p_{\text{sketch}}^{1/m}$). Every subgoal—valid or invalid, pruned or unpruned—applies consistent geometric early stopping (`1..B` quanta on success, `B` quanta on failure). Early-abort pruning immediately discards the sketch on the first failed subgoal.

Executing `Probe 1B` at stylized parameters (`C = 24, p = 0.72, eta = 0.79, r_loc = 0.55, beta_trap = 0.30, w_bt = 6, m = 4, B = 8`) illustrates three distinct winning regimes under $\kappa = 6.0$ plus KV-cache sensitivity at $\kappa = 2.0$:

#### 3.2 Four Quantitative Measurement Traps in Longitudinal Survival and `SZZ` Attribution

1. **Cluster-Variance Collapse (`Rahman et al. 2026`, `arXiv:2611.21784v2`, `Table 10`):** Shared release cadence, refactor sweeps, and review norms within PRs and repositories create large cluster design effects ($DEFF$). Across `22` cross-repository specifications on `Devin`, `Model-based` (line-independent) SEs yield `5 / 2 / 15` (`longer / none / sooner`), `PR-clustered` yields `0 / 13 / 9`, **`Repository-clustered`** collapses to `1 / 18 / 3` (indistinguishable from permuted-label noise), and **within-repository stratified + repo-clustered** yields **`0 / 22 / 0`**.
2. **Line-Number vs. Identity (`git blame -M -C`) Distortion (`Table 5`, `main.tex:749–758`; `Probe 3A`):** Across `276,314` sampled units, naive line-number tracking inflates modification rates by **`2.56x`** for human-supervised code (`46.8%` vs. `18.3%`), **`2.22x`** for human code (`64.5%` vs. `29.0%`), and **`1.83x`** for `Devin` (`63.8%` vs. `34.9%`). Because line-number noise saturates human baselines faster than `Devin`, it **suppresses `Devin`'s unadjusted HR from `1.294` (`-M -C` identity) down to `0.992` (line-number)**—i.e., switching from line-number to `-M -C` identity shifts Devin's HR from **`0.992` $\to$ `1.294`**.
3. **Keyword vs. Calibrated Modification-Intent Reversal (`Tables 12, 13, 17` of `2611.21784v2`):** Keyword regex rules (`fix`, `bug`, `revert`) achieve only Cohen's $\kappa = 0.38$ against `618` manually adjudicated commits and report a spurious $p < 0.001$ gap where `Devin`'s corrective share (`30.6%`) is *lower* than human (`34.2%`) while adaptive share is higher (`36.0%` vs. `28.7%`, with `10.1%` human-supervised / `4.3%` Devin / `12.2%` human unclassified, `Table 12`). Three independent LLMs (`DeepSeek`, `gpt-oss`, `MiniMax`) and Dawid–Skene aggregation reach $\kappa = 0.69\text{--}0.72$ (matching human inter-rater reliability) and find **no significant corrective-share difference** (`22.9%` human-supervised, `23.2%` Devin, `22.3%` human; $p = 0.31\text{--}0.93$; Rogan–Gladen pooled confusion-matrix corrected shares in **`Table 13`** are **`23.6% / 23.4% / 23.0%` for `DeepSeek`** and **`24.0% / 24.4% / 23.6%` for `Majority vote`**). Re-running `Xia & Miller`'s cause-specific corrective hazard (`Table 17`) swings from `HR = 0.68` ($p = 0.22$, keyword-first) to `HR = 1.37` ($p = 0.14$, LLM-labeled).
4. **Blame-Tracing `SZZ` Blindness to Extrinsic/Omission Bugs (`Kondo et al., Oct 2026`, `arXiv:2610.14462v1`, `higolab/rethinking-szz-replication` @ `455f6f8c`; `Shi, Li, Adams, & Hassan, Feb 2026`, `arXiv:2602.02934v2`, `SAILResearch/AgenticSZZ` @ `6540a5d2`):** Classical `SZZ` (`B-SZZ`, `AG-SZZ`, `R-SZZ`) seeds exclusively from `git blame` on deleted/modified lines of a bug-fixing commit (`BFC`), failing whenever a fix inserts a new guard or patches a different file from the true bug-inducing commit (`BIC`). Unconstrained commit-history search via `Claude Code` (`arXiv:2610.14462v1`; commit-history-first + diff inspection in `189/237 = 79.7%` of runs) reaches `0.771` F1 on the original `79`-case (`70`-repo) Java `DIO-V` dataset and **`0.938` F1 (`Precision 0.936`, `Recall 0.940`) on the reconstructed/revised `DIO-V` oracle** after correcting ground-truth errors, outperforming ten baselines including LLM/agent `SZZ` variants (`Simple-SZZ-Agent` `0.696` F1, `AgentSZZ` `0.685` F1). `AgenticSZZ` combines `git blame` with a **Temporal Knowledge Graph** (`agentic_szz/kg/tkg.py` `1,233` L, `agentic_szz/agent/bic_search_agent.py` `589` L, `agentic_szz/szz/blame.py` `579` L), evaluated over **`2,102` bug-fixing cases** (`1,500` Linux kernel, `241` Apache, `361` GitHub) encompassing **`2,272` ground-truth BICs** (`1,562` Linux, `353` Apache, `357` GitHub; `main.tex:287, 323–327`).

#### 3.3 Executable Verification of Cluster `DEFF`, Censored Kaplan–Meier, Block Alpha-Moves, and Def-Use `SZZ` (`Probes 3B–3C`)

`Basis: derived + execution (standalone Python 3.13 binary risk-difference analogue, product-limit KM, sequence/block-alpha matcher, and snapshot diff/def-use SZZ in Probes 3B–3C)`

1. **Binary Risk-Difference Analogue of Cluster Variance Inflation and Simpson's-Paradox Confounding (`Probe 3B`):** Simulating `75,434` lines (`seed = 20261122`) across `40` repositories (`20` high-churn `55%` base / `70%` agent share; `20` stable `18%` base / `10%` agent share; `25` PRs/repo; **true within-repository effect = `0.0000`**; note that `Rahman et al.` fits PR-weighted, repo-stratified Cox PH models with 500-resample cluster-bootstrap CIs rather than binary risk differences):
   - *Pooled Naive Line SE:* `diff = +0.2561`, `SE = 0.0035`, **`z = +72.92`** (severe false positive).
   - *Pooled Repo-Clustered (`Liang–Zeger` / Jackknife):* `diff = +0.2561`, `SE_LZ = 0.0184`, `SE_JK = 0.0186`, `z_LZ = +13.93` (**pooled `DEFF_LZ = 27.4x`, `DEFF_JK = 28.1x`** combining cross-repo base-rate confounding and intra-cluster correlation; clustering alone still leaves cross-repo bias!).
   - *Within-Repo Mantel–Haenszel + Repo Jackknife:* `diff = -0.0104`, `SE_naive = 0.0043`, `SE_JK = 0.0082`, **pure within-stratum `DEFF_within = 3.6x`** (isolating PR-level ICC), **`z = -1.26`** (95% CI `[-0.0265, +0.0057]`—unbiased null recovered).
2. **Kaplan–Meier Crossover Under Intermediate Right-Censoring (`Probe 3C`):** With `20` observations right-censored at day `90` (before day-240 clone-debt events shrink `n_at_risk` from `96` to `76`), exploratory prototyping (`18` events day `10`, `20` censored day `90`, `62` censored day `365`) yields `(S14, S180, S365) = (0.8200, 0.8200, 0.8200)`, whereas clone debt (`4` events day `10`, `20` censored day `90`, `24` events day `240`, `52` censored day `365`) scores higher at 14 days (`0.9600`) yet drops to **`0.6568`** at day 365 (`0.96 * 52/76`, strictly below naive uncensored `0.7200`)—confirming non-monotonicity of short-horizon churn and proper risk-set shrinkage.
3. **Sequence-Aligned Shift Tracking & Block-Scoped Alpha-Renaming (`Probe 3C`):** Prepending `5` header lines to a `10`-line file with duplicate closing braces yields `10/10` modified under index-aligned line numbers vs. `0/10` under `difflib.SequenceMatcher` (which also catches deleting one of two identical `"    }"` lines: `seq = 1` vs. naive `set = 0`). On a 3-line variable-renamed refactor (`idx -> pos`, `y -> val`, `acc -> total`), exact matching scores `0/3`, whereas **block-scoped consistent alpha-renaming** recovers **`3/3`** while **rejecting** a semantically inconsistent rename (`for a in 0..b { let c = d[e]; f = f + g; }`: `1/3`, false positive rejected).
4. **Source-Diff / Def-Use Omission-Bug `SZZ` (`Probe 3C`):** Over a 3-revision Rust snapshot history (`rev_base` creates `Packet` + `parse_header`; `rev_field` adds unchecked field `pub raw_len: usize` in `packet.rs`; `rev_fix` inserts a pure-addition guard referencing `pkt.raw_len` in `parser.rs` with `0` deleted lines), real `difflib` line blame (`B-SZZ`) falls back to the adjacent context line and misattributes **`['rev_base']`**, whereas commit-diff symbol-definition extraction + newly-referenced field resolution recovers the exact true BIC **`['rev_field']`**.

## Boundaries

- **`known not to apply`:**
  - `Baldur`'s `6.17x` TPU advantage over `Thor` (`35.0 s` vs. `216.0 s`) excludes CPU Isabelle verification time and assumes full state re-encoding without KV-cached incremental tactic servers (`Probe 1B` shows reducing $\kappa$ from `6.0` to `2.0` lifts closed-loop tree search to `97.88%–100.00%`).
  - `GitClear`'s macro 2020–2024 churn and clone-growth series cannot be attributed causally to AI assistants, and unclustered cross-repository line-level $p$-values (`Model-based` SEs) are invalid across multi-repository cohorts (`Rahman et al. 2026`).
  - `Vericoding`'s `82.2%` Dafny vs. `26.8%` non-`FVAPPS` Lean 4 rates measure off-the-shelf general-purpose LLMs on self-contained tasks without dedicated prover agents (`Hilbert`/`Aristotle`) and do not apply to trained prover-agent pipelines or multi-module systems libraries.
  - `Kani` verification with `--default-unwind 20` or `--no-unwinding-checks` does not establish unbounded loop safety (`20` permits at most `19` body iterations under Kani/CBMC's `N + 1` rule) or non-vacuity unless paired with enabled unwinding checks (or loop contracts) and reachability/postcondition-negation witnesses.
- **`unknown`:**
  - True `>24`-month post-merge defect survival for 2025–2026 autonomous multi-PR agents (`Claude Code`, `Codex`, `Devin`, `Cursor`) cannot yet be observed beyond `12–18` months of calendar history (`Rahman et al.` ends Dec 2025 at `>=5m`–`10m`; `Xia & Miller` spans `12m`; `>12m` causal DiD panels cover earlier autocomplete `GitHub Copilot`).
  - Whether `Aristotle`'s hosted MCGS + informal-lemma + `Yuclid` stack generalizes from Olympiad mathematics (`IMO 2025`) to large imperative software verification obligations remains unmeasured from public artifacts (`harmonic-ai/aristotle` exposes only the client SDK).
  - Whether `Laurel`'s placeholder + raw-error regression (`34.4%` $\to$ `26.2%` on `GPT-4o`) persists on 2025–2026 reasoning-trace models has not been re-measured on the `145`-task suite.
  - Exact raw sample count `n` of `Prover Agent`'s Appendix `tab:aux_lemma_categories` manual lemma audit is unreported in `arXiv:2506.19923v5` (only rounded percentages compatible with multiples of `12` are given).
- **`unsupported`:**
  - `MinghuaWang/KaPilot` (cited in Footnote 1 of `arXiv:2607.21957v1`, `chapters/intro.tex:67`) returns HTTP `404` on GitHub as of `2026-11-22`; `KaPilot` findings therefore rest on the arXiv paper source rather than an inspectable repository.
  - `Baldur`'s fine-tuned `Minerva` `8B`/`62B` weights and training code are unreleased; primary verification rests on `arXiv:2303.04910v2` (`repairPaper.tex` and embedded `data.tex` CSVs).
  - `GitClear`'s 2-week churn series (`3.1% → 5.7% → 7.9%`) resides behind an email-gated whitepaper PDF rather than open public tables; only the landing-page `153M → 211M` line counts, `4x` cloning headline, `copy/pasted` (`8.3% → 12.3%`), and `moved` (`25% → <10%`) figures were openly verified.
- **`not examined`:**
  - Live execution of the 16 upstream repositories against live LLM APIs, Isabelle/Lean/Dafny/Verus/Kani toolchains, or production git clusters (only the standalone Python 3.13 verification suite was executed).
  - Proprietary enterprise telemetry reports without open replication methodology; Coq/Rocq neural proof agents (`Proverbot9001`, `Tactician`, `CoqPilot`); and hardware RTL formal verification (`VeriCoder`, `arXiv:2504.15659v2`) or internal SMT bitvector heuristics.
